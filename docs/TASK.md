在 Windows 空白工作区中，需要从零构建一个面向本地 SQLite 数据的查询计划与索引选择组件，供上层查询优化器集成。组件读取表与列的统计信息（行数、不同值数、直方图、空值比例），估算谓词选择率与多表连接基数，并据此在候选索引集合中为等值、范围和组合谓词选择索引与连接顺序。真实数据分布存在偏斜、相关列和精度敏感的比较运算，浮点运算顺序、直方图边界包含关系和累计求和的误差都会影响选择率与最终计划，因此要在数值稳定、误差可界定、计划可解释之间做取舍。用户通过本地 HTTP API 提交查询描述与统计快照，获得带代价分解的计划；所有输入来自固定的本地确定性样本库，不依赖外部数据库服务或真实数据集。

任务环境与准备：
安装 Python 3.11 及以上，并确认 pip 可用。
安装 NumPy 到当前虚拟环境，使用 requirements.txt 固定版本。
确认标准库 sqlite3 可用，生成本地确定性样本库与统计快照文件。
预留本地回环端口用于 HTTP 示例服务，所有运行在 Windows 命令行完成。

业务要求：
1. 实现选择率估算模块：支持等值、范围、IN 列表与 NULL 判定谓词，使用行数、不同值数、空值比例与等深直方图计算选择率，结果必须落在 [0,1] 且对空表和零不同值列返回确定值而非除零异常。
2. 直方图累计计数必须使用 Kahan 或等价补偿求和来计算桶边界分位与累计占比，与传统朴素求和在存在大计数与小计数混合时相比，需提供可量化的误差上界，并让同一快照多次求值得到逐位一致的结果。
3. 处理列间相关性：当查询涉及已声明函数依赖或相关系数的列组合时，按给定相关度修正独立假设下的联合选择率，修正后结果不得超出 [0,1]；未声明相关性时保持独立假设，并在计划说明中标注假设来源。
4. 实现连接基数估算，对多表连接按左深与至多一遍的枚举方式计算中间基数，使用几何平均或对数域累加避免中间基数溢出与下溢，并对无连接谓词的笛卡尔积给出明确上限策略而非静默截断。
5. 实现索引选择：在给定候选索引集合中为查询选择可用索引，计算索引扫描、全表扫描与回表的代价分解（CPU、IO、选择率敏感项），当组合谓词仅部分列被索引覆盖时按前缀匹配规则取舍，并输出每个候选被排除的具体原因。
6. 定义计划代价的数值精度契约：代价各分项在 JSON 输出中保留固定小数位并附舍入误差累计说明，比较两个计划优劣时使用带相对容差的比较而非裸浮点比较；当两计划代价差在容差内时按稳定次序打破平局，保证计划选择可复现。
7. 实现统计快照加载与版本识别：输入为带版本号与生成时间戳的本地统计快照文件，加载时校验版本变化并整体替换旧快照，不得把新旧快照的统计混合使用；快照校验失败时返回业务错误码 E_SNAPSHOT_INVALID，缺少表统计时返回 E_STATS_MISSING。
8. 提供本地 HTTP API 与完整示例：提交查询描述与快照版本返回计划与代价分解，支持查询指定快照版本；统一错误响应为包含业务码的 JSON；附一个固定样本库的端到端示例脚本，输出三种典型查询的候选索引、估算基数、代价分解与最终选择，供人工核验。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
在本地固定样本上验证选择率估算、索引选择与代价精度契约，并用示例脚本核对计划输出与错误码。
