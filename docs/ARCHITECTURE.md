# 技术设计

## 1. 数据模型

`manifest.json` 逐分片声明：

- `id`、`index`、`image`、`width`、`height`、`pixel_count`、`size_tier`；
- `truth.table`：归一化区域、行/列数、表头行数、合并跨度、真值单元格、文本样本；
- `truth.chart`：归一化区域、柱/折线类型、X/Y 范围、刻度、数据系列真值；
- 顶层的检测、表格、图表和预算配置。

实际 PNG 尺寸在导入时逐一校验；图片内容摘要参与运行 ID 与检测阶段指纹。

## 2. 图像原语

`connected_components` 使用逐行 run-length 扫描和并查集完成确定性 8 连通域标记，返回外接框、面积和可选标签图。投影函数统计连通域自身的像素覆盖率，避免同一外接框内其他组件污染线检测。

刻度数字采用 5×7 位图字形。生成器用矩形绘制并用下划线固定标签宽度；解码器按固定字宽采样 7×5 单元，与模板逐位匹配。该过程不是通用 OCR。

## 3. 表格合并恢复

1. 对表格框内的二值图求行/列覆盖率，得到连续峰组，峰组数量减一即检测行列数。
2. 与清单声明的行列数比较；若交换相等则报告方向冲突，否则报告数量冲突。
3. 对每个相邻单元格检查共享边界线段是否缺线。缺线时合并两个 DSU 节点。
4. 验证每个 DSU 组件是矩形；生成 `(row, col, row_span, col_span)` 与像素范围。
5. 首行若干行的内部采样亮度低于阈值时计为表头。

## 4. 图表提取

- 先在图表面板内部寻找不接触面板边缘、覆盖面积较大的深色矩形组件作为绘图框。
- X 刻度位于绘图框下方，Y 刻度位于左侧；刻度标签在独立条带中按列/行分组。
- X 标签中心与刻度中心对齐后解码数值；Y 标签按刻度纵坐标附近解码。
- 对像素间距与数值间距分别做均匀性检验，再检查轴范围非零。
- 颜色通道差大于阈值的像素组成系列掩码。颜色连通块多且窄判为柱；跨绘图区宽度判为折线。
- 折线标记点通过 7×7 窗口颜色密度峰值定位，避免陡峭线段被误判为标记。
- 轴解码失败时先完成几何提取，并将 `partial.series` 放入错误诊断。

## 5. 确定性

- 所有对外 JSON 使用 UTF-8、排序键、紧凑分隔符、固定换行。
- 浮点数在边界处统一 `round(..., 6)`。
- 并行结果在父进程中按 `(分片序号, 阶段序号)` 排序后发布。
- 导出只包含结构化结果与稳定指纹，不包含时间戳、进程 ID、绝对临时路径或完成顺序。
- 串行/并行通过 `execution_workers` 切换，不改变业务配置、运行 ID 或缓存键。

## 6. 原子记录与恢复

发布流程：

1. 获取 `work/checkpoints/.publish.lock`。
2. 扫描并验证当前记录前缀。
3. 校验下一序号、阶段前置、同阶段分片单调性。
4. 原子写入/校验内容寻址产物。
5. 计算记录摘要链，原子写入 `records/<12位序号>.json`。

记录前缀的判定条件：文件名与 `sequence` 一致、JSON 完整、字段合法、产物哈希匹配、`previous_record_sha256` 等于前一条记录摘要、无重复 `(shard, stage)`。任一条件失败即停止接纳后续记录。

## 7. 失效传播

阶段指纹：

```text
detection  = H(image_sha, detection_config, pipeline_version)
table      = H(detection_fp, table_config, declared_rows, declared_cols)
chart      = H(table_fp, detection_fp, chart_config)
validation = H(table_fp, chart_fp, budget_config, truth, schedule)
```

图表阶段虽然算法上只需检测结果，但按管线顺序显式链接到表格指纹，从而保证“表格容差变化使其全部下游失效”的要求。预算变化只改变验证指纹。

## 8. HTTP 与 CLI

两者共享 `Pipeline`、`import_inputs`、`write_exports`，没有第二套业务逻辑。HTTP 运行在后台线程，停止请求写入工作区 `stop.request`；运行器在阶段批次边界读取该文件。
