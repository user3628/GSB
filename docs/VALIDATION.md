## 停止/恢复验证

自动化测试分别覆盖：

1. `run(max_stages=1)` 后 `resume`，p5 复用，p4/p3 重建，序号严格为 `[1,2,3]`。
2. CLI 带 `--stage-delay` 运行，在 p5 提交后写停止请求；当前层完成后退出；恢复后的关键输出/误差/敏感性文件与一次完整运行哈希完全一致。
3. CLI `--crash-after p4` 使进程退出码为 `137`，删除 `outputs/` 和全部报告、注入半写临时记录后恢复；p5/p4 从检查点复用，p3 重建，最终输出与完整运行逐字节一致。

## 增量验证

自动化测试对以下变化逐项验证“复用层 + 失效层 + 字节一致性”：

| 变化 | 复用 | 重建 | 最早受影响阶段 |
|---|---|---|---|
| `p4` 注意力向量 | `p5` | `p4`, `p3` | `p4` |
| `p3` 融合系数 | `p5`, `p4` | `p3` | `p3` |
| `p4` 量化位宽 | `p5` | `p4`, `p3` | `p4` |
| `p4` 输入分片内容 | `p5` | `p4`, `p3` | `p4` |
| 仅敏感性扰动幅度 | 全部 | 无 | `sensitivity` |

每一行都与使用新清单/新分片从零构建的独立工作区比较以下文件 SHA-256：

```text
p3.npy
p4.npy
p5.npy
final.npy
reports/quantization.json
reports/sensitivity.json
```

结果全部一致。若输入分片变化而高精度参考未同步更新，量化报告会将 `reference_error_within_bound` 标为 `false`，但增量与全量结果仍逐字节一致，说明该标记比较的是来源参考而非复用路径。

## 检查点异常验证

| 场景 | 结果 |
|---|---|
| 完整链 | `normal`，序号 `[1,2,3]` |
| 追加字节篡改 `raw.npy` | `E_STALE_CHECKPOINT`，`tamper`，`artifact_digest_mismatch` |
| 删除最后记录但保留 HEAD | `E_STALE_CHECKPOINT`，`rollback`，`head_ahead_of_records` |
| 替换记录字段但保留旧 HEAD | `E_STALE_CHECKPOINT`，`tamper`，`head_digest_mismatch` |
| 删除 HEAD 后扫描修复 | 恢复为序号 3，后续校验 `normal` |
| 半写 `.tmp` 记录 | 被忽略，链保持 3 条 |
| 重复发布序号 3 | `E_STALE_CHECKPOINT`，`publication_rollback_or_duplicate` |
| 跳跃发布序号 99 | `E_STALE_CHECKPOINT`，`publication_gap` |
| 跨任务发布 | `E_STALE_CHECKPOINT`，`cross_task_publish` |
| 缺失前置阶段 | `E_INVALID_STAGE` |
| 记录替换失败 | 无半写记录，HEAD 仍为 0 |

## 并发验证

同时启动 3 个独立 CLI 进程对同一工作区运行同一任务：

- 三个进程均返回码 0。
- 最终记录数严格为 3。
- 序号严格为 `[1,2,3]`，无重复、无跳跃。
- HEAD 序号为 3。
- 检查点校验为 `normal`。
- 增量对全量校验成功。
- 每个进程返回相同 HEAD 序号 3。
