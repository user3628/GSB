空白仓库里仅有一份关于边缘节点配置分发模块的需求说明，代码尚未开始编写，需要在 Windows 本地从零实现一个可集成的 Go 组件与结果验证工具。组件管理若干边缘节点及其订阅的配置键，配置以带单调版本号的 JSON 快照整体提交，运维还会提交只含局部键改动的增量片段。节点通过本地 HTTP 接口携带观察版本上报其已应用配置摘要与生效时刻，组件需依据订阅关系推导受影响的节点集合、各节点期望配置摘要与跨节点收敛一致度，并回答上报方携带的观察版本能否直接获得收敛结论、哪些必须被拒绝而不能返回陈旧判定。真实场景中增量片段可能触及多个配置键并引发订阅该键的节点级联失效，节点上报可能迟到或携带过期观察版本，进程可能在任意时刻被强制终止。

任务环境与准备：
Windows 10/11 本地环境，安装 Go 1.22 及以上并确认 go version 可用；无需 Docker 或任何容器工具。
用 go mod init 初始化模块，标准库 net/http 与 database/sql 即可；SQLite 驱动建议使用纯 Go 实现（如 modernc.org/sqlite），通过 go get 安装并在 go.mod 中记录版本。
准备一个由 Go 程序自身启动的本地回环节点端点，支持返回已应用摘要、业务拒绝状态码与可配置的响应挂起行为，用于产生真实探测成功、拒绝与超时场景。
准备固定本地 JSON 样本目录，包含配置键与节点订阅样本、增量片段、观察版本与容差配置，以及一个可重复执行的验证脚本入口；所有数据由本地文件与本地端点提供，不依赖外部账号或线上服务。

业务要求：
1. 实现配置键、边缘节点与订阅关系模型：配置键声明键路径、类型、取值与生效顺序号，边缘节点声明标识、所属区域、订阅的配置键集合与上报端点地址；解析本地确定性 JSON 样本时校验节点标识唯一、键路径格式合法、订阅的键均已声明，非法输入返回含业务码的 JSON 错误体且整批不落盘。
2. 实现带单调版本号的配置快照与增量片段提交：快照携带版本号、生成时间与整体校验摘要，增量片段只含受影响的配置键与订阅变更并携带基础版本号；提交时版本号不大于当前已提交版本返回 E_STALE_SNAPSHOT，基础版本不是当前版本返回 E_STALE_BASE，两种情形均不修改任何已提交状态。
3. 实现受影响节点集合与期望配置摘要推导：依据订阅关系计算直接订阅被改键的节点及依赖这些节点的下游节点，输出受影响节点集合、触发键与传播跳数；单节点订阅数覆盖全部配置键时不得退化为逐键扫描全量节点，需按声明阈值选择逐键精算或按区域分桶，并输出所选路径与依据。
4. 实现节点上报摄入与观察版本裁决：上报含节点标识、已应用配置摘要、生效时刻毫秒与观察版本；节点期望摘要版本不高于观察版本时返回收敛结论并标注所用版本，因增量传播未完成而落后于观察版本必须返回 E_STALE_READ 并附期望版本与当前视图版本，禁止返回陈旧摘要冒充结论。
5. 实现基于本地 HTTP 端点的真实收敛探测：对每个待确认节点向其声明端点发起真实请求以拉取当前已应用摘要，单次探测具备独立超时，超时后必须真实关闭底层连接并释放其占用的并发名额，返回 E_PROBE_TIMEOUT；探测结果、节点收敛状态与跨节点收敛一致度必须在同一事务边界内一并更新。
6. 实现跨节点收敛一致度与区域分桶的数值契约：一致度由各节点期望摘要与实际上报摘要的匹配情况按声明权重合成，全程使用整数或显式定点表示并输出每步舍入方式与累计舍入误差；判断一致度是否越过声明阈值时使用带相对容差的定点比较而非裸浮点比较，容差内按区域标识与节点标识稳定字典序打破平局。
7. 实现单写者提交与多读者查询的并发一致及幂等复用：快照提交、增量提交、受影响集合重算与探测轮次按版本单写者串行执行，多个只读查询可并发读取某一完整提交版本；同一提交标识重复提交只执行一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_REQUEST；查询不得看到某节点已判定收敛而其期望摘要尚未落盘的中间状态。
8. 使用 SQLite 持久化快照版本、订阅关系、节点收敛视图、探测记录与意图日志，所有写操作先落意图记录再提交事务；进程在受影响集合重算或探测轮次中途被强制终止后重启须扫描未完成意图，把收敛视图回滚到最后一个完整提交版本或将增量标记为已中止，恢复报告只包含已落盘事实。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
