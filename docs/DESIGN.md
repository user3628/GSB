# 设计说明

## 1. 数据模型

### 工单（JSONL，每行一张）

字段：`ticket_id`、`text`、`channel`、`language`、`intent_label`（多类单标签）、
`priority`（合法范围 0..3）、`agreement`（指针类型，缺失与显式 0 可区分）。

每个分片附带 `<shard>.meta.json` 侧车，声明 `declared_rows`。装载时比对声明行数与
实际行数，不符即返回 `E_SHARD_MISMATCH`，而不是泛化的 I/O 错误。

### 策略快照（单调版本号）

`policy.vN.json` 包含：意图词表权重、三个优先级阈值、平滑强度、哈希维度、分片采样
比例、异常注入开关。任何变更都生成 `Version+1` 的新文件，旧版本保留可回放。

## 2. 规范化与词项抽取

- 先做 Unicode NFKC（同时完成全/半角统一），再小写化，再用 `strings.Fields` 把任意
  空白折叠为单个 ASCII 空格并去首尾。
- 中文（`unicode.Han`）按连续段切出单字（`han_uni`）与相邻二字（`han_bi`）；
  拉丁字母数字按最大连续串切出（`latin`）；标点与其他字符跳过。
- 每个词项带 `rune_start/end`、`byte_start/end`、`channel` 与 FNV-1a 特征桶下标，
  哈希把渠道与词项混合，因此同文本不同渠道落到不同桶，且全程确定。
- 空串或归一化后零词项（纯标点）返回带 `ticket_id` 的 `E_EMPTY_TEXT`。
- 哈希维度 ≤0 在阶段入口即判 `E_CONFIG`，不会静默退化为 0 号桶。

## 3. 朴素贝叶斯意图打分

- 训练集由 `InTrainingSet(ticketID, ratio)` 决定：对工单号 FNV 取模映射到
  [0,1)，小于采样比例即入训练集。该划分与行号、并发归并顺序无关。
- 统计各类文档数（先验）与特征桶条件计数；词汇表大小为 `hashDim+1`，最后一个桶是
  显式未知标记。
- 全程对数域：`log prior + Σ log cond`，加性平滑；训练期未出现的全局特征桶在打分时
  回退未知标记桶，而不是靠「log 值是否为 0」猜测（概率为 1 时 log 合法为 0）。
- 每个加法步骤都做有限性守卫：NaN/Inf、log(0) 下溢返回带工单号、类别与词项上下文的
  `E_NUMERIC`；非正/非有限词表权重判 `E_CONFIG`。
- 类别分数以 map 持久化但经规范 JSON 编码，最高分类别用「分数高者胜、同分按类名字典
  序」决胜，保证同输入同配置逐字节一致。

## 4. 优先级与标签裁决

- 三个严格递增阈值把最高意图分映射为基础优先级 0..3。
- 一致度合成规则：
  - 一致度缺失：按 0 处理，优先级封顶 1，记录 `D_AGREEMENT_MISSING`；
  - 一致度 <50：优先级封顶 2，记录 `D_AGREEMENT_LOW`；
  - 标注优先级越界（非 0..3）：返回 `E_LABEL_RANGE`，同时保留诊断结果并标
    `D_LABEL_RANGE`、裁定为 `excluded`，样本不被静默丢弃。
- 预测与标注比对输出 `hit`（相等）、`missed`（预测偏低）、`false`（预测偏高）。

## 5. 检查点与 SQLite 模式

`checkpoints` 表对 `(stage, ticket_id)` 建唯一约束，含全局自增 `seq`、阶段内连续
`stage_seq`、输入/配置/产物指纹、摘要、状态与业务码；`stage_runs` 表记录每阶段每代的
配置指纹、输入指纹、阶段摘要与逻辑时间戳。

阶段摘要是对该阶段全部检查点（按 `stage_seq` 排序、只取工单号与内容指纹等）的
SHA-256，因此阶段一结束即可得，且重放、增量、崩溃恢复三者一致。

## 6. 发布协议三态识别

对同一 `(stage,ticket_id)` 的发布请求：

- 内容与序号完全相同 → `duplicate`（幂等成功）；
- 新行序号恰为 `max+1` 且为正常推进 → `accepted`；
- 序号变小 → `rollback`；同序号但指纹/摘要变化 → `replacement`；
  序号非 `max+1` → `out_of_order`；后三者统一拒绝为 `E_STALE_CHECKPOINT`。

跨进程互斥由工作区 `pipeline.lock` 上的 `flock(2)`（POSIX）/`LockFileEx`（Windows）
保证，库内再以条件 UPDATE/INSERT 兜底竞态。

## 7. 恢复边界

- 一切阶段产物写入与检查点发布在事务边界内完成；WAL 模式保证已提交即持久。
- 重启后 `hydrate` 只读已提交检查点还原内存态；`planReuse` 用「该阶段应有检查点数」
  （由输入纯函数推导，空文本等上游失败不计入下游）识别中途被杀的不完整阶段，并从该
  阶段整体重建，避免用残缺词表训练。
- 重建阶段 `stage_seq` 重置为从 1 连续；`AssertContiguous` 与验证命令负责校验无跳跃、
  无重复、每工单每阶段仅一条有效记录。

## 8. 关键取舍

- 配置指纹刻意**不含**版本号与注入开关本身：注入通过具体数值字段生效（如零平滑即
  `smoothing=0`），单纯版本号提升不应触发无谓全量重建；版本号仍逐行记录用于审计。
- 报告的阶段自摘要留空并在报告定稿后由阶段摘要承载，避免「摘要包含自身」的自指哈希。
- 数据库句柄串行化（单连接）+ WAL + 文件锁，换取跨平台与跨进程的简单确定性，而非
  追求单库高并发吞吐。
