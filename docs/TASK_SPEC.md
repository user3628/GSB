车载语音团队在 Windows 空白工作区启动一个多音区交互引擎项目，为上层语音助手交付可集成的领域组件与可重复演示。程序内置固定种子生成器在本地产出 16 kHz、单声道、16 位 PCM WAV 分片，每片按清单声明偏移依次拼接主驾、副驾、后排左右四个音区的信号；另附 JSON 会话清单声明各音区样本起止偏移、参考语音活动区间（毫秒整数）与参考指令词表命中结果，作为真值与观测来源。引擎按逐音区活动检测、跨音区指令归属、统一毫秒时间轴状态演进、交互查询四个阶段推进，每阶段以带单调序号的 SQLite 事务快照记录。需求方希望先看到完整可演示版本：交互查询须满足毫秒级延迟预算，而同一批查询在并发编辑下必须与结算侧全量计算结果逐条一致，延迟预算与结果一致性之间的取舍是本题核心冲突。

任务环境与准备：
Windows 10/11 开发机，安装 Go 1.22 或以上（go version 确认），无需外部网络。
使用 Go 标准库与 mattn/go-sqlite3（v1.14.22）或纯 Go SQLite 驱动 modernc.org/sqlite（v1.29.0），按本地模块缓存或 vendor 目录获取。
确认本地临时目录可写，样本、SQLite 数据库与工作区均放在该临时目录下。
程序内置固定种子生成器负责产出 WAV 分片与会话清单，运行前无需手工准备数据。

业务要求：
1. 实现逐音区语音活动检测：按清单音区偏移切出各路信号，以可配置帧长与帧移做汉宁窗分帧，帧长帧移以毫秒声明但须显式换算为整数采样点并记录换算值；逐帧计算对数能量与频谱平坦度合成得分，用高阈值进入、低阈值退出的滞回状态机判定活跃帧，叠加最短语音段与最短静音段后输出各音区活动区间（毫秒起止）。同一输入与配置必须产生逐字节一致的活动区间清单。
2. 实现跨音区指令归属与到达时延估计：以各音区活动区间起止毫秒计算两两到达时延差，按可配置声速与音区几何先验转换为距离差得分，再与参考词表命中强度在对数域合成归属分，为每条疑似指令判定唯一责任音区；最高两名归属分差低于可配置间隔阈值时标为歧义并保留全部候选与依据，不得静默取其一。
3. 实现统一毫秒时间轴与音区编辑模型：以毫秒整数维护各音区活动区间、重叠活动标记、语音来源音区与指令归属记录，支持切分区间、合并相邻同类区间、调整音区优先级与编辑命中词表条目；每次编辑生成单调编辑版本号，记录操作者、被影响区间与依据，编辑后所有下游状态须可复算。
4. 实现交互查询的延迟预算与缓存一致性：单次查询（时刻活跃音区集合、时延差明细或指令归属依据）须在可配置延迟预算内返回，超出预算时返回带查询标识与已耗时字段的 E_LATENCY_BUDGET 结构化错误而非阻塞等待；缓存键须包含查询区间、配置版本与编辑版本号，命中结果与重新计算结果逐字节一致。
5. 实现增量重算与全量一致性校验：当音区优先级、命中词表、帧参数、滞回阈值或归属间隔阈值修改时，依据各阶段内容摘要构成的版本指纹识别受影响的最早阶段，仅重算该阶段及其下游，未受影响上游结果继续复用；增量结果须与从零全量构建的活动区间、归属结果与汇总摘要逐字节一致，不一致返回 E_INCREMENTAL_MISMATCH 并附首个差异区间。
6. 实现 SQLite 事务化阶段快照与优雅停止恢复：每分片每阶段完成时以事务写入含阶段名、分片内容指纹、配置版本、编辑版本号、产物摘要与单调序号的记录，同一分片同一阶段只允许一条有效记录；收到停止请求时完成当前不可拆分单元后落库退出，不承诺强制终止后生成退出报告，强制终止后的恢复只依赖已提交的持久化事实，恢复后结果与一次连续执行逐字节一致。
7. 实现快照整体替换识别与并发发布保护：多工作进程发布阶段产物时使用 SQLite 条件更新与真实文件锁并比较分片内序号，仅允许序号连续推进，落后、重复或跨分片错位发布返回 E_STALE_CHECKPOINT；当检测到快照记录被整体替换（序号回退、指纹变化或摘要不匹配）时须区分回退、篡改与正常推进，仅正常推进被接受，其余拒绝并保留诊断。
8. 实现外部参数注入的异常链路与业务错误码一致性：支持注入清单声明样本总数与实际不符、采样率与清单冲突、某音区偏移重叠、说话人数上限为零、掩码迭代轮数为负与音区声速非正等情况；各注入须在对应阶段返回稳定业务码（如 E_SAMPLE_COUNT_MISMATCH、E_RATE_CONFLICT、E_INVALID_PARAM）并附分片标识与阶段名，不得以抛栈或静默跳过代替。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
