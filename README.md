当前是空白工作区，没有现存项目、代码或数据附件，需从零构建一个本地可运行的车内多音区语音活动仲裁与指令归属引擎，交付可集成的领域组件与完整示例。输入为固定随机种子生成器产出的本地 WAV 分片（16 kHz、单声道、16 位 PCM），每个分片模拟一段车内录音，主驾、副驾、后排左右共 4 个音区的信号按清单声明偏移依次拼接存储；另附 JSON 会话清单声明各音区样本起止偏移、参考语音活动区间（毫秒）、参考指令词表命中结果与音区优先级，作为真值与观测来源。引擎需依次完成分帧与逐音区活动检测、跨音区到达时延估计、指令归属仲裁与状态演进汇总，并支持中断后恢复。

任务环境与准备：
安装 Python 3.11 与 NumPy、pytest，使用标准库 http.server 提供本地接口，不引入容器或外部服务
从空工作区创建项目目录，编写固定种子的样本生成器，按清单生成 3 个以上多音区 WAV 分片、参考活动区间、词表命中结果与音区优先级
准备至少一份音区偏移越界的注入用例与一份音区重叠指令用例，供异常链路与仲裁路径演示
运行方式为本地命令行与本地 HTTP 接口，全部样本与真值随项目生成，不下载外部数据

业务要求：
1. 实现分帧与逐音区活动检测核心：按清单音区偏移切出各路信号，以可配置帧长与帧移做汉宁窗分帧，逐帧计算对数能量与频谱平坦度并合成得分，用高阈值进入、低阈值退出的滞回状态机判定各音区活跃帧，再叠加最短语音段与最短静音段后处理；高阈值低于低阈值、帧移为零等非法配置须在启动时返回带音区标识与参数名的 E_INVALID_CONFIG。
2. 实现跨音区到达时延与指令归属仲裁：以各音区活跃区间起止毫秒计算两两到达时延差，按可配置声速与音区几何先验转换为距离差得分，与参考词表命中强度在对数域合成归属分，为每条疑似指令判定唯一责任音区；最高两名归属分差距小于可配置间隔阈值时须标为待复核并保留两者依据，不得静默取其一。
3. 实现统一毫秒时间轴与音区编辑模型：以毫秒整数维护各音区活动区间、重叠活动标记、语音来源音区与指令归属记录，支持切分区间、合并相邻同类区间、调整音区优先级与编辑命中词表条目；每次编辑生成单调编辑版本号并记录操作前后摘要，同一编辑序列必须得到逐字节一致的区间集合与版本轨迹。
4. 实现状态演进的阶段检查点：每分片按分帧检测、时延估计、归属仲裁、汇总四阶段推进，每阶段完成时以原子方式写入含阶段名、分片内容指纹、配置版本、编辑版本号、产物摘要与单调序号的记录，写入任意位置中断不得留下半写记录；恢复时必须忽略损坏、不完整或序号重复的记录并从最近一致检查点继续。
5. 实现优雅停止与恢复一致性：进程收到停止请求时完成当前不可拆分的分片与状态演进单元后退出，不承诺强制终止后生成退出报告，强制终止后的恢复仅依赖已写入的持久化记录；恢复后最终活动区间、重叠标记、归属结果与汇总摘要必须与一次从零完整运行的对应产物逐字节一致，且检查点序号连续推进、无跳跃与重复。
6. 实现版本变化检测与增量失效传播：当某分片样本内容、音区优先级、命中词表、帧参数、滞回阈值或归属间隔阈值任一变化时，通过各阶段内容摘要构成的版本指纹识别受影响的最早阶段，使该阶段及其全部下游产物失效并重建，未受影响上游结果继续复用；失效原因与指纹须可在查询中观测。
7. 实现增量与全量一致性校验及业务错误码：提供单分片样本替换与单配置变更入口，仅重建失效链路后与从零全量构建的活动区间、归属结果与汇总摘要做逐字节摘要比对，不一致须返回 E_INCREMENTAL_MISMATCH 并附首个差异位置；音区偏移越界、参考词表缺失、分数出现 NaN 或 Inf 时分别返回稳定业务码。
8. 实现并发发布保护与本地演示工作台：多个工作进程对同一工作区发布阶段产物时使用真实文件锁并比较分片内序号，仅允许序号连续推进，落后、重复或跨分片错位发布返回 E_STALE_CHECKPOINT；命令行与本地 HTTP 接口支持导入分片与清单、查询各阶段状态与版本指纹、请求停止与恢复，演示数据至少 3 个分片覆盖多音区同时活跃与重叠指令。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
