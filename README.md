当前为空白工作区，需从零构建一个面向中文检索场景的稀疏倒排索引构建与压缩查询管线，交付数据处理管线与结果验证工具。输入为固定随机种子生成器产出的本地 JSONL 文档分片，每条含 doc_id、标题、正文、lang 与 source 字段，覆盖中英混排、重复文档与少量空正文字档；另附一份 YAML 索引配置，描述分词粒度、停用词表、跳表步长、倒排列表分块大小、差值编码与变长字节编码参数、查询缓存容量以及查询延迟预算。管线需按四个阶段推进：分词与词项编号、文档频次与权重统计、倒排列表构建与压缩、压缩查询执行与结果汇总。核心难点在于交互式查询延迟与计算结果一致性之间的冲突：压缩后的倒排列表必须支持按需解压与跳表加速，但任何缓存、分块预解压或跳表跳跃都不能改变查询命中集合与打分结果。系统需支持阶段检查点、优雅停止后恢复，并在文档内容或索引参数变化时识别受影响阶段及其下游产物失效重建。

任务环境与准备：
Windows 本地环境，安装 Python 3.11 与 NumPy，安装说明放入 requirements.txt，全程不依赖容器、外部服务或网络。
在工作区创建 data/ 目录，用固定随机种子生成至少 3 个 JSONL 文档分片（含中英混排、跨分片近似重复与空正文字档）与对应 YAML 索引配置，生成脚本随项目提供以保证可重建。
准备参考实现所需的顺序遍历求交脚本与基准查询集清单，作为结果一致性比对与延迟预算的本地观测来源。
准备错误注入参数样本（非法跳表步长、越界查询、非法阶段跳转）用于触发异常链路验证，注入不改动源码。
演示运行使用本地文件与本地 HTTP 服务，输出固定摘要与查询命中清单，便于复现。

业务要求：
1. 实现分词与词项编号阶段：对标题与正文分别做 Unicode NFKC、空白折叠、全半角统一与小写化，中文按单字与相邻二字组合切分、拉丁字母数字按连续串切分，去除停用词后为每个词项分配稳定单调递增的整数编号，并输出带词项编号与词频的文档词项记录；空正文字档须保留 doc_id 并从索引中标记为空文档，同一输入与配置必须产生逐字节一致的编号表。
2. 实现文档频次与权重统计：统计每个词项的文档频次、每篇文档长度与平均文档长度，按可配置的 BM25 参数计算文档-词项权重，权重须以定点量化方式存储并记录每词项的量化缩放因子；词项在所有分片中均未出现、或权重出现 NaN 与 Inf 时须返回带 doc_id 与词项编号的业务错误码 E_WEIGHT_NUMERIC，不得静默写零。
3. 实现倒排列表构建与压缩：每个词项的倒排列表按 doc_id 升序组织，采用差值编码后以变长字节编码写入分块，分块大小可配置；为每个倒排列表稀疏构建跳表并记录跳表步长与对应 doc_id；解压任意分块得到的 doc_id 与权重序列须与未压缩原始序列完全一致，压缩前后查询结果必须逐条一致，任何分块边界处的解压错误须被检测并报告。
4. 实现压缩查询执行与打分汇总：支持多词项的与、或两种查询语义，利用跳表在两个及以上倒排列表间做跳跃求交，按需解压命中的分块并累加量化权重后还原为浮点分数，输出按分数降序、同分按 doc_id 升序的命中清单与分量明细；查询执行不得预解压全部倒排列表，命中集合须与逐条遍历求交的参考实现完全一致，差异须以 E_QUERY_MISMATCH 报告涉及的词项编号。
5. 实现查询缓存与延迟预算：单次查询须在可配置延迟预算内返回，超出预算时返回带查询标识与已耗时字段的 E_LATENCY_BUDGET 结构化错误，而非阻塞等待或静默截断结果；缓存键须包含查询词项集合、查询语义、索引配置版本指纹与阶段产物摘要，缓存命中结果须与未命中时逐字段一致，缓存容量淘汰不得影响正确性。
6. 实现持久化阶段检查点与优雅停止恢复：每阶段完成时以原子方式写入含阶段名、输入分片内容摘要、配置版本、产物摘要与单调序号的记录，写入过程任意位置中断不得留下半写记录；进程收到停止请求时完成当前不可拆分的文档或词项单元后退出，不承诺强制终止后生成退出报告；恢复时须忽略损坏、不完整或序号重复的记录并从最近一致检查点继续，最终索引与查询结果同一次完整运行逐字节一致。
7. 实现版本变化检测与增量失效传播：当文档内容、停用词表、跳表步长、分块大小、编码参数、BM25 参数或缓存配置任一变化时，通过各阶段内容摘要构成的版本指纹识别受影响的最早阶段，使该阶段及其全部下游产物（含缓存条目）失效并重建，未受影响上游产物继续复用；失效原因、受影响阶段与新旧指纹须在状态查询接口中可观测，禁止复用旧版本缓存命中结果。
8. 实现并发发布保护与本地确定性演示工具：多工作进程对同一工作区发布阶段产物时使用文件锁并比较序号，仅允许序号连续推进，落后、重复或跨阶段错位发布返回 E_STALE_CHECKPOINT，非法阶段跳转或缺失前置产物返回 E_INVALID_STAGE；演示工具须用至少 3 个文档分片（含跨分片近似重复、中英混排与空正文档）生成固定摘要一次完整构建，验证缓存命中与未命中结果一致、缓存淘汰后正确性不变，并用注入的非法跳表步长与越界查询验证错误码。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地分片完成构建后，验证与、或查询结果同参考遍历一致，缓存与淘汰不影响正确性，停止恢复及错误码可复现。
