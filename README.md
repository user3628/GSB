本地特征平台要把文本分类、短文本情感与意图标注三路上游任务产出的历史样本迁移到统一特征空间，工作区里还没有任何代码。样本由程序内置固定种子生成器确定性产出，每路分片含 sample_id、任务标识、原始文本、标签、任务版本号与可选特征覆盖声明。迁移配置以带单调版本号的 JSON 快照与只含局部字段改动的增量片段提交，声明哈希维度、任务到特征空间的映射规则、标签重编码表、覆盖阈值与每轮处理预算。引擎需把各任务样本规范化后映射到统一哈希特征空间，为每个样本生成带任务来源与映射依据的特征记录；当任务版本、映射规则或覆盖阈值变化时，判定受影响的最小样本集合与特征记录，依据 SQLite 中已提交事实做增量重建而非整体重算，并回答携带观察版本的读取方哪些记录可直接返回、哪些必须拒绝。

任务环境与准备：
Windows 10 或以上，安装 Go 1.22 或以上（go version 检查），无需第三方数据库服务。
使用 SQLite 嵌入式驱动（如 modernc.org/sqlite），通过 go mod tidy 拉取，离线环境需预先准备模块缓存。
无需外部数据集、账号或 GPU；样本由题目要求内置的固定种子生成器在本地产出。
默认工作目录为空，所有源码、配置与本地 SQLite 库文件均在该目录内创建。

业务要求：
1. 实现样本规范化与跨任务统一特征映射核心：对原始文本做 Unicode NFKC、空白折叠与全半角统一后按中文单字加相邻二字与拉丁连续串切分，以配置的哈希维度与任务映射规则生成特征记录，并记录每个特征位的来源任务、映射词项与映射版本；同一输入与配置必须产生逐字节一致的特征记录，哈希维度为零、映射规则缺失某任务或文本为空时须返回带 sample_id 与任务标识的业务码。
2. 实现标签重编码与覆盖声明校验：依据标签重编码表把各任务标签映射到统一标签集合，任务版本号与映射表版本不一致时须按显式降级规则处理并在记录中标注；当某任务样本的实际特征覆盖低于覆盖阈值，或标签无法映射时，须单独输出不可迁移样本清单与原因，处理流程继续且输入样本总数与输出计数守恒。
3. 实现增量片段应用与依赖失效传播：接受只含局部改动的增量片段，通过各阶段内容摘要构成的版本指纹识别受影响的最早阶段与最小样本集合，仅重建该集合及其下游特征记录，未受影响记录继续复用；当任务版本号回退或映射表被整体替换时须区分情形并触发全量特征空间重建。
4. 实现 SQLite 事务化的阶段检查点与强制终止恢复：每阶段与每个不可拆分样本单元完成时以事务写入含阶段名、样本内容指纹、配置版本、产物摘要与单调序号的记录，同一阶段同一单元只允许一条有效记录；进程被强制终止后重启仅凭已提交事实重建进度，不承诺生成退出报告，恢复后的特征记录须与一次连续执行逐字节一致。
5. 实现携带观察版本的陈旧读裁决：读取方请求特征记录时须携带观察版本，低于当前生效版本时返回 E_STALE_READ 并附当前版本与最小可接受版本，而不是给出陈旧值；版本相等但对应阶段检查点缺失或摘要不匹配时须返回带缺失阶段名与样本标识的 E_STALE_CHECKPOINT，不得静默返回部分结果。
6. 实现并发提交互斥与版本连续推进：多工作进程对同一 SQLite 库提交配置版本或特征记录时使用条件更新与真实文件锁，仅允许版本号与样本内序号连续推进，落后、重复或跨任务错位提交返回 E_STALE_VERSION 并附当前生效版本；并发下不得出现同一特征记录的多个有效版本并存。
7. 实现跨任务特征覆盖一致性汇总：按任务、统一标签与映射版本统计样本数、覆盖命中的特征位数、被拒绝记录数与覆盖阈值余量，汇总须与逐样本特征记录按 sample_id 排序后累加的结果一致；分母为零时须显式记为不适用并计数，不得从缺失样本推断覆盖情况。
8. 提供本地 HTTP 与命令行交互接口及确定性演示：支持导入三组任务分片与配置快照、提交增量片段、触发分阶段迁移、查询各阶段状态与版本指纹、执行带观察版本的读取、查看失效原因与覆盖汇总、请求优雅停止与执行恢复；演示数据至少三组任务、跨任务版本变化一次与强制终止恢复一次，完整运行产生固定摘要。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
