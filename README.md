团队准备新建一个项目，针对二进制文件格式解析器在状态演进过程中出现的恢复不一致问题，构建本地可交互的审计引擎。目标格式为一种自定义的带长度前缀分块二进制容器，块类型包括元数据头、变长记录、嵌套子块和校验尾块，解析器需要能处理截断、校验失败、超长长度、类型未知及嵌套深度超限等畸形输入。审计引擎需在单次解析会话内维护解析状态快照，并在遇到可恢复错误（如单个记录校验失败）时记录错误位置与上下文并继续处理后续块，遇到不可恢复错误（如长度越界）时保存当前进度并按策略回滚到最近一个安全检查点。同时需支持并发解析多个样本文件，每个会话独立隔离，结果汇总到统一报告。最终交付一个命令行可交互程序，能够加载本地样本目录、逐步回放解析过程、展示状态迁移轨迹，并导出结构化审计报告。

任务环境与准备：
安装 Go 1.22 或以上版本（https://go.dev/dl/），确认 go version 可用。
在 Windows 工作区创建项目目录，初始化 Go module，不引入外部网络依赖。
准备本地确定性样本生成工具（作为项目内代码或脚本），生成六类样本文件至本地 samples 目录。
确保终端支持交互输入与标准输出重定向，用于逐步回放与报告导出。

业务要求：
1. 实现自定义二进制容器的流式解析器，按块头中的类型字段与变长长度字段定位块体，严格校验块边界不得越出当前文件长度，对截断块给出稳定错误码 E_TRUNCATED 并保留已读字节计数。
2. 在解析会话内维护状态快照与检查点机制：每成功解析一个完整块后提交快照，遇到块级校验失败时按配置策略选择继续或回滚到最近检查点，回滚后输出的状态必须与提交时记录的快照字节一致，版本号递增可识别。
3. 支持可交互的逐步回放模式，允许用户单步执行解析、查看当前偏移、块类型、累计校验值与状态版本，并能在任意步骤导出当前快照用于外部比对，回放过程不得依赖随机因素。
4. 实现并发样本审计调度，每个样本在独立会话中解析，会话间状态隔离，汇总时按样本路径与错误码聚合；并发度可配置且有上限，超过上限的请求排队而非直接拒绝，所有并发错误必须可追溯至具体样本偏移。
5. 对畸形输入注入验证异常链路：构造长度字段远超实际数据的记录、循环嵌套子块、未知块类型、校验尾块缺失四类样本，分别给出 E_LENGTH_OVERFLOW、E_DEPTH_EXCEEDED、E_UNKNOWN_TYPE、E_MISSING_TRAILER 业务码，且不因单个块异常导致整个会话崩溃。
6. 设计并实现嵌套子块的深度与总量双约束，深度超过 8 层或单个父块内子块累计声明长度超过父块剩余长度时终止该子树解析，回退到父块上下文继续兄弟块，状态迁移轨迹中记录子树终止点与父块恢复点。
7. 导出结构化审计报告为 JSON，包含每个样本的块序列摘要、状态版本变迁、错误码及偏移、最终是否完成，报告需与交互模式展示的信息一致；报告中的版本号必须来自实际快照递增，不得预估。
8. 提供可重复演示入口，使用本地生成的确定性样本集（包含正常、截断、校验失败、超长、深嵌套、未知类型六类文件）一键运行审计并输出报告摘要，重复运行结果字节级一致，同时支持通过参数切换继续与回滚两种恢复策略并对比差异。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地六类确定性样本验证解析交互、状态快照回滚与并发审计报告的一致性，重复运行结果相同。
