训练框架的通信组把梯度分片聚合组件的首次落地交给了小团队，工作区尚无任何实现，需要从第一行代码交付可集成组件与可复现实验环境。训练分为若干工作节点，每轮各节点按参数分片提交梯度块，块内包含形状声明、定点量化缩放因子与逐元素 int32 量化值；聚合端需按分片把各节点梯度块归并为全局梯度，并据定点链路输出可复核的舍入误差。与外部训练工具互换数据的约束使持久化必须同时支持紧凑二进制与分片 JSON 行两种格式：二进制以魔数、格式版本字节、长度前缀和 CRC32 组织，JSON 行以文本字段组织，两代格式在缩放因子精度与空分片语义上存在差异。聚合批次受全局并发聚合上限、每轮时间预算与单分片字节预算三重约束，进程可能在聚合中途被强制终止，重启后必须依据 SQLite 中已提交事实恢复。

任务环境与准备：
安装 Go 1.22 或更高版本（如 go1.22.5），确认 go 命令与 GOCACHE 可用；安装现代 C 编译器与 SQLite 开发库（如 libsqlite3-dev），以便 go-sqlite3 驱动编译通过。
在空工作目录初始化 Go 模块并放入 `go.mod`，添加 SQLite 驱动与标准库依赖，运行一次 `go mod tidy` 确认依赖可离线解析；不依赖任何外部服务、GPU 或真实模型。
实现内置的固定种子生成器，产出确定性样本：若干工作节点、若干轮次与参数分片的 int32 量化梯度块及对应的缩放因子，并生成同一逻辑数据的二进制与 JSON 行两种格式文件，以及高精度参考聚合结果作为唯一真值来源。
准备本地回环 HTTP 测试能力的说明性前置条件（使用标准库即可），确保服务可在本地端口启动并被同一进程内的测试客户端访问；所有验证命令均为 Linux（WSL Ubuntu）下可执行的 go test 或 go run。
确认运行环境的临时目录可写，用于存放生成样本、二进制与 JSON 行导出文件及 SQLite 数据库文件；无需容器、网络代理或云计算资源。

业务要求：
1. 实现梯度块与聚合策略快照模型：节点声明标识、权重与所属通信组，梯度块记录节点标识、轮次、分片标识、形状、定点量化缩放因子（整数，表示 2 的负幂次）、int32 量化值与内容摘要，策略快照携带单调递增版本号、生成时间、参与节点集合、全局并发聚合上限、每轮时间预算与单分片字节预算；解析时校验形状维度为正整数、缩放因子在允许范围内、量化值数量与形状乘积一致，失败返回 E_GRAD_INVALID。
2. 实现两种持久化格式的编解码：紧凑二进制格式必须含魔数、格式版本字节、每条记录长度前缀、CRC32 校验与可选字段存在位图，缩放因子以单字节指数承载；分片 JSON 行格式每行含节点标识、轮次、分片标识、形状、缩放因子与量化值数组；两种格式对同一逻辑记录的语义必须一一对应且可互换往返，往返后逐元素相等，并输出每条记录的格式版本与解析路径。
3. 实现格式协商与版本兼容裁决：导入前检测输入格式与格式版本，按可从配置读取且可覆盖的兼容矩阵给出接受、降级接受与拒绝三种结论；旧版本整数比例表示的缩放因子须降级接受并换算为 2 的负幂次指数并记录降级明细，旧版本以空数组表示缺失分片时须降级为显式缺失标记；高版本含未知必填字段或魔数不符时拒绝并返回 E_FORMAT_INCOMPATIBLE，任一拒绝不得影响已加载数据。
4. 实现定点量化数值契约：量化与反量化全程使用整数运算，反量化得到以 2 的负幂次表示的有理数并按声明的舍入方式写入输出；逐元素比较聚合结果与本地参考实现时输出最大绝对偏差与相对偏差，并对每个分片输出每步舍入的位与累计舍入误差上界；同一批梯度块无论一次聚合还是分批聚合，误差声明必须逐片一致，偏差越界返回 E_PRECISION_BOUND。
5. 实现按分片的加权聚合与缺块裁决：各节点梯度块按策略快照声明的节点权重加权归并，权重和不为 1000 时按声明归一化并输出归一化后的权重；某分片仅部分节点提交时按声明的最小参与比例判定降级聚合或应等待，降级后须输出参与节点集合、缺失节点与降级依据；参与节点数不足返回 E_INSUFFICIENT_PARTICIPANTS，权重与量化值累加使用 int64 并在每步校验不越界，越界返回 E_NUMERIC_OVERFLOW。
6. 实现并发聚合调度器：聚合任务受全局并发聚合上限、每轮时间预算与单分片字节预算共同约束，预算内按分片优先级与分片标识稳定次序取任务，超出并发上限的任务进入有界等待队列，队列满返回 E_AGG_QUEUE_FULL；单分片估算字节超过单分片预算时返回 E_SHARD_TOO_LARGE 并附估算字节与预算，调度轮次须输出本轮取用的分片清单、排队长度与剩余预算。
7. 实现单写者提交与多读者查询的并发一致及幂等：梯度块导入、聚合批次提交与派生结构重建按提交单写者串行执行，多个只读查询可并发读取某一完整提交版本，不得出现某分片已标记聚合完成而其误差声明尚未落定、或节点权重已更新而聚合结果仍按旧权重的中间可见状态；同一批次标识重复提交只执行一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_BATCH。
8. 实现基于 SQLite 的意图持久化与强制终止后恢复：梯度块导入、聚合批次提交、降级裁决与格式切换前先写意图记录再提交事务；进程在聚合或导入中途被强制终止后重启须扫描未完成意图，把未提交聚合回滚为待聚合、未提交导入丢弃，恢复报告只包含已落盘事实与未完成意图清单；同时提供本地 HTTP 接口覆盖两种格式导入、聚合批次提交、按版本查询分片聚合结果与误差声明、降级明细查询与恢复报告查询，失败响应为含业务码与上下文的 JSON。
