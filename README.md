在全新工作区中，需要从零构建一个面向本地单机推理服务集群的伸缩策略迁移与副本预算重估组件，供推理平台在策略模型升级期间离线核对新旧策略语义是否等价。平台的伸缩策略历史以旧版扁平 JSON 保存：服务标识、固定副本数、每副本显存字节、每副本算力份额（千分之一整数）、是否允许弹性伸缩与若干废弃字段。新版策略改为分层模型：副本上下界、按目标并发与延迟预算推导的弹性规则、引用配额组获得显存与算力上限、以千分比整数表示的跨服务权重，并且需要以两种可互换格式持久化：紧凑二进制格式（含魔数、格式版本字节、大小端标记、长度前缀、CRC32 校验与可选字段存在位图）与分片 JSON 行格式。运维团队需要把旧格式策略迁移到新模型，同时支持增量片段提交与跨服务加权伸缩指数重估。难点在于格式互操作与版本兼容下的语义迁移裁决：旧版缺少弹性规则与权重，必须按显式兼容矩阵降级补齐；迁移后副本预算与加权指数必须与旧版固定副本数在声明容差内自洽；某个服务权重或配额组引用变化时，其期望副本数、副本放置索引与加权伸缩指数必须级联失效并原子重建。所有样本均为本地确定性数据。

任务环境与准备：
安装 Go 1.22 或以上版本，确认 go version 可执行。
使用标准库 net/http 与 encoding/json，SQLite 通过 modernc.org/sqlite 纯 Go 驱动接入，执行 go mod tidy 拉取依赖。
准备固定的本地样本：旧版扁平策略 JSON、新版两种格式的策略文件与增量片段、配额组清单，全部使用固定数值生成。
确认本地回环端口可监听，用于演示脚本中的 HTTP API 与恢复报告查询。

业务要求：
1. 实现旧版扁平策略与新版分层策略的解析：旧版含服务标识、固定副本数、每副本显存字节、每副本算力份额、是否允许弹性伸缩与废弃字段；新版含副本上下界、目标并发、延迟预算毫秒、配额组引用与千分比权重。解析时校验服务标识唯一、副本上下界为正整数且下界不大于上界、资源与权重做溢出与范围检查，失败返回 E_SPEC_INVALID 且整批不入库。
2. 实现两种新版持久化格式的编解码：紧凑二进制格式必须含魔数、格式版本字节、大小端标记、每条记录长度前缀、CRC32 校验与可选字段存在位图；分片 JSON 行格式每行含服务标识、副本上下界、目标并发、配额组引用与权重。任一格式解析出未知记录类型、长度前缀越界或校验摘要不一致时返回 E_RECORD_CORRUPT 并指明记录序号。
3. 实现格式协商与版本兼容矩阵裁决：导入前检测输入格式与格式版本，按显式声明的兼容矩阵给出接受、降级接受或拒绝三种结论；旧版缺弹性规则与权重时降级接受，按声明规则由固定副本数推导副本上下界并将权重补齐为默认千分比，记录降级明细；高版本含未知必填字段的数据返回 E_FORMAT_UNSUPPORTED，不得静默忽略。
4. 实现跨版本语义迁移裁决与副本预算重估：把旧版固定副本数映射到新版分层模型时，判定废弃字段是否可迁移、配额组引用是否存在、迁移后推导出的期望副本数是否与旧版固定副本数在声明容差内自洽；可完整映射的接受并输出映射依据，不自洽的标记为需人工确认并返回 E_MIGRATION_AMBIGUOUS，同时仍须给出不自洽的数值明细。
5. 实现派生结构的引用关系与级联失效：为每个服务维护其对期望副本数、副本放置索引与跨服务加权伸缩指数的引用关系；当权重、配额组引用、副本上下界或目标并发变化时，受影响服务的全部派生结构及依赖它们的加权指数必须级联失效并在同一事务边界内原子重建，禁止出现期望副本数已更新而加权指数仍为旧值的中间可见状态。
6. 实现跨服务加权伸缩指数的数值契约：指数由各服务期望副本数按千分比权重加权合成，使用整数或显式定点表示，加权累加使用补偿求和并输出每步舍入方式与累计舍入误差；比较指数是否越过声明阈值时使用带相对容差的定点比较而非裸浮点比较，容差内视为未越界并按服务标识稳定字典序打破平局。
7. 实现增量片段提交与基础版本校验：增量只含受影响的策略字段并携带基础版本号，基础版本不是当前已提交版本时返回 E_STALE_BASE 且不改变任何已提交状态；同一基础版本的两个并发增量只允许一个成功、另一个必须收到 E_STALE_BASE；格式协商结果与迁移裁决结论须绑定同一快照版本，不得出现按新格式补齐而按旧格式判定权重的情形。
8. 使用 SQLite 持久化旧版与新版策略、迁移批次、派生结构、引用关系与意图日志，写操作先写意图记录再提交事务；进程在级联重建或格式导入中途被强制终止后重启须扫描未完成意图，把策略集合与派生结构回滚到最后一个完整版本或将迁移批次标记为已中止，恢复报告只基于已持久化事实，并提供统一业务码 JSON 错误体与可重复演示脚本。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定样本验证双格式导入、降级补齐、迁移自洽判定、级联重建与强制终止后恢复报告。
