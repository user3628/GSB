原型先行的小团队需要在本地回环环境下验证一个多租户丢包诊断引擎的核心链路：租户通过本地 HTTP 接口提交带版本号的探测目标快照与只含局部改动的增量片段，引擎依据租户配额、全局并发探测上限与每轮时间预算，向本地测试端点发起真实 TCP 探测与 UDP 丢包采样，累计丢包率与往返时延分位，维护每个租户的诊断视图，并回答携带观察版本的读请求能否直接返回、哪些必须拒绝而不能给出陈旧值。真实场景中热点租户与长尾租户并存，探测结果会因并发抢占与超时而部分缺失，进程也可能在探测批次中途被强制终止，因此引擎必须以 SQLite 中已提交事实为唯一恢复依据，并保证同一快照版本下的诊断结论可逐位复核。所有样本与测试端点均由程序内置生成器和本地回环服务提供，不依赖真实账号、外部站点或特定硬件。

任务环境与准备：
在 Linux（WSL Ubuntu）空工作目录中初始化 Go 模块（建议 Go 1.22 及以上），并引入 SQLite 驱动（如 modernc.org/sqlite 或 mattn/go-sqlite3），使用 go mod tidy 拉取依赖。
实现程序内置固定种子样本生成器，在首次运行时于本地写出租户、探测目标与策略快照 JSON 样本，保证同一工作目录重复运行产出逐字节一致。
实现本地回环测试端点，作为 TCP 探测目标与 UDP 丢包采样对端，支持按声明丢弃指定序号探测报文并支持连接拒绝、不响应与正常响应三种模式。
准备 SQLite 数据库文件路径与意图日志表结构，运行前确保目录可写；提供本地 HTTP 监听端口配置，默认仅绑定回环地址。
提供可重复演示脚本入口，用于一次快照加载、一次增量提交、一次并发限制下的探测轮次、一次陈旧读拒绝与一次强制终止后恢复核对。

业务要求：
1. 实现租户、探测目标与探测策略快照模型：租户声明标识、千分比权重、并发探测配额与所属分组，探测目标声明目标标识、协议（TCP 或 UDP）、本地回环端口、探测间隔毫秒与丢包判定阈值，策略快照携带单调递增版本号、生成时间、全局并发探测上限、每轮时间预算与整体校验摘要；加载本地确定性 JSON 样本时校验租户标识唯一、端口在合法范围、间隔为正整数，任一失败返回 E_SPEC_INVALID 并保持旧快照完全可用。
2. 实现增量片段提交与基础版本校验：增量片段只含受影响的租户或探测目标并携带基础版本号，基础版本不是当前已提交版本时返回 E_STALE_BASE 且不改变任何已提交状态；同一基础版本的两个并发增量只允许一个成功，另一个必须收到 E_STALE_BASE；提交成功后受影响租户的诊断视图与探测计划须在同一事务边界内级联失效并原子重建，禁止出现目标端口已更新而探测计划仍指向旧端口的中间可见状态。
3. 实现真实 TCP 探测与 UDP 丢包采样并保证可中断：TCP 探测须对本地测试端点发起真实连接并区分连接拒绝、连接成功与超时，UDP 采样须真实发送带序号的探测报文并统计本地测试端点声明丢弃的序号比例；每次探测具备独立超时，超时后必须真实关闭底层连接并释放其占用的并发名额，返回 E_PROBE_TIMEOUT，不得以等待冒充超时，也不得把协程超时描述为已终止失控代码。
4. 实现全局并发探测上限、每租户并发配额与每轮时间预算三重约束下的并行调度器：预算内按租户权重与探测目标稳定次序取任务，超出全局上限的任务进入有界等待队列，队列满返回 E_PROBE_QUEUE_FULL；租户并发配额耗尽时该租户后续任务延后而不得挤占其他租户配额；预算耗尽时按租户权重与已消耗预算给出确定性延后次序并输出延后依据与剩余预算，已发起探测必须完成或真实超时后才能结束本轮。
5. 实现丢包率与往返时延分位的数值契约及诊断结论：分位使用确定性最近秩法并注明样本规模，丢包率以千分比整数输出并声明舍入方式与累计舍入误差，往返时延累计使用补偿求和并输出可量化误差上界；样本数不足以计算所声明分位时返回 E_INSUFFICIENT_SAMPLES 并附样本数与所需下限；同一快照版本与同一探测结果集合重复查询必须逐位一致，诊断结论须包含各探测目标的丢包率、时延分位与故障等级。
6. 实现携带观察版本的诊断读取与陈旧读裁决：读请求携带观察版本，若该租户诊断视图版本不高于观察版本则返回结论并标注所用版本，若因增量传播或本轮探测尚未完成而落后于观察版本，必须返回 E_STALE_READ 并附视图版本、观察版本与未完成原因；状态迁移与结果写入前先写 SQLite 意图记录再提交事务，进程在探测批次或级联重建中途被强制终止后重启须扫描未完成意图，把未提交探测结果丢弃、视图回滚到最后一个完整提交版本。
7. 实现单写者提交与多读者查询的并发一致及幂等复用：快照提交、增量提交、视图重建与探测批次推进按快照版本单写者串行执行，多个只读诊断查询可并发读取某一完整提交版本，不得看到某探测目标已标记探测成功而丢包统计尚未落定的中间状态；同一探测批次标识重复提交只执行一次、其余等待并复用同一结果，内容不一致返回 E_CONFLICTING_REQUEST。
8. 提供本地 HTTP API 与可重复演示脚本：接口覆盖策略快照提交、增量片段提交、触发探测轮次、按观察版本查询租户诊断视图与探测明细、查询延后依据与恢复报告，失败响应统一为含业务码与上下文的 JSON，至少覆盖 E_SPEC_INVALID、E_STALE_BASE、E_PROBE_TIMEOUT、E_PROBE_QUEUE_FULL、E_INSUFFICIENT_SAMPLES、E_STALE_READ、E_CONFLICTING_REQUEST；演示脚本用固定本地样本完成一次快照加载、一次增量提交、一次并发限制下的探测轮次、一次陈旧读拒绝与一次强制终止后恢复核对。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证探测调度、丢包与时延统计、陈旧读拒绝及强制终止后恢复，输出业务码与恢复核对结果。
