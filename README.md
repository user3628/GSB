在一台没有历史代码的机器上，需要从零构建一个面向本地微服务测试环境的变更风险分级与自动回滚裁决工作台，交付可交互的专业应用与可重复演示。工作台维护若干服务及其变更批次：每个变更批次声明目标服务、变更类型（配置下发、镜像升级、扩缩容）、批次规模、变更前基线与变更后候选指标观测（毫秒时间戳、错误率、P90 延迟毫秒、成功率）。系统需依据带版本号的风险策略快照（各指标判定阈值、观察窗口长度、风险阈值、自动回滚开关与冷却期）对每个变更批次计算风险分与风险等级，并裁决继续观察、放行或触发自动回滚。真实运维中，工程师会以低延迟模式反复查看当前风险与裁决依据，同时观测仍在持续到达，且策略与批次会以增量形式被小步修改。因此系统必须在交互延迟预算内返回单一完整提交版本上的风险结论，不能让快速视图混用不同策略版本或不同观测批次的中间状态，同时要保证在任何时刻被强制终止后都能依据持久化事实恢复到一致状态。所有数据来自本地确定性样本与本地 HTTP 测试端点，不依赖真实账号、线上站点或外部服务。

任务环境与准备：
安装 Go 1.22 或更高版本（Windows 官方安装包），确认 go version 可用。
无需外部服务，SQLite 使用纯 Go 驱动（如 modernc.org/sqlite）通过 go mod 拉取，确保模块缓存可访问。
准备本地确定性样本文件：风险策略快照、变更批次清单与观测序列，时间戳与延迟均为整数毫秒。
准备一个本地 HTTP 测试端点用于演示回滚触达，绑定 127.0.0.1 回环端口，不依赖任何线上站点。
在空目录初始化 Go 模块并预留 docs 目录放置演示脚本说明，禁止使用容器环境。

业务要求：
1. 实现风险策略快照与变更批次模型的加载和校验：策略快照携带单调递增版本号、生成时间、各指标判定阈值、观察窗口长度、风险阈值、自动回滚开关与冷却期，以及整体校验摘要；变更批次包含目标服务、变更类型、批次规模与基线观测。提交快照时版本号不大于当前已提交版本返回业务码 E_STALE_SNAPSHOT，任一校验失败必须保持旧快照完全可用。
2. 实现观测摄入与带版本的时间桶模型：观测按毫秒时间戳、批次标识与指标类型分配到窗口桶，桶记录样本数、成功数与延迟样本；同一批次同一序号的重复上报必须幂等，内容不一致返回 E_CONFLICTING_REPORT 并保留首次上报内容；时间戳回退、指标类型非法或样本数为负的记录整批拒绝并返回 E_OBSERVATION_INVALID。
3. 实现风险分计算与可核对数值契约：由错误率、P90 延迟偏离基线程度与成功率下降幅度合成风险分，各分项与加权合成一律使用整数或显式定点表示，输出每步舍入方式与累计舍入误差；分位延迟使用声明的确定性最近秩法并注明样本规模，样本数不足返回业务码 E_INSUFFICIENT_SAMPLES 且不得以零值冒充风险分。
4. 实现风险等级与变更状态机，至少包含 OBSERVING、PASSED、ROLLING_BACK、ROLLED_BACK、ESCALATED 五种状态并规定合法迁移路径，非法迁移返回 E_INVALID_TRANSITION 且不得修改已持久化状态；风险等级须显式落在低、中、高、极高四档，每档的边界判定使用带相对容差的定点比较，容差内取下档并按稳定次序打破平局。
5. 实现低延迟快速裁决与完整裁决两种模式：快速模式按配置的采样上限只使用部分观测并输出采样率、采样方法与结论置信说明，完整模式使用窗口内全部观测；两种模式对同一策略版本与同一批次的结论差异处须逐项可核对，快速模式不得把越过风险阈值的批次判为放行，且快速模式返回时必须标注所用策略版本与观测批次边界。
6. 实现自动回滚的冷却期与并发一致：触发自动回滚须同时校验策略开关、批次状态与冷却期，冷却期内重复触发返回 E_ROLLBACK_COOLDOWN 并附剩余冷却时长；回滚结论、批次状态与冷却期占用必须在同一事务边界内生效，禁止出现批次已 ROLLING_BACK 而冷却期尚未占用、或回滚已完成而状态仍为 OBSERVING 的中间可见状态。
7. 实现意图持久化与强制终止后恢复：策略提交、观测摄入、风险重算与回滚裁决均先写入 SQLite 意图记录再提交事务；进程在风险重算或回滚中途被强制终止后重启必须扫描未完成意图，把批次与窗口回滚到最后一个完整提交版本或将对应批次标记为已中止，恢复报告只包含已落盘事实，不得把未提交观测计入风险结论。
8. 提供本地 HTTP 接口与可重复演示脚本：接口覆盖策略提交、变更批次提交、观测摄入、按批次查询风险分与裁决结论及误差说明、查询回滚冷却状态与恢复报告，失败响应统一为含业务码与上下文的 JSON（至少覆盖 E_STALE_SNAPSHOT、E_OBSERVATION_INVALID 与 E_INVALID_TRANSITION）；脚本使用固定本地样本与本地测试端点完成一次放行、一次自动回滚、一次冷却期拦截与一次强制终止后恢复。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定本地样本与端点跑通放行、自动回滚、冷却拦截与强制终止恢复，核对风险分、裁决与恢复报告一致。
