当前是空白工作区，需要在 Windows 本地从零构建一个面向模型推理服务的弹性伸缩与并行放置裁决组件，交付可交互的专业应用与可重复演示。系统维护若干推理服务（标识、模型、当前副本数、最小与最大副本数、每副本显存与算力需求、目标并发、延迟预算）与一组逻辑 GPU 节点（显存与算力份额、所属故障域、健康状态、已占用资源）。运维人员通过本地 HTTP 接口提交带版本的伸缩策略快照与负载观测（每服务到达请求数、排队时长、P99 估计），组件据此计算目标副本数，并在全局扩容并发预算与单轮时间预算内并行地把副本放置到节点上，同时追踪服务状态在 STABLE、SCALING_UP、SCALING_DOWN、DEGRADED、BLOCKED 之间的演进。核心难点是并行调度与资源预算：扩容与缩容会争用同一份显存和算力余量，多个服务同时请求扩容时配额授予顺序影响可行性，缩容回收与扩容准入必须原子生效，进程被强制终止后需按持久化事实恢复一致状态。所有数据来自本地确定性样本，不依赖真实 GPU、容器或外部集群。

任务环境与准备：
在 Windows 本地新建空白工作目录，准备 Python 3.11 或以上解释器，并创建虚拟环境。
安装 FastAPI、uvicorn、NumPy 与 SQLite 相关依赖（SQLite 使用 Python 标准库 sqlite3），全部通过本地已缓存的 wheel 或离线安装包完成，不依赖外网。
在项目内提供固定随机种子的本地确定性样本：伸缩策略快照、节点清单与负载观测，以及多处后续观测批次，样本随项目提交。
准备启动本地 HTTP 服务的脚本与查询用的命令行示例，确认 8000 端口在本机可用。
不要求 GPU、容器运行时或任何外部集群，全部判定基于本地样本与本地进程。

业务要求：
1. 实现伸缩策略快照与负载观测的解析和归一化：策略含单调递增版本号、生成时间、各服务副本上下界、每副本显存字节与算力份额（千分之一整数）、目标并发与延迟预算毫秒，观测含服务标识、采样时刻、到达请求数与分位延迟；解析样本中形如 2Gi、512Mi、250m 的量纲字符串并做溢出与负数检查，失败返回 E_SPEC_INVALID；提交策略时版本号不大于当前版本返回 E_STALE_SNAPSHOT 且不修改任何状态。
2. 实现目标副本数计算：依据到达请求数、目标并发、当前副本数与延迟预算是否被突破，按确定性规则计算每个服务的期望副本数并夹在最小与最大副本数之间；期望副本数计算须对分位延迟与并发做定点化处理并输出推导依据（含各输入值与夹取是否发生），同一观测重复计算必须得到逐位一致的结果；无法计算（如观测缺失或目标并发为零）时返回 E_OBSERVATION_INVALID。
3. 定义服务状态机，至少包含 STABLE、SCALING_UP、SCALING_DOWN、DEGRADED、BLOCKED 五种状态并规定合法迁移路径；非法迁移返回 E_INVALID_TRANSITION 且不修改已持久化状态；扩容成功但未达期望副本数须停留在 SCALING_UP 或进入 DEGRADED，不得直接标记 STABLE；状态与副本数、占用资源必须由同一事务边界提交。
4. 实现并行放置调度器，以全局扩容并发上限与每轮时间预算双重约束执行：预算内按服务优先级与到达顺序取扩容任务，超出并发上限的任务进入有界等待队列，队列满返回 E_SCALE_QUEUE_FULL；同一服务在同一轮中不得被重复扩容，同一节点不得被并发写入超额占用；每轮须输出实际授予、排队与被拒绝的副本数清单及原因。
5. 实现扩缩容的资源余量一致与原子生效：扩容前须校验目标节点显存字节与算力份额余量充足，不足返回 E_INSUFFICIENT_CAPACITY 并附当前余量；缩容回收的资源必须在同一事务内先释放再用于其他服务的扩容准入，禁止出现某服务已扩出副本而节点余量仍为旧值的中间可见状态；查询只能看到某一完整提交版本的副本分布与余量。
6. 实现故障域约束与降级取舍：同一服务的副本须按其声明的最大同域副本数分散到不同故障域，无法满足时在保持已放置副本不变的前提下放入剩余可行域并标记 DEGRADED 并附冲突域明细；节点不可用或健康检查失败时其上的副本须迁移，迁移与扩容争用资源时按优先级与预算给出确定性次序，不得以静默跳过代替失败说明。
7. 使用 SQLite 持久化策略版本、服务状态、副本放置与轮次记录，写操作先写意图记录再提交事务；进程在放置或缩容中途被强制终止后重启，须扫描未完成意图把副本分布回滚到最后一个完整版本或将轮次标记为已中止，恢复报告只基于已持久化事实，不得承诺强制终止后仍生成完整退出报告。
8. 实现单写者伸缩与多读者查询并发：伸缩轮次按快照版本单写者串行执行，多个只读查询可并发读取已提交版本；同一轮次标识重复触发只执行一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_ROUND；所有失败响应为含业务码的 JSON，至少覆盖 E_SPEC_INVALID、E_STALE_SNAPSHOT、E_INVALID_TRANSITION、E_SCALE_QUEUE_FULL、E_INSUFFICIENT_CAPACITY、E_ROUND_NOT_FOUND。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地固定样本验证副本数推导、预算内并行放置、故障域降级与强制终止后状态恢复，附运行结果与错误码。
