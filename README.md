开发机上目前只有一个未初始化的目录，需要据此构建一套面向本地回环环境的 DNS 递归解析缓存组件与结果验证工具。组件同时以本地 UDP 与 TCP 侦听真实 DNS 查询，向本地确定性权威测试服务器递归取回 A、AAAA、CNAME、MX、TXT、NS 与 SOA 记录，维护带生存期的正缓存与负缓存，并在全局并发上游查询上限、每权威服务器并发上限与每轮时间预算三重约束下并行推进解析任务。真实运维中，权威区数据会以区域快照与增量片段形式持续下发，缓存条目须随区域变更级联失效，进程也可能在缓存写入或区域重放中途被强制终止，重启后只能依据 SQLite 中已落盘的事实恢复缓存与区域状态。

任务环境与准备：
Linux（WSL Ubuntu）环境，安装 Go 1.22 及以上（例如通过官方二进制包解压并配置 PATH），SQLite 使用纯 Go 驱动或系统 sqlite3 库，确认 go env 可用。
准备本地确定性权威测试服务器与本地 UDP/TCP 测试端点，样本与测试端点地址均通过题目内声明的配置参数注入，不依赖真实域名解析或线上站点。
在空工作目录中初始化代码库，预留构建与运行脚本位置，执行前确认本地回环端口可绑定。

业务要求：
1. 实现 DNS 报文编解码与递归解析会话：支持 A、AAAA、CNAME、MX、TXT、NS 与 SOA 类型，正确处理域名压缩指针与标签长度上限；畸形报文、非法压缩指针或超长标签返回业务码 E_MESSAGE_MALFORMED 并回写 FORMERR，TCP 报文长度前缀不匹配返回 E_TCP_FRAME_INVALID。
2. 实现正负缓存的生存期语义：条目记录写入时刻、原始 TTL 与来源记录类型，命中时按已流逝毫秒递减返回剩余 TTL；过期条目不得命中且须被清理；NXDOMAIN 与 NODATA 按 SOA 声明的负缓存 TTL 生效，SOA 缺失时返回 E_NEGATIVE_TTL_UNDEFINED 并给出可诊断说明。
3. 实现区域快照与增量片段提交：区域快照携带单调递增版本号、生成时间与整体校验摘要，增量片段只含受影响的 RRset 并携带基础版本；基础版本不是当前已提交版本时返回 E_STALE_BASE 且不改变任何已提交状态，同一基础版本的两个并发增量只允许一个成功、另一个必须收到 E_STALE_BASE。
4. 实现区域变更驱动的缓存级联失效与原子重建：为每个权威区维护其 RRset 索引、受影响签名域集合与派生负缓存区间对区域版本与记录字段的引用关系；RRset 新增、删除或 TTL 变化时，该区全部派生结构及依赖它的下游缓存视图必须级联失效并在同一事务边界内原子重建，禁止出现区版本已更新而缓存条目仍按旧 TTL 命中。
5. 实现并行上游解析调度器，以全局并发上游上限、每权威服务器并发上限与每轮时间预算三重参数约束执行：预算内按查询优先级与到达顺序取任务，超出并发上限的任务进入有界等待队列，队列满返回 E_UPSTREAM_QUEUE_FULL；多个客户端并发查询同一未缓存域名时仅首个查询触发上游解析，其余挂起等待并复用同一结果，合并等待会令某长尾查询超出本轮时间预算时按确定性规则决定继续等待还是单独发起。
6. 实现真实上游超时与资源释放：每跳上游解析具备独立超时，超时后必须真实关闭对应 UDP 套接字或 TCP 连接并返回 E_UPSTREAM_TIMEOUT 的 SERVFAIL 应答，同时释放其占用的上游并发名额；连接被拒绝返回 E_UPSTREAM_REFUSED，响应报文校验失败返回 E_UPSTREAM_BAD_RESPONSE，不得以等待冒充超时或把未关闭的连接计为已释放。
7. 实现单写者提交与多读者查询的并发一致及幂等：缓存写入、负缓存写入、区域变更与级联重建按提交单写者串行执行，多个查询可并发读取某一完整提交版本；同一查询标识或区域批次标识重复提交只执行一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_REQUEST；查询不得看到会话已记录命中而缓存条目尚未落盘、或区索引已更新而负缓存区间仍为旧值。
8. 使用 SQLite 持久化缓存条目、区域版本、派生结构与意图日志，缓存写入、区域提交与级联重建前先写意图记录再提交事务；进程被强制终止后重启须扫描未完成意图，把未提交缓存条目回滚、把未完成区域批次标记为已中止或按已落盘事实重放，恢复报告只包含已落盘事实，并说明强制终止后无法保证的部分。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
