在一台 Windows 机器上，团队要为本地 Kubernetes 风格集群构建一个从零开始的声明式配置漂移收敛裁决引擎，交付可执行的 Go 服务与一套固定种子样本驱动的可重复验证工具。集群对象来自本地确定性 JSON 样本，每个对象声明对象标识、类别、命名空间、期望字段集合、实际字段集合、字段来源标记、依赖的其他对象与资源预算；收敛策略以带单调递增版本号的 JSON 快照提交，声明漂移判定容差、批次规模上限、依赖驱动顺序规则、单轮时间预算与重试上限。引擎需为每个对象判定漂移类别（字段缺失、字段多余、取值偏移、来源冲突），在依赖约束下生成收敛批次，向本地回环 HTTP 测试端点真实发起写回并依据回读结果判定是否收敛。真实场景中对象规模与依赖边规模会从数十跨越到数千，同时运维人员会并发提交整份快照与只含局部改动的增量片段，进程也可能在批次组织、写回或快照切换的任意时刻被强制终止。收敛必须对同一策略版本给出确定且可复现的结果，增量提交必须识别基础版本，被替换的版本不得泄漏陈旧结论。

任务环境与准备：
安装 Go 1.22 或以上版本，并确认 go version 可正常输出。
使用 go mod init 初始化模块，SQLite 通过纯 Go 驱动（如 modernc.org/sqlite）引入，执行 go mod tidy 拉取依赖。
任务执行前在本地准备固定种子生成器产出的确定性 JSON 样本（集群对象与收敛策略快照）以及一个仅监听回环地址的 HTTP 测试端点，用于写回与回读。
确认可在 Windows 本地创建临时工作目录并写入 SQLite 数据库文件，运行 go test ./... 作为本地验证入口。

业务要求：
1. 实现集群对象与收敛策略快照的解析与归一化：对象声明标识、类别、命名空间、期望字段集合、实际字段集合、字段来源标记、依赖对象列表与资源预算，策略快照携带单调递增版本号、生成时间、漂移判定容差、批次规模上限、单轮时间预算与重试上限及整体校验摘要；解析失败、对象标识重复或依赖引用不存在时返回 E_SPEC_INVALID 且不改变任何已提交状态。
2. 实现漂移判定核心：逐字段区分字段缺失、字段多余、取值偏移与来源冲突四类漂移，数值字段按策略声明的相对容差做定点比较而非裸浮点比较，同一对象命中多类漂移时按声明的稳定优先级给出主类别并保留全部命中明细；容差边界包含关系须显式定义，边界值下判定必须确定且可复算。
3. 实现依赖约束下的收敛批次组织：被依赖对象所在批次序号严格小于依赖者，依赖出现环时返回 E_DEPENDENCY_CYCLE 并附环上对象标识，环外对象仍须给出分层结果；批次规模受策略上限与对象资源预算共同约束，超限时拆分批次而非丢弃对象，每个批次须输出所含对象、依赖依据与预算占用。
4. 实现向本地回环测试端点的真实写回与回读核对：每次写回具备独立超时，超时后必须真实关闭底层 HTTP 连接并释放其占用的并发名额，返回 E_WRITE_TIMEOUT；写回成功后回读实际字段集合重新判定漂移，只有回读结果与期望一致才允许把对象标记为收敛，回读不一致须保留差异字段并计入重试次数，重试耗尽后返回 E_RETRY_EXHAUSTED。
5. 实现带版本号的整份快照提交与增量片段提交及版本绑定：增量片段只含受影响对象并携带基础版本，基础版本不是当前已提交版本时返回 E_STALE_BASE 且不改变任何状态；同一基础版本的两个并发增量只允许一个成功，另一个必须收到 E_STALE_BASE；加载新快照须识别版本变化并整体替换旧快照与全部派生结论，校验失败时旧快照必须完全可用，不得出现新旧快照混合生效。
6. 实现单轮时间预算与并行写回批次的并发约束，并保证派生产物的级联失效：写回受每轮时间预算与最大并行批数约束，超并行上限的批次进入有界等待队列，队列满返回 E_WRITE_QUEUE_FULL；批次划分、对象结论与汇总视图须维护对对象字段与依赖边的引用关系，任一变化时全部下游产物在同一事务边界内原子重建，禁止出现部分对象已按新策略收敛而汇总仍按旧策略呈现。
7. 实现单写者提交与多读者查询的并发一致及幂等复用：快照提交、增量提交、批次组织与写回推进按单写者串行执行，多个只读查询（对象状态、漂移明细、批次划分、收敛汇总）可并发读取某一完整提交版本；同一批次标识重复触发只执行一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_REQUEST。
8. 实现基于 SQLite 的意图持久化与强制终止后恢复：快照提交、批次组织与写回前先写意图记录再提交事务；进程在批次组织或写回中途被强制终止后重启须扫描未完成意图，把未提交写回回滚为待写回、把快照切换标记为已中止，恢复报告只基于已落盘事实给出每个对象的最终状态与差异，不得声称一定生成退出报告。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用固定本地样本验证漂移判定、依赖批次、真实写回与并发增量提交，并确认强制终止后依据持久化事实恢复。
