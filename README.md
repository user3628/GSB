本地运维团队手上只有一份目标说明，要在 Windows 空白目录中从零实现一个告警降噪与根因关联引擎，不接入任何外部监控平台。样本由程序内置固定种子生成器确定性产出：服务清单（服务标识、所属可用区、千分比整数权重、依赖的上游服务列表、告警灵敏度档位与静默窗口毫秒）、指标观测流（毫秒时间戳、服务标识、指标名、指标值、样本标签）以及带版本号的告警策略快照（各指标阈值、去重指纹组成字段、抑制窗口毫秒、根因评分容差、全局并发巡检上限与每轮时间预算毫秒）。引擎需按策略把观测转化为候选告警，按指纹去重并抑制降噪，再沿依赖拓扑对剩余告警做根因候选关联评分，并输出巡检轨迹与预算消耗明细。难点在于并行巡检调度与计算结果一致性必须同时成立：采样降噪路径与完整降噪路径要给出可逐条核对的告警集合，告警、抑制索引与根因评分表须在快照替换与增量提交下保持同版本一致，进程被强制终止后必须依据 SQLite 中的持久化事实恢复。

任务环境与准备：
安装 Go 1.21 或更高版本（Windows 官方安装包），确认 go version 可用；无需容器或外部服务。
安装 SQLite 3 命令行工具用于核对持久化事实，Go 侧使用纯 Go 驱动（如 modernc.org/sqlite），通过 go mod tidy 拉取。
在空白工作区执行 go mod init 初始化模块；任务样本与测试端点均由程序内置固定种子生成器在本地临时目录产出，无需联网下载数据集。
准备本地回环测试端点用于模拟发送端行为，全部绑定 127.0.0.1 高位端口，端口占用时由程序显式报错而不是静默跳过。
运行验证时通过外部参数注入非法输入、版本回退与中断标记，禁止修改源码制造验收失败。

业务要求：
1. 实现服务、观测与策略快照的加载和归一化：服务声明标识、可用区、千分比整数权重、依赖上游服务列表、灵敏度档位与静默窗口毫秒；观测声明毫秒时间戳、服务标识、指标名、指标值与样本标签；策略快照声明各指标阈值、去重指纹组成字段、抑制窗口毫秒、根因评分容差、全局并发巡检上限与每轮时间预算毫秒。解析时校验服务标识唯一、依赖引用存在、权重落在 1 至 1000、时间与阈值为非负整数并做溢出检查，失败返回业务码 E_SAMPLE_INVALID 且整批不入库。
2. 实现候选告警生成与去重指纹：按阈值把观测转化为候选告警，指纹由策略声明的服务标识、指标名与样本标签子集经确定性规范化后组成，同一指纹在抑制窗口内的多条告警合并为一条并累计被合并条数与被抑制来源；抑制窗口边界包含关系与时间戳截断规则须显式定义，窗口外的新告警必须生成新条目，禁止把窗口外告警并入旧条目。
3. 实现抑制索引与降噪结论：抑制规则按服务、可用区与依赖跳数在抑制窗口内合并同指纹告警，输出被抑制条目清单、抑制原因与释放时刻；同一告警同时命中多条抑制规则时按声明的确定次序裁决为主抑制原因并保留全部命中明细；告警状态至少包含 FIRING、SUPPRESSED、RESOLVED 三种并规定合法迁移路径，非法迁移返回 E_INVALID_TRANSITION 且不得修改已持久化状态。
4. 实现依赖拓扑上的根因候选关联评分：由告警时间邻近度与依赖跳数衰减合成评分，跳数与时间差使用整数或显式定点表示，评分比较使用带相对容差的定点比较而非裸浮点比较，容差内按服务标识稳定字典序打破平局；评分输出须附每步舍入方式与累计舍入误差，并给出根因候选排序及其依据中的跳数、时间差与触发告警标识。
5. 实现带基础版本校验的增量提交与快照整体替换：观测增量与策略增量只含受影响条目并携带基础版本，基础版本不是当前已提交版本时返回 E_STALE_BASE 且不改变任何已提交状态；快照携带单调递增版本号与整体校验摘要，加载时校验版本单调与摘要并整体替换旧快照，失败返回 E_SNAPSHOT_INVALID 且必须保持旧快照完全可用，禁止新旧快照内容混合使用。
6. 实现派生结构的级联失效与原子重建：为每个服务与告警指纹维护对候选告警集合、抑制索引与根因评分表的引用关系；当某服务的指标阈值、灵敏度档位、依赖边或抑制窗口变化时，其全部派生条目及依赖它的下游根因评分必须级联失效并在同一事务边界内原子重建，禁止出现抑制索引已更新而根因评分仍引用旧告警集合的中间可见状态。
7. 实现低延迟采样降噪与完整降噪两条路径：采样路径按配置的采样上限只处理部分观测并输出采样率、采样方法与结论置信说明，完整路径处理全部观测；两条路径对同一策略版本与同一观测批次须给出逐条可核对的告警差异，采样路径不得把未经过抑制裁决的告警计入最终结论，且其根因候选须可正确定位到同一跳数与时间差依据。
8. 实现并行巡检预算调度、单写者提交与强制终止恢复：巡检轮次受全局并发上限与每轮时间预算共同约束，超出并发上限的任务进入有界等待队列，队列满返回 E_PATROL_QUEUE_FULL，预算耗尽时按灵敏度档位与可用区轮转给出确定性降级次序并输出剩余预算；提交、抑制裁决与根因评分重建按策略版本单写者串行，多个只读查询可并发读取某一完整提交版本，同一请求标识重复提交只执行一次、其余复用结果、内容不一致返回 E_CONFLICTING_REQUEST；所有写操作先写 SQLite 意图记录再提交事务，进程被强制终止后重启须扫描未完成意图，把未提交告警回滚为候选状态、未提交重建回滚到最后一个完整版本，恢复报告只基于已落盘事实。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地固定种子样本验证告警去重、抑制降噪、根因评分与增量提交、预算降级及强制终止恢复的一致性。
