项目目录刚刚由版本管理初始化，还没有任何源码与样本，需要为一个 LLM 推理服务的量化模型库实现按分片组织的多专家量化位宽调度与校验组件。程序内置固定种子生成器在本地产出权重分片清单：每片含层号、专家编号、参数张量形状、逐通道数值与校准激活样本；并附一份带单调版本号的量化策略快照，声明每层候选位宽档（8 位与 4 位）、各专家可选的逐张量或逐通道粒度、校准样本比例与随机种子、每轮标定预算与峰值内存上限，以及只含局部改动的增量片段。运维通过本地 HTTP 接口导入分片、调整策略、触发标定与校验，并查询每个专家分片的量化参数与误差归因。真实场景里专家规模与位宽档位会持续变化，同一位宽的分片组合必须在追加、整体替换与回退之间保持判定一致。

任务环境与准备：
安装 Go 1.22 或以上版本，确认 go version 可用。
在 WSL Ubuntu 工作目录中初始化 Go module，并引入 SQLite 驱动依赖（如 modernc.org/sqlite），执行 go mod tidy。
准备程序内置的固定种子生成器，可在本地生成权重分片清单与校准激活样本；无需 GPU、外部数据集或网络服务。
确认本地回环端口可监听，用于演示 HTTP 接口；测试数据全部由本地生成器产出。

业务要求：
1. 实现校准样本选取与权重分片加载阶段：依据策略快照声明的校准比例与随机种子从本地激活样本中确定性分层抽样，按分片清单加载权重并校验实际张量形状与清单声明一致；同一输入与策略必须产生逐字节一致的校准集摘要与加载统计。
2. 实现逐专家分片的分级位宽标定核心：按每层候选位宽档与声明的粒度计算缩放因子与零点，位宽降档须基于同层上一档已标定的量化域结果而非原始浮点重新开始，逐片记录缩放因子、钳制次数与量化误差步长；缩放因子为零或激活全零通道须显式标记。
3. 实现全局标定预算与峰值内存双约束下的分片调度：以分片为调度单元，在每轮标定预算、峰值内存上限与并发标定上限三重约束下决定接纳顺序与并发度，超预算分片记录为未处理并给出预算余量与原因，不得静默丢弃。
4. 实现多专家位宽组合的误差界推导与容差比对：以本地高精度参考推理输出为唯一真值，按显式抽样位置逐片给出量化误差上界与有效位数，越界分片返回带层号、专家号与最大偏差的 E_TOLERANCE_EXCEEDED，并保留推导依据。
5. 实现 SQLite 事务化的分片级标定检查点与强制终止恢复：每个分片标定完成时以事务写入含策略版本、分片指纹、位宽档、产物摘要与单调序号的记录，同一分片同一策略版本只允许一条有效记录；进程被强制终止后重启仅凭已提交事实重建进度，不承诺生成退出报告。
6. 实现策略快照增量片段与整体替换的版本识别及失效传播：接受只含局部改动的片段并校验基础版本，通过内容摘要与版本序号区分正常推进、整体替换、回退与分叉；发生替换或位宽档改变时使受影响的最早阶段与最小专家集合失效重建，回退拒绝并返回 E_STALE_CHECKPOINT。
7. 实现并发发布互斥与峰值内存明细查询：多个工作进程对同一数据库发布分片标定结果时使用 SQLite 条件更新与真实文件锁，仅允许序号连续推进，落后、重复或跨专家错位发布返回 E_STALE_CHECKPOINT；内存预算超限返回带预算明细的 E_MEMORY_BUDGET。
8. 提供本地 HTTP 与命令行交互接口及确定性演示：支持导入分片与策略、提交增量片段、触发分阶段标定、查询各分片量化参数与误差归因、查看版本指纹与失效原因、请求优雅停止与执行恢复；演示数据至少覆盖 3 层、6 个专家与两档位宽。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地确定性样本验证逐专家标定、预算调度、失效传播与中断恢复结果一致。
