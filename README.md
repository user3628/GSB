当前是空白 Windows 工作区，需从零构建一个面向多环境部署一致性的领域可视化与诊断工作台，交付可交互的本地应用。平台维护若干环境（开发、预发、生产等），每个环境声明一组部署单元（服务名、镜像摘要、配置键值、依赖的其他部署单元、期望版本）与一份带版本号的部署快照。运维人员提交整份快照或只含局部改动的增量片段，工作台据此编译出每个环境的部署计划、依赖拓扑与期望状态摘要，并在本地测试端点执行一致性校验，把差异按严重级别整理为诊断清单。核心难点在增量更新与依赖失效：某个部署单元的镜像摘要、配置键或依赖列表变化时，依赖它的部署计划、拓扑分层与跨环境一致度评分必须级联失效并原子重建，同时进程可能在重建中途被强制终止，重启后必须依据持久化事实恢复到一致状态。所有数据来自本地确定性样本，不依赖真实集群或外部仓库。

任务环境与准备：
确认 Windows 环境已安装 Python 3.11 或以上版本，并可在命令行调用 python。
创建独立虚拟环境并安装 FastAPI、uvicorn、NumPy 与 pytest，安装完成后确认可导入。
Python 标准库 sqlite3 与 hashlib 直接使用，无需额外安装数据库服务。
在项目内准备本地确定性样本：至少三个环境、每环境若干部署单元与依赖关系，以及两份快照和一份只改单个服务镜像摘要的增量片段。
准备本地回环端口用于 HTTP 服务，确保无外部网络依赖；演示脚本与恢复演练均在本地执行。

业务要求：
1. 实现环境与部署单元模型：每个环境声明服务名、镜像摘要、配置键值对、依赖单元列表与期望版本，解析本地确定性 JSON 样本时校验服务名在环境内唯一、依赖引用存在且镜像摘要格式合法，解析失败返回业务码 E_SPEC_INVALID 且整份快照不入库。
2. 实现带单调版本号的部署快照与增量片段提交：增量只含受影响的部署单元并携带基础版本，基础版本不是当前版本时返回 E_STALE_BASE 且不修改任何已提交状态；同一基础版本的两个并发增量只允许一个成功，另一个必须收到 E_STALE_BASE，快照整体替换时须识别版本变化。
3. 实现部署计划、拓扑分层与跨环境一致度评分三类派生产物，并为每个部署单元与配置键维护其对派生产物的引用关系；当镜像摘要、配置键或依赖列表变化时，全部受影响产物及其下游产物必须级联失效并在同一事务边界内原子重建，禁止出现部分产物已更新而下游仍为旧值的中间可见状态。
4. 实现跨环境一致性校验与差异诊断：比较同一服务在各环境的镜像摘要、配置键与期望版本，按严重级别与稳定次序输出差异清单，差异项须携带环境、服务名、差异类型与双方取值；当某环境整体落后于基线环境超过声明的容忍级差时须单独标记，且诊断清单不得改变部署计划本身。
5. 实现依赖环检测与降级处置：环境内依赖出现环时返回 E_DEPENDENCY_CYCLE 并附环上服务名列表；无法完成拓扑分层时仍须输出未污染部分的分层结果与受阻单元清单，保证查询可在同一事务边界内看到完整结论而非半更新状态。
6. 实现单写者提交与多读者查询的并发一致及幂等：快照提交、增量提交与级联重建按提交串行执行，多个只读查询可并发读取某一完整提交版本；同一提交标识重复提交只执行一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_COMMIT；查询请求绑定的快照版本若在期间被替换须在该绑定版本上完成或返回 E_VERSION_RETIRED。
7. 实现基于 SQLite 的意图持久化与强制终止恢复：快照提交、增量提交与级联重建前先写意图记录再提交事务；进程在重建中途被强制终止后重启须扫描未完成意图，把部署状态回滚到最后一个完整快照版本或将增量标记为已中止，恢复报告只基于已落盘事实，不得承诺强制终止后仍生成完整退出报告。
8. 提供可视化诊断工作台与端到端演示脚本：本地 HTTP 接口覆盖快照提交、增量提交、按环境与应用查询部署计划与拓扑、跨环境差异清单、恢复报告查询，失败响应统一为含业务码的 JSON；演示脚本用固定样本完成全量提交、一次只改单个服务镜像摘要的增量提交、一次注入依赖环，输出级联失效轨迹、差异清单与最终状态摘要。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证增量提交、级联失效、跨环境差异诊断与强制终止后恢复的一致性，附运行结果。
