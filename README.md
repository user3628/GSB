在 Windows 空白工作区中，需要从零构建一个面向本地多进程场景的分布式租约锁中间件，供上层共享资源协调使用。锁以租约形式授予，持有者须在 TTL 内周期性续约，否则租约过期后锁可被其他候选者获取。每条租约记录锁键、持有者、授予时刻、到期时刻（毫秒）、续约次数与持有者申报的权重；候选者按权重参与公平性度量，中间件需据此计算每个持有者的租约占比、续约余量比例、集群级锁占用率以及跨租约的加权公平度等派生指标，并依据这些指标裁决锁的授予顺序与是否触发再平衡建议。真实场景中 TTL 会从数百毫秒到数小时不等，权重为浮点比例，续约余量与占比需要经过多级乘除与累计求和，浮点运算顺序、时间截断与权重归一化都会放大误差，使同一租约集合在不同计算路径下得出不同的授予或再平衡结论。用户通过本地 HTTP 接口获取锁、续约、释放、查询派生指标与诊断报告，所有租约与意图日志持久化到 SQLite，进程可能在任意时刻被强制终止。

任务环境与准备：
安装 Python 3.11 及 pip，创建并激活本地虚拟环境。
安装依赖 fastapi、uvicorn、pydantic、numpy 与 pytest，版本以本地 wheel 可安装为准。
确认 SQLite 由 Python 标准库 sqlite3 提供且可用，无需额外安装服务。
在空白工作区预留目录用于 SQLite 数据库文件、意图日志与固定租约样本 JSON。
准备固定租约样本与演示脚本骨架，样本含不同 TTL 量级、权重与到期时刻，供本地运行核对。

业务要求：
1. 实现租约锁核心模型与毫秒时间语义：锁键、持有者标识、租约版本号、授予时刻、到期时刻、续约次数与持有者申报权重（浮点比例）以毫秒精度持久化到 SQLite；获取锁时若锁空闲或已过期则授予并返回新版本号，否则返回业务码 E_LOCK_HELD 并附当前剩余寿命毫秒数，续约须携带当前租约版本，版本落后返回 E_STALE_LEASE 且不得延长到期时刻。
2. 实现派生指标计算并定义统一内部表示：由 TTL 与已流逝时间计算续约余量比例，由各持有者权重计算租约占比，由已占用锁键与总锁键计算集群锁占用率，并由占比与权重偏差合成跨租约加权公平度；占比与余量比例统一使用保留固定小数位的定点表示，输出每步运算的舍入方式与累计舍入误差，禁止在中间步骤混用未声明精度的浮点与定点。
3. 实现累计求和的数值稳定性与可量化误差界：多持有者占比累计与加权公平度求和须使用 Kahan 或等价补偿求和，并与朴素求和在混合大数小数、TTL 跨三个数量级的固定样本上对比，给出可量化的误差上界；同一租约集合同一时刻重复计算派生指标必须逐位一致，授予顺序判定不得因求和顺序或权重遍历顺序变化而翻转。
4. 实现带容差的授予顺序裁决与稳定打破平局：当多个候选者同时竞争同一锁键时，按加权公平度优先级排序并比较，比较使用带相对容差的定点比较而非裸浮点比较；容差内视为等优并按持有者标识稳定字典序打破平局，授予结论须输出参与比较的双方指标值、容差取值与最终依据，使同一租约集合在任意候选提交顺序下得到相同授予结论。
5. 实现到期时刻计算的时间精度契约：到期时刻由授予时刻加 TTL 毫秒得到，须输出按秒、分、时不同量级 TTL 归一化时的截断规则与累计误差；续约累加须避免因浮点秒与毫秒整数混用导致到期时刻漂移，提供一组 TTL 从 300 毫秒到 7200000 毫秒的固定样本核对到期时刻与剩余寿命，并说明系统时钟偏移注入方式及其对余量比例的影响。
6. 实现再平衡建议的容差契约与跨模块一致性：当某持有者租约占比与权重偏差超过声明的相对容差时才生成再平衡建议，建议须携带偏差数值与触发依据，容差内不生成；租约的续约、释放与过期须在同一事务边界内更新租约记录、到期索引与派生指标缓存，禁止出现续约已持久化而余量比例仍按旧到期时刻计算的中间可见状态，查询只能看到某一完整提交版本。
7. 实现单写者裁决与多读者查询的并发一致及幂等：授予、续约与释放按锁键单写者串行执行，多个只读指标查询可并发；同一请求标识重复提交只执行一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_REQUEST；并发竞争同一空闲锁键时仅一个候选者获得租约，其余返回 E_LOCK_HELD 并附新持有者与授予时刻。
8. 使用 SQLite 持久化租约、派生指标与意图日志并实现强制终止恢复：授予、续约、释放与指标重算前先写意图记录再提交事务；进程被强制终止后重启须扫描未完成意图，把未提交授予回滚为可获取、未提交续约回滚到上一个到期时刻，并输出仅基于已持久化事实的恢复报告，报告不得承诺强制终止后仍能生成完整退出报告；同时提供本地 HTTP 接口与固定样本演示脚本，输出授予轨迹、派生指标、误差说明与恢复差异。
