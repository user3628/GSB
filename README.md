当前是空白工作区，没有现存项目、代码或数据附件，需从零构建一个本地可运行的搜索推荐在线特征与样本链路系统，交付算法实现与可复现实验环境。业务场景是：给一批本地确定性样本（JSONL，每条含 sample_id、user 特征、item 特征、context 特征、曝光/点击/转化标签、source、lang），系统需按四个阶段推进完整样本链路：特征规范化与分桶、在线特征编码（数值特征分箱+类别特征哈希+交叉组合）、样本组装与标签统计、不同数据规模的算法取舍决策。规模分为三档：小档约 600 条、中档约 6000 条、大档约 30000 条，每档声明样本数、特征基数、交叉组合上限与总计算预算作为显式观测。系统不依赖任何真实模型、线上服务或外部数据，只依赖本地确定性样本与本地测试服务。

任务环境与准备：
确认 Windows 本地可运行 Python 3.10 及以上，安装 NumPy 与 PyYAML（pip install numpy pyyaml），无需 GPU、数据库或外部账号。
在工作区根目录新建项目目录，预留 samples/ 放分档样本、config/ 放 YAML 配置、workdir/ 放检查点与产物、scripts/ 放运行与演示脚本。
用固定随机种子生成器或手写脚本产出小/中/大三档 JSONL 样本、每档声明文件（样本数、特征基数、交叉上限、预算）与一份最小 YAML 配置，确保样本含中英混排、缺失标签与缺失数值字段。
准备本地 HTTP 测试服务的启动入口与命令行入口，二者共享同一工作区与配置目录；准备一个可重复执行的演示脚本，用于完整运行、阶段间停止后恢复与版本变更触发失效三条路径。
在 README 之外以脚本注释说明运行顺序与错误码含义；所有样本与配置随项目落盘，运行前不需要联网下载任何内容。

业务要求：
1. 实现特征规范化与分桶阶段：对 user/item/context 中的类别字段做 Unicode NFKC、空白折叠与小写化，数值字段按可配置分箱边界离散化并对缺失值写入显式缺失分桶；同一输入与配置必须产生逐字节一致的分桶记录，空特征区或分箱边界非单调时须返回带 sample_id 与字段名的 E_INVALID_FEATURE，不得静默丢弃样本。
2. 实现在线特征编码核心：类别特征以固定哈希函数映射到配置维度并处理哈希冲突（冲突计数须可观测），交叉组合特征按可配置上限生成并以固定顺序编号，数值分桶与类别编码拼接为定长特征向量；当哈希维度为零、交叉上限超限或编码向量长度与声明不一致时须返回明确业务错误码，同一输入在重复运行时逐字节一致。
3. 实现基于数据规模与计算预算的算法取舍决策：依据每档样本数、特征基数、交叉组合数与总计算预算，在编码策略（全量精确编码、分批近似编码、特征采样编码）与样本组装策略中按预测消耗与精度损失上界打分选出组合，并记录选择理由、打分明细与被淘汰原因；小档须避免选用仅为大档设计的分批策略，且须保证任一策略启用后已声明预算不被突破。
4. 实现样本组装与标签统计阶段：把编码向量与曝光/点击/转化标签组装为训练样本，按 source 与 lang 统计样本数、正例率与类别分布，并输出被舍弃样本及原因（如标签缺失、编码失败）；统计结果须依赖显式组装记录，不得从缺失信息推断，同输入同配置的统计摘要逐字节一致。
5. 实现阶段检查点持久化与优雅停止恢复：每档每阶段完成时以原子方式写入含阶段名、档位标识、输入内容指纹、配置版本、产物摘要与单调序号的记录，写入任意位置中断不得留下半写记录；收到停止请求时完成当前不可拆分的档位单元后退出，恢复时忽略损坏或不完整记录并从最近一致检查点继续，恢复后最终样本集与统计摘要须与一次从零完整运行逐字节一致。
6. 实现版本变化检测与增量失效传播：当样本内容、分箱边界、哈希维度、交叉组合上限、取舍策略参数或预算配置任一变化时，通过各阶段内容摘要构成的版本指纹识别受影响的最早阶段，使该阶段及其全部下游产物（编码记录、样本集、统计摘要）失效并重建，未受影响上游产物继续复用；失效原因与各阶段版本指纹须在查询接口中可观测。
7. 实现并发发布保护与稳定业务错误码：多个工作进程对同一工作区发布阶段产物时使用真实文件锁并比较档位内序号，仅允许序号连续推进，落后、重复或跨档位错位发布须被拒绝并返回 E_STALE_CHECKPOINT；请求非法阶段跳转、缺失前置阶段产物或档位声明与实际样本数不符时须返回带上下文的 E_INVALID_STAGE。
8. 提供本地 HTTP 与命令行实验接口及确定性演示：支持导入分档样本与配置、触发分阶段执行、查询各档状态与版本指纹、查看算法取舍理由与预算消耗明细、请求停止、执行恢复、导出样本集与统计摘要；演示数据须覆盖三个规模档、中英混排与至少一个缺失标签样本，一次完整运行生成固定摘要，并演示在阶段间触发停止后恢复结果与完整运行一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用三档本地样本验证特征编码、规模取舍决策、断点恢复一致性与版本失效，并附运行摘要。
