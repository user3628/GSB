项目从零开始，需要为安全运营团队构建一个面向本地取证预算受控场景的确定性重放引擎。该引擎不再承担多格式审计源的全量互操作解析，而是聚焦于：给定一批已经规范化好的审计事件窗口，在有限的全局资源预算下决定哪些窗口可以获得完整关联算力、哪些必须被降级或推迟，并在降级状态下仍产出一份可被事后复核的取证结论。输入由程序内置生成器产出的本地确定性样本组成：每个窗口包含事件列表（事件标识、主体、对象、操作类型、逻辑时间偏移与优先级权重）和一份窗口级资源声明（需要的关联深度与内存量）。引擎还需维护带递增版本号的取证结论快照，使降级裁决、预算耗尽与中断恢复都能被重放和复核，且并发的存在与否不得改变任何窗口的最终结论。

任务环境与准备：
安装 Go 1.22 或以上版本，确保 go 命令可在 Windows 命令行中执行。
SQLite 使用纯 Go 驱动，无需单独安装数据库服务，首次运行前执行 go mod tidy 拉取依赖。
在 Windows 上准备一个可写工作目录，用于生成确定性样本与临时事务数据库文件。
样本与注入参数均由程序内置生成器与命令行参数产出，不依赖外部网络、真实账号或附件。

业务要求：
1. 实现审计事件窗口模型与样本解析：从程序内置生成器产出的本地样本中读取每个窗口的事件列表与资源声明，事件含全局唯一标识、主体、对象、操作类型、逻辑时间偏移与优先级权重；解析时校验事件标识唯一性、权重取值域与资源声明字段完整性，非法窗口返回 E_WINDOW_MALFORMED 并不得进入调度队列。
2. 实现窗口内事件的确定性关联核心：按逻辑时间偏移与优先级权重对事件排序后，按主体与对象的引用关系构建关联链，对指向不存在主体或对象的事件标记 E_ORPHAN_REF 并挂到虚拟根；关联结果的节点顺序、链编号与孤儿归位必须是输入的函数，与遍历顺序或并发度无关。
3. 实现分层资源预算与降级裁决：全局内存预算、全局关联算力预算与单窗口算力上限均为参数，调度器按窗口优先级权重与关联链复杂度加权决定完整处理、降级处理或推迟三类裁决；降级窗口只做浅层关联但仍产出结论，推迟窗口保留原始摘要；预算耗尽标记 E_BUDGET_EXHAUSTED，单窗口超上限标记 E_WINDOW_BUDGET。
4. 实现跨窗口冲突检测与取证结论归并：当同一主体或对象在多个窗口中被不同操作处置（例如先授权后撤销、先创建后删除）时，按逻辑时间偏移合并出最终状态并标记该主体为跨窗口冲突项；冲突项须给出参与窗口集合与判定所依据的时间偏移，冲突归并结果按稳定键排序，不依赖窗口处理先后。
5. 实现带版本号的取证结论快照与整体替换识别：每完成一轮调度与关联后在单个 SQLite 事务内提交递增版本号快照，记录各窗口裁决类别、降级原因、冲突项与所用预算参数指纹；加载时校验版本链连续性，跳号返回 E_SNAPSHOT_VERSION 并回退到最近连续版本；快照内容比较须识别整体替换式版本变化而非仅比对版本号。
6. 实现强制终止后的恢复一致性：调度提交或快照提交过程中进程被强制终止后重启，依赖 SQLite 已提交事务恢复快照版本与窗口裁决进度，已提交窗口裁决不回退、未提交整体丢弃并重新纳入调度，恢复后版本链跳号须以 E_SNAPSHOT_VERSION 拒绝加载；不承诺生成退出报告。
7. 实现并发调度与确定性收敛：多窗口可在独立会话中并发处理，并发度可配置，超并发上限的窗口进入等待队列而非直接拒绝；无论并发度取 1 还是上限，各窗口裁决类别、降级与冲突归并结果、业务码序列必须逐字节一致，等待队列的排队与出队统计须作为可观测字段进入最终输出。
8. 实现异常注入验证链路与确定性报告：通过外部命令行参数或配置文件构造事件标识重复、孤儿引用、窗口预算极低、全局预算不足、冲突归并与快照版本跳号六类样本，分别断言对应业务码、已提交快照未被污染、其余窗口裁决不受影响；导出 JSON 报告按窗口标识与业务码稳定排序，时间字段只使用固定采样标记，重复运行且输入与参数不变时报告字节级一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地确定性样本验证降级预算裁决、跨窗口冲突归并与快照恢复，并发度变化时报告字节级一致。
