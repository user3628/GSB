当前是空白工作区，没有现存项目、代码或数据附件，需要从零实现一个面向本地可观测性场景的「告警风暴多源并行归并降噪与根因关联仲裁引擎」。生产环境在故障期间会从多个本地告警源桩（指标、日志、链路、合成探测）同时涌入大量告警，每条告警带来源、规则标识、实体标识、严重度、首次与最近触发时刻、标签映射与关联指纹；引擎须并行拉取各来源告警，在共享资源预算（同时在途抓取数、单轮归并预算、关联计算配额）下完成去重合并、降噪与根因簇划分，并在预算不足时有序推迟而非丢弃。真实难点在于四类约束相互挤占：抓取并发改变归并看到的告警集合，归并结果又决定关联计算量；根因簇的确定依赖跨来源的实体拓扑与时间因果，而时间戳来自不同源的观测，存在同步偏差，必须显式声明观测、同步标记与真值来源，不能把偏差当成因果。引擎须持久化状态以支持进程重启后继续同一轮归并，并保证同一输入在任何调度次序下产出相同的降噪与根因结论。

任务环境与准备：
安装 Python 3.11 或以上版本，并在 Windows PowerShell 中创建虚拟环境后安装 fastapi、uvicorn、numpy、pytest、httpx 与 pytest-asyncio，版本以本地 wheel 或已配置的离线镜像为准。
确认无需联网：告警源桩与引擎均绑定 127.0.0.1 的回环端口，端口号可配置并避开系统占用端口。
在工作区根目录准备 config 目录用于放置抓取上限、归并预算、关联配额、同步偏差阈值与端口配置样例，运行前由本地脚本生成 SQLite 数据目录与临时目录。
准备固定随机种子与固定并发配置的样本生成脚本，用于产出多来源告警列表；不依赖真实账号、线上站点或外部数据集。
运行前检查 Windows 防火墙未拦截回环端口，pytest 用例串行执行以避免端口冲突。

业务要求：
1. 实现多源告警模型与并行抓取协议：每个告警源桩通过本地 HTTP 暴露告警列表，告警含来源、规则标识、实体标识、严重度、首次与最近触发时刻、标签映射与关联指纹；引擎须在配置的在途抓取上限下并行抓取各来源，抓取须带基于 asyncio 的真实超时取消语义，超时来源须记为抓取不完整并在后续归并中显式标记覆盖缺口，不得把缺失来源当作无告警。
2. 实现跨来源去重合并与同步偏差标注：同一关联指纹的告警须合并为一条聚合告警，严重度取最高、首次时刻取最早、最近时刻取最晚，并保留各来源的原始触发记录；时间比较须依据声明的同步标记（各源时钟偏移量与采集序号）把观测时刻归一到共同时间基准，偏差超过配置阈值的记录须标记为时限可疑并不得作为因果关系依据，合并结果须在相同输入下与来源拉取顺序无关。
3. 实现降噪评分与预算受限的关联计算调度：对聚合告警按严重度、跨来源一致数、重复触发频次与实体关键度计算降噪分数，并据此决定哪些聚合告警进入根因关联计算；关联计算受单轮配额约束，配额不足时候选须进入推迟队列并按降噪分数与到达次序确定性排序，推迟不得使已进入队列的候选丢失或被重复计入下一轮。
4. 实现根因簇划分与因果方向仲裁：基于实体拓扑邻接与归一化后时间的先后关系划分根因簇，簇内须选出一个根因告警并要求其他成员在时间上不早于根因且存在可达的实体路径；当多个候选同时满足时按严重度、跨来源一致数、实体关键度、规则标识字典序的固定次序裁决并记录裁决依据；无法确定单向因果的成员须标记为伴随而非强行归因。
5. 实现并发预算与推迟队列的交互一致性：并行抓取上限、单轮归并预算与关联计算配额构成共享预算，抓取占用的名额须在抓取完成后立即释放供归并复用；当抓取因超时被取消时其占用的预算必须被真实回收，不得以计时器到期代替取消；被推迟的候选在下一轮开始时须按持久化次序恢复，且其同步偏差标注与去重结果不得因跨轮而丢失。
6. 实现 SQLite 持久化与进程重启后的轮次恢复：来源抓取水位、聚合告警、去重来源记录、推迟队列、根因簇结论与轮次事件须在每轮提交点以单事务写入，事务提交后才对查询可见；进程重启后须把中断时处于 running 的轮次回退为可重入状态并丢弃未提交部分，已完成的轮次结论须可重放且与重启前逐字段一致；被强制终止时不得承诺生成退出报告，恢复只能依据已提交状态。
7. 实现本地 HTTP 查询与诊断接口：提供触发一轮归并、查询轮次状态与事件序列、查询聚合告警与降噪分数明细、查询根因簇及裁决依据、查询推迟队列与预算账目的接口；事件须带严格递增序号且可重复读取，JSON 字段集合与业务码集合须固定，所有异常以业务码返回而不得泄漏内部堆栈。
8. 提供本地确定性告警源桩与可重复测试：实现可配置告警集合、响应延迟、超时与故障注入的本地告警源桩，不依赖外网与真实账号；pytest 用例须在 Windows 离线覆盖跨来源去重、同步偏差标注、预算耗尽推迟、抓取超时回收、根因簇裁决与重启恢复，并在固定随机种子与固定并发配置下重复运行结论一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
