当前是空白工作区，需要从零构建一个面向本地微服务测试环境的变更风险分级与自动回滚裁决工作台，交付可交互的专业应用与可重复演示。工作台维护若干服务及其变更批次：每个变更批次声明目标服务、变更类型（配置下发、镜像升级、扩缩容）、批次规模、变更前基线与变更后候选指标观测（毫秒时间戳、错误率、P90 延迟毫秒、成功率）。系统需依据带版本号的风险策略快照（各指标的判定阈值、观察窗口长度、风险阈值、自动回滚开关与冷却期）对每个变更批次计算风险分与风险等级，并裁决是否继续观察、放行或触发自动回滚。核心业务难点在于交互延迟与计算结果一致性：调用方可在低延迟预算下请求快速裁决，也可请求完整裁决，两种模式必须对同一变更批次与同一策略版本给出可核对、可解释的结论；观测数据持续到达，迟到样本、重复上报与策略版本切换会改变风险计算，若处理不当会出现同一批次在控制台显示已回滚而计算结果仍按放行统计的不一致。用户通过本地 HTTP 接口提交策略快照、变更批次与观测，查询风险分与裁决结论，所有数据来自本地确定性样本，不依赖真实集群。

任务环境与准备：
确认 Windows 本地已安装 Python 3.11 及 pip，可创建虚拟环境；无外部服务依赖。
在空白工作区创建项目目录与虚拟环境，安装 fastapi、uvicorn、pytest，SQLite 使用 Python 标准库 sqlite3。
准备本地确定性样本：一份策略快照 JSON、若干变更批次与观测事件批次（含重复序号、迟到样本与样本不足批次），以及一份含触发回滚与冷却期重触发的脚本输入。
准备快速与完整两种模式所需的配置参数（采样上限、置信上界、观察窗口长度）并写入样本配置，便于重复演示。
确认本地回环端口可用，服务以 uvicorn 启动，演示脚本通过本地 HTTP 调用接口并输出结果摘要。

业务要求：
1. 实现风险策略快照与变更批次模型：策略快照携带单调递增版本号、生成时间、各指标阈值、观察窗口长度、风险阈值与自动回滚开关及冷却期，以及整体校验摘要；变更批次含目标服务、变更类型、批次规模与基线观测。提交策略时若版本号不大于当前已提交版本则返回业务码 E_STALE_POLICY 且不改变任何状态，字段非法返回 E_POLICY_INVALID。
2. 实现观测摄入与带版本的时间桶模型：观测按毫秒时间戳、批次标识与指标类型分配到窗口桶，桶记录样本数、成功数与延迟样本；同一批次同一序号的重复上报必须幂等，内容不一致返回 E_CONFLICTING_REPORT 并保留首次上报；进入关闭状态的窗口须按确定的迟到容忍规则处理迟到样本，不得静默改写已关闭窗口的统计。
3. 实现风险分计算：由错误率、P90 延迟偏离基线程度与成功率下降幅度合成风险分，各分项使用定点表示并输出每步舍入方式与累计舍入误差；分位延迟使用声明的确定性最近秩法并注明样本规模，样本不足时返回业务码 E_INSUFFICIENT_SAMPLES 而非静默给出零风险。
4. 实现风险等级与变更状态机：变更批次状态至少包含 OBSERVING、PASSED、ROLLING_BACK、ROLLED_BACK、ESCALATED 五种并规定合法迁移路径，非法迁移返回 E_INVALID_TRANSITION 且不修改已持久化状态；风险等级与状态迁移须依据同一窗口版本与同一策略版本共同裁决，禁止风险分按新窗口算出而状态按旧窗口迁移的中间状态。
5. 实现低延迟快速裁决与完整裁决两种模式：快速模式按配置的采样上限只使用部分观测并输出采样率、采样方法与结论置信说明，完整模式使用窗口内全部观测；两种模式对同一策略版本与同一批次须在结论差异处可逐项核对，快速模式结论越过风险阈值而置信下界低于配置的置信上界时须降级为需完整复核，禁止把快速结论直接用于自动回滚。
6. 实现自动回滚的冷却期与并发一致：触发自动回滚须同时校验策略开关、批次状态与冷却期，冷却期内重复触发返回 E_ROLLBACK_COOLDOWN 并附剩余冷却时长；回滚结论、批次状态与冷却期占用必须在同一事务边界内生效，查询只能看到某一完整提交版本，不得出现批次已 ROLLED_BACK 而冷却期未占用或统计仍按放行计入的中间状态。
7. 实现意图持久化与强制终止后恢复：策略提交、观测摄入、风险重算与回滚裁决均先写入 SQLite 意图记录再提交事务；进程在风险重算或回滚中途被强制终止后重启必须扫描未完成意图，把批次与窗口回滚到最后一个完整提交边界或将对应操作标记为已中止，恢复报告只基于已持久化事实，不得承诺强制终止后仍生成完整退出报告。
8. 提供本地 HTTP API 与可重复演示脚本：API 覆盖策略提交、变更批次提交、观测摄入、按批次查询风险分与裁决结论及误差说明、查询回滚冷却状态与恢复报告，失败响应统一为含业务码与上下文的 JSON；脚本使用固定本地样本完成一次放行裁决、一次触发自动回滚、一次冷却期重触发、一次快速与完整模式结论对照以及一次强制终止后恢复演示，输出每批次风险分、等级、状态轨迹与恢复差异摘要。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地固定样本跑通策略提交、风险分级、自动回滚与强制终止恢复，核验裁决结论与误差说明一致。
