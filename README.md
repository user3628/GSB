当前是空白工作区，没有现存项目、代码或数据附件。需要从零实现一个面向本地 Kubernetes 调度模拟场景的「Pod 亲和性增量重算与依赖失效诊断工作台」。Kubernetes 调度中，Pod 的调度决策依赖节点标签、已运行 Pod 集合、亲和/反亲和规则与污点容忍关系；当某个节点标签被修改、某个 Pod 被删除或新增、某条亲和规则被调整时，并不是所有既有调度决策都失效——只有依赖该变更实体的候选节点评估、过滤结果与打分明细需要重算，其余决策应复用上一轮结果。工作台需维护节点、Pod、调度请求、规则与决策之间的依赖图，接受运维人员提交的状态变更补丁，沿依赖图计算失效闭包并只对闭包内实体增量重算调度决策，同时提供诊断报告说明每个失效实体的直接触发变更与传播路径。Kubernetes 的真实调度语义决定了失效判定必须精确：节点标签变更只影响引用该标签选择器的亲和规则与候选节点评估；Pod 新增只影响同标签域内的拓扑分布与反亲和候选评分；规则调整只影响引用了该规则的调度请求。增量重算结果必须与从零全量重算逐字段等价，且并发补丁提交与快照替换不得产生基于陈旧依赖图的结果。

任务环境与准备：
安装 Python 3.11 及以上版本，并确保 python 与 pip 可从命令行调用。
在空工作区创建项目目录，通过 pip 安装 Flask、NumPy 与 pytest，版本以本机可离线安装的稳定版为准。
确认 SQLite 随 Python 标准库可用，无需外部数据库服务；本地 HTTP 接口只绑定回环地址与高位端口。
准备本地样本目录用于存放节点、Pod、规则与调度请求的 JSON 初始数据及补丁样本，全部为本地确定性文件，不依赖网络、真实集群或云账号。
在 Windows 命令行中确认可运行 pytest 与启动服务的命令，测试全程离线可重复。

业务要求：
1. 实现调度状态模型与补丁解析：状态包含节点（节点名、可分配 CPU 毫核、内存字节、标签映射、污点列表）、Pod（Pod 标识、所属节点、标签映射、资源请求）、亲和/反亲和规则（required 与 preferred 两类、标签选择器、拓扑域键）与调度请求（请求标识、目标 Pod、插件打分权重）。补丁以 JSON 操作序列描述对节点标签、Pod 归属、规则内容与打分权重的增删改；解析时须检测目标路径不存在、类型不匹配与操作引用的实体缺失，分别返回 E_BAD_PATCH_PATH、E_BAD_PATCH_TYPE 与 E_UNKNOWN_ENTITY，且任一操作非法时整份补丁不得部分生效。
2. 维护实体依赖图与版本链：依赖图须记录节点标签到规则选择器、Pod 标签到拓扑域与反亲和规则、规则到调度请求、打分权重到调度请求的引用关系，并能回答给定实体的传递依赖方与被依赖方；每次成功应用补丁生成递增版本号，版本记录包含父版本、补丁摘要、受影响实体集合与决策快照摘要，全部持久化到 SQLite。依赖图须支持按实体键增量更新，不得每次补丁重建整张图。
3. 实现增量失效闭包计算：应用补丁后须从变更实体出发沿依赖图计算失效闭包，闭包必须包含直接变更实体与全部传递依赖方，且不得包含与变更无关的实体；节点标签变更只使引用该标签选择器的规则及其所在调度请求失效，同一节点上被其他调度请求引用的节点评估不得因此失效；Pod 新增只使同拓扑域内的偏好打分与反亲和候选失效；须输出闭包内每个实体的直接触发变更实体与传播路径。
4. 实现局部决策重算与全量等价校验：只对失效闭包内的调度请求重新执行过滤、打分与选定节点，未失效请求复用上一版本决策；重算后的完整决策快照须与从零全量重算结果在规范化序列化后逐字段比较等价，字段包含候选集合、过滤原因键、各插件分数、并列裁决结果与最终选定节点。局部重算过程中若某请求重算失败，须保留其上一版本决策并将该请求标记为 stale，不得写入半成品决策。
5. 实现容差内的确定性并列裁决与打分数值归一：各插件输出 [0,100] 分数按权重加权求和，得分差值小于配置相对容差（默认 0.02）时判定并列，按更少资源碎片、更多可用内存、节点名字典序次序裁决；插件分数与加权和须以十进制定点字符串输出并保留声明的小数位，禁止依赖二进制浮点默认表示造成相同输入结果抖动。裁决依据须随决策快照一并记录。
6. 实现并发补丁提交与快照替换的互斥：同一工作台的决策快照生成期间到达的新补丁必须等待当前快照完成后才计算失效闭包，避免基于陈旧依赖图生成决策；并发补丁提交须串行化版本号分配，保证版本号严格递增且无空洞；补丁应用失败不得消耗版本号。并发锁等待须有真实超时，超时返回 E_CONTENTION_TIMEOUT。
7. 实现持久化与进程重启恢复：版本链、依赖图、决策快照与诊断报告须在快照提交点以单事务写入 SQLite，事务提交后才对查询可见；快照整体替换须识别版本变化并原子替换元数据文件，替换前旧快照保持可读。重启后须将中断的补丁应用回退为未提交、把处于重算中的请求标记为 stale，并从最近已提交版本恢复依赖图与决策，恢复后对同一补丁重算的结果与重启前一致。
8. 提供本地 HTTP 诊断接口与可重复测试：通过本地 HTTP 提供提交补丁、查询版本链、查询实体依赖图、查询决策快照差异、查看失效闭包诊断报告与强制全量重算对比的接口，错误统一以固定业务码在 JSON 响应中返回。内置本地样本包含至少四个节点、六个 Pod、五条规则与四个调度请求，覆盖共享标签选择器与拓扑域变更场景；pytest 用例须在 Windows 离线覆盖非法补丁拒绝、失效闭包范围正确、局部与全量等价、并列裁决确定性、并发超时与重启恢复。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证补丁后失效闭包范围正确、局部重算与全量重算逐字段等价，且并发与重启后可复现。
