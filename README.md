当前是空白工作区，需要从零实现一个面向本地数据处理平台的跨组件 ETL 编排管线，用于在离线环境下复现真实平台中『多个组件协同推进同一份数据处理状态』的核心机制。管线由若干处理阶段组成（抽取、规范化、聚合、导出），阶段之间通过中间数据集形成依赖图；一次运行由运行标识驱动，每个阶段在依赖数据版本满足后才能推进，推进结果包括输出数据集版本号、行数摘要与内容摘要。平台要求支持同一批输入被多次运行复用（命中已发布的数据集版本）、运行中途失败、进程重启后从持久化断点继续，以及依赖数据在运行期间被新版本替换时受影响的阶段必须失效重算。管线状态必须通过 SQLite 持久化，运行推进与结果查询通过本地 HTTP 接口暴露，数据集内容以本地 NumPy 数组与 JSON 元数据落盘。

任务环境与准备：
安装 Python 3.11 与 pytest，使用标准库 sqlite3 与 http.server 搭建本地服务，NumPy 需预装且全程离线。
在空白工作区创建项目目录与样本数据目录，样本数据由固定随机种子的生成脚本产出，不依赖任何网络资源。
运行测试前先执行样本生成与目录初始化脚本，确认 SQLite 数据库文件与数据集目录可写。

业务要求：
1. 实现数据集与阶段的声明模型：数据集含名称、版本号、行数、列名与内容摘要，阶段含标识、输入数据集名列表、输出数据集名、处理算子类型与参数；启动时须校验依赖图无环且所有输入数据集可解析，缺失输入返回 E_MISSING_INPUT，成环返回 E_CYCLE，错误必须在任何计算开始前返回。
2. 实现确定性处理算子：至少提供过滤、列映射、按指定键分组求和与连接四类算子，输入输出以 NumPy 数组批量推进且输出行序按排序键与分组键的确定次序归一化；相同输入数据集版本与相同参数重复计算必须产出逐值相同的输出数组与相同内容摘要。
3. 实现基于版本键的运行推进状态机：阶段状态取值必须为 pending、ready、running、done、failed、skipped，只有全部输入数据集版本齐备且摘要与运行开始时记录的期望输入版本一致时才允许迁移到 ready；非法迁移须拒绝并返回 E_INVALID_TRANSITION，且不得改动已持久化的数据集版本。
4. 实现运行中途失败与重启断点恢复：每个阶段完成时须在单个 SQLite 事务中写入输出数据集版本、状态迁移与阶段事件，事务提交后才视为完成；进程重启后须从最后一个已提交阶段继续推进，中断时处于 running 的阶段回退为 ready 并重算，已完成阶段不得重算。
5. 实现依赖版本变化导致的失效传播：运行期间若某输入数据集被发布新版本，沿依赖图计算失效闭包，闭包内已 done 的阶段须置为 pending 并在后续推进中重算，闭包外的阶段保留结果；失效计算与阶段推进须在同一一致性边界内完成，不得出现依据新旧混合版本产出的阶段结果。
6. 实现数据集版本复用与发布互斥：同一输出数据集已有内容摘要相同且参数相同的已发布版本时须复用该版本而不重复写盘，复用须在运行报告中标记；新版本发布须分配严格递增版本号并原子替换元数据文件，替换前旧版本保持可读，摘要校验失败须返回 E_CORRUPT_DATA 且不发布。
7. 实现本地 HTTP 接口与运行报告：提供提交运行、查询运行状态与阶段事件序列、查询数据集版本清单、查询依赖图与失效诊断报告的接口；事件须按严格递增序号持久化且可重复读取，运行报告须列出每阶段的状态、输入版本、输出版本、是否复用与耗时，错误须以固定业务码在 JSON 中返回。
8. 提供本地确定性样本与可重复测试：样本须包含至少四个阶段、三个中间数据集与一次新版本替换场景，pytest 用例须覆盖命中复用、非法状态迁移、失败后重启续跑、版本变化失效闭包、缺失输入与成环拒绝，全部在 Windows 上离线运行且结果稳定。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
