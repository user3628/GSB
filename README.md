交付从新建的代码库开始，需要从零构建一个面向本地多组件平台协同的并行调度与资源预算裁决管线，交付数据处理管线与结果验证工具。平台包含一个分发协调器与若干本地组件端点（以本地 HTTP 测试服务模拟），每个组件声明其处理任务所需的 CPU 预算（毫核整数）与内存预算（字节整数），并声明依赖的上游组件。协调器接收带版本号的任务批次快照，依据组件依赖关系生成并行调度计划，在全局并发上限、每轮时间预算与每组件资源配额三重约束下把任务分派到各本地组件端点，采集处理结果与资源消耗，并输出每个任务的裁决结论、资源预算消耗明细与跨组件一致度评分。进程可能在任何时刻被强制终止，重启后必须依据持久化事实恢复调度状态与预算占用。

任务环境与准备：
安装 Go 1.22 或更高版本（Windows 官方安装包），执行 go version 确认可用。
使用 Go 标准库 net/http 与 database/sql，配合纯 Go 的 SQLite 驱动（如 modernc.org/sqlite），通过 go get 拉取，无需 CGO 与本地数据库服务。
准备本地确定性 JSON 样本：组件声明、任务批次快照与增量片段，以及若干本地 HTTP 测试端点，可由测试脚本以未监听端口、不响应端口与正常响应端点模拟三类结果。
确认本地回环端口可用，所有端点仅绑定 127.0.0.1，不访问外部网络。
在任务执行前运行 go mod tidy 完成依赖解析。

业务要求：
1. 实现组件声明与任务批次模型：组件声明包含组件标识、CPU 配额毫核整数、内存配额字节整数、依赖的上游组件列表与本地端点地址；任务声明包含任务标识、所属组件、CPU 与内存需求、优先级与期望完成时限毫秒。解析本地确定性 JSON 样本时须校验组件标识唯一、依赖引用存在、配额与需求为非负整数并做溢出检查，解析失败或引用未声明组件时返回业务码 E_SPEC_INVALID 且整批不生效。
2. 实现带单调版本号的任务批次快照与增量提交：快照携带版本号、生成时间、任务集合与整体校验摘要，增量片段只含受影响的任务并携带基础版本号。提交时若版本号不大于当前已提交版本返回 E_STALE_SNAPSHOT；增量提交时若基础版本不是当前版本则返回 E_STALE_BASE 且不改变任何已提交状态；同一基础版本的两个并发增量只允许一个成功，另一个必须收到 E_STALE_BASE。
3. 实现依赖拓扑校验与并行调度计划生成：依据组件依赖关系生成按拓扑分层排序的调度计划，层内任务可并行、跨层任务必须等待上游层全部完成。依赖出现环时返回 E_DEPENDENCY_CYCLE 并附环上组件标识；引用了未声明组件的任务返回 E_UNKNOWN_COMPONENT。计划须输出每个任务的层级、所属层以及并行度上界。
4. 实现三重预算并行调度器：调度轮次受全局并发任务上限、每轮时间预算与每组件 CPU 与内存配额共同约束。预算内按任务优先级与到达顺序取任务派发到本地组件端点，超出并发上限的任务进入有界等待队列，队列满返回 E_QUEUE_FULL；若某任务的资源需求超过其所属组件剩余配额则返回 E_QUOTA_EXCEEDED 并附当前占用与差额，不得绕过配额派发。
5. 实现真实可中断的任务派发与资源释放：派发到本地组件端点的请求具备独立超时，超时后必须真实关闭底层 HTTP 连接并释放其占用的并发名额与组件资源预留，返回 E_DISPATCH_TIMEOUT，不得以等待冒充超时，也不得把 goroutine 超时描述为已终止失控的执行。派发结果须区分成功、业务拒绝、连接失败与超时四类，并写入调度轨迹。
6. 实现资源预留与派发结果的跨模块一致及幂等：任务准入、组件资源预留与派发状态必须共同生效，禁止出现任务已派发而组件资源未预留、或任务已完成而预留未释放的中间可见状态。同一请求标识重复提交只执行一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_REQUEST；查询只能看到某一完整提交版本，跨组件一致度评分须与本次预留和派发结果读取同一提交版本。
7. 实现预算耗尽时的确定性降级裁决：当待派发任务规模超出并发与时间预算可覆盖范围时，按任务优先级、组件轮转与已消耗预算给出确定性降级顺序，被降级任务迁移为 SHED 状态并输出降级依据与剩余预算；降级后仍须保证已派发任务不被无谓中断，并输出本轮预算消耗明细（并发名额、CPU 毫核、内存字节与时间余量）。
8. 使用 SQLite 持久化批次版本、任务状态、组件资源预留与调度轮次，所有写操作先写意图记录再提交事务；进程在派发或预留中途被强制终止后重启须扫描未完成意图，把未提交派发回滚为待调度、未提交预留回滚为可用，并把未完成轮次标记为已中止或按持久化事实重排；恢复报告只包含已落盘事实。统一失败响应为含业务码与上下文的 JSON，至少覆盖 E_SPEC_INVALID、E_STALE_SNAPSHOT、E_STALE_BASE、E_DEPENDENCY_CYCLE、E_UNKNOWN_COMPONENT、E_QUOTA_EXCEEDED、E_QUEUE_FULL、E_DISPATCH_TIMEOUT、E_CONFLICTING_REQUEST。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证依赖拓扑调度、三重预算裁决、超时释放与强制终止后恢复，附运行结果与恢复报告。
