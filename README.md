当前为空工作区，需从零构建一个本地可运行的 GEMM（单矩阵乘）与 BMM（批量矩阵乘）算子库及完整示例，用于在不同数据规模下做真实的分块与算法取舍验证。输入为本地确定性生成的浮点矩阵集：小规模（64×64×64）、中规模（512×256×384）、大规模（1024×1024×1024）以及若干批量矩阵乘样本，含批量维度、非方阵、带转置 A/B 标志与含 NaN/Inf 的异常样本，均以固定随机种子生成并落盘为本地 .npy 文件，附形状清单。算子需实现分块矩阵乘核心（寄存器块、缓存块与累加策略）、基于形状启发式的分块参数选择、对批量维度的一致处理、结果误差估计、以及可持久化的调优配置。系统不依赖 BLAS 之外的第三方加速库，不依赖 GPU，所有精度观测均在本机 CPU 上以固定随机种子与固定测量方式取得；真值来源为同输入的二次幂分解求和参考实现与高精度累加基准，误差比较方式为对该基准逐元素求绝对与相对偏差。

任务环境与准备：
Windows 本地环境，安装 Python 3.11 与 NumPy（如 1.26），不依赖 GPU、BLAS 之外的加速库或外部服务。
从新工作区创建项目目录，包含算子库源码、示例脚本、本地确定性样本生成脚本与工作区数据目录。
用固定随机种子生成三档规模、非方阵、转置标志组合、批量样本及含 NaN/Inf 的异常样本，落盘为本地 .npy 文件并记录形状清单。
准备二次幂分解求和参考实现与高精度累加基准作为误差比较真值来源，并记录其生成方式与比较方式。
准备版本化配置存储目录与文件锁工作目录，确认命令行与本地接口可在无网络条件下运行。

业务要求：
1. 实现 GEMM 与 BMM 的统一分块内核：以寄存器块（MR×NR）、缓存块（MC×KC、KC×NC）三层分块组织 K 方向累加，支持 A/B 转置标志与任意合法非方阵形状；BMM 在循环最外层展开批量并复用同一内核，要求批量内每个矩阵结果与单独 GEMM 逐元素完全一致，且不同批之间不得发生累加器状态串扰。
2. 实现基于数据规模的自动分块参数选择：依据 M/N/K、批量大小与可配置的 L1/L2 缓存预算估计工作集，从候选分块方案中按预测访存量与并行维度打分选出方案，并记录选择理由与打分明细；小规模输入须避免过度分块的开销，大规模输入须限制工作集在预算内。当用户显式指定分块时须校验整除边界与块尺寸上限。
3. 实现数值精度与误差来源控制：累加按可配置的求和策略（顺序求和、成对求和、补偿求和）执行，并对每种策略给出与高精度参考结果的误差上界估计；当输入含 NaN 或 Inf 时须按 IEEE 语义传播而非静默置零，并在结果摘要中报告污染元的出现位置统计；误差估计须说明所依赖的高精度真值来源与比较方式。
4. 实现结果正确性自校验与异常链路：对每个输出矩阵抽样若干行块与二次幂分解求和参考实现比对，超出可配置容差的块须报告块行列区间与最大偏差并返回业务码 E_NUMERIC_MISMATCH；当出现形状非法、批量维度不一致、转置标志与形状冲突时，分别在参数校验阶段返回稳定的 E_INVALID_SHAPE 与 E_BATCH_MISMATCH，且不得部分写出输出缓冲。
5. 实现分块调优配置的持久化与版本识别：将自动选择与用户指定的分块方案连同输入形状指纹、求和策略与缓存预算写入版本化配置存储，每版本以原子方式写入含单调序号与摘要的记录；当检测到配置记录被整体替换（序号回退、指纹或摘要不匹配）时须区分正常推进、回退与篡改，只有正常推进可被采纳，其余返回 E_STALE_CONFIG。
6. 实现并发调优与结果缓存的一致性：多个工作进程对同一工作区发布分块方案或缓存结果时使用文件锁并比较版本序号，仅允许序号连续推进，落后或重复发布返回 E_STALE_PUBLISH；缓存键须包含形状指纹、分块方案、求和策略与输入数据摘要，键命中但版本失配时不得复用旧结果，须失效重建。
7. 实现内存预算约束下的执行调度：在可配置的峰值内存上限内规划输出缓冲、工作块与 BMM 批量切片的内存占用，超预算时须按批量切片拆分执行或返回带预算明细的 E_MEMORY_BUDGET，而非依赖运行时崩溃；调度须为每个分片记录实际峰值估算与预算余量，且拆分执行的结果须与不拆分执行逐元素一致。
8. 提供可集成的算子库接口与完整示例：以库函数与命令行提供 GEMM/BMM 调用、分块方案查询、误差报告、配置版本查询与调优缓存管理；示例须用本地确定性样本覆盖三档规模、非方阵、转置与含 NaN 的异常样本，一次完整运行产出固定摘要，并演示一次配置版本回退被拒与一次内存预算触发的切片执行，展示对应业务码与恢复后的一致性。
