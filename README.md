预算与交付周期敲定之后，团队需要在这台 Linux 开发机上把正向与反向代理转发的诊断工作台作为独立服务实现出来，此前没有任何可复用代码。工作台维护一组路由：反向路由按方法与路径前缀匹配并转发到本地后端测试服务，正向路由按目标主机与端口经本地出口转发，每条路由声明上游地址、超时毫秒、重试次数、请求头与健康状态。配置以带单调版本号的 JSON 快照整体提交，运维也可提交只含受影响路由的增量片段。路由关键字段变化会让该路由的编译产物（匹配表项、连接池分组、健康探测计划、转发规则缓存）连同依赖它们的匹配聚合索引与上游预算聚合一并失效。由于超时与重试须叠加为连接预算与总等待预算，而配置热更新又与并发转发交错，本工作台的核心是增量提交的原子性与转发链路上的定点数值一致：每次推导都必须给出可复核的舍入误差与累计误差上界。

任务环境与准备：
在 Linux（WSL Ubuntu）开发机上安装 Go 1.22 及以上版本（如 sudo apt install golang-go 或使用官方二进制包），确认 go version 可执行。
安装 SQLite 命令行工具（如 sudo apt install sqlite3），Go 的 SQLite 驱动依赖通过 go mod tidy 获取，不引入容器或外部服务。
准备本地后端测试服务与本地出口服务各一个，均由任务内自行启动的本地 HTTP 服务模拟，监听回环端口，提供可配置的正常、拒绝、超时与 5xx 响应。
准备带固定种子的本地路由配置快照与增量片段样本生成脚本，样本中包含共享同一上游的混合量级超时与重试组合，以及无匹配路由与非法上游地址情形。

业务要求：
1. 实现代理转发核心：反向路由按方法与路径前缀匹配，正向路由按目标主机与端口经本地出口服务转发；正确传递方法、路径、查询串、请求头与请求体，并把上游状态码与响应体回传客户端；无匹配路由返回 E_NO_ROUTE，上游地址非法在提交快照时即返回 E_UPSTREAM_INVALID。
2. 实现带版本号的配置快照与增量片段提交：快照携带单调递增版本号、生成时间与整体校验摘要，提交时版本号不大于当前已提交版本返回 E_STALE_SNAPSHOT；增量片段只含受影响路由并携带基础版本号，基础版本不是当前版本时返回 E_STALE_BASE 且不改变任何已提交状态。
3. 实现路由预算推导与定点数值契约：由每条路由的超时毫秒与重试次数推导单次连接预算、总等待预算与健康惩罚权重，归一化到同一内部定点表示并保留固定小数位，输出每步舍入方式与累计舍入误差；同一快照与同一路由集合重复推导必须逐位一致，超时为零或重试次数为负返回 E_BUDGET_INVALID。
4. 实现跨路由累计预算的数值稳定性：多条路由共享同一上游时，按上游累计总等待预算与惩罚权重使用 Kahan 或等价补偿求和，并与朴素求和在混合量级固定样本上对比给出可量化误差上界；累计结果须对路由数量与提交顺序不敏感，越过声明预算上界返回 E_BUDGET_OVERFLOW 并指明上游与超出量。
5. 实现依赖失效与级联原子重建：每条路由的匹配表项、连接池分组、健康探测计划与转发规则缓存，以及匹配聚合索引与上游预算聚合，须在路由关键字段变化时级联失效并在同一事务边界内原子重建；禁止出现部分产物已更新而另一些仍为旧值的可见状态，重建中途失败须整体回滚到上一完整版本。
6. 实现转发与配置更新的并发一致：读请求路径不得看到半更新配置，更新期间已在途请求按其绑定的路由版本完成转发；同一基础版本的两个并发增量提交只允许一个成功、另一个返回 E_STALE_BASE；同一请求标识重复提交只执行一次、其余等待并复用同一结果，内容不一致返回 E_CONFLICTING_REQUEST。
7. 实现真实超时、异常链路与业务码体系：区分连接超时、读取超时、上游连接拒绝与上游 5xx，超时后必须真实关闭底层连接并释放并发名额，不得以等待冒充超时；失败响应为含业务码与上下文的 JSON，至少覆盖 E_STALE_BASE、E_STALE_SNAPSHOT、E_BUDGET_INVALID、E_BUDGET_OVERFLOW、E_NO_ROUTE、E_UPSTREAM_TIMEOUT、E_UPSTREAM_REFUSED、E_CONFLICTING_REQUEST。
8. 实现基于 SQLite 的意图持久化与强制终止恢复，并提供可视化诊断工作台与端到端演示脚本：路由快照、增量提交与级联重建前先写意图记录再提交事务，进程被强制终止后重启须扫描未完成意图把配置回滚到最后一个完整提交或把增量标记为已中止；诊断页面展示路由视图、预算分解与舍入误差、命中聚合与重建轨迹，恢复报告只包含已落盘事实。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
