在一台没有历史代码的机器上，需要从零构建一个面向多租户 Web 服务的身份认证与会话隔离验证引擎。系统包含登录端点、令牌签发与校验、会话状态存储与租户级隔离边界，并需对认证流程中的异常路径进行可复现验证。认证流程采用本地确定性样本：预置租户、用户、口令哈希与密钥材料，不依赖外部身份提供商。引擎需在单进程内模拟多租户并发登录与令牌使用，维护带版本号的会话快照，并支持通过参数注入过期令牌、跨租户令牌重用、会话固定、权限提升与并发刷新竞争五类异常，验证隔离边界不被突破且状态可恢复。交付形式为可直接运行的 Go 命令行程序、可集成的包接口以及可重复的本地实验环境。

任务环境与准备：
安装 Go 1.22 或更高版本，配置 GOPATH 与模块代理可用，确认 go version 可在命令行执行。
Windows 上准备一个可写的本地工作目录，SQLite 采用纯 Go 驱动（如 modernc.org/sqlite），通过 go get 获取，不依赖 CGO。
准备本地确定性样本生成所需的固定租户、用户、口令与密钥材料脚本，样本由程序自身生成，不依赖网络下载或真实账号。
确认命令行可执行程序可创建本地临时文件与 SQLite 数据库文件，实验过程不要求管理员权限或外部服务。

业务要求：
1. 实现本地登录与令牌签发核心：依据预置的租户、用户与口令哈希样本完成凭证校验，签发绑定租户标识、用户标识、会话标识与过期时间的访问令牌与刷新令牌；令牌须使用本地密钥进行完整性签名，校验时严格拒绝签名不符、过期或租户标识缺失的令牌，并返回稳定业务码 E_TOKEN_INVALID，不得泄露用户是否存在。
2. 实现租户级会话隔离边界：会话存储按租户分区，任何令牌校验与刷新操作必须先解析令牌所属租户并仅在该租户分区内查找会话；跨租户使用令牌时返回 E_CROSS_TENANT 且不得改动任何租户的会话状态，隔离判定不得依赖调用方传入的租户参数。
3. 实现带版本号的会话快照与恢复：每个租户会话集合维护递增版本号快照，登录、刷新、撤销均产生新版本并持久化到 SQLite；读取时校验版本链连续性，发现跳号返回 E_SNAPSHOT_VERSION 并回退到最近连续版本；快照比较须识别整体替换式变化，即使版本号相同但内容摘要不同也须拒绝加载。
4. 实现令牌轮换与会话固定防护：刷新令牌每次使用后原子地失效旧令牌并签发新令牌，记录令牌族谱与序号；旧刷新令牌再次使用时整族撤销并返回 E_TOKEN_REUSE；登录成功后必须更换会话标识，不得沿用登录前客户端提供的会话标识，否则返回 E_SESSION_FIXATION。
5. 实现并发登录与刷新竞争的资源控制：并发请求按租户串行化会话变更，以可配置上限的信号量限制在途认证事务，超出等待阈值的请求返回 E_AUTH_CONTENTION 而非无限阻塞；同一刷新令牌并发提交时仅一次成功，其余返回 E_TOKEN_REUSE 或 E_AUTH_CONTENTION，且会话状态不得出现双活令牌。
6. 实现异常注入验证入口：通过命令行参数或配置文件注入过期令牌、跨租户令牌重用、会话固定、权限提升尝试与并发刷新竞争五类样本，分别断言对应业务码、目标租户会话状态终态未被污染、快照版本变化符合预期；注入仅通过输入参数完成，不得修改源码，每类注入可独立运行且结果确定。
7. 实现权限边界校验与提升拒绝：令牌中声明的角色与权限须与租户内该用户当前授权记录一致，令牌携带超出授权记录的角色或访问其他租户资源时返回 E_PRIVILEGE_ESCALATION；权限变更后旧令牌不得继续携带已撤销权限，校验失败不影响其他会话。
8. 提供可集成的 Go 包接口与可重复实验环境：导出认证中间件与会话存储接口供宿主服务接入，附带本地确定性样本生成入口（租户、用户、口令、密钥与注入脚本）与一键运行实验的命令，重复运行且输入不变时输出的会话状态导出与验证报告字节级一致，报告中版本号必须来自实际快照递增。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证登录签发、租户隔离与五类异常注入的业务码及快照状态一致性，重复运行报告字节级一致。
