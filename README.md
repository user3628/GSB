在一台没有历史代码的机器上，需要从零构建一个面向本地列式样本数据的 Join Shuffle 聚合引擎，交付可集成的领域组件与完整示例。引擎读取左右两张带版本号与校验摘要的本地列式快照（整数键列、双精度度量列、空值位图），按请求中的 Join 规格执行哈希 Shuffle 分区、分区内连接与分组求和、均值、计数聚合。业务核心是数值精度与误差传播：Shuffle 分区会改变求和顺序，分区间部分和再合并的顺序又会影响最终结果；因此引擎必须支持可切换的求和实现（朴素、补偿、参数化 DoubleDouble 定点提升），对每种实现给出可核对的误差声明，并保证同一输入在声明精度目标下无论分区数、分批提交方式与查询时刻如何变化，聚合结果都落在契约内且可复现。所有数据与测试均由本地确定性样本与本地 SQLite 产生。

任务环境与准备：
Windows 10 或以上，已安装 Go 1.21 或以上并配置 GOPATH 与模块代理可用；执行 go version 确认可用。
安装 SQLite 3 命令行工具用于人工核对，Go 项目使用纯 Go 的 SQLite 驱动依赖，版本在 go.mod 中固定。
创建全新工作目录，初始化 Go module，生成固定本地列式样本文件（左右表各含整数键、双精度度量与空值位图）与校验摘要文件。
提供本地 HTTP 服务默认监听 127.0.0.1 的约定端口，脚本通过环境变量指定端口；不依赖任何线上站点、账号或外部数据集。
准备固定随机种子与样本生成脚本，保证同一脚本多次运行生成逐位一致的样本与摘要。

业务要求：
1. 实现列式快照加载与整体替换：快照携带单调递增版本号、生成时间、整数键列、双精度度量列、空值位图与整体校验摘要；加载时校验版本单调与摘要，任一失败返回 E_SNAPSHOT_INVALID 且必须保持旧快照完全可用；加载成功须整体替换旧快照，不得把新旧快照的列数据混合使用。
2. 实现可参数化的三种分组求和实现：朴素顺序求和、Kahan 补偿求和与 DoubleDouble 定点提升求和；每种实现须在同一份分组数据上返回结果并输出所用算法标识、中间补偿状态摘要与可量化的误差上界声明；算法标识与参数须随请求显式指定或由精度目标推导，禁止在未声明的情况下静默切换算法。
3. 实现哈希 Shuffle 分区与分区内 Join：按键的确定性哈希把两表记录分配到请求指定的固定分区数，保证同一键的所有记录落入同一分区；分区内先按度量绝对值与键稳定排序再执行连接，支持内连接与左外连接，左外连接未匹配侧的度量按空值处理且不参与求和与均值但计入分组计数。
4. 实现与分区数无关的稳定归并顺序：合并各分区部分和之前须按声明规则对部分和排序（如按分区号、按量级分桶或按补偿状态合并），使同一输入在任意分区数（含单分区）下，对同一键的分组聚合结果落在声明的相对容差内；引擎须输出归并顺序依据与每个键在各分区数下的最大相对偏差，偏差超出容差返回 E_PRECISION_TOLERANCE_EXCEEDED 并附键与双方数值。
5. 实现精度预算与计算路径取舍：请求可声明相对精度目标或计算预算，引擎依据分区数、度量量级分布与偏斜度在高精度路径（补偿求和加稳定归并）与快速路径（朴素求和）之间选择，并输出所选路径、选择依据、该路径的误差上界声明与适用结论；两条路径分别执行时须各自可复现，同一路径在同一输入下多次执行结果逐位一致。
6. 实现偏斜检测与分区产物的跨模块一致性：键分布偏斜导致某分区记录数占比超过声明阈值时标记该分区并输出偏斜度、阈值与受影响键；分区产物（记录数、字节估计、部分和、分组计数）与最终聚合结果须在同一事务边界内共同生效，禁止出现部分和已写入而分区统计未更新、或聚合结果已可查询而某分区部分和未落库的中间可见状态；查询只能看到某一完整提交版本。
7. 使用 SQLite 持久化快照版本、分区计划、部分和、聚合结论与意图日志，写操作先写意图记录再提交事务；进程在 Shuffle 或归并中途被强制终止后重启须扫描未完成意图，把执行标记为已中止或回滚到最后一个完整提交版本，恢复报告只基于已持久化事实；同一请求标识重复提交只执行一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_REQUEST。
8. 提供本地 HTTP API 与可重复实验脚本：接口覆盖快照加载、Shuffle 与 Join 提交（含求和算法、分区数与精度参数）、按请求查询分区统计与分组聚合结果、误差声明与选择路径查询、恢复报告查询；失败响应为含业务码与上下文的 JSON，至少覆盖 E_SNAPSHOT_INVALID、E_PRECISION_TOLERANCE_EXCEEDED、E_CONFLICTING_REQUEST、E_EXECUTION_ABORTED；脚本使用固定本地样本完成单分区与多分区结果对比、三种求和实现的误差对比、一次强制终止后恢复续并与最终结果核对。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定样本验证多分区数与三种求和实现下聚合结果的容差一致、精度路径选择声明及强制终止后恢复续算。
