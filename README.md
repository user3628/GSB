# 本地日志增量索引与崩溃恢复组件（实现交付）

本仓库已按下方任务书完成实现，任务书原文保留在本文档末尾。

## 快速开始

```bash
python -m venv .venv
# Linux/macOS
.venv/bin/pip install -r requirements.txt
# Windows PowerShell: .venv\Scripts\Activate.ps1 后 pip install -r requirements.txt

.venv/bin/python -m pytest tests/        # 53 个用例，含真实子进程强制终止恢复
.venv/bin/python scripts/demo.py         # 四段端到端演示
```

演示脚本会先清理 `runtime/demo.db`（含 WAL/SHM 侧车），从空状态重跑，
完整 JSON 输出在 `runtime/demo_output.txt`。手动启动服务：

```bash
LOGINDEX_DB=runtime/manual.db .venv/bin/python -m uvicorn \
    logindex.api:create_app --factory --host 127.0.0.1 --port 8765
```

## 交付物导航

- `logindex/`：解析器、状态机、numpy 索引算子、SQLite 存储、单写者引擎、FastAPI
- `samples/`：5 个确定性样本（5 服务 / 5 级别 / 毫秒时间戳 / 迟到与可重打记录 / 非法行）
- `tests/`：解析、状态机、索引、引擎、级联失效、并发、恢复、API 共 53 个用例
- `scripts/demo.py`：全量索引 → 仅追加 → 重打级联失效 → 强制终止恢复
- `docs/DESIGN.md`：事务边界、路径等价性、版本可见性、恢复真实性的技术说明

## 业务错误码

`E_LINE_INVALID`、`E_CONFLICTING_RECORD`、`E_INVALID_TRANSITION`、
`E_STALE_BASE`、`E_BATCH_NOT_FOUND`、`E_RECORD_NOT_FOUND`、`E_LOCKED`、
`E_INTERNAL`，HTTP 响应统一为 `{"error": {code, message, detail}}`。

# 附：任务书原文

当前是空白工作区，需要从零构建一个面向本地日志分析的增量索引与崩溃恢复组件，供上层日志检索客户端集成。组件读取本地确定性日志样本（每行含毫秒时间戳、服务名、级别与消息），构建按服务名与级别的分类索引以及时间轴区间索引，并支持带版本号的增量批次：新日志追加时只索引受影响的服务分区，历史批次删除或重打时间戳时依赖这些分区的时间轴区间索引必须级联失效并原子重建。组件使用 SQLite 持久化日志记录、索引条目、批次版本与意图日志，进程可能在任何时刻被强制终止，重启后必须依据持久化事实恢复到最后一个完整批次边界。核心难点在于增量索引与依赖失效之间的耦合：分类索引、时间轴区间索引、统计摘要三类派生产物的失效范围不同，还要与只读查询的版本可见性、单写者并发控制以及恢复报告的真实性同时成立。

任务环境与准备：
Windows 本地安装 Python 3.11 及以上，创建虚拟环境并用 pip 安装 fastapi、uvicorn、numpy 与 pytest，版本以安装时稳定版为准。
准备固定本地日志样本文件（不少于 5 个服务、覆盖多级别与毫秒时间戳，含可重打时间戳的记录），放入工作区样本目录。
确认 SQLite 为 Python 标准库自带版本即可，不需要外部数据库服务；所有服务监听本地回环端口。
运行前清理工作区中的数据库文件与日志目录，确保演示脚本可从空状态重复执行。

业务要求：
1. 实现日志记录解析与入库：每行含毫秒时间戳、服务名、级别、消息，解析失败返回业务码 E_LINE_INVALID 且整批不入库；合法记录以批次标识与行内序号唯一标识，重复提交同批次同序号内容必须幂等，内容不一致返回 E_CONFLICTING_RECORD 并保留首次写入值。
2. 实现三类派生产物：按(服务名, 级别)的分类索引、按服务名的时间轴区间索引（区间按时间戳排序合并重叠）、按批次的统计摘要（各服务各级别计数）；三者均由已提交日志派生，写入批次后只更新受影响分区而非全量重建，且同一批次重复应用不得产生重复条目。
3. 定义日志批次状态机，至少包含 PENDING、INDEXING、COMMITTED、INVALIDATED、ABORTED 五种状态并规定合法迁移路径，非法迁移返回 E_INVALID_TRANSITION 且不修改任何持久化状态；状态与批次版本号一并持久化，供恢复时判定最后完整边界。
4. 实现依赖失效传播：当某服务分区的时间戳被重打或某批次被删除时，该分区的分类索引、时间轴区间索引与统计摘要必须全部失效并在同一事务边界内原子重建，禁止出现分类索引已更新而时间轴区间索引仍为旧值的中间可见状态；查询只能看到某一完整提交版本。
5. 实现增量与仅追加路径的取舍：校验提交批次中的记录是否只含时间戳晚于该服务已有最大时间戳的追加记录，若是则走仅追加快路径不触发区间重建；否则走重建路径并输出重建原因与受影响分区清单。无关功能不得充当路径取舍依据，两条路径对同一数据必须得到相同的索引内容。
6. 实现单写者并发控制与幂等：批次提交与索引重建按提交串行执行，多个只读查询可并发读取已提交版本；同一批次标识重复提交只执行一次、其余等待并复用结果；携带基础版本的增量提交若基础版本非当前版本返回 E_STALE_BASE 且不改变任何状态。
7. 使用 SQLite 持久化记录、索引条目、批次版本与意图日志，提交前先写意图记录；进程在 INDEXING 中途被强制终止后重启须扫描未完成意图，将批次恢复为 PENDING 重排或标记 ABORTED，并输出仅基于已持久化事实的恢复报告，不得承诺强制终止后仍生成完整退出报告。
8. 提供本地 HTTP API 与端到端演示脚本：API 覆盖批次提交、按服务与级别及时间范围查询、按版本查询索引状态、恢复报告查询，统一错误响应为含业务码的 JSON；脚本使用固定本地样本完成全量索引、只追加增量、重打时间戳触发级联失效、强制终止后恢复四段流程，输出每段索引版本、重建分区数与命中条数。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定本地日志样本验证增量索引、级联失效、版本可见性与强制终止后恢复的一致性，并附运行输出。
