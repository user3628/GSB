某存储团队在空白工作区启动块存储写时复制快照链的增量失效与引用裁决引擎，首版由一名开发者独立交付。卷由固定大小的块组成，块记录块号、版本号、内容摘要与最近写入时刻。快照以写时复制方式冻结块版本集合，支持全量与增量快照并允许合并与删除。增量写入一个块会使所有依赖该块旧版本的快照链派生结果、共享块引用计数与回滚基线失效。引擎需在全局并发上限与每轮时间预算下调度重建，回答携带观察版本的读请求能否直接返回，并提供基于 SQLite 意图日志的强制终止恢复。块内容由内置固定种子生成器确定性产出。

任务环境与准备：
安装 Go 1.22 及以上版本，并确保 go build、go test 可用。
使用 Go 标准库 database/sql 与纯 Go 的 SQLite 驱动（如 modernc.org/sqlite），通过 go get 获取并在 go.mod 中固定版本。
内置固定种子样本生成器随源码提供，运行前无需外部数据或网络。
本地 HTTP 服务仅监听回环地址，演示脚本在同一工作目录下执行。

业务要求：
1. 实现卷、块与快照模型及样本加载：卷声明固定块数，每块记录块号、版本号、内容摘要与最近写入时刻，快照记录标识、类型（全量或增量）、父快照标识、所属基线序号与冻结的块版本集合；加载本地确定性 JSON 样本时校验块号在范围、摘要为定长值、快照父引用存在且全量快照不得有父，失败返回 E_SNAPSHOT_INVALID 并保持旧快照完全可用。
2. 实现写时复制块的增量写入与版本推进：对某块写入时递增其版本号并记录新摘要，旧版本按保留策略保留；若目标块属于某快照冻结集合，写入须生成新块版本而不修改已冻结版本；同一卷的写入按卷单写者串行执行，写入须在同一事务边界内完成新版本落库、旧版本引用更新与卷摘要重算。
3. 实现快照共享块引用计数与合并语义：增量快照引用父快照中未变化的块版本，合并子快照到父快照时须把子快照独有的块版本引用转移给父快照并递减子快照引用；块版本的引用计数必须与引用它的快照集合精确对应，禁止出现引用计数为零而仍有快照冻结该版本，或引用计数大于实际引用者数，违例返回 E_REFCOUNT_INCONSISTENT 并附块号与版本号。
4. 实现增量写入引发的派生结构级联失效：为每条快照维护其回滚基线、已用容量估算与可回滚性裁决对块版本引用的依赖关系；任一被引用块版本写入或快照合并时，受影响快照的全部派生结构及依赖它们的下游快照裁决必须级联失效并在同一事务边界内原子重建，不得出现基线已更新而可回滚性裁决仍基于旧块版本。
5. 实现携带观察版本的陈旧读裁决：读请求携带观察版本，若目标快照的派生结构版本不高于观察版本则返回结论并标注所用版本；若因级联重建未完成而落后于观察版本，必须返回 E_STALE_READ 并附视图版本、观察版本与落后的派生结构名称，禁止返回旧值作为最终结论。
6. 实现全局并发上限与每轮时间预算下的级联重建调度：重建任务按快照序号与失效严重度取任务，超出并发上限的进入有界等待队列，队列满返回 E_REBUILD_QUEUE_FULL，预算耗尽时按稳定次序给出确定性延后清单与延后依据，且延后不得使已失效结构对外可见为有效。
7. 实现单写者提交与多读者查询的并发一致及幂等：块写入、快照合并、删除与级联重建按卷或快照单写者串行执行，多个只读查询可并发读取某一完整提交版本；同一请求标识重复提交只执行一次、其余等待并复用同一结果，内容不一致返回 E_CONFLICTING_REQUEST。
8. 使用 SQLite 持久化块、快照、引用计数、派生结构与意图日志，写入、合并、删除与级联重建前先写意图记录再提交事务；进程被强制终止后重启须扫描未完成意图，依据已提交的块与快照事实重建引用计数并把未提交操作回滚为一致状态，恢复报告只包含已落盘事实，并提供本地 HTTP 接口与可重复演示脚本覆盖各业务码。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地固定样本验证增量写入引发的级联失效、陈旧读拒绝与引用计数一致性，并演示强制终止后的恢复报告。
