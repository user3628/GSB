交付从新建的代码库开始，需要在 Windows 本地从零构建一个面向主从复制延迟治理的复制位点快照与延迟观测归并引擎，交付领域数据编辑与操作应用。与围绕「策略字段编辑」的方案不同，本引擎以「复制位点快照」为核心对象：每个从库在采样时刻上报一条观测，记录从库标识、采样时刻毫秒、GTID 集合（形如 3e11fa47-71ca-11e1-9e33-c80aa9429562:1-5 的若干段）、已执行位点名、延迟毫秒与从库上报版本；引擎需把同一从库多条观测按位点包含关系归并成「延迟演进序列」，判定位点停滞、位点回退与位点跨越，并据此给出延迟等级与建议动作。观测集合需要以两种可互换的持久化格式整份导入导出，历史版本的 GTID 段写法、位点名格式与时间精度存在差异，导入时必须依据显式兼容矩阵裁决接受、降级接受或拒绝。用户通过本地 HTTP 接口编辑观测、触发归并与查询延迟演进序列。

任务环境与准备：
安装 Go 1.22 或以上版本，并确认 go version 可在 PowerShell 中正常输出。
选用纯 Go 的 SQLite 驱动访问本地数据库文件，无需 CGO，也不需要安装外部数据库服务。
准备本地确定性样本：若干从库的多条观测 JSON、对应的紧凑二进制文件、一份 GTID 段简写的历史样本，以及一份兼容矩阵配置文件。
全部验证在回环地址完成，不依赖真实复制集群、外部账号或网络。

业务要求：
1. 实现观测样本与 GTID 集合的解析和归一化：延迟毫秒为非负整数，GTID 集合按「源标识:起止列表」解析为区间集合并合并重叠与相邻区间，位点名按声明格式校验，从库上报版本按版本段解析；任一字段非法返回 E_OBSERVATION_INVALID 并给出从库标识、采样时刻与出错字段，整批不入库。
2. 实现位点包含关系与演进判定：对同一从库相邻两条观测按 GTID 区间集合判定位点前进、停滞或回退，回退时附被撤销的区间，停滞时统计连续停滞次数；位点判定结果须由区间集合本身而非上报顺序决定，乱序到达的观测按采样时刻与位点双重序归并，同一采样时刻的冲突观测返回 E_OBSERVATION_CONFLICT。
3. 实现两种持久化格式的编解码：紧凑二进制格式含魔数、格式版本字节、每条记录长度前缀、CRC32 校验与可选字段存在位图，位点名与 GTID 段以长度前缀字符串承载；分片 JSON 行格式每行含从库标识、采样时刻、GTID 段列表、位点名、延迟与上报版本；两种格式导出后重导入须得到逐记录一致的观测集合与区间集合，校验失败返回 E_FORMAT_CORRUPT 并指明偏移或行号。
4. 实现格式协商与版本兼容裁决：导入前检测输入格式与格式版本，按可从配置文件读取且可覆盖的兼容矩阵给出接受、降级接受或拒绝；旧版本以整数区间简写 GTID 段或缺上报版本时降级接受并展开为规范区间、补齐默认版本并记录降级明细，高版本含未知必填字段返回 E_FORMAT_UNSUPPORTED，降级展开结果须与显式区间写法归并一致。
5. 实现导入冲突解决与批次原子生效：导入观测与现有观测同从库标识同采样时刻时按格式版本、位点区间规模与最后写入时间打破平局的确定规则解决，结局分为覆盖、跳过与拒绝三类并写入导入报告；整批导入必须原子生效，任一条被拒绝则整批回滚且保持导入前观测集合与演进序列完全可用，不得出现部分观测已生效。
6. 实现延迟等级状态机与位点停滞联动：从库状态至少包含 HEALTHY、LAG_WARN、LAG_CRITICAL、STALLED、RECOVERING 五种并规定合法迁移路径，非法迁移返回 E_INVALID_TRANSITION 且不修改已持久化状态；延迟超过声明阈值进入 LAG_WARN，超过上限进入 LAG_CRITICAL，位点连续停滞超过声明次数进入 STALLED，恢复须连续多条观测延迟回落且位点前进，报告中须附每一步依据。
7. 使用 SQLite 持久化观测集合、区间集合、演进序列、状态与意图日志，写操作先写意图记录再提交事务；进程在归并或导入中途被强制终止后重启须扫描未完成意图，把观测集合回滚到最后一个完整版本或把批次标记为已中止，恢复报告只基于已落盘事实并给出回滚或中止结论。
8. 实现单写者归并与多读者查询的并发一致及幂等：观测编辑、归并与导入按提交串行执行，多个查询可并发读取已提交版本且只能看到某一完整提交版本；同一批次标识重复提交只执行一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_BATCH；携带基础版本的增量编辑若基础版本非当前版本返回 E_STALE_BASE 且不改动状态，失败响应统一为含业务码与上下文的 JSON。
