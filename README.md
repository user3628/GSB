某本地推理服务团队在空白工作区立项，要为一个自研的提示词前缀缓存子系统交付可集成的 Go 组件与完整示例，核心问题不是采样而是前缀复用：同一提示词模板被改写、增删系统消息或追加对话轮次后，哪些请求还能命中已有缓存、哪些必须整体失效重建。输入由内置固定种子生成器在本地产出：一组请求记录（请求标识、模板标识、按轮次组织的消息段列表、每段文本及其语言标签），以及一份带单调版本号的缓存策略快照，声明前缀切分粒度、最短可缓存前缀长度、相似度归并阈值与单请求可复用前缀上限。文本需要规范化后计算分块指纹，命中判定须同时考虑前缀相等、归并相似与缓存槽位占用。运维人员通过本地 HTTP 接口提交整份策略快照或只含局部改动的增量片段，客户端携带观察版本提交命中查询，期望在快照被替换时得到明确裁决而非陈旧命中结果。

任务环境与准备：
安装 Go 1.22 或更高版本，确认 go env 在 Windows 本机可用。
引入 SQLite 纯 Go 驱动或已编译的本地驱动，执行 go mod tidy 验证依赖可用。
新建空白工程目录并初始化 Go 模块，确认本地回环 HTTP 端口可监听。
无需 GPU、外部网络或真实模型；请求记录与策略快照由程序内置固定种子生成器在本地产出。

业务要求：
1. 实现消息段规范化与分块指纹阶段：对每段文本做 Unicode NFKC、空白折叠、全半角统一与小写化，按策略声明的切分粒度切分为带字符偏移的前缀块，逐块以固定哈希函数生成指纹并记录块序号、字符跨度与来源消息段；同一请求与策略必须产生逐字节一致的前缀指纹清单，空消息段或块跨度过短须显式标记为不可缓存而非静默丢弃。
2. 实现前缀槽位分配与最短前缀过滤核心：按最短可缓存前缀长度筛除过短前缀，把可缓存前缀映射到有限槽位并按声明的前缀上限截断，槽位冲突时依据归并相似度与占用时间做确定性裁决并记录被挤出项；占用超过上限、槽位数为零或同一前缀被分配到多个槽位须返回带请求标识与槽位号的 E_SLOT_CONFLICT。
3. 实现相似归并下的命中裁决：对携带观察版本的命中查询，先判定观察版本是否为当前生效版本，再判定前缀指纹是否逐块相等、是否满足归并阈值，输出精确命中、归并命中、不可复用三种结论及各项依据数值；归并命中须保留块级相似度与阈值余量，禁止以最终布尔结论替代依据。
4. 实现策略增量片段应用与依赖失效传播：接受只含局部改动的增量片段（切分粒度、最短前缀长度、归并阈值、前缀上限单字段调整），通过各阶段内容摘要构成的版本指纹识别受影响的最早阶段，使该阶段及其全部下游槽位分配与命中结论失效并重建，未受影响前缀的槽位继续复用；失效清单须可追溯至具体字段与请求。
5. 实现 SQLite 事务化的版本快照与陈旧读裁决：每次策略推进或槽位重分配以事务写入含单调版本号、策略内容指纹、槽位摘要与序号的记录，同一版本同一请求只允许一条有效记录；读取方携带观察版本时，低于当前版本的命中结论不得直接返回陈旧结果，须返回带生效版本与观察版本的 E_STALE_VERSION，且读取任何版本不得看到半提交状态。
6. 实现整体替换识别与回退拒绝：当策略记录被整体替换时，通过内容摘要与版本序号区分正常推进、整体替换与版本回退；整体替换须使全部槽位与命中结论失效重建，回退须拒绝并返回 E_STALE_VERSION 并附当前生效版本，不得以覆盖写入掩盖回退。
7. 实现并发提交互斥与占用量预算裁决：多工作进程对同一数据库提交策略版本或槽位重分配时使用 SQLite 条件更新与真实文件锁，仅允许版本号连续推进，落后、重复或跨请求错位提交返回 E_STALE_VERSION；在单版本槽位总占用预算内决定保留与挤出集合，超预算时按可复用前缀长度降序裁决并记录取舍理由，不得静默超配。
8. 提供本地 HTTP 与命令行交互接口及确定性演示：支持导入请求记录与策略快照、提交增量片段、查询各阶段状态与版本指纹、执行带观察版本的命中查询、查看失效与挤出原因、请求优雅停止与执行恢复；演示数据由内置固定种子生成器产出，覆盖模板改写、系统消息增删、相似但不等前缀与一次中途终止后恢复。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
