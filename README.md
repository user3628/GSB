为搜索推荐团队的 CTR/CVR 预估特征工程构建一个本地可运行的数据处理管线与结果验证工具。工作区为空，需从零创建项目。输入是本地样本目录：多份曝光样本 JSONL 分片，每条含 sample id、user id、item id、若干类别特征与数值特征、曝光时间戳、点击标签（0/1）与转化标签（0/1）；一份特征登记表 JSON，声明每个特征的名称、类型、所属特征组、是否参与 CVR 训练与依赖的上游特征组列表，并带登记表版本号；一份增量批次清单 JSONL，按到达顺序声明每批新增分片集合与特征登记表的可选版本号。管线需要完成样本接入与字段校验、按特征组构造交叉特征、CTR 与 CVR 双目标的确定性样本统计与分层汇总，并在特征登记表增量演进后按依赖关系精确失效已计算的特征统计。核心难点在于：特征组之间存在多层依赖，登记表版本更新可能只影响部分特征组，而增量批次到达又会引入新的特征组状态，两者叠加时既要保证逐样本统计可重复，又要保证被失效的统计只在依赖真实变化时重算，中断后从持久化进度继续且不重复消费已提交样本。

任务环境与准备：
确认本机已安装 Python 3.10 及以上版本，并能在命令行使用 python 与 pip。
创建工作区目录并在其中初始化虚拟环境，安装 fastapi、uvicorn、numpy 与 pytest，版本以当前可用稳定版为准，无需容器环境。
在项目内准备本地样本目录：多份曝光样本 JSONL 分片、特征登记表 JSON 与增量批次清单 JSONL，全部由本地脚本确定性生成，不依赖任何线上数据或账号。
确认 SQLite 可用（Python 标准库自带 sqlite3 即可），并在 Windows 路径下验证临时文件与原子替换写法可用。
预留一个本地监听端口用于启动服务，演示与验证均在本机完成。

业务要求：
1. 管线入口接收样本目录、特征登记表、增量批次清单与校验参数，校验 sample id 唯一、点击与转化标签只取 0 或 1、转化标签为 1 时点击标签必须为 1、特征类型只能是类别或数值、登记表中依赖的特征组必须存在且依赖图无环；任一非法返回 E_PARAM、E_LABEL 或 E_GRAPH 业务码并定位出错文件、行号与特征组名，且不创建任何结果文件或临时目录。
2. 样本接入须做确定性归一：各分片按文件名升序拼接后按 sample id 字典序稳定排序，类别特征缺失统一映射为固定占位符，数值特征缺失按该特征在当前批次已接入样本上的均值填充并记录填充计数；同一输入下样本顺序、各列取值与填充计数须逐位可重复，不得依赖字典遍历顺序或分片内部行序。
3. 增量批次须按清单声明顺序逐批接入，每批接入时推进批次序号并记录此刻的特征登记表版本号；批次未按清单顺序请求、重复接入同一批次或跳过中间批次时分别返回 E_BATCH 业务码并给出期望批次与请求批次；已接入批次必须幂等，重复请求不得重复累加统计或改变已有批次状态。
4. 特征组交叉特征须按依赖图做分层构造：先构造无上游依赖的组，再按拓扑序构造下游组，交叉键按依赖组名与特征名声明顺序拼接后按哈希取模到可配置桶数，桶冲突须计入统计；同一输入与配置下每个特征组的交叉键与桶号须逐位一致，依赖图违反拓扑序的构造请求返回 E_GRAPH。
5. CTR 与 CVR 双目标统计须在特征组与桶两级分别汇总曝光数、点击数、转化数与未转化数，CVR 统计只允许使用点击样本；同一样本在 CVR 统计中缺少点击记录时须计入丢弃数并继续，某特征组全部桶样本量为零须给出空统计而非报错；统计只允许来自已提交批次，任一特征组缺失须给出可定位到批次与特征组的诊断信息。
6. 特征登记表须支持增量演进：新增特征组、修改组的依赖列表、把特征从参与 CVR 改为不参与与修改桶数四类操作，每次演进推进登记表版本号；服务须按特征与特征组到批次统计的依赖关系计算受影响统计集合，只重算依赖真实变化的特征组与桶，未受影响的统计必须复用已持久化结果，诊断报告须区分“依赖失效被评估但统计未变”与“实际重算”两类，并给出各自计数与特征组名。
7. 批次接入、特征组统计与登记表演进须在 SQLite 中以批次、特征组、桶三级事务提交，单桶的统计量、交叉键摘要与桶进度标记在同一事务中写入；某桶计算失败时该桶整体回滚且该批次其余已提交桶状态不变，每次完成须整体替换生成版本化快照，读取快照时若检测到数据库版本与磁盘统计文件哈希不一致、登记表版本变化或残留旧版本文件须返回 E_STALE 并定位到版本与文件名。
8. 进程被强制终止后重启须从 SQLite 已提交进度继续，核对每个批次的接入标记、桶统计文件内容哈希与快照版本，重算未提交桶且不重复消费已提交样本；须提供确定性演示入口，用固定分片、批次序列与登记表演进序列跑出各批次样本量、特征组桶冲突数、双目标统计、被失效评估与实际重算计数、恢复前后一致性结论与快照版本序列的可重复结果，并给出可用等价参数复现的请求示例。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定分片、增量批次与登记表演进序列验证双目标统计、依赖失效精确性与中断恢复一致性，附运行结果。
