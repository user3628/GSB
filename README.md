当前是空白工作区，需要在 Windows 本地从零构建一个面向 CI 流水线的制品缓存与复用组件，供上层构建编排器集成。流水线由若干阶段组成，每个阶段产出以内容摘要寻址的制品；缓存以(阶段标识, 输入指纹, 工具链版本)为键记录制品引用、元数据与命中统计。为与外部构建工具互换数据，缓存清单需要两种可互换的持久化格式：紧凑二进制格式（含魔数、格式版本字节、每条记录长度前缀、CRC32 校验、可选字段存在位图与大小端标记）与分片 JSON 行格式（每行含阶段标识、指纹、工具链版本、制品摘要、创建时间与相对保留期）。两种格式存在字段可选性、时间戳精度与版本号语义差异，导入方需要做格式协商与降级接受。用户通过本地 HTTP 接口提交缓存写入、查询命中、导出导入与快照切换，所有数据来自本地确定性样本，不依赖真实 CI 平台、制品仓库或容器环境。

任务环境与准备：
安装 Python 3.11 并在工作区创建虚拟环境，安装 FastAPI、uvicorn、pytest 与 SQLite 支持；其余依赖均为标准库，无需容器环境。
准备固定本地样本：若干阶段的缓存键与制品摘要清单、两份不同格式版本的导入文件（含缺字段的旧版本与含未知必填字段的高版本）、一份快照文件与统一的控制时间基准。
确认本地回环端口可用，所有测试服务与接口仅监听本地地址，不需要任何外部账号、线上站点或网络下载的数据集。

业务要求：
1. 实现两种持久化格式的编解码：紧凑二进制格式必须含魔数、格式版本字节、大小端标记、每条记录长度前缀、CRC32 校验与可选字段存在位图；分片 JSON 行格式每行含阶段标识、指纹、工具链版本、制品摘要、创建时间与相对保留期；畸形记录、校验失败、长度越界与非法魔数须返回互不相同的业务码且整批不生效。
2. 实现格式协商与版本兼容裁决：导入前检测输入格式与版本，按显式声明的兼容矩阵给出接受、降级接受或拒绝三种结论；旧版本缺字段数据走降级接受并按声明的默认值补齐并记录降级明细，高版本含未知必填字段的数据返回 E_FORMAT_INCOMPATIBLE；同一输入重复协商须给出逐位一致的结论与明细。
3. 实现时间与保留期的归一化：二进制格式的微秒时间戳与 JSON 行格式的毫秒时间戳须归一化为同一内部表示，按调用方声明的截断规则处理亚毫秒部分；JSON 相对保留期须依据记录自带的基准时间换算为绝对过期时刻，换算前后须可核对，基准时间缺失或早于保留期换算下界时返回 E_TIME_ANOMALY 而非静默取当前时间。
4. 实现导入冲突解决与批次原子生效：导入记录与现有缓存键相同时，按工具链版本优先级、制品摘要一致性与最后写入时间打破平局的确定规则解决，结局分为覆盖、跳过与拒绝三类并写入导入报告；整批导入须原子生效，任一条被拒绝则整批不落库，重复导入同一批次标识须幂等且不改动已有记录。
5. 实现缓存命中判定与复用语义，键由阶段标识、输入指纹与工具链版本规范化后组成，命中须校验制品摘要与保留期未过期，摘要复核失败或已过期不得命中并返回对应业务码；未命中须给出可核对的未命中原因（键不存在、摘要不符、已过期、版本降级不可用），同一键的命中断言不得因查询发起时刻不同而漂移。
6. 实现快照整体替换与版本识别：缓存清单快照文件携带格式版本、快照序号与生成时间，加载时须校验版本兼容性与序号单调，加载过程在内存索引与 SQLite 表之间原子切换，切换成功后旧快照资源与派生统计才可释放；加载中任一校验失败须保持原快照完全可用并返回 E_SNAPSHOT_INVALID，禁止新旧快照条目混合存在。
7. 实现并发控制与强制终止恢复：缓存写入、导入与快照切换按单写者串行执行，多个只读命中查询可并发；同一缓存键的并发写入仅一个生效、其余按幂等或冲突规则处理；写操作先落意图记录再提交事务，进程被强制终止后重启须扫描未完成意图把导入批次或快照切换标记为已中止或回滚，恢复报告只基于已持久化事实，不得承诺强制终止后仍生成完整退出报告。
8. 提供本地 HTTP 接口与端到端互操作演示脚本：接口覆盖缓存写入、命中查询、二进制导出、JSON 行导出、两种格式导入、格式协商预检、快照切换与恢复报告查询，统一错误响应为含业务码的 JSON；脚本使用固定本地样本完成一次全量写入、一次二进制导出后 JSON 再导出、一次降级接受导入、一次冲突导入、一次快照整体替换与一次强制终止后恢复，输出命中统计、导入报告、降级明细与恢复结论供人工核验。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地固定样本运行演示脚本，核验两种格式互转、降级接受导入、命中与快照一致性及恢复结论。
