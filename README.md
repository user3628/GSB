从无到有搭建时，需要为多租户 Web 平台构建一套密码哈希与重置令牌管理的本地引擎。平台用户口令以带算法标识与代价参数的哈希记录保存，历史数据中并存多种哈希方案，需要在不破坏旧记录可登录性的前提下完成渐进迁移。重置流程要求：用户发起重置后签发一次性令牌，令牌绑定租户、用户、签发时间与口令版本，兑换时必须原子地校验令牌未被消费、未过期且口令版本未变，并以新哈希原子替换旧哈希。整个过程需在 SQLite 中维护带递增版本号的状态快照，支持并发兑换竞争、进程强制终止后的恢复、哈希迁移与重置交错时的版本一致性，并能通过外部参数注入过期令牌、重复消费、版本跳号与迁移竞争等异常。

任务环境与准备：
安装 Go 1.22 或更高版本（Windows amd64），确认 go version 可用；使用纯 Go SQLite 驱动（如 modernc.org/sqlite）以免依赖 CGO，通过 go mod tidy 拉取。
准备本地确定性样本生成入口：内置生成器产出多租户、多用户、多方案哈希记录与令牌签发脚本，以及过期令牌、重复消费、版本跳号、迁移竞争、签名篡改五类注入样本，不依赖网络或真实账号。
在 Windows 临时目录下建立独立工作目录用于 SQLite 数据库与样本文件，确认目录可写；所有时间与密钥材料由样本固定提供，不读取系统墙钟作为判定依据。
确认可执行强制终止测试的本地子进程入口（启动后由测试侧终止进程再重启），用于验证恢复一致性；不要求管理员权限，不使用容器或外部服务。

业务要求：
1. 实现多方案密码哈希记录的解析与校验核心：每条哈希记录包含算法标识、代价参数、盐与摘要，支持两种以上本地确定性方案并严格按记录中的代价参数复算，校验时对算法标识未知、参数越界或记录截断给出稳定业务码 E_HASH_FORMAT，校验结果不得泄露摘要字节。
2. 实现渐进式哈希迁移：旧方案记录在用户成功登录或口令重置后按新方案重算并原子替换，迁移前后口令校验结果必须一致；迁移期间旧记录保持可登录，迁移完成版本号递增，重复迁移同一记录返回 E_ALREADY_MIGRATED 且不改变记录内容。
3. 实现重置令牌签发与一次性兑换：令牌绑定租户、用户、签发时间、口令版本与一次性 nonce 并以本地密钥做完整性签名，兑换时严格校验签名、过期时间、口令版本与未消费状态，签名不符返回 E_TOKEN_INVALID，过期返回 E_TOKEN_EXPIRED，已消费返回 E_TOKEN_CONSUMED。
4. 实现并发兑换竞争与口令更新原子性：同一令牌的并发兑换请求中仅一个成功，其余返回 E_TOKEN_CONSUMED；成功兑换须在同一 SQLite 事务内完成令牌消费、旧哈希替换与快照版本递增，任何一步失败整体回滚且令牌保持未消费。
5. 实现带版本号的状态快照与整体替换识别：每次令牌签发、兑换、哈希迁移或口令变更后在单个事务内提交递增版本号快照，旧快照整体保留可回放；快照内容比较须识别整体替换式版本变化而非仅比对版本号，加载时校验版本链连续性，跳号返回 E_SNAPSHOT_VERSION 并回退到最近连续版本。
6. 实现强制终止后的恢复一致性：兑换或迁移过程中进程被强制终止后重启，依赖 SQLite 已提交事务恢复令牌状态、哈希记录与快照版本，已提交操作不回退、未提交事务整体丢弃且令牌仍可正常兑换；恢复后若发现版本链跳号须以 E_SNAPSHOT_VERSION 拒绝加载并进入只读诊断模式。
7. 实现并发资源控制与会话隔离：并发兑换与迁移请求按租户串行化口令变更，在途事务数以可配置上限的信号量约束，超出等待阈值的请求返回 E_AUTH_CONTENTION 而非无限阻塞；在途计数须可观测，同一用户在任一时刻至多一个口令变更在途。
8. 实现异常注入验证链路与确定性报告：通过外部参数或配置文件构造过期令牌、重复消费、版本跳号、迁移竞争与签名篡改五类样本，分别断言对应业务码、令牌与哈希终态未被污染、快照版本变化符合预期；导出 JSON 报告按租户、用户与业务码稳定排序，时间字段仅用固定采样标记，重复运行字节级一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证令牌一次性兑换、哈希迁移一致性与异常注入下的状态恢复，附运行结果。
