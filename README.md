这项需求没有既有代码，需要为安全团队构建一个面向不可信二进制输入的本地分析工作台，用于在并行调度下识别内存边界违规与资源耗尽风险。输入是程序内置生成器产出的确定性样本：一类是带长度前缀的记录容器，记录中包含变长字段、嵌套子记录与声明长度字段；另一类是调度任务清单，描述若干分析任务及其声明的内存预算。工作台的职责是对每条记录做边界校验与安全解码，分析解码过程中的峰值内存与分配次数，判决是否在预算内，并在并行执行多个任务时对总资源预算做裁决。系统需要维护带版本号的状态快照以支持中断恢复，暴露可交互的编辑与操作界面供分析员调整样本参数、切换策略并回放裁决过程，所有结论必须可在 Windows 本地复现且字节级一致。

任务环境与准备：
安装 Go 1.22 或更高版本，确认 go version 可执行，模块使用标准库与 go-sqlite3 驱动即可。
准备 Windows 本地可写临时目录用于 SQLite 状态库与样本输出，无需外部网络、账号或容器。
运行前无需预置样本：样本由程序内置确定性生成器产出，生成参数固定且不依赖系统时间。
如需第三方 SQLite 驱动，执行 go get 安装并锁定版本到 go.mod，构建命令为 go build ./...

业务要求：
1. 实现不可信记录容器的安全解码核心：按长度前缀定位变长字段与嵌套子记录，对每条记录严格校验声明长度与实际剩余字节，禁止越过父级缓冲边界，对截断、长度回绕、长度相加溢出分别给出稳定业务码 E_TRUNCATED、E_LENGTH_WRAP、E_LENGTH_OVERFLOW，并保留已安全解码的记录前缀。
2. 实现嵌套深度的双约束裁决：子记录嵌套层数超过可配置上限或单个父记录内子记录声明长度累计超过父记录剩余长度时，终止该子树解码并回退到父级继续兄弟记录，深度上限与累计量上限均为参数，触发时分别返回 E_DEPTH_EXCEEDED 与 E_NESTED_BUDGET，状态迁移轨迹记录子树终止点与父级恢复点。
3. 实现每条记录的峰值内存与分配次数度量：在解码过程中以确定性计数方式统计单条记录解码占用的字节峰值与分配次数，作为调度器预算裁决的依据；度量只认解码过程的真实增长，不做事后估算，同一输入重复解码所得度量必须完全一致，度量结果随记录摘要一并进入快照。
4. 实现并行任务调度与资源预算裁决器：并发度、全局内存预算与单任务内存预算均为参数，调度器按任务声明预算与已用预算裁决准入，超出并发上限的任务排队等待而非直接拒绝，单任务超预算标记 E_TASK_MEMORY_BUDGET，全局预算不足以准入时标记 E_GLOBAL_BUDGET，被拒任务仍须原样出现在报告中。
5. 实现带版本号的状态快照与中断恢复：每完成一个任务即在单个 SQLite 事务内提交递增版本号快照，快照比较须能识别整体替换式版本变化而非仅比对版本号；运行中断后重启从最近已提交快照继续，已提交任务不重做、未提交任务整体重做，版本链跳号时以 E_SNAPSHOT_VERSION 拒绝加载并回退到最近连续版本。
6. 实现编辑与操作界面：以子命令方式支持查看当前版本链、编辑样本参数与预算策略、单步回放某任务的解码与裁决过程、展示被拒任务及原因；编辑产生的策略变更以新版本快照提交，回放过程不得依赖墙钟或随机因素，界面展示的信息与最终报告必须彼此一致。
7. 实现异常注入验证入口：通过外部参数或配置文件构造长度回绕、深嵌套循环子记录、单任务预算极低、全局预算不足、快照版本跳号五类输入，分别断言对应业务码、已提交快照未被污染、其余任务结论不受影响；注入仅通过输入与参数完成，不修改源码，注入后预算与并发参数可恢复。
8. 导出确定性 JSON 报告：包含每个任务的记录摘要、峰值内存与分配次数、解码与裁决业务码、最终状态、资源预算使用量与快照版本链，报告按任务标识与业务码稳定排序，时间字段只使用固定采样标记；并发度从 1 变到上限且输入不变时报告字节级一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
