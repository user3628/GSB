当前是空白工作区，需要在 Windows 本地从零构建一个面向单机训练场景的检查点管理与恢复组件，供上层训练编排器集成。训练以若干轮次推进，每轮包含参数分片与优化器状态；检查点由训练进程周期性写入，内容包括模型参数、优化器动量、学习率调度器位置与数据加载器游标。组件需维护检查点状态在 WRITING、COMMITTED、INVALID、PRUNED 之间的演进，支持异步写入、保留策略裁剪与按持久化事实恢复训练进度。核心难点在于状态演进与恢复一致性：训练进程可能在任意时刻被强制终止，部分写入的文件、未提交的意图记录与已完成的保留裁剪会交错出现，重启后必须回到某个完整检查点边界并给出可核验的差异报告。

任务环境与准备：
Windows 本机安装 Python 3.11 及以上，并安装 fastapi、uvicorn、numpy 与标准库以外的 pytest（可选，用于自检）。
在空白工作区创建项目目录，准备固定本地样本：若干轮次的参数分片与优化器动量二进制片段、学习率调度器位置与数据游标记录，均由脚本按固定随机种子生成。
准备 SQLite 数据库文件用于持久化检查点元数据、状态迁移记录与意图日志，首次运行由程序自动建表。
演示脚本以本地回环端口启动 HTTP 服务，并用子进程模拟训练进程中一次强制终止。
所有样本与测试端点均在本地生成，不依赖真实训练作业、外部存储或网络服务。

业务要求：
1. 实现检查点模型与文件布局：每个检查点包含轮次序号、参数分片集合、优化器动量分片、调度器位置与数据游标，各分片带内容摘要；写入时先写临时分片与清单文件，全部摘要校验通过后才原子提交为正式检查点，摘要不一致返回业务码 E_CHECKSUM_MISMATCH 并保持旧检查点可用。
2. 定义检查点状态机，至少包含 WRITING、COMMITTED、INVALID、PRUNED 四种状态并规定合法迁移路径；非法迁移返回 E_INVALID_TRANSITION 且不修改已持久化状态；每次迁移须记录触发原因与时间戳，供恢复报告引用。
3. 实现异步检查点写入：训练线程提交写入请求后立即返回，由后台写者按提交顺序串行落盘；同时最多允许配置数量的检查点处于 WRITING，超出返回 E_WRITER_BUSY；写入完成前对外查询必须显示该检查点为 WRITING，不得提前暴露为 COMMITTED。
4. 实现保留策略裁剪：按配置的最大保留数与最小保留轮次间隔选择prune候选，已提交检查点的裁剪须先写意图记录再从存储中移除分片与元数据；裁剪与写入并发时必须保证被裁剪对象不是当前可用于恢复的最新完整检查点，否则跳过并输出跳过原因。
5. 实现强制终止后的恢复：进程被强制终止后重启须扫描未提交意图与临时分片，把 WRITING 中的检查点标记为 INVALID 或清理其临时产物，并定位最新的 COMMITTED 检查点作为恢复基点；恢复报告只基于已持久化事实，不得承诺强制终止后仍能生成完整退出报告。
6. 实现恢复差异核验：依据恢复基点的轮次序号、调度器位置与数据游标计算与训练目标轮次的差距，输出需重放的轮次数、优化器动量是否可用、分片摘要复核结论；若最新检查点参数分片摘要复核失败，须回退到更早的 COMMITTED 检查点并在报告中说明回退原因。
7. 实现并发一致性与幂等：写入、提交与裁剪按单写者串行，多个只读查询可并发；同一写入请求标识重复提交只执行一次、其余等待并复用结果；查询只能看到某一完整提交版本，不得出现清单已提交而部分分片摘要尚未复核的中间可见状态。
8. 提供本地 HTTP API 与可重复演示脚本：API 覆盖提交写入、查询检查点列表与状态、触发裁剪、查询恢复基线、查询恢复报告，统一错误响应为含业务码的 JSON，至少覆盖 E_CHECKSUM_MISMATCH、E_INVALID_TRANSITION、E_WRITER_BUSY、E_CHECKPOINT_NOT_FOUND、E_PRUNE_CONFLICT；脚本使用固定本地样本完成多次写入、一次裁剪与一次强制终止后恢复，输出状态轨迹与差异报告。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定本地样本验证检查点状态演进、异步写入、裁剪与强制终止后恢复一致性和差异报告，附运行输出。
