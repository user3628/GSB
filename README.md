当前是空白工作区，没有现存项目、代码或数据附件，需从零构建一个本地可运行的多轮对话状态管理组件与完整示例，核心问题是在对话轮次规模变化时对上下文窗口做算法取舍并保证中断恢复后状态一致。输入为固定随机种子生成器产出的本地 JSONL 对话分片，每条含 session_id、turn_index、用户话语、助手回复、语言标签与可选的槽位标注；对话覆盖 4 至 40 轮不等，含中英混排、重复追问与意图切换。组件需为每个会话维护结构化状态（已确认槽位、待澄清槽位、对话摘要与窗口策略），在轮次增长时按可配置策略决定保留最近轮次、生成增量摘要或压缩历史，并持久化每轮后的状态快照。当用户编辑早期轮次内容时，须识别受影响的最早轮次并使后续状态失效重建，未受影响的后续摘要可复用。

任务环境与准备：
安装 Python 3.11 或更高版本，并安装 NumPy 与 PyYAML 的固定版本；无需 GPU、外部服务或网络访问。
在工作区创建项目目录与本地数据目录，使用固定随机种子运行题目要求的本地对话样本生成器，产出至少 3 个会话的 JSONL 分片与对应的槽位配置。
准备本地 HTTP 与命令行示例的运行入口，确认无外部端口冲突；不启用任何容器或虚拟化运行环境。

业务要求：
1. 实现逐轮状态转移与槽位跟踪：按 turn_index 顺序解析用户话语与助手回复，提取并更新已确认槽位与待澄清槽位，记录每轮的状态变更集、触发规则与语言标签；同一输入与配置必须产生逐字节一致的状态轨迹，轮次序号重复或缺失时返回带 session_id 与轮次号的 E_TURN_SEQUENCE 错误。
2. 实现基于轮次规模的窗口策略取舍：依据当前轮数、累计 token 估计（按空白切分）、配置的最近轮次保留数与摘要触发阈值，在保留最近轮次、增量摘要、全量压缩三种策略中选择，并记录选择理由、候选打分与被淘汰策略原因；小规模会话不得选用全量压缩，策略切换须在轨迹中可观测，并保证策略切换后槽位变更集与摘要覆盖区间一致。
3. 实现增量摘要生成与数值精度控制：对超出窗口的早期轮次按固定哈希嵌入做聚类后抽取要点句生成摘要，摘要长度受 token 预算约束，全程在对数域计算要点权重并记录有效位数；摘要为空、权重出现 NaN 或 token 预算为零时返回带 session_id 与轮次号的 E_SUMMARY_INVALID，不得静默丢弃历史。
4. 实现每轮状态快照的原子持久化：每轮完成后以原子方式写入包含 session_id、轮次号、输入内容指纹、配置版本、状态摘要与单调序号的记录，写入过程任意位置中断不得留下半写记录；恢复时必须忽略损坏、不完整或序号重复的记录，从最近一致快照继续，且不承诺强制终止后生成退出报告。
5. 实现早期轮次编辑后的依赖失效传播：当某轮用户话语或助手回复被编辑时，通过各轮内容摘要与摘要输入构成的版本指纹识别受影响的最早轮次，使该轮及其后续状态与摘要失效重建，未受影响的后续轮次摘要继续复用；失效原因与受影响区间须在查询接口中可观测。
6. 实现增量重建与全量一致性校验：提供单轮编辑入口，仅重建失效链路后与从零全量重建的状态轨迹、摘要摘要与槽位汇总逐字节比对；检测到不一致须返回 E_INCREMENTAL_MISMATCH 并附首个差异轮次与字段，校验须在可配置延迟预算内完成，超出时返回 E_LATENCY_BUDGET。
7. 实现并发快照发布保护与稳定业务错误码：多个工作进程对同一工作区发布快照时使用文件锁并比较会话内轮次序号，仅允许序号连续推进，落后、重复或跨会话错位发布返回 E_STALE_CHECKPOINT；请求缺失前置轮次快照、非法轮次跳转或版本整体替换（序号回退或摘要不匹配）时返回带上下文的 E_INVALID_STATE。
8. 提供可集成的库接口、本地 HTTP 与命令行示例及确定性演示：支持导入对话分片、查询各轮状态与窗口策略、编辑早期轮次、请求停止、执行恢复、导出摘要与槽位汇总；演示数据至少 3 个会话、轮数覆盖 4 至 40 轮并含中英混排与意图切换，一次完整运行生成固定摘要，并演示编辑第 2 轮后增量重建与全量结果一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
