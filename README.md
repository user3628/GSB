为文档理解团队从零构建一个本地可运行的版面阅读顺序分析编辑应用，核心问题是阅读顺序标注状态在编辑操作下的演进与进程强制终止后的一致性恢复。输入是本地样本目录：一份页面清单 JSONL，每条含 page id、宽高、以像素矩形表示的版面元素（元素 id、类别名 heading/paragraph/figure/table/caption、边框左上与右下坐标、文本密度与置信度）；一份元素关系清单 JSONL，声明同一页面内元素之间的候选阅读顺序关系（前驱元素 id、后继元素 id、关系权重）。应用需对每页构造阅读顺序并输出有序元素序列与页面级置信度，同时支持元素增删改与关系调整等编辑操作，编辑后仅对依赖变化的页面重新判定顺序，并保证中断恢复后结果与无中断执行一致。

任务环境与准备：
安装 Python 3.10 及以上版本，创建虚拟环境并安装 fastapi、uvicorn、numpy、httpx 与 pytest。
在空工作区初始化项目目录，准备本地样本生成脚本，生成页面清单、元素关系清单与固定编辑序列，样本覆盖多栏、重叠元素、成环关系与中断恢复场景。
确认 SQLite 可用（Python 标准库内置），无需外部服务、账号或 GPU。
启动本地服务并准备 curl 请求示例所需端口，验证用例不依赖网络与系统时间。

业务要求：
1. 应用须提供工程创建接口，接收页面清单与元素关系清单，校验 page id 唯一、元素 id 在页面内唯一、矩形坐标左上小于右下且落在页面宽高内、类别名属于声明集合、权重为有限实数；任一非法返回 E_PARAM 或 E_RECT 业务码并指出页面与元素，且不得写入任何页面顺序记录。
2. 阅读顺序判定须先把页面元素按几何布局分栏与分行：以元素水平中心聚类分栏，栏内按垂直重叠与水平间距分行，再按栏从左到右、行从上到下、行内按左边界升序产出确定性的初始顺序；同一页面输入重复判定得到的元素顺序与分行结果须完全一致，不得依赖字典遍历序。
3. 顺序判定须融合关系权重做确定性修正：以初始顺序为基准，对候选关系按后继元素排序约束构造有向图，用基于权重的确定性拓扑排序消解冲突，权重相同时按元素 id 字典序稳定选择；成环时返回 E_CYCLE 并给出环上元素序列，不得静默丢弃关系或给出非全序结果。
4. 每个页面须输出页面级置信度，定义为修正前后顺序一致的元素比例与关系权重覆盖率的加权合成，并在配置容差内构成有效概率；逐元素须给出顺序稳定标记与判定依据（初始顺序位置、被关系修正次数），超容差页面须在诊断中标出且不得被静默计入已提交结果。
5. 编辑操作须支持元素增删改与关系增删改的批量提交，每次提交推进页面版本；应用须按元素与关系到页面的依赖关系计算受影响页面集合，只对真正引用变更元素或关系的页面重算顺序，未受影响页面必须复用已持久化结果，诊断报告须区分被失效评估但结果未变与实际重算两类页面并给出计数与 page id。
6. 页面顺序判定结果须在 SQLite 中以页面、阶段、元素三级记录事务提交，单页的元素顺序、页面置信度与进度标记在同一事务中写入；某页判定失败时该页整体回滚且其余已提交页面状态不变，不得留下部分顺序记录或与快照版本不一致的结果文件。
7. 每次编辑提交或完整判定须以整体替换方式生成版本化快照，含工程版本号、各页面顺序摘要与结果文件内容哈希；读取快照或导出时若检测到数据库版本与磁盘结果文件哈希不一致、版本变化或残留旧版本文件，须返回 E_STALE 并定位到页面与文件，禁止汇入旧数据。
8. 进程被强制终止后重启，须从 SQLite 已提交进度继续，核对每个页面的阶段标记、结果文件内容哈希与快照版本，重算未提交页面且不重复消费已提交页面；恢复后的逐页元素顺序、页面置信度、实际重算页面集合与快照版本序列须与无中断执行完全一致，并提供确定性本地演示入口用固定样本与编辑序列跑出可重复结果及 curl 复现示例。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证逐页阅读顺序、编辑后依赖失效范围及强制终止后的恢复结果与快照版本一致。
