当前是空白工作区，需要在 Windows 本地从零构建一个面向本地列式样本数据的 Join 与 Shuffle 执行引擎，交付算法实现与可复现实验环境。引擎读取两个带版本号与校验摘要的本地列式快照（左表与右表，含整数键、数值度量列与空值位图），按请求中的 Join 规格执行哈希 Shuffle 分区、分区内 Join 与分组求和、均值、计数聚合，并把结果写出。核心业务问题是数值精度与误差传播：度量列为双精度浮点，Shuffle 分区会改变聚合时的求和顺序，分区间部分和再合并时浮点结合律失效，导致同一输入在不同分区数、不同并行度下得到不同数值；空值参与聚合、键分布偏斜导致部分分区超大、以及精度预算不足时如何取舍，都会直接影响结果可复现性与结论可比性。

任务环境与准备：
Windows 本地安装 Python 3.11 及以上，并安装 NumPy 与 SQLite 支持（Python 标准库 sqlite3 即可）。
在空白工作区创建项目目录与固定随机种子的列式样本生成脚本，样本包含整数键、双精度度量与空值位图，并生成带版本号与校验摘要的快照文件。
准备本地 HTTP 服务运行方式与端口配置说明，确保仅使用回环地址且不依赖外部网络或真实账号。
提供中断与恢复演练所需的批次样本与执行步骤说明，所有验证均在本地确定性数据上完成。

业务要求：
1. 实现列式快照加载与版本识别：快照携带版本号、生成时间与校验摘要，包含整数键列、双精度度量列与空值位图；加载时校验版本单调与摘要，失败返回 E_SNAPSHOT_INVALID，加载过程整体替换旧快照，不得混用新旧统计；对空值位置与非法量纲给出确定报错。
2. 实现哈希 Shuffle 分区：按键的确定性哈希把两表记录分配到固定分区数，分区数可在请求中指定并须保证同一键的所有记录落入同一分区；分区结果须输出每分区记录数与字节估计，键分布偏斜导致某分区占比超过声明阈值时标记为偏斜分区并给出热点键清单。
3. 实现分区内 Join 与聚合：支持内连接与左外连接，分区内按键稳定排序后执行连接，并对度量列计算分组求和、均值与计数；空值度量不参与求和与均值但计入计数，左外连接未匹配侧度量全空时聚合须返回确定值而非错误；连接与聚合结果按分组键稳定升序输出。
4. 实现可界定的数值精度契约：分组求和采用 Kahan 补偿求和并与朴素求和在混合量级固定样本上对比，输出可量化误差上界；合并分区间部分和时使用与分区数无关的稳定归并顺序，使同一输入在任意分区数下聚合结果逐位一致，均值由补偿后总和与计数推导而非累加均值。
5. 实现精度预算与分区数的取舍：请求可指定精度目标或计算预算，引擎依据分区数、偏斜度与度量量级选择高精度路径（补偿求和与稳定归并）或快速路径（朴素求和）；两条路径须输出各自误差声明与适用结论，同一输入在同一路径下重复执行须逐位一致，并在快速路径越界时返回 E_PRECISION_BUDGET 而非静默降级。
6. 实现单写者执行与多读者查询的并发一致：Shuffle 与 Join 执行按请求标识串行提交，多个分区统计与结果查询可并发读取已提交版本；同一请求标识重复提交只执行一次、其余等待并复用结果；查询不得看到部分分区已写出而聚合结果仍为旧的中间状态，并须明确执行期间提交新请求的排队语义。
7. 使用 SQLite 持久化快照版本、分区计划、部分和与聚合结论，写操作先写意图记录再提交事务；进程在 Shuffle 或归并中途被强制终止后重启须扫描未完成意图，把执行标记为已中止或回滚到最后一个完整分区边界，恢复报告只基于已持久化事实，不得承诺强制终止后仍生成完整退出报告。
8. 提供本地 HTTP API 与可重复实验脚本：API 覆盖快照加载、Shuffle 与 Join 提交、按请求查询分区统计与聚合结果、误差声明查询与恢复报告查询，统一错误响应为含业务码的 JSON（至少覆盖 E_SNAPSHOT_INVALID、E_SKEW_LIMIT、E_PRECISION_BUDGET、E_REQUEST_NOT_FOUND）；脚本用固定本地样本在不同分区数下对比聚合结果并输出误差指标。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地固定样本验证不同分区数下聚合结果逐位一致、偏斜与精度预算边界及中断恢复，附运行输出。
