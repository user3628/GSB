在 Windows 空白工作区中，需要从零构建一个面向本地多组件平台的基础设施配置一致性组件。平台以带版本号的 JSON 快照描述若干组件的配置项（数值型配额、比例、阈值与整型上限），协调器需依据快照计算派生指标（如各组件的配额占比、阈值余量、跨组件加权一致度），并进行一致性校验与差异报告。核心难点是数值精度与误差传播：配置值存在浮点比例与整型上限混合，派生指标经过多级乘除与累计求和，浮点运算顺序、舍入方式与量纲归一化都会放大误差，导致同一快照在不同计算路径下判定结论不一致。系统需在定点数值精度契约、误差上界可界定与判定可复现之间取得平衡，同时处理快照版本切换、并发校验与强制终止后的恢复。所有样本为本地确定性 JSON 文件，不依赖外部服务；判定所依赖的观测为快照原始数值与其校验摘要，真值来源为按定点规则独立重算的参考结果，不接受从缺失信息推断。

任务环境与准备：
安装 Python 3.11 并创建独立虚拟环境，安装 FastAPI、Uvicorn、NumPy 与 pytest，版本以 requirements.txt 固定。
准备本地确定性配置快照 JSON 样本与固定随机种子脚本，置于工作区 data 目录，不依赖任何外部服务或网络。
确认 SQLite 可用（Python 内置 sqlite3），在 Windows 上可直接运行本地 HTTP 服务与演示脚本。

业务要求：
1. 实现配置快照加载与校验：快照文件携带版本号、生成时间、组件配置项集合与整体校验摘要，配置项含配额、比例、阈值等数值字段；加载时校验版本单调与摘要，失败返回业务码 E_SNAPSHOT_INVALID，且不得部分载入或与旧快照混合使用，版本变化须整体替换。
2. 实现派生指标计算：由组件配额计算占比、由阈值与当前用量计算余量、由跨组件权重计算加权一致度，各指标使用统一内部定点表示（比例保留固定小数位），并输出每步运算的舍入方式与累计舍入误差，禁止在中间步骤混用未归一化的量纲。
3. 实现累计求和的数值稳定性：多组件指标累计时使用 Kahan 或等价补偿求和，并与朴素求和在混合大数小数的固定样本上对比，给出可量化的误差上界；同一快照多次重算须逐位一致，判定结论不得因运算顺序变化而翻转。
4. 实现一致性判定与容差契约：判定各组件派生指标是否落在允许区间时使用带相对容差的比较而非裸浮点比较，容差内视为一致并按稳定字典序打破平局；输出 JSON 中各数值保留固定小数位并附舍入误差说明，使同一输入的判定结论可复现。
5. 实现跨模块一致性校验：当某组件配置项变化时，受影响组件的派生指标与其下游加权一致度必须级联重算且在同一事务边界内生效，禁止出现部分组件指标已更新而依赖它的一致度仍为旧值的中间可见状态；查询只能看到某一完整提交版本的指标。
6. 实现并发校验与单写者控制：快照提交与一致性重算按提交串行执行，多个查询可并发读取已提交结论；同一快照版本重复触发校验只执行一次、其余等待并复用结果；请求携带基础版本时若基础版本非当前版本返回 E_STALE_BASE 且不改变任何状态。
7. 使用 SQLite 持久化快照版本、派生指标与一致性结论，写操作先写意图记录再提交事务；进程在重算中途被强制终止后重启须扫描未完成意图，将对应版本指标回滚到最后一个完整版本或标记为已中止，恢复报告只包含已持久化事实，不得承诺强制终止后仍生成完整退出报告。
8. 提供本地 HTTP API 与可复现实验脚本：API 覆盖快照提交、按版本查询派生指标、一致性结论查询、误差说明查询与恢复报告查询，统一错误响应为含业务码的 JSON（至少覆盖 E_SNAPSHOT_INVALID、E_STALE_BASE、E_DUPLICATE_VERSION）；脚本使用固定本地样本完成一次全量校验、一次单组件数值微调触发的级联重算与一次强制终止后恢复，输出误差对比与判定结论。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定本地样本验证派生指标误差界、容差判定可复现及版本切换与恢复一致，附运行结论。
