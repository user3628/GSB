在 Windows 空白工作区中，需要从零构建一个面向本地单机 GPU 资源池的配额调度与推理批调度诊断工作台，供集群管理员离线评估一组推理服务请求能否被放入若干逻辑 GPU 节点，并诊断判定过程中的配额传播与批组织取舍。节点规格由本地确定性 JSON 样本提供：每个逻辑节点声明总显存（字节整数）、可用算力份额（千分之一为单位的整数）、已占用显存、配额组标识与健康状态。请求声明服务名、模型标识、显存需求、每批样本数、期望批延迟上限、优先级与所属配额组。系统需依据配额组的显存与算力上限判定准入，在准入后把同模型请求组织成推理批，把批放入节点并追踪请求在 PENDING、ADMITTED、BATCHED、RUNNING、COMPLETED、REJECTED、PREEMPTED 之间的状态演进。难点在于数据规模变化与算法取舍：请求规模从数十条增长到数千条时，批组织既要控制显存碎片与批延迟，又不能突破配额上限；同时进程可能在批调度中途被强制终止，重启后必须依据持久化事实恢复或中止。所有资源数值以本地样本与整数运算为准，不依赖真实 GPU。

任务环境与准备：
在 Windows 空白工作区安装 Python 3.11 及以上版本，并使用 venv 创建虚拟环境。
在虚拟环境中安装 fastapi、uvicorn、numpy 与 pytest，版本以 pip 可解析的最新稳定版为准，SQLite 使用 Python 标准库 sqlite3。
准备本地确定性 JSON 样本：节点规格、配额组声明与请求规格由固定随机种子生成脚本产出，不依赖真实 GPU 或外部服务。
确认本地回环端口可用，所有 HTTP 测试与查询仅请求本机服务；任务开始前不预置任何项目代码或数据库文件。

业务要求：
1. 实现节点与请求规格的解析与归一化：显存以字节整数、算力份额以千分之一整数为内部表示，解析样本中形如 40Gi、512Mi、250m 的量纲字符串并做溢出与负数检查；解析失败返回业务码 E_SPEC_INVALID 且不写入任何状态。
2. 实现配额组准入判定：每个配额组声明显存上限与算力上限，成员节点的已占用与该组已准入请求的预留量共同计入占用；请求准入后预留量须在同一事务内计入配额，超额返回 E_QUOTA_EXCEEDED 并附当前占用与剩余量，禁止出现节点已接受而配额未扣减的状态。
3. 定义请求状态机，至少包含 PENDING、ADMITTED、BATCHED、RUNNING、COMPLETED、REJECTED、PREEMPTED 七种状态并规定合法迁移路径；非法迁移返回 E_INVALID_TRANSITION 且保持原状态，状态迁移需记录触发原因与关联的节点与批标识。
4. 实现推理批组织：把同模型、同节点且相邻提交的请求按批样本数上限与显存余量组织成批，批的合计显存不得超过节点剩余显存；当请求规模超过配置阈值时允许按提交顺序在贪心装箱与按显存降序装箱之间选择策略，并输出所选策略、装箱利用率与因碎片被拒的请求清单。
5. 实现批延迟与显存碎片的取舍：每批的估计延迟由批样本数与模型单位样本代价决定，超期望批延迟上限的批不得成批并返回 E_BATCH_TOO_LARGE 或拆分重排；在碎片导致批无法装入时按确定规则尝试重组已有批，重组须保持每个批内请求的准入结论与配额扣减不变前后一致。
6. 实现并发控制与可见性：批调度按配额组单写者串行执行，多个只读查询可并发；同一请求标识重复提交只生效一次，其余复用结果；查询不得看到请求已进入 BATCHED 而其配额预留量仍为旧值的中间状态，并须明确抢占发生时在途批的处置语义。
7. 实现抢占与配额回收：高优先级请求在配额不足时可对低优先级请求发起抢占，被抢占请求迁移为 PREEMPTED 并真实释放其预留显存与算力份额，释放须在同一事务内完成；禁止仅修改状态而配额占用不变，回收后须能再次通过准入校验。
8. 使用 SQLite 持久化节点占用、配额预留、请求状态与批记录，写操作先落意图记录再提交；进程在批调度中途被强制终止后重启须扫描未完成意图，把批与请求恢复到最后一个完整版本或标记为已中止，并输出仅基于持久化事实的恢复报告与前后占用差异。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证配额准入、批组织取舍、抢占回收与强制终止后恢复的一致性，并附运行结果。
