为视频预测与运动时序团队从零构建一个本地可运行的预测会话服务，核心技术问题是多段运动轨迹证据的融合、外推与状态演进在进程被强制终止后的一致性恢复。工作区为空，需自行初始化项目。输入是本地场景目录：一份视频片段清单 JSONL，每条含 clip id、帧数、帧率、宽高与若干运动轨迹观测（轨迹 id、逐帧二维位置浮点坐标、可见标记与置信度）；一份运动先验配置 JSON，声明速度平滑系数、外推步数、融合权重与浮点容差。服务须按片段推进 evidence_loaded、tracks_fused、rolled_forward、committed 四阶段，产出逐轨迹融合位置、外推帧位置与不确定度，并支持快照导出与中断恢复。

任务环境与准备：
安装 Python 3.11 或以上，并创建本地虚拟环境。
安装 numpy、fastapi、uvicorn 与 pytest，全部使用本地 wheel 或已配置的包索引。
在工作区创建 data 目录，按题面格式手写或脚本生成固定片段清单、先验配置与含若干轨迹的 JSONL 样本，不依赖任何外部数据集。
确认当前工作区为空后初始化项目目录，启动服务前检查所用端口未被占用。
准备一份固定变更序列与预算参数，用于反复执行的确定性演示与中断恢复演练。

业务要求：
1. 会话创建接口接收场景目录、先验配置与全局外推预算，校验 clip id 唯一、轨迹逐帧位置为有限实数且帧下标连续、置信度位于闭区间 [0,1]、平滑系数位于开区间、外推步数为非负整数、预算为正整数；任一非法返回 E_PARAM 业务码并指出出错文件与行号，且不写入任何阶段状态。
2. evidence_loaded 阶段须完成证据校验与确定性载入：同一轨迹 id 在同一 clip 内重复、可见标记非布尔、置信度越界或某帧位置缺失时分别返回 E_DUP、E_MARK、E_CONF、E_EVID 业务码并定位 clip id 与轨迹 id；阶段内按轨迹 id 字典序、帧下标升序稳定组织证据，重复执行须得到逐位一致的组织结果。
3. tracks_fused 阶段须按速度平滑系数把逐帧观测融合为轨迹状态序列，融合在 float64 下按帧下标升序递推并输出每帧融合位置与位置不确定度；不可见帧须以可见帧状态插值补齐并计入补齐帧数，任意长度轨迹的中间量不得溢出或下溢，同一输入与配置下融合结果须逐位可重复且不依赖字典遍历顺序。
4. rolled_forward 阶段须按外推步数把每条轨迹向后预测，外推位置由末端融合速度按平滑系数衰减推得，并输出外推帧位置与由融合不确定度与平滑衰减合成的不确定度；外推步数为零时须给出空外推序列而非报错，超出容差的轨迹须被标记并能在结果中定位到轨迹 id 与外推帧下标。
5. 会话须按 evidence_loaded、tracks_fused、rolled_forward、committed 四阶段推进，阶段顺序不可跳步，乱序推进返回 E_STAGE 并给出当前阶段；重复调用已完成阶段须幂等返回已有结果与当前快照版本，返回内容与首次调用逐位一致。
6. 外推须受创建时给定的全局外推预算约束，预算按每条轨迹实际外推帧数原子扣减；预算不足以覆盖某轨迹的剩余外推帧时该轨迹整条排队并返回 E_BUDGET，须给出等待轨迹清单与剩余预算，并发场景下扣减总数不得超过给定预算且排队顺序按轨迹 id 字典序确定。
7. 会话状态须以会话、阶段、轨迹三级记录在 SQLite 中事务提交，单条轨迹的融合结果、外推结果与轨迹进度标记在同一事务中写入；某条轨迹失败时整阶段事务回滚，不得留下部分轨迹结果、半写结果文件或与快照版本不一致的记录；结果文件须先写临时文件再原子替换并登记内容哈希。
8. 每次阶段完成须整体替换生成版本化快照，含会话版本号、各轨迹阶段结果摘要与结果文件内容哈希；读取快照时若检测到数据库版本与磁盘文件哈希不一致、版本变化或残留旧结果文件，须返回 E_STALE 并定位到会话与轨迹；进程被强制终止后重启须从已提交轨迹进度继续，核对每条轨迹的阶段标记与内容哈希，重算未提交轨迹且不重复消费已提交轨迹，恢复后的融合位置、外推序列与快照版本须与无中断执行完全一致，并提供固定样本下的确定性演示入口。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定样本与预算跑通四阶段，校验非法输入业务码、逐位可重复结果、预算排队与强制终止后恢复一致。
