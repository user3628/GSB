交付从新建的代码库开始，面向反向代理与后端服务之间的 HTTP 请求走私风险，构建一个本地可集成的规范化裁决组件。组件接收成对的原始请求报文（代理视角与后端视角），对 Content-Length 与 Transfer-Encoding 的组合、重复头、首尾空白、obs-fold、分块长度写法等做归一化，并判定两个视角下报文边界是否一致；不一致即视为走私面，需给出可定位的裁决结论与业务码。由于同一连接内可能承载大量请求，组件需要按连接批处理并在数据规模变化时自适应选择逐请求精算或流式扫描的算法路径，同时保证两种路径裁决结论一致。组件需维护带版本号的裁决快照，并支持通过外部注入构造畸形报文样本进行异常链路验证。

任务环境与准备：
安装 Go 1.22 或更高版本，确认 go version 在 Windows 上可用。
使用 Go 内置的 SQLite 驱动路径（如 modernc.org/sqlite）从本地模块缓存获取，无需外部数据库服务。
在新建工作区执行 go mod init 初始化模块，确保后续依赖均从本地模块缓存获取。
准备本地确定性样本目录，样本由程序内生成入口写出，不依赖网络下载或外部附件。
确认 Windows 临时目录可读写，用于 SQLite 数据库文件与运行示例输出目录。

业务要求：
1. 实现报文归一化与请求边界计算核心：对代理视角与后端视角分别解析起始行、头部字段与消息体长度，统一处理 Content-Length 多值与不一致、Transfer-Encoding 多值与 chunked 位置、头部名称大小写、obs-fold 续行与字段值首尾空白，输出每个视角下的请求条数与每条请求的字节边界区间；任何无法确定边界的报文须给出稳定业务码而非静默截断。
2. 实现走私面裁决引擎：比较两个视角下同一连接内的请求条数与各请求边界，判定一致、条数不一致、边界错位或编码歧义四类结论，并给出首个偏离位置的字节偏移、涉及的头部字段名与裁决码 E_SMUGGLE_AMBIGUITY；当两视角均判定为单请求且边界一致时必须得出无走私结论，不得因头部顺序差异误报。
3. 实现数据规模自适应的算法路径选择：当单连接请求数低于阈值时采用逐请求精算路径，高于阈值时采用流式扫描路径；两条路径必须对同一输入产生逐字节一致的裁决结论与业务码序列，阈值与路径选择结果须在输出中可观测，不得以随机或墙钟因素影响路径切换。
4. 实现带版本号的裁决快照与整体替换识别：每完成一个连接的裁决后提交递增版本号快照并持久化到 SQLite，快照内容比较须识别整体替换式版本变化而非仅比对版本号；加载时校验版本链连续性，发现跳号返回 E_SNAPSHOT_VERSION 并回退到最近连续版本，已提交快照不得被部分覆盖。
5. 实现并发连接批处理的资源控制：多个连接在独立会话中裁决，会话间状态隔离；并发度与单会话请求数上限可配置，超并发上限的连接进入等待队列而非直接拒绝，单连接请求数超限时以 E_REQUEST_BUDGET 终止该连接并保留已裁决结果，超等待阈值的请求返回 E_BATCH_CONTENTION 并记录连接标识。
6. 实现异常注入验证链路：通过外部参数或配置文件构造 Content-Length 与 Transfer-Encoding 并存、重复 Content-Length 且值冲突、分块长度带前导零与十六进制大写、obs-fold 嵌入分块边界、未知传输编码五类畸形样本，分别断言对应业务码、该连接未污染其他连接结论、快照版本变化符合预期；注入仅通过输入参数生效，不得修改源码制造失败。
7. 实现裁决结果的确定性排序与可重复报告：导出的 JSON 报告按连接相对路径、请求序号与偏离偏移稳定排序，包含各连接两视角请求数、裁决结论、业务码及偏移、所用算法路径与快照版本号；报告中的时间字段仅使用固定采样标记而非墙钟，输入不变且并发度变化时报告字节级一致。
8. 提供可集成的 Go 包接口与完整示例：导出裁决组件入口供宿主代理服务接入，附带本地确定性样本集（正常双边一致、条数不一致、边界错位、编码歧义及五类畸形样本）与一键运行示例命令，示例须在 Windows 上以纯本地文件运行，重复运行输出字节级一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证归一化、走私裁决、双路径一致性与快照版本链，并核对异常注入的业务码与确定性报告。
