当前是空白工作区，需要从零构建一个面向本地嵌入式场景的键值存储索引与过期管理组件，供上层领域数据编辑应用集成。组件以段文件持久化键值记录，每条记录包含键、值、版本号、写入时间戳与可空过期时间，内存索引维护键到段偏移的映射，并以过期时间最小堆支撑过期清理。为支持与外部工具互换数据，需要实现紧凑二进制格式（魔数、记录长度、CRC32 校验、大小端标记）与分片 JSON 行格式两种持久化编码。业务上的核心难点是增量维护与依赖失效：导入批次与写入操作只允许改动受影响的键及其派生结构（过期最小堆、键版本索引、段摘要），同一键的删除后重建、过期后重写必须使旧派生条目失效；同时进程可能在导入或快照切换中途被强制终止，重启后必须依据 SQLite 中的意图日志恢复到一致状态。

任务环境与准备：
安装 Python 3.11 或以上，并用 pip 安装 pytest 与 requests，无需其他外部服务。
在工作区创建项目目录与本地样本目录，样本由脚本生成固定键值记录与两份格式文件，不下载外部数据集。
确认 SQLite 由 Python 标准库提供，端口可本地回环监听，运行前无需启动数据库或网络服务。

业务要求：
1. 实现两种持久化格式的编解码：紧凑二进制格式必须包含魔数、版本字节、大小端标记、每条记录长度前缀、CRC32 校验与键值版本过期字段，分片 JSON 行格式每行含键、值、版本、写入时间戳与过期字段；任一条记录校验失败须返回业务码 E_RECORD_CORRUPT 并指出记录位置，整批不得部分生效。
2. 实现格式协商与字段映射：导入前检测输入格式并给出协商结果；二进制毫秒时间戳与 JSON 微秒时间戳须归一化为同一内部毫秒表示，按声明截断规则处理亚毫秒部分并输出每条舍入位与累计舍入误差；JSON 相对 TTL 须依据记录自带基准时间换算为绝对过期时刻，缺失字段按降级规则补齐为声明默认值。
3. 实现基于最小堆的过期索引增量维护：写入、导入与删除只允许对受影响的键更新堆中条目，堆中不得残留同一键的旧过期时刻的僵尸条目；同一键删除后重建或过期后重写必须使旧索引条目失效并可被检测；堆顶时间与当前时间比较得出应清理键集合，清理过程记录墓碑并输出清理数量。
4. 实现键版本索引与段偏移的依赖失效：每个键的当前版本号、段偏移与段内长度构成派生映射，写入与导入须使旧版本映射失效而不是叠加，段文件被压缩或段摘要复核失败时依赖该段的全部键映射必须级联失效并原子重建，禁止出现偏移已更新而版本号仍为旧值的中间可见状态。
5. 实现导入冲突解决与批次原子生效：导入记录与现有键版本号相同但值不同、版本号较低或文件内重复键时，按版本优先与最后写入时间打破平局的确定规则解决，结局分为覆盖、跳过与拒绝三类并写入导入报告；整批导入须原子生效，任一条被拒绝则整批回滚并保留原状态。
6. 实现快照整体替换与版本识别：快照文件携带格式版本、快照序号与生成时间，加载时须校验版本兼容性与序号单调，加载过程在内存索引、过期堆与段映射之间原子切换，切换成功后才释放旧快照资源；任一校验失败须保持旧状态完全可用，并返回 E_SNAPSHOT_INVALID 或 E_SNAPSHOT_STALE。
7. 实现单写者写事务、多读者只读隔离与强制终止恢复：写操作先写 SQLite 意图日志再修改段文件与索引，只读查询在写进行时看到写前一致快照；并发导入同一批次或并发快照切换时仅一个成功、其余返回 E_CONFLICTING_BATCH；进程被强制终止后重启须扫描未完成意图恢复到最后完整事务边界，并输出仅基于已持久化事实的恢复报告，不承诺强制终止后仍生成退出报告。
8. 提供本地 HTTP API 与端到端演示：API 覆盖写入、读取、删除、二进制导出、JSON 行导出、两种格式导入、快照切换与恢复报告查询，失败响应统一为含业务码与上下文的 JSON（至少覆盖 E_RECORD_CORRUPT、E_CONFLICTING_BATCH、E_SNAPSHOT_INVALID、E_STALE_BASE、E_SNAPSHOT_STALE）；附固定样本脚本演示一次全量导入、一次只改单键的增量写入及一次强制终止后恢复。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
