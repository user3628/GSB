当前是空白工作区，需要从零构建一个面向本地块存储场景的冷热分层与迁移组件，供上层分层存储编排器集成。存储池由若干分层（表示存储介质等级，例如高性能层与容量层）与若干逻辑对象分片组成；每个分片带标识、字节大小、最近访问灰度（0-255 的整数热度值）、所在分层与迁移冷却截止时刻。组件以带单调版本号的分层策略快照（各分层容量上限、热度阈值、迁移批次上限、冷却时长与整体校验摘要）驱动分片在分层间的迁移，维护分片迁移状态在 PENDING、MIGRATING、COMMITTED、FAILED、ABORTED 之间的演进，并在每次迁移后重算各层容量占用与冷热分布摘要。核心难点是状态演进与恢复一致性：容量重算依赖全部分片所在分层，若迁移在计算占用与更新分层之间被强制终止，重启后必须依据持久化意图记录与快照版本才能得到自洽的分层占用，且迁移批次与快照版本之间不得出现半新半旧的可观测状态。所有数据来自本地确定性样本，进程可能在任何时刻被强制终止，必须区分安全退出的收尾与强制终止后的恢复，强制终止后的恢复只能依赖已持久化事实。用户通过本地 HTTP API 提交策略快照、触发迁移批次、注入中断、查询分层占用与恢复报告。

任务环境与准备：
在 Windows 上安装 Python 3.10 或以上，并确认 python 与 pip 在 PATH 中可用。
在项目虚拟环境中安装 fastapi、uvicorn、numpy 与 pytest，版本以本地 wheel 或 PyPI 可用版本为准；SQLite 使用 Python 标准库 sqlite3，无需额外安装。
准备本地确定性样本：分层策略快照 JSON、分片清单 JSON 与热度灰度分布，均由固定随机种子脚本生成并纳入项目，不依赖外部数据或网络服务。
启动本地 HTTP 服务前确认可用回环端口，数据库文件与样本目录位于工作区内，运行前清空旧的临时产物以保证可重复。
全部运行与验收均在 Windows 本地完成，不涉及容器、真实账号或线上站点。

业务要求：
1. 实现分层、分片与策略快照模型：快照包含单调递增版本号、生成时间、各分层容量上限字节、热度阈值、每批迁移数上限与冷却时长，以及整体校验摘要；分片记录标识、字节大小、热度值、所在分层与冷却截止时刻。提交快照时版本号不大于当前已提交版本返回 E_STALE_SNAPSHOT；加载须整体替换旧策略，不得把新旧快照的分层参数混合使用，校验摘要失败返回 E_SNAPSHOT_INVALID 且必须保持旧快照继续可服务。
2. 实现迁移候选选择与批次构造：按热度阈值、冷却截止时刻与目标层容量余量从各层筛出跨层迁移候选，构成迁移批次；候选必须满足单批数量上限且同一分片在同一批次内不得重复出现；当候选为空时返回空批次而非错误；当某层剩余容量无法容纳全部达标候选时，按确定规则（如热度降序与分片标识升序）截断，并输出被截断候选清单与截断依据，不得静默丢弃。
3. 定义分片迁移状态机，至少包含 PENDING、MIGRATING、COMMITTED、FAILED、ABORTED 五种状态并规定合法迁移路径；非法迁移返回 E_INVALID_TRANSITION 且不得修改任何已持久化状态；批次内每个分片的状态迁移须可追溯，查询接口须能给出某批次的全部分片状态与最后变更时刻，用于核对批次整体结论与逐个分片结论是否一致。
4. 实现迁移执行与真实资源转移：迁移须真实改变分片所在分层并记录源层释放字节与目标层占用字节，源层与目标层的容量占用必须在同一事务边界内一并更新，禁止出现分片已迁移而源层占用未释放、或目标层占用已计入而分片仍指向源层的中间可见状态；每批迁移完成后重算各层占用与冷热分布摘要，重算结果须与逐分片累加结果一致。
5. 实现进程被强制终止后的恢复：批次的迁移意图、分片状态变更与层级占用更新在提交前均先写入 SQLite 意图记录；强制终止后重启须扫描未完成意图，把未提交的迁移回滚为 PENDING 或标记为 ABORTED，并基于已持久化事实重建各层占用，使分层占用恰好等于已提交分片所在层的累加；恢复报告只能基于已落盘记录，不得承诺强制终止后仍生成完整退出报告；安全退出路径可写入批次完成摘要，两条路径须在报告中明确区分。
6. 实现并发控制与幂等：迁移批次的执行与层级占用更新按提交单写者串行执行，多个只读查询（分层占用、分片状态、冷热分布摘要）可并发且只能看到某一完整提交版本；同一批次标识重复触发只执行一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_BATCH；并发提交同一策略版本的两个增量式调整（如只改某层容量上限）只允许一个成功，另一个返回 E_STALE_BASE 且不改变任何状态。
7. 实现分层容量变更时的级联一致性：当策略快照调整某层容量上限或热度阈值时，受影响分片的迁移候选资格、批次构造输入与各层占用摘要须级联失效并在同一事务边界内重算；若新容量上限低于该层当前占用，须返回 E_CAPACITY_OVERFLOW 并附超出的字节数，且不得部分应用新快照（容量参数、热度阈值与已提交分片的迁移结论保持旧快照状态）。
8. 提供统一业务错误码 JSON 错误体与端到端演示脚本：所有失败响应为含业务码与上下文的 JSON，至少覆盖 E_STALE_SNAPSHOT、E_SNAPSHOT_INVALID、E_INVALID_TRANSITION、E_CONFLICTING_BATCH、E_STALE_BASE、E_CAPACITY_OVERFLOW；演示脚本使用固定本地样本完成一次全量迁移批次、一次容量调整触发级联重算、一次非法迁移拒绝、一次强制终止后恢复，输出各层迁移前后的占用、迁移分片数、状态迁移记录与恢复差异，便于人工核对。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定本地样本跑通迁移批次、容量级联重算与强制终止后恢复，核对分层占用与状态迁移一致。
