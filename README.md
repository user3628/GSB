当前是空白 Windows 工作区，需要从零构建一个面向本地小规模训练任务的训练数据预处理管线与结果验证工具。输入为本地确定性样本：原始记录文件（每行含毫秒时间戳、样本标识、文本片段长度、标签、分片键）与一份带版本号的预处理策略快照（清洗规则、过滤阈值、分片规则、归一化参数、随机种子与采样比例）。管线需依次完成解析清洗、过滤、分片、确定性采样与张量化输出，把每个分片产出写入本地存储，并把每个阶段的输入摘要、输出摘要与统计写入 SQLite，供验证工具按版本回放核对。核心难点是可复现验证与异常注入：同一策略版本与同一样本必须逐位产出相同结果，异常输入（重复标识、非法标签、分片键缺失、采样比例越界）与中途强制终止都必须在持久化事实基础上给出可核对的恢复结论，而不得依赖任何未落盘的中间内存状态。

任务环境与准备：
安装 Python 3.11 与 NumPy、FastAPI、Uvicorn 及 SQLite 支持，创建独立虚拟环境。
准备固定本地样本文件（含合法记录与各类畸形行）与两份带版本号的策略快照，放置于工作区 data 目录。
确认本地回环端口可用，无需外部网络、账号、GPU 或数据集。

业务要求：
1. 实现样本解析与清洗：逐行解析时间戳、样本标识、文本片段长度、标签与分片键，非法行返回业务码 E_RECORD_INVALID 并整批不入库；同一批次内样本标识重复须按确定性规则保留首条并把重复条数计入批统计，重复内容不一致时返回 E_CONFLICTING_RECORD 且不改变已提交状态。
2. 实现带版本号的策略快照与基础版本校验：快照含单调递增版本号、生成时间、清洗与过滤规则、分片规则、归一化参数、随机种子与采样比例，以及整体校验摘要；提交时版本号不大于当前版本返回 E_STALE_SNAPSHOT，同一基础版本的两个并发增量只允许一个成功，另一个返回 E_STALE_BASE。
3. 实现固定种子驱动的阶段确定性：从解析、过滤、分片、采样到张量化的每一步随机性只能来自策略快照声明的种子与本阶段输入摘要的组合，禁止使用全局随机源或当前时间；同一策略版本与同一样本重复执行必须逐位一致，任何阶段输出摘要不一致时返回 E_REPRO_MISMATCH 并指明首个偏离阶段。
4. 实现分片规则与张量化输出：按分片键把记录划分到声明数量的分片并保证分片间不重不漏，样本数与字节量的分布偏斜超过声明阈值时输出偏斜告警但不得改变分片归属；张量化输出须带数据类型、空值掩码与样本数，且写入后重新读取的摘要必须与写出摘要一致。
5. 实现异常注入接口：请求参数可注入非法标签、分片键缺失、采样比例越界、重复标识冲突与阶段中途注入中断标记五类情形，每类返回互不相同的业务码（至少含 E_LABEL_INVALID、E_SHARD_KEY_MISSING、E_SAMPLE_RATIO_INVALID、E_CONFLICTING_RECORD），错误体为含业务码与上下文的 JSON。
6. 实现单写者执行与多读者查询的并发一致：管线执行按策略版本单写者串行，多个验证查询可并发读取已提交结果；同一批次标识重复提交只执行一次、其余等待并复用结果；查询只能看到某一完整提交版本，不得出现某分片已写完而批统计仍为旧值的中间可见状态，须明确该可见性边界。
7. 使用 SQLite 持久化阶段摘要、分片产物索引与意图日志，执行前先写意图记录再提交事务；进程被强制终止后重启须扫描未完成意图，把批次回滚到最后一个完整阶段边界或标记为已中止，恢复报告只包含已落盘事实，不得声称强制终止后仍生成完整退出报告，也不得承诺恢复未提交产物。
8. 提供本地 HTTP 接口与结果验证工具：接口覆盖策略提交、样本批次提交、按批次查询阶段摘要与分片统计、恢复报告查询，失败响应统一为含业务码的 JSON；验证工具依据持久化阶段摘要逐阶段重算并比对，输出首个偏离阶段、两侧摘要与建议排查范围，并支持按任意历史策略版本回放核对。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定样本验证同版本逐位复现、五类异常注入的业务码与强制终止后的分片恢复结论。
