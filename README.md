团队先做独立原型，在空目录里验证日志分区聚合在增量追加、日志乱序与进程强制终止后的重算一致性。原型读取程序内置固定种子生成器写出的确定性日志批次（毫秒时间戳、日志序号、分区键、int64 定点度量值 scale=1e6、空值标记与批次摘要），按带单调版本号的聚合规格快照（分区数、分组键、乱序容忍窗口毫秒、迟到处理策略、每轮时间预算与全局并发上限）执行分区聚合。真实场景里同一分区的日志会乱序到达并有迟到记录，迟到记录可能落在已关闭的时间窗内，引擎须决定回填窗口还是落入迟到队列；同时增量追加只允许重算受影响分区，而迟到回填会波及已提交窗口，二者对同一窗口结论的要求互相拉扯。进程随时可能被强制终止，重启后只能依据 SQLite 中已落盘的事实恢复分区状态与窗口结论。

任务环境与准备：
安装 Go 1.21 或以上版本与 SQLite 开发库（go-sqlite3 需开启 CGO），在 WSL Ubuntu 上执行 go mod init 初始化模块。
运行程序内置的固定种子生成器在本地写出带版本号的日志批次与聚合规格快照，样本与依赖均落本地磁盘，不访问外部网络。
准备本地测试端点用于探测，并确保可对进程发送 SIGKILL 以模拟强制终止，重启入口只从 SQLite 恢复而不依赖内存状态。
本机不依赖 GPU、真实账号或线上服务，所有校验基于本地确定性样本与本地测试端点完成。

业务要求：
1. 实现日志批次与聚合规格快照的联合加载与整体替换：日志批次携带单调递增版本号、生成时间与整体校验摘要，规格快照携带分区数、分组键、乱序容忍窗口毫秒与迟到处理策略；加载时须同时校验版本单调与摘要，任一失败返回 E_SNAPSHOT_INVALID 并保持旧快照完全可用，成功则原子替换旧快照。
2. 实现批次增量追加与基础版本校验：每批只含新增日志并携带基础版本，基础版本不是当前已提交版本时返回 E_STALE_BASE 且不改变任何状态；同一基础版本的两个并发追加只允许一个成功，另一个必须收到 E_STALE_BASE；度量值超出 int64 定点可表示范围时整批拒绝并返回 E_NUMERIC_OVERFLOW。
3. 实现乱序容忍与迟到记录回填裁决：按分区维护乱序容忍窗口，窗口内到达的记录按日志序号归位，超出容忍深度仍未到达的序号判定缺口并把窗口固定；迟到记录若落在已固定窗口内，按规格声明的迟到策略决定回填该窗口并把窗口结论重新计算后提交，或落入迟到队列并输出迟到数量、迟到毫秒偏移与策略依据，回填与入队两种结局均须可核对。
4. 实现分区间增量重算与窗口部分和复用：每批只对受影响分区重算窗口内分组计数、求和、最小与最大，未受影响分区的已登记窗口部分和直接复用；迟到回填只重算被回填窗口及其所在分区，并输出本批实际重算的分区号、窗口号与复用的部分和数量，增量重算结果与全量重算结果须落在声明的相对容差内。
5. 实现两种求和实现与精度路径选择：提供朴素顺序求和与 Kahan 补偿求和两种实现，均须输出所用算法标识与可量化误差上界；引擎依据分区度量量级分布与规格声明的相对精度目标在两者间选择并输出选择依据，同一分区同一窗口在两种实现下结果须落在声明的相对容差内，容差外须报告差异字段与偏差值。
6. 实现三重预算约束下的分区扫描调度与延后分区状态迁移：窗口重算任务在全局并发上限、单分区内存预算与每轮时间预算约束下执行，超并发上限者进入有界等待队列，队列满返回 E_SCAN_QUEUE_FULL；预算内未完成的分区迁移为延后状态并输出延后依据与剩余预算，已提交的窗口结论不得因延后而被回退或覆盖。
7. 实现单写者执行与多读者查询的并发一致及幂等：批次追加、窗口重算与迟到回填按快照版本单写者串行执行，多个只读查询可并发读取某一完整提交版本，不得出现某窗口已提交新结论而规格版本仍为旧值或部分和登记仍在旧版本；同一批次标识重复提交只执行一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_REQUEST。
8. 实现基于 SQLite 的意图持久化与强制终止后恢复：批次追加、窗口部分和写入、迟到回填与规格切换前先写意图记录再提交事务；进程被强制终止后重启须扫描未完成意图，把未提交窗口回滚为待重算、未提交部分和丢弃，恢复报告只包含已落盘事实，并对已提交窗口与复用部分和重新校验一致性。
