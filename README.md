当前是空白工作区，需要在 Windows 本地从零构建一个面向多集群平台的配置分发协调组件，交付可集成的领域组件与完整示例。平台包含配置仓库、分发协调器与若干本地集群端点（以本地 HTTP 测试服务模拟）。配置以带版本号的 JSON 快照提交，每个配置项被多个集群组件依赖；协调器据依赖关系计算受影响组件集合，生成分发计划并推进组件状态演进。运维人员还会提交只含局部改动的增量片段，某个配置项变化时依赖它的派生结果（组件期望配置摘要、跨集群一致度评分与分发批次索引）必须级联失效并原子重建。核心业务问题是增量更新与依赖失效：增量片段与整份快照共享版本空间，级联重建跨多个持久化产物，进程可能在重建中途被强制终止。

任务环境与准备：
安装 Python 3.11 或以上并确认 python 与 pip 可用；Windows 命令提示符或 PowerShell 均可执行。
执行 pip install fastapi uvicorn httpx pydantic 安装本地依赖，不依赖任何外部账号、容器或在线服务。
在空白工作区创建项目目录，准备固定本地样本：两份配置快照 JSON、一份增量片段、组件声明文件与本地集群端点测试服务脚本。
准备端到端演示脚本入口，确保其可用 python 直接运行并打印受影响组件清单、重建范围、状态轨迹与恢复报告摘要。

业务要求：
1. 实现配置快照与依赖声明模型：快照携带单调递增版本号、生成时间、配置项集合与整体校验摘要，组件声明包含组件标识、依赖配置键、期望配置版本与本地端点地址；提交时版本号不大于当前版本返回 E_STALE_SNAPSHOT，摘要不一致返回 E_SNAPSHOT_INVALID，且失败不得改动任何已提交状态。
2. 实现增量片段提交：增量只包含受影响的配置键或组件声明并携带基础版本号；基础版本不是当前版本时返回 E_STALE_BASE 且不修改状态；同一基础版本的两个并发增量只允许一个成功，另一个必须收到 E_STALE_BASE，增量与整份快照共用同一版本序列。
3. 实现影响分析与分发计划：依据组件声明解析出直接引用新配置的组件以及需要连带重新分发的下游依赖组件，按依赖拓扑排序生成批次；依赖出现环时返回 E_DEPENDENCY_CYCLE 并附环上标识；无关配置键变化的组件不得进入受影响集合。
4. 定义组件状态机，至少包含 PENDING、DISPATCHED、APPLIED、FAILED、ROLLED_BACK 五种状态并规定合法迁移路径；非法迁移返回 E_INVALID_TRANSITION 且不修改已持久化状态；每次迁移须记录原因与对应快照版本。
5. 实现派生结果的级联失效与原子重建：每个组件的期望配置摘要、跨集群一致度评分与分发批次索引需维护对配置键与组件声明的引用关系；某配置键或声明变化时其全部派生结果及依赖它们的产物必须级联失效并在同一事务边界内原子重建，禁止出现摘要已更新而一致度仍为旧值的中间可见状态。
6. 实现向本地集群端点推送：推送携带快照版本、配置项与幂等请求标识，端点可返回成功、业务拒绝或延时响应；须区分推送被拒绝、连接失败与超时，超时须真实关闭连接并返回 E_PUSH_TIMEOUT，不得以等待冒充超时；失败按策略选择继续其余组件或回滚已应用组件，并输出最终结论。
7. 实现并发一致、幂等与强制终止恢复：分发执行按快照版本单写者串行，多个只读查询可并发且只能看到某一完整提交版本；同一快照重复触发分发只执行一次、其余复用结果；所有写操作先落 SQLite 意图记录再提交事务，进程在级联重建或推送中途被强制终止后重启须扫描未完成意图回滚到最后一个完整版本或将分发标记为已中止，恢复报告只基于已持久化事实。
8. 提供统一业务错误码 JSON 错误体（至少覆盖 E_STALE_SNAPSHOT、E_STALE_BASE、E_DEPENDENCY_CYCLE、E_INVALID_TRANSITION、E_PUSH_TIMEOUT、E_CONFLICTING_PUSH）与端到端演示脚本：脚本用固定本地样本与本地测试端点完成一次全量分发、一次只改单个配置键的增量提交触发级联失效重建、一次含失败组件与超时组件的策略处置以及一次强制终止后恢复，输出两次受影响的组件清单、派生结果重建范围、状态迁移轨迹与恢复报告。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
