球面数据聚类团队的新项目刚立项，代码尚未开始编写，需要先在本地把可运行的球面k均值聚类与核密度估计增量演进组件搭出来。输入由程序内置固定种子生成器确定性产出一批批次到达的 JSON 样本分片：每片含单位球面上的三维特征点（坐标为定点整数并附 scale 声明）、批次标识、来源通道与可选真值簇编号，覆盖单峰、双峰、含离群点、含零向量与批次间簇心漂移等情形，并附一份带单调版本号的聚类与密度估计配置快照，声明簇数、迭代上限、收敛阈值、带宽估计规则、密度查询网格与漂移判定阈值。组件需要按批次滚动维护簇心与密度状态，每次判定都必须可追溯到对应状态版本，且进程被强制终止后只能依据 SQLite 中已提交事实恢复。

任务环境与准备：
安装 Go 1.21 或以上版本，并确认 go 命令在 PATH 中可用。
在 Linux（WSL Ubuntu）工作目录中初始化 Go module，无需第三方网络依赖。
SQLite 通过纯 Go 驱动或系统包引入，版本随所选驱动确定，准备本地可写数据目录。
程序内置固定种子生成器，无需外部数据集、GPU 或网络服务。

业务要求：
1. 实现球面上的分块k均值聚类核心：把定点坐标按 scale 还原为单位向量后，以余弦相似度而非欧氏距离分配最近簇心，簇心更新须在对数域或缩放域累加后重新归一化并处理零向量样本；同一批样本与配置必须产生逐字节一致的分配序列与簇心摘要，全零向量或簇心模长退化须返回带批次与样本标识的 E_GEOMETRY。
2. 实现核密度估计的分块评估：在配置声明的查询网格上对当前批次样本做球面核密度累加，带宽由该批样本的稳健离散度显式估计，分块累加采用补偿求和并逐块记录部分和与块索引；同一批样本、网格与配置必须产生逐字节一致的密度曲线，带宽为零或网格为空须返回 E_DENSITY_PARAM。
3. 实现批次到达后的簇心与密度状态演进：以批序号维护累积样本计数、簇心版本与逐网格点密度权重，新批次到达时按增量方式合并进当前状态并输出新的状态摘要（版本号、覆盖批数、有效样本数、簇心漂移量）；状态演进必须显式记录所用配置版本与批内容指纹。
4. 实现基于参考分位数的漂移裁决：以本地参考分位数表为唯一真值来源，对当前密度曲线与参考曲线计算分布比对得分，按可配置阈值与至少两档置信水平裁决本批是否漂移，输出得分、阈值、参与比对的分位数索引范围与裁决依据；参考表缺失或分位数索引越界须返回 E_REFERENCE_MISSING。
5. 实现数值精度与误差传播控制：簇心归一化与密度累加全程在缩放定点域或对数域执行，禁止直接累加未缩放的原始概率密度；对每个批次的簇心与密度曲线给出与本地高精度参考累加比较的误差上界与有效位数，误差界必须由显式缩放因子与分块求和顺序推导，推导依据随结果保留。
6. 实现批次粒度的 SQLite 事务检查点与优雅停止恢复：每批完成簇心合并与漂移裁决后以事务写入含批号、输入分片内容指纹、配置版本、状态摘要与单调序号的记录，同一批只允许一条有效记录；收到停止请求时完成当前不可拆分的批次单元后退出，强制终止后仅凭已提交事实恢复，恢复后状态须与一次连续运行逐字节一致。
7. 实现版本变化检测与增量失效传播：当某批样本内容、带宽估计规则、分块大小、求和策略、漂移阈值或参考分位数表任一变化时，通过各阶段内容摘要构成的版本指纹识别受影响的最早批次，使该批及其后续所有批次的状态与裁决失效重建，未受影响的上游批次状态继续复用；增量重建结果须与从零全量运行逐字节一致。
8. 实现并发状态发布保护与稳定业务错误码：多工作进程对同一 SQLite 库发布批次状态时使用事务条件更新与真实文件锁并比较批内序号，仅允许序号连续推进，落后、重复或跨批错位发布返回 E_STALE_CHECKPOINT 并附当前生效批号；请求缺失前置阶段产物或非法阶段跳转须返回对应业务码而非静默继续。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地批次样本验证聚类与密度演进、漂移裁决、增量重建与中断恢复的一致性，并检查异常注入的业务码。
