为 LLM 推理采样团队从零构建一个本地可运行的拒绝采样解码组件与完整示例，核心问题是解码策略的可复现验证与入参驱动的异常注入。输入是本地样本目录：一份词表 JSON，含 token id、token 文本与固定维度 logit 偏置向量；一份解码任务清单 JSONL，每条含 task id、提示 token 序列、最大新生成 token 数、温度、top-k、top-p、随机种子与拒绝采样规则（每步候选数、接受温度差上限）；一份外部 logits 文件，为每个 task 每步给出整词表上的 logit 向量（float64 JSON 数组），用于替代真实模型输出以保证结果可复现；一份期望摘要文件，记录部分 task 在固定种子下的期望 token 序列摘要。组件需完成温度缩放、top-k/top-p 截断、基于种子的确定性采样与拒绝接受判定，输出逐 token 序列、每步候选明细与整段序列摘要，并支持按声明阶段注入异常以验证流程稳定复现。工作区为空，需自行初始化项目。

任务环境与准备：
安装 Python 3.11 或以上版本，并在隔离的虚拟环境中安装 numpy 与 fastapi，安装说明须写入项目 README 供复现。
本地准备样本目录，包含词表 JSON、解码任务清单 JSONL、外部 logits JSON 文件与期望摘要文件，数据由确定性脚本或手工生成，不依赖真实模型与网络。
确认 SQLite 可用（Python 标准库自带 sqlite3），并在 Windows 下验证可写入本地结果目录与临时目录。
提供启动本地服务的命令与可直接用 curl 复现的请求示例，固定随机种子与注入配置以保证演示结果可重复。

业务要求：
1. 组件须提供解码入口，接收样本目录、任务清单、logits 文件、解码配置与异常注入配置，校验 task id 唯一、温度为正有限实数、top-k 为正整数、top-p 位于开区间 (0,1]、种子为非负整数、每步候选数为正整数，任一非法返回 E_PARAM 并指出出错文件与行号，且不创建任何结果文件或临时目录。
2. 采样须基于种子与步数派生确定性随机数，逐 task 按步序号升序推进；同一输入、配置与种子下逐 token 输出、每步候选集合与采样值必须逐位一致，不得依赖字典遍历顺序、系统时间或全局随机状态，温度缩放须在对数域进行以避免下溢或除零。
3. top-k 与 top-p 截断须先按 logit 降序、同分按 token id 升序稳定排序，再保留前 k 个并按累积概率达到 p 为止的核集截断；截断后须重新归一化并输出每步保留 token、缩放后概率与累计质量，截断使核集为空或累计质量非有限时返回 E_DECODE 并定位 task 与步号，不得静默退回全词表采样。
4. 拒绝采样须对每个候选 token 依据规则与接受温度差上限做接受判定：接受概率须由候选概率与参考温度下概率的比值确定，被拒候选须在候选明细中记录拒绝原因与比值；某步全部候选被拒时须按规则在同一随机流上继续尝试并设上限，超过上限返回 E_REJECT 并给出 task、步号与实际尝试次数，不得丢弃该 task 其余结果。
5. 须与期望摘要文件逐 task 核对：按 task 粒度比较生成 token 序列摘要与期望摘要，不一致时返回 E_TRACE 并给出 task id、首个不一致的步号与两侧 token；期望摘要缺失、摘要格式错误或引用了清单中不存在的 task 时须返回 E_TRACE 并指出位置，核对结论须在结果中逐 task 标注。
6. 异常注入须在声明阶段按声明方式制造四类故障之一：logits 维度与词表不符、温度非法、采样值越界或期望摘要损坏，每类注入须给出确定的失败点与业务码 E_INPUT、E_PARAM、E_DECODE 或 E_TRACE，并含 task 与步号定位；未注入故障时任何阶段不得出现上述业务码，注入结论须可在结果中逐 task 查询。
7. 解码进度与结果须在 SQLite 中以 task、阶段、步三级记录事务提交，单步候选明细摘要、采样结果与步进度须在同一事务中写入；结果文件先写临时文件再原子替换并登记内容哈希，某 task 某步失败时该 task 整体回滚且其余已提交 task 状态不变，不得留下半写结果文件或与快照版本不一致的记录。
8. 每次完成须以整体替换方式生成版本化快照，含配置指纹（解码配置与注入配置的内容哈希）、逐 task 生成摘要与结果文件内容哈希；读取快照时若检测到数据库版本与磁盘结果文件哈希不一致、配置指纹变化或残留旧版本结果文件，须返回 E_STALE 并定位到 task 与文件；进程被强制终止后重启须从已提交步进度继续，重算未提交步且不重复消费已提交步，恢复后的逐 token 序列与快照版本序列须与无中断执行完全一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证确定性解码、截断、拒绝采样、异常注入业务码与中断恢复一致性，附运行结果。
