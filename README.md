当前是空白工作区，需从零构建一个本地可运行的 OCR 文字检测与识别领域可视化诊断工作台，核心是在数据规模变化下做检测与识别的算法取舍。输入为固定随机种子生成器产出的本地确定性图像分片（小尺寸 RGB PNG，含多行文字色块、不同字体大小与倾斜角）以及一份 JSON 任务清单，清单逐分片声明宽高、真值文本框（归一化坐标与文本内容）、语言标签与 image_id，并附三档规模分组（小档约 4 个分片、中档约 16 个分片、大档约 40 个分片），每组声明分片数与总字符数作为观测依据。工作台需执行四个阶段：文本检测（基于连通域投影与可配置合并规则产出候选框）、检测与识别候选的算法预算决策（依据分片规模、字符数、可用预算在三档检测策略与三档识别策略间取舍并记录理由）、文本识别（基于本地确定性模板匹配或哈希词袋的简单分类，不依赖真实 OCR 模型、GPU 或外部服务）、诊断聚合（统计检测召回率、识别准确率、各档策略命中与预算消耗）。工作台须支持阶段检查点、优雅停止恢复、版本变化后的增量失效传播、并发发布保护，并提供本地 HTTP 与命令行可视化诊断接口。

任务环境与准备：
安装 Python 3.10 及以上版本，并通过 pip 安装 numpy 与 Pillow；无需 GPU、真实 OCR 模型或外部服务。
在空工作区创建项目目录结构，预留 samples 目录存放确定性生成器产出的 PNG 分片与 JSON 任务清单。
确保本地可启动 HTTP 服务端口，并提前准备分布式文件锁所需的工作区目录与权限。

业务要求：
1. 实现文本检测阶段：对每个分片先做灰度化与二值化，再以可配置的字符级连通域与行投影合并规则产出候选文本框，输出归一化坐标、置信度与来源策略；同一输入与配置必须产生逐字节一致的候选框清单，候选框越界或宽高为零须返回带 image_id 与框序号的 E_DETECT_INVALID 并保留在诊断输出中。
2. 实现文本识别阶段：对每个候选框依据真值文本字符集合构造本地确定性模板库，以像素归一化后的哈希词袋最近邻方式输出识别文本与置信度，并记录每候选的匹配距离与所用模板量；当模板库为空、候选框尺寸与模板尺寸不匹配或距离出现 NaN 时返回带候选标识的 E_RECOGNIZE_INVALID，禁止静默给出空文本。
3. 实现基于数据规模的策略取舍：依据分片规模档、总字符数、候选框数与可配置的检测与识别计算预算，在检测侧与识别侧各三档策略中选择组合，并记录选择理由、候选打分明细、被淘汰策略与理由；小档须避免选用为大档设计的重策略，且任一策略启用时预算消耗不得超过配置上限。
4. 实现诊断聚合与指标统计：按分片与规模档计算检测召回率、识别准确率、平均匹配距离、预算消耗与策略命中分布，并给出与样本规模相关的误差带估计；指标须依赖清单真值与显式候选结果，不得从缺失信息推断，同输入与配置下的诊断摘要须逐字节一致。
5. 实现持久化阶段检查点与优雅停止恢复：每分片每阶段完成时以原子方式写入含阶段名、image_id、输入内容指纹、配置版本、产物摘要与单调序号的记录，写入任意位置中断不得留下半写记录；收到停止请求时完成当前不可拆分分片单元后退出，不承诺强制终止后生成退出报告；恢复后最终候选框、识别文本与诊断摘要必须与一次从零完整运行的输出逐字节一致。
6. 实现版本变化检测与增量失效传播：当分片像素内容、清单真值、二值化参数、合并规则、模板库或预算配置任一变化时，通过各阶段内容摘要构成的版本指纹识别受影响的最早阶段，使该阶段及其全部下游产物失效并重建，未受影响上游产物继续复用；失效原因与版本指纹须在查询接口中可观测，且增量结果须与从零全量构建逐字节一致，不一致时返回 E_INCREMENTAL_MISMATCH 并给出差异摘要。
7. 实现并发发布保护与稳定业务错误码：多个工作进程对同一工作区发布阶段产物时使用文件锁并比较分片内序号，仅允许序号连续推进，落后、重复或跨分片错位发布须被拒绝并返回 E_STALE_CHECKPOINT；请求非法阶段跳转或缺失前置阶段产物时返回 E_INVALID_STAGE，不得部分写入或覆盖已发布产物。
8. 提供本地 HTTP 与命令行可视化诊断工作台及确定性演示：支持导入分片与清单、触发分阶段执行、查询各阶段状态与版本指纹、查看策略取舍理由与诊断报告、请求停止、执行恢复、导出候选框与识别结果；演示数据至少覆盖小档与中档、含中英混排与倾斜文本，一次完整运行生成固定摘要，并演示一次停止后恢复与一次非法阶段请求的错误码。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地三档样本运行检测、取舍与识别全流程，验证诊断指标、停止恢复与版本失效行为一致。
