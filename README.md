为文生图与图像编辑团队从零构建一个本地可运行的生成式图像编辑作业服务，核心问题是编辑结果的可复现验证与故障异常注入下的稳定复现。工作区为空，需自行初始化项目。输入是本地样本目录：一份编辑作业清单 JSONL，每条含 job id、基准种子、宽高与尺寸步长、一组编辑指令（指令类型 inpaint、outpaint 或 restyle，区域掩码以像素矩形表示，局部提示词与局部种子）以及生成时的元数据声明（种子、采样步数、引导强度与噪声等级）；一份参考结果目录，存放与作业对应的期望结果摘要文件。图像合成采用本地确定性伪渲染器：由提示词与种子的哈希派生低频噪声场，按掩码区域回填并叠加到父图，输出以固定格式的像素文件与摘要哈希登记。服务需支持作业创建、分阶段执行、结果校验与故障注入，并保证在不注入故障时重复执行的结果逐字节一致；注入故障时必须按声明返回业务码且状态可恢复。

任务环境与准备：
安装 Python 3.10 或以上，创建本地虚拟环境并用 pip 安装 fastapi、uvicorn、numpy 与 pytest，版本以满足题目所述接口为准，全部来自本地已缓存或可离线获取的 wheel。
在工作区内准备样本目录：编辑作业清单 JSONL、参考结果目录中的期望摘要文件与基准尺寸配置，使用固定种子与固定尺寸集合以保证可重复。
确认 SQLite 由 Python 标准库提供且工作目录可写，用于作业状态库、快照与像素文件落盘；准备一个可用的本地端口用于 FastAPI 服务。
准备进程强制终止的验证方式（在本地测试中模拟终止后重启同一服务），并准备一份固定作业与故障注入序列用于演示入口。

业务要求：
1. 服务须提供作业创建接口，接收样本目录、编辑作业清单、参考结果目录与故障注入配置，校验 job id 唯一、种子与局部种子为整数、宽高为目标尺寸步长的整数倍、引导强度与噪声等级为有限实数、注入配置指向合法故障类型与目标阶段；任一非法返回 E_PARAM 业务码并指出出错文件与行号，不得创建任何结果文件、临时目录或作业状态。
2. 须实现确定性伪渲染器：由局部提示词、局部种子、掩码矩形与作业基准种子共同派生低频噪声场，按掩码区域回填并逐像素叠加到父图；同一作业在任何执行顺序、任何进程数与任何机器时钟下产出的像素文件必须逐字节一致，渲染器不得读取系统时间、全局随机状态或环境变量作为输入。
3. 编辑作业须按 validate_spec、render、verify、committed 四个阶段推进，阶段顺序不可跳步，乱序推进返回 E_STAGE 并给出当前阶段与已允许的下一阶段；重复调用已完成阶段须幂等返回已有结果与当前快照版本，不得重复渲染或重复写入作业记录。
4. 结果校验须按元数据声明核对：逐作业比较实际使用的种子、采样步数、引导强度与噪声等级是否与清单声明一致，不一致时返回 E_META 并指出 job id 与字段名；参考结果目录中的期望摘要按作业粒度逐条比对实际像素摘要，摘要不匹配返回 E_VERIFY 并列出 job id、期望摘要与实际摘要，禁止在存在不匹配时产出自愈或静默跳过的通过结论。
5. 故障注入须支持在指定阶段按声明方式制造失败：渲染阶段注入渲染中断、校验阶段注入摘要损坏、提交阶段注入写盘失败三类，每类注入须给出确定的失败点并提供业务码 E_INJECT 与定位信息；未注入故障时任何业务码都不得出现，注入故障时必须真实走对应代码路径，禁止以人为延迟或跳过阶段模拟失败。
6. 作业状态须以作业、阶段、作业分片三级记录在 SQLite 中提交，单个作业分片的渲染结果与阶段进度须在同一事务中写入；任一作业分片失败时该分片整体回滚，不得留下部分作业结果或与快照版本不一致的像素文件；提交完成后读取状态须返回一致的作业计数与阶段标记。
7. 每次阶段完成须以整体替换方式生成版本化快照，含作业版本号、各作业阶段结果摘要与像素文件内容哈希；读取快照时若检测到数据库版本与磁盘像素文件哈希不一致、版本变化或残留旧版本像素文件，须返回 E_STALE 并定位到具体作业与版本，禁止把残留旧文件汇入当前结果。
8. 进程被强制终止后重启，须从 SQLite 已提交的作业分片粒度继续，核对每个作业的阶段标记、像素文件内容哈希与快照版本，重算未提交作业分片且不重复渲染已提交作业；恢复后的逐作业像素摘要、校验结论、阶段标记与快照版本序列须与无中断执行完全一致，并须提供确定性本地演示入口输出可重复的作业计数、逐作业校验结论、注入失败定位与恢复前后一致性结论。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证编辑结果逐字节可复现、异常注入按声明返回业务码且中断恢复后结果一致。
