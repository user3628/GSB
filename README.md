为命名实体识别团队从零构建一个本地可运行的专业服务，核心问题是规则实体词典与类型规则增量更新后，已缓存的识别结果如何按依赖关系精确失效并在崩溃后保持一致。输入是本地样本目录：一份待识别文本清单 JSONL，每条含 doc id 与原始 UTF-8 文本；一份实体词典 JSON，含实体名、类型、别名字列表、优先级与是否区分大小写标记，并带词典版本号；一份类型规则文件，声明合法实体类型集合、类型间兼容关系与相邻实体类型的转移权重。服务需给出实体区间、类型、逐实体置信度，并在更新后只重算真正受影响的文档。工作区为空，从零创建项目。

任务环境与准备：
安装 Python 3.11 及以上版本，并用 pip 安装 fastapi、uvicorn、numpy、httpx 与 pytest，版本锁定在本地虚拟环境中。
在项目根目录创建本地样本目录，准备文本清单 JSONL、带版本号的实体词典 JSON、类型规则 JSON 与一组覆盖重叠命中、别名冲突与不兼容类型的样本。
预先确定 SQLite 数据库文件、结果分片目录与快照目录的本地路径，确保运行用户对目录有读写权限并清理历史文件。
准备可通过 curl 或 httpx 复现的请求脚本，包含作业创建、词典增量更新、快照读取与进程强制终止后重启的恢复调用顺序。

业务要求：
1. 工程创建接口接收文本清单、实体词典、类型规则文件与匹配参数，校验 doc id 唯一、实体名非空、别名不与实体名相同、类型规则声明合法类型集合、匹配窗口为正整数；任一非法返回 E_PARAM 业务码并指出出错文件与行号，且不创建任何结果文件或临时目录。
2. 识别输出须按起始字符下标升序排列，区间按 Unicode 字符计数而非字节，同一区间被多个实体名或别名命中时先按匹配长度降序、再按优先级降序、同分按实体名字典序稳定选择；重叠区间须被消解并记录被抑制的候选数。
3. 类型修正须基于类型转移权重做确定性序列解码，输出每实体一个类型；实体名命中但类型不在声明集合中或相邻两实体类型被声明不兼容时，须按权重选择合规替代类型并记录被修正实体的区间与原类型，修正不得使整篇文档失败。
4. 每个实体须附带置信度，定义为该实体全部命中候选与类型候选上的归一化后验，用 log-sum-exp 在 float64 下计算并在文档范围内构成有效概率分布；归一化误差超配置容差时返回 E_PRECISION 并定位 doc id，不得输出残缺结果。
5. 词典须支持新增实体、修改别名列表、调整优先级与修改是否区分大小写四类增量更新并推进词典版本号；更新时须按实体名与类型到文档的依赖关系计算受影响文档集合，只重算真正引用了变更实体名或受影响类型的文档。
6. 失效判定须精确到依赖粒度：未命中任何被更新实体名且已产出实体的类型未受规则变更影响的文档不得重算；诊断报告须区分被失效评估但结果未变与实际重算两类文档，给出各自计数与 doc id，并说明每篇文档的失效原因。
7. 识别进度与结果须在 SQLite 中以文档粒度事务提交，结果以原子替换写入不可分割的分片文件并登记内容哈希；进程被强制终止后重启须核对分片哈希与提交标记，重算未提交文档且不重复消费已提交文档，并发写同一分片须串行化。
8. 每次更新或完整识别须整体替换生成版本化快照，含词典版本号、各文档实体摘要与分片哈希；读取快照时若检测到数据库记录与磁盘分片哈希不一致、词典版本变化或残留旧分片，须返回 E_STALE 并定位到文档与分片。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证实体识别、词典增量更新后的精确失效与中断恢复一致性，附可重复演示结果。
