当前是空白 Windows 工作区，需要从零构建一个面向本地可观测性数据的日志与追踪采样协调应用，供 SRE 团队在离线数据集上评估采样策略，并保障采样状态在进程中断后仍可恢复。应用接收带毫秒时间戳的本地确定性样本：日志记录（服务名、级别、消息指纹、关联追踪标识）与追踪跨度记录（追踪标识、跨度标识、父跨度标识、服务名、延迟微秒、错误标志、采样权重）。采样策略以带单调版本号的 JSON 快照提交，包含按服务与级别的分层采样率、尾部采样规则（延迟阈值与错误放大）、去重窗口与偏置校正开关。应用需维护采样决策、分层计数与偏置校正估计在 PENDING、SAMPLED、DROPPED、EMITTED 之间的演进，按快照版本重建派生状态，并在进程被强制终止后依据 SQLite 持久化事实恢复一致状态，输出可与本机朴素采样结果核对的偏置报告。所有数据均来自本地样本文件，不依赖真实账号、线上服务或外部采集系统。

任务环境与准备：
确认已安装 Python 3.11 或以上版本，并在工作区创建虚拟环境。
在虚拟环境中安装 FastAPI、Uvicorn、NumPy 与 pytest，版本以可离线安装的本地包为准。
准备固定本地日志与追踪跨度样本文件、两份带版本号的采样策略快照及一份预期朴素采样结果，全部置于工作区 samples 目录。
确认 SQLite 可用（Python 标准库 sqlite3 即可），并预留工作区目录用于数据库文件与运行日志。
预先确定固定随机种子、去重窗口长度、误差上界与样本不足阈值，并写入策略快照与演示脚本参数中。

业务要求：
1. 实现日志与跨度样本的解析和批次入库：每行含毫秒时间戳、服务名、级别、追踪标识与跨度层级字段，非法行或时间戳非单调返回业务码 E_RECORD_INVALID 且整批不入库；合法记录以批次标识加行内序号幂等，内容不一致返回 E_CONFLICTING_RECORD。
2. 实现带版本号的采样策略快照与分层采样决策：快照含单调递增版本号、生成时间、分层采样率、尾部采样规则与整体校验摘要，提交时版本号不大于当前版本返回 E_STALE_SNAPSHOT；决策须由快照版本、固定种子与记录序号共同确定，同输入重复决策逐条一致。
3. 实现尾部采样与头部采样的协同：先按分层采样率做头部决策，再对已抽样记录依据延迟阈值与错误放大规则做尾部保留或提升，须明确两条路径的优先级与冲突裁决；被提升记录的权重须随之调整，禁止出现提升后权重仍沿用头部采样值。
4. 实现分层计数与偏置校正估计：各服务各层按采样权重计算命中数、加权估计总量与估计偏差，加权求和使用 Kahan 补偿求和并输出可量化误差上界；未抽样层不得以零计数冒充，样本不足时返回 E_INSUFFICIENT_SAMPLES 而非静默给出估计值。
5. 实现去重窗口与关联追踪的跨模块一致：同一追踪标识在去重窗口内的多次出现只计一次，去重窗口边界包含关系与时戳精度须显式定义；日志与跨度两侧的去重结果、分层计数与偏置报告须读取同一策略版本，禁止出现跨度已计入而日志计数仍为旧值的中间可见状态。
6. 实现单写者决策提交与多读者查询的并发一致：采样决策、计数与偏置报告按策略版本单写者串行提交，多个只读查询可并发读取某一完整提交版本；同一批次重复触发只执行一次、其余等待并复用结果；查询不得看到部分记录已 SAMPLED 而计数尚未累加的中间状态。
7. 使用 SQLite 持久化策略版本、记录决策、分层计数与意图日志，写操作先落意图记录再提交事务；进程在决策或偏置重算中途被强制终止后重启须扫描未完成意图，把决策回滚到最后一个完整版本或把批次标记为已中止，恢复报告只包含已落盘事实，不得承诺强制终止后仍生成完整退出报告。
8. 提供本地 HTTP API 与可重复演示脚本：API 覆盖策略提交、样本批次提交、按服务与级别查询采样率与偏置报告、恢复报告查询，失败响应统一为含业务码的 JSON（至少覆盖 E_RECORD_INVALID、E_STALE_SNAPSHOT、E_INSUFFICIENT_SAMPLES、E_CONFLICTING_RECORD）；脚本用固定样本完成全量决策、策略升版后重算、一次强制终止后恢复，输出偏置对比与恢复前后状态差异。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地固定样本验证分层与尾部采样决策、偏置估计一致性与强制终止后的恢复结果。
