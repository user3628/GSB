某平台团队正在把多集群配置分发的收敛逻辑整理成一个可集成的 Go 领域组件，工作区目前仅有这份需求说明。平台维护若干目标集群及其上的配置对象，每个对象声明标识、类别、命名空间、期望字段集合、实际字段集合、字段来源标记、依赖的其他对象与资源预算。配置以带单调递增版本号的 JSON 快照提交，收敛策略快照声明漂移判定容差、批次规模上限、单轮时间预算与重试上限。组件需为每个对象判定漂移类别并生成带依赖约束的收敛批次，在本地回环测试端点上真实执行写回并回读核对。增量片段只含受影响对象，其引发的级联失效与批次重排必须在同一事务边界内原子完成，进程被强制终止后须依据 SQLite 中的持久化事实恢复一致状态。

任务环境与准备：
安装 Go 1.22 或更高版本，并确保 go 命令在 PATH 中可用，无需第三方模块下载，使用标准库与内置 SQLite 驱动或本地依赖。
准备本地确定性 JSON 样本目录，包含集群对象、收敛策略快照与增量片段，以及用于写回核对的本地回环 HTTP 测试端点。
在 Windows 上执行 go build 与 go test，并通过本地命令行脚本驱动组件完成一次全量收敛与一次强制终止后恢复演示。

业务要求：
1. 实现集群对象、收敛策略快照与本地确定性 JSON 样本的解析和归一化：对象声明标识、类别、命名空间、期望与实际字段集合、字段来源标记、依赖对象列表与资源预算，策略快照携带单调递增版本号、生成时间、漂移判定容差、批次规模上限、单轮时间预算、重试上限与整体校验摘要；解析与服务启动时校验对象标识唯一、依赖引用存在、资源预算非负并做溢出检查，失败返回业务码 E_SPEC_INVALID 且不加载任何对象。
2. 实现漂移判定核心：逐字段区分字段缺失、字段多余、取值偏移与来源冲突四类漂移，数值字段按策略声明的相对容差做定点比较而非裸浮点比较，同一对象命中多类漂移时按声明的稳定优先级给出主类别并保留全部命中明细；输出每个对象的漂移类别、受影响字段与判定依据，输入或参数注入残缺字段集合时不得崩溃或静默收敛。
3. 实现依赖约束下的收敛批次组织：被依赖对象所在批次序号严格小于依赖者所在批次，依赖出现环时返回 E_DEPENDENCY_CYCLE 并附环上对象标识，环外对象仍须给出分层结果；批次规模受策略上限与对象资源预算约束，超限时拆分批次而非丢弃对象，拆分产物须标明所属原批次与拆分序号。
4. 实现带版本号的整份快照提交与增量片段提交及版本绑定：增量片段只含受影响对象并携带基础版本，基础版本不是当前已提交版本时返回 E_STALE_BASE 且不改变任何已提交状态；同一基础版本的两个并发增量只允许一个成功、另一个必须收到 E_STALE_BASE；整份快照整体替换时识别版本变化，校验失败必须保持旧快照完全可用。
5. 实现向本地回环测试端点的真实写回与回读核对：每次写回具备独立超时，超时后必须真实关闭底层 HTTP 连接并释放其占用的并发名额，返回 E_WRITE_TIMEOUT；写回成功后回读实际字段集合并重新判定漂移，回读结果与写回声明不一致时返回 E_APPLY_MISMATCH 并附对象标识、期望与实际字段集合。
6. 实现单轮时间预算与并行写回批次的并发约束，并保证派生产物的级联失效：写回受每轮时间预算与最大并行批数约束，超并行上限的批次进入有界等待队列，队列满返回 E_WRITE_QUEUE_FULL；对象字段、依赖边或批次划分变化时，其漂移结论、批次归属与收敛汇总必须级联失效并在同一事务边界内原子重建，禁止出现部分产物已更新而其它仍为旧值的中间可见状态。
7. 实现单写者提交与多读者查询的并发一致及幂等复用：快照提交、增量提交、批次组织与写回推进按单写者串行执行，多个只读查询可并发读取某一完整提交版本；同一批次标识重复提交只执行一次、其余等待并复用同一结果，内容不一致时返回 E_CONFLICTING_REQUEST；查询不得看到某对象已回读通过而批次状态仍为待写回的混合状态。
8. 实现基于 SQLite 的意图持久化与强制终止后恢复：快照提交、批次组织与写回前先写意图记录再提交事务；进程在批次组织或写回中途被强制终止后重启须扫描未完成意图，把未提交写回回滚为待写回、把快照切换标记为已中止，恢复报告只包含已落盘事实并说明恢复边界，不得承诺生成退出报告。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
