团队准备新建一个项目，为内部协议安全实验室构建一个面向自定义二进制通信协议的模糊测试工作台。该协议为请求/响应式状态机：连接以握手报文开始，随后在认证、就绪、传输、关闭四个状态间迁移，每种状态只接受特定类型的报文，报文由类型字节、变长负载与校验字段构成。实验室维护一组种子用例与变异算子，每次迭代会基于上一版用例集增量产出新用例，并可能删除或修改部分种子，从而引发依赖失效——例如某个变异算子引用的种子被删除，或某条路径覆盖断言依赖的报文模板被修改。工作台需维护带版本号的用例集与执行快照，在本地确定性被测服务上回放用例并诊断哪些用例因依赖失效而不再可执行、哪些状态迁移覆盖因用例集变化而丢失，同时支持并发执行与外部参数注入异常。

任务环境与准备：
安装 Go 1.22 或以上版本（Windows 安装包或压缩包解压后配置 PATH），执行 go version 确认可用。
准备 SQLite 驱动：在项目 go.mod 中引入纯 Go 的 modernc.org/sqlite，执行 go mod download 预取依赖，不依赖 CGO 与本地 SQLite 服务。
确保本地回环端口可监听且未被防火墙拦截，被测模拟协议服务仅绑定 127.0.0.1 的临时端口。
在新建工作区根目录初始化 Go 模块，预留 data 与 report 子目录用于确定性样本与报告输出，所有样本由程序内置生成器产出，不依赖外部下载。
确认 Windows 命令行可执行编译产物，进程强制终止验证使用任务管理器或 Stop-Process 模拟。

业务要求：
1. 实现自定义协议状态机的报文解析与迁移裁决核心：按协议定义解析类型字节、变长负载与校验字段，维护握手、认证、就绪、传输、关闭五状态迁移表，对非法状态下的报文返回 E_ILLEGAL_TRANSITION，对校验失败返回 E_BAD_CHECKSUM，对负载长度越界返回 E_PAYLOAD_OVERFLOW，并记录迁移轨迹与停留状态。
2. 实现种子用例集与变异算子的增量更新引擎：用例集由种子报文模板、变异算子引用与路径覆盖断言组成，变更集包含新增、修改、删除三类操作；应用须在单个 SQLite 事务内完成并生成递增版本号快照，旧版本整体保留可回放；应用前后须输出受影响用例与算子的差异摘要。
3. 实现依赖失效闭包计算与诊断：沿变异算子对种子模板的引用、路径断言对报文模板的引用建立依赖图，对每次删除或修改操作反向追踪直接失效与传递失效的用例集合；引用缺失标记 E_DEP_INVALIDATED，循环依赖标记 E_DEP_CYCLE，失效闭包须给出每项失效的根因链与版本号。
4. 实现本地确定性被测服务与用例回放：在独立本地监听端口上启动模拟协议服务，按状态机规则对回放报文给出确定性响应或错误；回放须记录每用例的状态迁移序列、覆盖到的迁移集合与最终业务码，同一用例集与目标版本重复回放结果字节级一致，不得依赖随机因素或墙钟。
5. 实现带版本号的执行快照与整体替换识别：每完成一轮用例回放后在单个 SQLite 事务内提交递增版本号快照，记录执行结论、迁移覆盖集合与用例集版本；快照内容比较须识别整体替换式版本变化而非仅比对版本号；加载时校验版本链连续性，发现跳号返回 E_SNAPSHOT_VERSION 并回退到最近连续版本。
6. 实现并发回放调度与资源控制：多个用例批次可在独立会话中并发回放，会话间状态隔离；并发度与单会话用例数上限可配置，超并发上限的批次进入等待队列而非直接拒绝，单会话用例数超限时以 E_CASE_BUDGET 终止该批次并保留已执行用例结论；在途会话数须可观测。
7. 实现强制终止后的恢复一致性与异常注入验证：回放或快照提交过程中进程被强制终止后重启，依赖 SQLite 已提交事务恢复用例集版本与执行进度，已提交批次不回退、未提交批次整体丢弃并重新回放；通过外部参数构造种子引用缺失、算子循环依赖、校验篡改报文、快照版本跳号与并发批次竞争五类样本，分别断言对应业务码与快照版本未被推进。
8. 提供领域可视化诊断工作台与确定性报告：以子命令方式支持查看当前用例集版本、按版本回放失效闭包、展示迁移覆盖矩阵与单条用例的依赖溯源链；导出 JSON 报告包含快照版本链、受影响用例、迁移覆盖变化、回放业务码与失效根因，报告按用例标识与业务码稳定排序，时间字段只使用固定采样标记，重复运行且输入不变时字节级一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地确定性样本验证增量更新、依赖失效闭包、并发回放与快照恢复，并输出字节级可重复的 JSON 诊断报告。
