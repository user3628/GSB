工作区目前是空的，评审方希望先看到一个可完整演示的掩码工程标注修订工作台，而不是只跑一次转换脚本。业务对象是全景分割标注在多人协作下的修订历史：固定种子生成器在本地产出小尺寸索引色 PNG 与配套 JSON 修订日志，日志按修订号记录每次对某个分片掩码的编辑动作（区域重涂类别、区域改判实例、区域置为忽略、撤销上一修订），并附清单结构版本 v2 与旧版 v1（动作以自然语言短语描述、实例改判不带目标段号、置信阈值为整数百分比）。工作台需要把修订序列逐条重放到内部全景模型（像素级段 id 图与段属性表）上，回答任意历史修订点的掩码快照与差异来源，并在新修订到达后只重建受影响区域。

任务环境与准备：
安装 Go 1.22 及以上版本，确认 go version 与 go env GOPATH 可用。
全部样本、修订日志与清单由程序内置固定种子生成器在本地临时目录产出，不依赖网络、外部数据集或附件。
SQLite 使用纯 Go 驱动随模块依赖引入，执行 go mod tidy 后本地构建，无需系统级安装。
在 Windows 空白目录初始化模块并保留本地 HTTP 端口与命令行入口，运行前清理临时产物与数据库文件。

业务要求：
1. 实现修订动作解析与内部全景模型的逐条重放：把区域重涂、区域改判实例、区域置为忽略、撤销上一修订四类动作解析为带区域范围与目标段号的结构化操作，按修订号顺序在像素级段 id 图与段属性表上重放，每次重放产出可寻址的修订点快照；同一日志与同一初始分片必须产生逐字节一致的重放轨迹与各修订点摘要。
2. 实现旧版修订日志结构的兼容解析与显式升级：v1 动作以自然语言短语描述、实例改判缺少目标段号、置信阈值为整数百分比，导入时按可配置短语映射解析动作类型、按邻域段号推断改判目标、换算百分比阈值，并在结果中逐条标注推断依据与不可恢复动作；升级后应能导出为 v2 日志并重新导入得到同一重放轨迹。
3. 实现修订点之间的差异归因与掩码快照查询：给定两个修订号，输出差异像素集合、受影响段清单、每段的类别与实例序号变化来源，并指出是哪个修订动作首次造成该差异；当查询的修订号超出已重放范围或指向被撤销的修订时，返回带修订号与原因的业务码而非返回近似结果。
4. 实现撤销动作的语义裁决与段编号回收：撤销只回退最近一个未被撤销的修订，被撤销的修订及其派生的实例段号须按可配置策略回收或作废并在段属性表中留痕；连续撤销、撤销不可撤销的初始状态、撤销后在中间修订点插入新修订产生分叉这三种情形必须各有确定性裁决与可追溯记录。
5. 实现区域重放的数值与像素一致性约束：重放过程中每次区域操作后段属性表的像素总数须与该段 id 图逐像素统计一致，重叠区域按可配置后写覆盖或先写优先策略裁决；当区域越界、段号指向不存在的段或像素统计出现偏差时，返回带分片标识、修订号与首个差异像素坐标的业务码。
6. 实现 SQLite 事务化的修订检查点与强制终止恢复：每个修订重放完成时以事务写入修订号、输入分片指纹、日志版本指纹、段属性表摘要与单调序号的记录，同一分片同一修订号只允许一条有效记录；进程被强制终止后仅凭已提交记录恢复重放进度，恢复后的修订点快照与一次连续重放逐字节一致，且不承诺生成退出报告。
7. 实现日志整体替换识别与新修订的增量失效传播：当修订日志被整体替换、某修订动作内容被编辑或初始分片被重传时，通过各阶段内容摘要构成的版本指纹区分正常追加、整体替换、回退与分叉四种情形，使受影响的最早修订点及其下游快照失效并重建，未受影响的更早修订点继续复用。
8. 实现并发修订发布互斥与确定性子代理演示：多执行进程对同一分片发布修订快照时使用事务条件更新与真实文件锁并比较修订号，仅允许连续推进，落后、重复或跨分片错位发布返回 E_STALE_CHECKPOINT；提供本地 HTTP 与命令行入口，演示数据至少 4 个分片、含 v1 日志、连续撤销与分叉场景，一次完整运行产出固定摘要。
