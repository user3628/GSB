当前为空工作区，需从零构建一个本地可运行的多路召回自适应融合实验台，面向搜索与推荐场景做数据规模变化下的算法取舍。输入为固定随机种子生成的本地 JSONL 样本：一组物品库（item_id、类目、若干隐因子数值特征）与一组查询（query_id、原始查询词、locale、channel、历史点击类目序列），另附一份 YAML 融合配置，描述三路召回来源（词法倒排召回、类目协同召回、向量近邻召回）各自的候选深度、融合权重策略、去重规则、排序截断位以及全局候选评估次数预算与单路配额。样本分三档规模（小档约 200 物品、中档约 2000 物品、大档约 12000 物品），并附分档清单声明每档文件、物品数、查询数与期望候选深度，作为规模观测来源。三路召回的候选结果必须经可配置融合策略合并为最终排序，且每档规模的召回深度与路数取舍需依据预算自动决策。系统还需支持中断恢复、版本失效传播与并发发布保护。

任务环境与准备：
安装 Python 3.11 与 NumPy 1.26（pip 安装即可），不引入任何在线服务或 GPU 依赖
准备本地样本生成脚本，以固定随机种子产出三档物品库、查询与分档清单 JSONL 文件
准备一份默认融合配置 YAML，含三路候选深度、权重策略、去重规则、全局预算与单路配额示例值
确认可在本地启动 HTTP 服务端口用于交互接口，无需外部网络

业务要求：
1. 实现三路召回核心：词法倒排召回按查询词与物品文本的词项重叠打分，类目协同召回按历史点击类目的物品频次打分，向量近邻召回按查询特征与物品隐因子的余弦相似度打分，三路各自返回按分数降序的候选及分数明细；空查询或物品库为空时返回稳定业务码 E_EMPTY_INPUT 并附查询标识，不得返回空结果伪装成功
2. 实现基于数据规模与预算的召回深度自适应取舍：依据物品数、查询数与全局候选评估预算、单路配额，为每档规模决定各路是否启用、候选深度与融合截断位，并记录选择理由、候选打分明细与被淘汰路原因；须保证任一路启用后其评估次数不超单路配额，且三路总和不超过全局预算，超预算情形须按规则降档而非静默截断
3. 实现可配置多路融合与去重：支持加权求和与倒数排名融合两种策略，同一物品被多路召回时须合并分数并记录来源各路的排名、分数与贡献，去重后结果不得出现重复 item_id；权重改变须改变融合排序并生成新的融合配置版本指纹，融合分数须在确定的浮点计算顺序下产生，避免并行归约引入顺序相关差异
4. 实现分档结果的可复现实验汇总：对每档规模批量执行召回与融合，统计每路命中数、融合后前十与参考标注的重合度、候选覆盖率与平均排名偏差，并按配置指纹与随机种子生成实验摘要；两次相同配置运行须得到逐字节一致的摘要，不同档位之间摘要不得互相污染
5. 实现持久化检查点与优雅停止恢复：每档按召回、融合、汇总三阶段完成时以原子方式写入含阶段名、档位标识、输入指纹、配置版本、产物摘要与单调序号的记录，写入任意位置中断不得留下半写记录；进程收到停止请求时完成当前不可拆分阶段后退出，不承诺强制终止后生成退出报告，恢复后最终摘要须与一次从零完整运行逐字节一致
6. 实现版本变化检测与失效传播：当物品库内容、查询内容、召回参数、融合权重或预算配置任一变化时，通过内容摘要构成的版本指纹识别受影响的最早阶段，使该阶段及其全部下游产物失效并重建，未受影响上游产物继续复用；检测到检查点记录被整体替换、序号回退或摘要不匹配时须区分并拒绝，返回 E_STALE_CHECKPOINT
7. 实现并发发布保护与稳定业务错误码：多工作进程对同一工作区发布阶段产物时使用文件锁并比较档位内序号，仅允许序号连续推进，落后、重复或跨档位错位发布返回 E_STALE_CHECKPOINT；请求非法阶段跳转或缺失前置阶段产物时返回 E_INVALID_STAGE；召回分数出现 NaN 或 Inf 时返回 E_NUMERIC
8. 提供交互接口与本地确定性演示：命令行与本地 HTTP 接口支持导入样本与分档清单、触发分阶段执行、查询各档状态与版本指纹、查看取舍理由与融合明细、请求停止、执行恢复、导出实验摘要；演示数据至少覆盖三个规模档、含跨路重复候选与中英混排查询，并至少演示一次预算注入与一次停止后恢复，验证恢复结果与完整运行一致

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地三档样本验证三路召回融合结果、预算取舍、增量失效与中断恢复的一致性，并输出摘要。
