当前为空白工作区，没有现存项目、代码或数据附件。需从零构建一个本地可运行的跨语言查询改写并行编排工作台，交付数据处理管线与结果验证工具。业务场景是：面向中英混排的搜索请求，系统需为每条查询并行生成多路改写候选（同义词替换路、字形近似路、跨语言桥接翻译路），再在有限改写评估预算下裁决采纳哪些候选，并按确定性规则输出改写后的查询集合。输入为固定随机种子生成器产出的本地 JSONL 查询分片（每条含 query_id、raw_query、lang、locale、channel 与可选点击历史词），以及一份 YAML 改写配置，声明同义词表规模、桥接词典版本、各路线候选上限、全局改写评估次数预算、单通道配额、并发通道上限与每请求延迟预算；另附一份分片清单声明每片行数与语料指纹，作为预算预估与一致性校验的显式观测。系统不依赖真实翻译服务、搜索引擎、GPU 或外部网络。工作台按四阶段推进：查询规范化与改写路派发、多路改写候选生成、预算约束下的并行编排与确定性归约、改写候选裁决与验证汇总。所有阶段状态需持久化，支持优雅停止后从最近一致检查点恢复，在输入或配置版本变化时使受影响阶段失效重建，且并行编排结果须与串行执行逐字节一致。

任务环境与准备：
安装 Python 3.10 及以上版本，确保标准库包含 json、hashlib、threading、http.server 等模块。
安装 NumPy 1.24 及以上版本，用于置信度合成与对数域数值计算，安装通过本地 wheel 或离线包完成。
无需 Docker、容器、GPU 或外部网络服务；所有查询分片、同义词表与桥接词典由本地固定随机种子生成器产出。
准备一个可写工作目录用于检查点、文件锁与阶段产物落盘，并确保进程对目录有读写权限。

业务要求：
1. 实现查询规范化与多路改写派发阶段：对 raw_query 做 Unicode NFKC、空白折叠、全半角统一与小写化，按中文单字与拉丁连续串切分并记录字符偏移，据此决定同义词、字形近似与跨语言桥接三路是否启用及各自候选上限；空查询或仅含标点时返回带 query_id 的 E_EMPTY_QUERY 并保留诊断上下文，同一输入与配置必须产生逐字节一致的派发计划。
2. 实现多路改写候选生成：同义路按本地同义词表替换词项并记录被替换偏移与词典条目版本，字形近似路以固定哈希生成近似码并检索同码词项，跨语言桥接路按桥接词典把查询词项映射到目标语言候选；三路均须输出候选改写文本、生成路径、置信度与生成依据，桥接词典缺少某词项时须以显式未知标记回退而非静默丢弃候选。
3. 实现预算约束下的并行编排调度：以查询为调度单元，在全局改写评估次数预算、单并发通道配额与并发通道上限三重约束下决定接纳顺序与并发度，并按每请求延迟预算约束单次编排时长；接纳前依据分片清单行数与各路线候选上限预估消耗，超预算查询记录为未处理并给出原因，保证任何时刻累计评估次数不超全局预算，超延迟返回带 query_id 与已耗时的 E_LATENCY_BUDGET 而非阻塞等待。
4. 实现并行执行与确定性归约：使用本地线程池并行处理已接纳查询，各查询的候选列表、置信度与采纳结果按 query_id 与候选生成路径排序位全局归约，使并行输出与单线程顺序执行逐字节一致；线程池不得以线程超时描述为已终止失控计算，工作线程异常须以结构化错误对象记录并保留已完成阶段产物。
5. 实现改写候选裁决与验证汇总阶段：按置信度、路线权重与与原查询的词项重叠度在对数域合成裁决分，在可配置采纳上限内选择候选并把被淘汰候选与其依据保留在诊断输出；同分须有确定性仲裁规则，采纳后改写文本为空或与原查询重复者须剔除并记录原因，汇总须按 lang 与 channel 分层输出采纳率与路命中分布。
6. 实现阶段检查点持久化与优雅停止恢复：每个查询按派发、候选生成、编排裁决、验证汇总四阶段完成时以原子方式写入含 query_id、阶段名、输入内容指纹、配置版本、产物摘要与单调序号的记录，写入任意位置中断不得留下半写记录；收到停止请求时完成当前不可拆分查询单元后退出，不承诺强制终止后生成退出报告，恢复后最终改写集与从零完整运行逐字节一致且检查点序号连续推进。
7. 实现版本变化检测与增量失效传播：当查询内容、同义词表、桥接词典、路线候选上限、裁决权重或预算配置任一变化时，通过各阶段内容摘要构成的版本指纹识别受影响的最早阶段，使该阶段及其全部下游产物失效并重建；未受影响上游产物继续复用，失效原因与版本指纹须在查询接口中可观测，禁止以旧指纹产物冒充新版本结果。
8. 实现并发发布保护、稳定业务错误码与本地演示：多进程对同一工作区发布阶段产物时使用真实文件锁并比较查询内序号，仅允许序号连续推进，落后、重复或跨查询错位发布返回 E_STALE_CHECKPOINT，缺失前置阶段产物或非法阶段跳转返回 E_INVALID_STAGE；命令行与本地 HTTP 接口支持导入分片与配置、查询各查询状态与版本指纹、查看预算消耗与未处理原因、查看裁决轨迹、请求停止与执行恢复，演示数据须含中英混排查询与分片间重复查询并演示一次停止后恢复的一致性比对。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
