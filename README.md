在空白 Windows 工作区中，需要从零构建一个面向本地回环环境的 VPN 隧道网关核心组件，交付可交互的专业应用与可重复演示。网关在一侧以本地 HTTP 服务接收入站请求，按带版本号的隧道与路由快照把请求封装为隧道帧，经本地 UDP 测试承载端转发到出口解封装端点，再把响应回传客户端。隧道帧含会话标识、通道序号、载荷字节数与校验摘要；同一会话的帧必须保持有序，不同会话可并行经由有限数量的隧道通道转发。运行中运维人员会提交只含局部改动的增量路由片段，改动会使该会话的通道绑定、出口端点与统计派生结果失效并需原子重建；进程可能被强制终止，重启后必须仅依据持久化事实恢复会话与通道租约，并输出恢复差异。难点在于并行通道调度与资源预算、增量更新与租约恢复三者互相牵制：预算收紧会改变帧的派发次序，增量改动又会令在途帧的出口绑定失效，恢复时不得把已发出的帧与新租约状态混用。

任务环境与准备：
确认 Windows 本地已安装 Python 3.11 及以上，并可在项目虚拟环境中安装 FastAPI、uvicorn 与 httpx。
预留本地回环端口用于网关 HTTP 服务、UDP 承载端与出口解封装测试端点，确保这些端口未被占用。
准备固定本地样本文件：隧道与路由快照、增量片段、多会话帧序列表与期望帧序，样本由任务自行生成且不含真实账号或外部网络依赖。
确保工作区可写，用于创建 SQLite 数据库、意图日志与演示输出目录。

业务要求：
1. 实现隧道与路由快照模型：快照含单调递增版本号、生成时间、会话到通道的绑定规则、出口端点地址与整体校验摘要；加载时校验版本单调与摘要，失败返回 E_SNAPSHOT_INVALID，且加载失败必须保持旧快照与现存会话完全不变。
2. 实现隧道帧的封装与解封装：帧含会话标识、通道序号、载荷字节数与校验摘要，封装后经本地 UDP 承载端真实发送到出口解封装端点并等待响应；序号解析失败、载荷超长或摘要不一致返回 E_FRAME_INVALID 且该帧不得发出，同一会话序号必须连续无缺口。
3. 实现并行通道调度器：通道池以固定并发通道数与每轮时间预算双重约束，预算内按会话优先级与到达顺序派发帧，超出通道数的帧进入有界等待队列，队满返回 E_CHANNEL_QUEUE_FULL；同一会话同一时刻只允许一帧占用通道，不同会话可并行转发。
4. 实现基于真实套接字的超时与释放：每帧转发具备独立超时，超时后必须真实关闭该 UDP 发送套接字或停止等待并标记该通道可复用，返回 E_TUNNEL_TIMEOUT，不得以等待冒充超时，也不得把异步超时描述为已终止底层传输。
5. 实现增量路由片段提交与级联失效：增量只含受影响的会话绑定或出口端点并携带基础版本，基础版本非当前版本返回 E_STALE_BASE 且不改动任何状态；受影响会话的通道绑定、出口端点与统计派生结果必须级联失效并在同一事务边界内原子重建，禁止出现部分会话已切换而统计仍计旧端点的中间可见状态。
6. 实现会话与通道租约持久化及强制终止后的恢复：租约记录会话标识、通道占用、已发未确认序数与最近活动时刻；帧派发与租约变更先写意图记录再提交，进程被强制终止后重启须扫描未完成意图，把已发未确认帧按持久化事实标记为待重传或已中止，恢复报告只包含已落盘事实，不承诺强制终止后仍生成完整退出报告。
7. 实现单写者派发与多读者查询的并发一致：通道租约授予、租约变更与增量重建按单写者串行执行，多个只读查询可并发读取某一完整提交版本；同一帧标识重复提交只允许派发一次、其余等待复用结果，内容不一致返回 E_CONFLICTING_FRAME；查询不得看到租约已释放而队列中仍留有该帧的中间状态。
8. 提供本地承载端测试服务、统一错误响应与可重复演示脚本：失败响应为含业务码与上下文的 JSON，至少覆盖上述业务码；脚本使用固定本地样本完成一次全量路由加载、一次多会话并行转发、一次仅改单会话出口的增量提交引发级联重建、一次通道耗尽排队与一次强制终止后恢复，输出通道占用轨迹、重建范围、恢复差异与各会话帧序核验结论。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地承载端样本验证并行转发有序性、增量切换一致性与强制终止后租约恢复，并输出轨迹与恢复差异。
