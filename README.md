在 Windows 空白工作区中，需要从零构建一个面向本地块存储场景的快照与回滚组件，供上层备份编排器集成。存储卷由固定大小的数据块组成，每个块携带块号、版本号、最近写入时刻与内容摘要；快照记录某一时刻各块版本的一致集合，回滚则把卷恢复到指定快照的块版本集合。为支撑真实运维场景，卷的数据规模会从数百块变化到数十万块，快照链需要支持增量快照（只记录相对父快照变化的块）与合并，同时必须保证快照元数据与块索引在并发写入、进程被强制终止后仍然一致。用户通过本地 HTTP 接口发起卷写入、创建快照、增量快照、合并与回滚，并查询回滚裁决明细与恢复报告。所有数据来自本地确定性样本文件，不依赖真实块设备或外部存储服务。

任务环境与准备：
安装 Python 3.10 及以上与 NumPy、Flask，并确认可用 sqlite3 标准库模块。
在空工作区创建项目目录与本地确定性样本文件，样本描述卷块数、若干块的写入内容、声明的块摘要与快照创建序列。
准备启动本地 HTTP 服务的脚本入口，确认回环端口可用，不需要任何外部服务或账号。

业务要求：
1. 实现卷与块的存储模型：卷由固定块数组成，每块保存数据内容、版本号、最近写入时刻与 SHA-256 摘要；写入接口接受块号与内容，写入后版本号单调递增且摘要必须与实际内容一致，内容摘要不一致时返回业务码 E_BLOCK_CHECKSUM 且不得改写该块现有版本，摘要校验须对比请求中声明的摘要与按实际内容重算的摘要。
2. 实现全量与增量快照：全量快照记录全部块的版本集合与一致性序号，增量快照只记录相对父快照发生变化的块并引用父快照；快照链需支持查询父链与派生关系，父快照被删除时若仍有未合并的子快照引用则返回 E_SNAPSHOT_IN_USE，禁止留下悬挂引用，删除操作须在通过引用检查后才修改快照链。
3. 实现快照合并与规模自适应策略：当快照链深度或变化块比例超过配置阈值时，合并相邻快照以减少链长并输出合并前后链深与引用块数；合并必须在同一事务边界内重写快照元数据与块引用，禁止出现元数据已合并而部分块引用仍指向旧链的中间可见状态，合并触发条件由输入参数显式给出以便复核。
4. 实现回滚裁决：回滚到指定快照时按快照记录的块版本集合恢复卷，并计算回滚差异（需要写回的块数、被覆盖的当前版本号、未受影响的块数）；当目标快照所需块内容缺失或摘要复核失败时返回 E_SNAPSHOT_CORRUPT 并保持卷不变，不得部分回滚，回滚差异须在恢复前后均可核对。
5. 实现数据规模变化下的索引取舍：为块的当前版本维护内存索引并按快照粒度缓存版本映射；当卷块数超过配置阈值时切换为分片索引并输出分片数、索引内存估计与切换依据，切换前后同一查询必须得到一致的块版本映射结果，分片键范围需覆盖全部块号且无重叠。
6. 实现并发写入与快照隔离：卷写入按卷单写者串行执行，快照创建与查询可并发；创建快照读写期间发生的新写入不得出现在该快照中，快照记录的是创建请求绑定的卷版本，查询只能看到某一完整提交版本而非半写入状态，同一写入请求重复提交须幂等处理。
7. 实现意图持久化与强制终止恢复：写入、快照提交与合并均先写意图记录再提交事务；进程在合并或回滚中途被强制终止后重启须扫描未完成意图，把卷与快照链恢复到最后一个完整版本或将操作标记为已中止，恢复报告只基于已持久化事实，不得承诺强制终止后仍生成完整退出报告。
8. 提供本地 HTTP 接口与端到端演示脚本：接口覆盖卷写入、创建全量快照、创建增量快照、合并、回滚、查询快照链与回滚裁决明细、查询恢复报告，统一错误响应为含业务码的 JSON（至少覆盖 E_BLOCK_CHECKSUM、E_SNAPSHOT_IN_USE、E_SNAPSHOT_CORRUPT、E_STALE_BASE、E_SNAPSHOT_NOT_FOUND）；脚本用固定本地样本完成一次全量快照、两次增量快照、一次合并与一次回滚，输出快照链、回滚差异与最终块版本摘要。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
