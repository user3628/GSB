当前是空白工作区，需要在 Windows 本地从零构建一个面向 GitOps 场景的集群配置回滚与收敛裁决组件，交付可集成的领域组件与完整示例。组件以本地确定性 JSON 样本维护若干受管集群与若干应用（应用标识、目标集群、期望配置版本、当前生效版本、副本预算、依赖的其他应用），运维人员提交带版本号的配置快照与只含局部改动的增量片段，组件据此计算受影响应用与集群、推进回滚与收敛状态、输出分批收敛计划。数据规模会从少量应用变化到数千应用与依赖边，受影响集合计算与收敛批次组织需在精确全量重算与增量局部重算之间取舍，并保证两条路径得到一致结论。核心难点是数据规模变化下的算法取舍与回滚状态一致性：某应用回滚触发其下游依赖应用的级联回滚，进程可能在任意时刻被强制终止，重启后必须依据持久化事实恢复回滚进度与收敛结论。

任务环境与准备：
安装 Python 3.11 及以上版本，并在项目虚拟环境中安装 FastAPI、uvicorn、NumPy 与 pytest，版本在 requirements 中固定。
准备本地确定性样本：一份含若干集群与数千应用的 JSON 依赖图、一份含单应用版本变化的增量片段与一份触发级联回滚的快照。
无需外部服务、账号或网络访问，SQLite 使用 Python 标准库 sqlite3，所有样本与数据库文件放在工作区本地目录。
启动本地 HTTP 服务前确认端口可绑定，示例脚本与测试均以本地回环地址访问。

业务要求：
1. 实现集群、应用与快照模型：应用声明标识、目标集群、期望配置版本、当前生效版本、副本预算与依赖的应用列表，快照携带单调递增版本号、生成时间与整体校验摘要；解析本地 JSON 样本时校验应用标识唯一、依赖引用存在、副本预算为非负整数并做溢出检查，解析失败返回 E_SPEC_INVALID 且整份快照不生效。
2. 实现回滚与收敛状态机，至少包含 PENDING、ROLLING_BACK、CONVERGED、FAILED、ABORTED 五种状态并规定合法迁移路径；非法迁移返回 E_INVALID_TRANSITION 且不修改已持久化状态；期望版本与当前生效版本不一致的应用初始进入 PENDING，版本一致的应用直接进入 CONVERGED，崩溃恢复后须依据持久化状态重算而不依赖内存残留。
3. 实现受影响集合与回滚级联计算：当某应用的回滚触发其直接与间接下游依赖应用的回滚时，须计算完整级联集合与回滚次序；当依赖出现环时返回 E_DEPENDENCY_CYCLE 并附环上应用标识，环外应用的受影响集合仍须给出；下游回滚集合须与状态迁移在同一事务边界内一致，禁止出现下游已标记 ROLLING_BACK 而上游仍为 CONVERGED 的中间可见状态。
4. 实现增量片段提交：增量只含受影响应用并携带基础版本号，基础版本不是当前版本时返回 E_STALE_BASE 且不改变任何已提交状态；同一基础版本的两个并发增量只允许一个成功、另一个必须收到 E_STALE_BASE；被改动应用的下游依赖集合须在增量生效后被识别为需要重新评估收敛的对象。
5. 实现收敛批次组织：按应用依赖关系把待收敛应用划分为批次，同一批次内的应用之间不得存在未完成的收敛依赖，批次规模受副本预算与集群配额约束，超配额时拆分批次而非丢弃应用；应用规模超过配置阈值时允许由精确全量重算切换为受影响的局部重算，并输出所用路径、受影响应用数与切换依据，两条路径对同一快照必须得到一致的批次划分与最终状态结论。
6. 实现并发一致与幂等：收敛执行按快照版本单写者串行，多个只读查询（应用状态、批次划分、回滚级联集合）可并发读取某一完整提交版本；同一快照版本重复触发收敛只执行一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_TRIGGER；查询不得看到部分应用已 CONVERGED 而批次划分仍包含它们的中间状态。
7. 使用 SQLite 持久化快照版本、应用状态、批次划分、回滚级联与意图日志，快照提交、状态迁移与批次重建前先写意图记录再提交事务；进程在级联回滚或批次重建中途被强制终止后重启须扫描未完成意图，把状态回滚到最后一个完整快照版本或将批次标记为已中止，恢复报告只包含已持久化事实，不承诺强制终止后仍生成完整退出报告。
8. 提供统一业务错误码与端到端示例：失败响应为含业务码与上下文的 JSON，至少覆盖 E_SPEC_INVALID、E_INVALID_TRANSITION、E_DEPENDENCY_CYCLE、E_STALE_BASE、E_CONFLICTING_TRIGGER；示例脚本用固定本地样本完成一次全量收敛、一次只改单应用版本的增量提交触发级联回滚、一次并发增量冲突与一次强制终止后恢复，输出每批应用状态、回滚级联集合与恢复前后差异。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
