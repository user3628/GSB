数据可靠性团队在本地 Windows 开发机上启动一个技术验证，目标是为列式块存储的副本一致性巡检交付可集成的领域组件与完整示例。每个列式块由固定行数的数据页组成，页内按列存放编码后的块数据，整块附带 Merkle 式分块摘要树：叶节点为各数据页的内容摘要，中间节点由子节点摘要拼接后取摘要，根摘要登记在块清单中。巡检时多个副本各自上报其页摘要列表与根摘要，组件需沿摘要树逐层核验，定位首个不一致的页与分叉层，并据核验结果计算每个副本的可信度与整块的损坏范围。真实环境中页数从数十到数十万，摘要计算量巨大，必须支持从上次巡检结果出发的增量核验：只对自上次巡检以来声明发生变化的页重算摘要，其余页复用已登记的摘要。所有输入来自程序内置固定种子生成器产出的本地确定性样本，不依赖真实集群或外部服务。

任务环境与准备：
安装 Go 1.22 或更高版本（Windows 官方安装包）并确认 go version 可用。
创建工作区目录，执行 go mod init 初始化模块；使用 Go 标准库 database/sql 与纯 Go 的 SQLite 驱动（go get modernc.org/sqlite），无需 CGO。
运行内置固定种子样本生成器产出列式块清单、页数据与多副本摘要报告到本地目录，样本的页数规模与种子写入样本清单以便复现。
以 go build ./... 编译，以 go test ./... 与示例脚本在本地执行；不依赖网络、容器或真实集群。

业务要求：
1. 实现列式块清单与摘要树模型：块清单记录块标识、行数、页数、各页列编码后字节长度与根摘要，摘要树节点记录层级、左右子节点引用与节点摘要；解析本地确定性样本时校验页数为正整数、摘要为 32 字节定长值、根摘要与最底层叶节点数量存在对应关系，失败返回 E_MANIFEST_INVALID 且保持已加载的旧清单可用。
2. 实现叶级与中间层摘要核验：按页数据重算叶摘要，再自底向上逐层重算中间摘要并与登记值比对，输出首个不一致页号、首次分叉层级、分叉处左右子摘要与两侧摘要所属副本；页数据缺失或长度与清单声明不符时返回 E_PAGE_MISMATCH 并附期望与实际长度，不得跳过后继页继续以错误摘要向上汇总。
3. 实现多副本报告的分叉定位与共识判定：每副本上报全部页摘要与根摘要，组件须判定各副本间首个分叉页与分叉层，并按副本数多数得出共识根摘要与共识页摘要集合；当没有任何摘要集合获得严格多数时返回 E_NO_QUORUM 并附各候选摘要的得票，不得默认任一副本胜出。
4. 实现增量核验：请求携带上次核验的检查点与本次声明发生变化的页号集合，组件只对变化页重算叶摘要，并沿受影响路径向上重算必要的中间节点，未变化子树的摘要必须复用已登记值而非重算；输出实际重算的节点数、复用节点数与节省比例，同一块同一检查点重复核验必须逐位一致。
5. 实现副本可信度与损坏范围计算：由分叉页数、分叉层深度与参与共识的副本数推导每个副本的可信度，由不一致页的分布推导损坏范围（起始页、结束页、受影响列），全程使用整数或显式定点表示并输出每步舍入方式与累计舍入误差；可信度比较使用带相对容差的定点比较并按副本标识稳定字典序打破平局。
6. 实现单写者核验与多读者查询的并发一致及幂等：同一块的核验按块标识单写者串行执行，多个只读查询可并发读取某一完整提交版本且不得看到部分页已核验而根摘要尚未落定的中间状态；同一请求标识重复提交只核验一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_REQUEST。
7. 实现基于 SQLite 的意图持久化与强制终止后恢复：页摘要登记、中间层摘要更新、共识结论与检查点推进前先写意图记录再提交事务；进程被强制终止后重启须扫描未完成意图，把摘要树与共识结论回滚到最后一个完整检查点或标记该次核验为已中止，恢复报告只包含已落盘事实。
8. 提供本地 HTTP API 与可复现验证工具：接口覆盖清单加载、多副本报告提交、触发核验、按请求查询分叉定位与可信度明细、查询增量化统计与恢复报告；失败响应统一为含业务码与上下文的 JSON，至少覆盖 E_MANIFEST_INVALID、E_PAGE_MISMATCH、E_NO_QUORUM、E_CONFLICTING_REQUEST 与 E_RECOVERY_INCOMPLETE，验证脚本使用固定种子样本完成全量核验、增量核验、分叉定位与强制终止后恢复各一次。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定样本验证摘要树核验、多副本分叉定位、增量复用与强制终止恢复，并输出可信度明细。
