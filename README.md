当前是空白工作区，需要从零实现一个面向本地块存储场景的「快照与回滚状态演进一致性服务」，用于在离线环境下复现真实块存储中快照链、增量写入与回滚恢复的核心机制。服务管理若干卷，每个卷以固定大小的数据块（例如 4 KiB）为单位存储内容摘要与数据引用，支持创建快照、对卷写入新块、从快照回滚卷以及卷与快照的删除。快照之间构成父子链，同一块在同一时刻只允许一条版本路径可见；回滚不是整体覆盖数据文件，而是依据快照链重排块引用并推进卷的版本代数。真实块存储的关键难点在于：回滚与快照创建、并发写入交错时会出现部分回滚（必须回到回滚前的一致点而不是半成品）、快照链中的中间快照被删除后仍须能回滚到更早快照、进程崩溃后要依据持久化状态判断哪些回滚已完成、哪些需回退，且回滚期间的新写入必须被有序阻塞而不能丢失。

任务环境与准备：
安装 Python 3.11 或以上，确认 python 与 pip 可在命令行执行。
确认 Python 标准库 sqlite3 可用（随 Python 提供，无需额外安装），并使用 pip install pytest 安装 pytest。
准备本地工作目录用于存放卷数据、快照元数据与 SQLite 数据库文件，无需任何外部服务或网络访问。
在 Windows 上确认可创建本地 HTTP 监听端口并运行子进程进行 pytest 用例。

业务要求：
1. 实现卷、块与快照链的模型及持久化结构：卷含标识、块大小、块数、版本代数与当前快照引用；块记录含卷标识、块序号、内容摘要、数据引用与写入序号；快照含标识、父快照或空、创建时的卷版本代数、被覆盖块清单与创建序号。须校验块序号在卷块数范围内、块大小为 2 的幂且不小于 512 字节、快照父链无环，非法输入返回业务码 E_BAD_MODEL 且不得写入任何状态。
2. 实现写时复制（COW）语义的块写入：对卷写入块时，若当前卷存在快照则须先把该块的旧内容归属记录到快照的被覆盖块清单，再写入新内容并推进写入序号，使快照读到的仍是旧内容、卷读到新内容；未变更块不得被复制从而保证写入规模与变更块数成正比。写入须原子：写入中途失败不得出现快照清单已记录但新内容未生效的状态。
3. 实现从任意快照回滚卷并推进版本代数：回滚须按快照链反向重排目标块引用，把卷恢复到该快照创建时的可见内容，同时把卷版本代数加一并在回滚结束后废弃回滚点之后的块版本。回滚须分阶段推进且每阶段完成都以持久化提交点为界，回滚中断后重启须依据提交点回到回滚前状态或完整回滚状态，不得停留在部分回滚。
4. 实现回滚期间并发写入的有序阻塞：回滚进行中，同一卷的新写入必须进入该卷的等待队列而不是被丢弃或静默失败，等待须有基于真实单调时钟的超时并以 E_ROLLBACK_BUSY 返回；回滚完成后队列按到达顺序恢复执行且每个写入都返回各自结果。回滚与写入不得交错产生快照旧内容与新内容混合的可见状态，读路径在回滚期间也须遵循同一可见性边界。
5. 实现快照链中间节点删除与链压缩的一致性：删除中间快照时须把其被覆盖块清单按其可见性合并到相邻保留快照，使保留下来的快照读取内容与删除前逐块一致；若某块仅被待删快照贡献且后继快照未覆盖，须把该块归属转移而不是丢弃。删除后仍须能回滚到更早快照，回滚结果与删除前回滚到同一快照逐块相等；回滚进行中禁止删除其依赖链上的快照并返回 E_SNAPSHOT_IN_USE。
6. 实现 SQLite 持久化与重启后的状态裁定：卷版本代数、块记录、快照清单、回滚提交点与写入队列须在提交点以单事务写入，事务提交后才对查询可见；重启时须把中断的回滚判定为已提交完整回滚或回退到回滚前版本，把等待队列中的写入恢复为待执行并保持到达顺序，恢复后的卷与快照可见内容必须与其版本代数描述一致。
7. 实现本地 HTTP 接口与错误码集合：提供创建卷、写入块、读取块、创建快照、回滚快照、删除快照、查询卷与快照链、查询回滚进度的接口；读请求须返回内容摘要与来源快照版本，便于判断可见性。所有错误以互不重叠的固定业务码在 JSON 中返回，包含 E_BAD_MODEL、E_SNAPSHOT_IN_USE、E_ROLLBACK_BUSY、E_NOT_FOUND。
8. 提供本地确定性演示与可重复测试：使用固定随机种子的样本生成器生成至少两个卷、每卷千级块写入与多级快照链，演示脚本须展示快照可见性、回滚中断与恢复、回滚期间写入排队及中间快照删除后的链压缩；pytest 用例须在 Windows 离线覆盖 COW 写入、任意快照回滚、中断回滚恢复、并发写入阻塞与链压缩等价性。
