当前是空白工作区，需要从零实现一个面向本地单机训练场景的「训练检查点保存、恢复与数值误差传播诊断工作台」，复现真实深度学习训练中检查点机制与混合精度数值路径的核心问题。训练循环由本地确定性样本驱动：每步从固定随机种子的样本生成器取一批，计算线性层与归一化层的前向、损失与反向梯度，可选以 float16 与 float32 混合精度路径更新参数。检查点按步数周期保存参数张量、优化器动量、随机数生成器状态、累积损失与学习率调度状态，并支持进程重启后从最近检查点继续训练。真实场景的难点在于：混合精度下的梯度缩放与累加会让参数在多次保存-恢复之间产生微小数值漂移，检查点格式的字段截断与序列化精度会放大误差；恢复后的损失曲线必须与不中断训练在容差内一致，否则需要定位漂移来自参数张量、优化器状态还是随机状态。

任务环境与准备：
安装 Python 3.11 及以上版本，并创建独立虚拟环境，避免污染系统解释器。
执行 pip install numpy fastapi uvicorn pytest httpx 安装依赖，全部离线包可用本地 wheel 缓存。
确认工作目录可写，用于生成检查点文件、SQLite 数据库与本地样本。
以固定随机种子运行示例脚本，确认可复现逐步损失与检查点摘要。
在 Windows 命令行运行 pytest，确认用例在无外网条件下全部执行。

业务要求：
1. 实现确定性训练循环与数值路径：以固定随机种子生成本地样本，实现线性层前向、均方损失与反向梯度，支持纯 float32 路径与 float16 前向加 float32 主权重、梯度缩放系数的混合精度路径；同一配置两次运行的逐步损失必须逐值一致，混合精度路径须显式记录缩放系数与溢出检测结果。
2. 实现版本化检查点格式与保存：检查点包含格式版本、步数、参数字典、优化器动量、随机数状态、累积损失与调度状态，以带魔数、格式版本、字段数、每字段字节长度与整体 CRC32 的自描述结构落盘，写入先写临时文件校验后原子替换；参数张量须声明 dtype 与形状，恢复时形状或版本不符返回 E_CKPT_INCOMPATIBLE。
3. 实现恢复与续训一致性判定：从检查点恢复后继续训练若干步，与不中断的参照运行逐步比较损失与参数范数，须在配置的相对容差与绝对容差内一致；超出容差须判定为漂移并输出首个越界步、最大偏差张量名与偏差来源分类（参数、优化器状态、随机状态或格式截断）。
4. 实现数值误差的量化传播诊断：对每步计算参数更新量的误差上界，依据混合精度缩放系数、float16 表示精度与检查点序列化保留的十进制位数给出分解项，以十进制定点字符串输出各来源贡献与合成上界，并按贡献从大到小排序；诊断须能说明容差是否足以吸收该上界。
5. 实现检查点间隔与误差累积的交互控制：检查点按步数周期或外部触发保存，恢复后累积的格式截断误差须随保存次数增长而被记录；须提供恢复链追溯，列出从初始运行到当前运行的每次保存-恢复的误差贡献与累计值，使调用方判断是否需要以更高精度重建基线。
6. 实现并发训练会话与检查点的互斥：多个训练会话可并行推进但同一检查点键（实验标识与步数）只能由一个会话写入；保存与恢复不得交错产生半写状态，并发写入须以真实超时返回 E_CONTENTION_TIMEOUT；不同实验标识之间互不阻塞，会话间不得共享可变参数张量。
7. 实现 SQLite 持久化与重启恢复：训练状态、检查点元数据、诊断结论与恢复链须在保存提交点以单事务写入，事务提交后才对查询可见；进程重启后须将处于保存中的检查点回退为不可用，从最近完整检查点继续，并保证恢复后续训与重启前未中断运行的损失一致性判定仍可重算。
8. 实现本地 HTTP 接口、确定性样本与可重复测试：提供创建训练配置、提交训练若干步、触发保存、从检查点恢复、查询诊断报告与恢复链的接口，错误统一以固定业务码返回；内置固定随机种子样本与 pytest 用例，覆盖保存-恢复一致、容差越界定位、版本不兼容、并发冲突与重启续训，需在 Windows 离线可重复运行。
