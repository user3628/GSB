当前是空白工作区，没有现存项目、代码或数据附件，需要从零实现一个面向本地 CI 流水线场景的“制品缓存并行调度与预算仲裁引擎”，用于复现云原生流水线中构建制品缓存复用与共享资源预算竞争的真实机制。引擎管理一组缓存条目（缓存键、内容摘要、字节大小、最近使用逻辑刻度、命中计数）与一组构建任务（任务标识、输入摘要集合、所需缓存键集合、优先级、提交时刻）。任务执行时按所需缓存键查取条目，命中则复用，未命中则按内容摘要生成新条目。系统同时运行多条流水线，共享两类硬约束：单轮缓存写入字节预算与并发执行任务上限，二者互相挤占——写入预算被占满时任务只能等待，等待又会延后缓存复用时机。引擎须在并行推进任务的同时做出准入、推迟与淘汰裁决，保证字节账目与命中结果可复现，并能从持久化状态恢复未完成轮次。

任务环境与准备：
安装 Python 3.11 或以上版本，并确认 python 与 pytest 命令在 PATH 中可用。
执行 pip install pytest 安装测试依赖，其余仅使用 Python 标准库（asyncio、sqlite3、http.server 或等效本地 HTTP 服务、hashlib、json）。
在空白工作区中创建项目目录与 SQLite 数据文件目录，确认当前用户对工作目录具有读写权限。
确认本地回环地址可用于启动 HTTP 服务与测试客户端，任务不需要外网、外部服务或额外数据集。
准备好运行 pytest 与演示脚本的命令行终端，所有样本与固定随机种子生成器随项目提供。

业务要求：
1. 实现缓存条目与构建任务的数据模型及载入校验：缓存条目含缓存键、内容摘要、字节大小、最近使用逻辑刻度与命中计数；任务含任务标识、输入摘要集合、所需缓存键集合、优先级与提交时刻。须校验缓存键格式合法、字节大小为正整数、任务所需缓存键集合非空且无重复，同一任务标识重复提交须按提交时刻较早者为准并幂等忽略后者，非法输入返回业务码 E_BAD_INPUT 且不进入任何队列。
2. 实现带字节预算的并行任务调度器：每一轮按优先级与提交时刻的确定次序选出候选任务，在并发上限与单轮写入字节预算双重约束下决定准入；预算不足时任务须进入等待队列而非丢弃，等待须有基于真实单调时钟的超时并以 E_BUDGET_WAIT_TIMEOUT 返回。调度结果必须与候选遍历次序确定，相同输入两次调度产出的准入集合与等待集合顺序逐项一致。
3. 实现缓存命中复用与未命中生成的确定性规则：任务所需缓存键全部命中时其所需字节不占用写入预算，部分未命中时只按未命中条目字节扣减预算；未命中条目内容摘要由输入摘要集合按确定次序连接后哈希得到，同一任务在预算充足与预算紧张两种轮次下落盘的内容摘要必须相同，命中计数须在任务准入成功后累加而非在调度预选阶段累加。
4. 实现字节账目的原子扣减与释放：任务准入时须在同一事务边界内同时写入缓存条目、扣减本轮写入预算并推进任务状态，任一步失败须整体回滚使字节账目与条目集合均不变化；任务失败或被取消时其尚未提交的条目字节须归还预算，已提交条目保留但不得重复计入下一轮预算，账目在任意时刻须满足已用字节与剩余字节之和等于轮次总预算。
5. 实现按容量上限的淘汰与引用一致性：当缓存总字节超过容量上限时须按最近使用逻辑刻度淘汰引用计数为零的条目，正被等待队列中任务所需或被在途任务占用的条目不得淘汰；淘汰与任务准入并发发生时不得淘汰本轮刚被准入任务复用的条目，且淘汰后重新计算的总字节须与保留条目字节之和精确相等，违反者返回 E_EVICTION_INCONSISTENT。
6. 实现 SQLite 持久化与重启后的轮次恢复：缓存条目、字节账目、任务状态、等待队列次序与轮次序号须在每轮提交点以单事务写入，事务提交后才对查询可见；进程重启后须把中断时处于 running 的任务判定为失败并归还其未提交字节，恢复等待队列次序与轮次序号，已提交条目仍可命中，恢复后的账目须与重启前最后一次提交一致。
7. 实现并发调度与缓存写入的互斥及跨轮一致性：同一缓存键的生成须串行化到该键的一致性边界内，不同键可并行推进；同一轮内多个任务同时未命中同一缓存键时只能有一个任务真正生成条目，其余任务须复用其结果而不得重复扣减预算；并发锁等待须有真实超时并返回 E_CONTENTION_TIMEOUT，超时不得留下半提交条目或错误账目。
8. 提供本地 HTTP 接口、诊断报告与可重复测试：通过本地 HTTP 提供提交任务、推进一轮、查询任务与等待队列、查询缓存条目与字节账目、查询淘汰与并发诊断报告的接口，错误统一以固定业务码在 JSON 中返回；报告须列出每轮准入集合、命中与未命中条目、预算扣减明细与等待原因。附带固定随机种子的样本生成器与 pytest 用例，覆盖命中复用、预算耗尽等待、并发同键争用、淘汰一致性、重启恢复与非法输入，全部在 Windows 离线运行。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
