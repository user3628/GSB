新成员刚接手的语音分析子项目尚处立项阶段，工作区只有一台可用的 Windows 开发机，需要交付一套可被上层转写服务集成的说话人分离与识别领域组件及完整示例。输入为程序内置固定种子生成器产出的确定性 16 kHz、单声道、16 位 PCM WAV 分片，每片含 2 至 4 个说话人的混合语音段、静音段与重叠说话段，采样点由确定性合成器按说话人基频区间、共振峰包络与起止区间叠加生成；另附 JSON 会话清单声明每片的参考分段标注（毫秒起止、说话人编号、可信度标记）、样本总数上界与分片顺序，作为唯一真值与观测来源。组件需按分帧与频谱分析、迭代掩码分离、声纹嵌入与聚类仲裁、阶段汇总四段推进，并支持在任一分片边界被中断后依据持久化事实恢复。所有样本、测试端点与验证数据均在本地确定性生成，不依赖真实分离模型、预训练权重、GPU 或外部服务。

任务环境与准备：
安装 Go 1.22 或以上（Windows 官方安装包，安装后执行 go version 确认）。
使用标准库与本地 SQLite 驱动（如 modernc.org/sqlite，通过 go get 引入），不引入任何音频或模型第三方依赖。
在空工作区执行 go mod init 初始化模块，样本 WAV 与 JSON 会话清单由程序内置固定种子生成器在首次运行时写入本地目录。
确认工作目录具备可写权限以创建 SQLite 状态库与快照目录，运行全部测试与演示均离线进行。

业务要求：
1. 实现分帧与频谱分析阶段：按可配置帧长（默认 25 ms）与帧移（默认 10 ms）对 16 位 PCM 做汉宁窗分帧，帧长与帧移以毫秒声明但须显式换算为整数采样点，逐帧做短时傅里叶变换并输出复数谱、对数能量与频谱平坦度；帧边界越出样本末尾时以确定性零填充并标记；同一分片与配置必须产生逐字节一致的谱摘要，谱出现 NaN 或 Inf 时返回 E_NUMERIC 并附分片标识与帧索引。
2. 实现迭代掩码分离核心：按初始说话人数对幅度谱做确定性的迭代幅值掩码估计，每轮记录逐帧掩码变化量，达到可配置最大轮数或变化量低于阈值即收敛；掩码迭代中出现掩码乘零导致全静音、说话人数超出上限或某声源在全部帧上能量为零时，返回带分片标识、声源编号与轮次的 E_SEPARATION 并保留诊断上下文；同一输入与配置的分离波形与逐轮变化量必须逐字节一致。
3. 实现声纹嵌入与聚类仲裁：以梅尔频带能量统计拼接固定哈希投影生成各分离声源的声纹嵌入，按与清单参考分段质心的余弦相似度做最近质心归类，再对相似度差距低于可配置间隔阈值的帧做聚类仲裁并记录仲裁依据；说话人编号须在分片内唯一且连续，声纹嵌入含 NaN 或相似度并列无仲裁依据返回 E_EMBEDDING；同配置下聚类标签不得随分片顺序变化。
4. 实现重叠说话段判定与统一毫秒时间轴：对分离后能量同时超过阈值的帧判定为重叠说话段，输出其起止毫秒与参与说话人集合，维护以毫秒整数表示的分段模型（起止、说话人编号、置信度、重叠标记），支持切分、合并相邻同说话人段与跨分片说话人身份合并，每次编辑生成单调版本号并记录操作来源；分段起止为负、结束早于开始或跨分片合并出现编号冲突时返回 E_TIMELINE。
5. 实现增量重算与全量一致性校验：当会话清单中的分段标注、说话人数、掩码迭代轮数、间隔阈值或声纹投影参数任一变化时，通过各阶段内容摘要构成的版本指纹识别受影响的最早阶段，仅重算该阶段及其下游，未受影响上游产物继续复用；增量结果须与从零全量运行得到的分段清单、重叠段清单与声纹摘要逐字节一致，不一致时返回 E_INCREMENTAL_MISMATCH 并给出首个差异分片与阶段。
6. 实现 SQLite 事务化检查点与优雅停止及强制终止后的恢复：每个分片每阶段完成时以事务写入含阶段名、分片内容指纹、配置版本、产物摘要与单调序号的记录，同一分片同一阶段只允许一条有效记录；收到停止请求时完成当前不可拆分分片后退出并保持检查点一致，被强制终止后重启只依据已提交事实重建进度、不承诺生成退出报告；恢复后的最终产物须与一次连续执行逐字节一致且检查点序号连续推进。
7. 实现并发发布保护与快照整体替换识别：多执行进程发布同一工作区的分片产物时使用 SQLite 条件更新与真实文件锁并比较分片内序号，仅允许序号连续推进，落后、重复或跨分片错位发布返回 E_STALE_CHECKPOINT；当检测到记录被整体替换（序号回退、指纹变化或摘要不匹配）时须区分正常推进、整体替换与回退，整体替换使受影响阶段全部失效重建，回退则拒绝并保留原状态。
8. 实现版本化阶段快照与外部参数注入异常链路：每阶段快照以原子方式整体落盘并携带版本指纹，注入入口支持清单声明样本总数与实际不符、采样率与清单冲突、说话人数为零、掩码轮数为负与声纹投影维度不匹配等情况，各注入在对应阶段返回稳定业务码（E_INPUT_LENGTH、E_RATE_MISMATCH、E_INVALID_PARAM、E_EMBEDDING），并保证注入失败后已提交快照仍可读取。
