当前是空白工作区，需从零构建一个本地可运行的生成式图像编辑管线，核心业务目标是在交互式编辑场景下同时满足可配置的延迟预算与计算结果一致性。输入为固定随机种子生成器产出的本地小尺寸 RGB PNG 分片（含几何色块与渐变区域）与一份 JSON 编辑任务清单，每条任务含 task_id、输入分片文件名、中英混排编辑指令（如“将背景调暖并裁剪右上区域”）、允许的编辑算子标签（crop、resize、rotate、color_shift、blur）、期望输出尺寸与期望编辑摘要。管线需按四个阶段推进：指令解析与算子链生成、算子链分块执行、结果摘要比对、延迟预算下的查询与导出。系统不依赖任何真实生成模型、GPU 或外部服务，全部计算基于本地确定性算法，可在 Windows 上直接运行。

任务环境与准备：
安装 Python 3.10 或以上，并安装 NumPy 与 Pillow 及其兼容版本。
准备本地确定性样本生成脚本，使用固定随机种子产出至少 4 个 PNG 分片与 6 条编辑任务清单。
确保工作区具备可写目录用于检查点、缓存与导出产物，无需网络与外部服务。
提供运行入口脚本与说明，使全部功能可在 Windows 命令行与本地 HTTP 接口下复现。

业务要求：
1. 实现指令解析与编辑算子链生成阶段：对编辑指令做 Unicode NFKC、空白折叠与全半角统一，按中文单字与拉丁连续串切分后匹配算子标签，生成有序算子链并校验每个算子存在、参数合法、上游输出尺寸可被下游接受；非法算子名、参数缺失或链长超限须返回带 task_id 与算子名的业务码 E_INVALID_CHAIN。
2. 实现确定性编辑算子内核：crop、resize、rotate、color_shift、blur 均以显式坐标、整数取整规则与固定采样顺序实现，resize 支持最近邻与双线性、rotate 采用固定角度采样与边界裁剪，color_shift 按定点量化实现；同一输入与配置必须产生逐像素一致的输出，越界参数须返回 E_INVALID_PARAM。
3. 实现延迟预算约束下的分块执行调度：以编辑任务为调度单元，在总操作步数预算、单工作线程步数配额与单任务延迟预算三重约束下决定接纳顺序与并发度，逐块记录耗时与累计步数；超预算任务记录为未处理并给出原因，不得以线程超时替代真实延迟预算判定。
4. 实现并行执行与确定性归约：使用本地线程池并行处理已接纳任务，各任务结果按 task_id 全局排序后归约，使并行输出与单线程顺序执行逐字节一致；查询结果须按内容指纹与配置版本缓存，缓存命中结果与重新计算逐字节一致，异常以结构化错误对象记录并保留上下文。
5. 实现持久化阶段检查点与优雅停止恢复：每个任务每阶段完成时以原子方式写入含 task_id、阶段名、输入内容指纹、配置版本、产物摘要与单调序号的记录，写入任意位置中断不得留下半写记录；收到停止请求时完成当前不可拆分任务后退出，恢复后最终输出与一次从零完整运行逐字节一致。
6. 实现版本变化检测与增量失效传播：当输入分片像素、编辑指令、算子参数、调度预算或延迟预算任一变化时，通过各阶段内容摘要构成的版本指纹识别受影响的最早阶段，使该阶段及其全部下游产物失效并重建，未受影响上游产物继续复用；失效原因与指纹须在查询接口中可观测。
7. 实现并发发布保护与稳定业务错误码一致性：多个工作进程对同一工作区发布阶段产物时使用真实文件锁并比较任务内序号，仅允许序号连续推进，落后、重复或跨任务错位发布返回 E_STALE_CHECKPOINT；请求非法阶段跳转或缺失前置阶段产物返回 E_INVALID_STAGE，并附可读原因。
8. 提供本地 HTTP 与命令行交互接口及确定性演示：支持导入分片与任务清单、触发分阶段执行、查询各阶段状态与版本指纹、查看逐任务耗时与延迟预算消耗、请求停止、执行恢复、导出编辑结果与摘要；演示数据至少 4 个分片与 6 条任务，含中英混排指令与至少 1 条必然超预算任务，一次完整运行生成固定摘要。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证分阶段执行、延迟预算判定、中断恢复与增量失效后产物一致，附运行结果。
