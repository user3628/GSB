当前是空白 Windows 工作区，需要从零构建一个面向本地 SQLite 数据的慢查询诊断与改写工作台，供 DBA 集成到运维流程。工作台读取本地确定性慢查询样本（查询语句、执行耗时毫秒、扫描行数、锁等待时间、发生时刻），结合表与索引的统计快照，判断查询是否属于慢查询并定位慢因（缺少索引、选择率估算偏差、锁等待、返回行数过多）。随后工作台按规则生成改写建议（增加索引、重写谓词顺序、拆分 OR、增加 LIMIT），并将建议提交给本地 SQLite 执行验证，比较改写前后的执行代价与结果一致性。核心业务问题是状态演进与恢复一致性：诊断会话在 CREATED、ANALYZING、SUGGESTED、VERIFIED、FAILED 之间迁移，进程可能在任何时刻被强制终止，重启后必须依据持久化事实恢复会话状态并给出仅基于已落盘数据的恢复报告，且改写建议不得在诊断未完成时被标记为已验证。

任务环境与准备：
安装 Python 3.11 及 Flask 依赖，使用 pip 在虚拟环境中安装，确保 Windows 命令行可运行。
准备本地 SQLite 样本数据库与慢查询样本 JSON、统计快照 JSON 文件，样本须固定且可重复。
确保工作区可写，SQLite 数据库文件路径与样本路径通过启动参数或配置文件指定。
提供端到端演示脚本入口说明，运行前无需外部账号、网络或容器环境。

业务要求：
1. 实现慢查询样本与统计快照的加载和归一化：每条样本含查询语句、耗时毫秒、扫描行数、锁等待毫秒与发生时刻，统计快照含表行数、索引定义与列不同值数；加载时校验耗时与扫描行数为非负整数并做溢出检查，解析失败整批不入库并返回业务码 E_SAMPLE_INVALID，统计快照摘要校验失败返回 E_SNAPSHOT_INVALID。
2. 定义诊断会话状态机，至少包含 CREATED、ANALYZING、SUGGESTED、VERIFIED、FAILED 五种状态并规定合法迁移路径；非法迁移必须返回 E_INVALID_TRANSITION 且不修改已持久化状态；处于 FAILED 或 VERIFIED 的会话不得再次进入 ANALYZING。
3. 实现慢因判定与改写建议生成：依据耗时阈值、扫描行数与锁等待时间判定是否慢查询，并按统计快照选择慢因；对每个慢因生成至少一条改写建议（增加索引、重写谓词顺序、拆分 OR、增加 LIMIT），建议须携带命中的规则标识、预期收益说明与所引用的统计快照版本，禁止在未加载统计快照时生成建议。
4. 实现改写验证：将原始查询与改写建议提交本地 SQLite 执行，比较改写前后执行代价估计与结果行集合摘要，结果不一致或改写执行报错时把会话迁移为 FAILED 并返回对应业务码；验证过程中须真实关闭数据库连接释放资源，不得以等待冒充超时。
5. 使用 SQLite 持久化诊断会话、样本、统计快照版本与改写验证记录，写操作先写意图记录再提交事务；进程在 ANALYZING 或验证中途被强制终止后重启须扫描未完成意图，把会话恢复为 CREATED 或标记为 FAILED，禁止把中断的验证结果直接标记为 VERIFIED，恢复报告只基于已持久化事实。
6. 实现单写者诊断与多读者查询的并发一致：同一会话的诊断与验证按提交串行执行，多个只读查询可并发读取已提交版本；同一会话标识重复提交诊断只执行一次、其余等待并复用结果；查询不得看到会话已 SUGGESTED 而改写建议尚未写入的中间状态。
7. 实现快照整体替换与版本识别：统计快照携带单调递增版本号与生成时间，加载新快照时须校验版本单调并整体替换旧快照，诊断会话绑定其分析时使用的快照版本；请求指定的快照版本已被替换时返回 E_SNAPSHOT_RETIRED，不得用新快照重新解释旧会话的慢因。
8. 提供统一业务错误码 JSON 错误体与本地 HTTP API，至少覆盖 E_SAMPLE_INVALID、E_SNAPSHOT_INVALID、E_SNAPSHOT_RETIRED、E_INVALID_TRANSITION、E_SESSION_NOT_FOUND、E_VERIFY_MISMATCH；API 覆盖样本提交、诊断触发、建议查询、验证触发与恢复报告查询，并附固定本地样本的端到端演示脚本输出各会话状态轨迹与验证结论。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证慢因判定、改写建议生成、验证结果一致性及中断后恢复报告的完整性。
