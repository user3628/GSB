当前是空白工作区，需要在 Windows 本地从零构建一个面向网关请求路径的限流与鉴权联合裁决中间件，交付算法实现与可复现的实验环境。网关接收带毫秒时间戳、路由键、客户端标识、令牌摘要与请求权重的事件批次，需要先完成鉴权判定（令牌有效性、客户端配额组归属、签名摘要比对），再按路由与客户端多窗口（如 1 秒短窗与 60 秒长窗）计数执行自适应限流，最终对每条请求给出放行或拒绝裁决。数据规模会从数百条请求增长到百万级请求批次，滑动窗口计数在全量精确计数与分桶采样估计之间取舍，同时鉴权失败、超限拒绝、窗口边界、迟到事件与令牌过期时刻必须给出稳定且可核对的结论。所有输入来自本地确定性样本，不依赖真实网关、外部鉴权服务或线上账号。

任务环境与准备：
安装 Python 3.11 及以上版本，创建虚拟环境并用 pip 安装 fastapi、uvicorn、numpy 与 pytest。
确认 SQLite 可用（Python 标准库 sqlite3 即可），准备本地工作目录用于数据库文件与恢复报告。
准备固定本地样本生成脚本所需的依赖仅限标准库与 NumPy，不联网、不访问真实鉴权服务。

业务要求：
1. 实现鉴权判定模块：对每条请求校验令牌有效性、客户端配额组归属与签名摘要（使用固定本地密钥的确定性摘要比对），令牌带绝对过期时刻且比较须按毫秒精度与声明边界规则判定；鉴权失败返回业务码 E_AUTH_DENIED 或 E_TOKEN_EXPIRED 并记录失败具体原因，失败请求不得进入限流计数。
2. 实现多窗口滑动计数模型：按固定窗口长度与滑动步长维护 1 秒短窗与 60 秒长窗的计数桶，桶以版本号与最后更新时间标识，事件按毫秒时间戳分配到所属桶；同一批次重复提交按批次标识与事件序号幂等去重，窗口边界包含关系须显式定义，禁止同一事件被计入两个不重叠窗口。
3. 实现数据规模自适应的精确与采样取舍：当单窗口事件数不超过配置精确上限时走全量精确计数，超过时改用均匀时间分桶采样或蓄水池采样，并输出采样率、采样方法与估计计数的置信区间；两条路径对同一批次的裁决差异须可由误差声明核对，精确路径结果必须逐次一致，不得因运算顺序变化而翻转限流结论。
4. 实现自适应配额与限流裁决：依据短窗与长窗的估计计数、客户端配额组上限与当前放行速率计算动态配额，配额缩放使用定点表示并逐步校验不越界；限流裁决须同时参考两窗口的计数，任一窗口超限即拒绝并返回 E_RATE_LIMITED，同时输出触发窗口、实测计数与配额值，配额调整须带阻尼以避免采样抖动引发配额震荡。
5. 实现鉴权与限流的跨模块一致性：同一请求的鉴权结论与限流结论必须读取同一窗口版本与同一令牌状态版本，禁止出现鉴权按新令牌状态通过而限流按旧窗口配额裁决的中间可见状态；查询接口只能看到某一完整提交版本，鉴权成功但被限流拒绝的请求须在裁决明细中同时保留两类原因。
6. 实现并发控制与幂等复用：鉴权与限流裁决按批次单写者串行执行，多个只读查询可并发读取已提交裁决；同一请求标识重复提交只裁决一次、其余等待并复用同一结果，内容不一致时返回 E_CONFLICTING_REQUEST；并发提交不同批次时各自的窗口计数与意图日志不得互相污染，并须明确单写者执行期间新到达事件进入下一批次还是被拒绝。
7. 实现意图持久化与强制终止恢复：鉴权状态、窗口计数与限流裁决写入 SQLite 前先落意图记录再提交事务；进程在批次裁决中途被强制终止后重启须扫描未完成意图，把窗口与裁决回滚到最后一个完整版本或将批次标记为已中止，恢复报告只基于已持久化事实，不得承诺强制终止后仍能生成完整退出报告。
8. 提供本地 HTTP API 与可重复实验脚本：API 覆盖事件批次提交、单请求裁决查询、按路由与客户端查询窗口计数与配额、采样误差说明查询与恢复报告查询，失败响应统一为含业务码的 JSON（至少覆盖 E_AUTH_DENIED、E_TOKEN_EXPIRED、E_RATE_LIMITED、E_CONFLICTING_REQUEST、E_BATCH_NOT_FOUND、E_SNAPSHOT_INVALID、E_INVALID_TRANSITION）；脚本使用固定本地样本分别生成小规模与大规模请求批次，输出两规模下的裁决分布、触发窗口、采样率与误差区间，并演示一次强制终止后的恢复。
