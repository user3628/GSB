当前为空工作区，需从零构建一个本地可运行的命名实体识别（NER）增量标注引擎，交付可被其他 NLP 服务以库形式集成的领域组件与完整示例。输入为若干本地 UTF-8 JSONL 语料分片，每条含 doc_id、tokens（已切分 token 列表）、可选的字符级标签序列（BIO 体系）以及 source 与 lang 字段；另有一份 YAML 标注配置，描述词表规模、字符与词形特征开关、转移约束（如 I-xx 前不得为无关标签）、平滑强度与置信阈值。引擎以本地确定性方式从种子分片估计标签转移与发射计数，构建特征化序列标注解码流程，对未标注分片产出带置信度的实体区间。分片内容、标注配置与特征开关均可能在增量更新中变化，引擎需识别受影响的最早阶段并重建其下游，未受影响阶段的结果继续复用。所有阶段产物需以原子检查点持久化，支持在阶段间优雅停止后恢复，且恢复后的实体结果与一次从零完整运行逐字节一致。系统不依赖任何真实预训练模型、外部账号或 GPU。

任务环境与准备：
确认 Windows 环境可用 Python 3.10 及以上版本，并安装 NumPy 与 PyYAML 到本地虚拟环境。
在工作区创建 data 目录，按题目背景放置本地 JSONL 分片与 YAML 标注配置，样本由固定种子脚本生成以保证确定性。
无需真实预训练模型、外部账号、GPU 或网络访问；运行前确认工作区路径可读写以支持文件锁与原子写盘。

业务要求：
1. 实现本地计数估计与特征化发射打分：从带标签种子分片统计 BIO 标签的初始、转移与发射计数，采用可配置平滑强度，未知 token 与未见转移回退到可配置的未知标记；特征开关控制字符前后缀与词形的参与，估计结果须带词表与配置指纹并可导出，同一输入与配置重复运行须逐字节一致。
2. 实现约束感知的序列标注解码：以对数域 Viterbi 为未标注 token 序列求解最优 BIO 路径，并在转移表中强制约束（I-xx 只能接 B-xx 或 I-xx），非法转移不得出现在最优路径中；解码须返回每 token 标签、路径对数概率与逐 token 置信度，同一输入结果确定，禁止出现未覆盖 token。
3. 实现实体区间抽取与置信度阈值过滤：将 BIO 路径重组为实体区间，输出实体类型、起止 token 下标与区间置信度（路径内 token 置信度的几何平均），低于配置阈值的实体标记为低置信并保留在诊断输出中；出现未闭合的 I 或标签越界时须回滚为带文档标识与 token 位置的 E_INVALID_TAG 错误对象，不得部分写入结果。
4. 实现阶段检查点与优雅停止恢复：解码流程按估计、特征化、解码、过滤四阶段推进，每阶段完成时以原子方式写入含阶段名、分片输入内容摘要、配置版本、产物摘要与单调序号的记录，写入任意位置中断不得留下半写记录；收到停止请求时完成当前不可拆分单元后退出，恢复时从最近一致检查点继续，最终实体结果与一次从零完整运行逐字节一致。
5. 实现增量更新与依赖失效传播：当分片标注内容、词表规模、特征开关、转移约束、平滑强度或置信阈值任一变化时，通过各阶段内容摘要构成的版本指纹识别受影响的最早阶段，使该阶段及其全部下游产物失效并重建，未受影响上游产物继续复用；失效原因、受影响阶段与指纹须在查询接口中可观测，禁止用旧指纹产物冒充新结果。
6. 实现增量与全量一致性校验：提供单分片更新入口，仅重建失效链路，并支持与从零全量构建的实体区间清单、逐 token 标签与摘要做逐字节比对；检测到不一致须返回 E_INCREMENTAL_MISMATCH 并附分片标识与阶段差异，且不得以覆盖方式掩盖差异。
7. 实现并发发布保护与业务错误码：多工作进程对同一工作区发布阶段产物时使用文件锁并比较检查点序号，仅允许序号连续推进，落后或重复发布返回 E_STALE_CHECKPOINT；请求非法阶段跳转、缺失前置阶段产物或使用与当前配置版本不符的查询返回 E_INVALID_STAGE，且工作区不得被部分写入。
8. 提供可集成组件接口与本地确定性演示：以库函数与命令行提供导入分片、查看各阶段状态与版本指纹、执行解码与实体查询、请求停止与恢复、导出增量校验报告；演示数据至少 3 个分片，含中英混排 token、跨分片重复实体名与至少 2 个未登录 token，完整运行生成固定摘要，并在阶段间触发停止后恢复验证结果一致。
