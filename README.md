弹性伸缩平台的设计说明已经评审通过，现在要在空白工作区把它落成可运行的本地服务：平台维护若干服务与它们的伸缩指标订阅关系，指标以带版本号的 JSON 快照提交，伸缩事实以只含局部改动的增量片段追加；平台据此维护每个服务的有效指标物化结果、由订阅依赖决定的上游影响集合与伸缩决策视图，并回答读取方携带观察版本时哪些结果可直接返回、哪些必须拒绝而不能给出陈旧值。指标来源为程序内置固定种子生成器产出的确定性样本（服务标识、实例标识、指标名、采样毫秒时刻、指标值、采集权重），不依赖真实监控系统或外网。伸缩决策需要按分位与权重合成风险分值，分值与比例一律以定点整数表示，伸缩产物还必须能被安全地增量重算与恢复。

任务环境与准备：
安装 Go 1.22 或以上版本（Windows 使用官方安装包），确认 go version 可执行。
使用标准库 database/sql 与纯 Go 的 SQLite 驱动（纯 Go 实现，无需 CGO），通过 go mod init 与 go get 获取依赖，不引入容器或外部服务。
无需外部监控系统与账号；样本由程序内置固定种子生成器在本地产出，HTTP 测试使用 127.0.0.1 回环端口。
任务执行前先运行一次生成器与本地服务冒烟检查，确认 SQLite 文件与工作目录可写、回环端口可用。

业务要求：
1. 实现服务、指标订阅与指标快照的模型和加载：服务声明组件标识、所属伸缩组、依赖的其他服务、订阅的指标名与权重；指标快照携带单调递增版本号、生成时间、服务到实例的采样记录与整体校验摘要。加载时校验版本单调与摘要，任一项失败返回业务码 E_SNAPSHOT_INVALID 且必须保持旧快照完全可用。
2. 实现增量片段提交与基础版本校验：增量片段只含受影响的采样记录或订阅项并携带基础版本号，基础版本不是当前已提交版本时返回 E_STALE_BASE 且不改变任何已提交状态；同一基础版本的两个并发增量只允许一个成功，另一个必须收到 E_STALE_BASE，不得出现两者都成功或都失败。
3. 实现按目标并发与延迟预算推导的伸缩决策：依据采样窗口内每实例请求数与 P90 延迟，按声明的目标并发、延迟预算与上下界推导期望副本数并夹在上下界之间；分位使用确定性最近秩法并注明样本规模，样本数不足时返回 E_INSUFFICIENT_SAMPLES，期望副本数须输出推导依据。
4. 实现有效指标物化与由订阅依赖决定的上游影响集合：每个服务的有效指标由自身采样与依赖服务声明的指标按权重合成为定点整数，影响集合由依赖关系向上递归得出并输出触发服务与传播跳数；读取时依据读请求携带的观察版本判定可返回的物化版本，落后于观察版本时返回 E_STALE_READ 并附当前物化版本。
5. 实现级联失效与增量重建：为每个服务维护其对合成指标、影响集合与伸缩决策视图的引用关系；订阅、采样或依赖关系变化时，受影响服务的全部派生结构及其下游服务的引用必须级联失效并在同一事务边界内原子重建，禁止出现上游已重建而下游仍引用旧上游值的中间可见状态。
6. 实现增量重算与全量重算的路径取舍：当被触及的订阅项与采样记录占比不超过声明阈值时，只重算受影响服务的合成指标并复用其余中间结果；超过阈值或触及影响集合的传播基数时退回全量重算，并输出所选路径、判定阈值、实际占比与重算范围，两条路径对同一快照版本必须给出逐位一致的合成指标与期望副本数。
7. 实现并发控制、幂等与强制终止恢复：快照提交、增量提交与级联重建按版本单写者串行执行，多个只读查询可并发读取某一完整提交版本，同一提交标识重复提交只执行一次、其余等待并复用结果、内容不一致返回 E_CONFLICTING_REQUEST；所有写操作先写 SQLite 意图记录再提交事务，进程被强制终止后重启须扫描未完成意图，把物化结果与引用关系回滚到最后一个完整版本或把增量标记为已中止，恢复报告只基于已落盘事实。
8. 提供本地 HTTP 接口与可重复演示脚本：接口覆盖快照加载、增量提交、按观察版本读取合成指标与伸缩决策、查询影响集合与重建路径、快照替换与恢复报告查询；失败响应为含业务码与上下文的 JSON，至少覆盖上述业务码；脚本用固定种子样本完成一次加载、一次只触达单服务的增量、一次触达全局的增量、一次观察版本落后读取与一次强制终止后恢复。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用固定本地样本验证增量提交、伸缩决策与级联重建，并核对观察版本陈旧读拒绝与强制终止后恢复。
