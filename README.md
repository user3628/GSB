当前是空白 Windows 工作区，需要从零构建一个面向本地分块列存文件的分块点查计算引擎，交付算法实现与可复现的实验环境。数据以带版本号的列式快照文件提供，每列包含数据类型、空值位图与按主键升序排列的行分块索引；查询为多主键集合等值点查，要求返回指定列并保持主键稳定顺序。数据规模会从数千行变化到数百万行，单块解压后的内存占用可能超出预算，因此引擎必须在逐块流式解码与批量多块解码之间做算法取舍，同时保证两种路径给出逐位一致的结果。所有数据来自本地确定性样本，通过本地 HTTP 服务提交查询，使用 SQLite 记录查询批次、分块任务与内存预算占用，进程可能被强制终止，重启后须依据持久化事实恢复，且强制终止后的恢复只能依赖已落盘状态，不得承诺生成完整退出报告。

任务环境与准备：
确认 Windows 上安装 Python 3.11 及以上版本，并可在命令行调用 python 与 pip。
安装依赖：pip install numpy fastapi uvicorn pytest，全部来自本地或公共包索引，不需要真实外部服务。
在空工作区创建项目目录，生成固定本地列存快照样本与查询主键集合样本，样本包含定长、游程与字典三种编码块及至少一个故意损坏块。
启动本地 HTTP 服务仅绑定回环地址，使用 pytest 或演示脚本驱动查询、分页拉取与强制终止恢复演练。

业务要求：
1. 实现列存快照的加载与版本识别：快照文件携带单调递增版本号、生成时间、列定义（数据类型与空值位图）、按主键升序排列的行分块索引与整体校验摘要；加载时须校验版本单调与摘要，失败返回业务码 E_SNAPSHOT_INVALID，且加载失败必须保持旧快照可用，不得让新旧快照的列定义与分块索引混合使用。
2. 实现三种分块编码的解码：定长编码、游程编码与字典编码各提供确定性解码实现，解码前校验块头的主键区间、原始行数、编码类型与摘要，损坏块返回 E_BLOCK_CORRUPT 并指明块号；解码结果须带空值位图与行偏移供后续过滤投影使用，空值列不得参与比较谓词，空值掩码必须与列数据类型一致。
3. 实现点查取数任务切分：按目标主键集合在升序主键空间中定位命中的分块，把相邻命中块合并为取数任务并保证任务间主键区间不重叠且覆盖全部命中块；主键集合为空时返回空结果而非错误，主键数量超过配置阈值时返回 E_KEY_SET_TOO_LARGE 而非静默截断。
4. 实现溢出前的内存预算裁决：依据命中块数、每块解压后字节数估计与剩余内存预算在逐块流式解码路径与批量多块解码路径之间选择，并输出所选路径、并行块数、峰值内存估计与选择依据；当单块解压后大小超过单任务内存预算时须对块做子块拆分重试并输出拆分记录，预算仍不足时返回 E_MEMORY_BUDGET_EXCEEDED，禁止先解压后判定预算。
5. 实现两条解码路径的逐位一致：同一查询在流式路径与批量路径下必须得到逐行一致的结果列与空值掩码，比较时使用带相对容差的比较并记录最大绝对与相对偏差；浮点列在 JSON 输出中保留固定小数位并附舍入说明，禁止因路径或并行块数变化导致结果数值或行序发生变化。
6. 实现拉取式分页结果：提交查询返回结果句柄与首页，后续按页序号拉取，页大小受客户端可接受页大小与配置上限共同约束；命中行按主键升序稳定归并，分页拼接后的行集合必须与不分页一次取尽的结果逐行一致且不重不漏，同一页被并发拉取时只允许一个客户端消费、其余返回 E_PAGE_CONSUMED。
7. 实现单写者物化与多读者查询的并发一致，并使用 SQLite 持久化查询批次、分块任务状态、内存预算占用与页进度，写操作前先写意图记录再提交事务；进程被强制终止后重启须扫描未完成意图，把已提交分块结果标记为可复用、未提交任务恢复为就绪，恢复报告只基于已落盘事实。
8. 提供统一业务错误码与可重复实验脚本：失败响应为含业务码与上下文的 JSON，至少覆盖 E_SNAPSHOT_INVALID、E_BLOCK_CORRUPT、E_KEY_SET_TOO_LARGE、E_MEMORY_BUDGET_EXCEEDED、E_PAGE_CONSUMED、E_BATCH_NOT_FOUND；脚本使用固定本地样本完成一次小规模逐块路径、一次大规模批量路径并比对两者结果一致、一次损坏块注入与一次强制终止后恢复续取，输出各批次所选路径、峰值内存、结果摘要与差异。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证预算裁决、两路径结果逐位一致、分页拼接及强制终止后恢复续取。
