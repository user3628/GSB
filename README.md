在 Windows 空白工作区中，需要从零构建一个面向本地单机推理服务的批处理调度与精度诊断工作台，供推理平台工程师离线评估批次组织对延迟与显存的影响。服务以本地确定性样本提供模型清单（模型标识、单样本显存字节、单样本计算代价微秒、最大批样本数）与请求轨迹（到达毫秒时间戳、模型标识、样本数、期望批延迟上限、优先级）。工作台按批样本数上限与节点剩余显存组织批次，依据单样本代价估计批延迟，计算每个批次的 P50/P95/P99 估计延迟与显存占用，并与从同一轨迹推导的逐条真值逐项核对：真值来源为样本中声明的单样本代价与显存乘加关系，估计来源为引擎自身的定点累计路径。核心难点是数值精度与误差传播：显存按字节整数累计，延迟按微秒定点累计再换算分位，批次重组、超时拆分与显存碎片回退会让多级乘除与累计求和的舍入误差逐层放大，导致同一轨迹在不同路径下命中率与判定结论不一致。用户通过本地 HTTP 接口提交轨迹、触发批次组织、查询每批分位延迟与显存预算明细及误差说明，工作台以本地静态页面展示批次时间轴、显存水位与误差传播链。

任务环境与准备：
在 Windows 空白工作区创建项目目录并初始化 Python 虚拟环境。
安装 Python 3.11 及以上、NumPy、FastAPI、Uvicorn 与 SQLite 相关依赖，版本以本地可安装为准。
准备固定本地确定性样本文件：模型清单、请求轨迹与量纲异常记录各一份，样本不含真实账号、网络服务或外部数据。
启动本地 HTTP 服务与静态诊断页面资源，全部在回环地址运行，不依赖容器或外部站点。
预留演示步骤：正常批次组织、碎片降批、强制终止后重启恢复，均由脚本驱动本地样本完成。

业务要求：
1. 实现模型清单与请求轨迹的解析和归一化：显存以字节整数、代价以微秒整数为内部表示，解析样本中形如 512Mi、2Gi、1500us、3ms 的量纲字符串并做溢出与负数检查；解析失败或模型标识未知的记录整批拒绝并返回业务码 E_SPEC_INVALID，轨迹到达时间戳非单调时返回 E_TRACE_INVALID 且不写入任何批次。
2. 实现批次组织：按模型标识与到达顺序把请求装入批，批的合计显存为各请求样本数乘单样本显存之和且不得超过节点剩余显存与模型最大批样本数，超出时按确定规则拆分为多批；优先级不同的请求不得混入同一批，拆分产生的批须保留原始请求标识与到达顺序，输出每批的组成清单与拆分原因。
3. 实现批延迟估计与分位计算：每批延迟由各请求样本数乘单样本代价累加得到，累加使用补偿求和，P50/P95/P99 采用声明的确定性最近秩法并注明样本规模；样本数不足以计算所请求分位时返回业务码 E_INSUFFICIENT_SAMPLES 而非静默返回零值或空值。
4. 实现定点数值契约：显存与延迟的中间累计一律使用整数或显式定点表示，延迟换算为毫秒时按声明舍入方式处理并输出每批的舍入位与累计舍入误差；同一轨迹重复组织与重算必须得到逐位一致的批次结果与分位值，禁止因浮点运算顺序不同而使判定结论翻转。
5. 实现与真值的逐项核对：真值由样本声明的单样本显存与代价直接乘加得出，引擎估计值与真值的偏差须逐批输出绝对偏差与相对偏差，并声明可接受的偏差上界；任一指标越过上界时整批标记为校验失败并返回业务码 E_PRECISION_DRIFT，同时保留可用于定位的具体批次与字段。
6. 实现显存碎片与批延迟上限的取舍：当某请求可与其他模型请求共处一个显存区域但会使批延迟超过期望上限时，须拒绝混批并给出原因；碎片导致批无法装入时按确定规则尝试重组或降批样本数，降批后各请求的样本数必须重新满足模型最大批样本数约束，并输出降批前后的位图式显存占用变化。
7. 使用 SQLite 持久化轨迹批次、批次组成、分位结果与意图日志，所有写操作先落意图记录再提交事务；进程在批次组织或分位计算中途被强制终止后重启须扫描未完成意图，把批次标记为已中止或回滚到最后一次完整提交，恢复报告只基于已持久化事实，不得承诺强制终止后仍生成完整退出报告。
8. 提供本地 HTTP 接口与诊断页面：接口覆盖轨迹提交、批次组织触发、按批次查询分位延迟与显存预算明细、误差说明查询、真值核对结论查询与恢复报告查询，统一错误响应为含业务码的 JSON（至少覆盖 E_SPEC_INVALID、E_TRACE_INVALID、E_INSUFFICIENT_SAMPLES、E_PRECISION_DRIFT、E_BATCH_NOT_FOUND）；页面展示批次时间轴、显存水位与误差传播链，并用固定本地样本完成一次正常组织、一次碎片降批与一次强制终止后恢复的演示。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
