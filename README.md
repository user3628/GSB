当前是空白工作区，需从零构建一个本地可运行的视频预测与运动时序状态演进引擎，交付领域数据编辑与操作应用。输入为固定随机种子生成器产出的本地确定性样本：一组低分辨率帧序列（.npy，形状 [帧数, 高, 宽]，像素为 0-255 整数），每段序列含匀速平移的方块、缓慢变形的色块与一次方向突变，另附一份 JSON 运动清单，逐序列声明初始状态（位移、速度、加速度衰减系数、形变幅度）、预测步数、每步期望状态取值范围与序列帧数，作为观测与真值来源；清单还声明每个序列的总帧数上界与逐步预测的时间轴对齐方式（以帧为单位的整数步）。引擎需以多步滚动方式推演运动状态：每步由当前状态经速度更新与形变演化得到下一状态，再据状态渲染预测帧，并将预测帧与后续真值帧比对得到逐步误差。工作台必须支持在推演中途停止并从持久化检查点恢复，使恢复后的状态轨迹、预测帧摘要与误差汇总与一次从零完整推演逐字节一致；同时须识别清单或帧内容变化带来的状态失效并只重建受影响链路。

任务环境与准备：
安装 Python 3.10 及以上版本与 NumPy，确保可在命令行运行；无需 GPU、容器或外部服务。
在空工作区中创建项目目录与本地样本生成脚本，以固定随机种子产出至少 3 段低分辨率帧序列 .npy 与对应运动清单 JSON。
准备本地 HTTP 与命令行运行所需的 Python 标准库组件，确认端口可本地绑定；运行前先生成演示样本并记录其内容指纹以便校验。

业务要求：
1. 实现运动状态滚动推演核心：按清单初始状态逐步更新位移、速度与形变参数，速度按配置的加速度衰减系数更新，每步状态须落在清单声明的取值范围内，越界须钳制并记录钳制步与分量；同一输入与配置必须产生逐字节一致的状态轨迹，禁止使用任何真实视频生成模型或外部服务。
2. 实现确定性的预测帧渲染：依据每步状态对低分辨率画布执行平移与形变变换，采用双线性采样与边界裁剪，将浮点结果量化回 0-255 像素；渲染须复用本地样本的分辨率与真值帧布局，输出每步预测帧摘要（均值、方差与帧指纹），同一步同状态渲染结果必须逐字节一致。
3. 实现逐步误差与时间轴对齐汇总：把每步预测帧与清单中对应后续真值帧比对，计算逐像素平均绝对误差与逐步误差曲线，并检查预测步数乘以步长是否超出序列真值帧数，超出时返回带序列标识与超出帧数的 E_TIMELINE_OVERFLOW；汇总须与逐步结果按同序累加一致。
4. 实现持久化状态检查点：每完成一个不可拆分的滚动步即原子写入含序列标识、步索引、输入帧内容指纹、清单配置指纹、状态摘要与单调序号的记录，写入任意位置中断不得留下半写记录；恢复时必须忽略损坏、不完整或序号重复的记录，从最近一致检查点继续，已发布步不得重复推演。
5. 实现优雅停止与恢复一致性：进程收到停止请求时完成当前不可拆分的滚动步后退出，不承诺强制终止后生成退出报告；恢复后最终状态轨迹、逐步误差与帧摘要必须与一次从零完整推演输出逐字节一致，且检查点序号连续推进、无跳跃与重复。
6. 实现版本变化检测与增量失效传播：当某序列的帧内容、初始状态、预测步数、步长、衰减系数或渲染参数任一变化时，通过各阶段内容摘要构成的版本指纹识别受影响的最早滚动步，使该步及其全部下游状态与误差失效并重建，未变化序列继续复用；失效原因与指纹须在查询接口中可观测。
7. 实现并发状态发布保护与业务错误码一致性：多个工作进程对同一工作区发布滚动状态时使用文件锁并比较序列内步序号，仅允许序号连续推进，落后、重复或跨序列错位发布返回 E_STALE_CHECKPOINT；请求恢复一个非法步、缺失前置状态或清单声明与实际帧数不符时返回 E_INVALID_STATE 并附序列标识与位置。
8. 提供可交互应用与本地确定性演示：命令行与本地 HTTP 接口支持导入帧序列与运动清单、触发分步推演、查看逐步状态与误差、查询各序列检查点状态与版本指纹、请求停止、执行恢复；演示数据至少 3 个序列，含匀速、形变与方向突变，一次完整推演生成固定摘要，并在中途停止后恢复比对一致性。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
