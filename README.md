当前是空白工作区，需要从零实现一个面向本地服务网格数据面场景的限流治理引擎，用于在离线环境下复现真实服务网格限流器与并行请求调度协同的核心机制。引擎管理一组路由（虚拟主机、路径前缀、目标上游集群），每条路由声明本地限流令牌桶（每窗口令牌数、窗口长度、突发容量）与上游集群的整体预算（单轮最大放行请求数）。请求由本地客户端桩并行发起，携带路由键、服务端时间戳、重试序号与幂等键。引擎须在真实并发压力下完成令牌扣减、预算准入、超限拒绝与排队推迟，并把每次决策持久化到 SQLite 以便重启后恢复窗口计数与排队状态。难点在于多窗口令牌桶与单轮预算两套资源约束并行生效，重试请求会放大令牌消耗，排队推迟又可能让令牌桶窗口跨越导致预算误判，必须在并发与资源控制、状态恢复和异常链路之间做取舍，而不是简单拒绝或无限排队。

任务环境与准备：
安装 Python 3.11 或以上，并在本地虚拟环境中安装 pytest 与标准库以外的必要依赖（如无需额外包则可省略）。
确认工作目录为空，准备本地样本配置目录用于存放路由与集群的 JSON 配置样本，所有探测与客户端桩均使用本机回环地址，不访问外网。
运行前确认 SQLite 可用（随 Python 标准库分发），测试使用临时目录隔离数据文件，保证重复执行结果可复现。

业务要求：
1. 实现路由与上游集群的配置模型及校验：路由含虚拟主机、路径前缀、目标集群、每窗口令牌数、窗口长度与突发容量；集群含单轮预算上限与排队超时。校验须拒绝非正令牌数、非正窗口长度、突发容量小于等于零以及同一虚拟主机下重复路径前缀，非法配置返回业务码 E_BAD_CONFIG，且不得进入限流运行态。
2. 实现令牌桶窗口的精确扣减与并发互斥：同一路由的令牌扣减须在路由一致性边界内串行化，扣减前须以服务端单调时钟判定窗口是否翻页并重置令牌；突发容量允许超出稳态速率但不得超过配置上限。并发请求不得超额扣减导致令牌数为负，所有扣减须记录窗口序号与剩余令牌。
3. 实现单轮预算与令牌桶的双约束准入：请求须同时通过路由令牌扣减与上游集群单轮预算才可放行，任一不满足须拒绝并给出首个触发约束名与当前值；预算耗尽时按到达顺序进入该集群的排队队列而不是立即丢弃，排队须有真实超时等待并返回 E_QUEUE_TIMEOUT，队列中的请求不得预先扣减令牌。
4. 实现重试序号与幂等键的计数语义：同一幂等键的重试请求不得重复消耗令牌与预算，须按首次决策结果回放判定；重试次数超过配置上限须返回 E_RETRY_EXHAUSTED 并计入拒绝统计；被拒绝请求的重试不得绕过排队约束直接扣减预算，重试计数须与窗口序号一并持久化。
5. 实现排队推迟与窗口翻页的交互一致性：排队超过一个令牌桶窗口的请求在出队时必须按出队时刻重新判定窗口与剩余令牌，不得沿用入队时已过期的窗口余量；若出队时该路由已被移除须返回 E_ROUTE_GONE 并释放其占用的预算名额；预算名额只在放行时占用，出队拒绝须保证预算计数不被泄漏。
6. 实现 SQLite 持久化与重启恢复：路由窗口状态（窗口序号、已扣令牌数）、集群预算批次计数、排队队列与幂等键决策记录须在每次决策提交点以单事务写入；重启后须恢复窗口计数与队列次序，把中断时处于放行中的请求标记为中止且不占用预算，恢复后同一批次内的剩余预算须与重启前一致。
7. 实现真实并发调度与资源控制：通过本地 HTTP 接口接收并行请求并在配置的最大在途请求数约束下调度，超出在途上限须有序推迟而非丢弃；同一路由的令牌扣减与不同集群的预算占用须分别串行化以保证互不阻塞；并发写入 SQLite 须使用真实事务锁等待超时并返回 E_CONTENTION_TIMEOUT，不得以线程休眠伪装隔离。
8. 提供本地客户端桩、诊断报告与可重复测试：实现可配置到达速率、重试行为与到达乱序的本地客户端桩驱动并发压测，输出每路由的窗口扣减、预算占用、拒绝与排队明细及诊断摘要；pytest 用例须在 Windows 离线覆盖并发超额拒绝、预算排队超时、重试回放、窗口跨界重判、重启恢复与锁等待超时。
