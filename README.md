在全新工作区中，需要为安全检测团队构建一个本地可运行的注入检测与上下文编码裁决引擎。业务输入是多类可疑载荷样本与对应宿主上下文声明：输入载荷包含 SQL 拼接、命令拼接、路径拼接与模板占位四类注入面，上下文声明给出载荷落点（字符串字面量、标识符位置、命令参数位、文件路径段、模板插值位）及该位置的编码要求（单引号转义、标识符引用、参数化占位、路径分隔符归一、HTML 实体）。引擎须对每条载荷在给定上下文中模拟落地后的规范化形式，判定其是否越出所在上下文的语法边界，并给出可定位的裁决码与归一化前后字节偏移。引擎还需支持并发批量检测、带版本号的裁决快照、进程被强制终止后的恢复，以及通过外部参数注入异常样本进行可复现验证，交互侧与结算侧的判定必须保持逐条一致。

任务环境与准备：
安装 Go 1.22 或以上版本，确认 go version 可在 Windows 命令行执行。
准备 SQLite 支持：使用纯 Go 驱动（如 modernc.org/sqlite），通过 go get 获取依赖，无需外部数据库服务。
无需网络账号或外部服务，全部样本由程序内置生成器在本地临时目录内确定性产出。
运行 go mod init 初始化模块并拉取依赖，确保 go build ./... 可在本地通过。

业务要求：
1. 实现载荷与上下文声明的本地解析与规范化模型：从 JSON 上下文声明与带长度前缀的文本块载荷集读取输入，统一为含样本标识、载荷原文、落点类型与编码要求集合的内部模型；解析时校验落点类型受支持、编码要求非空与标识唯一，非法输入返回 E_CONTEXT_INVALID 并记录来源偏移，不得让单条非法声明中断整批解析。
2. 实现按上下文编码的落地模拟与越界判定核心：对每条载荷按落点类型与编码要求执行确定性编码模拟，得到落地后的规范化形式，并在该形式中定位越过上下文语法边界的首次偏移；判定的依据只能是实际编码后的字节位置与上下文边界标记，不得使用关键词黑名单替代，越界时给出 E_CTX_ESCAPE 并记录规则标识、原始载荷偏移与落地偏移。
3. 实现交互侧与结算侧逐条一致性裁决：交互侧在收到样本时即时给出初步判定，结算侧在批次关闭后综合全部样本给出最终判定；两侧结果必须按样本标识与规则标识逐条一致，当结算侧因乱序到达或后到样本修正先置结论时须显式标注修正来源并递增推理版本，不得静默覆盖。
4. 实现基于单调时钟的交互延迟采样与统计：对交互侧每次判定记录从接收样本到返回初步结果的耗时，使用单调时钟差值而不依赖墙钟，按落点类型与裁决码聚合样本数、平均、P95 与最大值；统计中的时间字段只使用固定采样标记，重复运行且输入不变时判定与统计摘要字节级一致。
5. 实现带版本号的裁决快照与整体替换识别：每完成一轮批次结算后在单个 SQLite 事务内提交递增版本号快照，记录判定摘要、规则集合版本与上下文声明版本；快照内容比较须识别整体替换式版本变化而非仅比对版本号，加载时校验版本链连续性，跳号返回 E_SNAPSHOT_VERSION 并回退到最近连续版本。
6. 实现并发批次调度与资源控制：多个批次在独立会话中裁决，会话间状态与推理版本隔离；并发度、单批次样本数与单样本编码字节上限可配置，超并发上限的批次进入等待队列而非直接拒绝，单批次样本数超限以 E_SAMPLE_BUDGET 终止该批次且不影响其他批次结论，在途批次计数须可观测。
7. 实现强制终止后的恢复一致性：在批次结算提交或快照提交过程中进程被强制终止后重启，依赖 SQLite 已提交事务恢复快照版本与批次进度，已提交批次不回退、未提交事务整体丢弃且该批次可重新裁决；恢复后若版本链跳号须以 E_SNAPSHOT_VERSION 拒绝加载并报告最近连续版本。
8. 实现异常注入验证链路与确定性报告：通过外部参数或配置文件构造空载荷、上下文越界声明、快照版本跳号、并发批次竞争与编码字节超限五类样本，分别断言对应业务码、受影响批次终态未被污染、其余批次结论不受影响；导出 JSON 报告包含各批次样本摘要、判定与偏移、延迟统计、快照版本链与业务码，按批次标识与样本序号稳定排序。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地确定性样本验证编码模拟、逐条一致性、异常注入与快照恢复，重复运行输出字节级一致。
