在全新工作区中，需要从零构建一个面向 SQL 解析与逻辑计算的领域数据编辑器，用于维护逻辑计划快照并与外部查询优化工具交换数据。快照包含扫描、过滤、投影、连接、聚合、排序等算子树及其列引用、谓词与统计绑定。外部工具使用两种可互换的持久化格式：紧凑二进制格式（含魔数、格式版本字节、大小端标记、记录长度前缀、CRC32 校验与可选字段存在位图）与分片 JSON 行格式（每行一个算子或一个统计绑定）。编辑器需要加载快照、按兼容矩阵裁决格式版本、对旧版本缺失字段做降级补齐、拒绝高版本未知必填字段，并在内存索引与 SQLite 表之间原子切换快照。加载后支持对算子树做结构编辑（增删算子、改谓词、改列引用、调整连接顺序），每次编辑以带基础版本的增量片段提交，只重建受影响的派生结构（算子树摘要、列引用索引、谓词依赖索引与代价估计），任何派生结构都不得出现半更新可见状态。核心难点是格式互操作与版本兼容叠加在增量编辑之上：增量片段的基础版本可能因导入产生的新快照序号而失效，旧格式算子可能缺少列引用或统计绑定，树编辑又会改变后续导入的兼容判定；进程可能在导入或重建中途被强制终止，重启必须依据持久化意图恢复一致状态。

任务环境与准备：
安装 Go 1.22 或以上（Windows 发行版安装包），执行 go version 确认可用。
使用 Go 标准库 encoding/binary、hash/crc32、encoding/json 与 database/sql；SQLite 驱动可使用纯 Go 实现或本地 C 库绑定，在项目开始前确定并写入 go.mod。
准备固定本地样本：两份逻辑计划快照（一份旧格式版本缺列引用与统计绑定，一份高版本含未知必填字段）、若干增量片段与降级明细预期，全部置于项目内 samples 目录，不依赖网络或外部账号。
提供本地 HTTP 入口用于强制终止演练：以独立进程运行编辑器，由测试方在指定步骤终止进程后重启并查询恢复报告。

业务要求：
1. 实现逻辑计划算子树的内部模型：算子节点包含算子类型（Scan、Filter、Project、Join、Aggregate、Sort）、节点标识、子节点引用、列引用列表、谓词表达式与统计绑定，树中节点标识全局唯一且列引用必须指向上游已产出的列，违反时返回业务码 E_PLAN_INVALID 并拒绝整批加载。
2. 实现两种持久化格式的编解码：紧凑二进制格式必须含魔数、格式版本字节、大小端标记、每条记录长度前缀、CRC32 校验与可选字段存在位图；分片 JSON 行格式每行含算子标识、算子类型、父算子标识、列引用、谓词与可选统计绑定；任一格式解析失败返回 E_FORMAT_CORRUPT 并指明记录序号与校验值。
3. 实现格式协商与版本兼容裁决：导入前检测输入格式与格式版本，按显式声明的兼容矩阵给出接受、降级接受或拒绝三种结论；旧版本缺少列引用或统计绑定时走降级接受并按声明默认值补齐并记录降级明细，高版本含未知必填字段的数据返回 E_FORMAT_UNSUPPORTED 且不修改已加载快照。
4. 实现快照整体替换与版本识别：快照文件携带格式版本、快照序号与生成时间，加载时须校验版本兼容性与序号单调，加载过程在内存算子树索引与 SQLite 表之间原子切换，切换成功后才释放旧快照资源；任何校验失败必须保持旧快照完全可用，序号回退返回 E_SNAPSHOT_STALE。
5. 实现算子树结构编辑与增量片段提交：增删算子、改谓词、改列引用与调整连接顺序均以只含受影响算子及其祖先链的增量片段提交，片段携带基础版本号，基础版本非当前版本时返回 E_STALE_BASE 且不改变任何已提交状态；同一基础版本的两个并发增量只允许一个成功、另一个必须收到 E_STALE_BASE。
6. 实现派生结构的级联失效与原子重建：算子树摘要、列引用索引、谓词依赖索引与代价估计须维护对算子字段与树边界的引用关系，受影响的派生结构必须在同一事务边界内原子重建，禁止出现算子树摘要已更新而列引用索引仍指向已删除列、或代价估计按旧树结构计算的中间可见状态；查询只能看到某一完整提交版本。
7. 实现单写者提交与多读者查询的并发一致及幂等：快照导入、增量提交与级联重建按提交串行执行，多个只读查询（算子树结构、派生索引、降级明细）可并发读取某一完整提交版本；同一提交标识重复提交只执行一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_REQUEST。
8. 使用 SQLite 持久化快照版本、算子、派生索引与意图日志，导入、增量提交与重建前先写意图记录再提交事务；进程在导入或级联重建中途被强制终止后重启须扫描未完成意图，把快照与派生结构回滚到最后一个完整版本或将增量标记为已中止，恢复报告只基于已落盘事实；所有失败响应为含业务码与上下文的 JSON，至少覆盖上述全部业务码。
