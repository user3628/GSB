当前是空白工作区，需要在 Windows 本地从零构建一个面向多组件服务拓扑的故障隔离与容灾切换仿真台。仿真台读取本地确定性拓扑样本（服务节点、依赖边、副本分布、故障域、切换策略与预算参数）与一份故障注入计划，按计划并行地在多个故障域注入故障（节点不可用、依赖链路超时、副本延迟抖动），并在固定的并发预算与每轮时间预算内推进隔离裁决与容灾切换，输出每个服务在每轮的状态（HEALTHY、DEGRADED、ISOLATED、FAILED_OVER、FAILED）、切换是否成功、预算消耗与剩余、被跳过或被延后的注入项清单。难点在于并行调度与资源预算高度耦合：注入并发上限、每轮时间预算、故障域隔离配额与切换操作配额互相约束，注入与切换并发时状态演进必须一致，进程被强制终止后又要依据持久化事实恢复。用户通过本地 HTTP 接口提交拓扑与注入计划、查询轮次结论与预算明细、触发恢复报告。

任务环境与准备：
Windows 10/11，安装 Python 3.11 或以上并确保 python 与 pip 可在命令行使用。
创建空白项目目录，安装 FastAPI、uvicorn、NumPy 与 pytest（pip install fastapi uvicorn numpy pytest），版本以安装时可用稳定版为准。
准备本地确定性拓扑样本、故障注入计划样本与若干本地 HTTP 测试端点脚本（可返回成功、连接拒绝、挂起与延迟），全部随项目以文件形式提供。
使用 SQLite 作为持久化存储，无需外部数据库或容器环境；运行与演示均在本地回环地址完成。

业务要求：
1. 实现拓扑与注入计划的解析和归一化：节点声明服务名、副本数、故障域、依赖边与切换策略，故障注入项声明目标服务、故障类型（节点不可用、链路超时、副本延迟抖动）、持续轮数与优先级；解析失败或依赖成环时返回业务码 E_TOPOLOGY_INVALID 且整批不加载，同一拓扑重复提交须幂等复用。
2. 实现故障域隔离裁决：每个故障域声明隔离配额（该域内同时处于注入态的服务上限），注入项按故障域配额准入，准入后占用配额并须在同一事务内计入域内占用；超配额返回 E_FAULT_DOMAIN_FULL 并附当前占用明细，配额释放与注入结束必须在同一次提交中原子生效。
3. 实现并行注入调度，以全局注入并发上限与每轮时间预算双重约束执行：预算内按优先级与故障域轮转取任务，超出并发上限者进入有界等待队列，队列满返回 E_INJECTION_QUEUE_FULL；同一服务在同一轮中不得被重复注入，被跳过项须记录原因（配额不足、并发不足、时间预算耗尽）并可查询。
4. 实现真实可中断的注入执行：节点不可用通过本地 HTTP 测试端点的真实连接拒绝或超时体现，链路超时与延迟抖动通过真实连接超时并关闭底层连接体现，超时后必须释放资源并返回 E_INJECTION_TIMEOUT；单个注入挂起不得阻塞同轮其他注入，也不得使整轮越过时间预算继续执行。
5. 实现容灾切换与隔离的联动裁决：注入导致服务副本不可用时按切换策略把流量切至其他故障域副本，切换须同时校验目标副本可用性与切换操作配额，切换失败返回 E_FAILOVER_DENIED 并附失败原因；服务状态与切换记录、隔离记录必须在同一事务边界内生效，禁止出现切换成功而隔离记录仍为注入前的中间可见状态。
6. 定义服务状态机，至少包含 HEALTHY、DEGRADED、ISOLATED、FAILED_OVER、FAILED 五种状态并规定合法迁移路径，非法迁移返回 E_INVALID_TRANSITION 且不修改已持久化状态；恢复报告基于已持久化事实判定各状态的前后差异与回滚依据，只描述可观测到的事实。
7. 实现预算取舍与并发一致：当注入项规模超出并发与时间预算可覆盖范围时，按优先级与故障域轮转给出确定性跳过次序并输出预算消耗明细（注入配额、切换配额、时间预算余量）；并发提交同一拓扑的不同计划轮次可并行推进，但同轮注入与切换需按单写者串行并通过请求标识幂等，查询只能看到某一完整提交版本。
8. 使用 SQLite 持久化拓扑、注入步骤、预算占用与裁决结论，写操作先写意图记录再提交事务；进程在注入或切换中途被强制终止后重启须扫描未完成意图，把轮次标记为已中止并将故障域配额与切换配额回滚到最后一个完整版本，恢复报告不得承诺强制终止后仍生成完整退出报告。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
