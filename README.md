团队准备新建一个项目，在 Windows 本地从零构建一个面向正向代理场景的上游连接池诊断工作台，供网络运维人员离线评估慢接收端与连接复用对上游连接池的影响。工作台以本地确定性样本描述一组上游端点（端点标识、最大连接数、单连接最大复用次数、空闲回收毫秒、健康状态）与一份客户端请求轨迹（毫秒时间戳、客户端标识、目标端点、请求字节数、期望上传速率字节每秒、期望响应字节数）。工作台需按请求轨迹向本地回环上游测试服务真实建立与复用 TCP 连接，维护每条连接的阶段（IDLE、CONNECTING、HANDSHAKING、SEND_BODY、RECV_RESPONSE、DRAINING、CLOSED）与每端点的连接池占用，对慢接收端执行确定性的写入限速与背压，并在连接池耗尽时按声明的排队与拒绝策略裁决。运维人员通过本地 HTTP 接口提交轨迹、查询连接池快照与单连接阶段轨迹。难点在于连接池耗尽与慢接收端恢复的结构一致性：同一轨迹无论整批还是分段提交、无论查询发生在推进中途还是结束后，都必须得到相同的池占用与连接阶段序列；进程可能在写入或回收中途被强制终止，重启后必须依据持久化事实恢复连接池与连接阶段，续算结果须与未中断时逐项一致。

任务环境与准备：
在 Windows 上安装 Go 1.22 或更高版本，用 go version 确认可用，并确保 GOBIN 与模块缓存可写。
安装 SQLite 命令行工具以便抽查持久化表内容，Go 侧使用纯 Go 的 SQLite 驱动，无需本地数据库服务。
准备固定本地端点规格与请求轨迹样本，以及初始窗口、空闲回收毫秒、检查点间隔等配置，放入工作区样本目录。
确认本地回环端口可用于 HTTP 接口与上游测试服务，演练用独立进程启动以便从外部终止。

业务要求：
1. 实现端点规格与请求轨迹的解析和归一化：端点声明最大连接数、单连接最大复用次数、空闲回收毫秒与健康状态，请求声明毫秒时间戳、目标端点、请求字节数、期望上传速率字节每秒与期望响应字节数；最大连接数与复用次数须为正整数、空闲回收毫秒为非负整数并做溢出检查，解析失败或引用未声明端点返回业务码 E_SPEC_INVALID 且整批不入池。
2. 实现单连接阶段状态机，至少包含 IDLE、CONNECTING、HANDSHAKING、SEND_BODY、RECV_RESPONSE、DRAINING、CLOSED 七种并规定合法迁移路径；连接复用须从 IDLE 经 HANDSHAKING 回到 SEND_BODY 且累计复用次数不超过端点上限，超过上限的连接只能进入 DRAINING 再到 CLOSED，非法迁移返回 E_INVALID_TRANSITION 且不改变已持久化状态。
3. 实现连接池获取、复用与耗尽的裁决：池空闲连接优先复用，不足且未达端点上限时新建，达上限时按声明的排队策略进入有界等待队列，等待超时返回 E_POOL_ACQUIRE_TIMEOUT 并附已等待毫秒数；同一连接不得被两个请求同时持有，并发获取同一端点时仅一个成功取得该连接，其余进入等待或按策略返回 E_POOL_EXHAUSTED。
4. 实现真实连接建立与慢接收端写入背压：连接建立须对本地回环上游测试服务真实拨号，连接拒绝与拨号超时须真实关闭套接字并分别返回 E_DIAL_FAILED 与 E_DIAL_TIMEOUT；发送请求体时按期望上传速率进行确定性限速并在单次写入超时后真实关闭连接返回 E_SEND_TIMEOUT，不得以等待冒充超时。
5. 实现连接回收与池占用释放的结构一致：连接进入 DRAINING 后不再接受新请求，已在途写入完成或超时后才可迁至 CLOSED 并释放其池槽位；释放须在同一事务边界内归还端点槽位、更新空闲连接有序队列与活跃连接计数，禁止出现连接已 CLOSED 而端点槽位仍未归还的中间可见状态。
6. 实现整批与分段提交一致的快照语义：同一轨迹一次提交或按时间戳分段提交，查询得到的任一时刻端点占用数、空闲连接队列、连接阶段序列与排队明细必须逐项一致；查询可指定轨迹时刻取得该时刻快照，分段边界不得改变连接复用判定与排队结果，重复提交同批次只推进一次，内容不一致返回 E_CONFLICTING_BATCH。
7. 实现单写者推进与多读者查询的并发一致：轨迹推进、连接阶段迁移与池占用更新按端点单写者串行执行，多个只读查询可并发读取已提交快照；查询只能看到某一完整提交版本，不得出现某连接已进入 SEND_BODY 而端点活跃计数仍为旧值的中间状态；并发提交不同批次时各自意图日志不得互相污染。
8. 实现基于 SQLite 的意图持久化与强制终止后恢复，并提供统一错误体与可重复演示脚本：写入、回收与阶段迁移前先写意图记录再提交事务，进程被强制终止后重启须扫描未完成意图，把未提交连接回滚为可获取、未提交阶段迁移回滚到最后一个一致检查点，恢复报告只包含已落盘事实；失败响应为含业务码的 JSON，至少覆盖 E_SPEC_INVALID、E_INVALID_TRANSITION、E_POOL_ACQUIRE_TIMEOUT、E_POOL_EXHAUSTED、E_CONFLICTING_BATCH 与 E_CHECKPOINT_CORRUPT；脚本用固定样本完成一次整批推进、一次分段推进后比对快照、一次池耗尽排队与一次强制终止后恢复续算。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用固定本地样本验证整批与分段推进的池占用及连接阶段一致、池耗尽裁决正确及强制终止后恢复续算一致。
