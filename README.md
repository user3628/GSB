某本地 LLM 工具链团队在无历史代码的 Windows 空白目录中启动词表治理子项目，需要一套可集成的分词词表迁移与编码一致性裁决组件与完整示例。历史语料与模型导出物中的分词词表并存三代结构：v1 以逐行文本保存 token 与整数 id，v2 增加特殊标记段与字节回退表但 id 仍为稠密连续编号，v3 改为稀疏 id 并携带合并优先级与字节回退区间；同一文本在不同版本词表下切分出的 token 序列并不相同，而下游 embedding 行号依赖 id 映射，迁移时必须给出确定性的等价性与不可逆损失裁决。语料与词表由程序内置固定种子生成器产出，含中英混排、emoji、零宽字符、重复 token 与 id 空洞，不依赖真实模型、GPU 或外部下载。

任务环境与准备：
安装 Go 1.22 或更高版本，确保 go 命令可用
使用 go mod init 初始化模块；可直接使用标准库 database/sql 配纯 Go SQLite 驱动，避免 CGO 与外部编译依赖
Windows 本地无需网络、GPU、真实模型或外部服务，三代词表与语料由程序内置固定种子生成器产出
准备可写工作目录用于 SQLite 数据库、阶段检查点文件与导出报告
以 go build 与 go test 运行，演示命令与 HTTP 监听端口在示例中说明

业务要求：
1. 实现三代词表格式的统一内部模型与双向编解码：内部模型以规范 token、稀疏 id、字节回退区间、合并优先级与结构版本描述一份词表；实现与 v1 逐行文本、v2 稠密编号分段文本、v3 稀疏 id 紧凑文本的双向转换，往返后规范 token 集合与 id 映射必须保持不变。
2. 实现跨结构版本的兼容解析与显式升级：导入 v1/v2 时按可配置规则推导字节回退表、补齐合并优先级并识别稠密编号中的 id 空洞，转换结果须标注补齐项、换算依据与不可恢复项；版本号与内容形态不符时返回带词表标识与位置的 E_VOCAB_VERSION。
3. 实现确定性分词编码核心：对语料文本按词表做最长匹配并结合合并优先级切分，emoji 与零宽字符须按字节回退区间归并而非拆散，输出带字符偏移的 token 序列与所用 id；同一文本与词表必须产生逐字节一致的编码结果，零宽字符被截断或回退区间越界须返回 E_ENCODING_INVALID。
4. 实现迁移等价性与不可逆损失裁决：把同一语料在新旧词表下分别编码，逐句比对 token 序列与 id 序列，输出精确一致、仅 id 重映射、切分变化与无法表示四类裁决及各自依据；不可表示样本须保留原文字符偏移与可定位原因，任何类别都不得静默归为一致。
5. 实现阶段检查点持久化与优雅停止恢复：每份词表按解析、兼容升级、编码校验、裁决四阶段完成时以原子方式写入含阶段名、词表内容指纹、结构版本指纹、配置版本、产物摘要与单调序号的记录，写入任意位置中断不得留下半写记录；收到停止请求时完成当前不可拆分单元后退出，不承诺强制终止后生成退出报告。
6. 实现版本变化检测与增量失效传播：当词表内容、语料分片、合并优先级、字节回退配置或裁决阈值任一变化时，通过各阶段内容摘要构成的版本指纹识别受影响的最早阶段，使该阶段及其全部下游编码与裁决产物失效并重建，未受影响上游产物继续复用，失效定位须可查询。
7. 实现 SQLite 事务化存储与并发发布保护：以事务写入词表版本、逐句编码摘要与裁决结论，同一词表同一阶段只允许一条有效记录；多工作进程发布时使用事务条件更新并比较阶段内序号，仅允许连续推进，落后、重复或跨词表错位发布返回 E_STALE_CHECKPOINT，缺失前置阶段产物返回 E_MISSING_CHECKPOINT。
8. 提供本地 HTTP 与命令行交互接口及确定性演示：支持导入三代词表与语料分片、触发分阶段迁移、查询各阶段状态与版本指纹、查看逐句裁决依据与失效原因、请求停止、执行恢复、导出迁移报告；演示数据至少 3 份不同结构版本词表与中英混排、emoji、零宽字符语料，一次完整运行产生固定摘要。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地确定性样本验证三代词表迁移、编码裁决与中断恢复后的逐字节一致性及错误码。
