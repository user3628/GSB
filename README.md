当前是空白工作区，需要从零实现一个面向本地单机多 GPU 模拟环境的「GPU 训练作业配额调度与显存碎片诊断工作台」，用于在离线环境下复现真实 ML 训练平台的核心调度机制。平台管理若干 GPU 设备（每卡显存容量、算力配额、分区槽位）与提交的训练作业（请求卡数、每卡显存、算力配额、优先级、预计时长、配额组归属）。调度器按配额组限额与设备碎片状况决定准入与放置，放置需同时满足显存、算力与分区槽位约束，拒绝作业必须给出碎片诊断。配额组限额随提交作业的数据规模动态变化：小作业聚合可提升利用率但加剧碎片，大作业独占可降低碎片但挤占配额。工作台须支持并发提交与抢占、调度中途失败、进程重启恢复、配额组限额与设备状态一致性，并通过本地 HTTP 与 SQLite 暴露可查询证据。

任务环境与准备：
Windows 10/11，安装 Python 3.11 及以上并确保 python 与 pip 可在命令行使用。
创建虚拟环境并安装 fastapi、uvicorn、numpy、pytest、httpx，全部从离线轮子或本地缓存安装，无外部服务依赖。
工作区为空目录，无需预置代码或数据；样本生成器与本地测试桩在本机创建，CPU 模拟 GPU，不使用真实 GPU 或容器。

业务要求：
1. 实现设备与作业的模型及校验：设备含标识、显存容量字节、算力配额单位、分区槽位数与当前占用；作业含标识、配额组、请求卡数、每卡显存、算力配额、优先级与预计时长。校验须拒绝非正数显存、超出单卡容量的请求、未知配额组与非法优先级，并以固定业务码返回错误。
2. 实现配额组限额与准入判定：每个配额组声明卡数与显存上限，已被占用与排队中预留的额度须一并扣减。准入须在满足组限额、设备剩余显存、算力与分区槽位四项约束时才允许，任一不满足须拒绝并给出首个触发约束名与当前余量快照。
3. 实现碎片感知的放置与回退：放置时须优先选择能放下且剩余槽位最少的最小适配设备，当任一设备均无法满足时按优先级与预计时长给出抢占候选集合；若抢占后仍无法满足则回退为拒绝，且被抢占作业必须可恢复重排而不能丢失其原始提交信息。
4. 实现动态配额组限额调整的取舍：支持在运行期按提交作业规模调整组限额，调低限额时须先阻止新准入，再对超出部分按优先级有序驱逐；驱逐与准入并发发生时不得出现某作业既被准入又计入被驱逐集合，调整前后占用账目必须自洽。
5. 实现显存碎片量化诊断：对每个设备按空闲槽位分布计算碎片度指标并给出可解释的分解项，诊断输出须包含最大可分配连续显存、被低利用率作业占用的槽位列表与提升可分配量的建议操作；诊断结果须与同快照下重新调度一次的结果一致。
6. 实现并发提交与调度事务：多个提交请求并发到达时，额度扣减、设备占用与作业状态迁移须在同一事务边界内串行化到配额组，不同配额组之间可并行；锁等待须有真实超时并返回 E_CONTENTION_TIMEOUT，不得出现额度重复扣减或设备被两作业同时占用。
7. 实现持久化与重启恢复的一致性：作业状态、额度账目、设备占用与调度事件须在决策提交点原子写入 SQLite；重启后须将中断的调度决策回滚到一致点、把运行中作业标记为可重排并恢复排队队列次序，恢复后的额度账目须与设备占用逐项吻合。
8. 提供本地 HTTP 接口与可重复测试：通过本地 HTTP 提交作业、取消作业、调整配额组限额、查询设备视图与碎片诊断、分页查询调度事件；提供固定随机种子的样本生成器驱动至少两轮规模差异明显的提交流，pytest 用例在 Windows 离线覆盖准入拒绝、抢占恢复、限额调整驱逐、并发争用与重启恢复。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证配额准入、碎片诊断、并发事务与重启恢复后账目一致。
