在 Windows 空白工作区中，需要从零构建一个面向本地回环环境的正向与反向代理转发工作台，用于管理一组代理路由（反向路由把请求转发到本地后端服务，正向路由按目标主机和端口经本地出口转发），并支持路由配置的增量更新与依赖失效诊断。每条路由由匹配规则（方法、路径前缀或目标主机）、上游地址、超时、重试、请求头和上游健康状态组成；配置以带版本号的 JSON 快照形式提交，允许只提交受影响的增量片段而不是整份配置。当某条路由的上游地址、请求头或超时发生变化时，依赖该路由的编译产物（匹配表、连接池分组、健康探测计划、转发规则缓存）必须级联失效并重建，而不能出现部分新部分旧的中间可见状态。所有后端与出口均为本地回环测试服务，数据来自固定本地样本，不依赖真实站点、账号或外部网络。

任务环境与准备：
使用 Windows 本机 Python 3.11 或以上，安装 asyncio 与 SQLite 由标准库提供，无需额外依赖。
准备固定本地样本：一条整份配置快照、一条只修改单条路由上游地址的增量片段、一条基于过期基础版本的增量片段。
准备若干本地回环 HTTP 后端测试端点，可返回约定状态码、返回 5xx、延迟响应以触发读取超时，以及一个拒绝连接的端口。
运行前确认回环端口未被占用，所有测试均在 127.0.0.1 范围内进行，不访问外部网络。

业务要求：
1. 实现代理转发核心：反向路由把入站请求按方法与前缀匹配转发到本地后端，正向路由按目标主机和端口经本地出口转发，正确转发方法、路径、查询串、请求头与请求体，并把上游响应状态码与响应体回传给客户端，需明确逐跳头部的处理边界。
2. 实现带版本号的配置快照与增量更新：提交服务端接收整份或增量片段，增量只包含受影响路由并携带基础版本；若基础版本不是当前版本则返回业务码 E_STALE_BASE 且不改变任何状态，快照整体替换时须识别版本变化并拒绝版本回退。
3. 实现依赖失效与级联重建：每条路由编译出匹配表项、连接池分组、健康探测计划与转发规则缓存；某路由的关键字段变化时其全部产物以及匹配该路由的聚合索引必须级联失效并原子重建，禁止出现部分产物已更新而另一部分仍指向旧上游的中间可见状态。
4. 实现转发与配置更新的并发一致：读请求路径不得看到半更新配置，更新期间已在途的请求按提交时绑定的路由版本完成转发；多个并发更新串行化执行，同一基础版本的两个并发增量只允许一个成功，另一个返回 E_STALE_BASE。
5. 实现上游健康依赖联动：后端健康状态由本地健康探测与真实转发结果共同决定，路由字段变化后旧探测计划失效并按新字段重新探测；当某上游被判定为不可用时，依赖该上游的路由须按配置的失败策略返回业务码 E_UPSTREAM_UNAVAILABLE 或切换到同组备用上游，且不得继续向已知不可用上游发送新请求。
6. 实现超时与异常链路：区分连接超时、读取超时、上游连接拒绝与上游返回 5xx，各返回稳定的业务码与 JSON 错误体；转发过程需真实关闭底层连接释放资源，不得以等待冒充超时；在途请求遇到配置更新时按绑定版本决定沿用旧上游还是以 E_CONFIG_CHANGED 终止，行为需确定且可解释。
7. 实现持久化与重启恢复：路由快照与版本历史持久化到 SQLite，提交事务前写入意图记录；进程被强制终止后重启须扫描未完成意图并把配置回滚到最后一个完整快照版本，恢复报告只基于已持久化事实；若采用安全退出信号则须完成在途请求或明确拒绝，两种退出路径的差异需在诊断输出中体现。
8. 提供可视化诊断工作台与端到端演示脚本：工作台以本地 HTTP 页面展示路由版本、各路由产物状态、上游健康、最近转发错误与级联失效轨迹；脚本使用固定本地样本完成一次全量提交、一次只改单条路由上游的增量提交、一次基于过期基础版本的被拒绝提交，并输出失效产物清单、重建产物清单与最终配置版本，便于人工核验。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地回环后端样本验证转发正确性、增量更新级联失效、过期基础版本拒绝与强杀后快照回滚一致。
