为图像重建三维几何团队构建一个本地可运行的离线重建诊断组件，核心问题是多视图位姿链解算与点云融合过程中的数值精度与误差传播。工作区为空，需从零创建项目。输入是本地样本目录：一份相机清单 JSONL，每条含 camera id、内参矩阵、由外参给出的旋转矩阵与平移向量、以及该相机在链上的父相机 id（首个相机父为空）；一份观测清单 JSONL，每条含 obs id、camera id、二维像素坐标与对应三维路标 id；一份路标初始估计 JSON，含每个路标 id 的三维坐标与初始协方差对角元；另有一份融合配置，声明视图链遍历顺序、三角化残差容差、点云泊松融合半径与浮点容差。组件需沿相机链解算路标三维坐标、按相机逐层融合点云，并输出每个路标与每台相机的不确定度与误差贡献，供建模人员判断重建结果是否可信。

任务环境与准备：
安装 Python 3.11 与 NumPy，创建项目虚拟环境并放置 requirements 清单。
在本地生成或放置相机清单、观测清单、路标初始估计与融合配置样本，均为 JSON/JSONL 纯文本。
确认 SQLite 可用（Python 标准库 sqlite3 即可），无外部服务与网络依赖。
准备确定性演示入口运行说明与 curl 复现示例所需脚本位置。

业务要求：
1. 组件须提供装载与校验入口，接收样本目录、融合配置与浮点容差，校验 camera id 与 obs id 唯一、父相机引用存在且相机链无环、旋转矩阵正交且行列式为正、内参可逆、路标初始协方差对角元为正、容差为正小数；任一非法返回 E_PARAM 或 E_GRAPH 业务码并定位到出错文件与行号或相机 id，且不得写出任何结果文件。
2. 位姿链解算须从根相机出发按链序逐层把观测投影到三维空间，累乘旋转与平移时在 float64 下按声明顺序计算并显式补偿正交性漂移；同一输入下每台相机的世界位姿（旋转与平移）与逐观测重投影残差须逐位可重复，不得依赖字典遍历顺序，重投影残差超三角化容差时须返回 E_REPROJ 并给出 obs id 与残差。
3. 路标三角化须以各观测的最小二乘残差加权求解，多相机关联同一路标时按相机链深度升序、同深度按 camera id 字典序稳定累加；未知路标或观测不足两台相机时须计入未解算统计并继续其余路标，不得使整体任务失败，最终每个路标须输出三维坐标与求解残差。
4. 误差传播须逐路标显式输出：不确定度由路标初始协方差、各相机位姿链累计误差与观测像素噪声按权重平方和合成，并给出各来源贡献分量；相机链上误差须按父到子递归传播而不是各相机独立估计，超容差路标须在诊断报告中定位到路标 id、主导误差来源与首个越界观测。
5. 点云融合须按相机链顺序逐层并入已解算路标，融合半径由配置给出，半径内已有路标须按逆不确定度加权合并且合并后不确定度须严格小于任一分量；融合顺序须确定且合并结果须与同序无中断执行完全一致，重复运行合成点云须逐点逐坐标逐位一致。
6. 融合状态须在 SQLite 中以相机、阶段、路标三级记录事务提交，单台相机层内的路标坐标、不确定度分量与进度标记须在同一事务中写入；某相机层融合失败时该层整体回滚且已提交层保持不变，不得留下部分路标或与快照版本不一致的记录。
7. 每次阶段完成须以整体替换方式生成版本化快照，含重建版本号、各相机层路标摘要与点云文件内容哈希；读取快照时若检测到数据库版本与磁盘点云哈希不一致、版本变化或残留旧版本点云文件，须返回 E_STALE 并定位到相机 id 与快照版本，禁止汇入旧数据。
8. 进程被强制终止后重启，须从 SQLite 已提交相机层进度继续，核对每层路标处理标记、点云文件内容哈希与快照版本，重算未提交层且不重复消费已提交路标；恢复后的逐路标坐标、不确定度分量、合成点云与快照版本序列须与无中断执行完全一致，并须提供确定性本地演示入口跑出可重复结果。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证链式解算、误差分量、点云融合与中断恢复结果一致可复现。
