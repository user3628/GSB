当前是空白工作区，需从零构建一个本地可运行的流式语音识别（ASR）分片解码管线，交付可交互的专业应用与可重复演示，核心业务目标是在音频分片可复现验证与异常注入条件下，保证流式解码结果与断点恢复结果的一致性，同时在解码算力预算内完成端点对齐。输入为固定随机种子生成器产出的本地 WAV 分片（16 kHz、单声道、16 位 PCM），每片含清晰语音段、静音段、语句内短停顿与突发冲击噪声；另附一份 JSON 清单，逐分片声明参考词级时间标注（毫秒起止与参考词文本）、分片顺序、声明样本总数与声明声谱参数，作为端点对齐与结果比对的唯一真值来源。系统不依赖任何真实 ASR 模型、外部服务或 GPU：声学前端以确定性分帧、汉宁窗与频带能量统计实现，解码以本地词表与固定哈希发射打分实现，输出词级起止毫秒、识别文本、置信度与每帧对齐轨迹。管线按四个阶段推进：前端特征化、流式解码、端点对齐校验、预算汇总。需提供本地 HTTP 与命令行接口，支持导入分片与清单、触发分阶段解码、查询阶段状态与版本指纹、请求优雅停止、执行恢复，并用本地确定性样本完整演示一次正常解码与一次异常注入验证。

任务环境与准备：
确认工作区为空，安装 64 位 Python 3.10 及以上版本，并保证 python 与 pip 在 PATH 中可用。
创建并激活本地虚拟环境，安装 numpy（2.x 系列）；HTTP 接口使用标准库 http.server 即可，不安装任何深度学习框架或音频处理专用工具包。
准备本地确定性样本生成脚本：以固定随机种子产出至少 3 个 16 kHz 单声道 16 位 PCM WAV 分片，覆盖清晰语音段、语句内停顿、全静音、幅值削顶与突发冲击噪声情形，并同步生成含参考词级时间标注、分片顺序与声明样本总数的 JSON 清单。
在分片目录与清单之外准备一份独立的工作区目录用于检查点与阶段产物，确认该目录在任务开始时不包含任何已有产物记录。
Windows 下需确认文件锁实现基于真实文件句柄（如 msvcrt.locking 或等价方式），并准备两个并发进程的本地发布验证脚本，检查其可在无管理员权限下运行。
准备一份异常注入参数清单（样本数不符、采样率冲突、非法帧参数、全静音与削顶分片），用于演示阶段通过外部参数或输入文件注入，不修改源码。
在本地记录一次完整运行的固定摘要作为基准，用于后续对比流式解码、断点恢复与从零完整运行三者结果一致。

业务要求：
1. 实现前端特征化阶段：按清单声明的帧长与帧移（毫秒，须能换算为整数样本数）对 16 位 PCM 做汉宁窗分帧，逐帧计算频带对数能量与谱平坦度特征；不得把毫秒帧移直接当作样本数使用，须显式记录换算后的样本偏移，帧边界跨越样本末尾时以确定性零填充并标记；同一输入与配置必须产生逐字节一致的特征摘要。
2. 实现流式解码核心：提供逐帧块喂入接口，按本地词表与固定哈希发射打分和确定性的转移权重在帧序列上做贪心扩展，输出词级起止毫秒、识别文本与每词置信度；单词只能在其后的最低静音帧数被确认后才允许发布，未确认词须以候选形式保留，禁止因分块大小变化导致词序列或起止毫秒不同。
3. 实现流式与整段解码的一致性校验：对同一分片，逐帧流式解码与整段一次性解码的词序列、每词起止毫秒与置信度必须逐字段一致；出现不一致时须返回带分片标识、首个差异词序与两路取值的 E_STREAM_MISMATCH，且不得只保留其中一路结果继续汇总，须保留差异上下文供诊断查询。
4. 实现端点对齐校验阶段：把解码得到的词级起止与清单参考词级时间标注按可配置毫秒容差比对，统计命中词数、时间偏差均值与最大值、越界词清单与语言混排词数；越界词须返回带分片标识、词序与偏差值的 E_ENDPOINT_MISMATCH 并保留在诊断中，指标计算不得从缺失信息推断，缺少参考标注的分片须显式标记为未校验而非按通过处理。
5. 实现解码算力预算下的分片调度：以分片为调度单元，在全局帧处理预算、单工作线程帧配额与单分片延迟预算共同约束下决定接纳顺序与并发度；接纳前依据清单声明样本总数与帧参数预估帧消耗，超预算分片记录为未处理并给出原因，任何时刻不得出现累计帧消耗越过预算后仍继续接纳新分片的情形。
6. 实现持久化阶段检查点与优雅停止恢复：每个分片每阶段完成时以原子方式写入含分片标识、阶段名、输入内容指纹、配置版本、产物摘要与单调序号的记录，写入任意位置中断不得留下半写记录；收到停止请求时完成当前不可拆分分片后退出，恢复时必须忽略损坏、不完整或序号重复的记录，从最近一致检查点继续，最终产物与从零完整运行逐字节一致。
7. 实现异常注入与业务错误码一致性：提供参数注入入口，支持注入清单声明样本数与实际样本数不符、采样率与清单声明冲突、全静音分片、幅值削顶分片、非法帧参数（帧移为零或大于帧长）等情况；各注入须在对应阶段返回稳定业务码（E_INPUT_LENGTH、E_SAMPLE_RATE、E_SILENT_AUDIO、E_CLIPPED_AUDIO、E_INVALID_FRAME），且注入只通过输入或参数进行，不得修改源码制造验收失败。
8. 实现版本变化检测与并发发布保护：当分片样本内容、帧参数、词表、发射权重或预算配置任一变化时，通过各阶段内容摘要构成的版本指纹识别受影响的最早阶段，使该阶段及其全部下游产物失效并重建，未受影响上游产物继续复用，失效原因与指纹须在查询接口可观测；多工作进程发布同一工作区阶段产物时须使用真实文件锁并比较阶段内序号，落后、重复或跨阶段错位发布返回 E_STALE_CHECKPOINT，缺失前置阶段产物时返回 E_INVALID_STAGE。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地分片样本验证流式解码与断点恢复结果一致、端点对齐达标，并核对异常注入返回约定业务错误码。
