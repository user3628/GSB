在 Windows 空白工作区中，需要从零构建一个面向本地单机数据库的检查点与 WAL 回放组件，供上层存储引擎集成。组件维护以页为单位的表空间（页号、页内容摘要、页版本号、最近修改 LSN），所有修改先追加到 WAL 日志（LSN 单调递增，记录页号、修改前后摘要、事务号与写入时刻），周期性地把内存中脏页与 WAL 位置写入检查点，使重启后的回放起点前移。数据规模会从数百条 WAL 记录增长到数十万条：小规模时逐条重放并逐页落盘成本低，大规模时需要批量重放、增量检查点与后台刷页以避免重启回放时间失控，但两条路径必须得到完全一致的最终页版本与摘要结果。WAL 段文件需要支持轮转、截断与归档，检查点元数据必须携带回放起点 LSN、页版本集合与校验摘要，且回放过程可中断续算。进程可能在任何时刻被强制终止，重启后必须依据持久化事实恢复一致状态。

任务环境与准备：
确认 Windows 本地已安装 Python 3.10 或以上，并可在命令行执行 python 与 pip。
安装依赖：pip install numpy，SQLite 使用 Python 标准库 sqlite3，无需额外服务。
在工作区创建 data 目录，放入确定性本地样本：页初始内容描述文件、WAL 记录序列脚本与检查点参数配置，均以 JSON 形式随任务一并生成。
启动脚本与测试均在本地回环执行，无需网络、外部账号、容器或特定硬件。

业务要求：
1. 实现页式表空间与 WAL 记录模型：页由页号唯一标识并保存内容摘要、版本号与最近修改 LSN；WAL 记录包含单调递增 LSN、页号、修改前后摘要、事务号、写入时刻与校验字段，记录解析失败返回业务码 E_WAL_CORRUPT 且整段不参与回放；同一页多次修改必须得到连续递增的页版本号，跨页互不约束。
2. 实现 WAL 追加与段文件轮转：追加需按配置段大小切换段文件，全部 LSN 跨段连续无缺口，段头记录起始 LSN 与校验摘要；段轮转必须原子生效，禁止出现两条记录占用同一 LSN 或段头起始 LSN 与实际首条记录不一致；只读查询可按 LSN 范围检索记录并返回其所在段标识。
3. 实现检查点元数据与整体版本替换：检查点记录回放起点 LSN、各页版本号集合与整体校验摘要，携带单调递增的检查点序号；加载检查点时须识别序号变化并整体替换旧检查点状态，不得把新旧检查点的页版本集合混合使用；校验摘要失败或序号回退返回 E_CHECKPOINT_INVALID 并保持原状态可用。
4. 实现 WAL 回放：从检查点记录的起点 LSN 起按 LSN 升序重放记录到页，逐条校验记录摘要与页当前版本的一致性，版本跳号或不匹配返回 E_REPLAY_MISMATCH 并附期望与实际 LSN；回放完成后各页摘要与版本必须与从未中断的基准一致，重复回放同一区间不得改变最终结果。
5. 实现数据规模自适应的回放与刷页路径：当待回放记录数与脏页数低于配置阈值时走逐条重放并逐页落盘的精确路径，超过阈值时走批量重放与分组刷页路径；两条路径对同一 WAL 前缀必须得到逐页一致的摘要与版本结果，并输出本次选择的路径、批量参数与选择依据。
6. 实现增量检查点与 WAL 截断的取舍：允许只对自上次检查点以来变化的脏页做增量检查点，但截断 WAL 段必须先确认该段所有记录的页修改已被检查点覆盖；未覆盖时拒绝截断并返回 E_TRUNCATE_UNSAFE 并附未覆盖 LSN 区间，禁止为了空间回收截断仍被回放依赖的段。
7. 实现单写者提交与多读者可见性：WAL 追加、检查点写入与截断按单写者串行执行，多个只读查询可并发读取已提交的检查点与页状态；查询只能看到某一完整提交版本，不得出现检查点已记录某页新版本而页当前版本仍为旧值的中间可见状态；同一请求标识重复提交只执行一次，其余等待并复用结果。
8. 实现基于 SQLite 的意图持久化与强制终止后恢复：WAL 追加、检查点提交与截断前先写意图记录再提交事务；进程在检查点写入或回放中途被强制终止后重启须扫描未完成意图，把检查点与页状态回滚到最后一个完整检查点或将批次标记为已中止，恢复报告只基于已持久化事实，不承诺强制终止后生成完整退出报告。
