项目初始状态是空目录，需要从零构建一个面向 Windows 的沙箱权限策略诊断工作台。沙箱策略以分层规则集描述文件访问、进程启动与注册表写入三类权限边界，规则之间存在显式依赖（如某条放行规则引用某个目录声明、某条拒绝规则覆盖某个进程组）。运维需要以增量方式将新版策略应用到本地状态库，并在应用过程中识别依赖失效：被删除或收紧的上游声明导致下游规则失去依据。工作台需维护带版本号的策略快照、对每次增量变更计算受影响规则闭包、在真实文件系统与进程边界上执行最小化探测以确认权限判定，并将诊断结果以可交互方式呈现。所有输入为本地确定性样本，不依赖真实账号或线上资源。

任务环境与准备：
安装 Go 1.22 或以上版本并确认 go 命令在 Windows 命令行可用；SQLite 通过纯 Go 驱动引入，无需系统级安装。
准备本地确定性样本目录：基线策略、若干变更集、畸形策略与冲突变更集各一份，均为静态文件，不依赖网络。
以 go mod init 初始化模块并拉取 SQLite 纯 Go 驱动依赖，完成后在无网络条件下可重复构建。
在 Windows 本地临时目录下运行探测相关命令，确保当前用户具备在该临时目录创建子目录与子进程的权限。

业务要求：
1. 实现分层策略模型的解析与规范化：支持目录声明、进程组、注册表路径三类上游实体与放行/拒绝规则，规则通过标识引用上游实体；解析时校验标识唯一性、引用可解析性与层级顺序，非法策略返回 E_POLICY_MALFORMED 并指出具体条目，规范化输出的字段顺序与排序必须稳定，保证同一输入在不同解析顺序下得到相同规范形。
2. 实现增量应用引擎：以“基线快照 + 变更集”方式将新版策略应用到 SQLite 状态库，变更集包含新增、修改、删除三类操作；应用须在单个事务内完成并生成新版本快照，版本号递增且旧快照整体保留，应用前后失败均不得留下部分写入，回退依据为已提交快照而非内存状态。
3. 实现依赖失效检测与受影响闭包计算：对每次删除或收紧操作，沿规则对上游实体的引用关系反向追踪，计算直接失效规则与传递失效规则集合；当上游目录声明被删除时其下所有引用规则标记 E_DEP_INVALIDATED，当上游进程组被收紧时标记 E_DEP_RESTRICTED，闭包结果须与快照版本绑定并可从指定历史版本重放。
4. 实现真实权限探测层：在 Windows 本地临时目录上以受限访问方式创建目录、文件与子进程，对策略声明的文件读写与进程启动边界执行最小化探测，探测结果与策略判定逐条比对；探测必须在独立临时工作目录内完成并在结束后清理，不得修改工作目录之外的文件权限，探测自身失败以 E_PROBE_FAILED 单独归类而不污染策略结论。
5. 实现策略快照版本演进与一致性校验：每次读取快照时校验版本链连续性，发现跳号或缺失则以 E_SNAPSHOT_VERSION 拒绝加载并回退到最近连续版本；快照内容比较须识别整体替换式的版本变化，即使版本号相同但内容摘要不同也须判定为不一致并拒绝混合使用。
6. 实现并发变更的资源控制：允许多个增量应用请求并发提交，按策略命名空间串行化同一命名空间的变更，在途事务数以可配置上限的信号量约束，超出等待阈值的请求返回 E_CHANGE_CONTENTION 而非无限阻塞；冲突与排队事件须记录命名空间、版本号与操作类型，且不得造成快照版本交错。
7. 实现异常注入验证链路：通过外部参数构造引用缺失、循环依赖、版本跳号、命名空间越权引用、变更集中的删除后新增冲突五类输入，分别断言对应业务码、状态库终态版本号未被推进与已提交快照未被污染；注入仅通过输入文件与参数完成，不修改源码。
8. 提供可交互诊断工作台与结构化输出：以命令子方式支持查看当前版本、按版本回放诊断、展示失效闭包、单条规则溯源依赖链；同时导出 JSON 诊断报告，包含快照版本链、受影响规则、探测比对结果与业务码，报告按规则标识稳定排序，相同输入重复运行结论字节级一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地确定性策略样本执行增量应用与失效诊断，核对快照版本链、失效闭包与探测结论一致。
