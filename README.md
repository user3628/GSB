交付从新建的代码库开始，某研发团队需要在本机离线构建一个依赖闭包完整性核验引擎，用于在构建前校验内部组件依赖图是否被人为降级或替换。组件依赖以两层数据给出：一层是组件清单，由程序内置生成器产出带魔数与长度前缀的紧凑二进制格式，记录组件标识、版本整数序列与摘要字节；另一层是依赖边声明，以逐行 JSON 给出父组件、子组件与约束版本。团队既关注单个组件的摘要是否与登记值一致，更关注在闭包范围内是否存在版本降级、循环依赖与约束冲突，并要求在组件规模从小到极大时自动切换核验路径且结论逐字节一致。引擎需持久化带版本号的核验快照，支持并发核验会话、中断恢复与外部参数注入的异常验证。

任务环境与准备：
安装 Go 1.22 或以上版本并确认 go 命令可用；SQLite 通过纯 Go 驱动集成，无需系统安装数据库服务。
在空目录执行 go mod init 初始化模块，按需引入 SQLite 驱动依赖并执行 go mod tidy，依赖可离线缓存。
准备本地确定性样本生成入口：由程序内置生成器产出二进制组件清单、依赖边 JSON 行及六类畸形样本，写入临时目录，不依赖网络与外部数据。
确认可在 Windows 命令行下执行构建与测试命令，工作目录具备普通文件读写权限，测试使用临时目录隔离，不访问真实仓库或线上服务。

业务要求：
1. 实现二进制组件清单的流式解析与模型规范化：按魔数与长度前缀逐条读取组件记录，提取组件标识、版本整数序列、摘要算法标识与摘要字节，严格校验每条记录边界不越出源缓冲；对截断、魔数不符、长度字段回绕分别给出 E_TRUNCATED、E_BAD_MAGIC、E_LENGTH_OVERFLOW，并保留已成功解析条目数与最后偏移。
2. 实现依赖边 JSON 行的解析与组件键规范化：逐行解析父组件、子组件与约束版本，把约束版本统一为可比较的整数序列视图，组件标识统一小写并保留命名空间分隔；对同一父组件出现的重复子组件边、指向清单中不存在组件的边分别给出 E_DUP_EDGE、E_EDGE_DANGLING，并记录行号与字段名。
3. 实现依赖闭包构建与版本降级判定核心：以指定根组件集合出发沿依赖边做闭包遍历，对每条边比较子组件实际版本与约束版本，实际版本低于约束时标记 E_VERSION_DOWNGRADE 并记录该边所在的父与子组件、两条版本序列，闭包遍历对环边不得无限展开。
4. 实现循环依赖与约束冲突裁决：在闭包内检测由依赖边构成的有向环，输出参与环的最小组件集合与边序列并标记 E_CYCLE；当同一子组件被多个父组件以互斥约束引用时标记 E_CONSTRAINT_CONFLICT，并给出冲突约束的并集与不可满足证明所需的两个边来源，裁决结果不得依赖边输入顺序。
5. 实现规模自适应的双路径核验：闭包组件数低于阈值时采用逐边精算路径并即时判断，高于阈值时先对边与组件建立排序索引再做批量路径核验；两条路径对同一输入必须产生逐字节一致的结论序列、业务码序列与环集合描述，阈值与所选路径须在输出中可观测且可被参数覆盖。
6. 实现带版本号核验快照与整体替换识别：每完成一轮核验后在单个 SQLite 事务内提交递增版本号快照，记录闭包结论、业务码、算法路径与摘要登记来源；快照内容比较须识别整体替换式版本变化而非仅比对版本号，加载时校验版本链连续性，发现跳号返回 E_SNAPSHOT_VERSION 并回退到最近连续版本，回退目标须写入报告。
7. 实现并发核验会话的资源控制与中断恢复：多个核验任务在独立会话中执行，会话间闭包状态隔离；并发度与单会话组件数上限可配置，超并发上限的任务进入等待队列而非直接拒绝，单会话组件数超限时以 E_ITEM_BUDGET 终止该会话并保留其余会话结论；进程被强制终止后重启依赖 SQLite 已提交事务恢复快照版本与任务进度，已提交快照不回退、未提交事务整体丢弃。
8. 实现异常注入与确定性报告入口：通过外部命令行参数或配置文件构造截断记录、悬挂边、版本降级、循环依赖、约束冲突与快照版本跳号六类样本，分别断言对应业务码、其余组件结论不受污染与快照版本未被推进；导出 JSON 报告按组件标识、边来源与业务码稳定排序，时间字段仅使用固定采样标记，重复运行且输入不变时报告字节级一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
