本地生活搜索团队的工作区里还没有任何代码，需要在 Windows 上从零交付一个多路召回融合的离线实验组件，用于在固定评估预算下比较词法倒排、类目协同与向量近邻三路召回的融合效果。程序内置固定种子生成器在本地产出 JSONL 样本：物品库（item_id、类目、隐因子向量、标题文本）与查询集（query_id、查询词、locale、历史点击类目序列），并附一份带版本号的融合配置（各路候选深度、融合权重、去重与截断规则、全局候选评估次数预算、单路评估配额与每轮时间预算）。组件需提供命令行与本地 HTTP 接口，执行召回、融合、评估三阶段并持久化到 SQLite，供上层实验平台集成。

任务环境与准备：
安装 Go 1.22 或更高版本并确认 go 命令在 PATH 中，无需外部网络下载依赖，SQLite 驱动使用标准库 database/sql 配合纯 Go 实现。
在空白工作区初始化 Go module，创建程序内置固定种子生成器，产出物品库、查询集与融合配置样本，样本规模覆盖数十至数千查询。
准备本地 HTTP 测试端口与命令行入口的运行脚本，所有数据与测试端点均在本机生成，不依赖真实账号、线上站点或外部数据集。

业务要求：
1. 实现三路召回打分核心：词法路按查询词与物品标题的词项重叠度打分，类目协同路按历史点击类目的物品频次打分，向量近邻路按查询特征与物品隐因子的余弦相似度打分；三路各自返回按分数降序、同分按 item_id 升序的候选及分数分量，空查询或空物品库须返回带 query_id 的 E_EMPTY_INPUT 而非空结果。
2. 实现候选深度与评估预算的自适应裁决：依据查询数、物品数、各路候选深度与全局候选评估次数预算、单路评估配额，为每轮决定各路是否启用及截断后的候选深度，并记录选择理由、预测消耗与被淘汰路原因；累计消耗超预算时未处理查询记录为未处理并给出原因，不得静默丢弃。
3. 实现可配置多路融合与去重：支持加权求和与倒数排名融合两种策略，同一物品被多路召回时须合并分数并记录来源各路的排名、分数与贡献，去重后结果不得出现重复 item_id；截断位大于候选数时须按候选数截断并记录，融合结果须与逐路明细按 item_id 排序后自洽。
4. 实现并行召回与确定性归约：以查询为调度单元，在全局并发查询上限与每轮时间预算约束下使用本地进程池并行处理，各查询的召回候选、融合分数与评估指标按 query_id 全局排序后归约，使并行输出与串行顺序执行逐字节一致；工作进程异常须以结构化错误对象记录并保留其分片与查询标识。
5. 实现评估汇总与误差口径：按配置的参考标注计算每路命中数、融合后前十重合度、候选覆盖率与平均排名偏差，各项分母为零时须显式记为不适用并计数，并输出按配置指纹与随机种子生成的实验摘要；两次相同配置运行须得到逐字节一致的摘要。
6. 实现 SQLite 事务化阶段检查点与优雅停止恢复：每查询每阶段完成时以事务写入含阶段名、query_id、输入内容指纹、配置版本、产物摘要与单调序号的记录，同一查询同一阶段只允许一条有效记录；收到停止请求时完成当前不可拆分查询单元后退出，恢复后最终融合结果与实验摘要须与一次从零完整运行逐字节一致。
7. 实现配置与样本变化的版本指纹与失效传播：当物品库内容、查询集、融合权重、候选深度或预算配置任一变化时，由各阶段内容摘要构成版本指纹识别受影响的最早阶段，使该阶段及其全部下游产物失效并重建，未受影响上游产物继续复用；增量结果须与从零全量运行逐字节一致，不一致返回 E_INCREMENTAL_MISMATCH 并附首个差异 query_id。
8. 实现并发发布保护、整体替换识别与稳定业务错误码：多工作进程对同一数据库发布阶段产物时使用 SQLite 事务条件更新与真实文件锁并比较查询内序号，仅允许序号连续推进，落后、重复或跨查询错位发布返回 E_STALE_CHECKPOINT；检测到记录被整体替换（序号回退、指纹变化或摘要不匹配）时须区分回退、篡改与正常推进，仅正常推进被接受；请求非法阶段跳转、缺失前置阶段产物或融合权重为负须返回各自稳定业务码。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地确定性样本验证三路召回、预算裁决与融合结果的一致性，并验证中断恢复与失效重建的逐字节一致。
