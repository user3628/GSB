为推理框架团队从零构建一个可集成的矩阵乘算子组件，覆盖 GEMM（二维矩阵乘）与 BMM（批量矩阵乘）两类形态，核心问题是数据规模变化时算法路径的取舍与结果一致性。输入是本地确定性生成的浮点矩阵样本（float32 与 float64 混合规模，从 1×1 到数千维，含非方阵、尾块不对齐、批量内形状不一致等情形），以及一份分块与路径配置（分块尺寸、微小规模阈值、累加类型策略、批量并行预算）。组件需要依据规模与配置在直接乘、分块乘与批量并行分块乘之间选择算法路径，输出结果矩阵、路径决策记录与误差观测数据。工作区为空，需自行初始化项目。难点在于：不同规模下所选路径必须给出在声明容差内一致的结果，分块边界与累加顺序改变不得引入未声明的数值漂移，批量内形状不一致与预算受限须有清晰的降级与错误语义，算子须能被上层以统一接口集成并复现。

任务环境与准备：
安装 Python 3.10 及以上版本，并在项目虚拟环境中安装 numpy（版本以本地可获取的稳定版为准），无需 GPU 或外部服务。
在空工作区初始化项目目录，创建用于本地确定性矩阵样本生成与 BMM 样例的脚本，样本规模与 dtype 覆盖要求中列出的形态并固定随机种子。
确认本地 SQLite（Python 标准库 sqlite3）可用，用于结果快照的版本记录与内容哈希登记。
准备一份本地分块与路径配置文件，包含分块尺寸、微小规模阈值、累加类型策略与并行预算字段，供演示入口与复现命令使用。

业务要求：
1. 组件须提供统一算子入口，接收左矩阵与右矩阵的数组描述（形状、dtype、是否批量、批量维下标映射）、分块配置与累加类型策略，校验形状可乘、dtype 属于 float32 或 float64、分块尺寸为正整数、微小规模阈值为非负整数，任一非法返回 E_SHAPE、E_DTYPE 或 E_PARAM 业务码并指出出错参数名，且不得产出任何结果缓冲或临时文件。
2. 须实现至少三条算法路径：小规模直接乘、一般规模分块乘、批量分块乘，路径选择由矩阵规模与微小规模阈值共同决定并输出路径决策记录（含选择理由、分块尺寸、边界块数量与累加 dtype）；同一输入与配置下路径选择与结果须完全可重复，不得依赖运行环境的 BLAS 线程数或字典遍历顺序。
3. 分块乘须自行按分块尺寸遍历边界块并完成累加，尾块（不整除部分）必须走同一累加路径而非退回整块拷贝；分块尺寸由配置给出时，任意合法分块尺寸下的结果须与不分块直接乘在声明容差内一致，超出容差须返回 E_PRECISION 并给出最大绝对差与出现位置，不得静默返回偏差结果。
4. 累加类型策略须显式支持 float32 累加与 float64 累加两种模式：输入为 float32 且选择 float64 累加时须先提升再累加、最后按声明舍入回 float32，并输出提升、舍入与两种模式差异的统计量；选择 float32 累加时须如实记录其与 float64 累加的最大偏差，使规模增大时误差增长可观测。
5. BMM 须支持批量内形状不一致的分组执行：按可乘形状分桶后逐桶选择路径，桶内按批量下标升序稳定执行；不可乘的批量元素须返回 E_SHAPE 并定位批量下标，禁止因单个元素非法而丢弃其余元素的结果或伪造占位输出，成功桶的结果须完整保留。
6. 批量分块乘须受创建时给定的并行预算约束，预算按实际并发执行的分块任务计数并原子扣减；预算不足时须按确定性顺序排队或降级为串行分块路径而非阻塞等待，降级决策须写入路径决策记录，并发场景下同一输入的结果与串行路径在声明容差内一致。
7. 须以整体替换方式生成版本化结果快照，含配置指纹、路径决策摘要、逐结果矩阵的内容哈希与误差观测摘要；读取快照时若检测到内容哈希与数据库记录不一致、配置指纹变化或残留旧版本结果文件，须返回 E_STALE 并定位到版本与矩阵，禁止汇入旧结果。
8. 须提供确定性本地演示入口与可集成示例：用本地生成覆盖非方阵、尾块不对齐、批量形状不一致与预算受限的样本，输出各样本所选路径、分块尺寸、两种累加模式差值、批量分桶数、预算降级次数与快照版本序列的可重复结果，并给出上层以统一接口调用算子的示例与等价参数复现命令。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证各规模与分块下的路径选择、两种累加模式误差一致性与批量降级语义，附可复现结果。
