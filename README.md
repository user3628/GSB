语音合成服务落地前，团队需要先在 Windows 空白工作区把流式 TTS 的分帧处理做成可集成的领域组件与完整示例，重点解决合成过程中任意帧段中断后发音状态能否严格复原。输入由程序内置固定种子生成器在本地产出 JSONL 文本样本（每条含 utt_id、文本、语言标签 zh/en、说话人编号与韵律控制参数）与一份 YAML 合成配置，声明声学模型结构（文本嵌入维度、帧移样本数、频带数）、切分策略（首块最小字符数、后续块字符数、标点强制切分）、音素到发音单元的映射表、合成采样率与位深，以及帧边界检查点间隔；全部数据本地可复算，不依赖真实模型、GPU 或外部服务。组件按文本前端、声学参数预测、波形合成、一致性校验四阶段推进，每阶段在帧段边界写出带单调序号的 SQLite 检查点，并支持在优雅停止或强制终止后仅凭持久化事实恢复。

任务环境与准备：
在 Windows 本地准备 Go 1.22 及以上工具链，确认 go version 可用。
安装 SQLite 开发库或使用纯 Go 的 SQLite 驱动（如 modernc.org/sqlite），通过 go mod tidy 拉取依赖。
无需 GPU、外部模型或网络服务；所有样本与配置由程序内置固定种子生成器在首次运行时产出到本地工作目录。
确保工作区可创建目录与文件锁，Go 依赖缓存目录可写。

业务要求：
1. 实现文本前端与发音单元切分阶段：对每条文本做 Unicode NFKC、空白折叠与全半角统一，按中文单字与拉丁字母串切分，依据首块最小字符数、后续块字符数与标点强制切分规则输出带字符偏移的块序列，并把每个块映射为音素序列与发音单元；空文本、音素映射缺失或某块无法切分时须返回带 utt_id 与块序号的稳定业务码并保留诊断上下文。
2. 实现确定性声学参数逐帧预测：每个发音单元经固定哈希嵌入与配置声明的逐层线性变换输出帧级频带能量与基频，帧移样本数、频带数与嵌入维度均由配置显式给定；同一输入与配置在任意合法切分参数下，按块拼接得到的声学参数序列必须与不切分整体预测逐字节一致，出现 NaN 或 Inf 须返回带 utt_id 与帧号的 E_NUMERIC 而非静默继续。
3. 实现波形合成与发音边界对齐：依据声学参数按固定相位与包络生成采样率、位深、声道由配置声明的 16 位 PCM，记录每块起止采样点与对应发音单元，幅值越界时钳制并统计次数；合成采样总数必须与声学参数帧数与帧移换算一致，采样数不符须返回带 utt_id 与声明值、实际值的 E_LENGTH_MISMATCH。
4. 实现帧段边界检查点与优雅停止：每合成完一个不可拆分的发音单元帧段即在一个 SQLite 事务内写入含 utt_id、帧段序号、文本与配置内容指纹、发音单元摘要、产物摘要与单调序号的记录，同一 utt_id 同一帧段只允许一条有效记录；收到停止请求时完成当前发音单元后落库退出，被强制终止后重启仅凭已提交事实恢复，不承诺生成退出报告。
5. 实现增量失效与全量一致性校验：当某条文本、切分参数、音素映射表或声学权重变化时，通过各阶段内容摘要构成的版本指纹识别受影响的最早阶段与最早帧段，使该帧段及其全部下游声学参数与波形失效重建，未受影响帧段继续复用；增量重建后的声学参数摘要、PCM 摘要与逐帧统计须与从零全量运行结果逐字节比对，不一致返回 E_INCREMENTAL_MISMATCH 并附首个差异帧段。
6. 实现并发发布互斥与快照整体替换识别：多工作进程对同一 SQLite 库发布帧段产物时使用条件更新与真实文件锁并比较帧段序号，仅允许序号连续推进，落后、重复或跨 utt_id 错位发布返回 E_STALE_CHECKPOINT 并附当前生效序号；当检测到检查点记录被整体替换（序号回退、指纹变化或摘要不匹配）时须区分正常推进、整体替换与回退，仅正常推进被接受。
7. 实现配置与文本整体替换时发音状态的失效传播：当合成配置或文本样本集被整体替换时，内容摘要与版本序号须能区分正常追加、整体替换与回退，整体替换使全部派生声学参数与波形失效重建，回退则拒绝并返回业务码；替换后首次恢复不得沿用旧配置下的任何帧段状态。
8. 提供可集成组件接口与本地确定性演示：以库函数与命令行提供文本导入、分阶段流式合成、按 utt_id 与帧段查询状态与版本指纹、请求优雅停止、执行恢复与诊断报告导出；演示数据由内置生成器产出至少 3 条语句，覆盖中英混排、标点强制切分与一次强制终止后恢复，完整运行产生固定摘要。
