当前是空白工作区，没有现存项目、代码或数据附件。需要从零实现一个面向本地单模型推理场景的推理批处理调度与规模自适应诊断工作台，复现真实在线推理服务中批处理调度器的核心机制。工作台管理一个模型服务的推理请求流：每个请求含请求标识、到达时刻（逻辑刻度）、输入张量形状、优先级与超时预算，调度器按配置的批处理策略（固定批量、按到达时间窗口聚合、按令牌预算动态组批）把请求组织成批，逐批调用本地确定性推理桩（以 NumPy 计算代替真实模型，耗时按输入规模与批量建模），再把结果按请求回填。真实服务中数据规模变化剧烈：低峰期到达稀疏使固定批量长期等不满而抬高排队时延，高峰期大批量又使单批耗时越过请求超时预算；令牌预算动态组批能降低时延但会使批内形状不齐、可解释性变差且回填顺序难以对齐。工作台须维护批队列、在途批、结果回填与超时判定，提供实时诊断视图，并在进程重启后依据持久化状态恢复。

任务环境与准备：
安装 Python 3.11 或以上版本，并确认标准库包含 sqlite3 与 http.server。
使用 pip 安装 NumPy 与 pytest，版本不作硬性要求，安装后以 pip show 确认可用。
在空白工作区创建项目目录，样本数据由内置固定随机种子生成器在首次运行时写出到本地目录，不下载任何外部数据。
确认可在 Windows 命令行直接运行 python 与 pytest，测试全程离线，不访问外网或真实推理服务。

业务要求：
1. 实现请求模型与规模统计的载入校验：每个请求含唯一请求标识、到达逻辑刻度、输入张量形状（维度名与各维长度）、优先级与超时预算毫秒；须校验形状维度为正整数、超时预算在配置上下界内、同一请求标识重复提交须幂等拒绝并返回 E_DUPLICATE_REQUEST，非法请求不得进入调度队列。
2. 实现批处理调度器与三种组批策略：固定批量按批容量凑满或到达窗口到期发批；时间窗口策略按到达时刻聚合固定窗口内的所有待组批请求；令牌预算策略按每请求形状折算令牌数、在不超过单批令牌上限前提下尽量多组。三种策略在同一请求流下的组批决策须写入诊断事件，且均须遵守同一批容量上限与到达顺序不翻转约束。
3. 实现批规模与单批耗时的建模及超时判定：推理桩耗时按批内请求数、形状折算令牌数与配置的固定开销线性建模，以真实单调时钟推进；批内任一请求若在批完成时刻已超过其到达时刻加超时预算，须判定该请求超时并以 E_REQUEST_TIMEOUT 计入结果，不得把超时请求的结果当作成功回填。
4. 实现调度参数的规模自适应调整：调度器须依据滑动窗口内的到达速率、平均排队时长与超时比例，调整到达窗口长度与单批令牌上限，每次调整须记录触发依据、调整前后取值与生效批次；调整不得造成在途批参数被改写，新参数只对后续组批生效，且同一输入序列在固定种子下调整轨迹可复现。
5. 实现结果回填顺序与批内形状对齐：每批结果须按请求在批内的确定性次序回填，诊断事件须记录批标识、批内请求顺序、批形状摘要与回填序号；同一请求在任何策略下最终回填的结果数值必须一致，不得因组批方式不同改变推理桩对单请求的计算路径，形状不齐时须按补齐规则记录补齐量。
6. 实现 SQLite 持久化与重启恢复：批队列、在途批、请求状态、策略参数快照与诊断事件须在每批发批与回填的提交点以单事务写入，事务提交后才对查询可见；进程重启后须把中断的在途批判定为失败并以 E_BATCH_INTERRUPTED 回填其请求、恢复待组批队列次序与自适应参数，恢复后对同一剩余请求流继续调度的结果须与未中断时一致。
7. 实现并发提交与调度诊断接口：通过本地 HTTP 提供提交请求、推进调度若干步、查询实时诊断视图（待组批队列、在途批、超时比例、参数调整历史）、查询请求结果与终止服务的接口；并发提交须串行化到调度器边界内，锁等待须有基于真实单调时钟的超时并返回 E_CONTENTION_TIMEOUT，诊断视图不得观察到某请求已回填但批事件未写入的中间状态。
8. 提供本地确定性样本与可重复测试：内置固定随机种子的请求流生成器，产出至少覆盖低峰稀疏、高峰突发与形状长尾差异明显的三段流，总请求数不少于五千；pytest 用例须在 Windows 离线覆盖三种策略组批、超时判定、参数自适应复现、回填一致性与重启恢复，并输出批次数、平均排队时延与超时比例。
