本地机器翻译服务组目前手上只有一个空工作区和一份同步需求说明，需要先把译后编辑场景的翻译记忆库同步组件落成可运行服务。系统维护两份对齐语料：程序内置固定种子生成器在本地产出的 JSONL 分段源（含段标识、源语言、目标语言、源文本、目标文本、更新序号与译文质量标记，覆盖中英混排、空目标文本、重复源文、长段落与标记越界），以及由同一生成器产出的增量片段（只含被修改的段及其新译文、变更类型与基础版本号）。运维通过本地 HTTP 接口导入分段源与增量片段，系统按规范化切分、双语对齐打分、记忆单元合并、失效传播四阶段推进，并把每个记忆单元与阶段进度以事务写入本地 SQLite。真实场景里同一源文的短句会跨分段重复出现，增量片段只改少数段，但一个段的译文变化会通过共享记忆单元影响已导出翻译建议与其他段的命中裁决，因此必须精确识别哪些单元与建议失效、哪些可继续复用，且中断后的恢复只能依据已提交事实。

任务环境与准备：
在 WSL Ubuntu 上安装 Go 1.22 及以上（sudo apt-get install -y golang-go 或使用官方二进制包）。
安装 sqlite3 命令行与开发头文件（sudo apt-get install -y sqlite3 libsqlite3-dev），供本地事务写入与调试使用。
创建空工作目录作为项目根，确认无既有代码或样本文件。
无需网络、GPU 或外部数据集，样本由程序内置固定种子生成器在本地确定性写出。
确认本地回环端口可用，供 HTTP 交互接口监听使用。

业务要求：
1. 实现双语规范化与分段切分阶段：对源文本与目标文本分别做 Unicode NFKC、空白折叠与全半角统一，按中文句读与拉丁标点切分为带字符偏移的句段并保留段落序号；空目标文本、仅含标点或切分后零句段的段须返回带段标识与阶段名的 E_SEGMENT_EMPTY，且不得写入半成品记忆单元。
2. 实现双语对齐打分与记忆单元合并核心：以句段字符 n-gram 覆盖率、长度比例与语言标签相容性在对数域合成对齐分，按可配置阈值把源句段与目标句段配对为记忆单元，同一源文短句跨分段重复出现时须归并到同一单元并累加出现计数，互斥配对按确定性仲裁裁决并记录依据；对齐分出现非有限值或长度比例为零须返回 E_ALIGN_INVALID 并附段标识与句段偏移。
3. 实现增量片段应用与最小失效集合推导：增量片段携带基础版本号，应用前须校验其与当前生效版本一致，不一致返回 E_STALE_BASE 并附当前版本；片段中某段译文变化时，通过各阶段内容摘要构成的版本指纹定位受影响的最早阶段，把共享该记忆单元的其余段与已导出翻译建议标记为失效并记录失效原因链，未受影响的单元继续复用。
4. 实现失效链上的增量重建与全量一致性校验：对失效集合仅重算对齐打分与记忆单元合并，重建结果须与从零全量运行得到的单元摘要、出现计数与建议清单逐字节一致；检测到不一致须返回 E_INCREMENTAL_MISMATCH 并附首个差异单元标识与两路摘要，禁止以整体重算掩盖增量缺陷。
5. 实现 SQLite 事务化阶段检查点与强制终止恢复边界：每阶段与每个不可拆分段单元完成时在单个事务内写入含阶段名、段内容指纹、生效版本号、产物摘要与单调序号的记录，同一阶段同一段只允许一条有效记录；进程被强制终止后重启仅凭已提交事实重建进度，不承诺生成退出报告，恢复后的记忆单元与建议清单须与一次连续执行逐字节一致。
6. 实现版本整体替换识别与回退拒绝：当分段源或增量版本记录被整体替换时，通过内容摘要与版本序号区分正常推进、整体替换与版本回退；整体替换须使全部记忆单元与翻译建议失效重建并记录替换前版本摘要，回退须拒绝并返回 E_VERSION_ROLLBACK 附被拒版本号与当前生效版本。
7. 实现并发发布互斥与稳定业务错误码：多个工作进程对同一数据库发布记忆单元或建议时使用 SQLite 条件更新与真实文件锁并比较段内序号，仅允许序号连续推进，落后、重复或跨段错位发布返回 E_STALE_CHECKPOINT 并附提交序号与当前序号；非法阶段跳转或缺失前置产物须返回带段标识的业务码而非通用错误。
8. 提供本地 HTTP 与命令行交互接口及确定性演示：支持导入分段源与增量片段、触发分阶段同步、查询各阶段状态与版本指纹、按源文检索翻译建议并查看失效原因链、请求优雅停止与执行恢复、导出记忆单元清单；演示数据由内置生成器产出至少 3 个分段源与 2 个增量片段，覆盖中英混排、重复短句与跨段共享单元场景。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地分段源与增量片段验证记忆单元合并、共享单元失效传播与中断恢复，结果须与全量运行逐字节一致。
