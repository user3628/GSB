在 Windows 空白工作区中，需要从零构建一个面向本地确定性样本数据的多表连接顺序优化与代价评估组件，供上层查询执行管线集成。组件读取表统计快照（每个关系的行数、连接列的不同值数、相关列系数）与一组连接谓词（等值、范围与自连接），按左深树枚举连接顺序，为每个候选顺序估算中间基数与总代价，选出最优顺序并输出完整代价分解。难点在于交互延迟与计算结果一致性：调用方可在低延迟预算下请求快速计划，也可请求精确计划，两种模式必须对同一输入在可界定的偏差内给出可解释结果；统计快照版本切换期间的查询不得混用新旧统计，中间基数估算顺序不同会放大误差，连通关系必须保证所有可连接关系均被纳入。用户通过本地 HTTP API 提交查询与快照版本并获取计划。

任务环境与准备：
安装 Python 3.11 或以上版本，并使用虚拟环境安装 FastAPI、uvicorn 与 pytest（版本以本地可用为准），全程不依赖容器。
在空工作区创建项目目录结构，准备确定性统计快照 JSON 样本与连接谓词样本文件，行数与不同值数固定以便复现。
确认本地回环端口可用，服务以 uvicorn 启动并暴露约定 HTTP 端点；准备一个可通过信号强制终止服务进程的本地脚本用于恢复验证。
准备 pytest 用例与演示脚本入口，保持所有输入为本地文件，不访问外部网络或真实数据源。

业务要求：
1. 实现统计快照加载与版本识别：快照文件为带版本号、生成时间与校验摘要的本地 JSON，包含每个关系的行数、连接列不同值数与相关列系数；加载时校验版本单调与摘要，校验失败返回业务码 E_SNAPSHOT_INVALID 且不替换内存中现有快照，整体替换须识别版本变化并拒绝相同或更旧版本。
2. 实现选择性估算：对等值、范围与自连接谓词分别估算选择率，结果落在 (0,1] 且不出现除零；相关列存在声明系数时按系数修正独立假设，修正后不得越界；未声明相关性时保持独立假设并在代价分解中标注假设来源。
3. 实现左深连接顺序枚举：对给定关系集合枚举全部合法左深顺序，仅当两子树间存在谓词边时才生成连接，禁止产生笛卡尔积分支；关系数超过配置上限时返回业务码 E_SEARCH_SPACE_TOO_LARGE 并说明上限与候选规模，不得静默截断搜索空间。
4. 实现中间基数估算：按选定顺序逐次相乘并应用谓词选择率，使用对数域累加避免上溢与下溢，并对每个中间结果给出有限上界；自连接与多谓词同表的修正须避免重复应用同一条谓词。
5. 实现代价模型与最优顺序选择：代价分解为扫描、连接与中间结果写出三项，各分项以定点小数输出并附舍入误差说明；计划比较使用带相对容差的比较，容差内平局按稳定的字典序打破，保证同一输入重复请求返回逐位一致的选定顺序。
6. 实现低延迟模式与精确模式的一致：低延迟模式按配置的搜索预算（候选顺序数上限）提前剪枝并输出被剪枝分支数与模式标记，精确模式给出全局最优；两种模式对同一快照版本的结果差异须在两者的代价分解中可核对，低延迟模式结果代价不得低于精确最优代价。
7. 实现并发与快照隔离：计划构建按提交串行执行，多个查询可并发读取已物化计划；同查询标识重复提交只执行一次，其余等待复用结果；查询请求指定的快照版本若在构建期间被替换，须在请求绑定的版本上完成或返回 E_VERSION_RETIRED，禁止混用新旧统计。
8. 实现强制终止恢复与统一错误响应：计划构建前写入意图记录，进程被强制终止后重启须扫描未完成意图将对应构建标记为已中止或回滚到一致状态，恢复报告只基于已持久化事实；所有失败响应为含业务码的 JSON，至少覆盖 E_SNAPSHOT_INVALID、E_SEARCH_SPACE_TOO_LARGE、E_VERSION_RETIRED、E_INVALID_QUERY，并提供本地样本演示脚本输出三种查询的选定顺序与代价分解。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地固定样本与 HTTP 服务验证两模式计划、快照版本隔离、错误码及一次强制终止后的恢复报告。
