为传统机器学习建模团队从零构建一个本地可运行的交叉组合与降维工作台，核心问题是交叉特征生成与降维投影过程中的状态演进与崩溃恢复一致性。输入是本地特征分片目录：多个 CSV 分片含样本 id、若干类别特征列与数值特征列；一份交互声明文件，指定若干类别特征两两交叉并给出交叉名与是否做哈希压缩；一份降维配置，声明目标维度、投影方法与随机种子。团队需要据此完成确定性交叉特征构造、投影矩阵拟合与降维输出，并可视化诊断各阶段状态。工作区为空，需从零创建项目：一个可交互的 FastAPI 服务，提供工程创建、分阶段执行、查询投影与诊断状态、导出快照的接口。难点在于：交叉特征数量随分片与配置演进快速增长，投影矩阵必须在同一份训练视图上拟合，而用户会反复触发增量重跑，中途可能被强制终止，恢复后投影结果、交叉统计与快照版本必须与无中断执行完全一致。

任务环境与准备：
Windows 本地环境，安装 Python 3.11 与 pip，创建虚拟环境并安装 fastapi、uvicorn、numpy、pytest，不依赖容器或外部服务。
在空工作区初始化项目目录，准备本地确定性特征分片 CSV、交互声明 JSON 与降维配置 JSON，样本与配置固定以保证演示可重复。
确认 SQLite 随 Python 标准库可用，演示使用 uvicorn 本地回环端口，脚本可用 curl 或等价 HTTP 调用复现。

业务要求：
1. 工程创建接口接收分片目录、交互声明文件与降维配置，校验分片字段完整、样本 id 唯一、交叉引用的列存在且类别列才可交叉、目标维度为正整数、投影方法与随机种子合法；任一非法返回 E_PARAM 业务码并指出出错文件与行号，且不得创建任何结果文件、临时目录或状态记录。
2. 须实现确定性交叉特征构造：按交互声明顺序逐对交叉类别列，单列先在分片内映射为稳定编码，交叉键按声明顺序拼接后按哈希压缩开关决定是否取模到可配置桶数；同一样本与配置下交叉键与桶号须逐位一致，桶冲突须计入冲突统计且不得因冲突丢弃样本。
3. 投影矩阵须只在当前训练视图上拟合：训练视图为按样本 id 字典序稳定排序后的交叉特征矩阵，投影矩阵由种子与投影方法确定性派生并在每次拟合时记录训练视图内容哈希；若训练视图哈希与已有投影记录不一致，必须重新拟合并推进投影版本，禁止复用旧矩阵。
4. 服务须按 cross_built、projection_fitted、reduced、committed 四阶段推进，阶段顺序不可跳步，乱序推进返回 E_STAGE 并给出当前阶段；重复调用已完成阶段须幂等返回已有结果与当前快照版本，不得重新消耗投影版本号。
5. 每次阶段完成须以整体替换方式生成版本化快照，含工程版本号、训练视图哈希、投影版本、逐样本降维结果摘要与结果文件内容哈希；读取快照时若检测到数据库记录与磁盘文件哈希不一致、工程版本变化或残留旧版本文件，须返回 E_STALE 并定位到阶段与文件。
6. 工程状态须以工程、阶段、分片三级记录在 SQLite 中提交，单个分片的交叉统计、降维结果与分片进度须在同一事务中写入；某分片处理失败时该分片整体回滚，不得留下部分交叉统计或与快照版本不一致的降维结果。
7. 进程被强制终止后重启，须从 SQLite 已提交进度继续，核对每个分片处理标记、训练视图哈希与快照版本，重算未提交分片且不重复消费已提交分片；恢复后的投影版本序列、逐样本降维结果与快照版本须与无中断执行逐位一致。
8. 须提供诊断工作台接口与确定性演示入口，输出交叉特征列数、桶冲突数、训练视图哈希、投影版本、逐阶段受影响分片数与快照版本序列；演示使用固定分片与变更序列跑出可重复结果，并给出可用 curl 复现的请求示例。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地固定分片验证交叉构造、投影拟合、阶段恢复与快照一致性，并给出可复现演示结果。
