在 Windows 空白工作区中，需要从零构建一个面向本地文档集合的倒排索引存储组件，供上层文档检索客户端集成。组件以 SQLite 存储文档（含 _id、嵌套对象与数组字段）与倒排索引条目（词项、文档标识、字段路径、词频、位置列表），索引按字段路径分别建立，支持多词项合取与析取、短语位置匹配、字段限定与数组元素展开。写入批次提交后需增量维护倒排表而非全量重建，并对外暴露带版本的索引视图：查询只能看到某一完整提交版本的倒排状态。核心难点在于增量索引与并发查询的一致性：新批次写入正在改动倒排表时，已开始的查询必须在旧索引版本上得到确定结果，任何词项的添加、删除或位置列表变更都不能让查询看到部分更新；同时组件需支持对索引段做合并压缩，并在合并中途被强制终止后依据持久化状态恢复可用索引。

任务环境与准备：
确认 Windows 上已安装 Python 3.11 或更高版本，并可在命令行使用 python 与 pip。
在空白工作区创建项目目录，使用 pip 安装 FastAPI、uvicorn、pytest 与 httpx，版本以本地可获取的稳定版为准并写入依赖清单。
准备固定本地样本：预置若干带嵌套对象与数组字段的文档 JSON 文件及批次描述，生成脚本使用固定随机种子保证多次生成内容一致。
确认本地回环端口可被 uvicorn 监听；所有数据与服务均在本机运行，不使用外部网络、账号或付费资源。
准备一次强制终止演示流程，通过操作系统终止进程模拟合并中途失败，重启后读取 SQLite 持久化意图生成恢复报告。

业务要求：
1. 实现文档存储与字段路径解析：文档以 _id 唯一标识并允许嵌套对象与数组字段，索引字段路径需支持点分隔嵌套路径与数组元素展开（同一文档同一路径下的数组元素位置按数组下标与元素序号确定性排序）；未知字段路径、非法路径语法与重复 _id 写入必须返回互不相同的业务码如 E_BAD_PATH，且不得改动已有索引。
2. 实现倒排表结构：以 (字段路径, 词项) 为键存储文档标识引用、词频与位置列表，位置列表按文档内出现顺序升序且不得重复；词项需经统一规范化（小写与固定分隔规则）后写入，同一文档重复提交时同键条目必须整体替换而非累加，并提供按 (字段路径, 词项) 查询倒排条目的读取路径。
3. 实现增量维护：写入批次包含新增、更新与删除文档，倒排表须只针对受影响文档的受影响字段路径做增量修改，删除文档时须从其出现过的全部 (字段路径, 词项) 条目中移除引用并把空条目清理；批次必须原子生效，禁止出现部分文档已入倒排而另一部分未入的可见中间状态。
4. 实现带版本的索引视图：每次批次提交产生严格单调递增的索引版本，查询需携带或可解析出索引版本并在该版本上执行，不得读取更高版本的倒排内容；查询在批次提交进行中启动时，必须完整地在提交前版本上完成，结果与该版本已提交内容逐项一致。
5. 实现多版本条目可见性存储：倒排条目需保留可判定版本区间的元数据，使旧版本查询在增量修改后仍能得到正确结果，同时旧版本被回收后对应查询返回 E_VERSION_RETIRED 而非错误结果；版本回收须以确定规则推进且不得回收仍有活跃查询引用的版本。
6. 实现查询执行：支持多词项合取与析取、短语位置匹配（按位置列表判定相邻）、字段限定与数组元素展开语义，结果按 _id 稳定升序输出并支持 LIMIT/OFFSET 窗口化，分页拼接不得重复或遗漏；短语匹配与析取组合须基于同一索引版本执行。
7. 实现索引段合并与强制终止恢复：合并操作把多个倒排段压缩为更少的段并保持每个版本区间的查询语义不变，合并前写入意图记录；进程在合并或批次提交中途被强制终止后，重启必须扫描未完成意图，丢弃未完成的合并产物并把索引恢复到最后一个完整版本，恢复报告只包含已持久化事实，不承诺强制终止后仍生成退出报告。
8. 提供本地 HTTP API 与可复现验证脚本：API 覆盖批次写入、按版本查询、倒排条目查询、索引段状态查询与恢复报告查询，统一错误响应为含业务码的 JSON；脚本使用固定本地样本完成一次全量写入、一次只改部分文档的增量写入，并在批次提交前后各发起一次查询，验证旧版本查询在增量生效后结果不变、新版本查询命中增量内容，再模拟一次合并中途强制终止与重启恢复。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定本地样本验证增量倒排维护下新旧版本查询结果互不污染，以及合并强杀后的索引恢复一致。
