从无到有搭建时，需要面向本地多服务测试环境构建一个配置中心热更新中间件，交付算法实现与可复现的实验环境。配置中心维护若干客户端依赖的配置项（数值参数、比例、阈值），配置以带版本号的快照提交；热更新时向本地客户端测试端点推送增量并等待确认，客户端按其拾取的配置版本执行确定性计算管线并回传结果摘要。难点在于异常路径的可复现验证：推送超时、连接拒绝、重复推送、迟到确认、确认与配置版本错位等异常必须通过真实连接行为触发并被稳定复现，且每次异常后的中间件状态必须可依据持久化事实核对，配置快照版本与客户端确认记录之间不得出现跨版本混合的中间可见状态。

任务环境与准备：
Windows 10/11 x64 本地环境，安装 Go 1.22 或以上并确保 go 命令在 PATH 中，无需任何外部服务或账号。
安装 SQLite 依赖：使用 modernc.org/sqlite 纯 Go 驱动或本机已装 sqlite3 动态库，go.mod 中固定版本，任务开始前执行 go mod download 拉取依赖。
准备本地确定性样本目录：配置快照 JSON、客户端注册清单、固定随机种子样本张量说明与计算管线参数，全部随题面给定，不依赖网络下载。
准备本地客户端测试端点程序（可用同一 Go 模块内的测试子命令启动），支持按请求参数返回成功、延时、拒绝与重复响应，供异常注入复现使用。
预留本地回环端口与临时数据目录用于 SQLite 数据库与意图日志写入，执行前清理遗留数据库文件。

业务要求：
1. 实现配置快照与客户端订阅模型：快照包含单调递增版本号、生成时间、配置项集合与整体校验摘要；客户端声明其依赖的配置键集合、本地测试端点地址与拾取版本策略。提交快照时若版本号不大于当前已提交版本则返回 E_STALE_SNAPSHOT 且不改变已提交状态，快照校验摘要不一致返回 E_SNAPSHOT_INVALID。
2. 实现配置推送与确认状态机，至少包含 PENDING、PUSHED、ACKED、APPLIED、ABORTED 五种状态并规定合法迁移路径；非法迁移返回 E_INVALID_TRANSITION 且不得修改已持久化状态；同一版本重复触发推送只执行一次、其余请求等待并复用结果。
3. 实现向本地客户端测试端点的真实推送：每次推送具备独立超时，超时后必须真实关闭底层 HTTP 连接并释放其占用的并发名额，返回 E_PUSH_TIMEOUT；连接被拒绝返回 E_PUSH_REFUSED；不得以等待冒充超时。推送数量受全局并发上限与每轮时间预算双重约束，超上限者进入有界等待队列。
4. 实现重复推送与迟到确认的异常语义：同一客户端同一配置版本的重复推送只生效一次，内容不一致返回 E_CONFLICTING_PUSH；迟到确认若对应版本已被更新版本取代则计入历史并返回 E_STALE_ACK，历史确认不得改写任何客户端当前状态。
5. 实现跨版本计算结果一致性校验：客户端按拾取的配置版本执行固定随机种子样本上的加权求和、归一化与阈值判定并回传结果摘要；校验工具须输出不一致明细（客户端标识、拾取版本、结果摘要与差异字段），并判定哪些结果可并入最新版本、哪些必须重算，判定依据须包含版本与确认记录。
6. 实现单写者提交与多读者查询的并发一致：配置提交、推送推进与结果汇总按版本单写者串行执行，多个查询可并发读取已提交的客户端状态与计算结果；查询不得看到客户端已 ACKED 而配置推送记录仍为 PENDING 的中间状态；同一客户端并发收到两个版本的推送时，仅较新版本可进入 APPLIED，旧版本须被判为 E_STALE_ACK。
7. 使用 SQLite 持久化快照、推送记录、确认记录、计算结果摘要与意图日志，所有写操作先落意图记录再提交事务；进程在推送或结果汇总中途被强制终止后重启须扫描未完成意图，将客户端与批次恢复到最后一个完整版本或标记为已中止，恢复报告只包含已落盘事实。
8. 提供本地 HTTP API 与可复现实验脚本：API 覆盖快照提交、客户端注册、触发推送、确认回传、计算结果上报、不一致明细查询与恢复报告查询，统一错误响应为含业务码与上下文的 JSON；脚本须使用固定本地样本与本地客户端测试端点复现推送超时、连接拒绝、重复推送、迟到确认与强制终止后恢复五类情形，并输出可核对的异常记录与状态快照。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地测试端点复现五类异常，核对状态、结果摘要与恢复报告一致。
