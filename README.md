为推理框架团队从零构建一个本地可运行的卷积与插值算子聚合组件，覆盖二维卷积（含步长、填充、空洞）与双线性/最近邻插值两类算子，核心问题是长序列分块计算中的中间状态演进与强制终止后的恢复一致性。工作区为空，需自行初始化项目。输入是本地确定性生成的张量样本：一份算子作业清单 JSONL，每条含 job id、算子类型 conv2d 或 interpolate、输入张量形状与输出尺寸或卷积核参数、分块尺寸与累加精度策略；一份张量分片目录，内含按作业引用的 float32 或 float64 输入张量与卷积核，形状覆盖非整除尾块、空洞卷积、非方阵核与最近邻放大缩小等情形。每个作业按输出分块推进计算，逐块提交中间结果与进度；真值来源为同一配置下的不分块全量直接计算，作为逐位与容差对照的基准。组件须在进程被强制终止后从 SQLite 已提交进度继续，且恢复结果须与无中断执行逐位一致。

任务环境与准备：
安装 Python 3.11 与 FastAPI、NumPy、uvicorn 等依赖并确认可在本地启动服务
创建空白工作区目录，按题目要求自行初始化项目结构与 SQLite 数据库文件
准备本地确定性张量样本生成脚本，生成覆盖尾块、空洞卷积与插值模式的输入张量与卷积核
确认可在 Windows 上强制终止服务进程以验证恢复流程，并保留 SQLite 与块结果文件作为持久化状态

业务要求：
1. 组件须提供作业创建接口，接收作业清单、张量分片目录、分块尺寸与累加精度策略，校验 job id 唯一、输入张量与卷积核形状可计算、dtype 仅为 float32 或 float64、步长与空洞为正整数、填充非负、插值缩放因子为正实数、分块尺寸各维为正整数；任一非法返回 E_PARAM 业务码并指出 job id 与字段名，不写入任何阶段状态与临时文件。
2. 须实现确定性 conv2d 分块计算：按分块尺寸把输出平面划分为块，逐块按元素索引升序完成乘加，边界块与空洞卷积须走同一累加路径而非退回整块拷贝；插值算子须实现双线性与最近邻两种模式并显式声明坐标映射与边界外取值约定，同一作业与配置在重复运行、任意合法分块尺寸下的结果须与不分块全量直接计算逐位一致。
3. 累加精度策略须显式支持 float32 累加与 float64 累加两种模式：float64 模式须先提升输入再累加、最后按算子目标 dtype 声明舍入，并输出逐块提升次数、舍入次数与两模式结果的最大逐元素差值；浮点容差由配置给出，超出容差须返回 E_PRECISION 并定位 job id 与块下标。
4. 每个作业须按 chunks_planned、chunks_computed、aggregated、committed 四个阶段推进，阶段顺序不可跳步，乱序推进返回 E_STAGE 并给出当前阶段；重复调用已完成阶段须幂等返回已有块结果与当前快照版本，不得重复累加已提交块。
5. 块结果与阶段进度须在 SQLite 中以作业、阶段、块三级记录提交，单个块的输出值与块进度在同一事务中写入；某块计算失败时该块整体回滚且不得留下部分写入，同一作业其余已提交块的状态保持不变，聚合时只读取已提交块。
6. 每次阶段完成须以整体替换方式生成版本化快照，含作业版本号、各作业逐块结果摘要与结果文件内容哈希；读取快照时若检测到数据库版本与磁盘块结果哈希不一致、作业版本变化或残留旧版本块文件，须返回 E_STALE 并定位到作业与块下标，禁止汇入旧数据。
7. 进程被强制终止后重启，须从 SQLite 已提交块进度继续，核对每个作业的阶段标记、块结果内容哈希与快照版本，重算未提交块且不重复累加已提交块；恢复后的逐作业输出张量、逐块摘要与快照版本序列须与无中断执行完全一致，被强制终止时不承诺生成退出报告。
8. 须提供确定性本地演示入口：用固定样本覆盖非整除尾块、空洞卷积、非方阵核、最近邻与双线性插值以及恢复中断场景，跑出各作业所选算子与分块尺寸、逐块结果摘要、两种累加模式差值、恢复前后一致性结论与快照版本序列的可重复结果，并给出可用等价参数复现的命令示例。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证卷积与插值分块结果、累加模式差值及强制终止后恢复与无中断执行逐位一致。
