为内容安全团队从零构建一个本地可运行的情感与风险判定工作台，核心问题是交互式判定请求的低延迟预览与全量判定结果的一致性，以及判定状态在中断后的恢复。输入是本地样本目录：一份待判定文本清单 JSONL，每条含 doc id、原始 UTF-8 文本、来源与人工情感极性标注（-1、0、1）；一份风险词表 JSON，含若干风险词条、风险等级、类别名与是否区分大小写标记，并带词表版本号；一份判定配置 JSON，声明情感打分所用的情感词典对数权重、风险等级映射阈值、聚合窗口大小（以 Unicode 字符计）与浮点容差。工作区为空，需从零创建 FastAPI 服务，提供作业创建、低延迟预览、全量判定、快照查询与诊断报告接口。判定须同时产出情感极性与风险等级，风险等级由风险词命中密度与情感分共同决定；预览须返回文档级摘要而全量须逐段产出结果，两者必须对同一参数给出完全一致的情感和风险判定。服务还须支持词表增量更新后按依赖关系只重判受影响文档，并在进程被强制终止后从 SQLite 已提交进度继续。

任务环境与准备：
安装 Python 3.11 及以上版本，并安装 FastAPI、uvicorn、NumPy 与 requests 依赖。
创建本地样本目录：生成文本清单 JSONL、风险词表 JSON（带版本号）与判定配置 JSON，文本覆盖否定词、程度副词、多风险词条重叠与超长窗口边界情形。
确认工作目录为空，启动 uvicorn 服务前检查端口可用，服务数据目录中放置 SQLite 数据库文件与结果分片目录。

业务要求：
1. 作业创建接口接收文本清单、风险词表、判定配置与浮点容差，校验 doc id 唯一、文本非空、人工情感极性取值属于 {-1,0,1}、风险等级映射阈值严格递增、聚合窗口为正整数、容差为正小数；任一非法返回 E_PARAM 业务码并指出出错文件与行号，且不创建任何结果文件或临时目录。
2. 情感判定须以配置的情感词典对数权重按 Unicode 字符下标升序扫描文本，对否定词与程度副词按声明规则修正极性贡献；风险判定须按聚合窗口统计风险词命中密度并与情感分合成风险等级；同一文本与配置下情感极性、逐段风险分与风险等级须逐位可重复，不得依赖字典遍历顺序或系统时间。
3. 低延迟预览接口须返回文档级摘要：命中风险词条数、情感极性、风险等级与聚合窗口数，且必须与用同一参数走全量判定得到的结果完全一致，包括风险词命中集合、情感极性、风险等级与逐段划分；预览不得走抽样、截断文本或近似密度路径，检测到任何差异须返回 E_VERIFY 并给出 doc id 与首个不一致项。
4. 须实现以配置指纹（风险词表版本、判定配置内容与容差的内容哈希）为键的预览缓存；词表或配置任何变更须使相关文档缓存失效，读取缓存时若指纹与当前状态不一致须返回 E_STALE 并给出新旧指纹版本，禁止返回旧版本判定结果。
5. 风险词表须支持增量更新：新增词条、修改风险等级与类别、修改是否区分大小写三类操作并推进词表版本号；更新时须按词条到文档的依赖关系计算受影响文档集合，只重判真正命中被更新词条的文档，未命中文档不得重算。
6. 失效判定须精确到依赖粒度：若某文档未命中任何被更新词条且其风险等级不受等级映射阈值变化影响，则该文档不得重算；诊断报告须区分“依赖失效被评估但结果未变”与“实际重算”两类文档，给出各自计数与 doc id，并说明每篇文档的失效依据。
7. 判定进度与结果须在 SQLite 中以文档粒度事务提交，单文档的情感分、逐段风险分、风险等级与进度标记须在同一事务中写入，结果以原子替换写入不可分割的分片文件并登记内容哈希；进程被强制终止后重启须核对分片哈希与提交标记，重算未提交文档且不重复消费已提交文档。
8. 每次全量判定或词表更新完成须以整体替换方式生成版本化快照，含词表版本号、配置指纹、各文档判定摘要与分片哈希；读取快照时若检测到数据库记录与磁盘分片哈希不一致、词表版本变化或残留旧分片，须返回 E_STALE 并定位到文档与分片；另须提供确定性演示入口，固定样本与更新序列跑出逐文档情感与风险判定、命中词条、失效评估与实际重算文档数、快照版本序列的可重复结果，并给出可用 curl 复现的请求示例。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
