为搜索与推荐团队从零构建一个本地可运行的多路召回与融合工作台，核心问题是数据规模变化时的算法取舍与在线结果一致性。输入是本地样本目录：一份物品库 JSONL，每条含 item id、来源通道名、固定维度嵌入向量与若干类别标签；一份查询清单 JSONL，每条含 query id、查询嵌入向量与期望通道集合；一份通道配置 JSON，声明每个通道的候选规模上限、相似度融合权重、是否启用近似召回以及预算单元；一份真实相关性标注 JSONL，用于离线验证。工作区为空，需从零创建项目：一个可交互的 FastAPI 服务，提供工程创建、按查询执行多通道召回与融合、查询通道与融合状态、导出快照与诊断报告的接口。核心难点在于：物品库规模跨数量级变化时，须在精确扫描与分块索引召回之间取舍，而两种路径的最终候选集合、排序与分数必须逐位一致，用户会反复调参并期望低延迟预览与全量重算结论相同；单查询零候选不得整体失败；人为注入的非法配置与坏索引块须给出可定位的业务码；进度须以查询粒度事务提交，强制终止后从已提交状态恢复且不重复消费。

任务环境与准备：
准备 Windows 本地环境，安装 Python 3.11 及以上版本，并创建独立虚拟环境。
在虚拟环境中安装 fastapi、uvicorn、numpy、pytest 与 httpx，版本以本机可用的稳定发行版为准，无需容器。
确认工作区为空目录，运行前由脚本生成本地确定性样本：物品库与查询清单 JSONL、通道配置 JSON、真实相关性标注 JSONL，规模覆盖小库与大库两档。
确认 SQLite 可写（Python 自带 sqlite3 即可），并为服务监听端口预留可用端口；样本与索引、快照目录均位于工作区内，不访问外部网络。

业务要求：
1. 工程创建接口接收样本目录、物品库、查询清单、通道配置与监听端口，校验 item id 唯一、query id 唯一、嵌入维度与通道配置声明一致、通道权重非负且和为 1、通道候选上限与预算单元为正整数；任一非法返回 E_PARAM 业务码并指出出错文件与行号，且不创建任何结果文件或临时目录。
2. 须实现精确扫描召回与分块索引召回两条路径，路径选择由物品库规模与通道配置中的近似开关共同决定，并输出路径决策记录（含选择理由、块数、实际扫描物品数）；同一输入与配置下两条路径为每个查询输出的候选集合、排序与融合分数必须逐位一致，超出容差的差异须返回 E_VERIFY 而不是择一返回。
3. 分块索引须以整体替换方式构建并携带索引版本号，块内物品按 item id 升序稳定排列；检索时只允许读取涉及的块，未命中块不得全量解码，块缺失或内容哈希不符时返回 E_INDEX 并定位到通道与块序号，禁止退回全量扫描掩盖坏块。
4. 多通道融合须按通道权重与归一化余弦相似度加权合成最终分数，相似度统一用 float64 计算并对极端分数在对数域处理；同分时按 item id 字典序稳定排序，截断到通道候选上限与最终候选数时须声明截断顺序，同一查询重复请求结果须逐位可重复。
5. 查询须支持低延迟预览与全量重算两种入口，预览结果必须与同一参数走全量重算的结果完全一致，包括候选集合、排序、融合分数与截断位置；检测到两者不一致须返回 E_VERIFY 并给出 query id 与首个差异位置，不得因走近似路径而静默返回近似结果。
6. 某查询在所有通道均无候选或全部被通道约束过滤时须记录空结果并继续其他查询，不得因单查询零候选整体失败或返回错误码；逐查询的通道命中数、过滤数与截断数须可按 query id 查询，融合权重配置非法或某通道权重为负时返回 E_SCORE 并指出配置项。
7. 查询执行进度与逐通道召回统计须在 SQLite 中以查询粒度事务提交，逐查询结果以原子替换写入不可分割的分片文件并登记内容哈希；每次完成须生成整体替换的版本化快照，含索引版本号、各查询结果摘要与分片哈希；读取快照时若检测到分片哈希与数据库记录不一致、索引版本变化或残留旧分片，须返回 E_STALE 并定位到查询与分片。
8. 进程被强制终止后重启，须从 SQLite 已提交进度继续，核对每个查询的提交标记、分片哈希与索引版本，重算未提交查询且不重复消费已提交查询；恢复后的逐查询候选、融合分数、快照版本序列与无中断执行须完全一致，并须提供确定性演示入口用固定样本跑出各查询通道命中数、所选路径、预览与全量一致性结论及恢复前后一致性的可重复结果。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地固定样本验证双路径召回逐位一致、跨版本快照拒旧、零候选不整体失败及中断恢复后结果与快照序列一致。
