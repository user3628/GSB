当前是空白工作区，没有现存项目、代码或数据附件，需要从零实现一个面向本地列式计算引擎的“算子下推与列裁剪自适应执行组件”。组件接收本地列式数据表（每列以 NumPy 数组存储，列类型为整数或定长字符串编码）以及一条受限逻辑查询（多表等值连接、过滤谓词、投影列、分组聚合与排序键），在生成执行计划时决定谓词下推位置与投影列裁剪范围，并按向量批量推进扫描、过滤、哈希连接、聚合与排序输出。真实计算引擎中下推和裁剪都带来收益也带来代价：下推过度会在连接前重复计算昂贵谓词，裁剪过度会导致后续阶段需要回表补列，因而必须依据数据规模、谓词选择率与列基数做自适应取舍，且任何取舍都不能改变结果语义。

任务环境与准备：
安装 Python 3.11 或以上版本，并安装 NumPy 与 pytest 依赖；无需容器或外部服务。
确认可在 Windows 本地回环地址绑定 HTTP 端口，SQLite 使用标准库自带模块。
准备本地样本目录与固定随机种子生成脚本，运行前不需要网络访问或真实账号。

业务要求：
1. 实现列式数据表与受限查询描述的载入与校验：每张表以列名到 NumPy 数组的映射及元数据（行数、列类型、列基数、空值计数）描述，查询包含表引用、等值连接条件、过滤谓词、投影列、分组键、聚合函数与排序键；须校验列存在性、类型可比性与聚合函数参数合法性，非法输入返回固定业务码 E_BAD_QUERY 且不得进入规划阶段。
2. 实现谓词选择率估计与下推位置决策：对每个谓词依据列基数与值域统计估计选择率，并计算下推到扫描、过滤、连接前或连接后各位置的估计代价；须记录每个谓词的候选下推位置、估计收益与选定位置，且只有当收益超过配置阈值时才下推，避免在连接前重复计算昂贵谓词。
3. 实现列裁剪的最早可用点计算与补列回退：依据查询最终需要的投影列、连接键与谓词列，计算每个扫描节点可裁剪保留的最小列集合；若某列在后续阶段才被需要且无法在扫描时确定，须记录补列需求并在该阶段按行号回表补列，补列结果须与未裁剪执行逐值一致。
4. 实现下推与裁剪联合后的语义等价校验：对任意查询须生成一条不下推不裁剪的参照计划，与自适应计划在同一输入上执行并比较规范化结果（排序键与分组键的确定次序归一），结果不一致须以 E_SEMANTIC_MISMATCH 报告并输出首个差异行位置与列名，不得静默降级。
5. 实现按向量批量推进的执行与已提交批次游标：扫描、过滤、哈希连接、聚合、排序须为分离阶段，每批在单个 SQLite 事务中写入批次序号、阶段标识、完整结果批次与中间状态摘要，事务提交后才允许游标读取；中断或失败时未提交批次不得可见，游标位置须持久化以支持重启后继续读取。
6. 实现数据规模变化下的自适应路径切换与阈值配置：当表行数、列基数或谓词选择率超出配置阈值时，须在扫描路径（全量扫描与按选择率过滤后扫描）、连接构建侧选择与裁剪激进程度之间切换，并记录切换依据、切换前后估计代价与生效批次；切换不得改变已提交批次结果，也不得造成同一查询在相同输入下产出不同结果。
7. 实现并发查询的会话隔离与共享预算控制：多个查询可并发推进，每个会话开始时固定数据表版本与统计版本，中途版本变化须以 E_SNAPSHOT_STALE 终止并保留已提交批次；所有会话共享内存额度与临时目录命名空间，额度耗尽须以 E_BUDGET_EXHAUSTED 有序推迟而非静默失败，隔离失败须以 E_ISOLATION_BREACH 报告。
8. 提供本地 HTTP 接口、确定性样本与完整示例：通过本地 HTTP 提供提交查询、推进一批、查询会话与批次状态、创建并推进游标、查询下推与裁剪决策报告、触发语义等价校验的接口，错误统一以固定业务码在 JSON 中返回；内置固定随机种子的数据生成器产出至少四表、每表万行级含倾斜键与空值的数据，示例演示下推取舍、裁剪回退与语义校验。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
