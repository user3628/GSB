本地 Serverless 平台团队要在空白工作区交付一个冷启动与并发控制验证器，供函数平台工程师离线复现实例池行为。程序内置固定种子生成器在本地产出函数规格样本（函数标识、运行时、初始化耗时微秒、每实例内存字节、单实例并发上限、函数并发上限、预留额度）与调用轨迹样本（到达毫秒时间戳、函数标识、期望执行时长微秒、优先级、重试标记），并附一份带单调版本号的运行策略快照，声明冷启动判定阈值、实例回收宽限毫秒、等待队列上限与每轮时间预算。策略须与外部平台工具互换数据，因此持久化必须同时支持紧凑二进制与分片 JSON 行两种格式，两代格式在字段存在性与时间精度上不同。验证器要模拟实例池创建、复用、回收，执行并发准入裁决，并在本地回环测试端点上真实发起创建与执行请求。

任务环境与准备：
安装 Go 1.22 及以上版本，执行 go version 确认可用。
安装 sqlite3 命令行工具用于核对持久化数据，执行 sqlite3 --version 确认。
在 Linux（WSL Ubuntu）工作区创建工作目录并初始化 Go module。
程序内置固定种子生成器产出函数规格与调用轨迹样本，无需外部数据集或账号。
在本地回环端口启动测试端点，用于实例创建与调用执行的超时与连接关闭验证。

业务要求：
1. 实现运行策略快照的两种持久化格式编解码：紧凑二进制必须含魔数、格式版本字节、大小端标记、每条记录长度前缀、CRC32 校验与可选字段存在位图；分片 JSON 行每行一条记录，含函数标识、版本号、冷启动阈值与回收宽限。两种格式对同一逻辑快照必须可无损互转。
2. 实现格式协商与版本兼容矩阵裁决：导入前检测输入格式与格式版本，按显式声明且可从配置读取覆盖的兼容矩阵给出接受、降级接受或拒绝三种结论；旧版本缺回收宽限或时间精度较低时降级接受并按声明规则补齐，高版本含未知必填字段时拒绝并返回业务码 E_VERSION_UNSUPPORTED。
3. 实现时间与容量归一化：二进制格式毫秒时间戳与 JSON 行微秒时间戳须归一化为同一内部毫秒表示，按调用方声明的截断规则处理亚毫秒部分并输出每条舍入位与累计舍入误差；内存字节与初始化耗时做溢出与负数检查，失败返回 E_SPEC_INVALID 且整批不入库。
4. 实现实例池与冷启动判定：实例记录状态至少含 CREATING、READY、BUSY、DRAINING、TERMINATED 并规定合法迁移路径，非法迁移返回 E_INVALID_TRANSITION；调用命中 READY 实例记为热启动，需新建实例时记为冷启动，冷启动计数须与实例创建记录逐条对应。
5. 实现并发准入与真实可中断的创建执行：调用按函数并发上限与预留额度准入，超出上限时按优先级进入有界等待队列，队列满返回 E_CONCURRENCY_LIMIT；实例创建与调用执行须通过本地回环测试端点的真实连接体现，单次操作具备独立超时，超时后真实关闭连接并释放并发槽位与预留额度，返回 E_START_TIMEOUT。
6. 实现策略快照整体替换与增量片段提交：快照提交时版本号不大于当前已提交版本返回 E_STALE_SNAPSHOT，快照整体替换须识别版本变化并原子切换，校验失败保持旧快照完全可用；增量只更新受影响的函数参数并携带基础版本，基础版本不符返回 E_STALE_BASE 且不改变任何提交状态。
7. 实现单写者调度与多读者查询的并发一致及幂等：实例创建与并发准入按函数单写者串行执行，多个只读查询可并发读取某一完整提交版本，不得出现调用已记为冷启动而实例创建记录尚未落盘；同一调用标识重复提交只执行一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_REQUEST。
8. 使用 SQLite 持久化策略版本、实例、调用裁决、额度占用与意图日志，准入、创建、执行与回收前先写意图记录再提交事务；进程被强制终止后重启须扫描未完成意图，把未提交实例回滚为 TERMINATED、未提交额度回滚，恢复报告只含已落盘事实。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证两种格式互转、兼容裁决、冷启动与并发裁决及强制终止后恢复报告一致。
