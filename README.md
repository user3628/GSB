为传统机器学习建模团队从零构建一个本地可运行的梯度提升树增量训练与依赖失效诊断工作台，核心问题是训练数据分片增量到达或特征定义变更后，已训练的树模型与缓存的特征统计如何按依赖关系精确失效、只做必要的增量更新，并保证中断恢复后的模型与无中断训练一致。输入是本地样本目录：多个 CSV 特征分片，含样本 id、若干数值特征列与若干类别特征列；一份标签文件（样本 id 到 0/1 标签）；一份训练配置，声明树数量、最大深度、学习率、增量轮数、特征编码方式与浮点容差；一份特征变更记录 JSONL，声明对某特征列的改名、类型变更（数值转类别或反向）、删除与新增操作及其生效序号。工作区为空，需从零创建项目：一个 FastAPI 服务，提供工程创建、分片增量导入、按变更序号触发增量训练、查询特征依赖与失效诊断、导出快照接口。树的拟合使用本地确定性实现：按特征分位点分桶后以固定顺序贪心选择分裂点，不依赖系统随机状态。

任务环境与准备：
安装 Python 3.11 并确认可执行 python --version；安装依赖：pip install numpy fastapi uvicorn scikit-learn。
准备本地 CSV 特征分片与标签文件，样本 id 唯一、标签取 0/1，分片列名集合一致，含数值与类别特征列；再准备特征变更记录 JSONL 与训练配置 JSON。
确认当前目录为空工作区，预留可写目录用于 SQLite 数据库、模型缓存文件与快照文件；确认服务监听端口未被占用。
启动服务后用固定分片、变更序列与容差跑一遍确定性演示，记录逐树结构摘要、依赖统计与快照版本序列，作为复现运行的对照基线。

业务要求：
1. 工程创建接口接收分片目录、标签文件、训练配置与浮点容差，校验样本 id 跨分片唯一、标签覆盖全部样本且只取 0 或 1、各分片列名集合一致、树数量与最大深度为正整数、学习率位于开区间 (0,1]、容差为正小数；任一非法返回 E_PARAM 业务码并指出出错文件与行号，且不创建任何结果文件或临时目录。
2. 须实现确定性数据加载与特征分桶：分片按文件名升序拼接、样本按 id 字典序稳定排序，数值特征按分位点分桶、类别特征按取值字典序映射为稳定编码；同一输入下分桶边界、编码映射与样本顺序须逐位可重复，不得依赖字典遍历顺序或哈希随机化。
3. 须实现确定性树拟合：每棵树按当前学习率下的残差贪心选择分裂特征与分裂桶，候选遍历按特征下标升序、桶号升序进行，增益相同时按特征下标小者优先；同一训练视图与轮数下各树的树结构、叶子值与样本预测须逐位可重复。
4. 特征依赖须显式建模并可查询：记录每个特征被哪些树的哪些分裂节点引用、每棵树的样本覆盖分片集合；当特征变更记录生效时，须按依赖关系计算受影响的树与受影响的增量轮，未引用该特征的树不得重训，被删除或类型变更的特征须使其引用树整体失效重训。
5. 增量训练须支持分片与变更序号驱动的部分更新：新分片到达时只追加该分片样本参与后续轮次，特征变更时只重训依赖失效的树；诊断报告须区分“依赖失效被评估但树结构未变”与“实际重训”两类树，给出各自计数与树编号，并输出每个特征被引用的节点数。
6. 训练进度与模型状态须在 SQLite 中以工程、阶段、树三级记录提交，单棵树的树结构、叶子值与样本预测摘要须在同一事务中写入；某棵树重训失败时该树整体回滚且其余已提交树状态不变，为后续轮次准备的缓存不得留下与已提交树不一致的记录。
7. 每次增量训练完成须以整体替换方式生成版本化快照，含配置指纹、特征变更序号、各树结构摘要与模型文件内容哈希；读取快照或导出诊断时若检测到数据库版本与磁盘模型文件哈希不一致、配置指纹或变更序号变化、残留旧版本模型文件，须返回 E_STALE 并定位到树编号，禁止汇入旧数据。
8. 进程被强制终止后重启，须从 SQLite 已提交进度继续，核对每棵树的重训标记、模型文件内容哈希与快照版本，重训未提交树且不重复累加已提交树的残差；恢复后的逐树结构、特征依赖统计、快照版本序列须与无中断执行完全一致，并提供固定样本与变更序列的确定性演示入口。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地分片与特征变更序列验证增量训练、依赖失效范围、中断恢复一致性与快照版本，附可复现运行结果。
