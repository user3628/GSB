当前是空白工作区，需要从零实现一个面向本地消息中间件场景的“跨版本消息中继与投递语义组件”，用于在离线环境下复现真实消息系统在格式互操作与版本兼容上的核心机制。中继接收上游生产者以两种消息编码格式（旧版紧凑二进制信封 v1 与新版带扩展头的自描述信封 v2）发布的消息，按主题与分区路由，持久化到本地日志段，再向下游消费者按至少一次语义投递并接受确认。v1 信封只支持基础字段：消息标识、主题、分区键、时间戳、负载长度与负载字节，负载原样透传；v2 信封在此基础上扩展了头部映射（字符串键值对）、内容类型、投递属性（延迟刻度、优先级、过期刻度）与生产者链路标识。中继在同一条日志段与同一份投递状态中必须同时承载两种来源的消息，并保证下游无论以 v1 还是 v2 视图消费同一消息都能得到语义等价的基础字段；当 v2 专有属性无法在 v1 视图中表达时，必须按显式定义的降级规则处理而不是静默丢弃。与此同时，至少一次语义要求确认丢失后的重投不能改变消息的可见顺序与去重结果，中继重启后未确认消息必须延续原顺序重新投递。

任务环境与准备：
安装 Python 3.11 及以上版本，创建本地虚拟环境并安装 pytest 与标准库之外的零依赖扩展（仅使用标准库的 http.server 与 sqlite3 即可运行）。
在空白工作区中创建项目目录与样本目录，准备 v1 与 v2 混合消息的本地 JSON 样本以及中继配置默认值文件（兼容默认值、降级规则表、超时与重投上限）。
确认 Windows 上可本地回环绑定 HTTP 端口并读写工作区内的临时目录与 SQLite 文件，全程不访问外网、不使用容器或外部消息服务。

业务要求：
1. 实现 v1 与 v2 两种消息信封的编解码与自描述校验：v1 为定长头加负载，v2 为带变长头部映射的自描述结构，两种编码都须能识别魔数、格式版本与整体 CRC32；解码须拒绝截断报文、魔数不符、CRC 失配与声明长度与实际长度不符，并分别返回固定业务码（E_BAD_MAGIC、E_BAD_VERSION、E_CRC_MISMATCH、E_TRUNCATED），错误信息须指向出错字段偏移。
2. 实现跨版本字段投影与降级规则：以 v2 视图读取 v1 消息时，头部映射须为空、内容类型取声明的默认值、投递属性取中继配置的兼容默认值，并在视图中标记来源版本；以 v1 视图读取 v2 消息时，仅暴露基础字段，v2 专有属性无法表达的须在视图中产生显式降级记录（含被降级属性名与降级原因），不得被静默丢弃；同一消息两种视图的基础字段必须逐字段相等。
3. 实现按主题分区的有序日志段持久化：消息按主题与分区键散列进入分区日志段，段内以严格递增的段内偏移追加，段头记录魔数、格式版本、分区标识、条目数与 CRC32；写入须保证原子性，中途失败不得留下半条记录，重启时须能截断残缺尾部并保留完整前缀，截断后的段内偏移不得出现空洞。
4. 实现至少一次投递、确认与去重语义：未确认消息在确认超时后须按原段内顺序重投，重投次数超过上限时转入死信并以固定业务码 E_DELIVERY_EXHAUSTED 报告；消费者以消息标识加来源版本作为去重键，同一去重键的重投不得被下游视为新消息；重投不得改变同分区内已确认消息之后消息的可见顺序。
5. 实现投递属性的跨版本生效与过期判定：v2 消息的延迟刻度、优先级与过期刻度须在同一逻辑刻度体系中判定，v1 消息按兼容默认值参与同一判定；过期消息在投递前须被判定为已过期并以 E_MESSAGE_EXPIRED 拒绝投递且不占用重投次数；逻辑刻度须持久化，重启后与日志段中记录的刻度保持单调一致。
6. 实现进程重启后的投递状态恢复与顺序延续：确认位点、重投计数、死信登记与逻辑刻度须在确认提交点以单事务写入 SQLite；重启后须从已提交的确认位点继续投递，中断时处于投递中的消息须回退为未确认并按原顺序重投，且恢复后的可见序列与崩溃前已确认前缀一致。
7. 实现并发生产与消费下的分区一致性：同一分区的追加写入须串行化到分区边界内，不同分区可并行；消费者并发拉取同一分区须各自获得不重叠的可见区间或同一区间但可安全去重，不得出现两方同时视为首投；并发写入与拉取竞争时须以真实超时返回 E_CONTENTION_TIMEOUT 而非无限阻塞。
8. 提供本地 HTTP 接口、可集成的示例与可重复测试：通过本地 HTTP 提供生产消息（可指定信封版本）、拉取消息（可指定消费视图版本）、确认、查询分区日志状态与死信清单的接口，错误统一以业务码在 JSON 中返回；附带使用本地样本驱动 v1 与 v2 混合消息流的完整示例，pytest 用例须在 Windows 离线覆盖格式拒绝、跨版本投影等价、确认超时重投去重、过期拒绝、重启顺序延续与并发分区一致性。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
