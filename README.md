当前是空白工作区，需要从零构建一个面向本地图数据存储与查询的图遍历与索引组件，提供带版本号的图快照、邻接索引与路径查询能力，供上层图分析应用集成。图由节点（标识、标签、属性）与有向边（源、目标、类型、权重）组成，索引包括按节点标签的倒排索引与按边类型的邻接索引。查询请求包括多跳邻接遍历、最短路径与指定模式的路径匹配。组件需支持增量更新：新增或删除节点与边时，只更新受影响的节点标签倒排索引、边类型邻接索引以及依赖这些索引的路径查询缓存。核心业务问题是交互延迟与计算结果一致性：调用方可在低延迟预算下请求快速结果，也可请求精确结果；两种模式必须对同一快照版本在可界定偏差内给出可解释的结果，且过期索引项不得影响查询正确性，并发更新与查询之间必须保持版本绑定。所有数据来自本地确定性样本，不依赖外部图数据库或网络服务。

任务环境与准备：
安装 Python 3.10 或以上版本，并确保 pip 可用。
安装 NumPy 与 pytest：pip install numpy pytest。
准备本地固定图样本 JSON（节点、边、版本号与校验摘要）以及查询请求样本，存放于工作目录下的 samples 子目录。
使用 SQLite 3（Python 内置 sqlite3 模块即可）作为持久化存储，无需额外安装数据库服务。
确保本地回环端口可用，用于启动 HTTP API 服务与端到端演示脚本。

业务要求：
1. 实现图快照加载与版本识别：快照文件为本地 JSON，携带单调递增的版本号、生成时间、节点集合、边集合与整体校验摘要；加载时须校验版本单调与摘要，失败返回业务码 E_SNAPSHOT_INVALID，且加载失败必须保持旧快照可用，不得出现部分加载状态。
2. 实现节点标签倒排索引与边类型邻接索引：标签倒排索引以标签为键记录节点标识集合，邻接索引以(边类型, 源节点)为键记录目标节点与权重列表；增量更新时只对受影响的标签与邻接键做增量修改，删除节点或边时须从全部相关索引条目中移除引用并把空条目清理，索引写入与图数据写入必须原子生效。
3. 实现多跳邻接遍历与最短路径查询：多跳遍历按声明的跳数上限沿邻接索引展开，结果按节点标识稳定排序并去重；最短路径基于边权重使用确定性实现，当图中存在零权重或负权重边时返回 E_WEIGHT_INVALID，遍历过程中须检测到节点或边缺失并返回 E_GRAPH_INCONSISTENT 并指明缺失位置。
4. 实现低延迟快速结果与精确结果两种模式：快速模式按配置的遍历节点上限与索引预取预算提前截断并输出被截断分支数与模式标记，精确模式给出完整结果；两种模式对同一快照版本的结果差异须在输出中逐项可核对，快速模式不得返回精确模式下不存在的节点或路径。
5. 实现索引版本绑定与查询缓存一致性：查询请求须携带或解析出图快照版本，缓存键包含快照版本与查询签名；当请求绑定的版本在查询期间被新版本替换时，须在该绑定版本上完成查询或返回 E_VERSION_RETIRED，不得混用新旧版本的索引结果；过期索引项不得影响查询正确性。
6. 实现增量更新的级联失效与原子重建：为每个标签与邻接键维护其对遍历结果、最短路径缓存与查询缓存的引用关系；当某节点标签或边类型变化时，受影响索引条目及其下游缓存必须级联失效并在同一事务边界内原子重建，禁止出现部分索引已更新而依赖它的缓存仍为旧值的中间可见状态。
7. 实现单写者更新与多读者查询的并发一致：图数据与索引的增量更新按快照版本单写者串行执行，多个只读查询可并发读取某一完整提交版本；同一请求标识重复提交只执行一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_REQUEST；查询不得看到图数据已更新而索引未更新的中间状态。
8. 实现统一业务错误码与基于 SQLite 的意图持久化及强制终止恢复：所有失败响应为含业务码与上下文的 JSON，至少覆盖 E_SNAPSHOT_INVALID、E_WEIGHT_INVALID、E_GRAPH_INCONSISTENT、E_VERSION_RETIRED、E_CONFLICTING_REQUEST；图数据、索引与查询缓存的写入前先写意图记录再提交事务，进程被强制终止后重启须扫描未完成意图，把索引与缓存回滚到最后一个完整版本或标记为已中止，恢复报告只基于已持久化事实。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
