当前为空白工作区，需从零构建一个本地可运行的模型能力评测与选择引擎，面向多模型多基准的评测结果汇总与模型排序场景。输入为若干本地 JSONL 评测分片，每条记录含 run_id、model_id、benchmark_id、sample_id、原始输出文本、参考标准答案、语言标签与来源批次；样本与伪推理输出由固定随机种子的本地生成器产出，不依赖任何真实模型、API、GPU 或线上站点。引擎按四个阶段执行：输出规范化与自动判分（文本规范化后按精确匹配与 token 级重叠度打分）、按模型与基准聚合（分项得分、有效样本数与异常样本剔除）、加权能力画像（按语言与题型分层加权，映射为若干能力维度得分）、模型排序与选择结论（含并列裁决与最小可用样本量约束）。评测结果的增量化是核心难点：基准答案、判分规则、分层权重或样本集合变化时，必须准确判定哪些聚合结果与模型排序失效、哪些可继续复用；失效判定错误会导致排序结论与真实数据不一致，因此需要可验证的依赖关系建模。

任务环境与准备：
安装 Python 3.11 或以上版本，使用标准库 json、hashlib、unittest 与第三方库 numpy，建议通过本地虚拟环境安装并固定版本。
安装 pytest 用于运行本地测试，无需联网下载任何数据集或模型权重。
任务开始前在工作区创建空的 samples、configs 与 work 目录，所有评测分片与基准答案由本地固定种子生成器脚本产出。
确认运行在 Windows 本地文件系统上，文件锁与原子写入使用 os.replace 等本地机制实现，不依赖容器或外部服务。

业务要求：
1. 实现规范化与自动判分阶段：对原始输出文本做 Unicode NFKC、空白折叠、全半角统一与小写化后，按参考标准答案计算精确匹配得分与 token 级重叠度得分，并按可配置权重合成单样本得分；同一输入与规则必须产生逐字节一致的判分结果，空输出、参考答案缺失或重叠度为 0 的情况须有确定性处理并留存原因。
2. 实现分项聚合与异常剔除阶段：按 model_id 与 benchmark_id 聚合单样本得分，输出有效样本数、平均分与分位数，并按可配置规则剔除长度异常、语言标签不匹配与判分规则不适用的样本；剔除清单须带 sample_id 与剔除原因，聚合结果必须能从剔除后的样本集合逐项复算一致。
3. 实现分层加权能力画像：按语言与题型分层计算加权得分并映射到若干能力维度，权重归一化与累加须在对数域或定点域进行以控制浮点误差，输出各维度的有效权重与样本覆盖说明；当某层有效样本数低于可配置下限时须将该维度标记为证据不足而非按零分处理。
4. 实现模型排序与并列裁决：依据能力画像总分与各维度得分排序，总分在可配置容差内视为并列并按最小可用样本量、基准覆盖数与稳定模型标识做确定性仲裁；输出排序结论、仲裁理由与被挤出模型的落选原因，同输入同配置的排序结论须逐字节一致。
5. 实现阶段检查点与优雅停止恢复：四阶段各自完成时以原子方式写入含阶段名、输入分片内容摘要、配置版本、产物摘要与单调序号的记录，写入任意位置中断不得留下半写记录；收到停止请求时完成当前不可拆分聚合单元后退出，恢复后最终排序结论须与一次从零完整运行逐字节一致且序号连续。
6. 实现版本指纹与依赖失效传播：当参考答案、判分规则、剔除规则、分层权重或样本集合任一变化时，通过各阶段内容摘要构成的版本指纹识别受影响的最早阶段，使该阶段及其全部下游产物（含模型排序）失效并重建；未受影响上游产物继续复用，失效原因与受影响模型清单须在查询接口中可观测。
7. 实现增量重建与全量一致性校验：提供单基准答案更新与单批次样本替换入口，仅重建失效链路后与从零全量构建的聚合结果、能力画像与排序结论做逐字节摘要比对；检测到不一致须返回 E_INCREMENTAL_MISMATCH 并附首个差异阶段与差异模型标识，禁止以旧版本结果冒充新版本结论。
8. 实现并发发布保护与稳定业务错误码：多个工作进程对同一工作区发布阶段产物时使用文件锁并比较检查点序号，仅允许序号连续推进，落后、重复或跨阶段错位发布返回 E_STALE_CHECKPOINT；请求非法阶段跳转、缺失前置阶段产物或引用不存在基准时返回 E_INVALID_STAGE，错误码须在 JSON 输出与查询接口中保持一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
