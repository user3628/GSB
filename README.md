当前是空白工作区，需要从零构建一个面向本地分片列存数据的聚合执行组件，供上层报表计算管线集成。组件读取本地确定性列存快照（每列含数据类型、空值位图与按键哈希预分区的数据块），按请求中的聚合规格执行分区聚合、分组求和与分位计算，并在执行过程中维护分区状态演进：每个分区在 PENDING、SCANNING、AGGREGATED、SKEWED、ABORTED 之间迁移。真实数据存在严重倾斜，某些分区记录数与度量量级远超其他分区，组件需在全局并发扫描上限、单分区内存预算与每轮时间预算下调度，并对倾斜分区做拆分或降级处理。进程可能在任意时刻被强制终止，重启后必须依据 SQLite 中持久化的意图记录、分区聚合部分和与会话进度恢复，使继续摄入后续批次后的聚合结果与从未中断时逐项一致。用户通过本地 HTTP 接口提交聚合会话、按基础版本追加后续批次、查询分区状态与结果、模拟中断与恢复。

任务环境与准备：
确认 Windows 上已安装 Python 3.11 或以上，并可在命令行运行 python --version。
安装 NumPy 与 requests：python -m pip install numpy requests。
在任务工作目录下放置本地列存快照 JSON 样本与聚合请求样本，样本由脚本生成且固定随机种子，不需要外部数据集或网络账号。
确认 SQLite 随 Python 标准库可用，无需额外数据库服务。
启动本地 HTTP 服务前确保所用回环端口未被占用，所有请求仅访问本机回环地址。

业务要求：
1. 实现列存快照加载与版本识别：快照携带单调递增版本号、生成时间、列定义（数据类型与空值位图）、按分区键哈希预分区的数据块索引与整体校验摘要；加载时校验版本单调与摘要，失败返回 E_SNAPSHOT_INVALID，且加载失败必须保持旧快照与旧会话状态完全可用。
2. 实现分区聚合核心：对每个分区按分组键计算计数、求和、最小值、最大值与分位值，求和采用 Kahan 补偿求和以降低混合量级样本的累计误差，分位使用确定性最近秩法并注明样本规模；空值度量不计入求和与均值但计入计数，空分区与全空列返回确定值而非异常。
3. 定义分区状态机，至少包含 PENDING、SCANNING、AGGREGATED、SKEWED、ABORTED 五种状态并规定合法迁移路径；非法迁移返回 E_INVALID_TRANSITION 且不修改任何已持久化状态；状态迁移与分区聚合部分和必须在同一事务边界内提交。
4. 实现倾斜识别与拆分区处理：当某分区记录数或度量量级超过同批次声明阈值时标记为 SKEWED，并按确定规则把该分区拆为子分区继续聚合或走降级路径，输出倾斜判定依据、拆分数与降级原因；拆分后的子分区部分和合并结果必须与不拆分时逐位一致。
5. 实现三重预算调度：分区扫描任务在全局并发上限、单分区内存预算与每轮时间预算约束下执行；预算内按分区号升序取任务，超并发上限者进入有界等待队列，队列满返回 E_SCAN_QUEUE_FULL；单分区估算内存超预算时须先尝试拆分区，仍超则降级并记录，禁止无界占用内存。
6. 实现强制终止后的恢复：分区扫描、部分和写入与状态迁移前先写 SQLite 意图记录再提交事务；进程在 SCANNING 或拆分区中途被强制终止后重启须扫描未完成意图，把未提交分区恢复为 PENDING 重排或标记 ABORTED，并输出仅基于已落盘事实的恢复报告，不得承诺强制终止后仍能生成完整退出报告。
7. 实现单写者执行与多读者查询的并发一致：会话提交、分区状态迁移与拆分区重建按会话单写者串行执行，多个只读查询可并发读取某一完整提交版本；同一会话标识重复提交只执行一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_SESSION；查询不得看到分区已 SKEWED 而其子分区部分和尚未写入的中间状态。
8. 实现幂等批次追加与统一错误响应：聚合会话支持按基础版本追加后续数据批次，基础版本非当前版本返回 E_STALE_BASE 且不改变状态，仅追加且分组键单调时走快速路径；所有失败响应为含业务码与上下文的 JSON，至少覆盖 E_SNAPSHOT_INVALID、E_INVALID_TRANSITION、E_SCAN_QUEUE_FULL、E_CONFLICTING_SESSION、E_STALE_BASE。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地倾斜列存样本验证聚合、拆分区合并一致性、批次追加与强制终止恢复，错误码一致。
