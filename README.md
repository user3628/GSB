一位独立开发者接下了内部安全运维组交来的单项需求：在空白工作区实现一个主机安全基线漂移审计引擎，把配置基线的实际观测与声明期望比对，算出漂移等级并给出可复核的修复建议。基线项与观测样本由内置固定种子生成器产出，观测既有 JSON 行清单，也有旧版加固工具遗留的带长度前缀文本块，两代格式在字段存在性与时间精度上不同。审计任务要在有限并发、每轮时间预算与修复动作配额三重约束下推进，进程随时可能被强制终止，重启后只能依据 SQLite 中已落盘的事实恢复审计会话与基线项结论。

任务环境与准备：
安装 Go 1.22 或以上版本并确认 go version 可用，安装 sqlite3 命令行工具用于核对持久化事实。
在空白工作区初始化 Go 模块（go mod init），仅引入标准库与本地 SQLite 驱动，不依赖任何外部服务、账号或付费资源。
准备内置固定种子生成器产出的基线项样本、JSON 行观测清单与旧版长度前缀文本块，以及可在本地回环启动、可注入拒绝与不响应的 HTTP 测试端点。
确保可重复清理本地数据库与临时目录，以便多次运行强制终止后恢复的演示并比对恢复报告。

业务要求：
1. 实现基线项、观测样本与审计会话模型：基线项声明标识、类别（账户策略、审计策略、服务启动类型、注册表键权限）、期望取值、严重度权重与依赖的其他基线项，观测声明目标主机、基线项标识、实测取值与毫秒采样时刻；解析时校验基线项标识唯一、权重为正整数、依赖引用存在，失败返回 E_BASELINE_INVALID 且整批不入库。
2. 实现两种观测来源的解析与归一化：JSON 行清单每行含主机、基线项、实测取值与毫秒时刻，旧版文本块以长度前缀分段并含微秒时刻与可能缺失的可选字段；两代来源须归一化为同一内部毫秒表示，按调用方声明的截断规则处理亚毫秒部分并输出每条记录的舍入位与累计舍入误差，同一观测在两代格式下归一化后必须逐字段一致。
3. 实现漂移判定核心：把期望取值与实测取值按类别比较，账户与审计策略按数值区间比较，服务启动类型与注册表键权限按声明枚举与集合包含比较，区间端点包含关系须显式声明；判定输出漂移类别（缺失、多余、取值偏移、来源冲突）与漂移等级，严重度权重与偏移幅度合成等级时使用整数或显式定点表示并输出舍入说明；比较失败或取值类型不符返回 E_VALUE_TYPE_MISMATCH。
4. 实现并行审计调度器：审计任务受全局并发上限、每轮时间预算与修复动作配额三重约束，预算内按严重度权重与主机轮转取任务，超出并发上限者进入有界等待队列，队列满返回 E_AUDIT_QUEUE_FULL；修复配额按严重度加权消耗，配额耗尽时按确定性降级次序把剩余任务标记为 DEFERRED 并输出降级依据与剩余配额，禁止静默丢弃任务。
5. 实现向本地测试端点的真实探测与可中断超时：对每条基线项向本地回环测试端点发起真实 HTTP 探测以核对实测取值，每次探测具备独立超时，超时后必须真实关闭底层连接并释放其占用的并发名额，返回 E_PROBE_TIMEOUT；连接被拒绝返回 E_PROBE_REFUSED，响应可解析但取值不符返回正常的漂移结论而非错误。
6. 实现依赖驱动的失效传播与陈旧读裁决：基线项之间的依赖决定某基线的漂移是否放大下游基线项等级，传播跳数不得超过声明上限；读请求携带观察版本，若受影响基线项的结论视图版本不高于观察版本则返回并标注版本，若因传播未完成而落后于观察版本必须返回 E_STALE_READ 并附视图版本与观察版本。
7. 实现带单调版本号的基线快照与增量片段提交，并进行结论级联失效与原子重建：增量只含受影响基线项或观测并携带基础版本，基础版本非当前版本返回 E_STALE_BASE 且不改动任何已提交状态；某一基线项的期望取值、依赖边或严重度权重变化时，其漂移结论、下游等级与主机汇总必须级联失效并在同一事务边界内原子重建。
8. 实现基于 SQLite 的单写者提交、多读者查询与强制终止恢复：审计推进、结论写入与级联重建按会话单写者串行执行，多个只读查询可并发读取某一完整提交版本，不得看到基线项已判定 DEFERRED 而主机汇总仍为旧值；所有写操作先落意图记录再提交事务，强制终止后重启须扫描未完成意图把审计会话回滚到最后一个完整版本或标记为已中止，恢复报告只基于已落盘事实。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用内置固定样本与本地回环端点验证漂移判定、预算降级、增量级联失效及强制终止后的恢复一致性。
