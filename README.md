当前是空白工作区，需要在 Windows 本地从零构建一个面向本地回环环境的 DNS 递归解析缓存中间件与诊断工作台，供网络运维人员排查域名解析行为。中间件同时以本地 UDP 与 TCP 侦听真实 DNS 查询，向本地确定性权威测试服务器递归取回 A、AAAA、CNAME、MX、TXT 记录，维护带生存期的正缓存与负缓存，并在全局并发上游查询上限、每权威服务器并发上限与每轮时间预算三重约束下并行推进解析任务。真实运维中大量客户端会同时查询高度集中的少数热点域名，同时又有长尾域名竞争同一批上游名额，缓存命中、上游合并与预算排队之间存在明显冲突：合并能减少上游压力但会拉长尾部等待，扩大并发能降低延迟却可能突破上游承压上限，而在预算耗尽时必须确定性地牺牲部分长尾查询并给出可核对的原因。中间件需持久化解析会话与缓存条目，进程被强制终止后依据已落盘事实恢复。用户通过本地 HTTP 接口提交诊断查询、查看缓存与调度轨迹，并以可重复脚本核验行为。

任务环境与准备：
确认 Windows 本机可用 Python 3.11 及以上，并可在无管理员权限下绑定 127.0.0.1 的高位端口用于 UDP 与 TCP 侦听。
创建空白工作目录，准备虚拟环境并安装 fastapi、uvicorn、dnslib、pytest 等依赖，安装来源为本地已缓存或可离线获取的包。
准备本地确定性权威测试服务与固定查询样本文件，全部位于回环地址，不依赖真实域名、外部 DNS 或线上站点。
准备 SQLite 数据库文件路径与日志目录，并确认进程可被强制终止以验证恢复路径。

业务要求：
1. 实现 DNS 报文编解码与递归解析会话：支持 A、AAAA、CNAME、MX、TXT、NS 与 SOA 类型，正确处理域名压缩指针、标签长度上限与报文截断，畸形报文、非法压缩指针或超长标签返回业务码 E_MESSAGE_INVALID 且不建立会话；沿 CNAME 链追踪并受配置最大跳数约束，出现环或超长分别返回 E_CNAME_LOOP 与 E_CHAIN_TOO_LONG，并把最终对答码与来源记录类型记入会话。
2. 实现正负缓存的生存期语义：条目记录写入时刻、原始 TTL 与来源记录类型，命中时按已流逝毫秒递减返回剩余 TTL，过期条目不得命中且须被清理；NXDOMAIN 与 NODATA 按 SOA 中声明的负缓存 TTL 缓存，负缓存条目的剩余寿命同样可查询；缓存键由规范化查询名（小写、统一末尾点、保留转义标签）、查询类型与类别组成，大小写混写查询不得产生重复条目或不同应答。
3. 实现并行上游解析调度器，以全局并发上游上限、每权威服务器并发上限与每轮时间预算三重参数约束执行：预算内按查询优先级（热点域名与显式高优先级优先）与到达顺序取任务，超出并发上限的任务进入有界等待队列，队列满返回 E_QUEUE_FULL；同一权威服务器在途查询不得超过其并发上限，调度器须保证同一会话在同一轮内不被重复派发，并输出本轮派发清单、等待清单与被跳过清单。
4. 实现上游合并与预算冲突裁决：多个客户端并发查询同一未缓存域名时仅首个查询触发上游解析，其余挂起等待并复用同一结果；当合并等待会令某长尾查询超出本轮时间预算时，按确定性规则决定继续等待共享结果还是为其单独派发上游查询，并输出该裁决的依据数值；共享结果回填缓存后，所有等待者必须得到同一应答与同一 TTL 递减起点，不得出现不同等待者 TTL 不同的中间状态。
5. 实现真实上游超时与资源释放：每跳上游解析具备独立超时，超时后必须真实关闭对应 UDP 套接字或 TCP 连接并返回带业务码 E_UPSTREAM_TIMEOUT 的 SERVFAIL 应答，同时释放其占用的全局与权威服务器并发名额；某查询挂起不得阻塞其他查询，也不得使整轮越过时间预算继续执行，不得以等待冒充超时。
6. 实现缓存写入与并发查询的一致性：缓存写入、负缓存写入与会话状态推进按单写者串行提交，多个查询可并发读取；查询读取只能看到某一完整提交版本的缓存内容，不得出现会话已记录命中而缓存条目尚未写入、或缓存条目已写入而索引尚未更新的中间可见状态；请求指定以某查询标识重复提交时只执行一次，其余等待复用同一应答，内容不一致返回 E_CONFLICTING_QUERY。
7. 使用 SQLite 持久化缓存条目、解析会话与意图日志，缓存写入前先写意图记录再提交事务；进程被强制终止后重启须扫描未完成意图，把未提交缓存条目回滚、把未完成会话标记为已中止或按已落盘事实重新排队，恢复报告只包含已落盘事实，不得声称强制终止后仍能生成完整退出报告；恢复后对同一域名的查询结果须与中断前已完成部分一致。
8. 提供本地 HTTP API 与可重复演示脚本：API 覆盖诊断查询提交、按域名查询缓存条目与剩余 TTL、查询解析会话与调度轨迹、恢复报告查询，所有失败响应为含业务码与上下文的 JSON，至少覆盖 E_MESSAGE_INVALID、E_CNAME_LOOP、E_QUEUE_FULL、E_UPSTREAM_TIMEOUT、E_CONFLICTING_QUERY；脚本使用固定本地权威测试服务与固定查询样本完成一次冷缓存解析、一批热点并发查询触发合并、一次预算耗尽产生跳过、一次上游超时与一次强制终止后恢复，输出每轮派发与跳过清单、缓存命中与剩余 TTL。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地权威测试服务验证解析、缓存 TTL、并行调度合并、预算跳过、真实超时与强制终止恢复。
