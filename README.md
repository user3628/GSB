三维内容管线要在本机把多视角灰度图像增量重建为体素化场景表示，当前工作区尚未初始化，没有任何可沿用的代码或样本，首版需要独立交付可集成的领域组件与完整示例。输入由程序内置固定种子生成器确定性产出：一组低分辨率灰度 PNG 视角分片与一份 JSON 场景清单，逐视角声明旋转矩阵、平移向量、内参、图像尺寸与一组真值采样点坐标，作为校验的唯一真值来源。场景清单存在两种结构版本：版本 2 以结构化字段描述世界坐标系约定（右手系、原点与轴向单位）与相机外参；版本 1 仅以自由文本描述坐标系约定、缺失轴向单位声明且内参以焦距像素比表示，需在导入时按可配置规则做约定归一与单位换算。重建按视角投影采样、视角局部体素贡献体构建、全局体素融合稀疏化、重建校验四阶段推进，运维人员通过本地 HTTP 接口导入分片、调整相机或融合参数、触发重建并查询点云摘要与误差统计，阶段进度与产物以事务形式落进本地 SQLite。难点集中在坐标系约定的版本互操作与误差传播：不同版本对轴向与单位的解释不同，换算会向体素坐标传导偏差；一步修改相机参数或融合参数就会让部分已落盘体素状态不再可信，而每次重建结果都必须给出可复核的重投影误差上界。

任务环境与准备：
在 Linux（WSL Ubuntu）上创建工作目录并初始化为 Go 模块，使用 Go 1.21 或以上版本。
使用 Go 标准库实现 PNG 解码、JSON 读写与 HTTP 服务；SQLite 通过纯 Go 驱动接入，按模块文档安装对应版本，不依赖容器环境。
确认本地可运行 go build 与 go test；样本由程序内置固定种子生成器在首次运行时写出，无需下载数据集或访问外部服务。

业务要求：
1. 实现两种场景清单结构版本的兼容解析与统一内部坐标系模型：版本 2 读取结构化坐标系约定与外参，版本 1 依据可配置规则解析自由文本约定、补全缺失轴向单位并把焦距像素比换算为内参；转换结果须标注补齐项、换算依据与不可恢复项，当版本号与内容形态不符或轴向单位无法确定时返回带视角标识的稳定业务码，不得默认假定左手系。
2. 实现视角投影采样阶段：按归一后的旋转矩阵、平移向量与内参把每张分片的采样像素映射到世界射线，沿射线以配置步长读取灰度值，输出带分片标识、世界坐标与灰度值的贡献记录；位姿矩阵非正交、内参焦距为零或射线不与图像平面相交时须在对应视角返回带视角标识与环节名的结构化错误，不得产生越界读数。
3. 实现视角局部体素贡献体构建与全局融合：把采样点按体素分辨率量化到体素坐标，在截断距离内累计灰度与命中计数形成局部体素块，再按分片序与视角内顺序融合为全局体素场，按融合半径加权平均灰度并按稀疏度阈值剪枝；零体素块或融合半径为零时须显式标记并与正常体素区分。
4. 实现重建校验与重投影误差上界推导：把全局体素场中与清单真值采样点最近的体素灰度按最近邻或双线性比对，计算逐点偏差、均方根误差与落在可配置容差内点的比例；误差上界须由坐标系换算因子、体素分辨率与采样步长显式推导并保留推导依据，超出容差时返回带视角标识、真值点编号与最大偏差的 E_NUMERIC_MISMATCH。
5. 实现阶段检查点持久化与优雅停止恢复：每个视角每阶段完成时以 SQLite 事务写入含阶段名、视角标识、输入内容指纹、清单结构版本指纹、配置版本、产物摘要与单调序号的记录，同一视角同一阶段只允许一条有效记录；写入任意位置中断不得留下半写记录；收到停止请求时完成当前不可拆分视角单元后退出，不承诺强制终止后生成退出报告。
6. 实现版本变化检测与增量失效传播：当某分片像素内容、相机内外参、坐标系约定、体素分辨率或融合半径任一变化时，通过各阶段内容摘要构成的版本指纹识别受影响的最早阶段与最小视角集合，使该集合及其全部下游体素区域与校验结论失效重建，未受影响体素继续复用，增量重建结果须与从零全量构建逐字节一致，不一致时返回 E_INCREMENTAL_MISMATCH 并附首个差异视角。
7. 实现并发发布保护与快照整体替换识别：多个工作进程对同一 SQLite 库发布阶段产物时使用条件更新与真实文件锁并比较视角内序号，仅允许序号连续推进，落后、重复或跨视角错位发布返回 E_STALE_CHECKPOINT；当场景清单被整体替换时须依据内容摘要与版本序号区分正常推进、整体替换与版本回退，替换后全部派生状态失效重建，回退则拒绝并返回稳定业务码。
8. 提供本地 HTTP 与命令行交互入口及确定性演示：支持导入两版本场景清单与视角分片、执行格式互转与旧版回导、设置相机与融合参数、触发分阶段重建、查询各阶段状态与版本指纹、查看体素摘要与重投影误差上界、请求优雅停止与执行恢复；演示数据至少覆盖 3 个视角与两种清单结构版本。
