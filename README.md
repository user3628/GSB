从一个空仓库出发，需要在 Windows 本地从零构建一个面向 CI 流水线的制品缓存与复用组件，交付数据处理管线与结果验证工具。流水线由若干阶段组成，每个阶段以(阶段标识, 输入指纹, 工具链版本)为缓存键产出以内容摘要寻址的制品；缓存需维护缓存条目的状态演进（含写入、可用、失效、淘汰等阶段），支持按键命中与摘要复核，并在并发写入、进程被强制终止后依据持久化事实恢复一致状态。所有数据来自本地确定性样本与本地 HTTP 测试端点。

任务环境与准备：
安装 Go 1.22 或更高版本，安装 SQLite 由纯 Go 驱动加载，无需 CGO；执行 go mod init 初始化模块并拉取依赖。
在 Windows PowerShell 下确认可启动本地 HTTP 测试端点，端口由环境变量注入，避免使用固定被占用端口。
准备固定本地确定性 JSON 样本（阶段、输入指纹、工具链版本、制品内容与保留期），放入本地样本目录。
无需容器或外部服务；所有测试通过本地回环地址与临时目录完成。

业务要求：
1. 实现缓存条目与阶段制品模型：条目包含阶段标识、输入指纹、工具链版本、制品内容摘要、制品字节大小、命中统计与保留期，解析本地确定性 JSON 样本时做摘要格式与字节数非负校验，非法输入返回业务码 E_ENTRY_INVALID 且整批不入库
2. 定义缓存条目状态机，至少包含 PENDING、WRITING、AVAILABLE、STALE、EVICTED 五种状态并规定合法迁移路径，非法迁移返回 E_INVALID_TRANSITION 且不得修改已持久化状态；写入完成并摘要复核通过后才允许迁移为 AVAILABLE
3. 实现缓存命中判定与复用语义：键由阶段标识、输入指纹与工具链版本规范化后组成，命中须校验条目为 AVAILABLE、制品摘要复核一致且保留期未过期；复核失败或已过期不得命中并分别返回 E_DIGEST_MISMATCH 与 E_ENTRY_EXPIRED，未命中须给出可核对的未命中原因（键不存在、摘要不一致、已过期、已被淘汰）
4. 实现基于内容摘要的批量淘汰与保留期回收：当缓存总字节超过声明容量上限时，按最后命中时刻与条目大小计算确定性淘汰次序并真实释放制品占用，被淘汰条目迁移为 EVICTED 且其命中统计进入历史；保留期到期条目须先迁移为 STALE 再进入淘汰候选，回收前必须写意图记录
5. 实现单写者写入与多读者命中查询的并发一致及幂等：缓存写入、状态迁移与淘汰按单写者串行执行，多个只读命中查询可并发读取某一完整提交版本；同一缓存键并发写入仅一个生效、其余按幂等返回同一结果，内容不一致时返回 E_CONFLICTING_WRITE；查询不得看到条目已 AVAILABLE 而命中统计尚未更新、或已 EVICTED 而制品占用未释放的中间状态
6. 使用 SQLite 持久化缓存条目、制品占用、淘汰记录与意图日志，写入、状态迁移与淘汰前先写意图记录再提交事务；进程在写入或淘汰中途被强制终止后重启须扫描未完成意图，把未提交条目回滚为 PENDING、未提交淘汰回滚为 AVAILABLE，恢复报告只基于已落盘事实
7. 实现快照整体替换与版本识别：缓存清单快照文件携带快照版本、快照序号与生成时间，加载时须校验序号单调与摘要一致，加载过程在内存索引与 SQLite 表之间原子切换，切换成功后旧快照资源与派生命中统计才可释放；任何校验失败须保持旧快照完全可用
8. 提供本地 HTTP 接口与端到端验证工具：接口覆盖缓存写入、命中查询、清单导出与快照切换、淘汰触发、恢复报告查询，统一失败响应为含业务码与上下文的 JSON，至少覆盖 E_ENTRY_INVALID、E_INVALID_TRANSITION、E_DIGEST_MISMATCH、E_ENTRY_EXPIRED、E_CONFLICTING_WRITE；验证工具使用固定本地样本完成一次写入后命中、一次摘要不一致拒绝、一次容量超限淘汰与一次强制终止后恢复，并输出与预期逐项对比的核对结果

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定本地样本验证缓存写入命中、非法迁移与摘要不一致拒绝、容量淘汰及强制终止后状态恢复一致。
