为传统机器学习时序预测团队从零构建一个本地可运行的滞后特征构造与诊断工作台，核心问题是时间序列样本在多种序列化格式与多个模式版本之间的互操作，以及由此产生的泄漏防护、时间轴对齐与版本兼容判定。输入是本地样本目录：一份时序观测清单 JSONL，每条含 series id、时间戳（ISO 8601 字符串，精度到秒）、观测值（浮点）与缺失标记；一份滞后特征方案文件，存在两种格式变体：A 版以窗口对象数组给出滞后步长、聚合方式（mean/sum/last）与窗口内最少有效点数，B 版把同一语义展开为扁平字段 lag_list、agg、min_valid；方案文件带格式版本号与特征名到序列的引用表。工作区为空，需从零创建项目：一个可交互的 FastAPI 服务，提供工程创建、格式归一与兼容判定、滞后特征构造、分阶段执行、查询状态与快照导出接口。团队需要据此构造训练样本并诊断每一步的时间轴误差与泄漏风险。

任务环境与准备：
安装 Python 3.11 及以上版本，并确保 python 与 pip 可在命令行直接调用。
安装运行依赖：pip install fastapi uvicorn numpy 及其兼容版本，不需要外部服务或网络数据源。
在本地样本目录准备时序观测清单 JSONL、A 版与 B 版滞后特征方案文件、旧版本方案文件，均为固定内容、可重复读取的本地文件。
准备可写的本地工作目录用于 SQLite 数据库、特征文件与快照文件，确认进程对该目录有读写权限。
启动服务前确认监听端口在本机可用，演示入口使用固定参数并可通过命令行或 curl 重复触发。

业务要求：
1. 工程创建接口接收观测清单、滞后特征方案文件与浮点容差，校验 series id 唯一、时间戳可解析且同一序列内严格递增、观测值与缺失标记互斥、窗口最少有效点数为正整数，方案任一非法返回 E_PARAM 并指出文件与行号，且不得创建任何结果文件或临时目录。
2. 须实现 A 版窗口对象数组与 B 版扁平字段到统一内部方案的确定性互转，聚合方式与窗口语义在两版之间须保持等价，往返转换后方案逐字段一致；A 版与 B 版对同一样本序列产出的滞后特征必须逐位相同，任何差异须返回 E_FORMAT 并指出特征名与首个差异样本。
3. 滞后特征构造须以时间戳而非行号定位滞后步长：按方案给的步长回溯同序列上的历史观测，窗口跨越缺失观测时按最少有效点数规则决定该特征是否可算，聚合在 float64 下按时间戳升序累加；不可算的窗口须标记并计数，不得静默填零或丢弃整条序列。
4. 须实现泄漏防护校验：任何特征在时刻 t 的取值只允许使用时间戳严格早于 t 的观测，构造完成后须以独立复核路径重算每个特征的可用时间上界，若发现某特征用到了 t 及以后的观测须返回 E_LEAK 并定位 series id、特征名与时刻 t，禁止以关闭校验换取构造通过。
5. 方案文件须支持版本兼容判定与迁移：按版本号逐字段比较当前方案与旧版方案，只有聚合方式可归一到同一语义、滞后步长集合为原有子集、最少有效点数不放松的差异才允许迁移；不可映射字段须返回 E_COMPAT 并列出字段名与原因，被拒绝字段不得被静默丢弃后继续构造。
6. 须实现整体替换的版本化快照与缓存失效：快照含配置指纹（方案内容哈希、格式版本与容差）、逐序列样本摘要与特征文件内容哈希；读取快照时若检测到磁盘文件哈希与数据库记录不一致、配置指纹或格式版本变化、残留旧版本特征文件，须返回 E_STALE 并定位到序列与文件，禁止汇入旧数据。
7. 构造进度须在 SQLite 中以工程、阶段、序列三级事务提交，单条序列的滞后特征摘要、泄漏复核结论与进度标记在同一事务中写入；进程被强制终止后重启须核对已提交序列的特征文件哈希与进度标记，重算未提交序列且不重复消费已提交序列，恢复后的特征矩阵与快照版本序列须与无中断执行完全一致。
8. 须提供诊断工作台接口与确定性本地演示入口：输出 A 版与 B 版互转一致性结论、被拒绝的兼容字段清单、不可算窗口数、泄漏命中清单、逐序列样本数与快照版本序列；演示使用固定样本与两版方案跑出可重复结果，并给出可用等价参数复现的请求示例。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地固定样本与两版方案验证格式互转、滞后特征结果、泄漏拦截与中断恢复前后一致性。
