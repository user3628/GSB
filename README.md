针对需要持续调整访问控制的多服务主机，团队要在 Windows 空白工作区从零交付一套主机文件权限策略治理工作台。平台维护若干受管路径与命名主体（进程账户、服务账户、组），权限策略以带单调版本号的 JSON 快照与只含局部改动的增量片段提交；每次变更需在真实本地文件系统上创建受管目录与文件，并用 Windows 安全描述符建立实际访问控制项，再以真实文件打开验证拒绝与放行。难点在于增量变更引发的依赖失效：组嵌套、路径继承与策略版本都会使下游主体对下游路径的有效权限判定失效，工作台须级联重算并回答携带观察版本的读者能否直接读取、还是必须拒绝以免返回陈旧权限结论。

任务环境与准备：
Windows 10 或以上，安装 Go 1.22 或以上（go version 验证），SQLite 驱动可用 github.com/mattn/go-sqlite3（需 CGO 与本地编译工具链）或纯 Go 驱动，任选其一。
准备一个可写的临时工作目录作为受管根，样本 JSON 与增量片段由程序内置生成器确定性产出，不依赖外部网络与真实账户。
以具备创建文件与设置安全描述符权限的本地账户运行；运行前确认临时目录为空，运行后由工作台自行清理其创建的受管内容。

业务要求：
1. 实现受管路径、命名主体与策略快照的加载：主体声明标识、类型（用户账户、服务账户、组）、成员列表，受管路径声明相对路径、是否继承父级与初始访问控制项集合；解析时校验主体标识唯一、组成员引用存在、路径不含盘符与上跳段，失败返回业务码 E_SPEC_INVALID 且整批不生效。
2. 实现策略快照整体替换与增量片段提交：快照携带单调递增版本号、生成时间与整体校验摘要，增量片段只含受影响主体或路径并携带基础版本；基础版本非当前版本返回 E_STALE_BASE 且不改变任何已提交状态，同一基础版本的两个并发增量只允许一个成功、另一个返回 E_STALE_BASE。
3. 实现真实文件系统落地与访问控制项应用：加载策略时在独立临时根目录下创建受管目录与文件，按策略把访问控制项以真实安全描述符写入文件系统，应用后须回读实际访问控制项与期望比对，不一致返回 E_APPLY_MISMATCH 并附路径与不一致条目。
4. 实现真实访问验证：对每个主体针对每个受管路径以真实文件打开验证放行或拒绝，分别以请求写权限和请求读取权限两种打开方式各验证一次，拒绝须源于内核返回的访问被拒而非组件自行判定；验证结果记录打开方式、请求权限与实际结果，不得把组件预判当作用户态结论。
5. 实现有效权限判定的依赖失效与级联重建：主体有效权限由直接访问控制项、所属组的嵌套成员关系与路径继承共同决定；组变更或路径继承变化时，受影响主体及其下游路径的有效权限视图、验证结论与摘要必须级联失效并在同一事务边界内原子重建，禁止出现部分视图已更新而其余仍为旧值。
6. 实现版本绑定读取与陈旧拒绝：读请求携带观察版本，若该主体对路径的有效权限视图版本不高于观察版本则返回结论并标注所用版本；若因增量传播未完成而落后于观察版本，必须返回 E_STALE_READ 并附视图版本与观察版本，禁止返回可能过期的权限结论。
7. 实现访问验证的并发预算裁决：目录与文件落地及访问验证任务受全局并发验证上限与每轮时间预算共同约束，超出上限的路径进入有界等待队列，队列满返回 E_VERIFY_QUEUE_FULL，预算耗尽时按主体优先级与路径稳定次序给出确定性降级清单并记录被跳过路径。
8. 实现 SQLite 意图持久化与强制终止后恢复，并提供本地 HTTP 接口：策略提交、访问控制项应用、级联重建与验证结论写入前先写意图记录再提交事务；进程被强制终止后重启须扫描未完成意图，把未提交的访问控制项应用回滚到最后一个完整版本或标记为已中止，恢复报告仅基于已落盘事实；失败响应为含业务码与上下文的 JSON，至少覆盖 E_SPEC_INVALID、E_STALE_BASE、E_APPLY_MISMATCH、E_STALE_READ、E_VERIFY_QUEUE_FULL。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
在本地目录树与真实文件访问上验证权限落地、拒绝放行、增量失效级联与陈旧读拒绝，并附恢复报告。
