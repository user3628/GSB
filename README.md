方案评审已通过，团队需要在 Windows 空白工作区把一套跨语言实体链接的数据处理管线与结果验证工具落成可运行代码。输入为若干本地 UTF-8 JSONL 文档分片，每条含 doc_id、tokens、每 token 的字符偏移、候选实体片段（起止 token 下标）、语言标签与来源通道；另有一份本地知识库分片，每个实体条目含实体标识、规范名、别名列表（中英混排）、类型标签与条目版本号。管线需把候选片段与知识库条目做跨语言对齐：以字符 n-gram 与别名覆盖度在对数域打分，结合类型标签相容性裁决唯一链接目标，无法裁决时给出并列候选与依据。真实业务中知识库条目会分批新增、改别名与被整体替换，候选片段也可能被重新切分，因此管线必须识别版本变化、只重建受影响阶段，并保证增量结果与从零全量结果逐字节一致。

任务环境与准备：
Windows 本地工作区，安装 Go 1.22 或以上版本并确认 go 命令可用。
选用 modernc.org/sqlite 等纯 Go 驱动时无需 C 编译器；若改用 mattn/go-sqlite3 须先确认 CGO 与 C 工具链可用。
准备程序内置固定种子生成器产出的 JSONL 文档分片、本地知识库分片与 YAML 配置，样本随项目生成，不依赖外部数据集或网络。
在项目目录内执行 go mod init 初始化模块，并通过 go get 拉取所选 SQLite 驱动与 YAML 解析库。
运行前确认工作区可写，阶段检查点文件与 SQLite 库写入独立临时目录。

业务要求：
1. 实现候选片段规范化与跨语言别名索引阶段：对文档 token 与实体片段做 Unicode NFKC、空白折叠与全半角统一，按字符 n-gram 建立别名索引，中英文别名须能互通检索；同一输入必须产生逐字节一致的索引摘要，空片段、片段下标越界或 n-gram 长度配置为零时返回带 doc_id 与片段下标的结构化业务码。
2. 实现跨语言一致性打分与类型相容裁决：以字符 n-gram 覆盖率、别名命中与来源通道先验在对数域合成链接分，并按知识库条目的类型标签与片段上下文类型相容性过滤；分数并列时须有确定性仲裁规则，对数域出现 NaN 或 Inf、类型标签不在知识库类型表内时返回带 doc_id 与实体标识的业务码。
3. 实现并列候选诊断与无法裁决输出：对最高分并列或相容性不足的片段输出并列候选清单、各候选分数分量与被排除原因，不得静默丢弃；无法裁决须保留全部候选与判定依据供复核，且诊断输出须能按文档与片段下标确定性复现。
4. 实现阶段检查点持久化与优雅停止恢复：管线按索引构建、打分裁决、结果汇总三阶段推进，每阶段完成时以原子方式写入含阶段名、输入内容摘要、配置版本、产物摘要与单调序号的记录，写入任意位置中断不得留下半写记录；收到停止请求时完成当前不可拆分文档单元后退出，不承诺强制终止后生成退出报告，恢复后的产物须与一次从零完整运行逐字节一致。
5. 实现知识库条目增删改与整体替换的版本识别：当某条目别名或类型标签变化、条目被删除、知识库分片被整体替换时，通过内容摘要构成的版本指纹区分正常推进、条目级变更与整体替换，整体替换须使全部链接结果失效重建，条目级变更仅使受影响实体相关片段失效，回退的版本号须被拒绝。
6. 实现增量与全量一致性校验与失效传播：提供单条目更新与单文档重切分入口，仅重建失效链路，并与从零全量构建的链接结果、并列候选清单与摘要做逐字节比对；检测到不一致须返回 E_INCREMENTAL_MISMATCH 并附首个差异位置与两路取值，校验本身不得修改已提交阶段产物。
7. 实现 SQLite 事务化状态与并发发布保护：以事务写入阶段进度、条目版本归属与链接结果，同一阶段同一文档只允许一条有效记录；多工作进程发布时使用事务条件更新与真实文件锁并比较序号，仅允许序号连续推进，落后、重复或跨文档错位发布返回 E_STALE_CHECKPOINT，缺失前置阶段产物返回 E_MISSING_STAGE。
8. 实现数值精度与异常链路诊断：链接分全程在对数域累加，字符 n-gram 覆盖率以定点量化记录有效位数并给出与本地高精度参考分数的误差界；当片段长度与 n-gram 参数不匹配、别名表为空或量化缩放因子为零时，返回带 doc_id、片段下标与阶段名的业务码。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
