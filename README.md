当前是空白工作区，需要在 Windows 本地从零构建一个面向本地块设备仿真场景的写时复制快照链组件，供上层备份与回滚编排器集成。卷由固定块数的逻辑块组成，每块带块号、内容摘要、版本号与最近写入时刻；快照以写时复制方式记录被冻结的块版本，快照链支持增量快照与相邻快照合并。卷写入、快照创建、快照删除与合并都会改变快照链状态，进程可能在任意时刻被强制终止，重启后必须依据持久化事实恢复快照链与块索引的一致状态，并给出仅基于已落盘数据的恢复报告。所有数据来自本地确定性样本，用户通过本地 HTTP 接口提交写入与快照操作。

任务环境与准备：
安装 Python 3.11 或以上版本，并在任务工作区创建虚拟环境。
在虚拟环境中安装 FastAPI、uvicorn 与 pytest，版本以能本地离线安装为准。
准备本地确定性块样本与操作脚本所需的固定随机种子文件，样本与脚本均置于工作区内，不依赖网络或其他服务。
确认 SQLite 由 Python 标准库提供，无需额外安装；在 Windows 上直接运行 uvicorn 与 pytest 验证环境可用。

业务要求：
1. 实现卷与块的存储模型：卷由配置的固定块数组成，每块在 SQLite 中保存块号、内容摘要、版本号与最近写入时刻；写入接口接受块号与内容，写入后版本号必须单调递增且内容摘要与实际内容一致，摘要不一致时返回业务码 E_BLOCK_CORRUPT 且整次写入不生效；非法块号返回 E_BLOCK_NOT_FOUND。
2. 实现快照冻结与写时复制解耦：创建快照时只冻结当时各块的版本引用而不复制块内容，快照记录父快照标识、一致性序号与各块版本集合；创建期间发生的新写入不得进入该快照；写时复制在首次快照后修改块时真实发生，共享未修改块的版本引用，删除仍有子快照引用的父快照须返回 E_SNAPSHOT_REFERENCED 且不修改任何引用关系。
3. 定义快照状态机，至少包含 CREATING、COMMITTED、MERGING、MERGED、DELETED 五种状态并规定合法迁移路径；非法迁移返回 E_INVALID_TRANSITION 且不得修改已持久化状态；合并后的源快照必须处于 MERGED 而非直接消失，历史记录与引用计数须可追溯。
4. 实现增量快照与相邻快照合并：增量快照只记录相对父快照发生版本变化的块，并可通过父链解析出完整块版本集合；合并相邻快照时须校验两快照状态允许合并，并在同一事务边界内重写块引用与一致性序号，禁止出现元数据已合并而部分块引用仍指向旧快照的中间可见状态，合并后链深与引用块数须输出可核对。
5. 实现回滚裁决：回滚到指定快照时按解析出的块版本集合恢复卷的当前视图，并输出回滚差异，含需要写回的块数、被覆盖的当前版本号与未受影响块数；目标快照所需块内容缺失或摘要复核失败时返回 E_SNAPSHOT_CORRUPT 并保持卷当前视图不变；回滚与写入并发时读取方只能看到回滚前或回滚后的完整视图。
6. 实现并发控制与幂等：卷写入按卷单写者串行执行，快照创建、合并与回滚不可与同一卷的其他变更操作并行生效；多个只读查询（快照链、块版本、回滚差异）可并发读取某一完整提交版本；同一请求标识重复提交只生效一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_REQUEST；并发触发同一快照合并仅一个成功、其余返回 E_OPERATION_ACTIVE。
7. 使用 SQLite 持久化块、快照、引用关系与意图日志，写入、快照提交、合并与回滚的操作前均先写意图记录再提交事务；进程在合并或回滚中途被强制终止后重启，必须扫描未完成意图把快照链与块引用回滚到最后一个完整版本或将操作标记为已中止，恢复报告只包含已持久化事实，不得承诺强制终止后仍生成完整退出报告。
8. 提供本地 HTTP API 与端到端演示脚本：API 覆盖块写入、创建全量快照、创建增量快照、合并、删除、回滚、查询快照链与回滚差异、查询恢复报告，所有失败响应为含业务码的 JSON；脚本使用固定本地样本完成全量快照、增量快照、合并、回滚与一次强制终止后恢复，输出链深、引用块数、回滚差异与恢复结论。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地固定样本验证快照链创建、增量合并、回滚差异与强制终止后的一致性恢复，并核对业务码与恢复报告。
