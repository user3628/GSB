# 交付导航

本工作区已在需求草案基础上交付可集成 Go 根包、SQLite 持久化、本地 HTTP/交互式诊断工作台和一键验证工具。

- 技术与集成说明：[`docs/IMPLEMENTATION.md`](docs/IMPLEMENTATION.md)
- 实际验证报告：[`VERIFICATION.md`](VERIFICATION.md) 与 [`artifacts/verification-report.md`](artifacts/verification-report.md)
- Windows 一键脚本：[`scripts/verify.ps1`](scripts/verify.ps1)
- 启动工作台：`go run ./cmd/server --addr 127.0.0.1:18080`，打开 <http://127.0.0.1:18080/>
- 命令行验收：`go run ./cmd/verify`

---

工作区里只有一份灰度路由与算子图迁移的需求草案，模型服务热更新项目尚未动工，需要从零交付一套可集成的 Go 组件与可交互的诊断工作台。组件维护若干模型版本的算子图描述，每个节点声明算子类型、输入输出张量形状与 dtype、量化位宽与前后处理步骤标识；推理请求按路由表命中某个模型版本后，在本地用确定性算子图执行方式输出结果张量摘要。运维人员通过本地 HTTP 接口提交带单调版本号的模型版本快照，热切换时新版本以只含受影响模型版本的增量片段提交并携带基础版本。组件需判定新旧算子图之间的结构差异，决定哪些派生产物需要迁移、哪些必须重建，并保证灰度分流期间同一请求在相同配置下得到逐位一致的版本裁决与推理结果摘要。所有数据来自程序内置固定种子生成器与本地确定性样本，不依赖真实模型、GPU 或外部服务。

任务环境与准备：
Windows 10 及以上开发机，安装 Go 1.22 或更高版本，并确认 go env 中 GOOS 为 windows。
安装 SQLite 命令行工具用于核对持久化状态；Go 侧使用纯 Go 的 SQLite 驱动，通过 go get 获取并在 go.mod 中固定版本。
在空白工作区初始化 Go module，保证 go build ./... 与 go test ./... 可离线执行。
样本由程序内置固定种子生成器产出，包含若干模型版本算子图、路由表与请求轨迹，全部写入工作区本地目录。
本地 HTTP 测试端点只监听回环地址，不依赖任何外部服务、账号、GPU 或网络资源。
运行前执行 go mod tidy 完成依赖下载，运行后再执行一次构建与测试确认结果可重复。

业务要求：
1. 实现算子图解析与结构校验：算子图由节点序列组成，每个节点声明算子类型、输入输出形状与 dtype、量化位宽与前后处理步骤标识；解析时校验形状维度为正整数、dtype 在允许集合内、量化位宽在合法枚举中，失败返回业务码 E_GRAPH_INVALID 并指明节点标识与字段，且整份图不得入库。
2. 实现算子图签名与结构差异判定：为每个模型版本计算与节点顺序、算子类型、形状、dtype 与量化位宽相关的确定性图签名，热切换时比较新旧签名并输出差异类别（形状变化、dtype 变化、量化位宽变化、算子增删、前后处理变化）；同一算子图重复计算签名必须逐位一致。
3. 实现按差异类别驱动的级联失效与原子重建：为每个模型版本维护推理路由表项、前后处理缓存、在途请求绑定索引与灰度计划四类派生产物；图签名变化时，受影响产物按差异类别决定重建或迁移，并在同一事务边界内原子生效，禁止出现路由表已指向新版本而前后处理缓存仍为旧版本。
4. 实现增量片段提交与版本识别：增量只含受影响的模型版本并携带基础版本号，基础版本不是当前版本时返回 E_STALE_BASE 且不改变任何已提交状态；同一基础版本的两个并发增量只允许一个成功，另一个必须收到 E_CONFLICTING_UPDATE；整份快照替换时须识别版本变化并整体切换。
5. 实现本地算子图推理与结果摘要：按绑定的模型版本对固定种子生成的输入张量执行算子图，输出每个输出节点的张量形状、dtype 与内容摘要；量化位宽低于全精度时按声明规则执行量化与反量化，并输出每一步的舍入方式与累计舍入误差，同一输入同一版本重复推理结果摘要须逐位一致。
6. 实现灰度切换与在途请求版本绑定：灰度比例归一化为内部定点表示并输出舍入误差，分流累计使用补偿求和；同一请求标识在同一快照版本下重复裁决必须得到逐位一致的目标版本；切换瞬间已在途的请求必须按其进入时绑定的版本完成推理并回传该版本标识。
7. 实现基于 SQLite 的意图持久化与强制终止后恢复：模型版本提交、级联重建与在途请求绑定前先写意图记录再提交事务；进程在重建或推理中途被强制终止后重启，须扫描未完成意图，把路由、前后处理缓存与在途绑定回滚到最后一个完整版本或标记为已中止，恢复报告只包含已落盘事实。
8. 实现单写者提交与多读者查询的并发一致及幂等，并提供本地 HTTP 接口与结果验证工具：快照提交、增量提交、级联重建与推理推进按单写者串行执行，多个只读查询可并发读取某一完整提交版本；同一请求标识重复提交只执行一次、其余等待复用结果；接口覆盖迁移与重建清单查询、按模型版本推理、灰度裁决与恢复报告查询，失败响应为含业务码与上下文的 JSON。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地确定性样本验证算子图迁移与重建、灰度版本绑定、推理结果一致性及强制终止后的恢复，并给出可核对运行报告。
