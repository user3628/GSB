本次时序分析团队还停留在方案论证阶段，工作区里没有代码，只有一份围绕滚动窗口与预算约束的设想说明。输入由程序内置固定种子生成器在本地产出确定性 CSV 序列分片：每条分片含毫秒时间戳、序列标识、目标值、若干外生变量列与质量标记，覆盖日周期、趋势、缺失点与突变点；另附一份 YAML 回测配置，声明候选预测方法（移动平均、带衰减指数平滑、线性自回归）、窗口长度、步长、预测步数、全局最大拟合次数预算、单工作进程拟合配额、并行进程上限与单轮时间预算，并给出分档清单声明每档分片数与总样本数，作为预算预估的显式观测。引擎需在预算约束下并行完成滚动回测，把逐折误差与聚合指标持久化，并能从已提交事实恢复。

任务环境与准备：
在 Linux（WSL Ubuntu）下准备 Go 1.22 或以上与 SQLite 3 开发库，使用 go build 构建，SQLite 驱动通过 go get 安装。
确保工作目录为空，程序内置固定种子生成器在首次运行时写出 CSV 序列分片、分档清单与 YAML 回测配置样本。
不依赖外部服务、真实数据集、GPU 或网络；本地进程池与真实文件锁均使用标准库与 SQLite 实现。
运行前确认本地磁盘可写且可创建 SQLite 数据库文件，演示脚本使用内置样本完成一次完整运行与一次中途停止后的恢复。

业务要求：
1. 实现候选预测方法与滚动窗口切分：按配置的窗口长度、步长与预测步数把每条序列切分为相互重叠的滚动折，分别以移动平均、带衰减的指数平滑与线性自回归完成拟合与多步预测，拟合参数须按显式公式或最小二乘确定并逐折记录所用窗口起止时间戳与参数，同一输入与配置必须产生逐字节一致的逐折预测。
2. 实现缺失点与突变点的显式处理与诊断：对缺失时间戳或缺失目标值的序列按可配置比例与规则打标并从窗口切分中剔除不可用折，对突变点按可配置相对变化阈值标记并记录其时间戳，逐折记录被剔除折数与原因；缺失比例超过上限或序列长度不足最小窗口时返回带序列标识与原因的业务码并在汇总中单列。
3. 实现预算约束下的折级并行调度：以序列折为调度单元，在全局最大拟合次数预算、单工作进程拟合配额、并行进程上限与单轮时间预算四重约束下决定接纳顺序与并发度，接纳前依据分档清单中的样本数与窗口参数预估拟合消耗，超预算折记录为未处理并给出预估消耗与剩余预算，累计消耗不得超出预算。
4. 实现并行执行与确定性归约：使用本地进程池并行执行已接纳折的拟合与预测，各折结果按序列标识、折序与预测步全局排序后再归约，使并行运行的逐折误差曲线与聚合指标同单进程顺序执行逐字节一致；工作进程异常须以结构化错误对象记录并保留可恢复状态，不得以线程或进程超时描述为已终止失控代码。
5. 实现基于容差与参考结果的指标汇总与稳定性标记：按序列与分档计算 MAE、RMSE、MAPE（分母为零时须显式跳过并计数）与预测区间覆盖率，输出逐折误差曲线、聚合指标与预算消耗明细，并给出与显式观测样本量相容的置信区间估计；当指标出现 NaN、Inf 或有效折数为零时返回带序列标识与指标名的业务码并保留参与计算的折清单。
6. 实现阶段与分片的 SQLite 事务化检查点及优雅停止恢复：每分片每阶段完成时在单个事务内写入含阶段名、分片标识、已完成折数、输入内容指纹、配置版本指纹、产物摘要与单调序号的记录，同一分片同一阶段只允许一条有效记录；收到停止请求时完成当前不可拆分单元后退出，恢复后最终指标与逐折结果须与一次连续执行逐字节一致，强制终止后只依赖已提交事实恢复且不承诺生成退出报告。
7. 实现版本指纹识别、增量失效传播与并发发布保护：当分片序列内容、预测方法、窗口参数、步长、预测步数或预算配置任一变化时，由各阶段内容摘要构成版本指纹并识别受影响的最早阶段与最小分片集合，使该集合及其全部下游产物失效重建，未受影响分片复用；多工作进程发布分片结果时使用事务条件更新与真实文件锁并比较分片序号，仅允许序号连续推进，落后、重复或跨分片错位发布返回 E_STALE_CHECKPOINT 并附当前生效序号。
8. 实现整体替换识别与本地确定性交互演示：当配置或分片集被整体替换时，通过内容摘要与版本序号区分正常推进、整体替换与回退，整体替换使全部派生指标与逐折结果失效重建，回退拒绝并返回 E_STALE_VERSION；命令行与本地 HTTP 接口支持导入分档分片与配置、触发分阶段回测、查询各阶段状态与版本指纹、查看预算消耗与未处理折原因、请求停止与执行恢复，演示数据至少覆盖三个序列、两种分档与一次中途停止后的恢复。
