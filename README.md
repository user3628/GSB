团队拿到一份存储配额与限流方向的目标说明时，工作区仍是空的，没有任何可沿用的系统或代码。要做的是面向本地同步与备份客户端的内容寻址分片池组件：分片以 SHA-256 摘要寻址，可被多个逻辑节点共享引用，每个引用带有效期租约与千分比权重；分片池受全局容量配额、每节点配额与每轮时间预算约束，引用变化必须使对应节点的配额占用视图、共享度统计与回收候选集级联失效并原子重建。真实运行中同一分片的并发挂载、租约到期后未续、批量引用集合整体替换与进程被强制终止会同时出现，组件只能依据 SQLite 中已落盘事实恢复，不能依赖任何内存残留。

任务环境与准备：
安装 Go 1.22 或更高版本，确认 go version 可用；无需外部网络依赖。
准备 SQLite 命令行与 Go 驱动依赖（如 modernc.org/sqlite 或 mattn/go-sqlite3），预下载模块或使用本地模块缓存以便构建。
准备本地回环 HTTP 测试端点用于回收与恢复演练，端口可配置；样本分片与策略快照由固定种子生成器写出到工作目录。
在空工作目录初始化 go module，提供 make 目标或脚本完成构建、运行示例与强制终止恢复演练。

业务要求：
1. 实现分片、逻辑节点引用与配额策略快照模型：分片记录摘要、字节大小、入库时刻、保留期毫秒与物理状态，引用记录节点标识、分片摘要、挂载时刻、租约到期时刻、租约版本号与千分比权重（1 至 1000 整数），策略快照声明全局容量配额字节、每节点配额字节、回收批量上限与整体校验摘要；解析时校验摘要为 64 位十六进制、权重与字节数范围，非法输入返回 E_SPEC_INVALID 且整批不入库。
2. 实现租约引用语义：首次挂载授予引用并递增对应节点的配额占用，带当前租约版本号的续租延长到期时刻并递增版本，版本落后返回 E_LEASE_STALE 并附当前版本；租约到期后引用自动失效并递减节点配额占用与分片引用计数，失效判定只依据持久化的到期时刻与单调推进的时钟读数，不得依赖驻留内存。
3. 实现批量引用集合整体替换：请求给出某节点期望引用的分片摘要全集，引擎须计算需新增与需移除的引用并一次性生效；替换后该节点的配额占用、共享度统计与回收候选集须在同一事务边界内与引用集合精确对应，任一摘要无法入库或超出节点配额时整批不生效并返回 E_NODE_QUOTA_EXCEEDED 或 E_CONTENT_MISSING 并附差额。
4. 实现共享度统计与回收候选判定：共享度由引用该分片的有效节点数与权重合计推导，使用整数或显式定点表示并输出每步舍入方式与累计舍入误差；仅当分片引用计数为零、无任何有效租约且保留期已过时才可进入回收候选，否则返回 E_RECLAIM_UNSAFE 并附阻塞原因与最早到期时刻。
5. 实现全局配额与回收的预算调度：新建引用与物理回收任务受全局容量配额、每节点配额与每轮时间预算三重约束，预算内按分片共享度与摘要稳定次序取任务，超出并发上限的任务进入有界等待队列，队列满返回 E_QUEUE_FULL；预算耗尽时按确定性次序给出延后集合并附剩余预算，不得静默丢弃候选。
6. 实现跨模块一致与幂等复用：引用授予、配额占用、共享度统计、回收候选标记与物理移除必须在同一事务边界内共同生效，禁止出现引用已失效而节点配额仍占、或分片已标记可回收而引用计数未归零；同一请求标识重复提交只执行一次、其余等待并复用同一结果，内容不一致返回 E_CONFLICTING_REQUEST。
7. 使用 SQLite 持久化分片、引用、租约、配额占用、回收记录与意图日志：挂载、续租、失效、批量替换与物理回收前先写意图记录再提交事务；进程在替换或回收中途被强制终止后重启须扫描未完成意图，依据已提交引用与未过期租约重建每个分片的引用计数与每个节点的配额占用，把未提交替换回滚并把未提交回收标记为待回收。
8. 提供本地 HTTP API 与恢复报告：覆盖入库、挂载、续租、卸载、批量替换、触发回收轮次、按分片查询引用计数与租约明细、按节点查询配额占用与共享度、查询恢复报告，失败响应为含业务码与上下文的 JSON，恢复报告只包含已落盘事实并区分已中止替换与被回滚回收。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
