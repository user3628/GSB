在 Windows 空白工作区中，需要从零构建一个面向本地回环环境的 QoS 流量整形策略管理与诊断工作台。工作台维护一组整形策略（每条策略包含队列标识、承诺信息速率 CIR、峰值信息速率 PIR、承诺突发尺寸 CBS、峰值突发尺寸 PBS、优先级、匹配规则与依赖的父整形器），并支持策略集以两种可互换的持久化格式导入导出：紧凑二进制格式（含魔数、格式版本字节、长度前缀、CRC32 校验、可选字段存在位图与大小端标记）与分片 JSON 行格式（每行含队列标识、速率、突发尺寸、优先级与匹配规则）。两种格式在字段可选性、速率单位（bps 与 kbps）、突发尺寸单位（字节与 KB）以及时间戳精度上存在差异，需要归一化为统一内部表示并实现版本兼容协商。工作台还需依据策略快照对离线流量样本（毫秒时间戳、队列标识、包长字节、标记颜色）执行整形仿真，计算各队列的令牌桶余量、整形后发送字节与丢弃、标记字节，并输出整形效果与配置差异诊断报告。用户通过本地 HTTP API 提交策略快照、导入导出与仿真请求，所有数据来自本地确定性样本，不依赖真实网络设备或外部服务。

任务环境与准备：
安装 Python 3.11 或以上版本，并安装 FastAPI、Uvicorn、NumPy 与 pytest，版本以本地可获取的稳定版为准。
使用 SQLite 作为持久化存储，无需额外服务；在空白工作区创建项目目录与 SQLite 数据库文件路径。
准备本地确定性样本：一组整形策略（含不同单位与可选字段）与一组流量样本（毫秒时间戳、队列标识、包长、标记颜色），以文件形式放入项目样本目录。
确认本地回环端口可用，用于启动 HTTP API；不依赖真实网络设备、外部站点、付费资源或 GPU。

业务要求：
1. 实现两种持久化格式的编解码：紧凑二进制格式必须包含魔数、格式版本字节、大小端标记、每条记录的长度前缀、CRC32 校验与可选字段存在位图；分片 JSON 行格式每行含队列标识、CIR、PIR、CBS、PBS、优先级与匹配规则，且须与二进制格式逐字段语义等价，导出后再导入必须得到相同的内部策略集合。
2. 实现格式协商与版本兼容裁决：导入前检测输入格式与格式版本，按显式声明的兼容矩阵给出接受、降级接受或拒绝三种结论；旧版本缺 PIR 或 PBS 字段时降级接受并依据 CIR 与 CBS 按声明规则补齐，同时记录降级明细；高版本含未知必填字段的数据返回业务码 E_FORMAT_UNSUPPORTED 且不得部分导入。
3. 实现速率、突发尺寸与时间戳的归一化：二进制格式以 bps 与字节为单位、JSON 行格式以 kbps 与 KB 为单位，须归一化为 bps 整数与字节整数并做溢出检查；JSON 行格式的毫秒时间戳与二进制格式的微秒时间戳归一化为同一内部表示，按调用方声明的截断规则处理亚毫秒部分并输出每条记录的舍入位与累计舍入误差。
4. 实现整形策略的依赖关系与合法性校验：每条策略可声明依赖的父整形器，须检测依赖环并返回 E_DEPENDENCY_CYCLE 并附环上队列标识；子整形器的 CIR 与 PIR 不得超过父整形器对应速率，违反时返回 E_RATE_EXCEEDED 并给出双方数值；同一队列标识在导入批次内重复时按确定规则解决并写入导入报告。
5. 实现令牌桶整形仿真：依据策略快照对离线流量样本逐包模拟令牌桶，计算各队列在每包的令牌余量、整形后发送字节、丢弃字节与标记颜色（绿、黄、红），令牌补充速率与突发容量须严格使用归一化后的 CIR、PIR、CBS、PBS；仿真结果须包含每个队列的累计发送、丢弃与标记统计，且同一策略版本与同一样本重复仿真得到逐包一致结果。
6. 实现整形效果的数值精度契约与诊断报告：令牌累计与速率换算使用整数或显式定点表示，比例类输出保留固定小数位并附舍入方式与累计误差说明；诊断报告须列出各队列实际发送速率与承诺速率的偏差、超发或欠发队列清单与触发阈值，比较时使用带相对容差的比较而非裸浮点比较，容差内按稳定队列标识次序打破平局。
7. 实现策略快照整体替换与版本识别：策略快照携带格式版本、快照序号与生成时间，加载时须校验版本兼容性与序号单调，加载过程在内存策略索引与 SQLite 表之间原子切换，切换成功后旧快照资源才可释放；任何校验失败须保持旧快照继续可用并返回 E_SNAPSHOT_INVALID，禁止新旧快照策略混合使用。
8. 实现单写者提交与多读者查询的并发一致，并具备基于 SQLite 意图持久化的强制终止恢复：策略导入、快照切换与仿真批次按提交串行执行，多个只读诊断查询可并发读取某一完整提交版本；所有写操作先写意图记录再提交事务，进程被强制终止后重启须扫描未完成意图并回滚到最后一个完整快照版本或把批次标记为已中止，恢复报告只包含已持久化事实，不得承诺强制终止后仍生成完整退出报告。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
