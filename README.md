项目启动会上确定由一人完成首版，眼下工作目录里只有这份关于多集群配置漂移收敛的需求说明，没有任何可复用的代码。平台维护若干目标集群及其上的配置对象，每个对象声明标识、类别、命名空间、期望字段集合、实际字段集合、字段来源标记、依赖的其他对象与资源预算。配置以带单调递增版本号的 JSON 快照整体提交，运维还会提交只含受影响对象的增量片段。收敛策略快照声明漂移判定容差、批次规模上限、单轮时间预算与重试上限。组件需为每个对象判定漂移类别，组织带依赖约束的收敛批次，在本地回环测试端点上真实执行写回并回读核对，并在进程被强制终止后依据 SQLite 中已持久化的意图恢复。

任务环境与准备：
Linux（WSL Ubuntu）开发环境，安装 Go 1.22 或以上版本，使用 go mod init 初始化模块。
安装 SQLite 3 命令行工具用于核对数据库内容，Go 侧使用官方 database/sql 与纯 Go 驱动，无需外部数据库服务。
准备本地回环测试服务：可用 Go 标准库 httptest 或独立监听端口的小服务模拟写回与回读端点，任务执行前确认端口可用。
样本由程序内置固定种子生成器在本地写出 JSON 文件，包括集群对象、收敛策略快照与增量片段，不依赖网络素材或真实集群。

业务要求：
1. 实现集群对象与收敛策略快照的解析与归一化：对象声明标识、类别、命名空间、期望字段集合、实际字段集合、字段来源标记、依赖对象列表与资源预算（CPU 毫核与内存字节均为非负整数）；解析本地确定性 JSON 样本时校验对象标识唯一、依赖引用存在、资源量为非负整数并做溢出检查，字段集合中的数值字段须保留原始文本以便后续定点比较，解析失败返回 E_SPEC_INVALID 且不改变任何已持久化状态。
2. 实现漂移判定核心：逐字段比较期望与实际字段集合，区分字段缺失、字段多余、取值偏移与来源冲突四类漂移；数值字段按策略声明的相对容差做定点比较而非裸浮点比较，整数与字符串按严格相等比较；同一对象命中多类漂移时按声明的稳定优先级给出主类别，同时保留全部命中明细与逐字段比较值，任一字段无法按声明类型比较时返回 E_FIELD_UNCOMPARABLE 并指明对象与字段。
3. 实现带版本号的整份快照提交与增量片段提交：快照携带单调递增版本号、生成时间与整体校验摘要，提交时版本号不大于当前已提交版本返回 E_STALE_SNAPSHOT；增量片段只含受影响对象并携带基础版本号，基础版本不是当前已提交版本时返回 E_STALE_BASE 且不改变任何已提交状态；同一基础版本的两个并发增量只允许一个成功，另一个必须收到 E_STALE_BASE。
4. 实现依赖约束下的收敛批次组织：被依赖对象所在批次序号严格小于依赖者所在批次；依赖出现环时返回 E_DEPENDENCY_CYCLE 并附环上对象标识列表，环外对象仍须给出分层结果与未被环污染的对象清单；批次规模受策略上限与对象资源预算共同约束，同一对象不得在批内重复出现，批次划分须输出每批对象列表、批次序号与预算占用依据。
5. 实现向本地回环测试端点的真实写回与回读核对：每批对象按批次顺序向本地测试服务发起真实 HTTP 写回请求，每次写回具备独立超时，超时后必须真实关闭底层 HTTP 连接并释放其占用的并发名额，返回 E_WRITE_TIMEOUT 并附批次标识与对象标识；写回成功后回读实际字段集合并重新判定漂移，回读值与写回值不一致时返回 E_READBACK_MISMATCH 并附差异字段与两值。
6. 实现单轮时间预算与并行写回批次的并发约束，并保证派生产物级联失效：写回受每轮时间预算与最大并行批数共同约束，超并行上限的批次进入有界等待队列，队列满返回 E_WRITE_QUEUE_FULL；对象字段、依赖关系或策略容差变化时，受影响对象的漂移结论、批次划分与收敛汇总必须在同一事务边界内级联失效并原子重建，禁止出现部分产物已更新而其余仍为旧值的中间可见状态。
7. 实现单写者提交与多读者查询的并发一致及幂等复用：快照提交、增量提交、批次组织与写回推进按提交单写者串行执行，多个只读查询（对象漂移明细、批次划分、收敛汇总、写回记录）可并发读取某一完整提交版本，且不得看到对象已标记写回成功而回读核对结论尚未落定；同一批次标识重复触发只执行一次，其余等待并复用同一结果，内容不一致时返回 E_CONFLICTING_BATCH。
8. 实现基于 SQLite 的意图持久化与强制终止后恢复：快照提交、增量提交、批次组织与写回前先写意图记录再提交事务；进程在批次组织或写回中途被强制终止后重启须扫描未完成意图，把未提交写回回滚为待写回、把快照切换标记为已中止或回滚到最后一个完整版本；恢复报告只包含已落盘事实，记录被中止的批次、回滚的对象数量与剩余待写回对象，不得承诺为未持久化操作生成结果。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证漂移判定、依赖批次、真实写回回读与强制终止后恢复结论，并输出含业务码的 JSON 错误体。
