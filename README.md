当前是空白工作区，没有现存项目、代码或数据附件，需要从零实现一个面向本地数据分析平台的“分片聚合预计算选型引擎”。平台接收一组分片键上的聚合查询（分组键、聚合函数、过滤谓词与查询频率权重），并针对本地列式数据表决定每种查询采用哪条执行路线：实时全量扫描、按分片键预聚合物化、部分预聚合加回放补偿。三条路线的成本由数据集规模、分片键基数、查询频率与物化存储预算共同决定，且三者互斥地争夺同一份磁盘与内存预算：预聚合越多，存储与重建开销越大，但高频查询的扫描成本越低；部分预聚合在基数分布倾斜时会因补偿回放而出现成本反超。引擎必须在总预算约束下完成路线分配、物化与增量重建，并在数据分片追加、分片键重分布与进程重启后维持可复现的决策与一致的物化状态。

任务环境与准备：
确认 Windows 环境下已安装 Python 3.11 及以上版本，并可通过 python --version 验证。
安装依赖：pip install numpy pytest，均在离线可获取的本地包索引下完成，无需外部服务。
在工作区根目录预留数据目录与临时目录，确保有足够本地磁盘容纳样本数据块与物化文件。
提供固定随机种子的样本生成脚本入口与示例查询清单，运行前不依赖任何网络账号或线上站点。

业务要求：
1. 实现数据表、分片键与聚合查询的声明模型及载入校验：表以列名到 NumPy 数组的映射与元数据（行数、列类型、列基数、空值计数、分片键候选）描述，查询声明分组键、聚合函数（求和、计数、最小值、最大值）、过滤谓词、查询频率权重与代价敏感度。须校验分片键基数与行数之比的合法性、聚合函数与分组键类型匹配、权重为正，非法输入返回固定业务码 E_BAD_MODEL 且不进入选型流程。
2. 实现三条执行路线的成本模型与统一比较：实时扫描按行数与过滤选择率折算扫描字节，预聚合按物化行数折算存储占用与单次物化重建开销再叠加命中后的摊薄成本，部分预聚合按覆盖比例折算物化规模并叠加补偿回放的行数成本。三条路线须在同一度量单位下可比，浮点成本按相对容差 0.02 比较，并列时按更低存储占用、更少重建次数、路线名序的确定次序裁决，并在输出中标记并列与裁决键。
3. 实现倾斜感知的覆盖比例选取与补偿回放成本估算：对每个候选分片键，须按值频分布估算覆盖比例与对应补偿回放行数，覆盖比例不得仅按基数平均估算；须处理长尾与热点分片使覆盖比例在配置的候选网格上取离散点并记录每个候选点的估算误差区间；倾斜分布下成本反超时须显式标记该候选不可选并给出触发条件，保证相同输入在固定随机种子下复现同一候选网格与同一选择。
4. 实现物化视图的构建、增量维护与原子替换：被选为预聚合的查询须生成带自描述头（魔数、格式版本、分片键、覆盖比例、行数、内容摘要与 CRC32）的物化文件，写入先临时文件校验后再原子替换，替换前旧物化保持可读；数据分片追加时须只对受影响的物化增量重建并记录重建触发原因、涉及分片与重建耗时，未受影响物化不得被重写。
5. 实现预算约束下的全局选型与重建取舍：磁盘预算与内存预算须同时约束预聚合与部分预聚合的物化规模，选型须在预算内按查询频率加权收益最大化，且须在报告中说明每次上马或回退的边际成本依据。当分片键重分布使已物化视图的成本收益转为负值时，须按确定次序淘汰并回退相关查询到实时扫描，淘汰不得使任一查询失去唯一确定的执行路线。
6. 实现进程重启与物化损坏下的状态恢复一致性：查询路线分配、物化视图清单、覆盖比例、重建历史与预算账目须在决策与重建提交点以单事务写入 SQLite，事务提交后才对查询可见；启动时须校验每个物化文件的摘要，把中断时处于构建中的物化回退为未构建并将对应查询路线标记为待重选，损坏物化须以 E_MATERIALIZE_CORRUPT 记录且不得参与任何路线成本计算。
7. 实现并发查询选型与物化重建的互斥及预算账目原子性：同一物化视图的重建与针对其执行路线成本评估不得交错，多个提交请求同时改变同一分片键时须串行化到分片键一致性边界内，不同分片键之间可并行推进；预算扣减与物化上马须在同一事务内完成，任一步失败须整体回滚使预算账目与物化清单均不变化，锁等待须基于真实单调时钟超时并返回 E_CONTENTION_TIMEOUT。
8. 提供本地确定性样本、选型报告与可重复测试：内置固定随机种子的数据与查询生成器，覆盖均匀、长尾与热点三种分片值分布且总行数不少于十万；pytest 用例须在 Windows 离线覆盖非法模型拒绝、路线成本并列裁决、倾斜反超标记、增量重建范围、预算淘汰、重启续算、损坏物化隔离与并发互斥，并验证两次独立运行产出的路线分配与物化摘要完全一致。
