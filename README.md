本地流计算验证项目刚完成立项，仓库里还没有任何实现，需要先交付一个能完整演示的算子融合与背压预算组件。程序内置固定种子生成器在本地写出确定性事件流样本：每条事件带毫秒时间戳、分区号、分组键、int64 定点度量值（scale=1e6）与事件序号，并附一份带单调版本号的算子链策略快照，声明窗口规格、可融合算子集合、每算子缓冲上限、分区并发上限与每轮时间预算。引擎需把 Scan、Filter、Project、聚合等相邻算子按声明规则融合为融合算子，按批推进并为融合算子分配缓冲与并发名额，在背压出现时给出确定性降载次序，所有结论落 SQLite 供复核。

任务环境与准备：
安装 Go 1.22 或更高版本，确认 go version 可执行。
在空白工作区执行 go mod init，仅使用标准库与本地纯 Go SQLite 驱动（如 modernc.org/sqlite），无需容器、外部服务或网络依赖。
首次运行时由程序内置固定种子生成器在本地写出事件流样本与算子链策略快照，落在工作区的数据目录下，不依赖真实集群、线上资源或缺失数据集。

业务要求：
1. 实现事件流快照与算子链策略快照的解析和归一化：事件含毫秒时间戳、分区号、分组键、int64 定点度量值与事件序号，策略快照携带单调递增版本号、生成时间、窗口规格、可融合算子集合、每算子缓冲上限、分区并发上限与每轮时间预算及整体校验摘要。解析时校验分区号非负、事件序号在分区内单调、定点度量值不越界，任一项失败返回 E_SPEC_INVALID 且整批不生效。
2. 实现算子链的合法性校验与融合判定：算子链须为线性链且每个算子的输入输出类型相容，非法链返回 E_PIPELINE_INVALID 并指明首个不相容算子；相邻算子仅在策略声明的可融合集合内且无跨分区重分布语义时才允许融合，融合结果为带输入输出签名的融合算子，并输出每个算子是否被融合、融合分组边界与判定依据。
3. 实现按融合分组推进的批执行：按窗口规格把事件归入窗口，按融合分组依次执行过滤、投影与分组聚合，聚合计算计数、求和、最小值与最大值，求和全程使用 int64 定点并在每步校验不越界，越界返回 E_NUMERIC_OVERFLOW 并指明窗口与分组；窗口边界包含关系须显式声明，迟到事件的归属规则须与窗口边界一致。
4. 实现每算子缓冲上限下的背压判定：融合算子的在途批次字节与在途批次数不得超过策略声明的缓冲上限，逼近上限时暂停向其上游推送新批次并输出背压水位、触发算子与上游被阻塞批次数；当所有融合算子均处于背压且等待队列满时返回 E_BACKPRESSURE_STALL，不得通过丢弃未处理批次来缓解背压。
5. 实现确定性降载次序与预算裁决：当待执行批次的规模超出分区并发上限与每轮时间预算可覆盖范围时，按分区号、窗口起始毫秒与已消耗预算给出确定性降载次序，被降载批次迁移为 SHED 并输出降载依据与剩余预算；已提交的窗口聚合结论一旦写入即为终态，后续轮次不得重算或覆盖，降载后仍须保证已执行部分的结果可完整核对。
6. 实现算子链策略的整份替换与增量片段提交及版本绑定：策略快照携带单调递增版本号，加载时校验版本单调与摘要并整体替换旧策略，失败时保持旧策略完全可用；增量片段只含受影响的算子或缓冲参数并携带基础版本，基础版本非当前提交版本时返回 E_STALE_BASE 且不改变任何状态；受影响融合分组的缓冲水位、背压状态与窗口结论须级联失效并在同一事务边界内原子重建，禁止出现融合分组已换成新签名而下游窗口结论仍按旧签名计算。
7. 实现单写者推进与多读者查询的并发一致及幂等：批执行推进、背压状态迁移与级联重建按分区单写者串行执行，多个只读查询可并发读取某一完整提交版本；同一批次标识重复提交只执行一次、其余等待并复用同一结果，内容不一致返回 E_CONFLICTING_REQUEST；查询不得看到某融合分组已标记完成而其窗口聚合结论尚未落定。
8. 实现基于 SQLite 的意图持久化与强制终止后恢复：批次开始、窗口结论提交、背压状态迁移与策略切换前先写意图记录再提交事务；进程在批执行或级联重建中途被强制终止后重启须扫描未完成意图，把未提交批次回滚为待执行、未提交窗口结论丢弃、未完成策略切换标记为已中止，恢复报告只包含已落盘事实，不承诺强制终止后仍能产出完整窗口结论。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地种子样本完成算子融合判定、背压降载与中断恢复的端到端复核。
