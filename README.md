交付从新建的代码库开始，需要从零构建一个面向本地多组件平台的配置变更影响面引擎，用于回答「某个配置键被改后，哪些组件的有效配置需要重新物化、哪些读请求必须被拒绝而不能返回陈旧值」。平台以带版本号的 JSON 文档树描述组件（组件标识、所属分组、依赖的其他组件、监听配置键列表）与配置键值（键路径、类型、取值、生效顺序号），变更以键级补丁提交，补丁可能同时触及多个组件监听的键。引擎需维护每个组件的有效配置物化结果与由依赖关系决定的上游影响集合，并在读取时依据读请求携带的观察版本判定可见性。难点在于变更传播与陈旧读裁决：一个键的补丁会沿组件依赖与分组继承两条路径扩散，物化、影响集合与读可见性必须共同生效，任何部分更新的中间态都会让读方拿到与版本不匹配的配置。

任务环境与准备：
安装 Go 1.22 或以上版本，并确认 go env 与 go build 在 Windows 下可用
准备本地 SQLite 驱动（如 modernc.org/sqlite），使用 go get 拉取到本地模块缓存
在 Windows 工作区新建模块目录，准备固定本地 JSON 文档样本，含分组默认值、多层依赖与同键冲突用例
确认本地回环端口可用，不需要外部服务或容器环境

业务要求：
1. 实现组件与配置文档模型的加载与校验：组件声明标识、所属分组、依赖组件列表与监听配置键列表，配置键声明键路径、类型、取值与生效顺序号；加载时校验组件标识唯一、依赖引用存在且键路径格式合法，失败返回业务码 E_DOC_INVALID 并保持旧文档完全可用，成功时整体替换并识别版本变化。
2. 实现分组继承与依赖展开的两条传播路径：组件的有效配置由分组默认值与自身键值按生效顺序号合成，合成结果再沿依赖关系向上叠加被依赖组件声明的键；同一键在两条路径上都被提供时须按显式声明规则裁决来源并输出来源链，两条路径均未提供时该键视为未定义而非取零值。
3. 实现键级补丁提交与影响集合计算：补丁只含被修改或新增的键并携带基础版本号，引擎需依据监听键列表与依赖关系计算出必须重新物化的组件集合及其下游影响集合，并输出受影响组件、触发键与传播跳数；基础版本号非当前版本时返回 E_STALE_BASE 且不改变任何状态。
4. 实现有效配置物化与读可见性裁决：每个组件维护带物化版本的合成配置，读请求携带观察版本，若该组件物化版本不高于观察版本则返回配置并标注物化版本，若因未完成传播而落后于观察版本必须返回业务码 E_STALE_READ 并附落后版本信息，禁止以任意旧值充当命中。
5. 实现引用与影响集合的级联失效：为每个组件维护其对配置键、分组默认值与上游组件配置的引用关系；任一被引用对象变化时，该组件的物化结果、影响集合与其下游组件的相应引用必须级联失效并在同一事务边界内原子重建，禁止出现物化已更新而影响集合仍为旧值的中间可见状态。
6. 实现物化路径的取舍与预算约束：物化可在增量路径（仅重算失效键涉及的合成步骤并复用其余中间结果）与全量路径（对该组件整份重新合成）间选择，由补丁触及键数与该组件监听键总数的比例按显式阈值决定，并输出所选路径、阈值与耗时估计；两条路径对同一文档版本必须产生逐键一致的有效配置与来源链。
7. 实现单写者提交与多读者查询的并发一致及幂等：补丁提交、物化与级联重建按文档版本单写者串行执行，多个读请求可并发；同一补丁标识重复提交只生效一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_PATCH；读请求在提交进行中启动时必须在其绑定的观察版本上完成或返回 E_STALE_READ。
8. 使用 SQLite 持久化文档版本、物化配置、引用关系与意图日志，补丁提交与级联重建前先写意图记录再提交事务；进程在重建中途被强制终止后重启须扫描未完成意图，把物化结果与引用关系回滚到最后一个完整版本或将补丁标记为已中止，恢复报告只包含已持久化事实。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
