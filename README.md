当前是空白工作区，需从零构建一个面向 Windows 本地环境的 Kubernetes 风格多租户资源治理工作台。平台维护若干租户，每个租户声明 CPU 毫核、内存字节的硬性配额与突发额度，并绑定一套令牌桶限流参数（每秒补充速率、桶容量、初始令牌数）。租户对共享命名空间的资源申请以带毫秒时间戳的请求批次到达，工作台须依据当前策略快照对每条申请做配额准入与令牌桶限流联合裁决，并支持策略快照的增量片段提交与跨版本迁移：租户策略可从旧版扁平结构迁移到新版分层结构，迁移过程需判定字段兼容性并保留可回放裁决记录。难点在于配额占用、令牌余量与租户层级继承关系三者必须在同一事务边界内一致更新，同时增量片段提交、策略版本替换与裁决查询之间要在单写者串行与多读者并发下保持可核对的一致性。所有数据来自本地确定性样本，不依赖真实集群或外部账号。

任务环境与准备：
安装 Python 3.11 或以上版本，确保 python 与 pip 在 Windows 命令行可用。
在空白工作区创建项目目录，使用 pip 安装 FastAPI、uvicorn 与 pytest，版本以本地可安装的稳定版本为准。
准备固定本地样本：两份租户策略文件（旧版扁平与新版分层各一份）、一份含毫秒时间戳的资源申请批次 JSON，以及一份故意构造的字段冲突迁移样本，内容固定以便复现。

业务要求：
1. 实现租户策略的旧版扁平与新版的解析：旧版含租户标识、CPU 毫核上限、内存字节上限、每秒请求上限与废弃字段；新版含父租户引用、分层配额结构、令牌桶参数与生命周期起止毫秒。解析时校验租户标识唯一、配额为正整数、父引用存在且不得超过最大深度，失败返回 E_SPEC_INVALID 且整批不入库。
2. 实现令牌桶与配额联合裁决：每条资源申请按到达毫秒时间戳推进令牌补充，补充量按每秒速率与毫秒整数差计算并声明亚毫秒截断规则；同时校验 CPU 与内存剩余配额及令牌余量，任一不足则拒绝并返回 E_QUOTA_EXCEEDED 或 E_RATE_LIMITED，附当前余量与差额；整条申请必须原子扣减或整条不扣减。
3. 实现父租户配额与令牌的级联约束：子租户的占用与请求速率须同时计入全部祖先的已用量；子孙合计超出任一祖先配额时返回 E_PARENT_QUOTA_EXCEEDED 并指明祖先链上第一个不足的租户与差额；祖先链的级联扣减须在同一事务内完成，不得出现子租户已扣减而祖先未扣减的中间状态。
4. 实现策略快照版本识别与增量片段提交：快照携带单调递增版本号与校验摘要，加载须整体替换旧快照，不得新旧混用；增量只含受影响租户并携带基础版本，基础版本非当前版本时返回 E_STALE_BASE 且不改变任何已提交状态；同一基础版本的两个并发增量只允许一个成功、另一个必须收到 E_STALE_BASE。
5. 实现跨版本策略迁移裁决：将旧版策略映射到新版分层模型时，判定废弃字段是否可迁移、生命周期区间是否与已生效策略重叠、父租户引用是否存在；可完整映射的接受并输出映射依据，需人工确认的标记 PENDING_REVIEW 并返回 E_MIGRATION_REVIEW，不可映射的拒绝并计入迁移报告，整批迁移须原子生效或整批回滚。
6. 定义租户状态机，至少包含 ACTIVE、THROTTLED、QUOTA_BLOCKED、SUSPENDED、MIGRATING 五种状态并规定合法迁移路径；非法迁移返回 E_INVALID_TRANSITION 且不修改已持久化状态；状态变更、配额占用与令牌余量须在同一事务边界内提交，禁止出现状态已迁移而占用未更新的中间可见状态。
7. 实现单写者裁决与多读者查询的并发一致及幂等：资源申请裁决、策略提交与级联重建按版本单写者串行执行，多个只读查询可并发读取某一完整提交版本；同一请求标识重复提交只裁决一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_REQUEST；裁决查询支持分页，分页拼接与整取结果须逐位一致且不重不漏。
8. 使用 SQLite 持久化策略版本、租户状态、配额占用、令牌状态、裁决记录与意图日志，写操作先落意图记录再提交事务；进程被强制终止后重启须扫描未完成意图，将未提交的配额与令牌扣减回滚到最后一个完整版本或把批次标记为已中止，恢复报告只基于已持久化事实，并提供含业务码的统一 JSON 错误体与端到端演示脚本输出迁移前后裁决差异与恢复结论。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
本地样本验证旧新策略迁移裁决、配额与令牌桶联合判定、祖先级联扣减，并核对分页查询一致性与强制终止恢复报告。
