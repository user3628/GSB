为多租户模型推理服务团队从零构建一个本地可运行的批处理请求调度与算力预算仲裁引擎，核心技术问题是多个租户提交的推理批请求在共享算力预算下的准入仲裁、批次合并重排与幂等结果归并。输入是本地样本目录：一份请求清单 JSONL，每条含 request id、租户名、模型标识、输入 token 序列（整数列表，长度有固定上限）、优先级档位与提交序号；一份租户配置 JSON，声明每个租户的算力配额（以预算单元计）、是否允许被抢占、允许并发批次数；一份模型目录 JSON，声明每个模型的层数与隐藏维度，用于估算单请求算力消耗。推理为本地确定性伪推理：由模型标识与输入 token 序列派生分块矩阵并对隐藏维度做确定性归约，得到逐请求输出分数。引擎须在算力预算内合并同模型请求成批、按优先级与提交序号仲裁抢占、对重复提交做幂等归并，并支持中断后从已提交批次继续且不重复计算已归并请求。

任务环境与准备：
安装 Python 3.10 及以上，并在项目虚拟环境中安装 fastapi、uvicorn、numpy 与 pytest。
在空工作区初始化项目目录，准备本地确定性请求清单 JSONL、租户配置与模型目录 JSON 样本。
确认 SQLite 可用，服务默认监听本机端口，演示通过 curl 与本地脚本触发。

业务要求：
1. 服务须提供作业创建接口，接收请求清单、租户配置、模型目录与随机种子，校验 request id 唯一、租户名在租户配置中声明、模型标识在模型目录中声明、输入 token 序列非空且元素为有限整数、优先级档位在声明集合内；任一非法返回 E_PARAM 业务码并指出出错文件与行号，且不写入任何批次状态或临时结果文件。
2. 须实现确定性伪推理：由模型标识、输入 token 序列与种子派生分块矩阵，按隐藏维度做分块归约得到逐请求输出分数，归约在 float64 下按确定性顺序累加；相同输入与种子下逐请求输出分数须逐位一致，不得依赖全局随机状态、字典遍历顺序或系统时间。
3. 请求须按模型标识合并成批，批内按优先级档位降序、同档位按提交序号升序稳定排列；同模型请求合并后才可计算，合并不得改变逐请求输出分数，批次计算完成后须把结果拆分归并回原 request id，并记录每批合并的请求数与拆分归并的一致性结论。
4. 算力预算须按租户配额与全局预算单元双重仲裁：每个批次开始前先按批次合并后的估算消耗原子扣减租户配额与全局预算，租户配额不足时该租户请求进入等待队列，全局预算不足时按租户名与提交序号确定性地选择可被抢占租户释放占用；并发场景下任一租户累计扣减不得超过其配额，全局扣减峰值不得超过全局预算上限。
5. 请求须支持幂等提交：相同 request id 重复提交时须返回已有结果的归并视图而不重复计算或重复扣减预算，须在归并记录中给出首次提交的提交序号与本次重复次数；对内容不同但 request id 相同的冲突提交须返回 E_DUP 并指出 request id 与原提交的输入摘要。
6. 批次进度须在 SQLite 中以租户、批次、请求三级记录提交，单批的输出分数、预算扣减明细与归并回原请求的映射须在同一事务中写入；批次失败时该批整体回滚并归还已扣减预算，不得留下部分请求结果或与归并记录不一致的预算余额。
7. 每次完整调度须以整体替换方式生成版本化快照，含配置指纹、各批次合并摘要、逐租户预算余额与结果文件内容哈希；读取快照时若检测到数据库版本与磁盘结果文件哈希不一致、配置指纹变化或残留旧版本结果文件，须返回 E_STALE 并定位到批次与文件，禁止汇入旧结果。
8. 进程被强制终止后重启，须从 SQLite 已提交批次进度继续，核对每个租户的已提交批标记、预算余额与快照版本，重算未提交批次且不重复计算已归并请求；恢复后的逐请求输出分数、逐租户预算余额与快照版本序列须与无中断执行完全一致，并提供固定请求集与租户配置的演示入口，输出合并批次数、抢占次数、幂等归并次数与预算扣减峰值。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定请求集与租户配置验证合并分批、预算仲裁、幂等归并与中断恢复后结果逐位一致。
