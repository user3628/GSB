这项需求没有既有代码，需要为一家内部安全团队从零构建一个面向 Windows 主机的备份完整性与防篡改恢复引擎。备份仓库以本地确定性样本给出：每个备份代次由清单文件（记录代次号、文件条目、每文件内容摘要与前一链摘要）与对应内容对象组成，仓库中还预置少量被篡改对象、被删除对象与清单被整体替换的样本。团队需要沿着代次链增量维护仓库状态，识别链哈希断裂与对象摘要不符，在恢复时定位到最近一个可信代次并说明恢复边界，同时支持多仓库并发巡检、进程被强制终止后的恢复以及外部参数注入异常。引擎还需给出可回放的代次演进时间线与结构化报告，重复运行结果须字节级一致。

任务环境与准备：
安装 Go 1.21 或以上版本，确认 go 命令在 Windows 命令行可用。
安装可用的 SQLite 驱动依赖（如 modernc.org/sqlite），在空目录执行 go mod init 后拉取依赖。
准备本地确定性样本生成入口，产出多代次清单、内容对象、被篡改对象与整体替换清单样本，不依赖网络与外部账号。
确认可在 Windows 命令行运行 go build 与 go test，并使用独立临时目录存放样本与状态库。

业务要求：
1. 实现备份代次清单与内容对象的本地解析核心：读取确定性样本中的代次清单与对象文件，提取代次号、文件条目、每文件内容摘要、清单自身摘要与前一链摘要，严格校验清单内声明的对象长度与摘要格式，对清单截断、摘要格式非法与对象缺失分别给出稳定业务码 E_MANIFEST_TRUNCATED、E_DIGEST_FORMAT、E_OBJECT_MISSING。
2. 实现代次链哈希演进与篡改定位：从首个代次开始逐代校验前一链摘要与实际前代摘要是否衔接、每代清单自身摘要是否与登记值一致，链断裂时标记 E_CHAIN_BROKEN 并记录断裂代次与期望/实际摘要；当某一代清单被整体替换但代次号未变时，须依据内容摘要差异识别该替换而非仅比对代次号，替换识别结果写入演进轨迹，代次号相同不得作为跳过校验的依据。
3. 实现恢复点裁决与恢复边界输出：按代次由新到旧选择最近一个链完整且全部对象摘要校验通过的代次作为恢复点，输出可恢复文件集合与被排除的代次及其原因；当不存在任何可信代次时返回 E_NO_TRUSTED_RESTORE，且不得输出部分恢复清单；恢复边界必须与演进轨迹中记录的业务码自洽，替换代次不得被选为恢复点。
4. 实现带版本号的仓库状态快照与整体替换识别：每完成一轮代次巡检后在单个 SQLite 事务内提交递增版本号快照，记录代次结论、链状态与可信恢复点，旧快照整体保留可回放；快照内容比较须识别整体替换式版本变化而非仅比对版本号，加载时校验版本链连续性，发现跳号返回 E_SNAPSHOT_VERSION 并回退到最近连续版本，且回退本身不得推进版本号。
5. 实现并发多仓库巡检的资源控制：多个仓库在独立会话中巡检，会话间状态与快照版本隔离；并发度与单会话代次数上限可配置，超并发上限的仓库进入等待队列而非直接拒绝，单仓库代次数超限时以 E_GENERATION_BUDGET 终止该会话其余仓库不受影响，在途会话数须可观测，所有会话级失败须可追溯到具体仓库与代次。
6. 实现进程强制终止后的恢复一致性：在巡检提交或快照提交过程中进程被强制终止后重启，依赖 SQLite 已提交事务恢复仓库状态与快照版本，已提交结论不回退、未提交事务整体丢弃且该仓库可重新巡检；恢复后若发现版本链跳号须以 E_SNAPSHOT_VERSION 拒绝加载并回退到最近连续版本，不承诺生成退出报告。
7. 实现异常注入验证链路：通过外部命令行参数或配置文件构造内容摘要不符、代次断层、清单整体替换、对象缺失、快照版本跳号五类样本，分别断言对应业务码、可信恢复点终态未被污染、已提交快照版本未被推进；注入仅通过输入与参数进行，不得修改源码制造失败，注入样本须与正常样本共存于同一批次。
8. 提供可交互演示入口与确定性报告：以子命令方式支持巡检指定仓库、按快照版本回放代次演进时间线、查询恢复点与恢复边界、导出 JSON 报告；报告含代次演进轨迹、链状态、篡改定位、恢复点与业务码，按仓库相对路径与代次号稳定排序，时间字段只使用固定采样标记，重复运行且输入不变时报告字节级一致并在 Windows 上可直接运行。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证代次链校验、篡改定位与恢复点裁决，并核对并发巡检、中断恢复及报告字节级一致。
