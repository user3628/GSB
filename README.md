新接手的流式报表项目还没落任何代码，工作区里只有这份需求，需要先把窗口聚合执行组件做成可集成的 Go 领域库并附带结果验证工具。程序内置固定种子生成器在本地确定性产出事件分片：每条事件带毫秒时间戳、分区号、分组键、int64 定点度量值（scale=1e6）、可空标记与事件序号，覆盖滚动、滑动、会话三类窗口规格，并含全零分组、空值度量、迟到事件与单一分组占据多数记录的偏斜分区。另附一份带单调版本号的窗口规格快照，声明窗口类型、窗口宽度与步长毫秒、会话空闲间隔、迟到容忍毫秒、每轮处理预算与并发窗口重算上限，以及以小整数对保存的高精度参考窗口聚合值作为唯一真值来源。核心矛盾在于：度量列类型会随批次演化，窗口一旦关闭又可能被迟到事件回填，而每个窗口在任意批次切分与任意中断点下都必须给出可逐位核对的分组聚合结论。

任务环境与准备：
安装 Go 1.21 或以上版本（例如使用系统包管理器或官方二进制包），确认 go version 可用。
安装 SQLite 开发库与命令行工具，确保组件可通过 Go 的 SQLite 驱动打开本地数据库文件；无需外部服务或网络。
在空工作目录执行 go mod init 初始化模块，按需添加 SQLite 驱动依赖并保证离线缓存可用。
运行时使用程序内置固定种子生成器写出事件分片、窗口规格快照与高精度参考值文件，全部产物落在工作目录内，不依赖真实数据源或附件。

业务要求：
1. 实现事件分片与窗口规格快照的加载与版本识别：快照携带单调递增版本号、生成时间、窗口类型与参数、迟到容忍毫秒与整体校验摘要，加载时校验版本单调与摘要，失败返回 E_SNAPSHOT_INVALID 且已提交快照必须完全可用；新快照须整体替换窗口状态，不得新旧窗口混用。
2. 实现度量类型演化处理：每批次声明度量列类型（int64 定点、更高精度定点或空值），引擎须校验批次内非空度量与声明类型一致，不一致返回 E_MEASURE_TYPE_MISMATCH 并指明事件序号；类型升级时输出提升规则与每步转换的舍入位，类型降级须显式拒绝或按声明规则截断并记录被截断事件。
3. 实现三类窗口划分与归属判定：滚动窗口对齐纪元边界，滑动窗口按宽度与步长生成重叠窗口，会话窗口按同一分组键的空闲间隔切分；窗口起止以毫秒整数表示并显式声明边界包含关系，迟到事件落在已关闭窗口内时按迟到容忍期判定回填或落入迟到队列，越界返回 E_EVENT_OUT_OF_RANGE。
4. 实现窗口状态机与关闭裁决：窗口至少包含 OPEN、CLOSED、EMITTED、REOPENED 四种状态并规定合法迁移路径，非法迁移返回 E_INVALID_TRANSITION 且不改变已持久化状态；新事件只允许在 OPEN 或 REOPENED 状态并入，窗口关闭须记录关闭依据与迟到容忍截止毫秒。
5. 实现分组聚合与定点数值契约：每个窗口按分组计算计数、求和、最小值与最大值，求和使用 int64 定点并做越界检查，越界返回 E_NUMERIC_OVERFLOW 并指明窗口与分组；迟到回填只重算被回填窗口及其分组，须输出每步舍入方式与累计误差，并与高精度参考逐窗口比对给出最大绝对偏差与相对偏差。
6. 实现窗口结果的合并顺序无关性：同一窗口在分批摄入、乱序回填与不同批次切分下，分组聚合结论必须落在声明精度内且补偿求和的中间态可按段基版本重放；输出批次切分方式、合并次序与偏差明细，禁止因切分不同而使分组计数或最值改变。
7. 实现基于 SQLite 的意图持久化与强制终止后恢复：批次合入、窗口关闭与快照切换前先写意图记录再提交事务；进程在批次合入或窗口关闭中途被强制终止后重启须扫描未完成意图，把未提交窗口恢复为待重算或复用已提交部分和继续，恢复报告只基于已落盘事实，不得声称一定产出完整退出报告。
8. 实现单写者摄入与多读者查询的并发一致及幂等：事件摄入、窗口状态迁移与快照切换按全局单写者串行执行，多个按时间范围与分组过滤的查询可并发读取某一完整提交版本，不得出现窗口已 EMITTED 而迟到队列仍指向旧分组；同一批次标识重复提交只生效一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_REQUEST。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证类型演化、迟到回填窗口聚合与强制终止后续算恢复的可复现一致性，并核对异常业务码。
