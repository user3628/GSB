平台侧提出需要交付一套基础设施配置一致性数值审计能力，本次由独立开发者在空工作区完成首个可运行版本。平台维护若干节点的配置项，每项声明整数或定点小数取值、来源通道（文件、环境变量、模板渲染、脚本注入）、生效优先级与单位换算系数。同一逻辑配置在不同节点、不同来源通道上会得到不同数值，换算与优先级叠加会引入可复核的舍入误差与优先级传播误差，因此每次一致性判定都必须给出误差上界并与本地高精度有理数参考结果逐项比对。输入由内置固定种子生成器确定性产出：节点配置分片（JSON 行）、两代来源描述格式（新版结构化字段与旧版带单位后缀的自然文本），以及高精度参考取值。

任务环境与准备：
安装 Go 1.21 或更高版本，并确认 go version 可执行。
使用 modernc.org/sqlite 或 go-sqlite3 等纯 Go 或本地可编译的 SQLite 驱动，版本写入 go.mod。
在项目内实现固定种子样本生成器，产出节点配置分片、两代来源描述与高精度有理数参考取值，样本不依赖外部网络。
准备本地 HTTP 测试端点脚手架，用于暴露审计提交与查询接口。
确保工作目录可写，SQLite 数据库文件与样本目录由程序自行创建。

业务要求：
1. 实现配置项、来源通道与节点模型：配置项声明键路径、类型（整数或定点小数）、单位换算链、来源优先级与整体校验摘要；节点声明标识、来源通道集合与生效优先级。解析本地样本时校验键路径合法、单位换算链中每个系数为正整数、定点小数 scale 在允许集合内，解析失败返回 E_SPEC_INVALID 并指明字段与行号。
2. 实现两代来源描述格式的解析与归一化：新版描述以结构化字段给出数值、单位枚举与优先级；旧版描述为带单位后缀的文本（如 512Mi、1.5 GiB、250m）。两种格式须归一化为同一内部定点表示（比例保留固定小数位），输出每条记录的原始文本、归一化值、舍入位与累计舍入误差，无法识别的后缀返回 E_UNIT_INVALID。
3. 实现单位换算链的定点求值与误差传播：沿配置项声明的换算链逐级相乘或相除，全程使用 int64 定点运算并在每步校验不越界，越界返回 E_NUMERIC_OVERFLOW 并指明该步；对每步输出舍入方式与单步误差界，并按误差传播规则合成整链的可量化误差上界。
4. 实现多来源叠加与优先级传播误差：同一键路径被多个来源通道提供时，按生效优先级与来源顺序确定性叠加，叠加顺序的变化可能改变定点舍入结果，须输出每来源贡献、叠加次序与叠加引入的累计误差；当高优先级来源取值被低优先级来源遮蔽时输出遮蔽明细，遇优先级相同且取值冲突返回 E_PRIORITY_CONFLICT。
5. 实现与高精度有理数参考的逐项比对：将审计结果与本地样本中的高精度参考取值比较，输出每项绝对偏差、相对偏差与是否落在声明误差上界内；误差上界被突破时返回 E_ERROR_BOUND_EXCEEDED 并附项目标识、实测偏差与上界值。比对须对节点、来源通道与换算链的组合遍历完整，禁止抽样跳过。
6. 实现带版本号的审计快照整体替换与增量片段提交：快照携带单调递增版本号、生成时间与校验摘要，加载时校验版本单调与摘要并整体替换，失败返回 E_SNAPSHOT_INVALID 且保持旧快照完全可用；增量片段只含受影响配置项并携带基础版本，基础版本不是当前版本时返回 E_STALE_BASE 且不改变已提交状态。
7. 实现单写者审计提交与多读者查询的并发一致及幂等：审计执行与快照推进按提交单写者串行，多个只读查询可并发读取某一完整提交版本；同一请求标识重复提交只执行一次、其余等待并复用同一结果，内容不一致返回 E_CONFLICTING_REQUEST；查询不得看到部分配置项已审计而误差上界尚未落定的中间状态。
8. 使用 SQLite 持久化快照版本、审计结果、误差记录与意图日志，审计与快照切换前先写意图记录再提交事务；进程在审计或快照切换中途被强制终止后重启须扫描未完成意图，把审计结果回滚到最后一个完整快照版本或将增量标记为已中止，恢复报告只含已落盘事实。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证单位换算误差上界、多来源优先级叠加与参考比对，并核查强制终止后的恢复。
