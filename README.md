当前是空白工作区，没有现存项目、代码或数据附件，需从零构建一个本地可运行的注意力头激活阈值裁决与逐头降位版本轨迹工作台。业务目标是帮助部署工程师判断多注意力头结构中哪些注意力头对激活值截断敏感，从而在逐头选择激活位宽时有依据，并对每次逐头位宽组合保留可追溯、可回滚的版本轨迹。输入为固定随机种子生成器产出的本地 .npz 分片，每个分片含若干注意力头的查询与键投影矩阵、逐头激活样本张量（形如 [样本数, 头数, 序列长度, 头维度]）与层名头号清单；另附一份 YAML 裁决配置，声明逐头候选激活位宽档、每头采样样本数上限、截断敏感度阈值、全局截断误差预算与逐头误差容差。系统不依赖真实大模型、GPU、外部站点或在线资源，仅使用本地确定性样本与本地 HTTP 服务。核心取舍在于：敏感性裁决必须用有限的逐头采样来控制交互延迟，但结论要与足够采样的全量裁决逐字节一致；逐头位宽组合提交后若被阈值判定不可用，必须原子回滚到上一个可用组合，且回滚后查询仍须与全量运行一致。

任务环境与准备：
确认 Python 3.11 与 NumPy、FastAPI、uvicorn、PyYAML 已安装，全部为本地依赖，不安装容器、镜像或外部服务
新建工作目录并在其中初始化项目结构，确保全部输入样本、检查点与输出均落在该工作区内
运行本地固定种子生成器产出含注意力头投影矩阵与逐头激活样本的 .npz 分片、头号清单与 YAML 裁决配置，并核对激活形状与投影维度
准备两档采样窗口与一个刻意超出全局截断误差预算的位宽组合作为回滚用例
启动本地 HTTP 服务前确认工作目录可写，文件锁与检查点目录均可创建

业务要求：
1. 实现逐头激活截断探测：对每个注意力头仅对该头激活值按候选位宽档施加定点截断、其余头与权重保持全精度，用配置限定的采样窗口执行确定性前向并计算该头输出相对全精度参考的相对误差，形成逐头截断敏感度原始值；投影矩阵维度与激活头维度不匹配或头号超出清单时返回带头号与维度的 E_HEAD_MISMATCH。
2. 实现逐头截断敏感度裁决：把原始敏感度归一化为逐头裁决分数，输出按头号与分数的确定性排序、误差的上界估计与参与采样的样本区间；上界估计须由采样窗口与本地全精度参考逐项给出；某头采样样本数低于可配置下限时标记为采样不足并在裁决表中保留占位，不得静默剔除该头。
3. 实现截断误差预算约束下的逐头位宽裁决：依据逐头裁决分数与全局截断误差预算，在候选位宽档间为每个头分配位宽组合，并记录逐头取舍理由、被降档头与预算占用明细；当某头裁决分靠前但全局预算已耗尽时须在诊断中标明预算受限而非敏感度不足，且组合总误差估计不得超过预算上限。
4. 实现采样窗口扩大后的增量裁决与全量一致性校验：采样窗口扩大、敏感度阈值或位宽档变化时，由各阶段内容摘要构成的版本指纹识别受影响的最早阶段，仅重算该阶段及其下游；增量得到的逐头裁决排序、误差上界与位宽组合须与从零全量运行逐字节一致，不一致时返回 E_INCREMENTAL_MISMATCH 并附差异头号清单与首次分歧位置。
5. 实现逐头位宽组合的版本化原子提交与整体替换识别：每次提交位宽组合生成单调版本号，以原子方式写入含版本号、逐头位宽指纹、采样窗口摘要、配置版本与裁决摘要的记录，写入任意位置中断不得留下半写记录；检测到记录被整体替换（版本号回退、摘要不匹配或指纹变化）须区分回退与篡改并返回 E_STALE_VERSION。
6. 实现不可用组合的原子回滚与历史并存：当提交组合因超阈值或裁决摘要不自洽被判不可用时，回滚到上一个可用组合，使后续逐头裁决查询与位宽组合建议读取该版本内容；回滚本身生成可追溯记录且被回滚组合的历史保留可查，回滚后查询结果仍须满足与全量运行结果一致的约束。
7. 实现并发提交保护与交互查询延迟预算：多个工作进程对同一工作区提交版本时使用真实文件锁并比较版本号，仅允许版本号连续推进，落后或重复提交返回 E_STALE_VERSION；逐头裁决查询与位宽建议须在可配置延迟预算内返回，超预算返回带查询标识与已耗时字段的 E_LATENCY_BUDGET；缓存键须包含采样窗口指纹与配置版本，并在窗口或配置变化时失效。
8. 提供本地 HTTP 与命令行诊断入口：支持导入分片与配置、触发逐头探测裁决、查询裁决排序与位宽组合理由、查看版本轨迹与回滚记录、请求优雅停止、执行恢复；演示数据至少含 3 个分片、6 个注意力头与两档采样窗口，一次完整运行生成固定摘要，并以注入的头维度不匹配与一个超预算不可用组合验证错误码与回滚结果。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
