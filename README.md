本地生活搜索团队目前只有一份需求说明，工作区尚未初始化，需要从零交付一个多路召回融合的离线实验组件与可重复实验脚本。程序内置固定种子生成器在本地确定性产出 JSONL 样本：物品库（item_id、类目、类目路径、float32 编码向量、标题文本与语言标签）与查询集（query_id、原始查询、locale 与历史点击类目序列），覆盖三档规模（小档约 200 物品与 50 查询、中档约 2000 物品与 500 查询、大档约 20000 物品与 2000 查询），并附一份带单调版本号的融合配置快照，声明词法倒排、类目协同与向量近邻三路的候选深度与千分比评估配额、各路融合权重、相似度容忍间隔、去重与截断规则、全局候选评估次数预算与每轮时间预算。组件需在规模逐档增长时自适应地在精确全量打分、候选截断打分与预算分桶打分之间取舍，同时保证结果可与高精度参考比对且增量变更后与全量重算逐字节一致。

任务环境与准备：
在 Linux（WSL Ubuntu）工作区安装 Go 1.22 或以上版本并确认 go 命令可用，安装命令为 apt-get install -y golang-go 或使用官方二进制包。
确认 SQLite 版本为 3.35 或以上，并准备 Go 的纯 Go SQLite 驱动依赖（如 modernc.org/sqlite），通过 go mod tidy 拉取本地模块缓存可用的版本。
无需外部样本、账号、GPU 或网络服务，全部输入由程序内置固定种子生成器在启动时于本地写出。
预留本地可写目录用于 SQLite 数据库文件与检查点产物，并确保同一工作区可被多进程并发访问以验证发布互斥。

业务要求：
1. 实现查询与物品文本规范化及词法倒排打分：文本做 Unicode NFKC、空白折叠、全半角统一与小写化后按中文单字加相邻二字、拉丁连续串切分，构建倒排并以定点权重累加词项分，输出倒排命中明细与打分摘要；空查询或仅含标点须返回带 query_id 的 E_EMPTY_QUERY。
2. 实现类目协同与向量近邻两路打分：协同路按历史点击类目序列的路径前缀匹配加权，近邻路以缩放定点域累加余弦相似度，编码向量按显式 scale 还原；编码向量为零范数、维度与物品库声明不符或出现 NaN 时须返回带 item_id 与维度的结构化业务码而非静默跳过。
3. 实现可配置多路融合与去重截断：支持加权求和与倒数排名两种融合，同一物品多路命中时记录来源各路排名、分数与对数贡献并合并，输出按融合分降序、同分按 item_id 升序；截断位大于候选数时按候选数截断并记录，不得产生重复 item_id。
4. 实现基于规模档与预算的算法取舍：依据物品数、查询数、各路候选深度与全局候选评估次数预算，为每档在精确全量打分、候选截断打分与预算分桶打分三种策略中选定组合，记录候选打分明细、选择理由与被淘汰策略原因；小档须避免选用为大档设计的重策略。
5. 实现并行召回与确定性归约：以查询为调度单元，在全局并发查询上限与每轮时间预算约束下使用本地工作池并行处理，各查询的候选、融合分与指标按 query_id 全局排序后归约，使并行输出与串行顺序执行逐字节一致；工作进程异常须以结构化错误对象记录。
6. 实现误差界推导与排序稳定性裁决：每个命中结果须附带各路量化误差界、融合分有效位数与推导依据，并与本地高精度参考结果按固定抽样位比对；跨相邻分差落在误差界内的位次标为不稳定并记录跨越幅度，偏差超容差返回带 query_id 与 item_id 的 E_TOLERANCE_EXCEEDED。
7. 实现 SQLite 事务化阶段检查点与恢复边界：每查询每阶段完成时以单个事务写入含阶段名、query_id、配置版本、产物摘要与单调序号的记录，同一查询同一阶段只允许一条有效记录；被强制终止后重启仅凭已提交事实恢复，不承诺生成退出报告，恢复后指标须与连续执行逐字节一致。
8. 实现配置增量片段应用、整体替换识别与失效传播：增量片段须校验基础版本一致，不一致返回 E_STALE_BASE 并附当前版本；当配置快照或样本集被整体替换时通过内容摘要与版本序号区分正常推进、整体替换与回退，整体替换使全部派生索引、融合结果与指标失效重建，回退拒绝并返回 E_STALE_VERSION。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地三档样本验证多路召回融合、预算取舍与并行归约的一致性，并核验误差界、增量重建与整体替换裁决。
