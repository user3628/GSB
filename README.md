新接手的交易存储引擎需求尚未开工，当前目录里只有一份关于快照隔离的设计说明，需要据此实现一套 MVCC 可见性快照与版本链管理组件，并以可运行示例交付。每个事务在开始时领取单调递增的事务序号并持有自己的可见性快照；行的每次修改产生新版本，版本记录创建事务序号、提交状态与指向前一版本的引用。可见性规则由此决定：读只能看到在自身快照内已提交且未被后续提交删除的版本。真实环境里事务会并发提交、回滚与长时间持有快照，进程可能在写入或清理中途被强制终止；重启后必须依赖 SQLite 中持久化的事实重建可见性快照与版本链，并证明同一事务在重启前后读到的版本集合一致。

任务环境与准备：
安装 Go 1.22 或更高版本，安装后执行 go version 确认可用。
准备本地 SQLite 驱动（如 modernc.org/sqlite），在空工作区执行 go mod init 后通过 go get 引入，不依赖 CGO。
所有样本与 HTTP 测试端点均在本地生成与监听回环地址，不需要外部账号或网络服务。
在 Windows 上用独立临时目录存放快照文件与 SQLite 数据库，运行前确保目录可写。

业务要求：
1. 实现事务、行版本与自增事务序号模型：事务记录事务序号、状态（ACTIVE、COMMITTED、ABORTED）、开始时刻毫秒与可见性快照，行版本记录行键、版本序号、创建事务序号、提交状态、内容摘要与指向前一版本的引用。解析本地确定性样本时校验事务序号严格递增且无缺口、行键非空、内容摘要为定长十六进制，非法输入返回 E_TXN_INVALID 或 E_VERSION_INVALID 且整批不入库。
2. 实现可见性判定核心：对给定读事务快照与行键，沿版本链自新到旧返回第一个满足“创建事务序号已提交且不大于快照上界，并且未被快照内已提交的删除版本遮蔽”的版本；自修改未提交、快照外提交、已回滚版本三类情形必须给出可区分的判定原因。同一读快照重复读取同一行必须逐位一致，且判定结果须附命中的版本序号与判定依据。
3. 实现版本链的结构校验与修复：每次写入新版本时在同一事务内更新行键到最新版本的指针和前一版本引用，禁止出现同一行键的两个最新版本指针、版本序号回退或引用成环。结构校验发现分叉时返回 E_VERSION_CHAIN_BROKEN 并指明行键与分叉点版本序号；修复只允许回退到最后一个完整提交的版本链状态，不得凭空补齐缺失版本。
4. 实现快照整体替换与版本识别：读事务快照文件携带快照序号、生成时间、事务序号上界与整体校验摘要，加载新快照时须校验序号单调与摘要，失败返回 E_SNAPSHOT_INVALID 且必须保持旧快照完全可用；加载成功须整体切换快照与依赖它的可见性视图，不得新旧快照混用，并输出被替换的旧快照序号与切换影响的事务数。
5. 实现基于 SQLite 的意图持久化与强制终止后恢复：写入新版本、提交或回滚事务、更新版本链指针与快照切换前均先写意图记录再提交事务；进程在写入或提交中途被强制终止后重启须扫描未完成意图，把未提交版本回滚为不存在、未提交事务回滚为 ACTIVE 或标记为 ABORTED，恢复报告只基于已落盘事实，且恢复后对同一读快照的可见性结果与终止前已提交状态下的结果逐行一致。
6. 实现单写者提交与多读者查询的并发一致及幂等：事务提交、回滚与版本链更新按事务序号单写者串行执行，多个按快照的读查询可并发；查询只能看到某一完整提交版本，不得出现事务已标记 COMMITTED 而该事务的某个行版本提交状态仍为未提交、或最新版本指针已更新而版本链引用未落库的中间可见状态。同一请求标识重复提交只执行一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_REQUEST。
7. 实现长事务对版本回收的阻塞与安全回收裁决：当清理流程尝试移除某一旧版本时，必须检查是否存在活跃快照（事务序号上界小于该版本被取代的提交序号）仍在引用该版本；被引用的旧版本不得移除，返回 E_RECLAIM_UNSAFE 并附最早阻塞快照的事务序号与剩余引用数。回收前后可见性判定结果不得改变，回收须先写意图记录并输出本次实际移除的版本数与仍被阻塞的版本数。
8. 提供本地 HTTP API 与可重复演示示例：接口覆盖事务开启与提交回滚、行版本写入、按快照读取行、快照切换、触发回收、查询事态与恢复报告；失败响应统一为含业务码与上下文的 JSON，至少覆盖 E_TXN_INVALID、E_VERSION_INVALID、E_VERSION_CHAIN_BROKEN、E_SNAPSHOT_INVALID、E_RECLAIM_UNSAFE、E_CONFLICTING_REQUEST。示例用固定本地样本完成一次并发提交场景、一次强制终止后恢复与一次长事务阻塞回收的演示。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
