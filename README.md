当前是空白工作区，没有现存项目、代码或数据附件，需从零构建一个本地可运行的多源时序遥测增量对齐工作台，交付可交互的专业应用与可重复演示。输入为固定随机种子生成器产出的本地确定性样本：三个传感器源各自以不同采样间隔（整数毫秒步长）产出时序分片（JSONL，含 sensor_id、timestamp_ms、数值通道、质量标记），三源在同一时间区间内存在重叠与缺口；另附一份 YAML 对齐配置，描述重采样网格步长、插值方式（前值保持、线性、最近邻）、各源优先级、有效值区间与对齐容差，并提供结构版本 2 与结构版本 1 两种配置形态（版本 1 以整数百分比描述容差、缺少通道映射字段）。工作台需完成规范化与时间轴构建、重采样与插值、多源融合与冲突裁决、对齐摘要导出四个阶段，并在某个源的分片或配置变化时做增量重建。

任务环境与准备：
安装 Python 3.11 及以上版本，并确保 python 与 pip 在 PATH 中可用。
安装 NumPy 与 PyYAML（pip install numpy pyyaml），版本以本地已安装为准，不依赖网络服务。
在空白工作区创建项目目录，样本、配置与运行脚本均由本任务自带的确定性生成器在本地产出，无需外部账号或数据集。
确认本地 HTTP 接口端口未被占用，运行脚本以本地文件与本地服务为唯一交互对象。

业务要求：
1. 实现规范化与统一时间轴阶段：对每个源分片按 timestamp_ms 排序并去重，检测重复时间戳、非单调时间戳与超出有效值区间的数值，输出清洗报告与带单调序号的统一以毫秒为单位的重采样网格；时间戳重复或非单调时须返回带 sensor_id 与时间戳的 E_TIME_INVALID 并保留诊断，同一输入与配置必须产生逐字节一致的网格。
2. 实现重采样与三种插值方式：按网格步长对每个源执行前值保持、线性与最近邻插值，线性插值须在浮点域计算并对有效值区间做钳制，缺口区间按可配置最大连续缺失长度决定是否插值；插值结果须记录每网格点的来源时间戳与插值方式，当网格步长为零、为负或超过对齐容差时返回 E_GRID_INVALID。
3. 实现多源融合与冲突裁决：多源在同一网格点均有有效值时按源优先级与可配置加权规则融合并记录参与源、各源值与融合贡献，源优先级并列时须有确定性仲裁规则；仅单源有效时标记为单源或外推并记录来源，某网格点全源缺失时须保留缺口记录而非静默跳过，融合结果在重复运行时逐字节一致。
4. 实现结构版本 1 配置的兼容解析与显式升级：版本 1 以整数百分比表述容差且缺少通道映射字段，导入时须按可配置规则做百分比到毫秒容差换算、补齐通道映射并在结果中标注降级与换算依据；换算后应能导出为版本 2 并再次导入得到等价配置，往返转换须保持对齐网格与融合结果不变。
5. 实现版本指纹与增量失效传播：当某源分片内容、网格步长、插值方式、源优先级、加权规则或容差任一变化时，通过各阶段内容摘要构成的版本指纹识别受影响的最早阶段，使该阶段及其全部下游产物（含融合结果与摘要）失效并重建，未受影响源的分片结果继续复用；失效原因与指纹须可查询，且旧版本结果不得被误用。
6. 实现持久化检查点、优雅停止与恢复一致性：每阶段完成时以原子方式写入含阶段名、输入内容摘要、配置版本、产物摘要与单调序号的记录，写入任意位置中断不得留下半写记录；收到停止请求时完成当前不可拆分单元后退出，恢复后最终网格、融合结果与摘要必须与一次从零完整运行逐字节一致，且检查点序号连续推进无跳跃。
7. 实现并发发布保护与快照整体替换识别：多个工作进程对同一工作区发布阶段产物时使用真实文件锁并比较序号，仅允许序号连续推进，落后、重复或跨阶段错位发布返回 E_STALE_CHECKPOINT，缺失前置阶段产物时返回 E_INVALID_STAGE；当检测到记录被整体替换（序号回退、配置指纹变化或摘要不匹配）时须区分回退、篡改与正常推进，仅正常推进可被接受。
8. 提供交互接口与本地确定性演示：命令行与本地 HTTP 接口支持导入三源分片与两份版本配置、触发分阶段对齐、查询各阶段状态与版本指纹、查看冲突裁决与缺口明细、请求停止、执行恢复、导出对齐摘要；演示数据至少含三源不同步长、重叠区间、缺口区间与中英混排字段标签，一次完整运行生成固定摘要，并演示一次增量重建与一次停止恢复。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
