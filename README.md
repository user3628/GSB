项目初始状态是空目录，需要为一家多租户物联网平台从零构建一个设备授权与信任度量的本地引擎。平台内每个租户维护若干设备，设备需通过注册、信任评估、授权签发与持续校验四个阶段获得访问能力；每次授权请求需依据设备指纹、历史行为评分（整数定点，scale=1e6）、信任阈值与租户策略综合裁决。由于设备接入呈批量化与突发性，引擎需在有限 CPU 与内存预算下并行调度设备评估任务，按设备风险分加权排队，并在总预算耗尽时按风险从低到高降级处理。引擎还需维护带递增版本号的授权快照，支持整体替换识别、强制终止后的恢复与外部参数注入异常验证。验收通过本地确定性样本与本地测试服务完成。

任务环境与准备：
安装 Go 1.22 或更高版本（Windows 官方安装包），确认 go version 可用；无需 CGO。
SQLite 使用纯 Go 驱动（如 modernc.org/sqlite），通过 go get 拉取，版本在 go.mod 中固定；确保本地模块缓存可用。
在空目录中初始化 Go module（go mod init），所有样本、密钥材料与测试服务由程序内置生成器在本地临时目录创建，不依赖网络。
准备本地确定性样本集，覆盖设备正常、指纹重复、评分溢出、凭证过期、快照跳号与预算耗尽场景，样本随程序生成。
运行入口使用 go run 或 go build 产出的本地可执行文件，测试使用 go test；所有路径使用 Windows 本地临时目录。

业务要求：
1. 实现设备注册与信任评分的解析与规范化：解析本地确定性样本中的设备声明（设备标识、指纹、所属租户、声明能力、历史行为事件序列），把历史行为事件按逻辑时间累加为整数定点评分（scale=1e6，禁止浮点），校验设备标识唯一性、指纹格式与租户归属可解析性；非法声明返回 E_DEVICE_INVALID 且不得写入任何设备状态，评分累加中的乘加溢出须返回 E_SCORE_OVERFLOW。
2. 实现设备授权签发与持续校验核心：依据设备当前信任评分、租户策略中的信任阈值与所需能力集合裁决是否签发授权凭证，凭证绑定设备标识、租户、能力集合、签发时的评分版本与过期时间并做本地签名；校验时严格拒绝签名不符、过期、能力超出策略允许范围或评分版本已回退的凭证，分别返回 E_CRED_SIGNATURE、E_CRED_EXPIRED、E_CAPABILITY_DENIED、E_SCORE_REGRESSED。
3. 实现按风险加权的并行调度器与资源预算裁决：并发度、全局 CPU 时间预算、全局内存预算与单设备评分时间预算均为参数，调度器按设备风险分从高到低加权排队，超并发上限的任务进入等待队列而非直接拒绝；单设备超预算标记 E_DEVICE_BUDGET，全局预算不足时按风险分从低到高将剩余设备标记 E_GLOBAL_BUDGET_EXHAUSTED，被降级设备仍须原样出现在报告计数中。
4. 实现带版本号的授权快照与整体替换识别：每完成一轮设备评估与授权签发后在单个 SQLite 事务内提交递增版本号快照，记录设备状态、评分、凭证摘要与所用策略版本；快照内容比较须识别整体替换式版本变化而非仅比对版本号，加载旧快照时校验版本链连续性，发现跳号返回 E_SNAPSHOT_VERSION 并回退到最近连续版本，已提交快照整体保留可回放。
5. 实现强制终止后的恢复一致性：在授权签发提交或快照提交过程中进程被强制终止后重启，依赖 SQLite 已提交事务恢复设备状态、评分与快照版本，已提交签发不回退、未提交事务整体丢弃且该设备仍可重新参与评估；恢复后若发现版本链跳号须以 E_SNAPSHOT_VERSION 拒绝加载并给出最近连续版本号，不承诺生成退出报告。
6. 实现并发设备评估的会话隔离与竞争控制：多个租户的设备评估在独立会话中执行，会话间设备状态与评分账本隔离；同一设备的并发授权请求须在设备粒度上互斥，仅一个成功、其余返回 E_AUTH_CONTENTION；在途事务数以可配置上限的信号量约束，超出等待阈值的请求排队而非无限阻塞，在途计数须在输出中可观测。
7. 实现异常注入验证链路：通过外部命令行参数或配置文件构造指纹重复、评分溢出、凭证过期复用、快照版本跳号、并发授权竞争与全局预算耗尽六类样本，分别断言对应业务码、受影响设备状态终态未被污染、已提交快照版本未被推进；注入仅通过输入与参数进行，不得修改源码制造验收失败。
8. 导出确定性 JSON 授权报告：包含每个设备的注册摘要、评分换算链与截断误差账本、授权裁决与业务码、凭证状态、调度排队与预算使用量、快照版本链；报告按租户标识、设备标识与业务码稳定排序，时间字段只使用固定采样标记，并发度从 1 变化到上限时报告字节级一致，重复运行且输入不变时结果字节级一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地确定性样本验证设备授权、并行预算裁决、快照恢复与异常注入的业务码及报告字节级一致性。
