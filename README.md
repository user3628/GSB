这项需求没有既有代码，需要为一家多租户 SaaS 开放平台从零构建一套令牌刷新与吊销的领域组件，并附带可直接运行的完整示例。平台为每个租户签发访问令牌与刷新令牌，刷新时必须轮换令牌并原子失效旧令牌，吊销分单令牌吊销与整族吊销两类，且每次刷新按整数定点配额扣减租户额度；令牌族谱随租户规模增长迅速，小型租户适合逐族精算、大型租户需要批量流式扫描，两条路径必须给出同一结论。所有金额与配额以 scale=1e9 的 int64 定点数运算，禁止浮点。组件需在 SQLite 中维护带递增版本号的令牌与配额快照，识别整体替换式版本变化，支持并发刷新竞争、强制终止后恢复，并通过外部参数注入异常。验收在 Windows 本地确定性样本上完成，不依赖任何外部账号或网络服务。

任务环境与准备：
安装 Go 1.22 或更高版本（Windows 官方安装包），确认 go version 可执行。
使用纯 Go 的 SQLite 驱动（如 modernc.org/sqlite），通过 go get 拉取后 go mod tidy 固化依赖，无需 CGO。
准备可写的本地临时目录用于 SQLite 数据库文件与确定性样本，示例命令在该目录内运行。
所有样本与密钥由程序内置生成器产出，不依赖网络、真实账号或外部数据。

业务要求：
1. 实现令牌签发与刷新轮换核心：访问令牌与刷新令牌绑定租户、用户、令牌族标识、族内序号与过期时刻，载荷以本地 HMAC-SHA256 密钥做完整性签名；刷新时严格校验签名、过期与族内序号连续性，签名不符返回 E_TOKEN_INVALID，过期返回 E_TOKEN_EXPIRED，序号跳号返回 E_TOKEN_SEQUENCE。
2. 实现整族吊销与重放检测：已轮换失效的刷新令牌被再次使用时，撤销该令牌族全部成员并返回 E_TOKEN_REUSE，被单令牌吊销的令牌再使用时返回 E_TOKEN_REVOKED；吊销状态与族谱记录的写入须与刷新轮换处于同一 SQLite 事务，事务回滚时令牌与配额均回到提交前状态。
3. 实现整数定点配额扣减：每次刷新按租户单位成本以 int64 定点数（scale=1e9）累计扣减，乘加前必须检查溢出，溢出返回 E_QUOTA_OVERFLOW 且账本不被写入；截断误差逐次记入误差账本并可按租户聚合出有界误差上界，所有金额路径不得出现浮点类型。
4. 实现按租户规模自适应选择族谱查询路径：当租户族数低于阈值时逐族精算查询族内成员与吊销状态，高于阈值时先建族谱索引再做批量流式扫描；两条路径对同一输入必须产出逐字节一致的族成员结论、业务码序列与配额扣减量，阈值与所选路径须在输出中可观测并能通过参数覆盖。
5. 实现带版本号的令牌与配额快照：每次刷新、吊销或配额扣减成功后在单个事务内提交递增版本号快照并整体保留旧快照可回放；快照内容比较须识别整体替换式版本变化而非仅比对版本号，加载时校验版本链连续性，跳号返回 E_SNAPSHOT_VERSION 并回退到最近连续版本。
6. 实现并发刷新竞争与资源控制：同一刷新令牌的并发提交仅一个成功、其余返回 E_TOKEN_CONSUMED；同一租户的配额扣减串行化，在途事务数以可配置上限的信号量约束，超出等待阈值的请求返回 E_QUOTA_CONTENTION 而非无限阻塞，在途计数与排队时长须可观测。
7. 实现强制终止后恢复与异常注入：刷新或吊销过程中进程被强制终止后重启，依赖 SQLite 已提交事务恢复令牌状态、族谱与快照版本，已提交操作不回退、未提交整体丢弃且令牌仍可正常刷新，恢复后版本链跳号须以 E_SNAPSHOT_VERSION 拒绝；通过外部参数注入签名篡改、重放、配额溢出、快照跳号与并发竞争五类样本，均不得修改源码。
8. 提供可集成的 Go 包接口与完整示例：导出令牌签发、刷新、吊销、快照回放与报告导出接口供宿主服务接入，附带本地确定性样本生成入口（租户、用户、密钥与配额脚本）与一键运行命令；导出的 JSON 报告含令牌摘要、族谱轨迹、配额扣减与误差账本、业务码与快照版本链，重复运行且输入不变时报告字节级一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
