当前是空白工作区，需要在 Windows 本地从零构建一个面向单机测试环境的故障注入执行工作台。工作台以本地确定性样本维护一组受测端点（端点标识、所属节点、健康权重、依赖的上游端点集合）与一条注入计划（注入项含目标端点、故障类型如连接拒绝、连接超时、响应体错乱、持续轮次与优先级），按全局注入并发上限、每类故障的启用开关与每轮时间预算推进注入轮次，输出每轮端点观测结论、注入轨迹与预算消耗明细。故障必须通过本地 HTTP 测试端点真实建立与关闭连接体现，例如连接拒绝由未监听端口产生、连接超时由真实不响应的套接字产生，不得以固定休眠冒充超时。进程可能在注入轮次中途被强制终止，重启后必须依据 SQLite 中持久化的意图记录恢复到最后一致状态。所有输入来自本地固定样本，不依赖真实集群或外部网络。

任务环境与准备：
安装 Python 3.11 及以上，使用 venv 创建虚拟环境并安装 fastapi、uvicorn、pytest。
在空白工作区创建项目目录与 SQLite 数据文件路径，确认本地回环端口可绑定。
准备固定样本的端点清单 JSON 与注入计划 JSON，以及本地 HTTP 测试端点脚本，可产生成功响应、连接拒绝（未监听端口）与真实不响应套接字。

业务要求：
1. 实现端点清单与注入计划的解析和归一化：端点声明标识、所属节点、健康权重与上游依赖，注入项声明目标端点、故障类型、持续轮次与优先级；解析失败、引用未知端点或出现依赖环时返回业务码 E_PLAN_INVALID 且整批不加载；同一计划版本重复加载须识别版本单调并整体替换。
2. 实现故障类型生效判定：连接拒绝只能对未监听端口生效、连接超时必须对真实不响应端点生效、响应体错乱只能对返回可解析响应的端点生效；注入项与实际端点能力不匹配时返回 E_FAULT_UNSUPPORTED 并附不匹配原因，不得静默降级为其他故障类型。
3. 实现并行注入轮次调度，以全局注入并发上限与每轮时间预算双重约束执行：预算内按优先级与端点轮转取任务，超出并发上限者进入有界等待队列，队列满返回 E_INJECTION_QUEUE_FULL；同一端点在同一轮中不得被重复注入，同一轮次标识重复触发只执行一次、其余等待复用结果。
4. 实现真实可中断的注入执行：连接拒绝以对未监听端口的真实连接尝试为判定，连接超时以对真实不响应套接字的连接等待并在超时后关闭套接字为判定，响应体错乱以对真实返回体的解析失败为判定；超时后必须释放套接字资源并返回 E_INJECTION_TIMEOUT，不得以固定休眠冒充超时。
5. 实现端点观测结论与上游影响传播：每轮依据注入结果、端点原始健康权重与上游端点受影响情况给出每个端点的观测结论（NORMAL、UNSTABLE、UNREACHABLE），当某端点的上游存在 UNREACHABLE 时其结论须按依赖规则降级并输出传播依据；传播只处理已提交轮次的结论，不得使用未提交的中间观测。
6. 定义注入计划状态机，至少包含 PLANNED、RUNNING、PAUSED、COMPLETED、ABORTED 五种状态并规定合法迁移路径，非法迁移返回 E_INVALID_TRANSITION 且不修改已持久化状态；状态迁移与轮次结论、预算占用须在同一事务边界内共同生效，查询只能看到某一完整提交版本。
7. 实现预算耗尽时的确定性取舍：当注入项规模超出并发与时间预算可覆盖范围时，按优先级与端点轮转给出确定性跳过次序，输出预算消耗明细（本轮注入配额、时间预算余量）与被跳过项清单及原因；低预算下必须牺牲覆盖范围而非违反并发上限，跳过、超时与故障不支持三类结局在轨迹中须分别标注。
8. 使用 SQLite 持久化计划、注入步骤、预算占用与轮次结论，所有写操作先写意图记录再提交事务；进程在注入或结论传播中途被强制终止后重启须扫描未完成意图，把计划标记为已中止或将轮次回滚到最后一致版本并输出仅基于已持久化事实的恢复报告；提供本地 HTTP 接口与可重复演示脚本，覆盖正常轮次、故障不支持、真实超时、强制终止后恢复四类演练。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地测试端点验证注入调度、故障类型判定与观测结论，并验证强制终止后的恢复。
