当前为空工作区，需从零构建一个本地可运行的目标检测候选匹配与并行调度管线，交付数据处理管线与结果验证工具。输入为本地确定性 JSON 样本：每张图像含 image_id、宽高，以及真值框列表（类别、归一化 xywh）和候选框列表（类别得分、归一化 xywh、来源算子标签）；样本由本地生成器固定随机种子产出，不依赖任何真实数据集或预训练模型。管线需对每张图像按类别做 IoU 匹配，区分已匹配、重复候选与背景候选，并按候选来源算子统计质量；随后在总计算预算（最大候选评估次数）与每工作线程配额约束下并行调度分片，输出每张图像的匹配摘要与全局统计。结果验证工具需支持从持久化的分片结果重建全局统计，并识别输入样本版本变化导致的结果失效。

任务环境与准备：
安装 Python 3.10 或以上版本与 NumPy，确保标准库中的 threading、json、hashlib 可用，无需网络访问。
在空工作区创建项目目录，准备本地确定性样本生成脚本，使用固定随机种子产出图像真值框、候选框与来源算子标签，样本只写入本地文件。
确认 Windows 文件锁可通过内置文件打开独占方式实现，检查工作区具备可写权限以创建检查点与分片结果目录。
准备运行脚本与验证脚本入口说明，演示停止与恢复流程时使用进程内停止信号或独立进程注入方式，不依赖外部服务。

业务要求：
1. 实现按类别 IoU 匹配核心：对每张图像，逐个真值框在同类别候选中按 IoU 从高到低选择唯一匹配，IoU 采用归一化坐标换算为像素面积后计算，默认阈值 0.5 可配置；已匹配候选不得再分配给其他真值框，同分同 IoU 时按候选索引稳定决胜，输出匹配对、未匹配真值与重复候选列表。
2. 实现候选分类与来源算子质量统计：将未匹配候选按得分阈值划分为背景候选与低置信候选，按来源算子标签汇总命中数、误报数与平均 IoU，类别维度与算子维度均需出现在摘要中；当得分阈值或 IoU 阈值改变时，相同输入的统计结果必须确定性变化且可复现。
3. 实现预算约束下的分片调度：以图像为单位组成分片，总候选评估次数上限与单工作线程配额共同约束调度；调度器须在评估前按剩余预算决定是否接纳分片，超预算分片记录为未处理并给出原因，保证任何时刻累计评估次数不超过总预算且各线程配额不被突破。
4. 实现并行执行与确定性归约：使用本地线程池并行处理分片，匹配结果按 image_id 全局排序后再归约，使并行输出与单线程顺序执行逐字节一致；线程池不得以线程超时方式中断失控计算，异常须以结构化错误对象回传主调度器。
5. 实现分片结果的持久化与中断恢复：每个分片完成后以原子方式写入包含分片序号、输入样本版本指纹、阈值配置版本与结果摘要的记录；进程收到停止请求时完成当前不可拆分分片后退出，恢复时从最近一致记录继续，已发布分片不重算，最终全局统计与一次完整运行一致。
6. 实现版本变化检测与失效传播：当输入样本内容、IoU 阈值、得分阈值或预算配置变化时，通过版本指纹识别受影响分片并使其结果失效，未受影响分片继续复用；失效判断与重建后的统计须在查询接口中可观测，禁止用旧版本结果冒充新版本。
7. 实现并发发布保护与业务错误码：多工作进程对同一工作区发布分片结果时使用文件锁并比较分片序号，仅允许连续推进，落后或重复发布返回 E_STALE_CHECKPOINT，缺前置分片时返回 E_INVALID_STAGE，预算非法或阈值越界返回 E_INVALID_CONFIG，且错误须携带分片序号或字段名。
8. 提供结果验证工具与本地确定性演示：至少 4 张图像样本、含跨图像重复候选模式与至少 3 种来源算子，一次完整运行生成固定摘要；演示在分片间触发停止后恢复，并用注入的非法预算与越界阈值验证错误码，同时验证恢复后全局统计与完整运行逐字节一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证匹配统计、预算调度、停止恢复与错误码，并核对恢复结果与完整运行一致。
