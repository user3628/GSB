一间做本地推理工具的团队刚接下预算敏感的低精度量化算子需求，工作区里还没有任何实现，需要把量化算子库、分批执行状态机与结果验证工具从零写起。输入由程序内置固定种子生成器在本地产出：权重与激活张量分片（.json 描述形状、每通道缩放因子与数值），覆盖 8 位与 4 位、对称与非对称、逐张量与逐通道量化粒度，并含离群值、全零通道与含 NaN 的异常样本；另附算子清单声明每分片需执行的量化线性算子链、各层位宽与模式、期望输出形状与允许误差区间。算子库须实现量化-反量化与量化域线性算子核心，把每个分片的执行建模为标定、前向、反量化、验证四阶段状态演进，逐分片以事务落盘状态并支持强制终止后恢复。核心冲突在于：状态演进要求分片按单调序号推进且中断后可从最近提交处续跑，而量化误差会沿算子链放大，验证阶段的误差报告又必须与分片执行顺序和是否经过恢复完全无关。

任务环境与准备：
安装 Go 1.22 或更高版本，确认 go 命令在 PATH 中可用。
在 Windows 空白目录创建工作区并初始化 Go module，引入 SQLite 驱动（如 modernc.org/sqlite 纯 Go 实现），不引入容器或外部服务。
所有样本与算子清单由程序内置固定种子生成器产出，或在工作区内按题面描述本地生成，不依赖下载数据集或网络。
运行前确认工作区可写，用于存放 SQLite 数据库文件与结果摘要文件。

业务要求：
1. 实现量化-反量化与量化域线性算子核心：按配置位宽（8 位或 4 位）、对称或非对称模式与逐通道或逐张量粒度计算缩放因子与零点，越界值钳制并记录钳制次数与位置；量化域矩阵乘须按缩放因子链正确还原，对含离群值、全零通道与显式零值样本给出确定性结果。
2. 实现四阶段状态演进模型：每个分片按标定、前向、反量化、验证顺序推进，状态记录含阶段名、分片标识、输入内容指纹、算子配置版本与单调序号；非法阶段跳转、缺失前置阶段产物或重复进入已完成阶段须返回带分片标识与当前阶段的稳定业务码。
3. 实现 SQLite 事务化状态持久化与强制终止恢复：每阶段完成时以事务写入状态记录，同一分片同一阶段只允许一条有效记录；进程被强制终止后重启仅凭已提交事实重建分片进度，不承诺生成退出报告，恢复后产物须与一次连续运行逐字节一致。
4. 实现快照整体替换识别与版本失效传播：当分片张量内容、位宽、量化模式、量化粒度、算子链或验证容差任一变化时，通过各阶段内容摘要构成的版本指纹识别受影响的最早阶段，使该阶段及其全部下游状态失效并重建；检测到状态表被整体替换（序号回退、指纹变化或摘要不匹配）时须区分正常推进、整体替换与回退，回退拒绝并返回 E_STALE_CHECKPOINT。
5. 实现精度自校验与误差传播诊断：对每层输出与本地高精度参考实现按显式抽样位置比对，计算量化误差与相对误差上界估计，输出逐层误差贡献与最接近容差的层余量；误差超出可配置容差时返回带分片标识、层名与最大偏差的业务码 E_NUMERIC_MISMATCH 并保留诊断上下文。
6. 实现并发阶段发布保护与稳定业务错误码：多个工作进程对同一数据库发布阶段状态时使用 SQLite 事务条件更新与真实文件锁并比较分片内序号，仅允许序号连续推进，落后、重复或跨分片错位发布返回 E_STALE_CHECKPOINT；超预算与数值异常分别返回 E_BUDGET_EXCEEDED 与 E_NUMERIC_MISMATCH。
7. 实现预算约束下的分批执行调度：以分片为调度单元，在总计算元素预算、单工作进程元素配额与峰值内存上限共同约束下决定接纳顺序与并发度；接纳前依据算子清单与形状声明预估元素消耗与工作集，超预算分片记录为未处理并给出预估值与预算余量，且调度决策不依赖并发时序。
8. 提供可集成算子库接口与结果验证工具：以库函数与命令行提供量化算子调用、分片状态与版本指纹查询、误差诊断报告、检查点恢复与整体替换识别；演示数据覆盖 8 位与 4 位、对称与非对称、逐通道与逐张量、离群值与全零通道，并可对同一配置重复运行比对摘要。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证量化算子、四阶段状态演进、强制终止恢复与误差诊断，并给出恢复前后结果逐字节一致报告。
