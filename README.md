当前是空白工作区，需要在 Windows 本地从零构建一个面向服务网格流量治理的策略仿真编排工作台。工作台接收带版本号的治理策略快照（虚拟服务路由规则、目标规则中的限流阈值、超时参数与熔断窗口），据此为一个给定的离线请求轨迹样本计算每条请求应命中的路由、生效的限流与熔断裁决以及最终响应结果，再把仿真过程中识别出的治理差异（如某路由限流过严、熔断窗口与超时参数冲突）整理成带优先级的差异工单。核心业务问题不是下发并行任务，而是仿真裁决与策略版本一致性：同一轨迹在不同策略版本与不同参数组合下的裁决结果必须可复现、可解释，差异工单必须指向具体路由、具体裁决项与触发条件。所有数据来自本地确定性轨迹样本与本地 SQLite 持久化，不依赖真实服务网格控制面。

任务环境与准备：
安装 Python 3.11 或更高版本，并确认 python 与 pip 在 PowerShell 中可用。
在空白工作区创建项目目录，使用虚拟环境安装 fastapi、uvicorn、httpx 与 pytest，并记录版本。
准备固定本地轨迹样本：包含请求时间戳（整数毫秒）、路由匹配所需请求头与路径、上游响应状态与耗时，以及两份带版本号的治理策略快照 JSON，放入项目本地样本目录。
准备本地 HTTP 测试端点脚本，仅绑定 127.0.0.1 回环地址，用于演示超时与连接失败处置。
确认 SQLite 由 Python 标准库提供，数据库文件放在项目目录内，无需外部数据库服务。

业务要求：
1. 实现治理策略快照模型与版本识别：快照包含版本号、生成时间、虚拟服务路由匹配规则、目标规则中的限流阈值、超时参数与熔断窗口，以及整体校验摘要；提交时若版本号不大于当前已提交版本则返回 E_STALE_SNAPSHOT 且不改变任何状态，校验摘要不符返回 E_SNAPSHOT_INVALID，加载与替换必须整体生效，禁止新旧版本字段混用。
2. 实现离线轨迹仿真裁决引擎：对轨迹样本中每条请求按虚拟服务路由规则匹配出唯一路由，若匹配到多条须按确定性优先级规则裁决，无匹配时记为该请求命中默认路由；再依据目标规则的限流阈值、超时参数与熔断窗口计算裁决结果，裁决结果必须包含命中路由、裁决类型与触发参数。
3. 实现限流与熔断的时间语义：限流按固定窗口与窗口边界对齐统计窗口内请求数，熔断按连续失败次数与熔断窗口时长判定状态切换；同一轨迹重新仿真必须逐条得到相同裁决，窗口边界包含关系与时间戳精度须明确定义，禁止因浮点时间比较或窗口对齐差异导致裁决翻转。
4. 实现超时与熔断的冲突识别：当某路由的超时参数大于其熔断窗口可容忍的上游响应时长时，须在仿真结果中标记该路由存在参数冲突并给出冲突双方的具体数值；冲突标记不得直接篡改裁决结果，只作为差异项输出，且同一轨迹在多版本快照上的冲突集合须可按路由逐项比较。
5. 实现差异工单生成与优先级：把仿真中识别出的治理差异（限流造成的高比例拒绝、熔断频繁切换、超时与熔断窗口冲突、路由匹配歧义）整理为工单，每张工单须携带路由标识、差异类型、触发条件与量化指标；工单优先级依据受影响请求数占比与差异类型权重做确定性计算，同优先级按稳定次序排列，禁止重复生成同一路由同一差异类型的工单。
6. 使用 SQLite 持久化快照版本、仿真批次与裁决明细，写操作先写意图记录再提交事务；进程在仿真批次中途被强制终止后重启须扫描未完成意图，将批次标记为已中止并基于已持久化事实输出恢复报告，不得承诺强制终止后仍能生成完整退出报告；查询只能看到某一完整提交版本的仿真结论。
7. 实现统一业务错误码与 JSON 错误体，至少覆盖 E_STALE_SNAPSHOT、E_SNAPSHOT_INVALID、E_BATCH_NOT_FOUND、E_ORDER_NOT_FOUND、E_ROUTE_AMBIGUOUS、E_INVALID_ARGUMENT；定义仿真批次在 PENDING、RUNNING、COMPLETED、ABORTED 间的合法迁移路径，非法迁移返回 E_INVALID_ARGUMENT 且不得修改状态。
8. 提供本地 HTTP API 与可重复演示脚本：API 覆盖策略快照提交、轨迹仿真提交、按批次查询裁决明细与差异工单、恢复报告查询，统一错误响应为含业务码的 JSON；脚本使用固定本地轨迹样本与两份策略快照完成一次全量仿真、一次含冲突参数快照的仿真、一次路由歧义处置与一次强制终止后恢复，输出各批次裁决统计、差异工单清单与恢复报告。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地轨迹在同一策略版本下重复仿真，核对裁决逐条一致、差异工单可追溯及强制终止后恢复事实。
