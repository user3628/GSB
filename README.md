当前是空白工作区，没有现存项目、代码或数据附件，需要从零实现一个面向本地配置中心场景的热更新组件，复现真实配置中心在格式互操作与版本兼容上的核心机制。组件以配置项（命名空间、键路径、值、值类型、来源格式、修订号）为单位管理配置，既接收旧版行式文本配置（v1 格式：每行键路径等号值，支持反斜杠转义）也接收新版自描述 JSON 配置（v2 格式：带 schema 版本、逐键类型声明、键值映射与整体校验和），并把二者归一化为同一配置视图对外提供查询。客户端以长轮询方式等待配置变更，组件变更后须触发原子热更新：正在读取配置的调用方要么看到完整旧版本，要么看到完整新版本，不能出现半更新状态。组件维护配置修订号链、变更事件与发布影响范围，通过 SQLite 持久化版本状态以支持进程重启后的恢复。v1 与 v2 在值类型、键转义、默认值与校验和上的差异必须被显式处理，不能静默丢弃字段或改变可见语义。

任务环境与准备：
安装 Python 3.11 及以上版本，确保 python 与 pip 可在 PowerShell 或命令提示符中直接调用。
使用 pip 安装 pytest 与 requests；标准库已包含 sqlite3、http.server 与 hashlib，无需额外依赖。
在空工作区创建项目目录与本地样本目录，样本配置、固定随机种子与期望视图均为本地文件，不访问外网。
运行前确认无占用端口的本地服务；测试与示例全部离线执行，仅使用本地回环地址与本地 SQLite 文件。

业务要求：
1. 实现 v1 行式文本与 v2 自描述 JSON 的编解码与格式校验：v1 每行以首个等号分键值并支持反斜杠转义，v2 须含 schema 版本、类型声明、键值映射与校验和。解码须拒绝重复键、非法转义、校验和不符与不支持的 schema 版本，并分别返回互不重叠的固定业务码，不得只报通用解析错误。
2. 实现两版本配置归一化到统一配置视图：v1 值按声明的默认类型推断，v2 显式类型优先；同键同值不同来源版本须在视图中标记来源格式与修订号。归一化后两种格式表达的等价配置须产生逐字段相同的视图，视图 JSON 字段顺序与数值格式须固定，便于调用方做稳定比较。
3. 实现配置修订号链与热更新原子发布：每次变更生成严格递增修订号并绑定变更摘要、变更键集合与有效视图摘要；发布须先完成视图构建与摘要校验再原子切换，任何构建失败或校验失败须回退到上一修订，已发布的修订不得被原地修改，旧修订须保留可查询。
4. 实现长轮询等待与变更唤醒语义：客户端以当前修订号发起长轮询，若已有更新须立即返回最新修订；否则须在真实单调时钟超时内挂起并在发布后唤醒。多客户端并发等待同一命名空间时须全部被唤醒且各返回一致的修订号，超时返回须带明确业务码而不是误报变更。
5. 实现并发读取与发布的快照隔离：读取方在单次调用内须绑定发布时的完整视图快照，发布过程中不得观察到半更新状态；同一命名空间内发布串行化，不同命名空间可并行推进。并发抢占须有真实超时并以业务码报告争用，不得用固定延迟模拟互斥。
6. 实现格式迁移与跨版本回退：提供把 v1 命名空间迁移为 v2 的接口，迁移须先构建并校验新视图再原子替换，替换前旧视图保持可读；迁移中断后重启须依据持久化迁移标记识别未完成迁移并回滚到迁移前视图，迁移前后等价键的可见值不得改变。
7. 实现 SQLite 持久化与进程重启恢复：修订链、有效视图、跨格式来源记录、长轮询等待状态与迁移标记须在发布提交点以单事务写入，提交后才对查询可见；重启后须从最后完整修订继续服务，中断时处于发布中的修订须判定为未发布并回退，恢复后视图与重启前一致。
8. 实现本地 HTTP 接口与可重复测试：通过本地 HTTP 提供提交 v1 或 v2 配置、查询当前视图与修订、发起长轮询、触发迁移、查询变更事件的接口，错误统一以固定业务码在 JSON 中返回；测试须使用固定随机种子的本地样本覆盖跨格式等价、校验失败拒绝、并发长轮询唤醒、迁移中断恢复与重启恢复，全部在 Windows 离线运行。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
