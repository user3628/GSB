当前只有一台干净的开发机，需要从零构建一个面向本地单机推理服务的批处理调度与一致性诊断工作台，供推理平台工程师离线评估批次组织、交互延迟与计算结果一致性。工作台以本地确定性 JSON 样本提供模型清单（模型标识、单样本显存字节、单样本计算代价微秒、单批最大样本数）与请求轨迹（到达毫秒时间戳、模型标识、样本数、期望批延迟上限、优先级）；调度器按批样本数上限与节点剩余显存组织批次，依据单样本代价估计批延迟，并对每批计算 P50/P95/P99 估计延迟与显存占用。工程人员会通过请求参数对调度过程注入异常（迟到到达、批超限、显存不足、重复提交、执行中途中断），并在一次强制终止后要求依据持久化事实恢复批次状态。难点在于交互延迟与计算结果一致性相互牵制：迟到请求若被并入已确认批次会改变已发布延迟结论，若一律拒绝又会与显存余量冲突；快速模式与完整模式、不同批组织顺序、中断前后重新组织，都必须对同一轨迹给出可核对的批次与分位结论。全部依赖本地确定样本与本地测试服务，不得依赖真实模型或加速器。

任务环境与准备：
安装 Go 1.22 或以上并确认 go version 可用；无第三方依赖，使用标准库 net/http、database/sql 与任务声明的纯 Go SQLite 驱动版本安装。
确认 Windows 本地回环可用并允许绑定 127.0.0.1 的高位端口；准备固定随机种子生成的模型清单与请求轨迹 JSON 样本，以及用于演示脚本的本地测试端点。
在项目目录执行 go mod init 与 go build 确认可编译，按题目给出命令启动本地 HTTP 服务并用演示脚本完成提交、组织、查询与恢复演练。

业务要求：
1. 实现模型清单与请求轨迹的解析与归一化：显存以字节整数、代价以微秒整数为内部表示，解析样本中形如 512Mi、2Gi、1500us、3ms 的量纲字符串并做溢出与负数检查；解析失败、模型标识未知或到达时间戳非单调的记录须整批不生效并返回含业务码的 JSON 错误体，业务码至少含 E_SPEC_INVALID 与 E_TRACE_INVALID，不得部分入库。
2. 实现批次组织：按模型标识与到达顺序把请求装入批，批的合计显存为各请求样本数乘单样本显存之和，不得超过节点剩余显存与模型单批最大样本数，超出时按确定规则拆分为多批；不同优先级的请求不得混入同一批，拆分产生的子批须保留原子批序号与可追溯的拆分依据。
3. 实现批延迟估计与分位计算：每批延迟由各请求样本数乘单样本代价累加得到，累加使用补偿求和，P50/P95/P99 采用声明的确定性最近秩法并注明样本规模；样本数不足以计算所请求分位时返回业务码 E_INSUFFICIENT_SAMPLES 而非静默补零，同一轨迹重复组织与重算必须逐位一致。
4. 实现定点数值契约：显存与延迟的中间累计一律使用整数或显式定点表示，延迟换算为毫秒时按声明舍入方式处理并输出每批的舍入位与累计舍入误差；与由单样本显存和代价直接乘加得出的真值逐批输出绝对偏差与相对偏差，任一指标越过声明上界时整批标记为校验失败并返回业务码 E_PRECISION_BREACH。
5. 实现交互延迟约束下的两种组织模式：低延迟模式按配置的组织预算提前封批并输出被推迟请求数、模式标记与推迟原因，完整模式使用全部可容纳请求；两种模式对同一轨迹版本的结果差异须逐批可核对，低延迟模式不得把超出期望批延迟上限的批标记为通过，也不得在未声明时改动已封批内容。
6. 实现显存碎片与批延迟上限的取舍：某请求可与其他模型请求共处同一显存区域但会使批延迟超过期望上限时须拒绝混批并给出原因；碎片导致批无法装入时按确定规则尝试重组或降批样本数，降批后各请求的样本数必须重新分配且总量守恒，无法容纳的请求返回 E_INSUFFICIENT_CAPACITY 并保留原批不变。
7. 使用 SQLite 持久化轨迹批次、批次组成、分位结果与意图日志，所有写操作先落意图记录再提交事务；进程在批次组织或分位计算中途被强制终止后重启须扫描未完成意图，把批次标记为已中止或回滚到最后一次完整提交的批次边界，恢复报告只包含已持久化事实，不承诺强制终止后仍生成完成结论。
8. 提供本地 HTTP 接口与诊断页面：接口覆盖轨迹提交、批次组织触发、按批次查询分位延迟与显存预算明细、误差说明查询、真值核对结论查询与恢复报告查询，失败响应统一为含业务码与上下文的 JSON（至少覆盖 E_SPEC_INVALID、E_TRACE_INVALID、E_INSUFFICIENT_SAMPLES、E_PRECISION_BREACH、E_INSUFFICIENT_CAPACITY、E_CONFLICTING_REQUEST）；诊断页面以本地静态资源展示批次组成、分位与误差明细，并提供可重复演示脚本。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定本地样本验证两种组织模式的分位与误差可核对、异常业务码互异、强制终止后可依持久化事实恢复批次状态。
