当前是空白工作区，需从零构建一个本地可运行的文生视频与图生视频分镜时间轴合成管线，交付数据处理管线与结果验证工具。输入为固定随机种子生成器产出的本地确定性样本：一组分镜图像（小尺寸 PNG）与一份 JSONL 分镜脚本，每条含 shot_id、图像文件名、提示词（中英混排）、运镜类型（静止/平移/缩放）、持续帧数、帧率与转场类型（硬切/交叉淡化）；帧内容由图像像素按可配置运动轨迹确定性合成，不依赖任何真实生成模型、GPU 或外部服务。管线需按四个阶段执行：帧调度（依据帧率与持续帧数把每个分镜展开为全局帧时间轴并对齐各镜头边界）、帧合成（按运镜类型生成逐帧变换与采样）、转场混合（在镜头交界处按转场类型混合相邻帧）、编码封装（量化为帧序列并写出清单与逐帧摘要）。核心难点在于样本规模从数个分镜变化到数十个分镜时，时间轴对齐精度、帧缓存占用与合成算法取舍之间必须协同设计，并通过版本指纹与检查点保证中断恢复后结果一致。

任务环境与准备：
安装 Python 3.10 及以上版本，并通过 pip 安装 numpy 与 Pillow。
准备本地工作区目录，不需要网络、GPU、真实视频素材或任何外部服务。
任务执行前运行本地生成器脚本产出两个规模档的分镜图像、JSONL 脚本与配置，确认样本摘要稳定可重建。

业务要求：
1. 实现全局帧调度阶段：依据每个分镜的帧率与持续帧数把分镜展开为以毫秒为精度的全局帧时间轴，处理非整数毫秒与不同帧率混排造成的累积误差，帧数为零或帧率为负须返回 E_INVALID_TIMELINE 并附 shot_id；同一脚本与配置下帧时间轴必须逐字段确定。
2. 实现运镜帧合成核心：对静止、平移与缩放三类运镜按可配置轨迹在浮点域生成逐帧变换矩阵并做双线性采样，边界采样坐标须按图像范围裁剪，同一输入与配置产生逐像素一致输出，禁止使用任何真实模型或外部图像服务。
3. 实现转场混合与帧序列封装：硬切不做混合，交叉淡化按镜头交界处可配置帧窗口做加权融合，权重全程在浮点域计算并按 8 位量化做越界钳制；输出帧序列清单须含每帧全局帧号、来源镜头、转场归属与像素摘要。
4. 实现基于数据规模的算法取舍：依据分镜数、总帧数、图像尺寸与可配置内存预算，为帧调度与合成在逐帧重算、全量缓存与按段缓存三种策略中选择一种，并记录选择理由、候选打分明细与被淘汰原因；小规模须避免不必要的全量缓存，大规模须保证峰值帧缓冲不超预算。
5. 实现指定规模的确定性演示与结果验证工具：提供本地生成器产出至少两个规模档（数个分镜与数十个分镜）的样本与脚本，一次完整运行生成固定摘要；验证工具须能对比不同规模下的帧时间轴与输出帧摘要，并统计各运镜与转场类型的帧数分配。
6. 实现版本指纹与增量失效传播：当分镜图像内容、提示词、运镜类型、帧率、持续帧数、转场参数或缓存预算任一变化时，通过各阶段内容摘要构成的版本指纹识别受影响的最早阶段，使该阶段及其全部下游产物失效并重建；未受影响上游产物继续复用，失效原因与指纹须在查询接口中可观测。
7. 实现阶段检查点、优雅停止与并发发布保护：每阶段完成时以原子方式写入含阶段名、输入指纹、配置版本、产物摘要与单调序号的记录，写入任意位置中断不得留下半写记录；收到停止请求时完成当前不可拆分镜头单元后退出，恢复后最终输出与从零完整运行逐字节一致；多工作进程发布时使用文件锁并比较序号，落后或重复发布返回 E_STALE_CHECKPOINT，部署阶段顺序被违反时返回 E_INVALID_STAGE。
8. 实现业务错误码一致的异常链路与交互接口：提供命令行与本地 HTTP 接口，支持导入样本与脚本、查询各阶段状态与版本指纹、请求停止与恢复、导出帧序列清单；对非法运镜类型、缺失图像文件、转场窗口超过镜头帧数、时间轴为负等异常须在对应阶段返回 E_INVALID_SHOT、E_MISSING_ASSET、E_TRANSITION_OVERFLOW 等稳定业务码，且不得部分写入产物。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地两档规模样本验证时间轴对齐、运镜合成、增量失效与中断恢复结果一致，并核对错误码。
