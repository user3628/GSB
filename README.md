交付从新建的代码库开始，需要从零构建一个面向单机混合精度训练的分级检查点存储与显存预算调度引擎，供训练编排器集成。训练以若干轮次推进，每轮产生按参数分片组织的权重副本：一部分分片以 FP16 形式保存在高速显存池中，另一部分以 FP32 主参数形式保存在低速持久池中，另含优化器动量与损失缩放系数。训练编排器通过本地 HTTP 接口提交带版本号的精度策略快照（哪些分片驻留显存池、哪些落持久池、损失缩放初始值与增长因子、显存池字节上限与每轮写盘字节预算），并以只含受影响分片的增量片段提交检查点。引擎需在显存池容量上限、写盘字节预算与每轮时间预算多重约束下，决定分片的驻留与驱逐、完成检查点的分级写入，并维护分片摘要、精度标记与参数一致性校验等派生结构。真实场景中分片规模从数十到数千、单分片字节量跨越多个数量级，进程可能在写盘或驱逐中途被强制终止，重启后必须依据持久化事实恢复显存池视图与检查点一致性。所有样本与 HTTP 测试端点均为本地确定性资源，运行于 Windows，不依赖 GPU 或外部数据集。

任务环境与准备：
安装 Go 1.22 或更高版本，确认 go version 可执行，所有依赖通过 go mod 在本地获取或使用标准库与 SQLite 驱动。
准备本地确定性样本：包含若干轮次的分片清单（精度标记、字节大小、摘要）、精度策略快照与增量片段，样本文件随代码库提交，不依赖外部数据集或 GPU。
准备 SQLite 驱动（如 modernc.org/sqlite）并固定版本，数据库文件位于本地工作目录。
准备本地 HTTP 服务端口配置与测试脚本，所有操作在 Windows 命令行或 PowerShell 下可执行。

业务要求：
1. 实现分片、显存池与持久池的存储模型：每个分片记录标识、轮次、精度标记（FP16 或 FP32）、字节大小、内容摘要、所在池与最近访问时刻，FP32 主参数分片须与对应 FP16 分片的摘要满足声明的还原关系；提交检查点时校验分片字节为非负整数、精度标记在允许集合内、分片标识在轮次内唯一，校验失败返回业务码 E_SHARD_INVALID 且整批不落库；同一分片内容重复提交须按摘要幂等，摘要不一致返回 E_SHARD_MISMATCH。
2. 实现显存池驻留与驱逐裁决：显存池内分片总字节不得超过策略声明的显存池字节上限，新分片驻留前须按最近访问时刻与精度标记计算可驱逐候选并真实驱逐，驱逐后该分片回落到持久池并把状态迁移为 PERSISTED；无法在驱逐后腾出足够空间时返回 E_POOL_EXHAUSTED 并附需要字节数与可腾出字节数；同一分片不得同时出现在两个池中，池占用合计必须与分片所在池精确对应。
3. 实现混合精度数值契约与还原校验：由 FP16 副本与损失缩放系数还原参数量时须显式声明舍入方式并使用定点或整数表示，输出每个分片的还原偏差与累计舍入误差，并与 FP32 主参数逐元素比较给出最大绝对与相对偏差；偏差越过策略声明上界时该分片参数一致性校验失败并返回 E_PRECISION_DRIFT，禁止把浮点累计误差静默舍入为通过；同一检查点重复校验必须逐位一致。
4. 实现带版本号的精度策略快照与增量片段提交：快照携带单调递增版本号、生成时间、显存池上限、每轮写盘字节预算与整体校验摘要，提交时版本号不大于当前已提交版本则返回 E_STALE_SNAPSHOT；增量片段只含受影响的参数分片与损失缩放字段并携带基础版本，基础版本非当前版本时返回 E_STALE_BASE 且不改变任何已提交状态；同一基础版本的两个并发增量只允许一个成功。
5. 实现派生结构的依赖失效与级联原子重建：为每个分片维护其对主参数派生摘要、参数一致性校验结果、显存占用估算与恢复基线的引用关系；当某分片精度标记、主参数摘要、动量摘要或损失缩放参数变化时，该分片全部派生结构及依赖它的轮次级一致性结论必须级联失效并在同一事务边界内原子重建，禁止出现分片已换精度而一致性结论仍指向旧摘要的中间可见状态。
6. 实现写盘字节预算与每轮时间预算的调度取舍：检查点分级写入受每轮写盘字节预算与每轮时间预算共同约束，预算内按分片优先级与轮次顺序取任务，超出预算的分片进入有界等待队列，队列满返回 E_WRITE_QUEUE_FULL；预算不足时按确定规则决定先写 FP32 主参数还是先写 FP16 副本并输出选择依据；预算耗尽被推迟的分片须保持 PENDING 并在报告中列明，不得以跳过分片冒充检查点完成。
7. 使用 SQLite 持久化分片、池视图、写盘记录、派生结构与意图日志，所有写操作先落意图记录再提交事务；进程在写盘或驱逐中途被强制终止后重启须扫描未完成意图，把未提交分片回滚为 PENDING、把未提交驱逐回滚为驻留状态，并依据已落盘分片摘要重建显存池视图与检查点一致性；恢复报告只能基于已落盘事实，不得声称对已被强制终止的在途写入生成退出报告。
8. 实现单写者提交与多读者查询的并发一致及幂等：检查点提交、驱逐与派生重建按提交单写者串行执行，多个只读查询（分片清单、池占用、精度偏差、恢复报告）可并发读取某一完整提交版本；同一提交标识重复提交只执行一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_SUBMIT；查询不得看到分片已标记写入完成而写盘记录未提交、或分片已驱逐而池占用未释放。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
