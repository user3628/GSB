当前是空白工作区，需要从零实现一个面向本地列式数据处理的向量化执行服务，用于在离线环境下复现真实计算引擎在“批式执行 + 状态演进 + 中断续算”上的核心机制。服务接收查询描述（至少三张本地列式数据表、等值连接条件、过滤谓词、分组聚合键与排序键），以列存 NumPy 数组为数据单元，按配置的向量批量推进扫描、过滤、哈希连接、聚合与结果输出阶段。每个批次完成后须把阶段状态、批次进度、已产出的完整结果集批次与中间哈希表摘要持久化到 SQLite，客户端可通过游标按批取回结果，也可在任意时刻中断、重启服务后从已提交批次继续推进，且续算结果必须与一次性完整执行逐值一致。真实引擎的难点不在单批计算，而在批次边界的状态归属：哪些中间聚合状态可以跨批合并、哪些哈希表分区必须在所有探测批次完成前保持可读、进程中断后未提交批次如何丢弃而不得污染已提交结果，以及并发查询共享同一数据快照时批量额度的争用。

任务环境与准备：
安装 Python 3.11 及 pip，创建本地虚拟环境。
安装 numpy、fastapi、uvicorn、pytest、httpx，版本锁定在 requirements.txt 中，全部为纯本地依赖。
无需外网、数据库服务或 GPU，SQLite 使用 Python 标准库内置模块。
运行前在工作区创建数据目录与临时目录，测试通过 pytest 在 Windows 命令行离线执行。

业务要求：
1. 实现列式数据表与查询描述的载入与校验：每张表以列名到 NumPy 数组的映射及元数据（行数、列类型、列基数）描述，查询包含过滤谓词列表、等值连接条件、分组键、聚合函数（求和、计数、最小值、最大值）、排序键与向量批量大小。校验须拒绝列不存在、类型不可比、聚合函数不支持和批量大小非正数，并返回固定业务码 E_BAD_QUERY；校验失败不得产生任何持久化状态。
2. 实现按批推进的分阶段执行器：扫描、过滤、哈希连接、聚合、排序输出须为分离阶段，每个阶段以配置的向量批量推进且单批内不得退化为逐行 Python 对象处理。执行器须对外暴露“推进一批并返回是否仍有后续”的接口，每批产出的完整结果行集合作为一个结果批次，批次序号严格递增且与推进次数对应，部分批次不得对外可见。
3. 实现基于 SQLite 的批次提交与进度持久化：每完成一批须在单个事务中写入批次进度、该批结果行、当前阶段标识、已完成阶段的中间摘要（哈希表行数与分组状态摘要）与递增批次序号，事务提交后才允许游标读取该批。事务失败须整体回滚且不改变已有进度；同一查询重复推进不得产生重复批次或跳号。
4. 实现中断与重启后的断点续算：服务启动时须扫描未完成的查询会话，丢弃未提交批次并恢复到最后一个已提交批次之后的确定性位置重新推进；续算必须复用已持久化的阶段中间摘要而非从头全量重算已完成阶段，且续算产出的全部批次与一次性完整执行的结果在规范化序列化后逐值一致。已完成会话不得被重启逻辑改写。
5. 实现聚合中间状态跨批合并的正确性边界：分组聚合须在批间使用可合并的中间状态（计数、求和、极值），合并结果须与全量一次性聚合逐值相等；对排序键相同的分组输出须按分组键的确定性次序归一化。当连接阶段因批边界而需要保留多个哈希分区时，须保证任一探测批看到的构建侧分区集合完整，缺失分区须以错误码 E_PARTITION_MISSING 拒绝该批而不得静默输出不完整结果。
6. 实现并发查询的会话隔离与批量额度控制：多个查询会话可并发推进，每个会话在开始时固定所读表的元数据版本与数据版本，中途版本变化须以 E_SNAPSHOT_STALE 终止该会话并保留已提交批次；所有会话共享配置的每轮总处理行数额度，额度耗尽时未推进的会话须按到达顺序排队而非丢弃，排队与推进须使用真实单调时钟的超时判定。
7. 实现游标读取、会话终止与结果摘要校验：客户端可创建游标按顺序读取已提交批次，游标位置须持久化以支持重启后继续读取，重复读取同一位置须返回相同内容；客户端可主动终止会话，终止须原子地把会话置为 aborted 并释放其额度占用，已提交批次保留可读但后续推进返回 E_SESSION_ABORTED。会话全部批次读完时须给出按排序键逐值哈希计算的确定性结果摘要。
8. 提供本地 HTTP 接口、确定性样本与可重复测试：通过本地 HTTP 提供提交查询、推进一批、查询会话状态与批次清单、创建并推进游标、终止会话的接口，错误统一以固定业务码在 JSON 中返回。内置固定随机种子的数据表生成器产出至少三表、每表万行级、含倾斜连接键与空值的数据，并提供 pytest 用例覆盖完整执行与续算一致、乱序重复推进去重、分区缺失拒绝、快照失效、额度排队、会话终止与游标重启续读，全部在 Windows 上离线运行。
