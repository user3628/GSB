当前是空白工作区，需要从零实现一个面向本地容量评估与压测的「吞吐误差传播诊断工作台」。工作台管理本地压测场景：每个场景由若干阶段组成（预热、爬坡、稳态、过载回收），每阶段声明并发数、请求速率、持续时长与样本采集间隔；本地确定性负载发生器按阶段产出请求记录（客户端时间戳、服务端时间戳、结果类别、延迟毫秒、重试序号），工作台据此计算各阶段吞吐、延迟分位与容量裕度，并换算到目标窗口的容量结论。真实压测中采样间隔与阶段时长不整除、客户端与服务端时钟存在偏移、重试放大有效请求数、分阶段速率单位换算（每秒/每分钟）都会使吞吐结论随误差传播漂移，工作台必须在数值精度、采样规模与结论稳定性之间做明确取舍，并向运维给出可解释的误差上界。

任务环境与准备：
安装 Python 3.11 及以上，并在任务目录创建虚拟环境，确保 pip 可离线或联网安装依赖。
安装 NumPy、pytest 与 requests（用于本地 HTTP 接口测试），版本以能支持当前 Python 版本为准。
准备本地样本目录，放置压测场景 JSON 与固定随机种子配置，不依赖任何外部服务、真实账号或网络端点。
确认 Windows 上本地回环端口可监听并可发起 HTTP 请求，测试全程离线运行。

业务要求：
1. 实现压测场景与阶段声明模型及校验：场景含场景标识、目标服务、阶段列表与采样间隔；阶段含阶段名、并发数、请求速率（须声明单位每秒或每分钟）、持续时长与结果类别分布参数。校验须拒绝非正数并发与时长、速率单位缺失、阶段时长为零或阶段名重复，非法输入返回业务码 E_BAD_SCENARIO 且不得进入后续计算与持久化。
2. 实现本地确定性负载发生器：按固定随机种子与阶段参数产出请求记录，记录含客户端时间戳、服务端时间戳、结果类别、延迟毫秒与重试序号；产出的记录序列必须可重复，同一场景与种子两次生成逐条一致。发生器须模拟客户端与服务端时钟偏移（含正负偏移），该偏移由场景参数注入并作为独立同步标记保存，不得从记录中反推。
3. 实现采样窗口与阶段边界的对齐计算：按采样间隔切分每个阶段并处理时长不被间隔整除的尾窗，尾窗须以显式标记区分并参与统计但不被丢弃；窗口归属以服务端时间戳为准并记录用于对齐的同步标记来源。窗口边界与阶段边界的换算须以整数毫秒进行，避免浮点累加漂移。
4. 实现吞吐与延迟统计及单位换算：按阶段与窗口计算有效请求数、成功占比与延迟分位（至少 p50、p95、p99），重试记录须按有效请求口径去重计入而非简单累加；每秒与每分钟速率单位换算须在输出中显式标注原始单位与换算后数值，换算前后同一窗口的吞吐必须可互相校验。
5. 实现误差传播与容量结论：对每个阶段给出吞吐结论及其误差上界，上界须综合采样间隔相对阶段时长的离散误差、时钟偏移对窗口归属的影响与重试放大比例，并以十进制定点字符串输出分解项与合成值。容量裕度须按目标速率与估算吞吐之差计算，差值小于误差上界时必须标记为不确定而非给出确定结论。
6. 实现容量结论稳定化的算法取舍：为降低小采样规模导致的结论抖动，须提供按窗口数合并的最少窗口数配置，并允许在阶段内样本不足时回退到使用更长窗口或标记为证据不足；合并与回退决策须写入诊断报告，且同一输入下专家与普通两种配置的结论差异必须可解释为合并窗口数与误差上界变化。
7. 实现 SQLite 持久化与重启恢复：场景定义、阶段状态、窗口统计摘要、误差上界与容量结论须在阶段完成时以单事务写入；重启后须从最后完成的阶段继续，中断阶段标记为中止并可从已持久化窗口重新计算，恢复后对同一场景与种子的结论必须与中断前已完成部分逐字段一致。
8. 实现本地 HTTP 接口、诊断报告与可重复测试：提供提交场景、启动压测、查询阶段与窗口统计、查询误差分解报告、查询容量结论的接口，错误以固定业务码在 JSON 中返回；报告须包含单位换算依据、同步标记来源与不确定标记。pytest 用例须在 Windows 离线覆盖尾窗对齐、重试去重、单位换算、不确定结论与重启恢复。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
