在全新工作区中，需要从零构建一个面向本地回环环境的 CDN 边缘缓存一致性仿真与诊断工作台，供网络运维工程师离线评估多边缘节点在带版本缓存策略下的行为。工作台以本地 HTTP 服务同时扮演源站与若干边缘节点，按策略快照（TTL、stale-while-revalidate 窗口、Vary 维度、缓存键规范化规则、purge 传播窗口、回源预算）处理客户端请求，在边缘节点执行缓存查找、回源合并、失效传播与异常注入，并记录每次请求的缓存判定轨迹。当边缘节点数从数个增长到数十个、缓存条目从数十增长到数万时，回源合并与 purge 广播的调度必须在全局并发上限与每轮时间预算约束下进行取舍，且多节点共享同一缓存键时的一致性不能因调度顺序而改变。源站内容可由本地脚本改写以驱动版本变化，连接拒绝与超时由本地端点真实表现。

任务环境与准备：
安装 Go 1.22 或更高版本并确认 go version 可用，安装 SQLite 命令行工具用于检查持久化文件（可选）。
创建全新工作目录，初始化 Go 模块（go mod init cdn-edge-consistency），默认使用标准库 net/http、database/sql 与 SQLite 驱动，无需外部网络依赖。
准备本地确定性样本：多边缘节点与源站配置、两份缓存策略快照（含版本号与校验摘要）、若干源站内容版本文件与异常注入参数清单。
源码运行前确保本地回环端口可用，示例脚本与测试端点均由本仓库启动。
所有验证在 Windows 本机执行，不依赖容器、真实 CDN 账号或线上站点。

业务要求：
1. 实现缓存键规范化与条目模型：缓存键由规范化路径（去除重复斜杠、合并点段、统一百分号编码大小写）、规范化查询串以及策略声明的 Vary 请求头取值集合共同组成；同一逻辑资源的不同 URL 形态不得产生重复缓存条目，条目须携带内容版本标识（ETag 或内容摘要）与写入时刻，不同 Vary 组合视为不同条目，规范化失败返回 E_KEY_INVALID。
2. 实现边缘缓存状态机与 TTL 语义：每个条目至少经历 MISS、REVALIDATING、FRESH、STALE、PURGED 五种状态并规定合法迁移路径，非法迁移返回 E_INVALID_TRANSITION 且不修改已持久化状态；TTL 按毫秒整数计算，stale-while-revalidate 窗口内允许返回旧内容并同时触发异步回源，窗口边界包含关系须显式定义。
3. 实现回源合并与源站内容版本识别：多个边缘节点并发未命中同一缓存键时仅首个请求触发回源，其余等待并复用同一结果；源站响应须携带内容版本标识，版本变化时所有持有旧版本的节点必须在策略声明窗口内同步更新，版本未变化时复用结果且不得重复触发回源，回源合并等待超出预算时返回 E_REVALIDATE_TIMEOUT。
4. 实现缓存策略快照与版本识别：策略快照携带单调递增版本号、生成时间、适用节点集合与整体校验摘要，提交时若版本号不大于当前已提交版本则返回 E_STALE_SNAPSHOT；加载新快照须整体替换旧策略且失败时保持旧策略完全可用，查询绑定其读取时的快照版本，版本在查询期间被替换时须在绑定版本上完成或返回 E_VERSION_RETIRED。
5. 实现 purge 传播与跨节点一致性：对某路径或某标签的 purge 须在策略声明的传播窗口内广播到所有适用边缘节点，各节点把受影响条目迁移为 PURGED 并使标签索引与路由映射级联失效，禁止出现部分节点已 purge 而其余节点仍返回旧内容的中间可见状态；传播窗口耗尽仍未完成的节点须返回 E_PURGE_INCOMPLETE 并附未完成节点清单。
6. 实现可复现异常注入与请求轨迹记录：允许通过请求参数对指定节点注入回源延迟、源站错误码、响应体长度变化、连接拒绝与 purge 传播中断，每类返回互不相同的业务码（至少 E_ORIGIN_TIMEOUT、E_ORIGIN_REFUSED、E_BODY_CORRUPT）；连接拒绝与超时须以本地端点真实连接表现，超时后真实关闭连接并释放资源，同一注入参数重复回放必须得到逐条一致的判定轨迹。
7. 实现回源与 purge 的并发调度预算：回源合并与 purge 广播受全局并发回源上限、每源站并发上限与每轮时间预算三重约束，预算内按节点优先级与缓存键热度取任务，超并发上限者进入有界等待队列，队列满返回 E_ORIGIN_QUEUE_FULL；预算不足时按确定性规则给出跳过次序与被跳过条目清单，不得因调度顺序改变同一缓存键的最终一致结果。
8. 实现单写者提交、多读者查询与强制终止恢复：条目写入、状态迁移与 purge 传播按单写者串行执行，多个读请求可并发；同一请求标识重复提交只生效一次、其余复用结果；写入与传播先写 SQLite 意图记录再提交事务，进程被强制终止后重启须扫描未完成意图把条目与传播状态回滚到最后一个完整版本或标记为已中止，恢复报告只基于已持久化事实并覆盖 E_STALE_SNAPSHOT、E_PURGE_INCOMPLETE、E_ORIGIN_TIMEOUT 等业务码的 JSON 错误体。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
