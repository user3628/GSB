当前是空白工作区，需要从零构建一个面向本地回环环境的正向与反向代理转发诊断工作台。工作台维护一组路由（反向路由把请求转发到本地后端测试服务，正向路由按目标主机与端口经本地出口转发），每条路由包含匹配规则（方法、路径前缀或目标主机）、上游地址、超时毫秒、重试次数、请求头与上游健康状态；配置以带单调版本号的 JSON 快照提交，也允许提交只含受影响路由的增量片段。路由字段变化会使该路由的编译产物（匹配表项、连接池分组、健康探测计划、转发规则缓存）以及依赖这些产物的聚合索引失效，需要级联重建。本工作台的核心难点是数值精度与误差传播：每条路由的超时与重试参数被用于推导连接预算、总等待预算与健康惩罚权重，这些推导要经过多级乘除、比例缩放与跨路由累计求和，浮点运算顺序、舍入方式与单位归一化都会放大误差；同时增量提交与级联重建必须与转发读路径保持跨模块一致。所有后端与出口端点均由本地测试服务提供，数据来自固定本地样本。

任务环境与准备：
确认 Windows 本地具备 Python 3.11 及以上解释器，并可用 pip 安装 FastAPI、uvicorn、NumPy 与 pytest；无需容器环境。
在工作区创建项目目录结构，准备固定本地样本：一组路由 JSON 快照与增量片段、若干可返回成功、固定错误码、延迟响应与故意挂起的本地后端测试服务配置。
初始化 SQLite 数据库文件路径，确保工作台启动时可创建意图日志、快照版本与级联产物表；准备本地回环端口占用清单，避免与测试服务端口冲突。
编写启动说明，确认本地后端测试服务可由脚本单独拉起，工作台通过回环地址访问，不依赖外部网络或真实站点。

业务要求：
1. 实现代理转发核心：反向路由按方法与路径前缀匹配并把入站请求转发到本地后端测试服务，正向路由按目标主机与端口经本地出口服务转发；正确转发方法、路径、查询串、请求头与请求体，并把上游状态码与响应体回传客户端。不得转发被声明为禁止的逐跳头部，转发失败时返回含业务码的 JSON 错误体。
2. 实现带版本号的配置快照与增量提交：快照携带单调递增版本号与校验摘要，增量片段只含受影响路由并携带基础版本号；基础版本不是当前版本时返回 E_STALE_BASE 且不改变任何已提交状态，整份快照替换时须识别版本变化并整体替换旧配置，不得把新旧快照的路由混合使用。
3. 实现路由预算推导与定点数值契约：由每条路由的超时毫秒与重试次数推导单次连接预算、总等待预算与健康惩罚权重，归一化到同一内部定点表示（比例保留固定小数位），输出每步舍入方式与累计舍入误差；同一快照重复推导必须逐位一致，不得因运算顺序改变而改变结论。
4. 实现跨路由累计预算的数值稳定性：多条路由共享上游时，按上游累计总等待预算与惩罚权重时使用 Kahan 或等价补偿求和，并与朴素求和在混合量级固定样本上对比给出可量化误差上界；累计结果须对路由数量与提交顺序不敏感，同一上游集合的结论在任意批次拆分下保持一致。
5. 实现依赖失效与级联原子重建：每条路由的匹配表项、连接池分组、健康探测计划与转发规则缓存，以及匹配聚合索引与上游预算聚合，须在路由关键字段变化时级联失效并在同一事务边界内原子重建；禁止出现部分产物已更新而另一部分仍为旧值的中间可见状态，查询只能看到某一完整提交版本。
6. 实现转发与配置更新的并发一致：读请求路径不得看到半更新配置，更新期间已在途请求按提交时绑定的路由版本完成转发；多个并发增量提交按基础版本串行化，同一基础版本的两个并发增量只允许一个成功、另一个返回 E_STALE_BASE；同请求标识重复提交只转发一次并复用结果。
7. 实现真实超时、异常链路与业务码体系：区分连接超时、读取超时、上游连接拒绝与上游 5xx，超时后必须真实关闭底层连接并释放资源，不得以等待冒充超时；失败响应为含业务码的 JSON，至少覆盖 E_STALE_BASE、E_SNAPSHOT_INVALID、E_UPSTREAM_UNAVAILABLE、E_UPSTREAM_TIMEOUT 与 E_CONFLICTING_REQUEST。
8. 实现基于 SQLite 的意图持久化与强制终止恢复，并提供可视化诊断工作台与端到端演示脚本：路由快照、增量提交与级联重建前先写意图记录再提交事务，进程被强制终止后重启须扫描未完成意图把配置回滚到最后一个完整快照版本，恢复报告只基于已持久化事实；脚本用固定本地样本完成全量提交、单路由上游增量提交、预算误差说明查询与一次强制终止后恢复，输出版本轨迹与级联失效轨迹。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
