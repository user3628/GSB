当前是空白工作区，需要从零实现一个面向本地边缘缓存场景的「副本版本一致性与陈旧容忍诊断工作台」，复现真实边缘缓存系统中副本版本落后、失效传播与陈旧容忍窗口协同的核心机制。系统由一个本地源站桩与多个边缘节点桩组成：源站为每个缓存对象维护单调递增的版本号、内容摘要与写入逻辑刻度；边缘节点按规范化缓存键持有对象副本，副本携带来源版本、写入逻辑刻度与命中计数。客户端经边缘节点读取对象，命中且版本与源站当前版本一致时直接返回；副本落后但仍在配置的陈旧容忍窗口内可返回并在响应中显式标记落后刻度；超出窗口必须回源。对象变更由源站发起，须沿边缘节点的订阅关系计算失效闭包并按确定顺序传播。诊断工作台需要回答：副本为何被判定为最新或陈旧、失效闭包包含哪些节点、某次读到的陈旧内容是否在容忍窗口内、误差来自逻辑刻度同步还是传播顺序。系统须以 SQLite 持久化对象版本、副本状态、订阅关系与失效事件，支持进程重启后刻度与重试队列恢复，并通过本地 HTTP 暴露诊断接口。

任务环境与准备：
安装 Python 3.11 及以上版本，创建虚拟环境并用 pip 安装 fastapi、uvicorn、numpy、pytest、httpx。
确认工作区为空白目录，不需要外网访问与外部服务，所有源站与边缘节点以本地进程内桩或回环地址 HTTP 桩实现。
准备样本生成脚本与固定随机种子，样本与测试数据在首次运行时确定性生成，SQLite 数据库文件放在工作区 data 目录。
在 Windows 命令行执行 pytest 验证，测试不得依赖真实 CDN、真实账号或任何网络外部资源。

业务要求：
1. 实现缓存键规范化与对象版本模型：缓存键须由对象路径与按参数名排序后的查询串规范化形式计算确定性摘要，须处理重复参数取首个规范值、空值参数、百分号编码与路径大小写敏感；源站对象记录包含版本号、内容摘要、写入逻辑刻度与变更序号，版本号必须单调递增且同一版本号不得对应不同内容摘要，重复发布相同内容摘要须幂等不推进版本。
2. 实现边缘副本读取与陈旧容忍窗口判定：命中读取时须依据源站当前版本与副本来源版本比较得出最新、落后、未知三种判定；落后副本只有在逻辑刻度差值不超过配置容忍刻度时方可返回，响应须显式携带副本来源版本、落后刻度与判定依据；超出窗口须触发回源并在回源失败时返回固定业务码 E_ORIGIN_UNAVAILABLE，不得降级返回陈旧内容。
3. 实现并发未命中回源合并：同一缓存键的并发未命中或超窗读取只能向源站发起一次回源，其余请求须等待同一结果并复用；回源合并期间若源站再次发布新版本，等待方须获得合并结束时刻的最新版本而非发起时刻的旧版本，回源方失败时等待方须收到与回源方一致的业务错误码而不得各自重试放大源站压力。
4. 实现失效传播的依赖闭包与确定性顺序：源站发布变更或显式失效时须沿边缘订阅关系计算失效闭包，闭包只包含订阅该对象的节点，节点按节点标识字典序执行失效；某节点失效失败须记录失败节点、原因业务码与传播路径并保留重试索引，恢复后从失败点继续而不是全量重播；未订阅节点收到失效须判定为越界并返回 E_NOT_SUBSCRIBED。
5. 实现副本状态与失效事件的事务化持久化：对象版本、副本来源版本与写入刻度、订阅关系、失效事件序列与失败重试索引须在每次发布与失效提交点以单事务写入 SQLite，事务提交后才对查询可见；事件序号须严格递增且可重复读取，提交失败须整体回滚使副本视图与事件序列同时不变。
6. 实现进程重启后的刻度恢复与失效补算：启动时须依据持久化的逻辑刻度、对象版本与未完成的失效事件恢复状态，把中断时处于传播中的失效事件回退为待重试并按序号顺序继续；重启窗口内已发布但未传播的变更须补算失效闭包，已完成的失效不得重复执行导致副本版本回退。
7. 实现诊断报告与本地 HTTP 接口：提供源站发布或失效对象、边缘读取对象、查询副本状态与失效事件、查询诊断报告的接口；诊断报告须列出每个落后副本的落后刻度和落后来源（刻度同步偏差或传播顺序滞后）、失效闭包成员与失败原因分解。错误统一以固定业务码在 JSON 中返回，报告字段顺序固定。
8. 提供本地确定性样本与可重复测试：样本须包含至少三个边缘节点、五个对象、多级订阅关系与一次刻度偏差场景；pytest 用例须在 Windows 离线覆盖键规范化等价、陈旧容忍边界、并发回源合并、失效闭包范围、事务回滚与重启补算，全部通过本地桩运行且同一种子下可重复。
