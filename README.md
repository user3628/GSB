交付从新建的代码库开始，某安全运营团队需要为 Windows 主机构建一套安全基线策略一致性验证工作台。团队维护多套基线策略包（如账户锁定阈值、审计日志保留天数、密码最长使用期、会话空闲超时、日志级别映射分值等），每套策略包由基线快照与偏差修复记录组成。不同来源的基线包在单位、刻度与时间纪元上互不兼容：账户锁定阈值有秒与分钟两种单位，密码最长使用期以天或小时给出，FILETIME 时间戳以 1601 纪元 100ns 为单位，分值型字段允许小数但落库以 1e-6 为最小单位的整数定点数表示。工作台需要把多来源策略统一归一到可比口径，计算基线偏差得分与传播误差上界，在并发校验与增量快照场景下给出可追溯的一致性结论，并输出诊断报告。

任务环境与准备：
在 Windows 上安装 Go 1.22 或更高版本（使用官方安装包），确认 go version 可用。
无需外部服务；SQLite 采用纯 Go 驱动（如 modernc.org/sqlite），通过 go get 安装并写入 go.mod。
在新建工作区中初始化模块，确保 go build 与 go test 可在无网络时基于已下载依赖运行。
运行样本生成器在本地临时目录产出确定性样本集，任务开始前执行一次以确认生成结果可重复。

业务要求：
1. 实现多来源基线策略包的解析与规范化：支持以 JSON 描述的基线快照和以带长度前缀文本块描述的偏差修复记录两种来源，统一转换为含策略项标识、原始单位、原始值、归一分值与来源偏移的内部模型；解析时校验策略项标识唯一性与单位合法性，未知单位返回 E_UNIT_UNKNOWN，非法标识返回 E_POLICY_MALFORMED，并保留已成功解析条目。
2. 实现单位归一与定点数值换算：把秒/分钟、天/小时、100ns FILETIME（1601 纪元）等统一换算为整数定点数（分值 scale=1e-6，时间换算为 UTC 秒整数），换算中的截断误差逐次写入误差账本；乘法与累加须执行 int64 溢出与精度截断检查，溢出返回 E_NUMERIC_OVERFLOW，数值路径禁止使用浮点。
3. 实现偏差得分与误差传播上界计算：按策略项权重对归一值做加权求差，累加得到基线偏差得分，同时沿换算链聚合每个条目的截断误差得到该包的总误差上界；当两条策略包对同一策略项的误差上界区间不重叠时标记为确定性偏差，重叠时标记为不确定性区间并记录区间端点，供诊断报告区分真偏差与精度噪声。
4. 实现带版本号的策略快照与整体替换识别：每完成一轮校验后在单个 SQLite 事务内提交递增版本号的快照，旧快照整体保留可回放；快照内容比较须识别整体替换式版本变化而非仅比对版本号，加载时校验版本链连续性，发现跳号以 E_SNAPSHOT_VERSION 拒绝并回退到最近连续版本，恢复后诊断结论与回退版本一致。
5. 实现并发校验会话的资源控制：多个策略包在独立会话中校验，会话间状态隔离；并发度与单会话策略项数上限可配置，超并发上限的包进入等待队列而非直接拒绝，单包策略项数超限时以 E_ITEM_BUDGET 终止该会话并保留已算出的部分得分与误差账本片段，部分结果不得污染其他会话的汇总。
6. 实现异常注入验证链路：通过命令行参数或配置文件构造未知单位、定点乘法溢出、FILETIME 溢出时间戳、快照版本跳号、误差区间越界五类样本，分别断言对应业务码、误差账本终态未被污染、快照版本未被推进，注入仅通过输入或参数完成，不得修改源码制造失败。
7. 实现确定性诊断报告与可视化摘要：导出 JSON 报告，包含每个策略包的归一化条目、单位换算链与误差账本、偏差得分、误差上界区间、确定性偏差与不确定性区间分类、快照版本链与业务码；报告按包相对路径与条目标识稳定排序，时间字段仅使用固定采样标记而非墙钟，重复运行且输入不变时报告字节级一致，并提供终端摘要展示各包偏差排序与误差上界。
8. 实现确定性样本生成与一键演示入口：内置生成器产出覆盖正常、单位混杂、截断文本块、数值溢出、版本跳号五类样本的本地样本集，支持一键运行完整校验并输出报告摘要，同时允许切换“严格模式”与“容错模式”两种误差处理策略，重复运行且输入不变时样本与报告均字节级一致，并可在 Windows 上执行。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地确定性样本验证单位归一、定点误差传播、快照一致性与异常业务码，附重复运行一致的结果。
