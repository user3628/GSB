项目从零开始，需要在 Windows 本地构建一个面向 Kubernetes 风格集群的声明式配置漂移收敛裁决组件，交付可交互的专业应用与可重复演示。组件读取本地确定性 JSON 样本中的集群对象（对象标识、类别、所属命名空间、期望字段集合、实际字段集合、字段来源标记、依赖的其他对象、资源预算）与带版本号的收敛策略快照（漂移判定容差、批次规模上限、依赖驱动顺序规则、单轮时间预算、重试上限），据此为每个对象判定漂移类别（字段缺失、字段多余、取值偏移、来源冲突），生成带依赖约束的收敛批次与每批次的写回计划，并在本地测试端点模拟写回后核对收敛结果。对象规模会从数十个变化到数万个、依赖边从稀疏变为稠密，漂移判定与批次组织需要在逐对象精确判定与按类别分组批量判定之间做算法取舍，两条路径必须给出逐对象一致的漂移结论与一致的批次划分。字段取值存在字符串、整数与浮点三类，浮点字段的容差比较与批次规模统计会带来舍入误差传播。

任务环境与准备：
在 Windows 本地安装 Go 1.22 或以上，并确认 go version 可执行；无需第三方网络依赖，仅使用标准库与 SQLite 驱动。
执行 go mod init 创建模块并从本地模块缓存或离线包引入 SQLite 驱动（如 modernc.org/sqlite），确认 go build 可在无网络环境完成。
准备固定本地确定性样本：一份集群对象与依赖边 JSON、一份收敛策略快照 JSON、一份漂移字段取值样本，均放在工作区 samples 目录并由程序读取绝对或相对路径。
启动两个本地回环 HTTP 测试端点：一个用于接收写回请求并可在成功后按脚本更新对象实际字段，一个用于模拟连接拒绝场景（未监听端口）；端口与开关通过配置文件或启动参数注入。
确认可在任务要求下通过输入参数或样本注入异常（写回超时、连接拒绝、复核未消除），不修改源码制造验收失败。

业务要求：
1. 实现集群对象与收敛策略快照的解析和归一化：对象声明标识、类别、命名空间、期望字段集合、实际字段集合、字段来源标记、依赖对象列表与资源预算，策略快照携带单调递增版本号、生成时间、漂移判定容差、批次规模上限与整体校验摘要；解析时校验对象标识唯一、依赖引用存在、资源预算为非负整数并做溢出检查，失败返回 E_SPEC_INVALID 且不改变任何已提交状态，提交时版本号不大于当前版本返回 E_STALE_SNAPSHOT。
2. 实现漂移判定核心：逐字段比较期望与实际集合，区分字段缺失、字段多余、取值偏移与来源冲突四类漂移，浮点字段按策略声明的相对容差做定点比较而非裸浮点比较，整数与字符串按严格相等比较；同一对象命中多类漂移时须输出全部类别并把来源冲突提升为首要漂移；漂移判定结论须携带触发字段名、双方取值与所用容差，保障同一对象重复判定逐字段一致。
3. 实现收敛批次的依赖约束组织：按对象依赖关系生成批次，要求被依赖对象所在批次序号严格小于依赖者所在批次；出现依赖环时返回 E_DEPENDENCY_CYCLE 并附环上对象标识，环外对象的批次仍须输出；无漂移对象不得进入任何写回批次但须计入统计；批次规模超过策略上限时按稳定次序拆分，拆分后同一对象的依赖先后不得改变，批次划分必须可由对象集合与依赖边唯一重现。
4. 实现数据规模自适应的判定路径取舍：当对象数不超过配置的精确上限时逐对象精确判定并输出每对象判定耗时与判定依据；超过上限时按漂移类别分桶批量判定并输出分桶方式、桶内对象数与结论抽样核对结果；两条路径对同一快照版本必须给出逐对象一致的漂移类别与一致的首要漂移，任一对象结论不一致时整批标记失败并返回 E_PATH_DIVERGENCE。
5. 实现写回计划的定点数值契约：由资源预算、漂移字段数与批次规模推导每批写回代价估计与总预算占用，全程使用整数或显式定点表示，比例类估计保留固定小数位并输出每步舍入方式与累计舍入误差；判断某批是否超出单轮时间预算时使用带相对容差的定点比较，容差内按批次序号稳定打破平局，比较双方数值与容差取值须可逐项复核。
6. 实现单轮时间预算与批次调度的并发约束：收敛轮次受每轮时间预算与策略声明的最大并行写回批数共同约束，预算内按批次序号与漂移严重度取批执行；超并行上限的批次进入有界等待队列，队列满返回 E_WRITE_QUEUE_FULL；预算耗尽时按确定性规则给出跳过次序与被跳过批次清单及原因，已执行批次的结论不得因跳过而重算或回退。
7. 实现写回执行与收敛结果核对：对每批对象向本地测试端点发起真实 HTTP 写回请求，每次请求具备独立超时，超时后必须真实关闭底层连接并释放并行名额，返回 E_WRITE_TIMEOUT；写回成功后须重新读取该对象实际字段集合复核漂移是否消除，未消除时该对象计入收敛失败并附残留漂移类别，禁止仅以请求成功就判定收敛；连接被拒绝返回 E_ENDPOINT_REFUSED。
8. 使用 SQLite 持久化快照版本、漂移结论、批次划分、写回记录与意图日志，写操作先落意图记录再提交事务；进程在批次组织或写回中途被强制终止后重启须扫描未完成意图，把未提交写回回滚为待写回、批次划分回滚到最后一个完整版本或标记为已中止，恢复报告只基于已落盘事实；单写者组织与多读者查询并发一致，同一轮次标识重复触发只执行一次、其余等待复用结果。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证漂移判定、批次依赖约束、规模自适应一致性与中断恢复，附运行结果。
