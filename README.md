当前是空白工作区，需要从零实现一个面向本地模型服务弹性伸缩场景的「副本伸缩决策与数值误差传播诊断工作台」，复现真实在线推理服务中基于健康指标做扩缩容判定的核心机制。系统管理一个模型服务与若干副本，每个副本周期上报健康指标（每秒请求数、错误率、p95 延迟毫秒、队列深度、GPU 显存占用比）；工作台按滑动窗口聚合指标并计算伸缩评分，评分由多项加权指标组成，各项按配置小数位截断后加权求和，窗口采样间隔与窗口长度不整除、各副本上报时刻存在偏移与采样规模差异，使伸缩评分带有误差传播。伸缩评分用于决定扩容、缩容或保持，评分接近容差时须按固定次序裁决，并输出误差分解诊断。

任务环境与准备：
Windows 10/11，安装 Python 3.11 及以上与 pip，并创建独立虚拟环境。
在虚拟环境中安装 numpy、httpx、pytest，版本以本地离线可用的 wheel 为准，安装过程不依赖外网。
准备本地工作目录与固定随机种子的样本生成脚本，不引入任何外部服务、账号或容器环境。

业务要求：
1. 实现服务、副本与指标上报的摄入模型及校验：上报记录含服务标识、副本标识、指标名称、指标值、采集时刻与采集序号；须校验指标值落在声明值域内、采集序号单调，同一副本同一指标同一序号重复上报须幂等覆盖而不改变聚合结果，非法上报返回固定业务码 E_BAD_METRIC 且不进入聚合。
2. 实现多窗口指标聚合与时间对齐：按滚动窗口（至少 1 分钟、5 分钟、15 分钟）聚合请求数、错误率、p95 延迟与队列深度，窗口归属以采集时刻落在闭开区间 [起始, 结束) 判定；采样间隔与窗口长度不整除时尾窗须显式标记并参与聚合，聚合结果须记录参与样本数与所用窗口边界，相同输入下重复聚合结果逐字段一致。
3. 实现伸缩评分的加权计算与误差上界量化：每个指标项按配置的小数位截断后乘以权重求和得到伸缩评分；须依据截断位数、各副本采样数差异与窗口错位时长计算评分误差上界，以十进制定点字符串输出各误差来源分解项与合成上界，误差贡献须按从大到小排序，且不得依赖二进制浮点默认字符串表示。
4. 实现容差内并列的确定性裁决与伸缩决策：当扩容候选与保持候选（或缩容候选）评分差值小于配置相对容差（默认 0.02）时判定为并列，按更低错误率、更多样本数、副本标识字典序的固定次序裁决；裁决须在诊断报告中标记为 tied 并附裁决键，同一输入下决策结果与裁决键必须可复现。
5. 实现缩容演练与恢复回切的副本状态机：副本合法状态为 active、draining、drained、recovering，迁移由缩容决策、排空完成、恢复演练与健康恢复驱动，非法迁移须拒绝并返回 E_INVALID_TRANSITION；排空期间到达的新请求须转入其他 active 副本而不丢失，排空完成前副本不得从聚合中移除。
6. 实现并发伸缩决策与持久化的互斥及重启恢复：同一服务的缩容演练与决策提交须串行化到服务一致性边界内，并发锁等待须基于真实单调时钟超时并返回 E_CONTENTION_TIMEOUT；决策提交点须以单事务写入评分、误差上界、副本状态与决策事件，重启后须把中断的演练回退到一致点并保留已提交事件，恢复后同输入重算结果与历史一致。
7. 实现本地 HTTP 诊断接口与报告：提供上报指标、触发缩容或恢复演练、查询服务与副本状态、查询评分与误差分解报告、查询决策历史的接口；报告须包含参与样本数、尾窗标记、刻度偏移来源、并列裁决依据与误差上界合成过程，所有错误以互不重叠的固定业务码在 JSON 中返回。
8. 提供本地确定性样本与可重复测试：内置固定随机种子的指标流生成器，产出至少三个副本、覆盖采样数差异悬殊与评分接近容差的两段流，总上报数不少于两千；pytest 用例须在 Windows 离线覆盖非法指标拒绝、尾窗聚合、误差上界、并列裁决、非法状态迁移、并发超时与重启恢复。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
