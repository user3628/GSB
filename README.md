项目从零开始，密码协议与密钥生命周期管理是安全防护的核心环节，团队需要一个面向本地授权样本的密钥生命周期可视化诊断工作台。系统需模拟密钥生成、激活、轮换、归档与销毁各阶段，对每个阶段执行策略校验并记录审计轨迹；当连接规模与密钥数量变化时，在逐密钥精算与批量流式路径之间自适应取舍，保证两种路径裁决结论与审计轨迹逐字节一致。工作台维护带版本号的密钥状态与审计快照，支持整体替换识别、中断恢复与并发会话资源控制，并通过外部参数注入密钥越权使用、过期密钥复用、快照版本跳号、算法降级与并发轮换竞争五类异常进行验证。所有样本由本地确定性生成器产出，协议交互仅在进程内内存通道上模拟，不依赖真实网络。

任务环境与准备：
安装 Go 1.22 或更高版本（Windows amd64），确认 go version 可执行。
使用 go mod init 初始化模块，引入纯 Go 的 SQLite 驱动（如 modernc.org/sqlite），通过 go mod tidy 拉取依赖，不依赖 CGO。
工作区为本机新建目录，所有样本由程序内置生成器在临时工作目录中产出，不依赖网络、外部账号或预置数据集。
运行测试与演示前设置本地临时目录环境变量（如 TMP），确保并发会话与 SQLite 文件位于可写路径。

业务要求：
1. 实现密钥生命周期模型与阶段迁移核心：为每个密钥维护全局唯一标识、算法族、强度参数、所属主体、创建与过期时间及当前阶段；严格按生成、激活、轮换、归档、销毁顺序迁移，非法迁移返回 E_PHASE_TRANSITION，过期后使用返回 E_KEY_EXPIRED，算法强度低于主体策略要求时返回 E_WEAK_ALGO，越权主体操作返回 E_SUBJECT_SCOPE。
2. 实现基于单调时钟的密钥存活时间与轮换窗口判定：所有时间比较使用单调时钟差值而非墙钟，记录密钥已存活时长与距下次轮换的剩余窗口；时间字段输出只使用固定采样标记，重复运行且参数不变时判定结果与剩余窗口字节级一致。
3. 实现规模自适应裁决器：当单主体下待裁决密钥数低于阈值时走逐密钥精算路径，高于阈值时走批量流式路径；两条路径必须对同一输入产生逐字节一致的裁决结论和业务码序列，阈值与所选路径须在输出中可观测并可通过参数调整。
4. 实现带版本号的密钥状态与审计快照：每次阶段迁移、轮换或销毁成功后在单个 SQLite 事务内提交递增版本号快照，旧快照整体保留可回放；快照内容比较须识别整体替换式版本变化而非仅比对版本号，加载时校验版本链连续性，跳号返回 E_SNAPSHOT_VERSION。
5. 实现并发轮换与资源控制：同一密钥的并发轮换请求须在密钥粒度上互斥，仅一个成功、其余返回 E_ROTATION_CONTENTION；并发度与单主体待处理请求数上限可配置，超并发上限的请求进入等待队列而非直接拒绝，单主体超限返回 E_KEY_BUDGET。
6. 实现中断恢复一致性：密钥轮换或销毁过程中进程被强制终止后重启，依赖 SQLite 已提交事务恢复阶段状态与快照版本，已提交迁移不回退、未提交操作整体丢弃且密钥可再次正常轮换；恢复后版本链跳号须以 E_SNAPSHOT_VERSION 拒绝加载并回退到最近连续版本。
7. 实现异常注入验证入口：通过外部参数或配置文件构造过期密钥复用、算法降级、快照版本跳号、并发轮换竞争与非法阶段迁移五类样本，分别断言对应业务码、密钥状态终态未被污染、快照版本变化符合预期；注入仅通过输入或参数进行，不得修改源码。
8. 实现可视化诊断工作台与结构化输出：以子命令方式支持查看密钥生命周期时间轴、按版本回放快照、展示算法取舍路径与告警列表；同时导出 JSON 诊断报告，包含密钥摘要、阶段迁移轨迹、裁决业务码、算法路径与快照版本链，报告按主体标识与密钥标识稳定排序，重复运行字节级一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
