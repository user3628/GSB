为传统机器学习建模团队从零构建一个本地可运行的线性模型正则化训练与数值诊断工作台，核心问题是数值精度与误差传播。输入是本地特征分片目录：多个 CSV 分片含样本 id、若干数值特征列与一份二分类标签文件（样本 id 到 0/1 标签）；一份正则化配置，声明正则化类型（L1、L2 或 ElasticNet）、正则化强度、ElasticNet 的 L1 占比、求解迭代上限、收敛容差与浮点容差；一份训练口径配置，声明特征标准化方式、各特征是否参与正则化惩罚与目标精度（float32 或 float64）。工作区为空，需自行初始化项目：一个可交互的 FastAPI 服务，提供作业创建、分阶段执行（数据加载与标准化、正则化求解、误差传播诊断、提交快照）、查询逐特征系数与诊断报告、读取版本化快照的接口。团队需要据此完成确定性正则化线性模型求解，并对每一环节的数值误差如何向最终系数传播给出可定位诊断。

任务环境与准备：
安装 Python 3.10 及以上版本，并在项目虚拟环境中安装 numpy、fastapi、uvicorn、pytest；版本以本地已安装且可导入为准，不要求联网固定版本号。
在项目内生成固定随机种子的 CSV 特征分片与标签文件：含 3 至 5 个分片、数百样本、数十特征，包含一列标准差为零的退化特征与少量缺失值，用于触发退化处理与校验分支。
准备三份正则化配置分别覆盖 L1、L2 与 ElasticNet，并准备一份含非法正则化强度的配置用于验证 E_PARAM 业务码。
确认本机可监听一个本地空闲端口用于 FastAPI 服务，SQLite 使用 Python 标准库 sqlite3，无需额外数据库服务。
在项目内编写启动说明与 curl 请求示例文本，演示入口以固定参数运行两次以核对结果逐位一致。

业务要求：
1. 作业创建接口接收分片目录、标签文件、正则化配置与训练口径配置，校验样本 id 唯一且跨分片无重复、标签覆盖全部样本、特征列均为可解析 float、正则化强度与容差为正实数、ElasticNet 的 L1 占比位于闭区间 [0,1]；任一非法返回 E_PARAM 业务码并指出出错分片与行号，且不得创建任何结果文件、临时目录或阶段状态。
2. 须实现确定性数据加载与标准化：分片按文件名升序拼接并按样本 id 字典序稳定排序，按训练口径对特征做列均值与列标准差标准化，标准差为零的列须声明退化处理方式并被记录；同一输入下特征矩阵的行顺序、列均值、列标准差与标准化后取值须逐位可重复，不得依赖字典遍历顺序或并行归约顺序。
3. 须实现 L1、L2 与 ElasticNet 三种正则化目标的确定性坐标下降求解，各轮迭代按特征下标升序更新，软阈值在 float64 下计算；达到迭代上限或系数变化量低于收敛容差即停止并记录收敛状态、实际迭代轮数与最大系数变化量，未收敛时不得静默给出看似收敛的结果。
4. 须显式支持 float32 与 float64 两条求解精度路径：同一次求解由目标精度参数选定路径，另一条路径须作为对照同步求解并记录逐特征系数差值、最大绝对差与相对差；两条路径的差值统计须能定位到具体特征名，超出浮点容差时须标记该特征为不稳定而非让整体结果失败。
5. 误差传播须可观测：每个特征的系数须附带由标准化误差、正则化项误差与迭代收敛误差按权重平方和合成的不确定度估计，并给出各误差来源的贡献分量；不确定度须能追溯到具体特征与标准化统计量，超阈值特征须在诊断报告中列出并计入不稳定特征比例。
6. 作业须按 data_loaded、solved、diagnosed、committed 四阶段推进，阶段顺序不可跳步，乱序推进返回 E_STAGE 并给出当前阶段；重复调用已完成阶段须幂等返回已有结果与当前快照版本，不得重复求解或重复写入系数记录。
7. 求解进度与系数结果须在 SQLite 中以作业、阶段、特征分片三级事务提交，单次求解的系数向量、收敛状态与诊断摘要在同一事务中写入；每次阶段完成须以整体替换方式生成版本化快照，读取快照时若检测到数据库版本与磁盘结果文件哈希不一致、配置指纹变化或残留旧版本文件，须返回 E_STALE 并定位到版本与配置文件。
8. 进程被强制终止后重启，须从 SQLite 已提交进度继续，核对每个分片的处理标记、系数结果内容哈希与快照版本，重算未提交分片且不重复累加已提交系数；恢复后的逐特征系数、收敛状态、两路径差值摘要与快照版本序列须与无中断执行完全一致，并提供确定性本地演示入口输出可重复结果与 curl 示例。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地固定分片验证四阶段求解、双精度路径差值诊断与中断恢复一致性，并复现错误业务码。
