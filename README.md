从无到有搭建时，某安全团队需要为 Windows 主机安全配置的持续变更验证构建一套本地可复现的实验引擎。团队维护多套安全配置基线（账户策略、审计策略、服务启动类型、注册表键权限），每次变更以增量变更集提交，变更之间通过基线项引用形成依赖；验证过程要求在真实本地文件系统与进程边界上执行受控探测，确认实际配置与预期一致。引擎还需维护带版本号的配置快照，支持强制终止后的恢复，并能通过外部参数注入越权读取、依赖缺失、版本跳号与并发变更竞争等异常。由于配置项存在数值区间、单位换算与继承覆盖关系，验证结论必须可解释且可重复。

任务环境与准备：
安装 Go 1.22 或以上版本（Windows 官方安装包或解压版），确认 go version 可执行。
准备本地 SQLite 依赖：使用纯 Go 驱动 modernc.org/sqlite（go get modernc.org/sqlite），无需 CGO 或 C 编译器。
在空目录中初始化模块（go mod init），除上述驱动外不引入其他第三方依赖。
任务执行前由程序内置生成器在临时工作目录中创建确定性配置样本与探测子目录，不预置任何二进制或外部数据文件。
确保本机允许创建本地子进程与本地回环监听，无需管理员特权，不依赖网络下载或真实账号。

业务要求：
1. 实现安全配置基线与增量变更集的解析与规范化：基线以 JSON 描述账户策略、审计策略、服务启动类型与注册表键权限四类配置项及项间依赖引用，变更集以带长度前缀的文本块描述新增、修改、删除三类操作；解析时校验项标识唯一性、引用可解析性与字段取值域，非法输入返回稳定业务码 E_CONFIG_PARSE 并指明项标识与来源偏移，不得部分应用。
2. 实现配置项依赖解析与失效闭包计算：沿基线项之间的引用关系建立有向依赖图，对每次删除或收紧操作反向追踪直接与传递受影响的配置项集合；当引用目标缺失或形成环时分别返回 E_DEP_MISSING 与 E_DEP_CYCLE 并输出参与失效的最小项集合与边序列，闭包计算结果须可逐项溯源到触发变更。
3. 实现真实边界探测层：在独立临时工作目录与受限子进程内，针对变更后的账户策略、审计日志目录权限、服务启动类型声明与注册表键访问控制执行最小化探测，把探测观测值与基线预期逐项比对；探测操作不得越出临时工作目录，越界尝试须被拒绝并记录为 E_PROBE_ESCAPE，探测结果须附带观测方式与同步标记。
4. 实现带版本号的配置快照与整体替换识别：每完成一轮变更应用与探测后在单个 SQLite 事务内提交递增版本号快照，旧快照整体保留可回放；加载时校验版本链连续性，发现跳号返回 E_SNAPSHOT_VERSION 并回退到最近连续版本；快照内容比较须识别整体替换式版本变化而非仅比对版本号，即使版本号相同也必须判定为不同快照。
5. 实现并发变更应用与探测的资源控制：同一配置命名空间的变更须串行化以保证版本链单调，不同命名空间可并行；在途事务数与在途探测进程数均以可配置上限约束，超出等待阈值的请求返回 E_CHANGE_CONTENTION 而非无限阻塞，在途计数与排队长度须在输出中可观测。
6. 实现强制终止后的恢复一致性：在变更提交或探测执行过程中进程被强制终止后重启，依赖 SQLite 已提交事务恢复快照版本与变更进度，已提交变更不回退、未提交事务整体丢弃且版本号不推进；恢复后若发现版本链跳号须以 E_SNAPSHOT_VERSION 拒绝继续并回退到最近连续版本，不承诺被强制终止的探测一定生成退出报告。
7. 实现异常注入验证链路：通过外部命令行参数或配置文件构造依赖缺失、依赖环、探测越界、快照版本跳号与并发变更竞争五类样本，分别断言对应业务码、受影响配置项终态未被污染、已提交快照版本未被推进；注入仅通过输入与参数进行，不得修改或替换源码来制造验收失败。
8. 导出确定性 JSON 验证报告：包含每轮变更的配置项差异、失效闭包与来源链、探测观测值与比对结论、业务码及来源偏移、快照版本链与并发排队统计；报告按配置项标识与业务码稳定排序，时间字段只使用固定采样标记，重复运行且输入不变时报告字节级一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证配置变更应用、依赖失效闭包、真实边界探测与强制终止恢复，并确认重复运行报告字节级一致。
