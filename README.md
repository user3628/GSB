从一个空仓库出发，需要从零构建一个面向本地微服务测试环境的分区有序消费位点与事务可见性裁决工作台，交付可交互的诊断应用与可重复演示。工作台以 SQLite 持久化主题、分区、消息、消费位点与事务可见性表：生产者按分区键把消息写入某主题的某一分区，同一分区内消息必须按生产序号严格有序；带事务标记的消息先写入事务可见性表并处于不可见状态，由组件向本地事务协调测试端点查询结论后才允许变为可见并进入该分区的可消费序列。消费者通过本地 HTTP 按分区拉取消息并提交消费位点，同一分区同一时刻只允许一个消费者持有消费位点租约。真实运行中热点分区积压深、长尾分区稀疏，事务结论到达时刻不一，位点提交与事务可见性推进相互耦合；工作台需要在全局并发协调查询上限、每分区在途位点租约上限与每轮时间预算下推进协调与位点提交，并展示每分区可消费序号前沿、待决事务、位点租约持有者与预算消耗轨迹。

任务环境与准备：
安装 Go 1.22 或更高版本（从 https://go.dev/dl/ 获取 Windows 安装包），确认 go version 可用。
使用 SQLite 需在 go.mod 中引入纯 Go 驱动 modernc.org/sqlite（或 go-sqlite3 并准备 CGO 工具链），版本以依赖声明锁定。
确认 8080 等本地端口可用，用于启动工作台 HTTP 服务、本地事务协调测试端点与消费者测试客户端。
准备固定本地样本目录，包含主题与分区定义、顺序与事务消息轨迹、注入场景参数与多轮演示脚本所需输入。
所有依赖与测试均在 Windows 本地执行，不依赖容器、真实账号或线上服务。

业务要求：
1. 实现主题、分区与消息模型：主题声明分区数与分区键路由规则（哈希或显式分区号），消息记录主题、分区、生产序号、事务标记、体摘要与生产时刻；同一分区内生产序号必须由组件单调分配且无缺口，跨分区互不约束；重复写入同一消息标识须幂等并返回既有序号，内容不一致返回 E_CONFLICTING_MESSAGE 且不改变既有记录；路由规则非法或分区号越界返回 E_ROUTE_INVALID。
2. 定义分区消费位点租约与消息可见性状态机：消息至少包含 PENDING_INVISIBLE、VISIBLE、CONSUMED、ROLLED_BACK、DEAD_LETTERED 五种状态，位点租约至少包含 FREE、LEASED、EXPIRED 三种状态，并规定合法迁移路径；非法迁移返回 E_INVALID_TRANSITION 且不修改已持久化状态；每次拉取与位点提交须绑定租约版本，版本落后返回 E_LEASE_STALE。
3. 实现分区内严格顺序消费与位点回退重放：拉取时返回该分区可消费序号前沿之后最小未消费序号的消息；位点租约在空闲超时后须真实释放，消费者再次拉取须按原序号继续而非跳到后继消息；回退请求可把位点租约设置的消费位点指向更大范围的起始序号并触发重放，重放期间该分区新消息不进入可消费前沿，重放完成后按位点继续；回退目标早于最早保留序号返回 E_REPLAY_EXPIRED，指向尚未可见序号返回 E_REPLAY_INVALID；重放不得使已消费消息被重复计入可消费前沿。
4. 实现事务可见性表与协调裁决：带事务标记的消息先写入事务可见性表并处于 PENDING_INVISIBLE，组件向本地事务协调测试端点发起查询以获得提交或回滚结论；查询具备独立超时，超时须真实关闭连接并返回 E_TXN_TIMEOUT，未知结论时消息保持不可见且不计入分区可消费前沿；提交须在同一事务内把消息转为 VISIBLE 并推进该分区可消费前沿，回滚须标记 ROLLED_BACK 且不参与消费；同一事务标识的重复查询以幂等键去重，不得改变已持久化结论，结论前后矛盾返回 E_TXN_CONFLICT。
5. 实现三重预算并行调度器：事务协调与位点租约推进在全局并发协调查询上限、每分区在途位点租约上限与每轮时间预算约束下执行，预算内按分区优先级与到达顺序取任务，超出并发上限者进入有界等待队列，队列满返回 E_QUEUE_FULL；同一分区同一事务不得被并行查询两次；预算耗尽时按优先级、分区轮转与已消耗预算给出确定性跳过次序，被跳过任务保持原状态并输出降级依据与剩余预算，降级不得使已在途位点租约被无谓中断。
6. 实现可复现异常注入与互不相同的业务码：请求参数可对本地协调端点注入返回提交、返回回滚、连接拒绝、响应挂起与重复矛盾结论五类情形，对位点租约注入租约超时抢占与重放期间新消息到达两类情形，每类返回互不相同的业务码（至少覆盖 E_TXN_TIMEOUT、E_TXN_CONFLICT、E_REPLAY_EXPIRED、E_LEASE_HELD、E_QUEUE_FULL），注入参数与实际观测须绑定记录并可逐项复核。
7. 实现单写者提交与多读者查询的并发一致及幂等：分区消费位点、消息可见性状态、事务结论与可消费前沿推进必须共同生效，禁止出现消息已标记提交而分区可消费前沿仍停在旧值、或位点租约已释放而不可见消息仍被拉取到的中间可见状态；查询只能看到某一完整提交版本；同一请求标识重复提交只执行一次、其余等待复用结果，内容不一致返回 E_CONFLICTING_REQUEST。
8. 实现基于 SQLite 的意图持久化、强制终止恢复与诊断工作台：拉取、位点提交、回退与事务裁决前先写意图记录再提交事务；进程被强制终止后重启须扫描未完成意图，把未提交拉取回滚为可消费、未提交位点回滚为旧位点、未完成重放标记为已中止，恢复报告只基于已落盘事实；提供本地 HTTP API 与诊断页面展示各分区可消费前沿、待决事务、位点租约持有者与预算消耗轨迹，并附可重复演示脚本覆盖顺序消费、待决提交、待决回滚、协调超时重试、同分区并发拉取冲突与强制终止后恢复。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
