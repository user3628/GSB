当前是空白工作区，没有现存项目、代码或数据附件。需要从零实现一个面向本地多节点基础设施场景的「配置一致性快照校验引擎」，用于在离线环境下复现真实运维中配置漂移检测与一致性判定的核心机制。引擎管理一组节点的配置快照（节点标识、配置项键路径、配置值、配置来源、采集序号与采集时刻），每个节点周期性上报本节点快照，引擎据此计算跨节点一致性视图：哪些配置项在所有节点上取值一致，哪些存在漂移，漂移的范围与首个分歧来源是什么。配置规模会随节点数与配置项数快速增长，判定算法必须在全量精确比对与分桶指纹摘要之间取舍：节点少时精确比对可直接给出每个分歧键，节点多时逐个键精确比对代价过高，必须依靠摘要筛选缩小候选再精确定位；同时上报数据的乱序、重复、缺失与来源标记不一致会让简单指纹误判为一致或误报为漂移，引擎需维护可解释的诊断结论。

任务环境与准备：
安装 Python 3.11 及以上版本，并确保 python 与 pip 可在 Windows 命令行直接调用。
创建虚拟环境并安装 numpy、pytest 与 requests，仅使用本地依赖，不访问外网。
确认工作区为空目录，运行目录具备可写权限以便 SQLite 数据库文件与临时样本目录写入。
准备固定随机种子的样本生成脚本入口约定（由实现方提供），执行前无需任何外部数据或账号。

业务要求：
1. 实现节点配置快照的解析与校验：每条上报记录包含节点标识、配置项键路径（按点分层）、配置值（字符串、整数、布尔或列表）、配置来源标记、采集序号与采集时刻。须校验键路径格式合法、值类型与声明类型一致、采集序号为正整数；重复提交同一节点同一采集序号须视为幂等覆盖而非新增版本，采集时刻必须单调不减，非法记录返回 E_BAD_RECORD 且不得进入一致性视图。
2. 实现按节点采集序号推导快照版本：每个节点只保留其最大有效采集序号对应的完整快照，较小序号的上报若在最大序号之后到达须按乱序处理并记录为迟到而不回退版本。须能查询任一节点当前快照版本与其历史版本数，并检测某节点上报的配置项集合与他人相比缺失的键，缺失必须与取值不同区分报告。
3. 实现分桶指纹摘要与精确比对的混合判定：对每个配置项键按配置值生成确定性指纹，按键路径前缀分桶计算桶级摘要（桶内键数与组合摘要），先用桶级摘要筛选出可能存在分歧的桶，再对候选桶内键做逐键精确比对。节点数低于配置阈值时须直接逐键精确比对，两条路径对同一输入必须给出一致的分歧键集合与分歧节点集合。
4. 实现跨来源标记的漂移判定语义：同一配置项在不同节点上取值相同但配置来源标记不同时须判定为来源不一致而非取值漂移，视图须分别统计取值漂移、来源不一致与节点缺失三类差异；配置项的期望来源若在清单中声明，须能把实际来源与期望来源不符单独标记。三类差异在总一致性结论中的权重须可配置且结论可解释。
5. 实现配置规模变化下的算法取舍与阈值自适应：当节点数或配置项数超过配置阈值时须自动启用分桶摘要路径，并在诊断报告中记录所选路径、桶数与候选桶比例。须提供对同一批数据的两种路径强制运行与结论比对能力，强制精确比对超时或超内存时须以 E_SCALE_LIMIT 有序终止而非降级为不完整结论。
6. 实现漂移定位与首个分歧来源诊断：对每个存在漂移的配置项须输出出现次数最多的取值及其持有节点列表、少数取值及其节点列表，并按采集时刻给出最早出现分歧的节点与时刻。若最早分歧节点的采集时刻晚于其他节点，诊断须标记为证据不足而不是断言该节点为源头；诊断结论须与同快照下重新计算的结论逐字段一致。
7. 实现 SQLite 持久化与并发上报的一致性：节点快照版本、配置项记录、桶级摘要与一致性视图结论须在快照版本推进时以单事务写入，事务提交后才对查询可见；并发上报同一节点时须串行化到节点边界内，不同节点可并行，锁等待须有真实超时并返回 E_CONTENTION_TIMEOUT；进程重启后须恢复各节点当前版本与摘要并保证视图结论和重启前一致。
8. 提供本地 HTTP 接口、诊断报告与可重复测试：通过本地 HTTP 提供上报快照、查询节点版本、查询一致性视图、查询漂移诊断报告、触发路径比对的接口，错误统一以固定业务码在 JSON 中返回。内置固定随机种子的样本生成器产出至少两档规模（少量节点与大量节点）的确定性数据，pytest 用例须在 Windows 离线覆盖幂等上报、乱序回退禁止、缺失与漂移区分、两路径结论一致、并发超时与重启恢复。
