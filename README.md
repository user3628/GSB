内部三维内容管线团队需要在 Windows 空白工作区交付一套从多视角图像到体素化场景表示的增量重建组件，作为新的服务端能力从第一行代码开始实现。每一份重建工程由程序内置固定种子生成器产出的低分辨率灰度图像分片与 JSON 场景清单构成，清单显式给出各视角的旋转矩阵、平移向量、内参与点云真值采样坐标，作为校验的唯一真值来源。重建按视角投影采样、视角局部体素贡献体构建、全局体素融合稀疏化、重建校验四个阶段推进。运维人员通过本地 HTTP 接口导入分片、修改相机或融合参数、触发重建并查询点云摘要与错误统计。由于视角数量与体素分辨率同时变化，管线需在逐视角重算、按块缓存、稀疏增量三种路径间自适应取舍，并保证任何路径下同一快照版本的重建结果逐字节一致。

任务环境与准备：
在 Windows 本地安装 Go 1.22 或更高版本与 SQLite（通过 go-sqlite3 驱动，需本地 CGO 工具链或预编译驱动），无需网络下载模型或数据集。
新建空工作区目录，确认程序内置固定种子生成器可产出多视角灰度 PNG 分片与 JSON 场景清单，并保留固定种子以便复现。
预留本地端口用于 HTTP 接口，确认临时目录可写并用于分阶段产物落盘与文件锁验证。
准备用于强制终止恢复验证的独立进程启动脚本，执行中可主动终止进程后重新启动。

业务要求：
1. 实现视角投影采样阶段：按清单声明的旋转矩阵、平移向量与内参把每张分片的采样像素映射到世界射线，沿射线以配置步长读取图像颜色，输出带分片标识、世界坐标与颜色值的贡献记录；位姿矩阵非正交、内参焦距为零或采样点落在图像范围外时，须返回带分片标识与字段名的 E_POSE_INVALID 或稳定业务码，不得静默跳过。
2. 实现视角局部体素贡献体构建与全局融合：把采样点按体素分辨率量化到体素坐标，在截断距离内累计颜色与命中计数，再按分片序与视角内顺序把局部体素块融合为全局体素场，按融合半径加权平均颜色并按稀疏度阈值剪枝；融合权重归一化须显式可复算，同一体素被同视角多次命中时按确定性顺序合并。
3. 实现基于视角规模与体素分辨率的路径取舍：依据分片数、体素数、相机参数变化范围与全局重建预算，在逐视角全量重算、按块缓存复用与稀疏增量更新三种策略中选择一种，记录选择理由、候选打分明细与被淘汰策略原因；小规模场景须避免选择仅适合大规模场景的策略，大规模场景须避免逐视角全量重算。
4. 实现交互查询的延迟预算与缓存一致性：单次查询点云摘要、剔除原因或误差统计须在可配置延迟预算内返回，超出预算时返回带查询标识与已耗时字段的 E_LATENCY_BUDGET 结构化错误而非阻塞等待；缓存键须包含场景内容指纹、配置版本与相机指纹，缓存命中结果与重新计算结果逐字节相同。
5. 实现阶段检查点持久化与优雅停止恢复：每阶段完成时以原子方式写入含阶段名、分片标识、输入内容指纹、配置版本、产物摘要与单调序号的记录，写入任意位置中断不得留下半写记录；收到停止请求时完成当前不可拆分分片单元后退出，恢复后点云摘要、误差统计与稀疏度统计须与一次连续重建逐字节一致，且恢复不得依赖未提交的内存状态。
6. 实现版本变化检测与增量失效传播：当某分片像素、相机内外参、体素分辨率、截断距离、融合半径或采样密度任一变化时，通过各阶段内容摘要构成的版本指纹识别受影响的最早阶段，使该阶段及其全部下游产物失效并重建；未受影响视角的贡献体继续复用，增量结果须与从零全量重建逐字节一致，不一致须返回 E_INCREMENTAL_MISMATCH 并附首个差异体素坐标。
7. 实现并发阶段发布的互斥与快照整体替换识别：多工作进程对同一工作区发布阶段产物时使用真实文件锁与 SQLite 条件更新并比较分片内序号，仅允许序号连续推进，落后、重复或跨分片错位发布返回 E_STALE_CHECKPOINT；当检测到检查点记录被整体替换时，须区分回退、篡改与正常推进，仅正常推进被接受。
8. 实现数值精度自校验与业务错误码一致性：对重建点云抽样与清单声明的真值采样坐标比对，计算重投影误差与逐点偏差，超出可配置容差时返回 E_NUMERIC_MISMATCH 并附视角标识与最大偏差；输入图像像素含 NaN、视角数为零或采样密度非正等异常须在对应阶段返回稳定业务码，所有业务码同时以 JSON 字段与 stderr 输出一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
