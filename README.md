当前是空白工作区，需在 Windows 本地从零构建一个面向分布式对象存储读路径的副本读修复裁决与纠删码重建预算引擎，交付可交互的专业应用与可重复演示。本地确定性样本包含：对象分片布局清单（对象标识、数据分片数 k、校验分片数 m、各分片所在节点与磁盘、分片字节大小、分片摘要）与读请求轨迹（毫秒时间戳、对象标识、请求分片位图、客户端优先级、可容忍读延迟微秒）。读请求到达时，引擎须按节点健康与磁盘状态判定每个所需分片是否可读，对不可读分片在“直接失败返回”“读取其余副本补齐”与“用 k 个存活分片做纠删码重建”之间做优先级裁决，并在全局重建并发上限、单轮重建字节预算与每轮时间预算三重约束下并行推进重建任务，最后按稳定顺序归并出读结果并输出裁决轨迹。核心业务问题是并行重建与读延迟预算的耦合：重建能救回读请求却消耗带宽与 CPU，若不加约束会把整体读延迟拖垮，因此引擎必须在有限预算下决定哪些请求值得重建、哪些应快速失败，且同一轨迹重放必须得到逐位一致的裁决。进程可能在任意时刻被强制终止，重启后必须依据持久化事实恢复预算占用与任务状态。

任务环境与准备：
Windows 10 及以上本地环境，安装 Python 3.11 或 3.12，使用 venv 创建虚拟环境。
在虚拟环境中安装 FastAPI、Uvicorn、NumPy、pytest，版本取兼容 Python 3.11 的稳定版，无需联网下载模型或外部数据集。
准备本地确定性样本文件：对象分片布局 JSON（含 k、m、节点与磁盘、分片字节大小与摘要）与读请求轨迹 JSON（含固定随机种子生成的请求序列与分片位图）。
确保 Python 标准库 sqlite3 可用，并预留本地回环端口启动 HTTP 服务；不涉及 Docker 或其他容器环境。
准备一个本地脚本用于触发强制终止（发送终止信号或调用退出接口），以便验证预算占用与任务状态的恢复路径。

业务要求：
1. 实现对象分片布局与读请求轨迹的解析和归一化：解析 k 与 m 为正整数且 k+m 不超过声明上限，分片字节大小为非负整数并做溢出检查，分片摘要做格式校验；解析失败或对象标识缺失返回 E_LAYOUT_INVALID 且整批不加载，请求轨迹中时间戳非单调的记录整批拒绝并返回 E_TRACE_INVALID。
2. 实现分片可读性判定：对每个分片依据节点健康状态、磁盘状态与分片摘要复核结果判定可读或不可读，不可读须给出具体原因码（节点不可用、磁盘故障、摘要不一致、分片缺失）并输出可读分片位图；当可读数据分片数少于 k 时该请求判定为不可恢复并返回 E_UNRECOVERABLE，不得尝试非法重建。
3. 实现读修复裁决：对每个请求在直接失败、读取其余完整副本补齐与纠删码重建三种策略间按请求优先级、可容忍读延迟、重建开销估计与存活分片数做确定性优先级裁决，输出所选策略与裁决依据；若同一请求冗余副本足以补齐则不触发纠删码重建，禁止对可补齐请求滥用重建预算。
4. 实现纠删码重建计算：使用固定本地确定性矩阵与 Galois 域运算从 k 个存活分片重建缺失分片，重建结果的分片摘要须与布局清单声明一致，不一致返回 E_RECONSTRUCT_MISMATCH 并附分片标识与两侧摘要；k 与 m 的组合须在样本声明范围内并校验运算前提，超出返回 E_MATRIX_INVALID。
5. 实现三重预算约束的并行重建调度：以全局重建并发上限、单轮重建字节预算与每轮时间预算推进重建任务，预算内按请求优先级与到达顺序取任务，超出并发上限者进入有界等待队列，队列满返回 E_REBUILD_QUEUE_FULL；同一请求同一分片不得被重复重建，单轮内并发重建的合计字节数不得超过字节预算，超出时任务延后并输出预算消耗明细。
6. 实现低预算降级裁决与读延迟保护：当重建预算不足以覆盖全部待修复请求时，按优先级与已消耗预算给出确定性降级顺序，被降级请求改为快速失败并返回 E_REBUILD_SHED 并附降级依据；降级后仍须保证已开始重建的请求不被中断，且任一请求的端到端估计延迟不得超过其可容忍读延迟，超出则不得选择重建策略。
7. 使用 SQLite 持久化布局版本、请求裁决轨迹、重建任务状态与预算占用，所有写操作先落意图记录再提交事务；进程在重建或归并中途被强制终止后重启须扫描未完成意图，把已提交分片结果标记为可复用、未提交任务恢复为就绪并按持久化事实重算剩余预算，恢复报告仅包含已落盘事实且不得承诺强制终止后生成完整退出报告。
8. 实现单写者裁决与多读者查询的并发一致，并提供本地 HTTP 接口与可重复演示脚本：裁决与预算占用按轮次单写者串行执行，多个只读查询可并发读取已提交版本；查询不得看到请求已标记重建成功而预算占用未释放的中间状态，同一请求标识重复提交只裁决一次、其余等待复用结果，内容不一致返回 E_CONFLICTING_REQUEST；接口覆盖布局加载、轨迹提交、按轮次查询裁决轨迹与预算消耗、恢复报告查询，失败响应统一为含业务码的 JSON，至少覆盖 E_LAYOUT_INVALID、E_TRACE_INVALID、E_UNRECOVERABLE、E_RECONSTRUCT_MISMATCH、E_REBUILD_QUEUE_FULL、E_REBUILD_SHED。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
