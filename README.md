在 Windows 空白工作区中，需要从零构建一个面向本地列式快照数据的算子下推与列裁剪执行组件，供上层分析管线集成。输入为若干带版本号与校验摘要的本地列式快照（每列含数据类型与空值位图）以及一份逻辑查询计划（Scan、Filter、Project、Join、Aggregate、Sort），组件需按等价规则执行谓词下推、投影裁剪与常量折叠，生成物理执行计划并在本地数据上执行。为支撑持续分析场景，数据以带基础版本的增量批次追加，列统计与查询缓存以带版本号的派生结构维护；当某列的统计或数据分布变化时，依赖该列的缓存计划与裁剪结论必须级联失效并原子重建，不允许把新旧版本的统计混合使用。所有数据来自本地确定性样本，不依赖外部站点或服务。

任务环境与准备：
安装 Python 3.11 与 NumPy，使用标准库 sqlite3 持久化。
在空白工作区创建项目目录并准备固定本地列式快照样本与增量片段文件。
运行前确认无外部网络依赖，全部数据来自本地确定性样本。
使用本地 HTTP 框架启动服务并通过脚本完成演示与恢复验证。

业务要求：
1. 实现列式快照加载与版本识别：快照携带单调递增版本号、生成时间与校验摘要，包含各列数据、数据类型与空值位图；加载时校验版本单调与摘要，失败返回业务码 E_SNAPSHOT_INVALID，且加载失败必须保持旧快照可用；整体替换须识别版本变化而非逐列混合新旧内容，版本相同但摘要不同须拒绝并保持旧快照。
2. 实现逻辑计划解析与规范化改写：至少支持 Filter 下推至 Scan 之上、投影裁剪未被上层引用的列与常量折叠三类规则，改写须保持语义等价；当规则会改变聚合语义、HAVING 引用被裁剪列或排序键丢失时，必须拒绝该条规则并记录冲突节点与规则名，不得静默产出错误计划。
3. 实现增量批次追加与基础版本校验：增量片段只含新增行及受影响的列统计，并携带所基于的快照版本；若基础版本不是当前版本则返回 E_STALE_BASE 且不改变任何已提交状态；仅追加且时间戳单调时走快速路径不做全量统计重建，否则走重建路径并输出重建原因与受影响列清单。
4. 实现统计依赖失效与级联重建：为每列维护其对选择率估算、裁剪结论与缓存物理计划的引用关系；某列统计或数据分布变化时，受影响列的全部派生结构及其下游查询缓存必须级联失效并在同一事务边界内原子重建，禁止出现部分缓存已重建而依赖它的计划仍按旧统计裁剪的中间可见状态。
5. 实现并发一致的单写者执行：计划规范化、缓存重建与批次追加按提交串行执行，多个只读查询可并发读取已提交版本；同一请求标识重复提交只执行一次、其余等待复用结果；查询请求绑定的快照版本若在执行期间被替换，须在该版本上完成或返回 E_VERSION_RETIRED，不得读取更高版本的列数据。
6. 实现 SQLite 意图持久化与强制终止恢复：批次追加与缓存重建前先写意图记录再提交事务；进程在级联重建中途被强制终止后重启须扫描未完成意图，把缓存与统计回滚到最后一个完整版本或将对应提交标记为已中止，恢复报告只基于已持久化事实，不承诺强制终止后仍生成完整退出报告。
7. 实现定点数值契约与计划可解释输出：选择率与代价各分项在 JSON 输出中保留固定小数位并附舍入误差累计说明，计划优劣比较使用带相对容差的比较而非裸浮点比较，容差内按稳定字典序打破平局；同一输入重复请求须返回逐位一致的规范化计划与实际扫描列集合，并在计划说明中标注每条改写规则的适用或拒绝依据。
8. 提供统一错误响应与可复现实验脚本：失败响应为含业务码与上下文的 JSON，至少覆盖 E_SNAPSHOT_INVALID、E_STALE_BASE、E_PLAN_INVALID、E_VERSION_RETIRED、E_RULE_REJECTED 与 E_CONFLICTING_BATCH；脚本使用固定本地样本完成一次全量加载与执行、一次仅改单列统计触发裁剪结论级联失效的增量、一次并发重复提交与一次强制终止后恢复，输出扫描列集合、行为计划变更与恢复前后统计版本差异。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
