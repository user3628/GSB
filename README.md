为稀疏推理算子团队从零构建一个本地可运行的稀疏矩阵乘（SpMM）组件，核心问题是行分块调度与稀疏度驱动路径取舍下的数值精度与误差传播诊断。工作区为空，需自行初始化项目。输入是本地确定性生成的稀疏样本目录：一份矩阵描述 JSON，声明左稀疏矩阵 CSR 结构（行指针、每行按列下标升序存放的列下标数组与对应非零元值数组）、右稠密矩阵形状与 dtype（float32 或 float64）、稠密矩阵数据文件相对路径；另有一份调度与精度配置，声明分块尺寸、稀疏度分支阈值、累加精度策略、稠密化代价阈值与浮点容差。稠密矩阵与 CSR 非零元由固定种子的本地脚本生成，不依赖网络与外部数据集。组件须在按行分块累加与稀疏度驱动的路径选择下产出稠密结果，同时给出逐输出元素的误差溯源与整体不确定度，使下游能判断该结果是否可作为参考基准；此外需以本地 SQLite 持久化块级进度，支持强制终止后的续算。

任务环境与准备：
安装 Python 3.10 及以上版本，并准备可用的虚拟环境。
通过 pip 安装 numpy、fastapi、uvicorn、pytest，不要求任何 GPU 或外部服务。
使用项目内脚本以固定种子生成 CSR 稀疏样本与稠密矩阵文件，样本与配置保存在本地目录，不依赖网络下载。
确认本地端口可用于启动 FastAPI 服务，SQLite 使用 Python 标准库自带实现，无需额外安装。

业务要求：
1. 组件须提供矩阵装载接口，解析并校验矩阵描述 JSON 与稠密数据文件：行指针单调不减且首尾与行数加一匹配、列下标均落在稠密矩阵行数范围内且行内严格升序、值数组长度与列下标长度一致、dtype 仅为 float32 或 float64、稠密文件记录数与声明形状一致；任一非法返回 E_STRUCT 业务码并定位到矩阵名与出错下标，且不得写出任何结果文件或临时目录。
2. 须实现按行分块的确定性 SpMM：以配置给出的分块尺寸把行区间划分为块，块内逐行、行内按列下标升序累加非零元与稠密矩阵对应行，尾块必须走同一累加路径而非退回整块拷贝；任意合法分块尺寸下的结果须与不分块直接累加在声明容差内一致，超出容差返回 E_PRECISION 并指出首个不一致的输出元素下标与两路径取值。
3. 须实现稀疏度驱动的路径取舍：按每块非零元密度与稠密化代价阈值在稀疏分块路径与稠密化路径之间选择，并输出逐块路径决策记录（含块序号、密度、估算代价、所选路径与理由）；同一输入与配置下路径决策序列须完全可重复，稠密化路径须显式补齐被跳过的零元累加语义，使切换路径不改变块内累加顺序语义。
4. 累加精度策略须显式支持 float32 累加与 float64 累加两种模式：输入为 float32 且选择 float64 模式时须先提升再累加、最后按目标 dtype 声明舍入，并输出逐块提升次数、舍入次数与两模式同一输出元素最大绝对差及出现位置；两种模式的结果差异不得因分块尺寸变化而改变符号。
5. 误差溯源须逐输出元素可观测：每个输出元素的误差估计由该行参与累加各非零元的相对误差与权重平方和合成，并须给出稠密化路径相对稀疏路径的额外舍入贡献；不确定度须能回溯到具体矩阵名、行号与列下标，超出容差的输出元素须在诊断报告中单列而不得被静默包含进最终结果。
6. 进度的持久化须以矩阵、行块两级记录在 SQLite 中提交，单块的累加中间量摘要、路径决策与块进度须在同一事务中写入；某块失败时该块整体回滚且不得留下部分写入，重复执行同一块不得在其上重复累加；每次完整计算须以整体替换方式生成版本化快照，读取时若检测到块结果内容哈希与数据库记录不一致、配置指纹变化或残留旧版本块文件须返回 E_STALE 并定位到块序号。
7. 进程被强制终止后重启，须从 SQLite 已提交的块进度继续，核对每个矩阵的行块处理标记、块结果内容哈希与快照版本，重算未提交块且不重复消费已提交块；恢复后的逐元素结果、逐块路径决策序列与快照版本须与无中断执行完全一致。
8. 须提供确定性本地演示入口与集成示例：用本地生成的 CSR 样本覆盖非方阵、行内非零元数量悬殊、尾块不对齐、稠密化阈值附近密度与中断恢复场景，跑出各矩阵所选路径、分块数、两种累加模式差值、超容差元素数、恢复前后一致性结论与快照版本序列的可重复结果，并给出可用等价参数复现的调用示例。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地稀疏样本验证分块结果、路径决策、两精度模式差异与中断恢复一致性，附可复现运行结果。
