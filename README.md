当前为空工作区，需从零构建一个本地可运行的 LoRA 参数高效微调并行调度工作台，面向小规模 Transformer 语言模型的适配器训练实验。输入为本地确定性 JSONL 指令样本（含 id、instruction、output、lang、source）与一份 YAML 实验配置，配置描述多条待训练的 LoRA 实验任务（每条含 rank、alpha、目标模块名列表、学习率、批大小、梯度累积步数与最大步数），以及全局资源预算：并行工作进程上限、单任务最大样本数配额与全局总样本消耗上限。样本与配置由固定随机种子的生成器产出，模型为一个本地随机初始化的小型 Transformer 编码器变体，权重由固定种子生成并以本地文件存放，不依赖任何外部模型、GPU 或在线服务。系统需要完成：LoRA 层注入与本地训练步核心、基于预算的任务接纳与并行调度、进度检查点持久化与中断恢复、配置版本变化后的任务失效与重建、并发发布保护，以及一个可交互的工作台应用用于查看各任务状态、预算消耗与训练摘要。核心难点在于并行调度与资源预算约束之下，多任务训练状态必须保持一致且可恢复，同时不得让预算之外的资源被隐性消耗。

任务环境与准备：
安装 Python 3.11 并在项目虚拟环境中安装 torch、numpy、fastapi、uvicorn、pyyaml、pytest 的固定版本，记录版本清单。
准备本地确定性样本与模型权重生成脚本：以固定种子生成 JSONL 指令样本、YAML 实验配置与小型 Transformer 初始化权重文件，生成后校验摘要。
确认可在 Windows 下启动本地 HTTP 服务与多进程工作池，准备用于演示停止与恢复的运行脚本及错误注入参数清单。

业务要求：
1. 实现 LoRA 注入与本地训练步核心：对配置中声明的目标模块注入低秩适配矩阵（A 用固定种子初始化、B 置零），前向时以缩放系数 alpha/rank 叠加原输出，仅适配矩阵参与梯度更新；同一配置与样本顺序在固定随机种子下必须产生逐位相同的损失序列与适配器权重摘要，且禁止使用任何外部预训练权重或在线服务。
2. 实现资源预算约束下的任务接纳调度：以实验任务为单位，在并行工作进程上限、单任务样本配额与全局总样本消耗上限三重约束下决定接纳顺序与并发度；接纳前按配置与样本实际条数预估消耗，超预算任务记录为未启动并给出原因分类，任何时刻累计样本消耗不得超过全局上限，且并发工作进程数不得超过上限。
3. 实现并行训练与确定性归约：使用本地进程池并行执行多个已接纳任务，各任务的损失序列与最终适配器摘要按任务序号全局排序后归约，使并行运行的汇总输出与串行顺序执行逐字节一致；工作进程异常时以结构化错误对象记录任务标识与步序号并继续处理其余任务，不得以线程或进程超时描述为已终止失控计算。
4. 实现进度检查点持久化与优雅停止恢复：每个任务按固定步数间隔与结束时以原子方式写入含任务标识、已完成步数、输入样本指纹、配置版本、适配器权重摘要与单调序号的记录，写入任意位置中断不得留下半写记录；收到停止请求时完成当前不可拆分的训练步后退出，恢复时忽略损坏或不完整记录，从最近一致检查点继续，最终汇总须与一次从零完整运行的结果逐字节一致。
5. 实现配置变更后的任务失效与重建：当某任务的 rank、alpha、目标模块、学习率、批大小或对应样本内容变化时，通过版本指纹识别该任务内受影响的最早检查点并使该任务后续状态失效重建，未受影响任务与未变化任务的检查点继续复用；全局预算变化须触发重新调度决策，重调度后不得复用已因预算不足被判为未启动的任务记录，失效原因与指纹须在查询接口中可观测。
6. 实现并发发布保护与业务错误码一致性：多个工作进程对同一工作区发布检查点时使用文件锁并比较任务内序号，仅允许序号连续推进，落后、重复或跨任务错位发布返回 E_STALE_CHECKPOINT；请求恢复一个不存在前置检查点的任务、提交非法 rank 或负学习率时返回 E_INVALID_TASK，预算不足启动返回 E_BUDGET_EXCEEDED，权重摘要不匹配返回 E_WEIGHT_MISMATCH，错误对象须含任务标识与定位字段。
7. 实现交互式工作台应用与诊断查询：提供本地 HTTP 接口与命令行，支持导入样本与实验配置、查看各任务状态与配置版本指纹、查询预算消耗明细与未启动任务原因、触发停止与恢复、导出各任务损失曲线与适配器摘要；所有查询须反映当前持久化状态而非内存猜测，非法阶段跳转返回稳定业务码。
8. 提供本地确定性演示与可重复验证脚本：演示数据至少含 3 个实验任务、中英混排样本与至少 1 个必然超预算的任务，模型权重与样本均由固定种子生成并可重建；一次完整运行生成固定摘要，演示中在训练步之间触发停止后恢复，并用注入的非法 rank、超预算配额与损坏检查点验证恢复结果及错误码。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
