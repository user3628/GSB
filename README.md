当前是空白工作区，需要从零构建一个面向本地多逻辑库的分片路由计划组件，供上层数据访问层集成。集群由若干逻辑库组成，每个逻辑库包含若干分表，分片规则以带版本号的 JSON 快照描述：分片键、取模或范围算法、逻辑表到物理表的映射、各物理表声明的行数统计与路由版本。与只做路由计算不同，本组件关注的是「路由计划代价」这一派生层：每个逻辑表的查询需要依据各目标物理表的行数统计与谓词选择率估算出访问代价，并据此决定是走单分片路由、多分片并行路由还是全分片扫描，同时把代价分解输出给上层优化器。当统计快照或分片规则以增量片段更新时，受影响的计划代价缓存、选择率估算与访问策略判定必须级联失效并按版本原子重估，禁止新旧统计混合产生代价误判。所有数据来自本地确定性样本，不依赖真实数据库集群。

任务环境与准备：
安装 Python 3.11 及以上解释器，并确保 pip 可用。
创建虚拟环境后安装 FastAPI、uvicorn、NumPy 与 pytest，版本以安装当日稳定版为准。
在工作区新建项目目录，预先准备两份带版本号与绑定关系的分片规则与统计快照 JSON、一份统计增量片段及本地 SQLite 样本库。
确认本地回环端口可用，演示脚本以 uvicorn 启动服务并自行关闭，不依赖任何外部网络或账号。

业务要求：
1. 实现分片规则快照与统计快照的联合加载与版本识别：两份快照各自带有单调递增版本号、生成时间与整体校验摘要，并声明它们之间的绑定关系；加载时须同时校验版本单调与摘要，任一失败返回 E_SNAPSHOT_INVALID 且保持已加载的旧版本不变；统计快照与分片规则快照的绑定版本不一致时不得进行代价估算，须返回 E_SNAPSHOT_MISMATCH。
2. 实现谓词选择率与单物理表访问代价估算：对等值、范围与 IN 列表谓词依据物理表声明行数与分片键区间估算选择率，结果落在 (0,1] 且对零行物理表返回确定值而非除零；单表访问代价分解为扫描行数估计、回表比例与固定启动开销三项，各分项以定点小数输出并附舍入说明，同一输入重复估算必须逐位一致。
3. 实现访问策略裁决：依据单分片与多分片的代价对比、可选的全分片扫描代价以及请求声明的代价上限，裁决为单分片路由、多分片并行路由或全分片扫描；当三种策略中最小代价仍超过声明的代价上限时必须返回业务码 E_COST_BUDGET_EXCEEDED 并附各策略代价与上限，禁止在超限时静默选择最低代价继续执行。
4. 实现统计增量更新与代价缓存级联失效：统计增量片段只含受影响的物理表并携带基础版本，基础版本非当前版本时返回 E_STALE_BASE 且不改变任何已提交状态；受影响物理表的选择率估算、单表代价与依赖它们的逻辑表访问策略判定必须级联失效并在同一事务边界内原子重估，禁止出现部分物理表统计已更新而策略判定仍基于旧代价的中间可见状态。
5. 实现计划缓存与路由版本绑定：查询请求可指定分片规则版本与统计版本，缓存键须同时包含两版本标识；当请求绑定的版本在估算期间被新版本替换时，须在该绑定版本上完成重估或返回 E_VERSION_RETIRED，不得把新统计结果写入旧版本缓存；只读查询读取缓存时只能看到某一完整重估版本，不得读取半重建的代价条目。
6. 实现单写者重估与幂等复用：快照提交、增量更新与级联重估按单写者串行执行，多个只读查询可并发；同一请求标识重复提交只执行一次、其余等待并复用同一结果，内容不一致返回 E_CONFLICTING_REQUEST；并发提交同一基础版本的两个统计增量时只允许一个成功、另一个必须收到 E_STALE_BASE。
7. 实现基于 SQLite 的意图持久化与强制终止后恢复：快照提交、增量重估与计划缓存写入前先写意图记录再提交事务；进程在级联重估中途被强制终止后重启须扫描未完成意图，把统计与代价缓存回滚到最后一个完整版本或将对应增量标记为已中止，恢复报告只基于已持久化事实，不得承诺强制终止后仍生成完整退出报告。
8. 实现可复现异常注入与本地演示：请求参数可注入统计行数为负、物理表映射缺失、绑定版本不匹配、代价上限过小与重估中途中断标记五类情形，各类返回互不相同的业务码且错误体为含业务码与上下文的 JSON；提供固定本地样本与演示脚本，完成一次基线代价估算、一次统计增量触发的局部重估、一次跨版本缓存命中与一次强制终止后恢复的端到端演练并输出代价分解与重估轨迹。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
