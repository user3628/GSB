某模型推理平台需要从零构建一个可交互的多租户批处理调度工作台，面向多个租户提交的推理请求在共享算力预算下完成准入仲裁、批次合并与结果归并。输入是本地样本目录：一份请求清单 JSONL，每条含 request id、租户名、模型标识、输入 token 序列（长度上限固定）、优先级档位与提交序号；一份租户配置 JSON，声明每个租户的算力配额单元、是否允许被抢占与允许并发批次数；一份模型目录 JSON，声明每个模型的隐藏维度、分块尺寸与每单元算力消耗。工作区为空，需从零创建 FastAPI 服务与确定性伪推理器，不使用真实模型权重，全部计算由本地样本与种子决定，需支持查询进度、导出快照与崩溃后恢复。

任务环境与准备：
安装 Python 3.11 及以上版本，创建虚拟环境并安装 fastapi、uvicorn、numpy 与 pytest，SQLite 使用标准库 sqlite3。
在空工作区初始化项目目录，自行生成请求清单 JSONL、租户配置 JSON、模型目录 JSON 等本地确定性样本，不依赖任何真实模型权重或线上服务。
准备手动触发强制终止与重启的操作说明，用于验证断点恢复；准备等价参数提交示例以便重复演示调度与快照结果。

业务要求：
1. 作业创建接口接收请求清单、租户配置、模型目录与随机种子，校验 request id 唯一、租户名与模型标识均已声明、输入 token 序列非空且为有限整数、优先级档位非负、租户配额单元与并发批次数为正整数；任一非法返回 E_PARAM 业务码并指出出错文件与行号，且不得写入任何批次或预算记录。
2. 确定性伪推理须由模型标识、token 序列与种子派生分块矩阵，按隐藏维度分块归约得到逐请求分数，归约在 float64 下按固定顺序累加；相同输入与种子下逐请求分数逐位一致，且合并成批计算与单请求计算必须得到相同结果。
3. 请求须按模型标识合并成批，批内按优先级档位降序、同档按提交序号升序稳定排列；批次完成后把结果拆分归并回原 request id，并记录每批包含的请求集合、批内顺序与归一化结果来源，重复运行时这一归并映射须完全可重复。
4. 算力预算须按租户配额与全局预算单元双重仲裁：每批开始前按合并后的估算消耗原子扣减租户配额与全局预算，租户配额不足时该租户请求进入等待队列，全局预算不足时按租户名与提交序号确定性选择允许抢占的租户批次并记录抢占事件。
5. 须实现幂等提交：相同 request id 重复提交返回已有结果的归并视图，不重复计算也不重复扣减预算，并在归并记录中给出首次提交序号与本次重复次数；request id 相同但内容不同时返回 E_DUP 并列出冲突字段。
6. 批处理进度须在 SQLite 中以租户、批次、请求三级记录事务提交，单批的输出分数、预算扣减明细与归并映射在同一事务中写入；批次失败时该批整体回滚并归还已扣减预算，不得留下部分请求结果或与归并记录不一致的预算余额。
7. 每次完整调度须整体替换生成版本化快照，含配置指纹、各批次合并摘要、逐租户预算余额与结果文件内容哈希；读取快照时若检测到数据库版本与磁盘结果文件哈希不一致、配置指纹变化或残留旧版本结果文件，须返回 E_STALE 并定位到批次与租户。
8. 进程被强制终止后重启，须从 SQLite 已提交批次进度继续，核对每个租户的已提交批标记、预算余额与快照版本，重算未提交批次且不重复计算已归并请求；恢复后的逐请求分数、逐租户预算余额与快照版本序列须与无中断执行完全一致，并提供确定性演示入口输出可重复结果。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证批次合并、预算仲裁、幂等归并与强制终止后恢复结果与无中断执行一致。
