为语音情感与对话理解团队从零构建一个本地可运行的工作台，核心问题是数据规模变化时的算法取舍与共享预算下的并行调度。输入是本地样本目录：一份对话清单 JSONL，每条含 dialog id、说话人数量、采样率（8000 或 16000 Hz）、若干轮次（每轮含 turn id、起止毫秒、转写文本、语气标签与对应的本地合成 PCM WAV 路径）；每个音频为确定性合成的 16 位单声道片段，按轮次切分，含基频与能量变化。另有一份情感词表 JSON，声明情感类别名、固定维度嵌入向量与情感强度范围。团队需要在工作台中完成帧级声学特征提取、情感打分与对话级聚合，并在全局预算约束下并行处理多个对话。工作区为空，需从零创建项目：一个可交互的 FastAPI 服务，提供工程创建、预览与全量执行、查询对话状态、导出快照与诊断报告接口。难点在于：同一对话在低延迟预览时与全量重算时必须得到完全一致的帧级特征与情感分，而规模增大后必须切换到分块索引路径仍保持结果一致，且并发下预算不得超扣。

任务环境与准备：
确认使用 Windows 本地 Python 3.11 环境，安装 numpy、fastapi、uvicorn、pytest，版本以任务执行时可用为准。
在空工作区初始化项目目录，自行编写脚本用确定性参数合成对话音频样本、对话清单与情感词表，并保证样本覆盖 8000 与 16000 Hz、不同帧长帧移与不同对话规模。
准备本地 SQLite 文件与结果输出目录，演示入口须可在无网络、无外部账号条件下重复运行。
准备强制终止与重启的演示方式（本地进程启动与停止脚本），用于验证恢复一致性，不依赖容器环境。

业务要求：
1. 工程创建接口接收对话清单、情感词表、帧长与帧移毫秒、全局预算单元与并行并发上限，校验 dialog id 唯一、WAV 头采样率声道与清单一致、帧长与帧移为正毫秒且帧移不超过帧长、嵌入维度与词表一致、预算与并发上限为正整数；任一非法返回 E_PARAM 或 E_AUDIO 业务码并指出文件与行号，且不创建任何结果文件或临时目录。
2. 须实现确定性帧级声学特征提取：各声道按清单下混为单声道，按帧长与帧移划分帧并加显式窗函数，由短时能量、过零率与基频估计派生固定维度特征向量，全部以 float64 计算；同一音频与参数下逐帧特征须逐位一致，帧数换算须声明取整规则并写入结果摘要，不得依赖全局随机状态或系统时钟。
3. 须实现精确扫描与分块索引两条特征计算路径，路径选择由对话总帧数与规模阈值共同决定并输出路径决策记录（含选择理由、块数、实际处理帧数）；同一对话在两条路径下产出的逐帧特征与情感分须完全一致，超出容差须返回 E_VERIFY 并定位到 dialog id 与帧下标。
4. 情感打分须由帧特征与情感词表嵌入的余弦相似度按可配置权重融合，余弦统一用 float64 并在对数域处理极端分数，同分时按情感类别名字典序稳定选择；轮次级得分须按帧时间区间聚合、对话级得分须跨轮次加权聚合，逐对话的得分序列与聚合顺序须可复现。
5. 预览接口须在低延迟预算内返回所选对话的帧数、轮次边界摘要、若干帧特征与当前情感分，且必须与同一参数走全量执行得到的结果完全一致；检测到预览与全量结果存在任何差异时返回 E_VERIFY 并给出首个不一致的帧下标，预览不得以抽样或跳过帧替代。
6. 服务须支持多对话并发处理并共享创建时给定的全局预算单元：每对话每帧特征提取与每轮打分按其帧数与配置消耗预算，任务开始前原子扣减、结束后归还，预算不足时按 dialog id 字典序排队而非阻塞等待或超额执行，并发下预算扣减总量不得超过给定值。
7. 须实现整体替换的版本化快照与缓存失效：快照含配置指纹（帧长帧移、规模阈值、情感权重与词表版本）、逐对话帧摘要与结果文件内容哈希；读取快照时若检测到数据库版本与磁盘文件哈希不一致、配置指纹变化或残留旧版本文件，须返回 E_STALE 并定位到 dialog id，禁止汇入旧数据。
8. 对话进度须在 SQLite 中以对话、阶段、帧三段记录事务提交，单帧特征写入与进度标记在同一事务中完成，结果文件先写临时文件再原子替换并登记内容哈希；进程被强制终止后重启须从已提交帧继续，核对阶段标记与文件哈希，重算未提交帧且不重复消费已提交帧，恢复后的逐帧特征、对话得分与快照版本序列须与无中断执行完全一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地合成对话验证预览与全量一致、路径结果一致、并发预算不超扣及强制终止后恢复一致。
