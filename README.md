项目从零开始，需要为安全运营团队的本地取证流程构建一个审计事件关联与取证工作台。团队从 Windows 主机侧收集到多种来源的审计记录：一类是自研的紧凑二进制审计日志（带版本头、变长事件、尾部校验块），一类是外部系统导出的 JSON 行格式事件，还有一类是旧版工具产出的带长度前缀的文本块格式。这些格式在字段命名、时间戳编码（epoch 毫秒、RFC3339、Windows FILETIME 1601 纪元）与事件类型枚举上互不兼容，且版本头存在 v1/v2 两代语义差异。工作台需要把多格式事件规范化到统一时间轴，按会话与进程谱系做关联取证，维护可版本识别的解析与关联快照，并在格式或版本不兼容时给出可追溯的业务码。

任务环境与准备：
Windows 10/11 或 Windows Server 2019 及以上，安装 Go 1.22 或以上（官方安装包），确认 go version 可用。
使用 Go 标准库与纯 Go 实现的 SQLite 驱动（如 modernc.org/sqlite），通过 go mod 安装，不依赖 CGO 与容器环境。
在项目内提供本地样本生成程序，确定性生成 v1/v2 二进制审计日志、JSON 行事件、文本块格式及五类畸形样本到本地临时目录，不依赖真实账号或线上资源。
运行 go mod tidy 完成依赖下载后，使用 go build 与 go test 在本机验证，所有读写限定在本地工作目录内。

业务要求：
1. 实现三种审计源格式的解析与规范化：二进制审计日志按版本头判定 v1/v2 字段布局，JSON 行格式逐行解析，文本块格式按长度前缀提取记录；统一转换为包含来源、原始偏移、事件类型、主体、对象与规范化时间的中间事件，未知事件类型降级保留原始载荷并标记 E_UNKNOWN_EVENT 而非丢弃。
2. 实现跨格式时间戳互操作：epoch 毫秒、RFC3339 与 Windows FILETIME（1601 纪元，100ns 单位）三类时间统一换算为 UTC 纳秒整数，FILETIME 换算须检查 int64 溢出与精度截断，换算失败返回 E_TIME_OVERFLOW 并保留原始值与来源偏移；同一事件在归一化后重复换算结果须字节级一致。
3. 实现按会话与进程谱系的事件关联：依据进程创建事件建立父子关系，把同一会话内的文件、注册表、网络与进程事件挂接到对应进程节点，对孤儿子进程（父进程创建事件缺失）标记 E_ORPHAN_REF 并挂到虚拟根节点；关联结果须能定位每条边到其来源格式与原始偏移，禁止跨会话误连。
4. 实现带版本号的取证快照与版本兼容加载：每次完成一轮解析与关联后提交快照，快照携带递增版本号与所依赖的格式版本集合；加载旧快照时若其格式版本与当前解析器不兼容，须整体拒绝并返回 E_SNAPSHOT_VERSION_INCOMPAT，不得部分加载；版本链跳号同样拒绝并回退到最近连续版本，整体替换式快照即使版本号相同也必须通过内容对比识别为版本变化。
5. 实现混入畸形输入时的异常链路：构造截断二进制事件、JSON 行字段类型错误、文本块长度前缀超出剩余字节、FILETIME 溢出时间戳、未知二进制版本号五类样本，分别给出稳定业务码、跳过范围与已成功事件计数，畸形输入不得中断其余源文件的解析，也不得污染已提交快照。
6. 实现并发多源取证调度与资源控制：各源文件在独立解析会话中处理，会话间状态隔离；并发度与单会话事件上限可配置，超上限的源进入等待队列而非直接拒绝，单会话事件数超限时以 E_EVENT_BUDGET 终止该会话并保留已解析部分，汇总时按源路径与业务码聚合。
7. 导出结构化取证报告与统一时间轴视图：JSON 报告包含各源解析摘要、统一时间轴事件序列、进程谱系边、错误码及原始偏移、快照版本号；时间轴按规范化时间稳定排序，同时间事件按来源路径与偏移次级排序，报告中的版本号必须来自实际提交的快照递增，不得预估；交互视图须能按会话过滤并展示单事件的多格式来源对照。
8. 提供确定性演示入口与格式版本切换：使用本地生成的确定性样本集（覆盖 v1/v2 二进制、JSON 行、文本块及五类畸形样本）一键运行，重复运行且输入不变时报告字节级一致；支持通过参数选择目标格式版本与继续/放弃两种畸形处理策略，策略切换须体现在报告的错误处理摘要中而不得改变正常事件结论。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地多格式样本验证规范化时间轴、进程谱系关联、快照版本拒绝及五类畸形输入的稳定业务码，重复运行报告一致。
