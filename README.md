当前是空白工作区，没有现存项目、代码或数据附件。需要从零实现一个面向本地 MySQL 风格主从复制场景的「复制延迟可观测与诊断工作台」，用于在离线环境下复现真实主从复制中由格式与版本差异导致的延迟观测失真问题。系统由主库桩与两个从库桩组成：主库以两种二进制日志格式（STATEMENT 与 ROW）并行产出事务事件，每类事件带有格式版本号（v1 或 v2）、库级位点与事务提交位点；从库按版本化解析器重放事件并持续上报重放位点、已应用事务摘要与本地中继日志段。采集侧需把主库提交时间戳、从库重放时间戳、位点三者在同一逻辑时钟体系下对齐，产出秒级延迟序列与分位统计，并在检测到格式降级、版本不兼容或位点回退时给出可追溯诊断报告。真实场景中 STATEMENT 与 ROW 两种格式产生的事件粒度不同，v1 与 v2 的位点字段宽度与时间戳精度不同，采集对齐错误会系统性放大或抹平延迟，因此工作台必须显式区分观测失真与真实延迟并在诊断中给出判定来源。

任务环境与准备：
确认 Windows 上可用 Python 3.11 或更高版本，并通过 pip 离线安装 FastAPI、uvicorn 与 pytest。
创建空白工作目录作为项目根，准备本地主从桩配置与固定随机种子的样本生成脚本所需的目录结构，不引入容器或外部数据库服务。
确认 SQLite 由 Python 标准库内置可用，检查临时目录可写以便持久化数据库文件与测试隔离目录。
运行前检查端口占用，为主库桩、从库桩与工作台 HTTP 接口分配本地回环端口，所有测试在离线环境下执行。

业务要求：
1. 实现复制事件与位点的多版本编解码：主库事件须携带格式类型（STATEMENT 或 ROW）、格式版本（v1 或 v2）、库级位点、事务提交位点、提交时刻与事务摘要；v1 与 v2 的位点字段宽度与时间戳精度不同，须在解码后统一投影为内部表示并保留原始版本标签。遇到未知格式版本、格式类型与事件体不匹配或事务摘要不符须返回 E_FORMAT_UNSUPPORTED 且不得进入后续对齐流程。
2. 实现主从位点对齐与延迟序列计算：采集器须按逻辑时钟把主库事务提交位点与从库重放位点配对，为配对记录计算延迟毫秒并写入秒级延迟时间桶；配对须考虑从库可能在事务中途上报重放位点，未完整应用的位点不得参与配对。同一事务重复上报须幂等，位点回退须记录为异常而非计算负延迟，并以 E_POSITION_REGRESS 报告。
3. 实现两种格式的粒度差异归一：STATEMENT 格式事件按语句计数，ROW 格式事件按行计数且一个事务可能对应多条行事件，工作台须在事务层面归一化后才能比较延迟；归一化须保留原始事件计数与事务级聚合计数两套视图，使大事务在两种格式下的延迟可对比。当某从库仅支持单一格式而主库并行产出两种格式时，诊断须标出该从库的观测覆盖缺口。
4. 实现观测失真与真实延迟的区分判定：须基于提交时刻与重放时刻的精度损失、格式归一化引入的计数偏差以及位点配对所依据的同步标记，给出每次延迟采样的失真上界；当延迟波动完全落在失真上界之内时须标记为观测噪声而非真实抖动，超出部分才计入真实延迟。失真上界须以十进制定点字符串输出分解项与合成值，判定来源须可追溯。
5. 实现延迟分位统计与诊断报告：按从库与格式维度计算延迟的 p50、p95、p99 与最大值，分位须在固定桶数下用确定性算法计算且可在相同输入下复现；诊断报告须列出失真标记占比、位点回退次数、版本不兼容事件数与覆盖缺口。跨格式对比同一事务的延迟时须说明归一化依据，不得直接把两种格式的原始计数混算。
6. 实现并发采集与事件写入的一致性：多个从库上报与采集器诊断查询可并发进行，查询须看到一致的时间点快照，不得观察到某从库位点已推进但延迟序列未更新的中间状态；延迟桶与诊断结论须在单事务中提交后才对查询可见。并发锁等待须有真实超时并返回 E_CONTENTION_TIMEOUT，不得以休眠代替资源控制。
7. 实现进程重启后的采集恢复与失真重算：从库上报水位、延迟时间桶、配对记录与诊断结论须持久化到 SQLite，重启后须从中断处继续采集，未提交事件丢弃且不得产生重复配对；对重启窗口内缺失的采样须判定为观测空洞而非零延迟，并在恢复后按同步标记重算受影响桶的失真上界。
8. 提供本地确定性主从桩与可重复测试：实现可配置格式组合、版本、事件粒度、上报延迟与故障注入的本地主从桩，不依赖外网真实数据库；pytest 用例须在 Windows 离线覆盖跨版本解码拒绝、位点回退、格式归一化、失真上界判定、并发快照与重启恢复，并在固定种子下可重复运行。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地主从桩生成跨格式跨版本复制流，验证延迟序列、失真判定与重启恢复结果一致且异常码正确。
