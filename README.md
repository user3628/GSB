在 Windows 空白工作区中，需要从零构建一个面向本地单机 GPU 资源池的配额调度与推理批处理预算裁决引擎，供集群管理员离线评估一组推理服务请求能否被放入若干逻辑 GPU 节点，并诊断判定过程中的配额传播与批组织取舍。节点规格由本地确定性 JSON 样本提供：每个逻辑节点声明总显存（字节整数）、可用算力份额（千分之一为单位的整数）、已占用显存、配额组标识与健康状态。请求声明服务名、模型标识、显存需求、每批样本数、期望批延迟上限、优先级与所属配额组。系统需依据配额组的显存与算力上限做准入判定，按模型与节点组织推理批，并在全局并行调度预算与每轮时间预算约束下推进批执行，所有结果须持久化并可在进程被强制终止后依据持久化事实恢复。

任务环境与准备：
安装 Python 3.11 或更新版本，并安装 Flask、NumPy 与 pytest。
在空白工作区创建项目目录，准备本地确定性 JSON 样本：节点清单（总显存、可用算力份额、已占用显存、配额组、健康状态）、配额组声明（显存上限与算力上限）、请求轨迹（服务名、模型标识、显存需求、每批样本数、期望批延迟上限、优先级、配额组）与模型清单（最大批样本数、单位样本代价）。
无需容器或外部服务，所有节点为本地逻辑节点，所有数据来自本地样本。
确保进程具备文件写入权限以创建 SQLite 数据库与意图日志文件。

业务要求：
1. 实现节点与配额组规格的解析与归一化：显存以字节整数、算力份额以千分之一整数为内部表示，解析样本中形如 40Gi、512Mi、250m 的量纲字符串并做溢出与负数检查，解析失败返回 E_SPEC_INVALID 并指明字段；配额组声明显存上限与算力上限，节点与请求都必须归属已声明的配额组，未知配额组返回 E_QUOTA_GROUP_UNKNOWN。
2. 实现配额组准入判定：成员节点的已占用显存与算力份额，加上该组已准入请求的预留量，共同计入配额组占用；请求准入后预留量须在同一事务内计入配额组，超额返回 E_QUOTA_EXCEEDED 并附当前占用、预留量与请求量；准入成功的请求进入 ADMITTED 状态，准入失败不得留下部分预留。
3. 定义请求状态机，至少包含 PENDING、ADMITTED、BATCHED、RUNNING、COMPLETED、REJECTED、PREEMPTED 七种状态并规定合法迁移路径，非法迁移返回 E_INVALID_TRANSITION 且不修改已持久化状态；状态迁移必须记录迁移前后状态、触发原因与操作序号，以便诊断轨迹可逐条回放。
4. 实现推理批组织：把同模型、同节点且相邻提交的请求按批样本数上限与显存余量组织成批，批的合计显存不得超过节点剩余显存与模型最大批样本数；当请求规模超过配置阈值时允许按提交顺序在贪心装箱与按显存降序装箱之间选择策略，并输出所选策略、装箱结果与整批后估计延迟，不得对超出模型最大批样本数的请求静默成批。
5. 实现批延迟与显存碎片的取舍：每批估计延迟由批样本数与模型单位样本代价决定，超期望批延迟上限的批不得成批并返回 E_BATCH_TOO_LARGE 或拆分重排；碎片导致批无法装入时按确定规则尝试重组或降批样本数，降批后各请求样本数必须重算并保持总样本数不变，同时输出每次重组或降批的原因。
6. 实现并行执行调度器，以全局并发批上限与每轮时间预算双重约束推进：预算内按优先级、配额组轮转与批估计延迟取批，超出并发上限的批进入有界等待队列，队列满返回 E_EXEC_QUEUE_FULL；同一批在同一轮不得被重复派发，已被抢占的批不得继续执行，并输出本轮被跳过批清单及跳过原因。
7. 实现抢占与配额回收：高优先级请求在配额不足时可对低优先级请求发起抢占，被抢占请求迁移为 PREEMPTED 并真实释放其预留显存与算力份额，释放须在同一事务内完成；禁止仅修改状态而配额占用不变，回收后须校验配额组占用与节点余量均回到一致值，不一致返回 E_QUOTA_INCONSISTENT。
8. 使用 SQLite 持久化节点占用、配额预留、请求状态、批记录与意图日志，所有写操作先落意图记录再提交事务；进程在批调度或抢占中途被强制终止后重启须扫描未完成意图，把批与请求恢复到最后一个完整版本或标记为已中止，并输出仅基于已持久化事实的恢复报告；同时实现单写者调度与多读者查询的并发一致，同一请求标识重复提交只生效一次、其余复用结果，查询不得看到请求已 BATCHED 而配额预留仍为旧值的中间状态。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证配额准入、批组织、抢占回收、并发幂等与强制终止后恢复，确认状态与配额占用始终一致。
