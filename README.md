当前是空白工作区，需要从零实现一个面向本地 CDN 边缘节点场景的「边缘缓存一致性管线与结果验证工具」。场景中存在一个源站桩与多个边缘节点桩：源站为每个对象维护内容与版本号，边缘节点按缓存键（对象路径加查询串规范化后的摘要）缓存对象副本，并保留来源版本与写入时刻；客户端经边缘节点读取对象，未命中或副本版本落后时须向源站回源并更新副本，同时按配置的失效规则把变更传播到其他边缘节点。真实 CDN 的核心难点在于缓存键规范化的一致、版本落后的副本何时可被容忍返回、失效传播的依赖闭包、回源并发合并以及异常中断后的可复现验证，因此管线必须同时提供一致的结果报告与可重复的异常注入能力，全部在本地离线运行。

任务环境与准备：
安装 Python 3.11 及以上版本，并确认 python 与 pytest 命令在 Windows 命令行可用。
在任务目录下创建虚拟环境并用 pip 安装 fastapi、uvicorn、pytest、httpx，全部来自本地已缓存或可离线取得的 wheel 包。
预先准备本地样本目录，包含对象路径与查询串样本、订阅关系描述与注入配置样例，不依赖外网或真实 CDN 账号。
确认本地回环端口可用，测试使用本地 HTTP 服务桩，不访问任何线上站点。

业务要求：
1. 实现缓存键规范化与对象版本模型：缓存键由对象路径、查询串参数按名称排序后拼接的规范化形式计算摘要，须处理重复参数、空值参数、百分号编码与大小写敏感的路径；每个对象在源站维护单调递增的版本号与内容摘要，边缘副本记录来源版本与写入时刻，键规范化不一致或版本号缺失须返回业务码 E_BAD_CACHE_KEY 且不进入缓存。
2. 实现边缘节点读取与回源合并：客户端读取时命中且副本版本等于源站当前版本的直接返回，副本落后时须回源更新；同一缓存键的并发未命中请求只能向源站发起一次回源，其余请求等待同一结果并复用，回源失败时等待方须得到相同错误码而非各自重试，且不得把失败结果写入缓存。
3. 实现失效传播的依赖闭包与传播顺序：对象变更或失效由源站发起，须沿边缘节点的订阅关系计算失效闭包，闭包内节点按固定确定性顺序执行失效；未订阅该对象的节点不得被失效；失效执行中某节点失败须记录失败节点与原因并继续其余节点，整体结果须标记为部分成功并可由后续重试补齐。
4. 实现副本版本落后时的容忍窗口与一致读语义：边缘副本允许在配置的陈旧容忍窗口内返回落后版本，返回时须显式标记副本版本与落后刻度；超出窗口的读必须强制回源，不得返回陈旧内容；容忍窗口的判定须使用源站与边缘共用的同一逻辑刻度，重启后刻度必须延续，禁止用本地延迟近似代替版本判定。
5. 实现可复现异常注入机制：注入配置来自请求参数或配置文件，按注入点名称（normalize、lookup、origin_fetch、propagate、commit 等）与触发计数精确定位，仅在指定注入点第 N 次进入时抛出指定异常，其余调用正常执行；相同配置与相同输入序列须产生相同的失败位置与错误码，注入不得依赖随机数。
6. 实现异常链路映射与状态原子性：规范化失败、缓存未命中回源失败、注入异常、失效传播失败与刻度越界须映射为固定且互不重叠的业务码集合，注入异常统一映射为 E_INJECTED 并保留注入点与计数；任一阶段失败不得留下半写入的边缘副本、部分失效标记或残留事务，失败后关闭注入以相同输入重跑须成功且结果与从未失败过时逐字段一致。
7. 实现 SQLite 持久化与进程重启恢复：对象版本、边缘副本版本与写入时刻、订阅关系、失效事件序列与注入计数水位须在提交点以单事务写入；重启后须恢复逻辑刻度、副本状态与未完成的失效重试队列，中断时处于传播中的失效须按原顺序重试，中断时处于回源中的请求回退为未命中，恢复后的读结果与重启前一致。
8. 提供结果验证工具、本地 HTTP 接口与可重复测试：通过本地 HTTP 提供源站发布或失效对象、边缘读取、查询副本状态与失效事件、提交注入配置的接口，错误以固定业务码在 JSON 中返回；验证工具须对同一场景在无注入与各注入点下各跑一遍并逐字段比对副本版本、返回内容摘要与失效事件序列，输出差异报告；pytest 用例须在 Windows 离线覆盖键规范化、回源合并、部分失效重试、陈旧窗口越界、注入复现与重启恢复。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证缓存键规范化、回源合并、失效闭包与注入复现，并给出重启恢复后一致性结果。
