在 Windows 本地开发环境中，需要实现一个可交互的专业应用，用于管理容器镜像分层构建的缓存。该应用应能根据构建指令（如 COPY、RUN、ENV）计算每层的缓存键，追踪层状态在“待构建→构建中→已提交→失效”之间的演进，并在进程被强制终止后依据持久化元数据恢复到一致状态。用户通过 HTTP API 提交构建计划、查询缓存命中、模拟中断与恢复。所有构建数据来自本地确定性样本文件，不依赖真实容器运行时或外部镜像仓库。

任务环境与准备：
安装 Python 3.11 或更高版本，并确保 python 与 pip 命令可用。
安装依赖：fastapi、uvicorn、pytest、httpx；使用 pip install 安装。
准备本地确定性样本目录，包含至少三个构建计划 JSON 文件和对应的上下文文件；所有文件内容固定且不依赖网络。
确认 SQLite 可用（Python 标准库 sqlite3），无需额外安装数据库服务。

业务要求：
1. 实现缓存键计算：对构建计划中的每条指令结合父层缓存键、指令内容与上下文文件的内容摘要生成确定性缓存键，相同输入必须得到相同键，不同层顺序或文件内容变化必须得到不同键。
2. 定义层状态机，至少包含 PENDING、BUILDING、COMMITTED、INVALID 四种状态，并规定合法迁移路径；非法迁移必须返回业务码 E_INVALID_TRANSITION，且不得修改持久化状态。
3. 使用 SQLite 持久化层元数据与构建会话，提交事务前先写日志式意图记录；进程在 BUILDING 阶段被强制终止后，重启时必须扫描未完成意图并将对应层状态恢复为 PENDING 或明确标记 INVALID，不得产生悬空 BUILDING 状态。
4. 提供 HTTP API 提交构建计划并执行层构建，服务端以单写者串行执行构建，同时支持多个只读查询并发；并发提交同一缓存键时只允许一个构建实际执行，其余请求等待并复用结果。
5. 缓存失效传播：当某层的上下文文件摘要变化时，该层及所有下游层的缓存键与状态必须级联失效，且失效操作与新的构建计划在同一事务边界内保证跨层一致性，不得出现部分层已失效而下游仍标记为命中的中间可见状态。
6. 构建中断与恢复演示：提供模拟中断端点，在指定层构建过程中注入中断标记并触发安全退出流程；重启后能依据持久化意图记录恢复会话，并输出恢复前后的层状态差异报告，恢复报告不得承诺强制终止后仍生成完整退出报告。
7. 定义业务错误码并统一处理，至少覆盖 E_INVALID_TRANSITION、E_DUPLICATE_LAYER、E_SESSION_NOT_FOUND、E_KEY_CONFLICT；错误响应为 JSON 且包含业务码，不得以 HTTP 状态码替代业务码语义。
8. 提供可重复演示脚本，使用固定本地样本生成两次构建计划：第一次全量构建并缓存，第二次仅修改一个中间层文件触发部分失效与重建；脚本输出两次的命中层数、重建层数与最终状态摘要，便于人工核验。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证缓存键确定性、状态机约束、中断恢复一致性与级联失效结果，并附演示输出。
