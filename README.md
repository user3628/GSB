在 Windows 空白工作区中，需要从零构建一个面向本地执行的小型 SQL 逻辑计划引擎，用于把一条 SELECT 语句解析为逻辑计划并进行可复现的规范化与验证。语句子集包含单表与多表 FROM、WHERE 布尔表达式、GROUP BY 与聚合、HAVING、ORDER BY、LIMIT；逻辑计划由 Scan、Filter、Project、Aggregate、Sort、Limit、Join 节点组成。引擎需要把语法树先转为逻辑计划，再按等价规则做谓词下推、投影裁剪与常量折叠等改写，最后输出规范化计划文本与逐节点摘要。除正常语义外，任务要求围绕本地确定性样本与本地测试服务实现异常注入：通过请求参数注入畸形 SQL、超限节点数、非法聚合引用、计划改写中断等情形，验证引擎在异常链路上的业务码、可观测事实与恢复行为，而不是依靠修改源码制造失败。所有数据与统计来自本地固定样本，不依赖任何在线服务。

任务环境与准备：
安装 Python 3.11 及以上版本，并确认 python 与 pip 在 PowerShell 中可用。
创建虚拟环境并安装 pytest；核心实现只使用 Python 标准库 sqlite3 与 http.server 或等价本地服务，不引入外部数据库依赖。
在项目工作目录内准备本地固定 SQLite 样本库与固定 SQL 语句清单，样本生成脚本应可重复执行并产生相同数据。
确认可在 Windows 下以子进程启动本地 HTTP 服务并进行强制终止演练；不需要任何在线账号、外部数据库或容器环境。

业务要求：
1. 实现 SQL 子集解析并转为逻辑计划：支持 SELECT 投影别名、单表与多表 FROM、WHERE 布尔表达式（AND/OR/NOT、比较、IS NULL、IN 列表）、GROUP BY 与 COUNT/SUM/MIN/MAX、HAVING、ORDER BY 与 LIMIT；语法错误必须返回业务码 E_PARSE 且错误信息包含出错位置，不得抛出未捕获异常。
2. 定义逻辑计划节点模型与稳定序列化格式：每个节点包含类型、标识、子节点顺序与属性集合，序列化输出必须逐字段确定、可重复解析回等价计划；节点标识在计划重写前后保持可追踪的映射关系，便于后续比对改写差异。
3. 实现规范化改写：至少支持谓词下推（把可下推的 Filter 推至 Scan 之上并保持外连接语义安全）、投影裁剪（移除未被上层引用的列）与常量折叠；改写必须保持结果语义等价，改写过程需记录每条规则的应用位置与前后节点，改写不得陷入无限循环。
4. 实现改写安全保障：当规则应用会导致聚合语义改变、HAVING 引用被裁剪列或排序键丢失时，必须拒绝该条改写并记录拒绝原因，而不是静默产生错误计划；拒绝信息需指出被拒绝的规则与冲突节点。
5. 实现异常注入接口：请求携带注入参数可触发畸形 SQL、计划节点数超过配置上限、聚合函数引用非分组列、改写中途注入中断标记等情形；每种情形返回互不相同的业务码（至少 E_PARSE、E_PLAN_TOO_LARGE、E_INVALID_AGGREGATE、E_REWRITE_ABORTED），响应为含业务码与上下文的 JSON，注入只通过参数生效。
6. 实现单写者与多读者并发控制：计划构建与规范化按提交串行执行，只读查询可并发返回已提交的规范化计划；同一请求标识的重复提交必须复用同一结果，并发提交相同语句时只允许一个执行，其余等待并复用结果，不得出现半改写状态对外可见。
7. 实现持久化与中断恢复：计划提交先写入意图记录再落库，进程被强制终止后重启需扫描未完成意图，将对应计划标记为已中止或回滚到最后一个完整版本，并输出基于持久化事实的恢复报告；恢复报告不得承诺强制终止后仍生成完整退出报告，仅安全退出时可输出退出摘要。
8. 提供可复现实验环境与演示脚本：使用本地固定 SQLite 样本与本地 HTTP 服务完成正常改写、四类异常注入、并发重复提交与一次强制终止后恢复的端到端演练，输出每条语句的规范化计划、规则应用记录、业务码清单与恢复前后差异，重复执行结果应一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证解析、规范化改写、四类异常注入业务码及中断恢复后计划状态与报告一致。
