当前是空白工作区，需要从零构建一个面向本地回环环境的 HTTP/2 多路复用诊断工作台，供网络运维人员离线评估多路流在连接级与流级流量窗口约束下的调度行为。系统以确定性帧序列样本描述 HEADERS、DATA、WINDOW_UPDATE、RST_STREAM、SETTINGS 帧流，需按多路复用语义推进各流收发状态、维护连接级与流级窗口余量、依据权重与优先级组织数据帧发送顺序，并记录每条流的调度轨迹与诊断结论。数据规模会在数十条流到数千条流、每流若干字节到数百兆字节之间变化，调度器需在精确预算计算与有界近似排序之间取舍，同时保证同一帧序列样本在不同提交批次划分与不同查询时刻下得到逐条一致的调度轨迹与窗口余量。用户通过本地 HTTP 接口提交帧序列样本、触发调度并查询轨迹。

任务环境与准备：
安装 Python 3.11，并在项目虚拟环境中安装 FastAPI、uvicorn 与 pytest，版本锁定在 requirements.txt。
准备本地固定的 HTTP/2 帧序列 JSON 样本文件，覆盖正常收发、窗口不足、流重置与结束标志等情形，样本不依赖外部网络。
初始化本地 SQLite 数据库文件用于持久化连接窗口、流窗口、流状态与意图日志，库文件路径由启动参数指定。
在 Windows 本地启动 uvicorn 服务并确认本地 HTTP 端口可访问，运行演示脚本前确认样本路径与数据库路径配置正确。

业务要求：
1. 实现帧序列样本解析与连接状态校验：样本每条记录含连接标识、流标识、帧类型、帧标志、载荷字节数与窗口增量，帧类型至少覆盖 HEADERS、DATA、WINDOW_UPDATE、RST_STREAM、SETTINGS；非法帧类型、流标识为负或 DATA 在未打开流上出现时返回业务码 E_FRAME_INVALID 且整批不推进。
2. 实现连接级与流级窗口状态模型：每连接维护连接窗口余量与初始窗口，每流维护流窗口余量与已发送未确认字节；发送 DATA 前须同时校验连接与流余量，任一不足返回 E_FLOW_CONTROL_BLOCKED 并附两侧余量与所需字节；WINDOW_UPDATE 增量不得使窗口超过初始窗口上限，超出按确定规则截断并记录协议违例。
3. 实现多路复用调度发送顺序：待发送的 DATA 帧按流权重与占用带宽组织发送次序，支持至少两级优先级；同一优先级下按加权分配本轮可发送字节，并输出本轮选择的流标识、发送字节与选择依据。当流数超过配置阈值时切换为有界近似排序并输出候选截断数与近似误差说明，切换前后对同一小规模样本的发送顺序必须一致。
4. 实现流状态机，至少包含 IDLE、OPEN、HALF_CLOSED_LOCAL、HALF_CLOSED_REMOTE、CLOSED、RESET 六种状态并规定合法迁移路径；END_STREAM 标志、RST_STREAM 与连接关闭触发确定迁移，非法迁移返回 E_INVALID_TRANSITION 且不修改已持久化状态；重置或关闭的流不得再被调度发送数据。
5. 实现进程被强制终止后的恢复：连接窗口、流窗口、流状态与调度轮次先写意图记录再提交事务；进程在调度轮次中途被强制终止后重启须扫描未完成意图，将轮次标记为已中止或回滚到最后一个完整提交边界，恢复报告只基于已持久化事实，不得承诺强制终止后仍生成完整退出报告。
6. 实现并发提交与查询可见性：调度推进按连接单写者串行执行，多个只读查询可并发读取已提交快照；同一帧序列样本标识重复提交只推进一次、其余等待并复用结果，内容不一致时返回 E_CONFLICTING_SAMPLE；查询不得看到部分流窗口已更新而连接窗口仍为旧值的中间状态。
7. 实现统一业务错误码与 JSON 错误体，至少覆盖 E_FRAME_INVALID、E_FLOW_CONTROL_BLOCKED、E_INVALID_TRANSITION、E_CONFLICTING_SAMPLE、E_SAMPLE_NOT_FOUND，错误体携带业务码、连接标识与上下文；同时提供本地 HTTP 接口覆盖样本提交、调度触发、按连接与流查询窗口余量与状态、查询调度轨迹与恢复报告。
8. 提供诊断展示与可重复演示脚本：工作台页面展示连接窗口余量、各流窗口余量与状态、本轮调度次序与阻塞原因；脚本使用固定本地帧序列样本完成一次完整调度、一次窗口不足阻塞、一次流重置与一次强制终止后恢复，输出调度轨迹、窗口余量与状态迁移记录的核验摘要。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
