排序离线建模方向的老系统正在被替换，接手人只拿到一页迁移说明，工作区尚无任何实现，需要做出可集成的 Go 组件与可重复实验脚本，把积累的两代曝光日志归并成统一特征样本。样本由内置固定种子生成器在本地确定性产出：一态是遗留宽表，以管道分隔纯文本记录曝光，字段顺序由表头行声明，数值为自由浮点书写、毫秒时间以秒级整数记录、缺失用单一符号占位；另一态是新一代分片 JSONL，每行含 impression_id、毫秒时间戳、按字段名组织的特征值及显式类型与定点 scale、曝光标签、仅曝光为正时出现的转化标签、来源与语言。两代记录描述同一批曝光但字段集合与取值形态并不同，日志按时间持续追加，同一用户同一物品可多次曝光。字段语义由带单调版本号的规范快照声明，另可提交只含局部字段改动的增量片段。

任务环境与准备：
安装 Go 1.22 及以上版本与 SQLite 开发库（如 libsqlite3-dev），确认 go 与 gcc 可用；网络受限时预先拉取所需 Go 模块。
创建全新工作目录并在其中初始化 Go 模块，所需样本全部由程序内置固定种子生成器在首次运行时写入本地目录，不依赖外部数据。
确认当前用户对工作目录与 SQLite 数据库文件所在目录具备读写权限，并留出可同时运行多个进程的本地端口用于 HTTP 接口。

业务要求：
1. 实现统一内部样本模型与两代日志形态的双向编解码：内部模型以 impression_id、毫秒时间戳、按字段名组织的带类型与定点 scale 的特征值、曝光与转化标签、来源与语言描述一条样本；遗留宽表与分片 JSONL 均可转换为内部模型并再导出，导出后重新导入须得到与首次导入逐字节一致的内部摘要，表头字段顺序变化须被显式识别而非按位置错读。
2. 实现遗留宽表的兼容解析与显式升级：宽表无类型声明、浮点自由书写、秒级时间戳、单一符号占位；导入时须依据规范声明的类型推断列类型、把秒级时间换算为毫秒并记录换算因子、把占位符按字段语义区分为缺失与显式零，全部推断与换算须在报告中标注依据与不可恢复项，无法归一的列返回带记录标识与列名的业务错误码。
3. 实现按时间归并的分片接入与双目标标签装配：新记录到达时按毫秒时间戳归并进当前样本集，同一 impression_id 重复出现时按可配置保留策略裁决并记录被丢弃副本及其来源形态与时间戳；曝光标签缺失或取值不在零一范围的样本判为不可训练并单列统计，转化标签存在而曝光标签为零的样本单独标记为漏斗异常。
4. 实现规范快照与增量片段的版本推进：整体快照与只含局部字段改动的片段均可提交，推进时须校验基础版本与当前生效版本一致、字段类型变更需显式声明，字段被删除或类型改变时使依赖该字段的派生特征与已导出产物失效并重建；版本号不连续、基础版本不匹配或同字段重复定义返回稳定业务码。
5. 实现跨形态的标签一致性校验与定点精度控制：数值特征在定点域按声明 scale 参与校验与统计，类别特征经 NFKC 规范化与小写化后再比对，转化标签只能在曝光为正的样本上装配；当同一 impression_id 在两代形态中的曝光或转化标签不一致，或定点换算后数值超出声明位宽时，须返回带 impression_id 与字段名的业务错误码并保留两条来源记录。
6. 实现基于 SQLite 事务的阶段检查点与强制终止恢复：导入、标签装配、一致性校验、导出四阶段的进度与中间摘要以事务写入本地库，同一批次同一阶段只允许一条有效记录；进程被强制终止后重启只能凭已提交事实恢复进度，不承诺生成退出报告，恢复后的样本集与导出摘要须与一次连续执行逐字节一致。
7. 实现整体替换识别、并发发布互斥与稳定业务错误码：多个执行进程对同一库发布阶段产物时使用 SQLite 条件更新与真实文件锁，仅允许序号连续推进；检测到记录被整体替换（序号回退、内容指纹变化或摘要不匹配）时须区分正常推进、替换与回退，仅正常推进被接受，其余写入拒绝记录并返回 E_STALE_CHECKPOINT 或 E_STALE_VERSION。
8. 提供本地 HTTP 与命令行接口及确定性演示：支持导入两代形态记录、提交整体快照与增量片段、触发分阶段执行、查询各阶段状态与版本指纹、查看推断与换算依据、列出不可训练与漏斗异常样本、执行两代形态双向互转并比对摘要、请求优雅停止与执行恢复；演示数据覆盖中英混排、重复曝光、转化标签越界与遗留宽表占位列。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
