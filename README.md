为模型与数据管线协同团队从零构建一个本地可运行的模型检查点合并与误差传播诊断组件。输入是本地检查点目录：若干 JSON 描述的浮点张量分片文件（NPZ 或 JSON 数组，float32 与 float64 混合），一份张量清单声明每个张量的名称、形状、dtype 与所在分片；一份合并方案文件，声明参与合并的检查点、逐张量合并权重（非负、按张量独立给出且需归一）、累加精度策略与噪声舍入模式。团队需要按张量粒度完成加权合并、精度路径选择与结果校验，并诊断每一步的数值误差如何向上游指标传播。核心难点在于：合并权重归一、float32 与 float64 两条累加路径的结果差异、以及分片级部分失败后如何保持已提交张量与快照版本一致，必须同时成立且可逐位复现。

任务环境与准备：
安装 Python 3.11 与依赖 numpy、fastapi、uvicorn、pytest（离线本地 wheel 或已配置镜像）。
在空工作区初始化项目并准备本地确定性检查点样本：多个 NPZ 分片、张量清单 JSON、合并方案 JSON，覆盖 float32 与 float64、非方阵形状、缺失张量与非法权重用例。
确认 SQLite 可用且工作目录可写；不需要网络、账号、GPU 或外部数据集。

业务要求：
1. 组件须提供清单与方案加载接口，校验张量清单中的名称唯一、形状各维为正整数、dtype 仅为 float32 或 float64，且分片文件存在、其键集合与清单声明完全对应；任一不一致返回 E_SHAPE 或 E_INPUT 业务码并指出张量名与分片路径，且不得创建任何输出或临时文件。
2. 合并须按张量独立执行：对每个张量收集参与检查点的值，按方案给出的逐检查点原始权重做归一化后加权累加，归一化后权重之和与 1 的偏差超过配置容差时返回 E_WEIGHT 并给出张量名与实际和；权重为负或参与检查点缺失该张量时分别返回 E_NEG、E_MISS 并定位检查点名，不得静默补零继续。
3. 必须实现两条数值路径：全部在 float64 下累加后再按目标 dtype 声明舍入，以及在 float32 下逐项累加；同一次合并由一个策略参数选定路径，另一条路径须作为对照同步算出并记录两路径逐张量的最大绝对差与相对差；两路径差异超容差时须标记为数值不稳定并写入诊断，但不得因此丢弃合并结果。
4. 累加顺序须确定：对每个张量内元素采用与形状无关的按索引升序累加，对参与检查点按方案声明顺序累加；实现须避免依赖字典遍历顺序与分片文件内部键序，同一输入与策略下两路径的逐元素结果在重复运行间必须逐位一致，含 NaN 或 Inf 的输入张量须返回 E_FINITE 并定位张量名与元素下标。
5. 合并须按分片粒度在 SQLite 中事务提交：单个分片内所有张量的合并值与对照差值统计、分片进度标记在同一事务中写入，任一失败该分片整体回滚且不留下部分张量记录；已提交分片不得在后续重试中被重复累加或重复统计。
6. 每次完整合并须以整体替换方式生成版本化快照，含配置指纹（合并方案内容哈希、策略、容差）、逐张量合并值内容哈希与两路径差异摘要；读取快照时若检测到数据库版本与磁盘结果文件哈希不一致、配置指纹变化或残留旧版本结果文件，须返回 E_STALE 并定位张量名与快照版本。
7. 进程被强制终止后重启，须从 SQLite 已提交的分片进度继续，核对每个分片的处理标记、结果文件内容哈希与快照版本，重算未提交分片且不重复消费已提交分片；恢复后的逐张量合并值、两路径差异摘要与快照版本序列须与无中断执行完全一致，且不得承诺为被强制终止时正在写入的分片生成退出报告。
8. 须提供误差传播诊断接口与确定性演示入口：把逐张量差异按合并方案中的权重上限聚合为整体误差估计，输出不稳定的张量清单、其占张量总数的比例、两条路径总差异分布；演示使用固定检查点与方案跑出逐张量差异、不稳定张量数、快照版本序列与恢复前后一致性的可重复结果，并给出可用 curl 复现的请求示例。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地确定性检查点验证加权合并、双精度路径差异诊断、权重校验、快照版本与中断恢复的一致性。
