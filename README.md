当前是空白工作区，需要在 Windows 本地从零构建一个面向 CDN 边缘缓存一致性的仿真验证与诊断工作台。工作台以本地 HTTP 服务同时扮演源站与若干边缘节点，按带版本号的缓存策略快照（TTL、stale-while-revalidate 窗口、Cache-Control 指令、Vary 维度、缓存键规范化规则、purge 传播策略）处理客户端请求，在边缘节点上执行缓存查找、回源、合并回源与失效传播，并记录每次请求的缓存判定轨迹。由于源站内容可被脚本改写并可注入延迟、错误码与响应体长度变化，边缘节点必须识别内容版本变化并让旧缓存整体替换而不是逐字段修补。工作台还需支持对指定节点或路由注入异常，并把可复现的请求轨迹、缓存状态演进与异常注入记录整理为可核验的诊断视图。所有数据来自本地确定性样本与本地测试服务，不访问真实 CDN 或外部站点。

任务环境与准备：
确认 Windows 本地已安装 Python 3.11 或以上，并可在命令行执行 python --version 与 pip --version。
创建全新工作区目录，使用 venv 建立虚拟环境并激活后安装 fastapi、uvicorn、pytest、httpx 依赖，全部来自本地或离线可用的包源。
准备本地确定性样本：缓存策略快照 JSON 两份（含 TTL、Vary、stale-while-revalidate 窗口、purge 传播窗口与版本号差异）、请求清单样本与源站内容初版及替换版文件，均放入工作区的 samples 目录。
在本地回环地址启动工作台自带的源站与边缘节点 HTTP 服务，端口从配置读取以避免冲突，不访问任何外部站点或真实 CDN。
运行演示脚本前确认 SQLite 数据文件路径可写，并记录一次干净启动的基线状态摘要用于后续对比。

业务要求：
1. 实现缓存键规范化与查找：缓存键由规范化路径（去除重复斜杠、合并点段、统一百分号编码大小写）、规范化查询串以及策略声明的 Vary 请求头取值集合共同组成；同一逻辑资源的不同 URL 形态不得产生重复缓存项，不同 Vary 取值必须分离存储，规范化失败返回业务码 E_KEY_INVALID 且不得写入任何缓存条目。
2. 实现边缘缓存状态机与 TTL 语义：每个缓存条目至少经历 MISS、REVALIDATING、FRESH、STALE、PURGED 五种状态并规定合法迁移，非法迁移返回 E_INVALID_TRANSITION 且不改变条目；命中时按已流逝时间递减剩余 TTL 并返回 Age 与 Cache-Control 响应头，过期条目不得以新鲜身份返回，stale-while-revalidate 窗口内允许返回旧内容但须标记陈旧并使后台回源与请求处理解耦。
3. 实现回源合并与源站内容版本识别：多个边缘请求并发未命中同一缓存键时仅首个请求触发回源，其余等待并复用同一结果；源站响应须携带内容版本标识（ETag 或内容摘要），边缘节点据此判定内容是否变化，变化时必须整体替换缓存条目及其标签、路由映射等派生索引，禁止逐字段修补旧条目；合并期间的额外回源尝试不得再向源站发起请求。
4. 实现缓存策略快照与版本识别：策略快照携带版本号、生成时间、适用节点集合与校验摘要，提交时若版本号不大于当前已提交版本则返回 E_STALE_SNAPSHOT；加载新快照须整体替换旧策略，不得让新旧快照的 TTL、Vary 或 purge 规则混合生效，加载校验失败返回 E_SNAPSHOT_INVALID 且现有策略保持不变。
5. 实现 purge 传播与跨节点一致性：对某路径或某标签的 purge 须在策略声明的传播窗口内广播到所有适用边缘节点，各节点把受影响条目迁移为 PURGED 并使其派生索引（标签索引、路由到条目映射）级联失效；传播过程中禁止出现部分节点已清除而共享索引仍指向旧条目的中间可见状态，查询只能看到某一完整提交的传播结果。
6. 实现可复现异常注入与请求轨迹记录：允许通过请求参数对指定节点注入回源延迟、源站错误码、响应体长度变化、连接拒绝与 purge 广播中断，每种异常返回互不相同的业务码（至少 E_ORIGIN_TIMEOUT、E_ORIGIN_5XX、E_INJECT_INVALID、E_PURGE_BROADCAST_FAIL）；每次请求记录含缓存键、状态迁移、回源次数与判定依据的轨迹，注入回源延迟须通过真实等待并关闭底层回源连接实现超时，不得以跳过回源冒充。
7. 实现并发一致与强制终止恢复：缓存条目写入、状态迁移与 purge 传播按单写者串行执行，多个边缘读请求可并发；同一请求标识重复提交只生效一次，其余复用结果；写入与传播先落意图记录再提交事务，进程被强制终止后重启须扫描未完成意图，将未完成回源或广播回滚到最后一个完整版本并输出仅基于持久化事实的恢复报告，不得承诺强制终止后仍生成完整退出报告。
8. 提供诊断视图与可重复演示脚本：API 覆盖策略提交、请求处理、批量请求回放、purge 触发、按缓存键查询条目与状态、异常注入记录查询与恢复报告查询，统一错误响应为含业务码的 JSON；演示脚本使用固定本地样本完成一次冷启动全量回源、一次源站内容替换后的整体替换、一次 purge 传播与一次注入异常后强制终止恢复，输出每条请求的缓存判定轨迹、各节点条目状态摘要与恢复差异报告，便于人工核验。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

用固定本地样本与本地测试服务验证缓存判定、整体替换、purge 传播、异常注入与重启恢复，并输出轨迹与恢复报告。
