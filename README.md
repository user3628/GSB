当前是空白工作区，需要从零构建一个面向本地可观测性样本的告警降噪与根因关联组件，交付可集成的领域组件与完整示例。组件读取本地确定性告警样本（毫秒时间戳、告警指纹、服务名、资源对象、级别、标签）与服务依赖拓扑快照（服务到下游的依赖边、拓扑版本与校验摘要），构建三类派生产物：按服务与严重级别的聚合去重索引、按指纹的抑制规则索引、以及告警到根因候选的关联评分表。为支撑持续运维，告警以带版本的增量批次追加，抑制规则与拓扑以带版本的增量片段提交；当某服务的拓扑依赖、告警指纹标签或抑制规则发生变化时，依赖这些输入的聚合索引、抑制索引与根因关联评分必须级联失效并原子重建。用户通过本地 HTTP 接口提交增量或整份快照、查询降噪结果与根因候选、查询失效轨迹与恢复报告，全部数据来自本地样本。

任务环境与准备：
在 Windows 空白工作区创建项目目录，确认可用的 Python 3.11 及以上解释器与 pip。
安装依赖：pip install numpy 并确认 SQLite 通过标准库 sqlite3 可用，无需外部服务或容器。
准备固定本地样本：告警样本 JSON 行文件、依赖拓扑快照 JSON、抑制规则快照 JSON，各含版本号与校验摘要。
任务执行前启动本地 HTTP 服务端口供接口验证，示例脚本以本地回环地址访问，不依赖真实账号或线上站点。

业务要求：
1. 实现告警样本解析与批次入库：每条告警含毫秒时间戳、指纹、服务名、资源对象、级别与标签集合，解析失败返回业务码 E_ALERT_INVALID 且整批不入库；合法告警以批次标识与行内序号唯一标识，同批次同序号重复提交内容一致须幂等成功，内容不一致返回 E_CONFLICTING_ALERT 并保留首次提交。
2. 实现带版本号的告警增量提交与基础版本校验：增量片段只含新增告警与受影响的指纹条目并携带基础版本，若基础版本不是当前版本则返回 E_STALE_BASE 且不改变任何已提交状态；整份快照替换时必须识别版本变化并整体替换告警状态，不得把新旧快照的告警混合使用。
3. 实现三类派生产物：按(服务名, 级别)的聚合去重索引（同指纹在抑制窗口内只计首条）、按指纹的抑制规则索引（规则含匹配标签、抑制窗口与作用范围）、以及告警到根因候选的关联评分表（依据服务依赖拓扑跳数与时间邻近度打分），三者均由已提交告警与快照派生而非全量重建。
4. 实现依赖失效与级联重建：为每个服务与指纹维护其对三类产物的引用关系；当某服务的拓扑依赖、指纹标签或抑制规则变化时，受影响服务的聚合索引、抑制索引以及依赖它的根因关联评分必须级联失效并在同一事务边界内原子重建，禁止出现抑制索引已更新而根因评分仍为旧值的中间可见状态。
5. 实现单写者提交与多读者查询的并发一致：告警提交、规则与拓扑增量提交以及级联重建按提交串行执行，多个只读查询可并发读取已提交版本；同一基础版本的两个并发增量只允许一个成功、另一个返回 E_STALE_BASE；查询只能看到某一完整提交版本，同一批次标识重复提交只执行一次、其余等待复用结果。
6. 实现抑制判定与根因评分的数值契约：根因评分由拓扑跳数衰减与时间邻近度合成，使用定点表示并在每步校验不越界，评分比较使用带容差的定点比较并按稳定次序打破平局；抑制窗口的边界包含关系与时戳精度须明确定义，使同一输入重复查询得到逐位一致的去重结果与评分。
7. 使用 SQLite 持久化告警、拓扑与规则版本、三类产物及意图日志，写操作先写意图记录再提交事务；进程在级联重建中途被强制终止后重启必须扫描未完成意图，把产物回滚到最后一个完整版本或将对应增量标记为已中止，恢复报告只基于已持久化事实且不承诺强制终止后仍生成完整退出报告。
8. 实现统一业务错误码与 JSON 错误体，至少覆盖 E_ALERT_INVALID、E_STALE_BASE、E_CONFLICTING_ALERT、E_SNAPSHOT_INVALID、E_ORDER_NOT_FOUND、E_REBUILD_CONFLICT；并提供端到端示例脚本，使用固定本地样本完成全量加载、一次只改单服务拓扑的增量提交触发级联重建、一次抑制规则变化与一次强制终止后恢复，输出降噪前后告警数、根因候选、失效轨迹与恢复报告。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
