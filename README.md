# 多路召回融合实验组件

可运行实现、HTTP/CLI 用法和实际验收记录见 `docs/DELIVERY.md`。一键本地验证：

```bash
export GOPROXY=https://goproxy.cn,direct
bash scripts/verify.sh
```

---

这次立项要交付的是多路召回融合实验组件的首个可运行版本，仓库里没有源码也没有样本，全部输入都来自程序内置的固定种子生成器。物品库与查询集在本地确定性产出：物品含 item_id、类目、类目路径、float32 编码向量、标题文本与语言标签，查询含 query_id、原始查询、locale 与历史点击类目序列；另附一份带单调版本号的融合配置快照，声明词法倒排、类目协同、向量近邻三路的候选深度与千分比预算、各路融合权重、相似度容忍间隔、去重与截断规则、全局候选评估次数预算与每轮时间预算。三路打分分属词法定点、类目前缀计数与缩放余弦三个数值域，融合后的小分差会改变 top-k 排序，因此每次召回结果都要附带可复核的误差上界，并与本地高精度参考结果逐位比对。

任务环境与准备：
在 WSL Ubuntu 安装 Go 1.22 或以上，确保 go 命令可用，并准备可联网或已缓存的模块代理以获取 SQLite 驱动依赖。
安装 SQLite 命令行工具与 C 编译环境（gcc、libsqlite3-dev），用于检查组件写入的本地数据库文件。
工作目录保持空白，由程序内置固定种子生成器在首次运行时写出物品库、查询集与融合配置快照，不依赖外部数据集或网络服务。
验证时使用本地回环端口运行组件提供的 HTTP 接口，所有样本与参考结果均在本地生成。

业务要求：
1. 实现查询与物品文本规范化及词法倒排打分：文本做 Unicode NFKC、空白折叠、全半角统一与小写化后按中文单字加相邻二字、拉丁连续串切分，构建倒排并以定点权重累加词项分，输出倒排命中明细与打分摘要；空查询、零词项或倒排为空时返回带 query_id 的 E_EMPTY_QUERY。
2. 实现类目协同与向量近邻两路打分：协同路按历史点击类目序列的路径前缀匹配加权，近邻路以缩放定点域累加余弦相似度，编码向量按显式 scale 还原；编码向量为零范数、维度与物品库声明不符或出现 NaN 时返回 E_VECTOR_INVALID 并指出 item_id 与维度。
3. 实现可配置多路融合与去重截断：支持加权求和与倒数排名两种融合，同一物品多路命中时记录来源各路排名、分数与对数贡献并合并，输出按融合分降序、同分按 item_id 升序；截断位大于候选数时按候选数截断并记录，融合权重全为零返回 E_NO_WEIGHT。
4. 实现误差传播追踪与排序稳定性裁决：对每个命中给出各路量化误差界、融合分有效位数与推导依据，再与本地高精度参考结果按固定抽样位比对，跨相邻分差落在误差界内的位次标为不稳定并记录跨越幅度；偏差超容差返回 E_NUMERIC_MISMATCH 并附最大偏差与来源路。
5. 实现基于千分比预算与全局评估预算的多路预算裁决：每轮按查询数与各路候选深度、千分比配额决定各路启用与截断深度，累计消耗超预算时按确定性优先级缩减并记录被淘汰路与原因；缩减后结果须与按缩减后配置从零运行逐字节一致。
6. 实现并行召回与确定性归约：以查询为调度单元，在全局并发查询上限与每轮时间预算约束下用工作池并行处理，各查询的候选、融合分与指标按 query_id 全局排序后归约，使并行输出与单线程顺序执行逐字节一致；工作池取消只能在查询边界生效，不得以线程超时描述为已终止执行。
7. 实现 SQLite 事务化阶段检查点与恢复边界：每查询每阶段完成时在单个事务写入含阶段名、query_id、输入内容指纹、配置版本、产物摘要与单调序号的记录，同一查询同一阶段只允许一条有效记录；被强制终止后重启仅凭已提交事实恢复，不承诺生成退出报告，恢复结果须与一次连续执行一致。
8. 实现配置快照增量片段与整体替换识别：接受只含局部改动（候选深度、千分比配额、融合权重、截断规则）的片段并校验基础版本，版本不一致返回 E_STALE_BASE；通过内容摘要与版本序号区分正常推进、整体替换与回退，替换使受影响最早阶段及其下游失效重建，回退拒绝并返回 E_STALE_VERSION。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地确定性样本验证三路召回、融合去重、误差上界与失效版本拒绝，并核查并行与恢复结果逐字节一致。
