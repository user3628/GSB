在 Windows 空白工作区中，需要从零构建一个面向本地多进程场景的协调选举与故障转移中间件组件，供上层分布式应用集成。组件维护若干候选节点（节点标识、优先级、租约 TTL、最近心跳时刻）与主节点租约，候选节点通过本地 HTTP 接口发起竞选、续约与退位；协调器依据租约有效性、优先级与心跳活性裁决主节点，并在主节点失联后依据故障转移策略选举新主节点。系统需要支持候选规模从数十个变化到数千个的选举批次，在精确全量扫描与分桶采样裁决之间做算法取舍，同时保证租约判定、心跳状态与故障转移结论在并发竞选、网络乱序与进程强制终止后仍保持一致。所有数据来自本地确定性样本与本地测试端点，不依赖真实网络或外部基础设施。

任务环境与准备：
安装 Python 3.11 或更高版本，并确保 pip 可用。
安装 SQLite 3（Python 标准库 sqlite3 即可）与 NumPy。
在空白工作区创建项目目录，准备固定本地样本 JSON 文件，包含候选节点清单与确定性心跳序列。
准备本地 HTTP 测试服务所需的端口，确保回环地址可用。

业务要求：
1. 实现候选节点与租约模型：节点包含标识、优先级、租约 TTL 毫秒、最近心跳时刻与状态；竞选请求须校验节点已注册、优先级在允许范围内、心跳未超时，校验失败返回业务码 E_NODE_INVALID 且不改变租约状态；重复注册同一节点须按更新处理并保持其租约版本连续。
2. 实现租约判定与主节点选举：主节点租约记录持有者、租约版本、到期时刻与任期序号，租约到期前持有者续约成功则延长到期时刻并递增版本；租约空闲或已到期时按优先级与心跳活性裁决新主节点，同优先级时按节点标识稳定次序打破平局，输出选举依据与租约版本。
3. 实现数据规模自适应裁决路径：当候选节点数不超过配置的精确上限时对全部候选做精确全量比较；超过上限时改为按优先级分桶采样并输出采样率、桶划分与估计置信说明；两条路径对同一次选举必须给出相同的主节点或给出可逐项核对的差异说明，采样路径须显式标注其为估计结论。
4. 实现心跳活性与故障转移：节点心跳更新最近心跳时刻，心跳超过声明的失联阈值后该节点不得当选并标记为 SUSPECT；主节点失联时触发故障转移，故障转移须校验候选池中至少存在一个心跳有效节点，否则返回 E_NO_ELIGIBLE_CANDIDATE 并保留原租约版本不变；故障转移结论须记录触发原因与参与裁决的候选集合摘要。
5. 实现并发竞选与单写者裁决：竞选、续约与退位请求按租约版本单写者串行裁决，多个只读查询可并发读取已提交租约状态；同一节点在同一租约版本下的并发竞选只允许一个成功，其余返回 E_LEASE_HELD 并附当前持有者与到期时刻；查询不得看到租约已授予而节点状态仍为 SUSPECT 的中间可见状态。
6. 实现租约与心跳的强制终止恢复：租约授予、续约与故障转移前先写入 SQLite 意图记录再提交事务；进程被强制终止后重启须扫描未完成意图，把未提交租约回滚到最后一个完整版本或标记为已中止，恢复报告只基于已持久化事实且不得承诺强制终止后仍生成完整退出报告；恢复后须重新评估所有节点心跳活性并输出失效节点清单。
7. 实现统一业务错误码与本地 HTTP 接口：接口覆盖节点注册、竞选、续约、退位、查询主节点与租约状态、查询恢复报告；失败响应为含业务码与上下文的 JSON，至少覆盖 E_NODE_INVALID、E_LEASE_HELD、E_NO_ELIGIBLE_CANDIDATE、E_STALE_LEASE、E_CONFLICTING_REQUEST 与 E_INVALID_TRANSITION。
8. 实现租约与故障转移状态机并定义合法迁移路径：节点状态至少包含 ACTIVE、SUSPECT、LEADER、FOLLOWER 四种，租约状态至少包含 FREE、GRANTED、EXPIRED 三种；非法迁移返回 E_INVALID_TRANSITION 且不修改已持久化状态；同一节点的状态迁移须与其租约版本变更在同一事务边界内完成，禁止出现节点已标记 LEADER 而租约版本未递增的情况。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地固定样本验证竞选、续约、故障转移、规模自适应裁决与强制终止恢复，输出租约版本与恢复报告。
