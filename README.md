需求评审已经通过，接下来要在 Linux 工作区的空目录中实现一套随机森林增量训练与诊断工作台，供建模团队在本地可复现数据上反复调参与观察。程序内置固定种子生成器产出本地 CSV 样本分片与 JSON 分片清单：每片含行数、列数、整数与定点小数列、类别列和含缺失值列，标签为二分类，并声明该片的样本行数与特征列名，作为预算预估与预处理的显式观测。运维通过本地 HTTP 接口提交带单调版本号的森林策略快照（树数、最大深度、每次分裂候选特征数、最小叶样本数、自助采样种子派生规则、全局评估次数预算、单工作进程配额与每轮时间预算），并以只含局部改动的增量片段调整参数或追加样本分片。工作台按特征分箱、逐树构建、森林汇总与诊断三个阶段推进，同时渲染一份可交互诊断视图：给出单树重要性、袋外误差曲线、预算消耗与并行执行明细，并把每棵树的构建进度与结论持久化到 SQLite，使进程被强制终止后能凭已提交事实恢复，且恢复结果与一次连续运行逐字节一致。

任务环境与准备：
安装 Go 1.22 及以上版本（如通过发行版包管理器或官方二进制包安装），执行 go version 确认可用。
准备 SQLite 访问：使用纯 Go 的 modernc.org/sqlite 驱动或系统 libsqlite3 绑定，离线模块缓存或本地 vendor 目录需提前就位。
确认本地回环网络可用，工作台 HTTP 接口监听 127.0.0.1 即可，不依赖外部服务与真实账号。
运行前用内置固定种子生成器完成样本分片与清单生成，写入本地工作目录，任务执行期间不再改动生成器种子。

业务要求：
1. 实现特征分箱与样本快照阶段：依据分片清单声明的列名与行数读取各分片，对连续列按可配置等频或等宽规则分箱、类别列按稳定字典编码、含缺失列写入显式缺失桶，并按分片序与行号拼接为带快照版本与内容指纹的样本矩阵；同一输入与配置必须产生逐字节一致的分箱映射与快照摘要，分片清单声明行数与实际不符、列名缺失或分箱边界重复时须返回带分片标识与列名的结构化错误码。
2. 实现确定性逐树构建核心：每棵树按配置的树数、最大深度、候选特征数与最小叶样本数构建，自助采样由配置种子与树索引派生的本地随机源生成，候选特征选择与分裂阈值裁决均按显式比较次序执行，叶节点不纯度以定点量化记录；同一快照与配置必须生成逐字节一致的树结构与叶节点摘要，出现无正样本叶、全缺失特征或量化后不纯度全等并列时须有确定性拆分规则并保留诊断依据。
3. 实现预算约束下的并行构建调度：以树为调度单元，在全局评估次数预算、单工作进程评估配额、并行工作进程上限与每轮时间预算四重约束下决定接纳顺序与并发度；接纳前依据样本行数、候选特征数与最大深度预估消耗，超预算树记录为未启动或已截断并给出原因，累计消耗与预估偏差须在诊断视图中逐树可见，不得静默丢弃任何一棵树。
4. 实现并行执行与确定性归约：使用本地工作进程池并行构建已接纳的树，各树的节点分裂记录、袋外误差与重要性贡献按树索引与节点路径全局排序后归约，使并行运行的森林摘要、重要性排序与袋外误差曲线与单进程顺序执行逐字节一致；工作进程异常须以结构化错误对象记录并保留已完成节点的部分产物，不得以线程超时描述为已终止失控代码。
5. 实现森林汇总与诊断视图：按归约结果计算每棵树的重要性与森林级重要性排序、袋外误差随树数增长曲线、逐树预算消耗与并行执行时序，输出可按树索引与特征名确定性查询的诊断报告；袋外样本数为零、某树无有效叶节点或重要性出现非有限值时须显式标记并计数，诊断报告中的排名须与逐树明细按同一口径重算一致。
6. 实现 SQLite 事务化的树级检查点与强制终止恢复：每棵树完成时在一个事务内写入含快照指纹、策略版本号、树索引、节点摘要、袋外误差、消耗预估与单调序号的记录，同一快照同一策略版本下同一树索引只允许一条有效记录；进程被强制终止后重启仅凭已提交事实重建森林进度，不承诺生成退出报告，恢复后的森林摘要与重要性排序须与一次连续运行逐字节一致。
7. 实现策略增量片段应用与依赖失效传播：接受只含局部改动的增量片段调整树数、深度、候选特征数与预算，通过各阶段内容摘要构成的版本指纹识别受影响的最早阶段与最早树索引，使该索引及其全部下游森林汇总失效重建，未受影响树的节点摘要继续复用；当策略快照整体替换或版本号回退时须区分正常推进、整体替换与回退，整体替换令全部派生状态失效，回退则拒绝并返回带当前生效版本的结构化错误码。
8. 实现并发发布互斥与本地确定性演示：多个工作进程对同一 SQLite 库提交树结果时使用事务条件更新与真实文件锁并比较树序号，仅允许序号连续推进，落后、重复或跨快照错位发布返回 E_STALE_CHECKPOINT 并附当前生效序号；提供命令行与本地 HTTP 接口的导入、执行、诊断查询、优雅停止与恢复能力，并用内置生成器的确定性分片演示正常构建、预算截断、中途强制终止后恢复与增量片段调参四类场景。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地确定性分片验证并行与串行森林结果逐字节一致、预算截断与恢复及增量失效行为正确。
