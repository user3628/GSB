在 Windows 空白工作区中，需要从零构建一个面向分布式块存储副本修复的领域组件与完整示例，供上层修复编排器集成。集群由若干副本组构成，每组有固定副本数并允许配置副本权重（表示各副本承载的数据份额比例），修复任务将一个副本组内各副本上报的数据摘要与块计数汇总为组级真值，再依据加权估算得出待修复字节量、进度比例与收敛判定。真实环境中各副本上报时刻不同、部分副本上报缺失或迟到，权重为浮点比例，块计数与字节量可达数十亿级整数，估算值经过多级乘除与累计求和，浮点运算顺序、权重归一化方式与舍入规则都会放大误差，使同一组在同一轮判定中得出不同的收敛结论。组件需以本地确定性样本驱动，持久化修复轮次并支持强制终止后的恢复。用户通过本地 HTTP 接口提交副本上报、发起轮次聚合与查询收敛结论。

任务环境与准备：
安装 Python 3.10 及以上版本，并准备 numpy 依赖：在项目根目录执行 pip install numpy 与本项目声明的其他纯本地依赖。
确认工作区为空目录，创建项目目录结构并初始化 SQLite 数据库文件，数据库文件与样本文件均放在本地项目目录内。
准备固定本地确定性样本：副本组与权重 JSON、多份副本上报 JSON（含缺失副本、迟到上报与混合量级块计数），样本随项目一并提交，不依赖任何外部服务。
在本机启动本地 HTTP 服务（监听回环地址的固定端口），示例脚本与自测均通过该地址访问接口，不访问外部网络。
确认可执行强制终止演示：脚本能启动子进程并在聚合中途终止，再次启动服务读取持久化状态生成恢复报告。

业务要求：
1. 实现副本组与上报模型：副本组声明副本数、各副本权重（浮点比例）与版本号，上报记录含副本标识、上报时刻、块计数与已同步字节量；解析时校验副本数一致、权重非负且合计为正，块计数与字节量为非负整数并做溢出检查，非法样本返回业务码 E_REPORT_INVALID 且整批不入库。
2. 实现权重归一化与加权估算：按权重把各副本块计数与字节量汇总为组级估算值，归一化须在选择全等权重、按上报权重归一与对缺失副本按零权重三种方案间由请求参数显式指定，并输出所用方案与归一化后权重，禁止在未声明方案时静默选择。
3. 实现累计求和的数值稳定性与误差界定：加权求和与占比计算使用 Kahan 或等价补偿求和，并与朴素求和在混合大数小数的固定样本上对比给出可量化误差上界；同一轮次同一上报集合重复聚合必须逐位一致，结论不得因运算顺序或副本上报顺序变化而翻转。
4. 实现待修复量与进度比例的定点表示：待修复字节量由组级估算值减已同步量得到，进度比例保留固定小数位并输出每步舍入方式与累计舍入误差；比例超出 [0,1] 的边界情形须给出确定处理与业务码，不得静默截断或产生 NaN。
5. 实现收敛判定与容差契约：判定某轮修复是否收敛时，比较实际进度与目标进度使用带相对容差的比较而非裸浮点比较，容差内视为收敛并按稳定字典序打破平局；输出判定结论、触发比较的双方数值与容差取值，使同一轮次在任意重算下结论稳定。
6. 实现迟到上报与轮次封版语义：轮次按声明截止时刻收集上报，截止后到达的上报进入迟到队列；封版时的估算仅使用截止时刻已入库上报并标记迟到条数，迟到上报只能在下一轮参与；若调用方要求严格等待，则轮次延后并在输出中标注延迟来源与延后时长。
7. 实现单写者聚合与多读者查询的并发一致：轮次聚合按副本组单写者串行执行，多个查询可并发读取已提交结论；同一轮次重复触发聚合只执行一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_ROUND；查询只能看到某一完整提交版本，不得出现上报已入库而组级估算未更新的中间状态。
8. 使用 SQLite 持久化副本组、上报、轮次结论与意图日志，聚合前先写意图记录再提交事务；进程在聚合中途被强制终止后重启须扫描未完成意图，把轮次标记为已中止或回滚到最后一个完整版本，恢复报告只基于已持久化事实，并附固定本地样本的端到端示例脚本输出三种归一化方案与迟到上报的估算差异。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
