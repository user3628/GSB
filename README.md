当前是空白工作区，没有现存项目、代码或数据附件，需要从零实现一个面向本地单机多模型推理场景的「推理网关并行路由与算力预算仲裁引擎」。网关对外暴露本地 HTTP 接口接收推理请求，每个请求携带模型名、输入张量形状、优先级、超时预算与幂等键；网关维护一组本地推理后端桩（每个后端只服务特定模型，声明并发槽位、单批最大请求数、每请求固定开销与按输入规模的算力系数），在共享算力预算（同时在途推理数上限、单轮总算力单位预算、每后端并发槽位）约束下完成并行路由、动态组批与结果回填。预算不足时请求须进入等待队列并基于真实单调时钟超时，不得以丢弃或伪造结果代替资源隔离。网关须对同一幂等键的重复请求回放首次结果而不重复消耗算力，并在进程重启后从持久化状态恢复窗口账目、队列次序与已提交结果。

任务环境与准备：
安装 Python 3.11 或以上版本，并确保 python 与 pytest 命令在 Windows PATH 中可用。
在项目虚拟环境中安装 FastAPI、uvicorn、NumPy、httpx 与 pytest（版本由本地已有 wheel 或离线源提供），不使用任何容器环境。
工作区为空，需自行创建项目目录、SQLite 数据库文件与本地样本目录，所有样本与推理桩在本地生成，不依赖外网或真实模型。
运行测试前确认 8000 至 8100 范围内本地回环端口可用，测试使用固定随机种子并可重复执行。

业务要求：
1. 实现推理后端与请求的数据模型及校验：后端桩声明标识、所服务模型名、并发槽位、单批最大请求数、固定开销算力单位与按输入规模的算力系数；请求含模型名、输入张量形状（维度名与各维长度）、优先级、超时预算与幂等键。须校验形状维度为正整数、算力折算结果为正、超时预算在配置上下界内、模型名有可用后端，非法请求返回固定业务码且不进入调度队列。
2. 实现并行路由与共享算力预算的双重准入：单个请求只有在目标后端并发槽位、单轮总算力单位预算与在途推理数上限三者同时满足时才可放行，任一不满足须拒绝本次准入并给出首个触发约束名与当前值；预算不足的请求须进入该后端等待队列而非丢弃，排队须有基于真实单调时钟的超时并以 E_QUEUE_BUDGET_EXHAUSTED 返回。
3. 实现按模型聚合的动态组批与批内算力核算：放行请求须按目标模型与到达次序组批，批容量受后端单批最大请求数与单批算力预算双重约束；批算力由固定开销与各请求形状折算的算力项求和得出，超出单批预算时须拆批并记录拆批依据；不得把不同模型的请求混入同一批，也不得在批执行中途追加请求。
4. 实现幂等键的结果回放与算力去重：同一幂等键的重复提交须回放首次完成的结果及其业务码，不得重复占用预算、并发槽位或算力单位；若首次请求仍在执行中，重复提交须等待同一结果而不是另起一次推理；幂等记录须持久化，进程重启后仍能识别已完成的幂等键并拒绝不一致的重复内容（形状或模型名不同）。
5. 实现算力账目与结果的原子提交：每批完成时须在单个 SQLite 事务中写入该批消耗的算力单位、占用槽位释放、各请求结果与幂等记录，事务提交后才对查询可见；任一步失败须整体回滚，使预算账目与结果集合均不变化；不得出现结果已可见但预算未扣减的中间状态。
6. 实现进程重启后的状态恢复与中断批处理：启动时须把中断时处于执行中的批判定为失败并释放其占用的槽位与预算，恢复等待队列的次序、轮次序号与已消耗预算账目，已成功提交的结果与幂等记录仍可回放；恢复后的账目须与历史累计消耗一致，并输出恢复裁定依据供诊断查询。
7. 实现本地 HTTP 调度与诊断接口：提供提交推理请求、查询请求状态与结果、查询后端实时视图（槽位占用、队列长度、已消耗算力）、查询调度事件序列、查询账目恢复报告的接口；事件须按严格递增序号持久化且可重复读取，所有错误统一以固定业务码在 JSON 中返回，诊断视图须与同一事务快照下的账目自洽。
8. 提供本地确定性推理桩与可重复测试：推理桩以 NumPy 计算代替真实模型并按形状与批量确定性产出结果，不依赖外网、真实模型或 GPU；pytest 用例须在 Windows 离线覆盖预算耗尽排队与超时、单批预算拆批、幂等回放、账目原子回滚、并发准入互斥与重启恢复，并使用固定随机种子保证逐条可复现。
