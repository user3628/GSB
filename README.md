# 多环境部署一致性验证平台

交付代码位于 `cmd/` 与 `internal/`。快速验收：

```powershell
# Windows PowerShell，要求 Go 1.22+
.\scripts\demo.ps1
```

```bash
# Linux/macOS/WSL
./scripts/demo.sh
```

关键文档与结果：

- `docs/TECHNICAL.md`：架构、API、业务码、事务/恢复和调度语义。
- `docs/VALIDATION.md`：实际测试、Windows 交叉构建、E2E 与强杀恢复记录。
- `artifacts/results/e2e-result.json`：机器可读的 15 项端到端验收结果。
- `workspace/samples/`：内置生成器产出的确定性 JSON 样本。
- `scripts/demo.ps1` / `scripts/demo.sh`：一键测试、构建和强杀重启演示。

手动启动：

```bash
go run ./cmd/platform -addr 127.0.0.1:18080 -db workspace/platform.db -workdir workspace
```

该服务使用纯 Go SQLite 驱动 `modernc.org/sqlite`，设置 `CGO_ENABLED=0` 即可构建 Windows 程序；探测目标全部是程序内置的 `127.0.0.1/probe/*` 端点。

## 原始任务说明

小团队承接的新需求要求在 Windows 空白工作区内构建一个多环境部署一致性验证平台，交付数据处理管线与结果验证工具。平台维护若干环境（开发、预发、生产）与每个环境下的部署单元，部署单元声明服务名、镜像摘要、配置键值、依赖单元与期望版本；运维人员通过本地 HTTP 接口提交带版本号的部署快照与只含局部改动的增量片段，平台据此编译每个环境的部署计划与依赖拓扑，并在本地测试端点并行执行一致性探测。难点在于并行调度与资源预算：探测任务受全局并发上限、每环境并发上限与每轮时间预算三重约束，同时某部署单元变化会沿依赖链触发级联失效，派生结果必须原子重建。

任务环境与准备：
安装 Go 1.22 或以上版本，确认 go 命令在 PATH 中可用。
使用 go mod init 初始化模块并引入 SQLite 驱动（如 modernc.org/sqlite），确保无需 CGO 即可在 Windows 构建。
创建本地工作目录用于存放 SQLite 数据库文件与由程序内置生成器产出的确定性 JSON 样本。
准备本地回环 HTTP 测试端点用于一致性探测，端点由程序内置测试服务提供，不依赖外部网络与真实账号。

业务要求：
1. 实现环境与部署单元模型及本地 JSON 样本解析：每个环境声明名称，部署单元声明服务名、镜像摘要、配置键值对、依赖单元列表与期望版本；解析时校验服务名在环境内唯一、依赖引用存在、镜像摘要格式合法，解析失败返回业务码 E_SPEC_INVALID 且不写入任何状态。
2. 实现带单调版本号的部署快照与增量片段提交：快照携带版本号、生成时间与整体校验摘要，增量片段只含受影响的部署单元并携带基础版本号；基础版本不是当前版本时返回 E_STALE_BASE 且不修改任何已提交状态；同一基础版本的两个并发增量只允许一个成功，另一个必须收到 E_STALE_BASE。
3. 实现部署计划、依赖拓扑分层与跨环境一致度评分三类派生产物，并维护每个部署单元与配置键对这些产物的引用关系；当镜像摘要、配置键或依赖列表变化时，全部受影响产物及其下游产物必须级联失效并在同一事务边界内原子重建，禁止出现部分产物已更新而引用索引仍指向旧版本。
4. 实现跨环境一致性校验与差异诊断：比较同一服务在各环境的镜像摘要、配置键与期望版本，按严重级别与稳定次序输出差异清单，差异项须携带环境、服务名、差异类型与双方取值；当某环境整体落后于基线环境超过声明的容差时返回 E_ENV_DRIFT 并附落后单元清单。
5. 实现以全局并发上限、每环境并发上限与每轮时间预算三重约束的并行探测调度器：预算内按环境优先级与环境内服务名稳定次序取任务，超并发上限者进入有界等待队列，队列满返回 E_PROBE_QUEUE_FULL；同一部署单元在同一轮内不得被重复探测，队列为空的轮次须显式输出空轮次结论而非静默跳过。
6. 实现真实可中断的探测执行：向本地测试端点发起 HTTP 探测，每次探测具备独立超时，超时后必须真实关闭底层连接并释放其占用的并发名额，返回 E_PROBE_TIMEOUT；探测结果、部署单元状态与预算消耗须跨模块一致生效，禁止出现探测成功而计划仍标记为待探测的中间可见状态。
7. 实现依赖环检测与降级处置：环境内依赖出现环时返回 E_DEPENDENCY_CYCLE 并附环上服务名列表；无法完成拓扑分层时仍须输出未被环污染部分的分层结果与受阻单元清单，保证同一事务边界内查询可见的部署计划与拓扑互相自洽。
8. 使用 SQLite 持久化快照版本、部署单元、依赖边、派生结构与意图日志，所有写操作先写意图记录再提交事务；进程在级联重建或探测轮次中途被强制终止后重启须扫描未完成意图，把状态回滚到最后一个完整快照版本或把增量标记为已中止，并提供含业务码的 JSON 错误响应与端到端演示脚本。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证快照与增量提交、级联重建、跨环境差异、并行探测预算与中断恢复，输出含业务码的结果。
