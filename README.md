当前是空白工作区，需要在 Windows 本地从零构建一个面向 Kubernetes 风格演练环境的 Pod 中断预算（PDB）与节点驱逐裁决仿真引擎。引擎读取本地确定性 JSON 样本：节点清单（节点名、可分配 CPU 毫核与内存字节、是否被标记为待腾空、污点），工作负载清单（控制器类型、期望副本数、当前副本分布）与 PDB 清单（minAvailable 或 maxUnavailable、匹配选择器、适用控制器）。当运维人员对某节点发起腾空请求时，引擎须依据 PDB 约束逐 Pod 判定驱逐是否被允许、被阻塞的具体原因，并在允许时给出将副本迁移到其他可行节点的模拟放置建议；当整节点驱逐会违反多个 PDB 时，须按确定性规则选择部分放行与部分阻塞的组合。核心业务问题不是求解通用装箱最优解，而是 PDB 语义下的裁决正确性与可解释性：同一 PDB 集合上的驱逐次序会改变哪些 Pod 可以被驱逐，判定必须与声明式语义逐条吻合，而不是以近似比例代替。

任务环境与准备：
确认 Windows 环境已安装 Python 3.11 及以上版本，可用 python --version 检查。
在空白工作区创建项目目录，并使用 venv 创建并激活虚拟环境。
通过 pip 安装 FastAPI、uvicorn、pytest，版本以本地缓存或已下载轮子为准，确保可离线安装。
准备固定本地 JSON 样本：节点清单、工作负载与副本分布、两份 PDB（分别使用 minAvailable 与 maxUnavailable 百分比形式），放入项目 samples 目录。
确认 Python 标准库 sqlite3 可用，并预留本地数据库文件路径。
准备演示脚本所需的本地输出目录，不依赖任何外部服务或线上集群。

业务要求：
1. 实现样本解析与 PDB 语义模型：解析形如 500m、2、512Mi、1Gi 的 CPU 与内存量纲为毫核整数与字节整数并做溢出检查，解析失败返回 E_SPEC_INVALID；PDB 须正确区分 minAvailable 与 maxUnavailable 两种形式（均允许整数或百分比字符串），并按目标控制器的期望副本数把百分比换算为整数下限或上限，换算规则与舍入方向须在输出中显式标注。
2. 实现 PDB 匹配与健康副本统计：按 PDB 的选择器与适用控制器解析出受约束的 Pod 集合，健康副本只计入运行中且未处于待驱逐状态的副本，处于驱逐中或已标记为终止的副本须从可用数中剔除；当某 PDB 选择器匹配不到任何副本时返回 E_SELECTOR_EMPTY 而非按零副本静默通过。
3. 实现单 Pod 驱逐裁决与阻塞原因：对候选 Pod 判定驱逐后受其影响的每个 PDB 是否仍满足约束，被允许时输出受影响 PDB 与驱逐后的可用数，被阻塞时输出业务码 E_PDB_BLOCKED 并附阻塞的 PDB 名、当前可用数、所需下限与本次驱逐将造成的缺口；一次驱逐涉及多个 PDB 时必须全部满足才允许，任一不满足即阻塞。
4. 实现整节点腾空的多 PDB 组合裁决：对节点上全部 Pod 生成驱逐序列并按序列逐 Pod 模拟可用数递减，输出放行清单与阻塞清单；当调整序列次序可使更多 Pod 被放行时，须按确定性规则（例如交错来自不同 PDB 的 Pod 以延缓单一预算耗尽）给出放行数不少于朴素顺序的序列，并输出两种序列的放行数对比，不得通过忽略 PDB 约束提升放行数。
5. 实现模拟放置建议与资源可行性：对每个被放行的 Pod 在其他节点中筛选满足 CPU 毫核与内存字节余量、节点选择器与污点容忍的候选节点，按余量利用率与分散度打分后给出建议目标节点；无可行节点时该 Pod 的驱逐须降级为阻塞并返回 E_NO_FEASIBLE_NODE，且不得以放行后无处安置作为事后结果。
6. 实现裁决批次的并发一致与幂等：腾空裁决按节点单写者串行执行，多个只读查询可并发；同一节点同一请求标识重复提交只执行一次、其余等待并复用结果；裁决期间新到达的其他节点请求可并行，但查询不得看到部分 Pod 已判定放行而 PDB 可用数尚未扣减的中间状态，须输出可见性规则说明。
7. 使用 SQLite 持久化 PDB 集合、驱逐步骤与裁决结论，写操作先写意图记录再提交事务；进程在腾空裁决中途被强制终止后重启须扫描未完成意图，把该节点腾空批次标记为 ABORTED 并将 PDB 可用数恢复到最后一个完整步骤，恢复报告只包含已持久化事实，不得承诺强制终止后仍生成完整退出报告。
8. 提供本地 HTTP API 与端到端演示脚本：API 覆盖样本加载、单 Pod 驱逐判定、整节点腾空裁决、裁决明细与恢复报告查询，失败响应统一为含业务码的 JSON（至少覆盖 E_SPEC_INVALID、E_SELECTOR_EMPTY、E_PDB_BLOCKED、E_NO_FEASIBLE_NODE、E_DRAIN_NOT_FOUND）；脚本使用固定本地样本完成一次单 Pod 被阻塞、一次整节点腾空跨两个 PDB 的部分放行与一次强制终止后恢复，输出每步放行与阻塞清单、阻塞原因与恢复报告。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用固定本地样本验证 PDB 驱逐裁决、整节点部分放行、放置可行性及强制终止恢复报告，并附运行输出。
