当前是空白工作区，没有现存项目、代码或数据附件。需要从零构建一个本地可运行的文本摘要与改写引擎，交付算法实现与可复现的实验环境。业务场景是：给定一批本地确定性新闻式长文档分片（每条含 doc_id、标题、正文、语言标签、来源通道与目标摘要长度档），引擎要并行产出多路候选摘要（抽取式句子选择、压缩式句子改写、模板式要点重组三路），再按预算调度与融合打分挑选最终摘要，并支持人工编辑摘要后的增量重建。所有候选生成都基于本地确定性算法：抽取路用句子打分与最大边际相关选择，压缩路用规则化删减与同义短语替换表，模板路用要点槽位填充；不依赖任何真实生成模型、GPU、外部服务或在线接口。核心工程问题是并行调度与资源预算：生成候选与融合打分都要受全局候选句评估次数预算、单工作进程配额、并发进程上限与单请求延迟预算共同约束，同时候选摘要要能持久化、被编辑、并在输入分片或配置变化时只重建受影响的链路。

任务环境与准备：
确认 Windows 上可用 Python 3.11 及以上解释器，并能创建本地虚拟环境。
在虚拟环境中安装 NumPy，HTTP 与并发相关能力使用标准库 http.server、multiprocessing、unittest，无需 GPU、外部服务或网络样本。
使用工作区内固定随机种子的本地生成器产出文档分片样本、配置 YAML 与演示脚本，运行前检查样本目录与摘要输出目录存在。
运行前确认工作区可写，用于写入阶段检查点、文件锁与导出摘要文件。

业务要求：
1. 实现句子切分与抽取式候选生成：按中英文标点切分为带字符偏移的句子，做 Unicode NFKC 与小写化后以本地词频与位置权重打分，再用最大边际相关在目标长度档内选出句子集合，输出句子下标、原文片段与分数分量；同一输入与配置必须产生逐字节一致的候选，空文档或正文过短须返回带 doc_id 的 E_INPUT_TOO_SHORT。
2. 实现压缩式改写与模板式重组两路候选：压缩路按规则删减修饰从句并依据可配置同义短语替换表做替换，模板路抽取要点槽位后按模板拼装，两路均须保持要点覆盖度不低于可配置下限并输出被删减片段与替换依据；替换表缺少条目时须显式回退到原文并记录回退数量，禁止静默丢句。
3. 实现候选融合打分与最终摘要裁决：按要点覆盖、长度贴合度、语言一致性、来源先验在对数域合成三路候选的融合分，并输出各候选分数明细与被淘汰原因；同分须有确定性仲裁规则，长度档越界或语言标签与正文不匹配的候选须标记为不可用而非直接丢弃。
4. 实现预算约束下的并行调度：以文档为调度单元，在全局候选句评估次数预算、单工作进程评估配额、并发进程上限与单请求延迟预算共同约束下决定接纳顺序与并发度；接纳前按分片正文长度与目标长度档预估消耗，超预算文档记录为未处理并给出原因，超出延迟预算须返回 E_LATENCY_BUDGET 而非阻塞等待。
5. 实现并行执行与确定性归约：使用本地进程池并行处理已接纳文档，各文档的候选列表、融合分与最终摘要按 doc_id 全局排序后归约，使并行运行的汇总输出与串行顺序执行逐字节一致；工作进程异常须以结构化错误对象记录并按文档隔离，不得因单文档失败而丢弃其他已接纳文档结果。
6. 实现摘要编辑与阶段检查点持久化：允许人工编辑最终摘要文本并生成单调编辑版本号，每阶段完成时以原子方式写入含阶段名、doc_id、输入内容指纹、配置版本、编辑版本号、产物摘要与单调序号的记录，写入任意位置中断不得留下半写记录；进程收到停止请求时完成当前不可拆分文档单元后退出，不承诺强制终止后生成退出报告。
7. 实现版本变化检测、增量重建与并发发布保护：当文档内容、目标长度档、候选权重、预算配置或替换表任一变化时，通过各阶段内容摘要构成的版本指纹识别受影响的最早阶段，使该阶段及其全部下游产物失效并重建，未受影响上游候选继续复用，且人工编辑过的摘要须标记为需复核而非静默覆盖；多进程发布同一工作区产物时使用文件锁并比较序号，落后、重复或跨文档错位发布返回 E_STALE_CHECKPOINT。
8. 提供本地 HTTP 与命令行实验接口及确定性演示：支持导入文档分片与配置、触发分阶段候选生成与融合、查询各阶段状态与版本指纹、查看预算消耗与未处理文档原因、列出候选分数明细、提交摘要编辑、请求停止与执行恢复、导出最终摘要集；演示数据至少 4 个文档分片，含中英混排、不同长度档与至少 1 个必然超预算文档，一次完整运行生成固定摘要，并演示停止后恢复结果与完整运行逐字节一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地分片样本验证候选生成、预算调度、编辑后增量重建与停止恢复一致性，并检查各错误码。
