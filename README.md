当前是空白工作区，需要从零实现一个面向本地负载均衡场景的「健康检查探测与后端选择引擎」，用于在离线环境下复现真实负载均衡器中主动健康检查、被动观测与后端选择协同的核心机制。引擎管理一组后端实例（地址、权重、健康检查配置、被动失败统计），周期性发起主动健康检查并依据结果更新实例健康状态；同时维护后端连接观测，按观测结果动态调整健康判定。客户端以本地并发方式提交请求，引擎须在交互延迟预算内完成探测与选择，并根据当前健康视图与权重选择后端返回。真实负载均衡器的难点在于：探测任务并发受资源预算约束，被推迟的探测不得导致实例被错误标记为不可用；探测超时与连接观测必须区分真实超时与调度延迟；进程重启后探测进度与健康状态必须从持久化状态恢复且与重启前一致；并发探测与后端选择同时进行时，选择结果必须基于某个一致的健康视图快照。

任务环境与准备：
安装 Python 3.11 及以上版本，并确认 python 与 pytest 可在 PowerShell 中直接运行。
安装 asyncio 标准库外的依赖仅 pytest 与 pytest-asyncio，使用 pip 从本地 wheel 或离线缓存安装，不访问外网。
在工作区创建项目目录与本地样本目录，探测桩绑定 127.0.0.1 随机端口，测试前由 pytest 夹具启动与关闭。
SQLite 使用标准库 sqlite3，数据文件置于工作区临时目录，测试用例固定随机种子与执行顺序。
确认 Windows 防火墙不拦截回环端口，所有测试在离线环境运行。

业务要求：
1. 实现后端实例与健康检查配置的模型及校验：实例包含地址、端口、权重、探测间隔、超时、连续失败阈值与恢复阈值；同一地址与端口重复注册须幂等覆盖且保持实例标识稳定。须校验端口范围、权重为正整数、超时不超过探测间隔，非法配置返回 E_BAD_INSTANCE 且不得进入调度队列。
2. 实现基于 asyncio 的真实超时主动探测与并发调度：每轮按配置的并发上限并行探测候选实例，单次探测须带基于真实单调时钟的超时取消语义且真正取消底层任务；探测超时时该实例记为本次探测失败而非阻塞整轮，探测耗时为真实测量而非固定值。
3. 实现交互延迟预算与探测推迟的一致性：每轮声明单轮探测延迟预算，预算耗尽后剩余候选项须进入该实例的推迟队列并按到达顺序在后续轮次优先处理，不得丢弃；被推迟实例的连续失败计数不得增加，推迟期间其健康状态由最近一次已完成的探测结果与恢复阈值决定，不得因未探测被误判为不可用。
4. 实现主动探测与被动连接观测的统一健康判定：同一实例的主动探测结果与被动失败统计须合并为连续失败与连续成功计数，达到失败阈值转为 unhealthy、达到恢复阈值转为 healthy；从 unhealthy 恢复须要求连续成功次数满足恢复阈值且期间无被动失败。非法状态迁移须拒绝并返回 E_INVALID_TRANSITION。
5. 实现权重轮询的后端选择与一致健康视图快照：选择时须基于一个一致的健康视图快照计算加权轮询，使每个实例被选中的次数比例逼近权重比例且不出现连续饿死；unhealthy 实例不得被选中；快照采集期间到达的探测结果只影响下一次快照，不得使同一次选择读取到半更新视图。
6. 实现 SQLite 持久化与进程重启恢复：探测记录、连续成功与失败计数、推迟队列、轮次序号与健康状态须在每次探测结果与状态迁移的提交点以单事务写入；重启后须恢复计数与队列并继续调度，中断时处于探测中的实例回退为可再探测且不计入失败；恢复后的选择结果须与重启前健康视图一致。
7. 实现并发探测与选择、注册的互斥与资源边界：注册、探测结果提交与健康视图快照须串行化到实例一致性边界内，不同实例之间可并行；并发抢占须基于真实单调时钟超时并返回 E_CONTENTION_TIMEOUT 而非静默失败；并发注册同一实例时只能有一个生效记录。
8. 提供本地确定性探测服务桩、诊断报告与可重复测试：实现可配置健康状态、响应延迟、超时与故障注入的回环 HTTP 探测桩，不依赖外网；诊断报告须列出每轮候选集合、实际探测、推迟项、预算账目与状态迁移依据；pytest 用例须在 Windows 离线覆盖真实超时、预算推迟、阈值迁移、重启恢复与加权选择比例。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
