当前是空白工作区，没有现存项目、代码或数据附件，需从零构建一个本地可运行的表格型特征编码与选择工作台，面向传统机器学习建模准备阶段，核心问题是并行调度与资源预算裁决。输入为固定随机种子生成器产出的本地 CSV 样本分片（含数值列、类别列、含缺失值列与一个二分类标签列），分小规模（约 600 行、10 列）与中规模（约 6000 行、40 列，含相关冗余列）两档，并附一份 JSON 声明文件记录每档文件名、行数、列数、缺失列下标与类别列取值基数，作为类型推断与预算预估的显式观测。另附一份 YAML 配置，声明编码策略（独热、目标编码、哈希编码）、缺失填充方式、特征选择方法（方差过滤、互信息排序、递归消除）、并行工作进程上限、全局特征评估次数预算、单进程评估配额以及单次查询延迟预算。工作台需按列类型推断、编码、特征选择、结果汇总四阶段推进，支持中断恢复、版本失效与并发发布保护，并提供本地 HTTP 与命令行交互。

任务环境与准备：
确认 Windows 本地具备 Python 3.10 及以上解释器，创建虚拟环境。
安装 numpy 与 pytest 及标准库 YAML 解析依赖 pyyaml，版本在此步骤确定。
运行题目自带的固定种子样本生成脚本产出两档 CSV 分片与声明文件、YAML 配置，样本落盘于工作区 data 目录。
确认工作区可写以创建检查点目录、锁文件与导出目录，无需网络、账号、GPU 或外部服务。

业务要求：
1. 实现列类型推断与编码阶段：依据声明文件与非空取值统计区分数值列、类别列与缺失列，按配置对类别列执行独热、目标编码或哈希编码，对缺失值按配置填充，输出编码后特征矩阵描述、列名映射与每列取值域；同一输入与配置必须产生逐字节一致的编码摘要，列类型与声明冲突时返回带列名与两方取值的 E_COLUMN_MISMATCH。
2. 实现目标编码的防泄漏设计与诊断：目标编码须基于分折的标签均值估计并附加可配置平滑强度，禁止使用当前行标签；训练折中不可见的类别回退到全局均值，同一类别在不同折的编码值差异须在诊断输出中可查看，折划分须由固定种子确定且可复算，出现全折只含单一类别时返回 E_FOLD_INVALID。
3. 实现特征选择阶段：支持方差过滤、互信息排序与递归消除三种方法，按配置阈值输出保留与淘汰特征清单及依据分数，选择必须作用在编码后特征空间且与列名映射对齐；方法或阈值变化须改变选择结果并产生新的版本指纹，淘汰特征不得出现在下游输出，阈值越界返回 E_INVALID_THRESHOLD。
4. 实现预算约束下的并行调度：以样本分片为调度单元，在全局特征评估次数预算、单工作进程评估配额与并行进程上限三重约束下决定接纳顺序与并发度；接纳前依据声明文件行数与列基数预估消耗，超预算分片记为未处理并给出原因，任何时刻累计评估次数不得超过全局预算，超出返回 E_BUDGET_EXCEEDED。
5. 实现并行执行与确定性归约：使用本地进程池并行处理已接纳分片，各分片编码摘要、选择清单与依据分数按分片序号与特征列序全局排序后归约，使并行输出与单进程顺序执行逐字节一致；工作进程异常须以结构化错误对象记录并保留已成功分片结果，不得以进程超时描述为已终止失控计算。
6. 实现阶段检查点持久化与优雅停止恢复：每阶段与每分片完成时以原子方式写入含阶段名、分片标识、输入内容指纹、配置版本、产物摘要与单调序号的记录，写入过程任意位置中断不得留下半写记录；收到停止请求时完成当前不可拆分单元后退出，恢复后最终编码摘要与选择清单须与一次从零完整运行逐字节一致，且序号连续推进。
7. 实现版本变化检测与并发发布保护：当样本内容、编码策略、平滑强度、选择方法或预算配置任一变化时，通过各阶段内容摘要构成的版本指纹识别受影响的最早阶段，使该阶段及其全部下游产物失效并重建，未受影响上游产物继续复用；多工作进程发布时使用真实文件锁并比较序号，落后、重复或跨阶段错位发布返回 E_STALE_CHECKPOINT。
8. 提供交互接口与本地确定性演示：命令行与本地 HTTP 接口支持导入样本、修改配置、触发分阶段执行、查询各阶段状态与版本指纹、查看预算消耗与未处理分片原因、请求停止、执行恢复、导出选择结果；演示数据覆盖两个规模档与至少 4 个类别列，一次完整运行生成固定摘要，并演示在分片间触发停止后恢复结果与完整运行一致。
