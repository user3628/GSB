项目起点是一个空白工作区，需要为局域网内的 QoS 流量整形平台实现一套策略下发与整形诊断工作台，并作为独立服务交付。平台维护若干整形队列，每条队列声明标识、承诺信息速率（CIR，bps 整数）、峰值信息速率（PIR，bps 整数）、承诺突发尺寸（CBS，字节整数）、峰值突发尺寸（PBS，字节整数）、优先级、匹配规则（源端口区间与 DSCP 值集合）以及依赖的父整形器；子队列的 CIR 与 PIR 不得超过父队列，依赖关系构成树而非环。运维人员通过本地 HTTP 接口先整体提交带单调版本号的策略快照，随后持续提交只含局部改动的增量片段（改速率、改突发尺寸、增删队列、调整父子依赖），每次提交都会使受影响的派生结构失效：队列的有效速率继承结果、按优先级的分层令牌桶视图、跨队列整形一致度评分都必须随之重建，未受影响的队列不得重算。真正的难点在于增量片段与并发诊断交叠：诊断请求持续携带基版本号读取某队列的令牌余量、发送与丢弃字节以及整形结论，而一次增量提交可能只改了一个父队列的 CIR，却让整棵子树的令牌桶参数与结论失效。因此系统必须在同一提交边界内完成依赖失效与原子重建，让读者看到某个完整版本而不是新旧混杂的结果；若读者携带的版本已被替换，必须得到明确的陈旧读裁决而不是旧值。离线流量样本由内置固定种子生成器确定性产出，令牌桶补充用整数运算，须给出每次舍入的说明与累计误差，以便整形结论可被复核。

任务环境与准备：
Windows 10/11 或 Windows Server，安装 Go 1.22 及以上（go version 可核对），无需容器或外部服务。
在空工作区执行 go mod init qosshaper 初始化模块，仅允许标准库与本地 SQLite 驱动（如 modernc.org/sqlite 或 mattn/go-sqlite3），用 go mod tidy 拉取并锁定版本。
程序启动时用内置固定种子生成器产出确定性本地样本：整形队列集合、父子依赖边与离线流量样本（毫秒时间戳、队列标识、字节数、DSCP），样本文件与种子写入工作区备用。
本地 HTTP 服务监听 127.0.0.1 的可用端口，SQLite 数据库文件置于工作区 data 目录，首次运行自动建表。
演示脚本为 Go 或 PowerShell 脚本，按固定顺序调用接口并打印业务码、版本号与整形结论；强制终止恢复演示通过外部命令终止进程后重新启动并查询恢复报告。

业务要求：
1. 实现整形队列与依赖模型及本地样本加载：队列声明标识、CIR 与 PIR（bps 整数）、CBS 与 PBS（字节整数）、优先级、匹配规则与父整形器引用；加载时校验标识唯一、速率与突发尺寸为满足 CBS 不超过 PBS 的正整数、父引用存在，解析失败返回业务码 E_POLICY_INVALID 且不改变已加载的队列集合。
2. 实现带单调版本号的整份快照提交与增量片段提交：增量只含受影响的队列字段或父子依赖边并携带基础版本号，基础版本不是当前版本时返回 E_STALE_BASE 且不改变任何已提交状态；同一基础版本的两个并发增量只允许一个成功，另一个必须收到 E_STALE_BASE，快照版本不大于当前版本返回 E_STALE_SNAPSHOT。
3. 实现依赖树校验与有效速率继承：校验父子关系无环并返回 E_DEPENDENCY_CYCLE 附环上队列标识；子队列的有效 CIR 与有效 PIR 由自身声明与父队列上限共同取最小值得到，并输出继承来源；父队列速率下调导致子队列有效速率变化时，必须重算该子树全部队列的继承结果而不涉及无关分支。
4. 实现分层令牌桶整形仿真并给出数值契约：依据有效 CIR、PIR、CBS、PBS 与优先级对离线流量样本逐包模拟，输出每包令牌余量、整形后发送字节、丢弃字节与标记颜色（绿、黄、红）；令牌补充使用整数运算并声明毫秒截断规则，输出每次舍入位与累计舍入误差，同一策略版本与同一样本重复仿真必须逐位一致。
5. 实现增量驱动的派生结构级联失效与原子重建：为每个队列维护其有效速率继承结果、令牌桶视图与整形一致度对自身字段与父链的引用关系；某队列速率或父子依赖变化时，受影响队列的全部派生结构必须级联失效并在同一事务边界内原子重建，禁止出现父队列已更新而子队列有效速率仍为旧值、或视图已更新而一致度仍为旧值的中间状态。
6. 实现携带观察版本的诊断读取与陈旧读裁决：诊断请求携带基版本号读取队列令牌余量、发送与丢弃字节及整形结论，若该队列视图版本不高于观察版本则返回结果并标注所用版本；若因级联重建未完成而落后于观察版本，必须返回 E_STALE_READ 并附视图版本与观察版本，不得返回陈旧结果。
7. 实现单写者提交与多读者查询的并发一致及强制终止后恢复：提交、级联重建与仿真批次按单写者串行执行，多个只读查询可并发读取某一完整提交版本，同一请求标识重复提交只执行一次；所有写操作先向 SQLite 写意图记录再提交事务，进程在级联重建或仿真中途被强制终止后重启须扫描未完成意图，把派生结构与令牌状态回滚到最后一个完整版本并把该提交标记为已中止。
8. 提供本地 HTTP API 与可重复演示：接口覆盖快照提交、增量提交、按版本查询队列有效速率与令牌桶视图、触发仿真与查询整形结论及误差说明、恢复报告查询；失败响应为含业务码与上下文的 JSON，至少覆盖上述全部业务码；演示脚本使用固定本地样本完成一次全量加载、一次仅改父队列 CIR 的增量提交、一次携带旧版本的陈旧读裁决与一次强制终止后的恢复。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
