项目立项时本地目录还是空的，需要为本地微服务测试环境实现一套服务注册与健康探测中间件，交付可集成的 Go 领域组件与可交互的诊断工作台。组件维护若干服务实例的注册快照（服务名、实例标识、端点、千分比权重、租约 TTL 毫秒与探测参数），运维通过本地 HTTP 接口提交带单调版本号的整份注册快照，或提交只含受影响实例的增量片段。组件需在全局并发探测上限、每服务并发上限与每轮时间预算三重约束下，对实例执行真实 HTTP 探针与租约心跳判定，维护实例健康状态；注册数据变化会使健康汇总、权重分配视图与探测计划失效，需要在同一事务边界内级联重建。所有样本与本地测试端点由程序内置固定种子生成器确定性产出，进程可能在探测轮次或级联重建中途被强制终止。

任务环境与准备：
安装 Go 1.22 或更高版本，确认 go version 可用。
安装 SQLite 3 命令行工具，确认 sqlite3 --version 可用；Go 侧通过 database/sql 与本地驱动访问 SQLite。
在 Linux（WSL Ubuntu）工作目录中初始化 Go 模块，无需网络下载第三方服务。
准备由程序内置固定种子生成器产出的确定性注册样本 JSON 与本地回环 HTTP 测试端点，不依赖真实账号或线上站点。
确保可自由使用本地回环端口启动测试服务，用于真实探测与超时验证。

业务要求：
1. 实现服务实例注册模型与带单调版本号的快照提交：实例声明服务名、实例标识、端点、千分比权重（1 至 1000 整数）、租约 TTL 毫秒与探测参数；整份快照携带版本号、生成时间与整体校验摘要，提交时版本号不大于当前版本返回 E_STALE_SNAPSHOT 且不改变任何已提交状态，校验失败保持旧快照完全可用。
2. 实现只含受影响实例的增量片段提交与基础版本绑定：片段携带基础版本号，基础版本不是当前已提交版本时返回 E_STALE_BASE 且不改变任何状态；同一基础版本的两个并发增量只允许一个成功、另一个必须收到 E_STALE_BASE，且失败方不得留下部分写入。
3. 实现三类真实健康探测：HTTP 探针以本地测试服务返回的约定状态码与响应体标记共同判定，租约心跳依据最近心跳时刻与 TTL 计算剩余寿命，TCP 拨号以真实连接成功或拒绝判定；每类探测具备独立超时，超时后必须真实关闭底层连接并释放并发名额，返回 E_PROBE_TIMEOUT，不得以等待冒充超时。
4. 实现实例健康状态机，至少包含 UNKNOWN、HEALTHY、SUSPECT、UNHEALTHY、DRAINING 五种状态并规定合法迁移路径；连续成功与失败阈值由快照声明，非法迁移返回 E_INVALID_TRANSITION 且不得修改已持久化状态。
5. 实现派生结构的引用关系与级联原子重建：为每个实例维护其健康汇总、按可用实例集合归一化的权重分配视图与探测计划对实例字段与租约状态的引用关系；权重、端点、租约参数或探测参数变化时，受影响实例的全部派生结构必须级联失效并在同一事务边界内原子重建，禁止出现实例已标记 UNHEALTHY 而权重分配仍包含其份额的中间可见状态。
6. 实现三重预算并行探测调度器：探测任务受全局并发上限、每服务并发上限与每轮时间预算共同约束，预算内按服务名与实例标识稳定次序取任务，超出并发上限的任务进入有界等待队列，队列满返回 E_PROBE_QUEUE_FULL；预算耗尽时按实例优先级与已消耗预算给出确定性延后次序并输出延后依据。
7. 实现单写者提交与多读者查询的并发一致及幂等：快照提交、增量提交、探测轮次推进与级联重建按版本单写者串行执行，多个只读查询可并发读取某一完整提交版本；同一请求标识重复提交只执行一次、其余等待并复用同一结果，内容不一致返回 E_CONFLICTING_REQUEST。
8. 使用 SQLite 持久化注册快照、租约、探测结果、派生结构与意图日志；所有写操作先写意图记录再提交事务，进程在探测轮次或级联重建中途被强制终止后重启须扫描未完成意图，把未提交探测结果回滚为待探测、把派生结构回滚到最后一个完整版本，恢复报告只包含已落盘事实；失败响应统一为含业务码与上下文的 JSON。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地固定种子样本与回环测试端点验证增量提交、真实探测、级联重建、并发预算与强制终止恢复，并输出可重复运行的诊断结果。
