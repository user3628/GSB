在一台没有历史代码的机器上，需要为多分支企业的边界防火墙运维团队从零构建一套规则集一致性裁决引擎。企业各分支维护同一业务策略的多份规则快照：每条规则包含序号、方向、协议、源与目的地址段（CIDR）、端口区间、动作与优先级；同一条流量在多个快照下可能得到不同裁决，运维需要定位是哪条规则、哪个字段、哪次区间换算造成分叉。规则中的端口区间与地址段需要换算为整数定点视图参与比对，流量统计以 1e-6 为最小单位的整数定点数累计，禁止浮点，换算与累计的截断误差必须逐次记账并可聚合出有界上界。引擎须维护带递增版本号的规则快照与裁决快照，支持并发多快照比对、版本链连续性校验与进程强制终止后的恢复，并以本地确定性样本与本地测试服务构造异常注入，验证裁决结论与误差账本自洽。

任务环境与准备：
安装 Go 1.22 或更高版本（Windows amd64），并确认 go version 可执行。
使用 Go 标准库 database/sql 配合纯 Go 的 SQLite 驱动（如 modernc.org/sqlite），通过 go mod tidy 拉取模块，无需 CGO 与任何容器环境。
准备本地确定性样本：程序内置生成器或预置目录产出 JSON 规则文件、文本块规则文件与探测流量清单，覆盖正常、分叉、定点溢出、版本跳号与整体替换等场景。
在任务目录下初始化 go 模块，工作目录须可写以创建 SQLite 数据库文件与临时报告文件。
所有验证通过 go test 与本地命令行运行完成，不访问外部网络服务、不依赖真实防火墙设备或账号。

业务要求：
1. 实现规则快照解析与规范化：从 JSON 规则文件与带长度前缀的文本块两种来源读取规则，统一为含快照标识、规则序号、方向、协议枚举、源与目的 CIDR、端口区间与优先级的内部模型；解析时校验 CIDR 格式、端口区间上下界、协议枚举受支持性与规则序号唯一性，非法条目返回 E_RULE_INVALID 并携带来源偏移，不得让单条非法规则污染其余规则。
2. 实现地址段与端口区间的整数定点换算：把 CIDR 换算为起始与结束地址的 128 位无符号整数视图，把端口区间与流量权重换算为 scale=1e-6 的 int64 定点数，换算中的截断误差逐次写入误差账本并可按快照聚合出有界误差上界；换算路径禁止浮点运算，乘法须检查溢出并在溢出时返回 E_FIXED_OVERFLOW，账本不得残留部分写入。
3. 实现多快照规则叠加与流量裁决核心：给定一条探测流量（方向、协议、源地址、目的地址、目的端口），按优先级从高到低在单个快照内裁决允许或拒绝并记录命中规则序号；对同一流量在多个快照下产生裁决序列，当两快照裁决不一致时定位首个分叉规则与分叉字段，返回 E_RULE_DIVERGENCE 并输出两侧命中信息，优先级相同且动作冲突时视为隐式分叉。
4. 实现误差传播下的分叉分类：利用两条快照各自累计的误差上界，把裁决不一致区分为确定性分叉（误差区间不重叠，结论稳定）与不确定性分叉（误差区间重叠，可能由换算截断导致）；两类分类结果连同误差上界区间写入裁决快照，分类判定不得依赖墙钟或随机因素，同一输入重复裁决得到逐字节一致的分类与区间。
5. 实现带版本号的规则与裁决快照并识别整体替换：每完成一轮快照解析与一轮流量裁决后在单个 SQLite 事务内提交递增版本号的快照，旧快照整体保留可回放；加载快照时校验版本链连续性，发现跳号返回 E_SNAPSHOT_VERSION 并回退到最近连续版本；内容比较须识别整体替换式版本变化而非仅比对版本号，即使版本号递增但内容被整体替换也要标记并输出识别结论。
6. 实现并发多快照比对的资源控制：多个快照比对任务在独立会话中执行，会话间规则状态与误差账本隔离；并发度与单会话规则数上限可配置，超并发上限的任务进入等待队列而非直接拒绝，单快照规则数超限时以 E_RULE_BUDGET 终止该快照并保留已解析部分；在途会话数须可观测，超等待阈值的请求返回 E_COMPARE_CONTENTION，所有并发冲突须可追溯至具体快照与规则序号。
7. 实现进程强制终止后的恢复一致性：比对或快照提交过程中进程被强制终止后重启，依赖 SQLite 已提交事务恢复规则快照版本、裁决结果与误差账本，已提交快照与账本不回退、未提交变更整体丢弃且该快照可重新比对；恢复后若发现版本链跳号须以 E_SNAPSHOT_VERSION 报告并进入最近连续版本；退出报告只在正常退出路径下生成，强制终止后仅依赖已提交状态恢复。
8. 实现异常注入验证入口与确定性报告：通过外部参数或配置文件构造六类样本——CIDR 非法、端口区间倒置、定点乘法溢出、快照版本跳号、整体替换式版本变化与同优先级动作冲突——分别断言对应业务码、已提交快照与误差账本未被污染、其余快照结论不受影响；注入仅通过输入与参数进行，不得修改源码；导出 JSON 报告包含各快照规则摘要、分叉定位、分叉分类与误差上界区间、版本链与业务码，按快照标识、规则序号与业务码稳定排序，报告中的时间字段仅使用固定采样标记，重复运行且输入不变时字节级一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地确定性样本验证多快照裁决、定点误差分类、版本链与异常注入业务码，重复运行报告字节级一致。
