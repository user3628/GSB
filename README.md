当前只有一台干净的开发机，需要从零构建一个面向企业内部单点登录（SSO）场景的票据校验引擎。引擎模拟中心认证服务（CAS）签发一次性服务票据（ST），多个受保护的服务端（SP）凭 ST 向校验端换取身份断言。校验端需在并发票据校验请求下保证同一票据只能成功兑换一次，同时输出可交互的延迟统计与一致性校验结果。由于 ST 具有严格的一次性语义，并发校验同一票据必须只能有一个请求成功，其余返回明确的业务码；校验结果还必须在会话快照中留有可追溯版本，供事后审计与恢复。引擎需要支持亚毫秒级延迟观测（以单调时钟差值采样），并在并发、异常注入与进程强制终止后重启等场景下保持状态一致与可重复演示。

任务环境与准备：
安装 Go 1.22 或以上版本（Windows 官方安装包），并确认 go version 可正常执行。
使用 Go modules 管理依赖，仅引入 go-sqlite3 或纯 Go 的 SQLite 驱动（如 modernc.org/sqlite），通过 go get 获取并锁定版本，无需外部数据库服务。
准备本地确定性样本生成入口所需参数文件（租户、SP、用户、密钥与并发脚本），全部由程序内置确定性种子生成，不依赖网络或外部账号。
确保运行目录可写，SQLite 数据库文件与报告输出目录位于工作区内的临时路径。
演示命令通过 go run 或编译后的可执行文件在 Windows 终端运行，无需容器或虚拟机。

业务要求：
1. 实现票据签发与校验核心：中心认证服务生成带全局唯一票据标识、目标 SP、租户、用户与过期时间的服务票据，并以本地密钥对票据载荷做完整性签名；校验端仅接受签名合法、未过期且目标 SP 匹配的票据，签名不符返回 E_TICKET_SIGNATURE，过期返回 E_TICKET_EXPIRED，SP 不匹配返回 E_TICKET_AUDIENCE，且失败请求不得消耗票据的一次性语义。
2. 实现票据一次性兑换的并发控制：同一票据标识的并发校验请求中仅允许一个成功，成功者写入兑换记录并返回身份断言，其余请求返回 E_TICKET_CONSUMED；兑换记录的写入与票据状态迁移必须在同一 SQLite 事务内完成，事务提交失败时整体回滚且不消耗票据，所有冲突须记录票据标识、请求序号与业务码。
3. 实现基于单调时钟的交互延迟采样与统计：对每个校验请求记录从接收请求到返回响应的耗时（使用单调时钟差值，不依赖墙钟），按租户与结果码聚合出样本数、平均、P50、P95 与最大值；统计输出中的时间戳仅使用固定采样标记，重复运行且输入与并发度不变时统计结果字节级一致；聚合过程不得为记录延迟而串行化票据校验主路径。
4. 实现带版本号的校验会话快照与一致性校验：每个租户的票据与兑换记录集合维护递增版本号快照并持久化到 SQLite，签发、兑换、过期清理均产生新版本；读取快照时校验版本链连续性，发现跳号返回 E_SNAPSHOT_VERSION 并拒绝继续服务该租户，可回退到最近连续版本；快照内容比较须能识别整体替换式版本变化，即使版本号递增也必须比对内容摘要判定是否真正变更。
5. 实现过期票据清理与延迟敏感的资源控制：后台按可配置周期清理过期票据，清理操作必须与校验请求在票据粒度上互斥，不得使正在校验中的有效票据被误删；校验并发度以可配置上限的信号量约束，超出等待阈值的请求返回 E_TICKET_CONTENTION 而非无限阻塞，清理任务与校验请求共享同一资源预算且清理不得挤占超过其配额份额。
6. 实现异常注入验证链路：通过外部参数或配置文件构造签名篡改、票据重放、SP 不匹配、快照版本跳号与并发兑换竞争五类样本，分别断言对应业务码、票据状态终态（已兑换或未兑换）与快照版本变化符合预期；注入仅通过输入或参数进行，不得修改源码制造失败，注入后其他票据的可用性不受影响。
7. 实现强制终止后的恢复一致性：进程被强制终止后重启，依赖 SQLite 已提交事务恢复票据状态与快照版本，已兑换票据保持已兑换、未提交事务整体丢弃且票据仍可正常兑换；恢复后版本链若发现跳号须以 E_SNAPSHOT_VERSION 标识并回退到最近连续版本；不承诺在强制终止前生成退出报告，恢复过程不得将未兑换票据错误标记为已兑换。
8. 提供可交互的专业演示入口与结构化输出：以子命令方式支持启动校验服务、查看某租户票据与兑换状态、展示延迟统计、回放指定并发场景；同时导出 JSON 报告，包含票据摘要、兑换结果分布、延迟统计、快照版本链与业务码，报告按票据标识与请求序号稳定排序，重复运行且输入不变时报告字节级一致，并附带本地确定性样本生成入口（租户、SP、用户、密钥与并发脚本）。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
本地并发样本验证同一票据仅一次成功兑换、延迟统计与快照版本一致，强制终止重启后状态可恢复，重复运行报告字节级一致。
