技术验证项目在 Windows 空白目录中立项：构建一个面向本地单机场景的事件总线流式集成中间件，交付数据处理管线与结果验证工具。总线维护主题与消费者组，生产者按分区键发布事件，事件经过接入、投递、确认三段状态演进；订阅者通过本地 HTTP 接口拉取并确认，总线依据消费位点推进投递并支持位点回拨重放。订阅者的消费驱动一条本地确定性聚合管线，按事件键分组累计计数与度量求和，管线中间状态随已确认批次演进。真实场景中多个消费者组并发拉取、热点分区与长尾分区并存，度量为双精度且量级跨越多个数量级，聚合在分批累加、跨批次合并与位点回拨重放后都会引入不同顺序的浮点运算。因此本项目的核心是数值精度与误差传播：计数与度量求和在何种求和实现下保持可界定的误差，重放与回拨如何让聚合结论与位点状态一起回滚到一致版本，误差记账必须逐批保留并可聚合出有界上界。所有数据来自程序内置固定种子生成器产出的确定性样本与本地 HTTP 测试端点，不依赖外部服务。

任务环境与准备：
Windows 10 或以上，安装 Go 1.22 或以上并确保 go 命令在 PATH 中；使用标准库与 modernc.org/sqlite 等纯 Go 依赖，通过 go mod tidy 拉取。
准备本地确定性样本生成器：以固定种子生成主题、分区键、事件批次与双精度度量，覆盖热点分区与量级跨越多个数量级的样本。
准备本地 HTTP 测试端点用于模拟消费者拉取与确认，不依赖真实消息中间件或外部网络。
使用 go test 与提供的演示脚本在本地运行，SQLite 数据库文件置于临时工作目录。

业务要求：
1. 实现主题、分区与事件模型：主题声明分区数与消费者组，事件含事件标识、分区键、生产序号、事件时刻毫秒、体摘要与批次标识；同一分区内生产序号由总线单调分配且无缺口，分区键经确定性哈希路由到分区；重复发布同一事件标识须幂等并返回既有生产序号，内容不一致返回 E_CONFLICTING_EVENT。
2. 定义事件与订阅状态机，至少包含 ACCEPTED、DISPATCHED、ACKED、REDELIVERED、DEAD_LETTERED 五种状态并规定合法迁移路径，非法迁移返回 E_INVALID_TRANSITION 且不修改已持久化状态；同一分区同一消费者组的位点只能单调推进或经显式回拨后退，禁止无痕跳跃。
3. 实现基于消费位点的顺序投递：消费者按消费者组与分区拉取该分区位点之后最小未确认事件，同一分区同一时刻只允许一个消费者持有投递租约，租约超时后须真实释放并按原序号重投而非跳过后继事件；并发拉取同一分区时仅一个成功取得租约，其余返回 E_LEASE_HELD。
4. 实现位点回拨与重放：调用方可将位点回拨到指定生产序号并触发重放，重放期间新事件投递暂缓，重放完成后按位点继续；回拨目标早于最早保留序号返回 E_OFFSET_EXPIRED，指向未提交序号返回 E_OFFSET_INVALID，越界均不得改变任何状态。
5. 实现三种可切换的分组聚合求和实现：朴素顺序求和、Kahan 补偿求和与按量级分桶后再归并；每批确认后按事件键分组累计计数与度量求和，输出所用算法标识、每批部分和摘要与可量化误差上界，同一批事件无论分批提交还是一次提交都必须落在声明的相对容差内。
6. 实现重放与回拨驱动的聚合回退一致性：位点回拨后，受影响批次对应的聚合增量必须逐批撤销并把聚合状态回退到回拨位点对应版本，重放确认后再按原顺序重新应用；撤销与重放后的聚合结论须与从未回拨、直接按该位点重新消费的结果逐位一致，禁止出现计数已回退而度量部分和未回退的中间状态。
7. 实现单写者提交与多读者查询的并发一致及幂等：拉取租约授予、确认、位点推进与聚合状态提交按分区单写者串行执行，多个只读查询（事件状态、位点、聚合结果、误差记账）可并发读取某一完整提交版本；同一请求标识重复提交只执行一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_REQUEST。
8. 使用 SQLite 持久化事件、投递记录、确认记录、位点、聚合状态与意图日志，所有写操作先写意图记录再提交事务；进程在确认、位点推进或聚合提交中途被强制终止后重启须扫描未完成意图，把未提交确认回滚为待投递、未提交位点推进回滚到原值、未提交聚合增量丢弃，恢复报告只基于已落盘事实；并提供本地 HTTP API 覆盖发布、拉取、确认、位点回拨、查询聚合与误差记账、查询恢复报告，失败响应统一为含业务码的 JSON。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定本地样本验证顺序投递、回拨重放、三种求和误差上界与聚合回退一致性，并核验强制终止后的恢复。
