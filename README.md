当前为空工作区，需从零构建一个本地可运行的图像修复与风格迁移工作台，核心难点在于多格式互操作与版本兼容。输入为本地确定性生成器产出的若干小尺寸图像分片（PNG 与 JPEG）以及一份 JSON 工程清单，清单描述每个分片的修复掩码（矩形区域的归一化坐标）、风格参考分片标识、风格迁移强度、修复迭代次数与输出格式偏好；系统不依赖任何真实生成模型与 GPU，修复以确定性邻域扩散填充实现，风格迁移以参考图的颜色统计迁移与可配置强度混合实现。工作台必须支持在内部无损工程格式（含完整掩码、分片标识与版本元数据）与对外交换格式（PNG、JPEG、JSON 描述三者互转）之间双向转换，并处理格式能力差异：JPEG 无透明通道、颜色量化不同、元数据丢失、旧版工程结构字段缺失等兼容问题。所有输入输出须在 Windows 本地可运行、可重复演示。

任务环境与准备：
安装 Python 3.11，并准备 FastAPI、Pillow、NumPy 等依赖（使用 pip 安装，无需容器与外部服务）。
生成确定性样本：用固定随机种子的本地生成器产出至少 4 个 PNG/JPEG 小图分片、一份工程清单、一份旧版结构清单与配套掩码描述。
准备演示脚本与配置样例，在 Windows 本地终端确认命令行与本地 HTTP 服务的启动方式。
不依赖真实账号、线上站点、付费资源、GPU 或任何缺失数据集。

业务要求：
1. 实现内部工程模型与三种格式的双向编解码：内部模型以分片标识、像素矩阵、修复掩码区域、风格强度与版本元数据描述一个分片；实现内部模型与 PNG（掩码存为透明通道）、JPEG（掩码降级为配套 JSON 描述）、JSON 描述文件之间的双向转换，同一内部模型往返转换后除显式记录的格式能力损失项外，像素矩阵、掩码区域、风格强度与版本元数据须逐字段一致。
2. 实现格式能力差异的显式降级与回补：导出 JPEG 时透明通道不可保留，须将掩码区域写入配套 JSON 描述并在内部记录降级项；从 JPEG 加 JSON 描述重新导入时须依据降级项重建掩码，重建掩码与原掩码的像素集合差异须为零，若描述缺失或与图像尺寸不匹配须返回 E_FORMAT_LOSS 并列出丢失项。
3. 实现旧版工程结构兼容解析：支持导入结构版本号为 1 的旧清单，其中掩码以像素坐标描述、风格强度为整数百分比且缺少分片标识字段；导入时须按可配置规则做坐标与强度归一化并生成稳定分片标识，兼容转换结果须可导出为新版本结构，且升级前后修复区域与风格强度语义等价。
4. 实现确定性修复与风格迁移核心：修复对被掩码覆盖像素按邻域已知像素做固定轮数的迭代扩散填充，风格迁移按参考分片颜色均值与标准差做可配置强度的统计迁移并做数值截断；同一输入与配置必须产生逐像素一致的输出，禁止使用未固定种子的随机数。
5. 实现格式转换过程中的数值精度与越界校验：像素运算须在浮点域进行并按格式位深做舍入截断，修复与迁移后像素值须落在合法范围；当出现 NaN、Inf 或强度越界时返回 E_NUMERIC 并附分片标识与像素坐标，禁止静默截断后写出图像。
6. 实现版本指纹与增量失效传播：当分片像素内容、掩码区域、风格参考、迁移强度、修复迭代次数或格式能力配置任一变化时，计算各阶段版本指纹并识别受影响的最早阶段，使该阶段及其下游产物失效并重建；未受影响上游产物继续复用，失效原因须在查询接口中可观测。
7. 实现持久化快照、优雅停止与并发发布保护：每个分片各阶段完成时以原子方式写入含快照序号、输入指纹、配置指纹与产物摘要的记录，写入任意位置中断不得留下半写记录；收到停止请求时完成当前不可拆分分片后退出；快照被整体替换时须识别序号回退、摘要不符与正常推进三种情形，多进程发布仅允许序号连续推进，落后或重复发布返回 E_STALE_SNAPSHOT。
8. 提供可交互应用与本地确定性演示：命令行与本地 HTTP 接口支持导入分片与清单、触发修复与风格迁移、执行格式互转与降级回补、查询各阶段状态与版本指纹、请求停止与恢复、导出结果；演示数据含至少 4 个分片、含 PNG 与 JPEG、一处掩码、一处旧版清单与至少一次格式降级，完整运行生成固定摘要，并用注入的非法强度与尺寸不匹配验证错误码。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证双向格式互转、降级回补与确定性输出，并核验增量失效与错误码一致。
