在一台没有历史代码的机器上，需要为某研发团队的本地依赖供应链完整性审计构建一条数据处理管线与结果验证工具。团队从不同来源采集到同一批软件组件的依赖清单：一种是由自研采集器写出的紧凑二进制清单（带魔数与版本头，v1 与 v2 两代字段布局不同，v2 增加来源仓库与签名摘要字段），一种是包管理器导出的逐行 JSON 清单，还有一种是旧版工具产出的带长度前缀的文本块清单。三种格式在组件命名大小写、版本号编码（语义化版本字符串、整数四段、带构建元数据）、完整性摘要宽度（SHA-1 十六进制、SHA-256 base64、截断前缀）与来源标识上互不兼容，历史快照可能由旧版本采集器产生。管线需要把同一组件的多来源声明归并为统一视图，按来源优先级裁决摘要冲突，识别被篡改或降级的依赖声明，并维护带版本号的快照以支持版本兼容加载与中断恢复，全程在 Windows 本地以确定性样本运行。

任务环境与准备：
Windows 10 或以上，安装 Go 1.22 或以上（go version 可验证），启用本地文件系统与 SQLite 文件写入权限。
项目从空目录初始化 Go module，SQLite 使用纯 Go 驱动（如 modernc.org/sqlite），通过 go get 安装，无需 CGO。
内置确定性样本生成器产出 v1/v2 二进制清单、JSON 行清单、文本块清单及六类畸形样本，样本与摘要全部本地生成，不访问网络。
准备一个独立临时工作目录用于 SQLite 状态库与报告输出，确保重复运行时可清理并重放。

业务要求：
1. 实现三种依赖清单源格式的解析与统一规范化：二进制清单按魔数与版本头区分 v1/v2 字段布局并逐项提取组件名、版本、完整性摘要与来源标识，JSON 清单逐行解析，文本块清单按长度前缀提取记录；统一为含来源、原始偏移、组件键、版本视图与摘要视图的内部模型，未知魔数或未知版本头返回 E_FORMAT_VERSION，记录截断返回 E_TRUNCATED 并报告已读字节数。
2. 实现组件键与版本号的跨格式归一：组件名统一为小写并保留命名空间分隔，语义化版本字符串、四段整数与带构建元数据写法统一转换为可比较的版本视图，预发布标签按语义化规则排序；摘要按算法识别宽度后统一为算法标识加原始字节的视图，SHA-1 与 SHA-256 分别标注算法，无法识别算法或摘要长度与算法不符返回 E_DIGEST_INVALID，归一过程保留原始写法用于溯源。
3. 实现多来源依赖声明的归并与摘要冲突裁决：以组件键加归一版本为归并键，按可配置来源优先级（二进制采集器、JSON 导出、文本块旧工具）选出权威声明；当权威来源与非权威来源的完整性摘要不一致时，标记 E_DIGEST_CONFLICT 并记录双方来源、偏移与算法，而不同版本并存时按版本视图分别保留并标记多条声明而非覆盖；归并结果须与任一来源单独读取的组件条数自洽。
4. 实现依赖降级与篡改迹象的判定：对同一组件键，当后到来源声明的版本视图低于已归并的最高版本、或摘要算法宽度低于既有声明时，分别标记 E_VERSION_DOWNGRADE 与 E_WEAK_DIGEST；判定须依据归并后的版本视图与来源优先级而非采集顺序，且同一组件同时出现降级与摘要冲突时两个业务码都要保留，结论写入供验证工具比对的结果集。
5. 实现带版本号的审计快照与版本兼容加载：每完成一轮解析与归并后在单个 SQLite 事务内提交递增版本号的快照，快照记录所依赖的格式版本集合与来源优先级配置；加载旧快照时若其所需格式版本或优先级配置与当前不兼容须整体拒绝并返回 E_SNAPSHOT_VERSION，快照内容比较须识别整体替换式版本变化而非仅比对版本号，加载时校验版本链连续性，跳号同样以 E_SNAPSHOT_VERSION 处理。
6. 实现并发多源归并调度的资源控制：各来源文件在独立解析会话中处理，会话间状态隔离，归并阶段按组件键分区串行以保证裁决确定；并发度与单会话组件数上限可配置，超并发上限的来源进入等待队列而非直接拒绝，单源组件数超限时以 E_COMPONENT_BUDGET 终止该源并保留已解析条目，在途会话数与排队长度须在报告中可观测。
7. 实现异常注入验证链路：通过命令行参数或配置文件构造未知版本头、文本块长度前缀超出剩余字节、摘要算法不符、同组件摘要冲突、版本降级与快照版本跳号六类样本，分别断言对应业务码、归并结果终态未被污染、已提交快照未被推进；注入仅通过输入与参数进行，不得修改源码制造失败，且单类异常不得影响其余组件的归并结论。
8. 提供确定性结果验证工具与结构化报告：以子命令方式支持运行全量归并审计、查询指定组件键的多来源溯源链、回放指定快照版本、切换目标格式版本与来源优先级；导出 JSON 报告包含各源解析摘要、归并后的组件声明与业务码、降级与冲突清单、快照版本链，报告按组件键、业务码与来源路径稳定排序，时间字段仅用固定采样标记，重复运行且输入不变时报告字节级一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
以本地确定性样本验证三格式归并、摘要冲突与降级裁决及快照版本兼容，重复运行报告字节级一致。
