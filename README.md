项目初始状态是空目录，需要为一家内部数据平台的合规团队构建一套敏感信息流追踪管线与结果验证工具。平台每日产生大量结构化操作事件（字段级读写、跨表复制、跨服务导出），合规团队需要沿着事件链追踪敏感标记（如证件号、银行卡、密钥材料）从源头字段流向何处，判定每条传播路径是否越出授权边界，并对判定结果做可复核的一致性验证。事件以本地确定性样本集给出：一部分是带魔数与版本头的紧凑二进制事件日志（v1/v2 两代字段布局不同），一部分是逐行 JSON 摘要；合规侧还维护带版本号的授权策略快照。管线在并发窗口下处理事件流，交互侧需持续展示追踪中的敏感信息流状态与延迟统计，而批量结算结果必须与交互侧展示的最终判定逐条一致，不能因乱序到达、并发刷新或中途重启出现两侧分叉。

任务环境与准备：
安装 Go 1.22 或以上版本，确认 go 命令在 PowerShell 中可用。
使用纯 Go 的 SQLite 驱动 modernc.org/sqlite 并在 go.mod 中固定版本，首次构建前执行 go mod download。
在工作目录内建立本地确定性样本生成入口所需目录，样本由程序内置生成器产出，不依赖网络或外部数据。
所有命令在 Windows PowerShell 中执行，测试进程使用 go test 与本地样本目录，不依赖任何容器环境。

业务要求：
1. 实现两种事件源格式的解析与统一规范化：二进制事件日志按魔数与版本头区分 v1/v2 字段布局，逐条提取事件序号、主体、源字段、目标字段、操作类型与逻辑时间；JSON 摘要逐行解析并归一为同一内部事件模型；对未知版本头、截断记录与字段缺失分别返回稳定业务码 E_UNKNOWN_VERSION、E_TRUNCATED、E_EVENT_FIELD_MISSING，且错误事件不得污染已归一化事件集合。
2. 实现敏感标记沿事件链的传播追踪核心：以授权策略快照中的敏感字段声明为源头，按事件序号与逻辑时间双序推进标记集合，对跨表复制、跨服务导出与聚合写三类操作采用语义不同的传播规则，遇到环路事件不得无限扩散；每条传播路径记录完整来源链，标记到达授权边界外目标字段时产生越界判定 E_FLOW_ESCAPED 并保留最小越界路径。
3. 实现交互侧与批量结算侧的一致性裁决：交互侧持续输出当前追踪中的标记集合与逐条判定摘要，结算侧对同一事件窗口给出最终判定，两侧结果必须按事件序号与目标字段逐条一致；当结算侧因乱序事件或后到事件需要修正先前判定时，仅允许向前推进版本并输出修正记录，禁止静默改写，交互侧展示必须能对应到同一判定版本。
4. 实现基于单调时钟的交互延迟采样与统计：对交互侧每次判定刷新记录从接收事件到完成追踪更新的耗时，按窗口与结果码聚合样本数、平均、P95 与最大值；统计不得使用墙钟，时间字段仅使用固定采样标记，重复运行同一输入时延迟聚合结果字节级一致，且延迟统计不得反向影响追踪判定结果。
5. 实现带版本号的追踪快照与整体替换识别：每个事件窗口完成结算后在单个 SQLite 事务内提交递增版本号快照，记录标记集合、判定摘要与所依赖的策略版本；快照内容比较须识别整体替换式版本变化而非仅比对版本号，加载时校验版本链连续性，发现跳号返回 E_SNAPSHOT_VERSION 并回退到最近连续版本继续处理。
6. 实现并发窗口调度与资源预算控制：多个事件窗口可在独立会话中追踪，会话间标记状态隔离；并发度、单窗口事件数与单会话内存预算可配置，超并发上限的窗口进入等待队列而非直接拒绝，单窗口事件数超限以 E_EVENT_BUDGET 终止该窗口并标记其判定为不完整，不完整窗口的判定不得计入最终结算一致性比对。
7. 实现异常注入验证链路：通过外部参数或配置文件构造乱序事件、环路传播、越界导出、快照版本跳号与并发窗口竞争五类样本，分别断言对应业务码、受影响窗口判定终态与其他窗口结论不受污染；注入仅通过输入或参数进行，不得修改源码或预置运行结果。
8. 实现强制终止后的恢复一致性与可复核输出：追踪过程中进程被强制终止后重启，依赖 SQLite 已提交事务恢复快照版本与窗口进度，已提交窗口不回滚、未提交窗口整体丢弃并重新追踪；恢复后若版本链跳号须以 E_SNAPSHOT_VERSION 拒绝继续并须能从最近连续版本重放；导出 JSON 验证报告，包含各窗口事件摘要、传播路径与越界判定、两侧一致性比对结论、延迟统计与快照版本链，按窗口标识与事件序号稳定排序，重复运行输入不变时报告字节级一致。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地确定性样本与注入参数运行管线，核验流追踪越界判定、交互与结算结果逐条一致及中断后的快照恢复。
