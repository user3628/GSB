某新业务线首个存储引擎项目刚立项，工作区没有任何既有实现，需要在 Windows 本地从零交付一个面向单机数据库检查点与 WAL 回放的领域组件。组件以页为单位维护表空间，所有修改先追加到 WAL 段文件，再通过检查点推进回放起点。WAL 与检查点元数据需与外部工具互换，因此必须同时支持紧凑二进制与分片 JSON 行两种持久化格式，两代格式在字段存在性与时间戳精度上存在差异。进程可能在段轮转、组提交或检查点写入中途被强制终止，重启后必须依据 SQLite 中已提交事实而非内存状态重建。

任务环境与准备：
安装 Go 1.22 或以上版本，确认 go version 可用。
安装 SQLite 3 命令行工具用于检查持久化状态，Go 侧使用纯 Go 的 SQLite 驱动。
在 Windows 本地新建空工作区目录，所有样本、段文件与测试数据均由程序内置固定种子生成器在本地产出，不依赖网络或外部服务。

业务要求：
1. 实现页式表空间与 WAL 记录模型：页记录页号、内容摘要、版本号与最近修改 LSN，WAL 记录含单调递增 LSN、事务号、页号、修改前后摘要与校验字段；解析失败返回业务码 E_RECORD_CORRUPT 并整段不入库。
2. 实现两种 WAL 与检查点元数据的持久化格式编解码：紧凑二进制格式含魔数、格式版本字节、段内记录长度前缀、CRC32 校验与可选字段存在位图；分片 JSON 行格式每行一条记录。两种格式对同一逻辑记录集合须可互相转换且语义逐字段一致。
3. 实现格式协商与版本兼容裁决：导入前检测格式与格式版本，按显式声明的兼容矩阵给出接受、降级接受或拒绝三种结论；旧版本缺修改前摘要或时间戳精度较低时降级接受并记录降级明细，高版本含未知必填字段时拒绝并返回 E_FORMAT_UNSUPPORTED。
4. 实现 WAL 段轮转与跨段 LSN 连续性：按声明的段字节上限与事务数上限轮转新段，全部 LSN 跨段连续无缺口且禁止两条记录占用同一 LSN；段头记录起始 LSN 与上一段摘要，轮转须原子生效，失败返回 E_SEGMENT_ROTATE_FAILED 并保持旧段可用。
5. 实现检查点坐标推进与段回收裁决：检查点记录回放起点 LSN、各页版本集合与整体校验摘要，序号须单调递增；只有其全部记录 LSN 不大于回放起点的段才允许标记可回收并真实移除，未覆盖时返回 E_RECLAIM_UNSAFE 并附未覆盖的最早 LSN。
6. 实现 WAL 回放：从检查点回放起点按 LSN 升序重放记录到页，逐条校验记录摘要与页当前版本一致性，版本跳号或不匹配返回 E_REPLAY_MISMATCH 并附期望与实际 LSN；回放中途失败须保持页状态停在最后一个一致版本而非部分应用。
7. 实现单写者组提交与多读者查询的并发一致：同一提交组内事务共用一个持久化屏障，组内任一记录写入失败时整组回滚且不得有事务进入持久状态；只读查询可并发读取某一完整提交版本，不得出现记录已持久而检查点仍指向旧版本。
8. 使用 SQLite 持久化检查点元数据、段目录、事务状态与意图日志，WAL 追加、段轮转、检查点推进与段回收前先写意图记录再提交事务；进程在组提交或检查点写入中途被强制终止后重启须扫描未完成意图，把未持久事务回滚并把检查点与段目录恢复到最后一个完整版本，恢复报告只包含已落盘事实。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证两种格式互转、WAL 回放与检查点回收裁决，并核验强制终止后恢复一致。
