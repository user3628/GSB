新领到的开发机上只有一个空工作目录，需要从第一行代码落成一个配置订阅树的收敛与陈旧读裁决管线，供本地多组件平台的读路径集成。平台把配置组织成键路径树，若干组件声明自己订阅的键路径前缀与依赖的上游组件；运维提交带单调版本号的完整订阅与配置快照，也提交只含局部键路径改动的增量片段。管线需依据前缀匹配与组件依赖展开算出每个组件的有效配置视图与受影响组件集合，并回答携带观察版本的读方能否直接拿到结论、哪些必须被拒绝而不能返回陈旧值。真实场景里前缀会嵌套、同一个键被多条路径覆盖、组件依赖会改向，进程也可能在视图重算中途被强制终止，收敛结论必须只依据已落盘事实复核。

任务环境与准备：
安装 Go 1.22 及以上，确认 go version 可执行。
在空工作目录执行 go mod init，仅引入标准库与本地 SQLite 驱动（如 modernc.org/sqlite），不依赖容器、外部服务或网络访问。
配置项与组件订阅样本由程序内置固定种子生成器写出到本地目录，验证脚本读取同一批样本，无需外部账号或数据集。

业务要求：
1. 实现键路径树、配置项与组件订阅模型：键路径按点分段且分段非空，配置项声明键路径、类型、取值与生效顺序号，组件声明标识、订阅前缀集合与依赖的上游组件列表；加载本地确定性 JSON 样本时校验组件标识唯一、订阅前缀是已声明键路径的前缀或显式标注为通配订阅、依赖引用存在，非法输入返回 E_SPEC_INVALID 且整批不生效。
2. 实现前缀匹配与覆盖裁决：对每个组件按最长前缀优先匹配其订阅前缀命中的配置项，同一键路径被组件自身订阅与上游组件依赖两条来源同时提供时，按生效顺序号与显式声明的来源优先级裁决并输出胜出来源与冲突明细；前缀之间存在嵌套时不得把父前缀的键计入子前缀，并输出每个键的匹配前缀与跳数。
3. 实现带单调版本号的快照与增量片段提交：快照携带版本号、生成时间与整体校验摘要，提交时版本号不大于当前版本返回 E_STALE_SNAPSHOT 且不改动任何已提交状态；增量只含受影响键路径或订阅并携带基础版本，基础版本不是当前版本返回 E_STALE_BASE，同一基础版本的两个并发增量只允许一个成功、另一个必须收到 E_STALE_BASE。
4. 实现有效配置视图与受影响组件集合的重算：依据覆盖裁决结果与组件依赖展开计算每个组件的有效配置摘要、受影响组件集合与传播跳数；受影响集合须覆盖直接订阅被改键的组件及其全部下游依赖组件，输出触发键、传播路径与是否存在未收敛组件，重算结论按提交边界一次性可见。
5. 实现携带观察版本的陈旧读裁决：读请求携带观察版本，若该组件的有效配置视图版本不高于观察版本则返回视图并标注所用版本；若因重算未完成而落后于观察版本，必须返回 E_STALE_READ 并附视图版本、观察版本与待收敛的键路径清单，禁止降级返回更旧视图或部分视图。
6. 实现视图与受影响集合的级联失效与原子重建：为每个组件维护其有效配置摘要、受影响集合与传播跳数对键路径、订阅前缀与依赖边的引用关系；任一被引用对象变化时，受影响组件的全部派生结构必须级联失效并在同一事务边界内原子重建，禁止出现上游组件视图已重建而下游组件受影响集合仍指向旧依赖边。
7. 实现单写者重算与多读者查询的并发一致及幂等：快照提交、增量提交与级联重建按提交单写者串行执行，多个读请求可并发读取某一完整提交版本；同一提交标识重复提交只执行一次、其余等待并复用同一结果，内容不一致返回 E_CONFLICTING_REQUEST，查询不得看到某键已写入而视图摘要尚未更新。
8. 使用 SQLite 持久化快照版本、配置项、订阅关系、有效视图与意图日志，提交、重算与级联重建前先写意图记录再提交事务；进程在重算中途被强制终止后重启须扫描未完成意图，把有效视图与受影响集合回滚到最后一个完整提交版本或将增量标记为已中止，恢复报告中每个组件结论只能来自已落盘事实；并提供本地 HTTP 接口与基于固定样本的验证脚本，失败响应统一为含业务码与上下文的 JSON，至少覆盖 E_SPEC_INVALID、E_STALE_SNAPSHOT、E_STALE_BASE、E_STALE_READ、E_CONFLICTING_REQUEST。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定本地样本验证前缀覆盖裁决、增量提交的陈旧读拒绝、级联重建与强制终止后的恢复结论。
