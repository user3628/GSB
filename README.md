为说话人识别与分离团队从零构建一个本地可运行的说话人分离工作台，核心问题是交互延迟与计算结果一致性。输入是本地样本目录：一份录音清单 JSONL，每条含 recording id、采样率、声道数、时长秒数、相对路径；每个录音为本地确定性合成的 PCM WAV（16 位整数，采样率 8000 或 16000 Hz，单声道，时长数秒至数十秒，由不同基频与包络的合成音段拼接，段间有短静音）。另有一份说话人配置 JSON，声明目标说话人数上限、嵌入维度、分帧窗长与帧移毫秒、聚类迭代上限与融合权重，带配置版本号。工作区为空，需从零创建项目：一个可交互的 FastAPI 服务，提供工程创建、按录音触发嵌入提取与聚类、低延迟预览查询、逐录音结果查询、快照导出与诊断报告接口；另需输出说话人分离结果（逐帧说话人归属与逐段边界），并支持在并发请求下共享预算、中断后恢复。

任务环境与准备：
安装 Python 3.11 与 pip，创建本地虚拟环境并用 pip 安装 fastapi、uvicorn、numpy、httpx 与 pytest（不引入容器或外部服务）。
准备确定性合成脚本，生成覆盖 8000 与 16000 Hz、单声道、不同时长与含静音段的 PCM WAV 样本及录音清单 JSONL，固定随机种子与参数以便重复生成。
准备一份说话人配置 JSON（嵌入维度、窗长帧移、聚类迭代上限、融合权重与配置版本号）与一份全局预算单元取值，作为演示与测试的固定输入。
确认可在本机启动 uvicorn 服务并用 curl 与 httpx 调用接口，SQLite 使用 Python 标准库自带模块，结果目录可写。

业务要求：
1. 工程创建接口接收录音清单、说话人配置与全局预算单元，校验清单字段完整、WAV 头与清单声明的采样率与声道数一致、嵌入维度与窗长窗移为正毫秒且帧移不超过窗长、聚类迭代上限为正整数、预算单元为正整数；任一非法返回 E_PARAM 业务码并指出出错文件与行号，且不得创建任何结果文件或临时目录。
2. 须实现确定性帧级嵌入提取：先按清单把各声道下混为单声道，再按窗长与帧移划分帧并加显式窗函数，由帧能量、过零率与基频估计派生固定维度的嵌入向量，全部在 float64 下计算；相同录音与配置下嵌入向量须逐位可重复，提取器不得依赖系统时间、全局随机状态或字典遍历顺序。
3. 嵌入须按余弦相似度做确定性聚类：相似度矩阵按录音内帧下标升序计算，聚类迭代按帧编号升序处理，迭代达到配置上限或聚类中心变化量低于容差即停止；同一录音与配置下逐帧说话人归属与边界序列须完全可重复，帧数须按窗长窗移换算并声明取整规则。
4. 聚类结果须在低延迟预览接口上返回：预览只返回帧数、当前聚类数、逐段边界摘要与若干帧的归属，且必须与用同一参数走完整重算得到的结果完全一致；预览走近似或抽样路径的结果不得与全量结果产生任何差异，检测到差异时返回 E_VERIFY 而不是返回看似正常的结果。
5. 服务须支持多录音并发处理并共享创建时给定的全局预算单元：每个录音每帧嵌入提取与每轮聚类的预算消耗按实际帧数与配置给出，预算在任务开始前原子扣减、结束后归还，预算不足时按 recording id 字典序排队并返回 E_BUDGET，而不得阻塞等待或超额执行；并发场景下扣减总数不得超过给定值。
6. 逐录音的阶段结果须在 SQLite 中以录音、阶段、帧三段记录提交，单个录音的嵌入统计、聚类结果与进度标记在同一事务中写入；某录音处理失败时该录音整体回滚，不得留下部分帧归属或与快照版本不一致的记录，其他录音不得因此整体失败。
7. 每次完整处理须以整体替换方式生成版本化快照，含配置指纹（配置内容哈希、聚类迭代上限、相似度容差）、各录音逐帧归属摘要与结果文件内容哈希；读取快照时若检测到数据库版本与磁盘结果文件哈希不一致、配置指纹变化或残留旧版本结果文件，须返回 E_STALE 并定位到录音与版本，禁止汇入旧数据。
8. 进程被强制终止后重启，须从 SQLite 已提交进度继续，核对每个录音的阶段标记、结果文件内容哈希与快照版本，重算未提交录音且不重复消费已提交帧；恢复后的逐帧归属、段边界序列与快照版本须与无中断执行完全一致，并须提供确定性本地演示入口，用固定录音与并发序列跑出聚类数、预览与全量一致性结论、预算排队次数、快照版本序列的可重复结果并给出可用 curl 复现的请求示例。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地合成录音验证嵌入提取、聚类归属、低延迟预览与全量结果一致，并验证并发预算与中断恢复后结果逐位一致。
