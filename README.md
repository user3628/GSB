在 Windows 空白工作区中，需要从零构建一个面向本地回环环境的容量评估与压测编排工作台。工作台维护压测计划（目标本地测试服务、并发档位序列、每档持续时长与判定阈值），按档位依次推进压测轮次，实时采集本地测试服务返回的延迟样本与错误计数，计算每档的吞吐、分位延迟与错误率，并据此在档位之间做升降档决策，直至找到容量拐点或达到档位序列末端。难点在于状态演进与恢复一致性：轮次状态会在待执行、采样中、已收敛、已中止之间迁移，进程可能在任何时刻被强制终止，重启后必须依据持久化事实恢复到一致状态，且已收敛档位的结论不得被重算篡改。所有压测目标为本地确定性测试服务，数据来自固定样本与固定随机种子，不依赖外部站点或真实账号。

任务环境与准备：
在 Windows 空白工作区创建项目目录，安装 Python 3.11 及以上版本并确认 python 可执行命令可用。
使用 pip 安装 fastapi、uvicorn、httpx 与 pytest，版本以本地 wheel 可安装为准，无需容器环境。
准备本地确定性样本文件（计划与档位序列）与固定随机种子与分布参数配置，随项目一并提交。
确认本地回环端口可自由绑定，用于启动本地测试服务与工作台 HTTP 服务。

业务要求：
1. 实现压测计划与档位模型：计划包含目标端点、并发档位序列（每档并发数与持续时长为正整数）、判定阈值（P99 延迟上限、错误率上限、最小吞吐）、升降档规则与固定随机种子；提交时校验档位并发严格递增、时长为正、阈值区间合法，非法返回 E_PLAN_INVALID 且不落库。
2. 实现轮次状态机，至少包含 PENDING、SAMPLING、CONVERGED、ABORTED 四种状态并规定合法迁移路径；每个档位对应一个轮次，采样结果写入后触发状态演进，非法迁移返回 E_INVALID_TRANSITION 且不得修改任何持久化字段。
3. 实现采样引擎：按档位并发数向本地测试服务发起请求并采集延迟样本与错误计数，样本延迟由固定随机种子按配置的分布参数确定性生成；单请求具备独立超时，超时须真实关闭底层连接并计入错误；采样期间不得违反档位并发上限。
4. 实现档位判定：依据该轮样本计算吞吐、P50/P95/P99 分位延迟与错误率，与判定阈值比较后输出通过与否决及具体触发的阈值名称与实测值；分位计算须使用确定性最近秩法并注明样本规模，样本数不足以计算所选分位时返回 E_INSUFFICIENT_SAMPLES。
5. 实现升降档决策与拐点结论：某档否决时依据升降档规则决定停止序列、回退到上一通过档或降档重测；已通过档位的结论一旦写入即为终态，后续轮次不得重算或覆盖；降档重测产生的轮次需与旧轮次区分标识，输出拐点档位与判定依据。
6. 实现并发一致与幂等：同一计划同一时刻仅允许一个轮次处于采样中，重复启动返回 E_ROUND_ACTIVE；同一档位重复触发只执行一次，其余等待复用结果；只读查询可并发读取已提交轮次结论，不得看到样本已部分写入而判定尚未更新的中间状态。
7. 使用 SQLite 持久化计划、轮次、样本聚合与判定结论，写操作先落意图记录再提交事务；进程在 SAMPLING 中途被强制终止后重启须扫描未完成意图，将轮次标记为 ABORTED 或恢复到可由已持久化事实重算的状态，恢复报告只包含已持久化事实，不得承诺强制终止后仍生成完整退出报告。
8. 提供本地测试服务与端到端演示脚本：使用固定种子生成多种延迟分布与错误注入模式的测试端点，脚本完成一次完整档位序列推进、一次中途否决回退、一次强制终止后恢复，输出各档吞吐、分位延迟、错误率、判定结论、拐点与恢复前后状态差异。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地固定样本与测试服务验证档位推进、判定结论、状态迁移及强制终止后的恢复一致性，并附运行输出。
