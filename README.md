在 Windows 空白工作区中，需要从零构建一个面向本地回环环境的 TCP 连接状态与拥塞控制仿真裁决工作台，供网络运维与协议教学场景集成。工作台以本地确定性事件轨迹为输入，轨迹中每条记录含毫秒时间戳、连接标识、事件类型（发送、确认、丢包、超时、重复确认）与载荷字节数，据此推进每条连接的拥塞窗口、慢启动阈值、往返时延估计与状态机（CLOSED、SYN_SENT、ESTABLISHED、FIN_WAIT、TIME_WAIT 等），并输出窗口演进轨迹与诊断结论。运维人员通过本地 HTTP 接口提交轨迹批次、查询某连接在指定仿真时刻的窗口与状态、触发重复仿真比对。核心业务问题是交互延迟与计算结果一致性：同一轨迹在不同提交次序、不同查询时点与并发诊断请求下必须得到逐位一致的窗口演进结果，而仿真推进又要满足单次请求的响应延迟预算。

任务环境与准备：
安装 Python 3.11 及以上版本，并用 pip 安装 FastAPI、uvicorn、NumPy 与 pytest，版本以本地可离线获取的稳定版为准。
确认工作区为空目录，在项目根目录创建本地 SQLite 数据库文件与固定事件轨迹样本目录，样本内容由任务自行生成且不依赖外部网络。
启动本地 HTTP 服务监听回环地址端口，演示脚本以该地址完成提交、查询与恢复演练，全程不访问外部站点或真实账号。

业务要求：
1. 实现事件轨迹解析与连接状态机：轨迹每条记录含毫秒时间戳、连接标识、事件类型与载荷字节数，非法事件类型或时间戳非单调时返回业务码 E_TRACE_INVALID 且整批不推进；状态机至少包含 CLOSED、SYN_SENT、ESTABLISHED、FIN_WAIT、TIME_WAIT 五种状态并规定合法迁移路径，非法迁移返回 E_INVALID_TRANSITION 且不修改已持久化状态。
2. 实现拥塞窗口演进算法：慢启动阶段每收到确认按确认字节数增长窗口，达到慢启动阈值后转入拥塞避免并按往返时延比例增长；遇到重复确认达到三次数时执行快速重传与快速恢复，遇到超时则把阈值减半并把窗口重置为初始值；重传与恢复期间不得让窗口小于声明的最小窗口，超时事件后的增长至少滞后一个往返时延并在轨迹中标注原因。
3. 实现往返时延估计与超时判定：对每个连接维护平滑往返时延与偏差估计，使用定点表示避免浮点累计漂移，超时重传时限由估计租值与配置的上下界共同决定；同一确认事件重复到达时不得重复更新估计，乱序确认须按确定规则判定是否为重复确认，禁止把乱序确认计入快速重传次数。
4. 实现交互延迟与计算结果一致性约束：仿真推进以事件为粒度可中断续算，查询请求可在指定仿真时刻快照返回窗口、阈值与状态；同一轨迹无论分批提交还是一次提交、无论查询在推进过程中还是推进结束后发起，所得各时刻快照必须逐位一致；推进过程须记录检查点以便续算，检查点内容须足以复原后续演进所需全部状态。
5. 实现单写者推进与多读者查询并发：轨迹推进按批次单写者串行执行，多个诊断查询可并发读取已提交快照；同一批次标识重复提交只推进一次、其余等待并复用结果；并发提交不同批次时各自的检查点与意图日志不得互相污染，查询只能看到某一完整提交版本而不得看到窗口已增长而状态仍为旧值的中间状态。
6. 实现基于 SQLite 的意图持久化与强制终止恢复：批次推进、检查点写入与快照提交均先写意图记录再提交事务；进程在推进中途被强制终止后重启须扫描未完成意图，把批次标记为已中止或回滚到最后一个一致检查点，并输出仅基于已持久化事实的恢复报告；恢复报告不得承诺强制终止后仍能生成完整退出报告，后续续算须从持久化检查点出发。
7. 实现统一业务错误码与 JSON 错误体：至少覆盖 E_TRACE_INVALID、E_INVALID_TRANSITION、E_BATCH_NOT_FOUND、E_CHECKPOINT_CORRUPT、E_STALE_BASE，每种错误返回稳定业务码与可检验的上下文信息且不得改动已提交状态；错误响应须与被接受请求的响应结构可区分，便于调用方自动化处理。
8. 提供端到端可重复演示脚本：使用固定本地样本生成一条含慢启动、一次快速重传、一次超时重传与若干乱序确认的事件轨迹，脚本完成一次整批推进、一次分批推进后比对快照一致性、一次并发查询与一次强制终止后恢复续算，输出各时刻窗口与阈值轨迹、诊断结论、错误码清单与恢复报告，供人工核验。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地固定轨迹验证窗口演进、分批与整批快照逐位一致、并发查询及强制终止后由检查点恢复续算，附运行结果。
