当前是空白工作区，需要在 Windows 本地从零构建一个面向增量计算与物化视图的领域可视化与诊断工作台。工作台维护若干基表（带版本号的列式样本，含行版本、逻辑删除标记与内容摘要）与一组物化视图定义（投影、过滤、分组聚合、连接等算子组成的依赖图），基表以带基础版本的增量批次追加或修正，物化视图由依赖图推导并增量刷新。运维人员通过本地 HTTP 接口提交基表批次、查看物化视图的行级内容与新鲜度、触发刷新，并诊断依赖失效传播过程。核心难点是增量更新与依赖失效：同一批次可能同时命中多个视图、视图之间存在级联依赖、增量修正可能让下游视图的部分聚合结果失效而非整表重算，工作台必须保证依赖图、视图状态与查询结果在同一事务边界内一致，并在进程被强制终止后依据持久化事实恢复。

任务环境与准备：
在 Windows 本地安装 Python 3.11 及以上版本，并创建空白工作目录作为新项目根目录。
安装 FastAPI、uvicorn、NumPy 与 pytest，确认 pip 可用且 SQLite3 模块随 Python 标准库可用。
准备固定的本地 JSON 样本（基表、视图定义与增量批次），全部由脚本生成且内容确定，不依赖任何外部账号或网络资源。
确认本地回环端口可用于启动 HTTP 服务，并在运行演示脚本前清空工作目录中的数据库文件以复现初始状态。

业务要求：
1. 实现基表存储与增量批次模型：基表快照携带单调递增版本号、生成时间、列定义（数据类型与空值位图）、行版本与逻辑删除标记，增量批次只含新增或修正的行并携带基础版本；基表与视图定义共同以确定性 JSON 样本提供，解析失败或批次基础版本不是当前版本时返回业务码 E_STALE_BASE 且不改变任何已提交状态。
2. 实现物化视图依赖图构建与拓扑校验：由视图定义解析出基表与视图间的依赖边，生成依赖图并按拓扑分层排序；出现环时返回 E_DEPENDENCY_CYCLE 并附环上视图标识，引用了未声明基表或视图时返回 E_REFERENCE_UNKNOWN；依赖图版本须随视图定义的整体替换而更新并可查询历史版本。
3. 实现视图状态机，至少包含 FRESH、STALE、REFRESHING、PARTIAL、INVALID 五种状态并规定合法迁移路径，非法迁移返回 E_INVALID_TRANSITION 且不修改已持久化状态；基表批次到达后受影响视图进入 STALE，刷新完成进入 FRESH，刷新中失败或依赖未就绪时进入 PARTIAL 并附具体缺口。
4. 实现删除与修正驱动的部分失效判定：对聚合类视图区分可增量修正的聚合与必须整视图重算的聚合（如最值、分位），可修正时只更新受影响分组并保持其余分组结果不变，不可修正时整视图标记重算；判定结论须输出受影响分组键、判定为可增量或整重算的依据，禁止对不可修正情形只更新部分分组而产生陈旧结果。
5. 实现依赖失效的级联传播与原子重建：视图定义变化或基表批次到达时，受影响视图及其全部下游视图的物化结果、分组索引与新鲜度标记必须级联失效，并在同一事务边界内原子重建，禁止出现上游视图已刷新而下游视图仍标记为 FRESH 的中间可见状态；诊断接口须按视图输出失效传播轨迹与被重算的分组数。
6. 实现可见性一致的刷新与查询并发：基表批次提交与视图刷新按单写者串行执行，多个只读查询可并发读取某一完整提交版本；查询可指定视图版本，若在查询期间该视图被新版本替换须在绑定版本上完成或返回 E_VERSION_RETIRED；同一刷新请求标识重复提交只执行一次、其余等待复用结果，内容不一致时返回 E_CONFLICTING_REQUEST。
7. 实现基于 SQLite 的意图持久化与强制终止恢复：批次写入、级联失效与视图刷新前先写入意图记录再提交事务；进程在刷新中途被强制终止后重启须扫描未完成意图，把视图与依赖图状态回滚到最后一个完整提交版本或标记为 PARTIAL，恢复报告只包含已持久化事实，不得承诺强制终止后仍生成完整退出报告。
8. 提供可视化诊断页面与端到端演示脚本：本地 HTTP API 覆盖基表批次提交、视图定义替换、刷新触发、按版本查询视图内容与新鲜度、诊断轨迹与恢复报告查询，失败响应为含业务码与上下文的 JSON；页面展示依赖图分层、各视图状态与最近失效传播；脚本使用固定样本完成全量构建、一次修正触发部分失效、一次定义变化触发级联重建与一次强制终止后恢复。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定样本验证增量刷新、级联失效、版本一致查询及强制终止后恢复结论。
