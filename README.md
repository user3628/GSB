当前是空白工作区，没有现存项目、代码或数据附件。需从零构建一个本地可运行的词性标注体系迁移与跨版本标注对齐引擎，交付算法实现与可复现的实验环境。业务场景是标注资产治理：团队需要把历史标注语料从旧词性标签集（含自由字符串词性、大小写混用与自定义扩展标签）迁移到新标准标签集，同时对齐同批语料在两套标注体系下的重复标注，识别并裁决标签映射冲突。输入为若干本地确定性生成的 UTF-8 JSONL 标注分片，每条含 sent_id、tokens（已切分 token 列表）、旧标签序列、新标签序列（可缺省）、标注者标识与结构版本号；另附一份 YAML 治理配置，描述旧标签别名表、新旧标签映射候选集、冲突裁决优先级、对齐容差与置信阈值。系统不依赖任何真实模型、词典服务或 GPU，全部映射与裁决基于本地确定规则与计数统计。引擎按分片推进迁移、对齐、裁决与汇总四个阶段，并支持中断恢复与版本失效传播。

任务环境与准备：
安装 Python 3.11 与 NumPy（pip install numpy），全部依赖均为本地包，无网络与 GPU 要求。
在空白工作区创建源码目录、本地样本目录与运行输出目录，确保工作区可写。
运行随交付提供的本地确定性生成器脚本，产出至少 3 个 UTF-8 JSONL 标注分片，含中英混排 tokens、自由字符串旧标签与大小写混用标注，以及结构版本 1 与版本 2 各一份分片。
准备本地 YAML 治理配置样本（旧标签别名表、映射候选集、裁决优先级、对齐容差与置信阈值）与一份用于触发 E_ALIGNMENT_FAILED 的注入输入样本，均为本地文件。
确认可在 Windows 上直接执行命令行与本地 HTTP 接口，无需数据库、容器或外部服务。

业务要求：
1. 实现旧标签规范化与映射候选生成阶段：对旧标签做 Unicode NFKC、空白折叠与大小写归并，依据别名表把自由字符串与自定义扩展标签归并到候选标准标签集合，输出每个旧标签到候选标准标签的映射候选及其来源（别名表命中或规则归并）；别名表缺失旧标签或某旧标签映射到多个候选时须保留全部候选并记录诊断，不得静默丢弃。
2. 实现结构版本 1 标注分片的兼容解析与显式升级：版本 1 中旧标签为自由字符串、token 数为零表示整句未切分、标注置信度为整数百分比；导入时须按可配置规则做标签归一、把整句未切分标记为不可对齐并在汇总中单列、把百分比换算为小数，转换结果须标注降级与换算依据，且应能反向导出为可被版本 1 消费的形态。
3. 实现标注对对齐核心：按 sent_id 与 tokens 序列把旧标注与新标注配对，token 序列不一致时按可配置对齐容差做最长公共子序列对齐并记录插入、删除与错位位置；对齐后的每个 token 位置形成旧标签与新标签组成的标签对，配对失败或对齐率低于阈值时返回带 sent_id 与对齐率的 E_ALIGNMENT_FAILED，不得部分写入对齐结果。
4. 实现标签映射冲突裁决：对同一旧标签在不同句子中映射到不同标准标签的情形，依据映射频次、标注者可靠度先验与治理配置中的裁决优先级合成映射可信度并选出唯一映射；可信度并列时须有确定性仲裁规则，被否候选及其依据须保留在诊断输出，已裁决映射与候选映射须可分别查询。
5. 实现映射表版本化与整体替换识别：每次完成一批迁移后生成单调映射表版本号，以原子方式写入含版本号、旧标签别名表指纹、裁决配置指纹、映射摘要与序号记录；当检测到映射表被整体替换（版本号回退、指纹变化或摘要不匹配）时须区分回退、篡改与正常推进三种情形，仅正常推进可被接受，其余返回 E_STALE_MAPPING 并保留旧版本内容。
6. 实现分片级持久化检查点与优雅停止恢复：每个分片按解析、对齐、裁决、汇总四阶段完成时以原子方式写入含阶段名、分片内容指纹、治理配置版本、映射表版本与单调序号的记录，写入过程任意位置中断不得留下半写记录；收到停止请求时完成当前不可拆分的句子单元后退出，不承诺强制终止后生成退出报告，恢复后最终映射表、对齐统计与汇总须与一次从零完整运行逐字节一致。
7. 实现版本变化检测与增量失效传播：当分片 token 或标签内容、旧标签别名表、裁决优先级、对齐容差或置信阈值任一变化时，通过各阶段内容摘要构成的版本指纹识别受影响的最早阶段，使该阶段及其全部下游产物（含映射表与汇总）失效并重建，未受影响上游产物继续复用；失效原因与被复用产物清单须在状态查询接口中可观测，禁止在版本变化后继续引用旧映射与旧对齐结果。
8. 实现并发发布保护、稳定业务错误码与本地确定性演示：多工作进程对同一工作区发布阶段产物或映射表版本时使用真实文件锁并比较序号，仅允许序号连续推进，落后、重复或跨阶段错位发布返回 E_STALE_CHECKPOINT，缺失前置阶段产物时返回 E_INVALID_STAGE；提供命令行与本地 HTTP 接口及演示脚本，至少 3 个分片含中英混排 token、自由字符串旧标签与大小写混用，完整运行生成固定摘要，并演示一次版本 1 文件导入与一次 E_ALIGNMENT_FAILED 注入。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
