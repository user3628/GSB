工作区为空，需要为搜索推荐团队交付一套离线 A/B 实验的分阶段评测组件，在本地样本上重放实验批次并给出可复核的放量结论。样本由程序内置生成器以固定种子产出：若干曝光事件（毫秒时间戳、用户标识、实验分组、物品标识、是否点击、耗时微秒）与一份实验配置（分组流量比例、各阶段最小样本数、CTR 与延迟判定阈值、中途停止与恢复轮次）。批次需按事件时间推进分阶段累计 CTR 与延迟分位，计算两组差值与区间估计后进行放量、继续观察或回滚裁决，并把执行状态持久化到本地 SQLite，使任一阶段中断后重启所得结论与指标和一次连续执行完全一致。

任务环境与准备：
安装 Go 1.22 及以上版本，确认 go 命令在 PATH 中可用。
无需外部服务、账号或数据集；样本与实验配置由程序内置生成器以固定种子产出。
SQLite 采用 Go 纯 Go 驱动，依赖通过 go mod 拉取，首次构建前需可访问模块代理或已缓存模块。
在空工作区执行 go mod init 初始化模块，并通过 go build ./... 与 go test ./... 验证构建与本地测试。

业务要求：
1. 实现曝光事件的分阶段累计核心：按实验配置的阶段划分把事件归入阶段，逐阶段统计两组曝光数、点击数、CTR 与延迟分位，累计须使用显式排序与确定性分位算法，同一批事件与配置必须产生逐字节一致的阶段统计，不得依赖 map 遍历顺序。
2. 实现阶段判定与批次裁决：以阶段最小样本数为门槛计算两组 CTR 差值与基于本地样本的区间估计，与判定阈值比较后输出放量、继续观察或回滚，并记录各项依据值与被否定理由；样本不足时须给出明确的观察结论而非默认放量。
3. 实现基于 SQLite 的批次状态持久化：将批次、阶段进度、阶段统计摘要与裁决结论以事务写入本地库，同一批次同一阶段只允许一条有效记录；进程在任意时刻被强制终止后重启，须仅凭已提交的持久化事实重建进度，不得依赖内存残留。
4. 实现优雅停止与强制终止的差异处理：收到停止请求时完成当前阶段聚合后落库并退出；被强制终止后重启只依赖已提交状态，不承诺生成退出报告，且恢复后的最终指标与裁决必须与一次连续执行逐字节一致。
5. 实现配置与样本变化的整体替换识别：当实验配置内容或事件样本集被整体替换时，须通过内容摘要与版本序号区分正常推进、整体替换与回退，替换后令全部阶段状态与结论失效重建，回退则拒绝并返回业务码。
6. 实现并发执行的互斥与一致性保护：多个执行进程对同一批次写阶段统计时须使用 SQLite 事务与条件更新，仅允许阶段序号连续推进，落后或重复写入返回 E_STALE_CHECKPOINT，确保并发下不会出现两个进程写入同一阶段的不同统计。
7. 实现异常输入的结构化业务错误码：对时间戳非单调、分组标记不在配置集合内、点击标记非零一、阶段划分覆盖不全、延迟为负等情况，须在对应环节返回带事件标识与环节名的稳定错误码（如 E_INVALID_EVENT），并保留可定位的诊断上下文。
8. 提供可集成的组件接口与完整本地示例：以库函数加命令行提供批次导入、分阶段推进、状态与版本查询、裁决报告导出，示例须用确定性样本覆盖正常放量、样本不足观察、阈值触发回滚以及中途终止后恢复四类场景。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地生成样本验证分阶段指标、批次裁决、并发写入与中断恢复后的结论逐字节一致。
