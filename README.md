团队在 Linux 空白工作区里承接了一项批量任务调度引擎的首次交付，须提供可集成的 Go 领域组件与可重复演示。平台按「作业→任务→阶段」三层组织，每个作业声明预算上限（CPU 毫核与内存字节），其下任务各自声明资源需求、依赖的其他任务、优先级与预计耗时；依赖关系构成有向无环图，同一波次内任务可并行、跨波次必须等待上游波次全部完成。执行端是本地回环测试服务，任务派发后需真实发起 HTTP 请求并在超时后真实断开。约束在于：作业预算被波次内所有并发任务共享，高优先级任务到来时须在已准入任务中抢占低级任务释放预算，抢占后释放出的额度要与待准入需求精确对齐，且配额在作业、波次与任务三级视图上必须始终守恒；进程可能在任何时刻被强制终止，重启后只能依据 SQLite 中已落盘的事实恢复调度轮次与预算账本，不得依赖内存重建。

任务环境与准备：
安装 Go 1.22 或以上版本，执行 go version 确认可用。
创建空工作目录并执行 go mod init，无需引入外部网络依赖，SQLite 驱动与解析库通过 go get 获取后离线缓存即可。
准备本地回环测试端点，可用 Go 标准库 net/http 自行启动，提供成功、可重试失败、致命失败与不响应四类行为。
样本与真值均由程序内置固定种子生成器在本地写出，不依赖任何线上资源、账号或附件。

业务要求：
1. 实现作业、任务与阶段模型及本地确定性样本加载：作业声明预算上限与波次划分规则，任务声明资源需求、依赖任务列表、优先级与预计耗时；解析时校验标识唯一、资源量为非负整数并做溢出检查、依赖引用存在且不得自指，失败返回业务码 E_SPEC_INVALID 并整批拒收。
2. 实现依赖图的波次划分与合法性校验：依据任务依赖边计算每个任务的波次序号，要求所有上游任务波次严格小于下游任务波次；出现依赖环时返回 E_DEPENDENCY_CYCLE 并附环上任务标识列表，同时仍须输出未被环污染的合法任务的波次结果与受阻任务清单。
3. 实现作业预算账本与三级占用视图：作业已用额度由已准入但未结束的任务需求合计得到，同时按波次与任务两级汇总，三视图必须逐项守恒；准入任务前在同一事务内递增占用，释放时递减，任何视图间差额非零即返回 E_LEDGER_DRIFT 并拒绝该次变更。
4. 实现带精确对齐的抢占裁决：高优先级任务因作业预算不足无法准入时，可从同波次或更早波次中挑选低优先级已准入任务抢占，挑选须使释放额度不低于待准入需求且超出部分最小，超出相等的按任务标识稳定字典序打破平局；被抢占任务迁移为 PREEMPTED 并真实归还其占用，若无可行组合返回 E_PREEMPT_INFEASIBLE 并附缺口与可释放总额。
5. 实现波次推进与并行调度的三重预算约束：调度轮次受全局并发任务上限、作业预算上限与每轮时间预算共同约束，预算内按波次序号、优先级与任务标识稳定次序取任务，超出并发上限的任务进入有界等待队列，队列满返回 E_DISPATCH_QUEUE_FULL；波次完成判定只依赖其全部任务进入终态，不得以计时器推断完成。
6. 实现向本地回环端点的真实派发与资源释放：每次派发具备独立超时，超时后必须真实关闭底层 HTTP 连接并释放其占用的并发名额与作业预算，返回 E_DISPATCH_TIMEOUT 并附任务标识；上游返回错误码时按声明区分可重试与致命两类，致命失败触发其下游任务级联迁移为 BLOCKED 并释放其已预留额度。
7. 实现单写者调度与多读者查询的并发一致及幂等：准入、抢占、波次推进与预算变更按作业单写者串行执行，多个只读查询（作业账本、波次视图、任务状态、抢占明细）可并发读取某一完整提交版本，不得出现任务已 PREEMPTED 而预算占用未归还的中间可见状态；同一批次标识重复提交只执行一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_REQUEST。
8. 实现基于 SQLite 的意图持久化与强制终止后恢复：准入、抢占、派发与预算变更前先写意图记录再提交事务，进程被强制终止后重启须扫描未完成意图，把未提交准入回滚为待调度、未提交派发回滚为可重派并把预算账本按已落盘事实重算，恢复报告只列已提交事实与差异明细。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地固定样本验证波次编排、抢占额度对齐与三级账本守恒，并核对中断恢复后账本与状态一致。
