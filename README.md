当前是空白工作区，需要从零实现一个面向本地对象存储场景的「分片上传与元数据一致性诊断工作台」。对象存储的大对象上传按分片进行：客户端先发起上传会话，再依次上传分片并声明各分片的内容摘要，最后完成会话并把分片按序号拼接为完整对象。真实实现中，分片描述不完整或校验和不一致会导致对象被错误拼接；分片迟到、重复上传与并发完成会产生元数据竞争；进程崩溃后必须依据持久化状态判断哪些分片可复用、哪些拼接需回滚。工作台须维护上传会话、分片记录与对象元数据的版本关系，在交互延迟预算内完成分片登记与一致性诊断，并通过本地 HTTP 接口暴露上述能力，全部状态以 SQLite 持久化。

任务环境与准备：
安装 Python 3.11 及以上版本，创建虚拟环境并安装 fastapi、uvicorn、numpy、pytest、httpx。
确认工作区为空目录，本地无需网络与外部存储服务，全部状态文件与 SQLite 数据库写入工作区子目录。
准备固定随机种子的本地分片样本生成脚本所需的参数文件，样本在任务执行时生成，不依赖任何外部附件。

业务要求：
1. 实现上传会话与分片登记模型：会话含会话标识、目标桶与对象键、分片大小下界与上界、预期总大小与声明分片数；分片记录含会话标识、分片序号、内容摘要、字节长度与上传时刻。须校验分片序号在声明范围内、长度落在上下界内、非末分片长度一致，非法请求返回 E_BAD_PART 且不写入任何记录。
2. 实现分片内容的多摘要校验与确定性标识：每个分片同时维护内容 MD5 与 SHA-256 摘要，分片键由会话标识、序号与双摘要共同确定；重复上传同一序号时若双摘要一致须幂等覆盖记录且不改变已登记顺序，摘要不一致须返回 E_PART_CONFLICT 并保留原记录不被覆盖。
3. 实现完成会话的分片完整性检查与拼接元数据生成：完成时须校验已登记分片数等于声明数、序号连续无空洞、分片长度之和等于预期总大小，任一不满足返回 E_INCOMPLETE 并列出缺失序号；校验通过后按序号顺序生成对象分片清单与整体内容摘要，重复触发完成须返回同一结果而非重新分配版本号。
4. 实现交互延迟预算内的分片登记与超大分片清单分批处理：分片登记须在声明延迟预算内完成，按真实单调时钟计时，超预算时返回 E_LATENCY_BUDGET 并保持会话状态不变；当分片数超过分批阈值时，完成检查与清单生成须按批推进并允许在批间检查会话是否被取消，被取消会话不得产出对象元数据。
5. 实现并发上传与完成的互斥与状态机：会话合法状态为 initiated、uploading、completing、completed、aborted，非法迁移须拒绝并返回 E_INVALID_TRANSITION；同一会话的完成操作与分片登记须串行化到会话一致性边界内，不同会话可并行，完成进行中到达的分片登记须等待或按配置拒绝且结果必须确定。
6. 实现进程崩溃后的状态恢复与元数据版本识别：分片登记与完成提交须在单事务中写入 SQLite，事务提交后才对查询可见；启动时须把握中断时处于 completing 的会话回退为 uploading 并清除未提交的对象元数据，识别对象元数据的版本号变化，版本号未变但摘要变化须判定为损坏并返回 E_METADATA_CORRUPT。
7. 实现并发完成与元数据快照替换的一致性：对象元数据整体替换须携带递增版本号并先写临时文件校验摘要后原子替换，替换前旧版本保持可读；两个会话同时完成同一对象键时须按会话完成提交顺序串行分配版本号，后提交者不得覆盖已发布版本，冲突须返回 E_OBJECT_CONFLICT 并保留诊断依据。
8. 实现本地 HTTP 诊断接口与可重复测试：提供发起会话、上传分片、完成会话、中止会话、查询会话状态与分片清单、查询对象元数据版本的接口，错误统一以固定业务码在 JSON 响应中返回；附带固定随机种子的本地分片样本生成器与 pytest 用例，覆盖完整上传、摘要冲突、空洞拒绝、并发完成、崩溃恢复与元数据损坏诊断，全部在 Windows 离线运行。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地分片样本验证上传登记、完成校验、并发完成与崩溃恢复后的元数据一致性及错误码。
