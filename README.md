在 Windows 空白工作区中，需要从零构建一个面向本地对象存储场景的分片上传与元数据一致性组件，供上层领域数据编辑与操作应用集成。对象以对象键唯一标识，上传时被切分为有序分片，每个分片携带序号、字节大小、内容摘要（SHA-256）与上传时刻；组件维护上传会话、分片清单与对象元数据（键、总大小、分片数、对象摘要、创建时间、ETag 语义）。为支撑交互式编辑应用，客户端会边编辑边上传分片，中途可能取消、重传某分片、乱序提交分片或在同键上并发发起多个上传会话；合并对象前的校验与元数据写入必须保证交互延迟可控且最终结果一致。所有数据来自固定本地样本，不依赖真实对象存储服务或网络。

任务环境与准备：
安装 Python 3.11 或以上版本，并确保 pip 可用
在空白工作区创建项目目录，安装 FastAPI、uvicorn 与 pytest，版本以本机可安装的稳定版为准
准备固定本地分片样本与 SHA-256 摘要清单，放置于项目内 samples 目录，不引用外部对象存储
确认 SQLite 由 Python 标准库提供，无需额外安装；运行前执行数据库初始化脚本生成空库

业务要求：
1. 实现上传会话与分片模型：会话由对象键、会话标识、分片大小下界与状态组成，分片记录序号、字节大小、SHA-256 摘要与上传时刻；发起会话时若同键已有进行中的会话，须按指定策略返回业务码 E_SESSION_CONFLICT 或允许并存并给出明确规则，非法序号或超出分片大小约束的提交返回 E_PART_INVALID 且不得改动会话。
2. 实现分片提交幂等与乱序容忍：同一会话同一序号的重复提交只计一次，内容摘要一致视为幂等成功，摘要不一致返回 E_PART_MISMATCH 并保留首次提交；乱序到达的分片不影响最终合并顺序与对象摘要，组件须以序号为唯一定序依据而不依赖到达顺序。
3. 实现分片清单与对象元数据的一致性校验：合并前须校验分片序号从起始值连续无缺口、每个分片摘要与已存记录一致、对象总大小等于各分片大小之和；任一项不满足返回对应的业务码（至少 E_PART_MISSING、E_SIZE_MISMATCH）且不得产生部分写入的对象元数据，禁止出现对象已可见而分片清单仍不完整的状态。
4. 实现合并时的原子提交与版本识别：合并操作先写意图记录，再在同一事务内写入对象元数据与对象摘要并将会话置为完成；同键重复合并只允许一次成功，其余返回已有结果或 E_SESSION_COMPLETED；对象元数据须携带单调递增的对象版本号，覆盖写入时版本号递增且旧版本不可再被读取为新版本。
5. 实现交互延迟约束下的可配置合并策略：合并分为快速路径（仅追加且无缺口时直接依据已记录摘要计算对象摘要）与完整校验路径（逐分片重算摘要），由请求参数或会话配置选择；完整校验路径须输出每片校验耗时与总耗时，快速路径须输出所依赖的持久化证据；两条路径对同一会话必须得到相同的对象摘要与元数据，差异仅在耗时与校验覆盖度上。
6. 实现并发控制与可见性：分片提交与合并按会话单写者串行执行，多个只读查询（会话状态、分片清单、对象元数据）可并发；并发提交同一序号分片时仅一个生效、其余按幂等或冲突规则处理；查询只能看到某一完整提交版本，不得看到分片已记录而会话统计未更新的中间状态；同键并发会话的合并须串行化并保证对象版本号不重复。
7. 使用 SQLite 持久化会话、分片记录、对象元数据与意图日志，写操作先落意图再提交事务；进程在合并中途被强制终止后重启，必须扫描未完成意图把会话恢复为可重试状态或标记为已中止，并输出仅基于已持久化事实的恢复报告，不得承诺强制终止后仍生成完整退出报告；恢复后重新合并须得到与中断前一致的对象摘要。
8. 提供本地 HTTP API 与端到端演示脚本：API 覆盖发起会话、提交分片、查询会话与分片清单、合并、取消会话、查询对象元数据与恢复报告，统一错误响应为含业务码的 JSON；脚本使用固定本地样本完成一次乱序提交后合并、一次重复分片提交、一次缺口合并失败、一次取消会话及一次强制终止后恢复并重新合并，输出各步骤状态、对象摘要与恢复前后差异摘要。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
