当前是空白工作区，需要从零构建一个面向本地列式数据的向量化表达式执行引擎，供上层分析管线集成。引擎接收表达式计划（列引用、算术、比较、逻辑与条件表达式，以及聚合与过滤算子），从固定本地列式样本（每列带数据类型与空值位图）构建列批次，按批向量化执行并产出结果列。数据规模会在几千行到数百万行之间变化，引擎需要在精确逐行路径与向量化批处理路径之间做算法取舍：小规模时逐行解释开销低，大规模时向量化收益明显，但两条路径必须给出完全一致的数值结果与空值语义。样本包含整数、双精度浮点与布尔列，并覆盖空值、溢出边界与除零等情形。用户通过本地 HTTP API 提交表达式计划与执行参数，组件以 SQLite 持久化执行会话、批统计与意图日志，进程可能被强制终止后恢复。

任务环境与准备：
确认 Windows 上可用 Python 3.11 及以上版本，并创建独立虚拟环境。
安装 numpy 与 requests 等依赖，版本写入依赖清单文件；不依赖任何外部服务或网络数据。
预置或由脚本用固定种子生成三档本地列式样本文件，包含空值、溢出与除零用例。
准备本地回环 HTTP 服务端口与 SQLite 数据库文件路径，确保可重复清理与重建。

业务要求：
1. 实现表达式计划解析与列批次模型：表达式计划为本地 JSON，节点包含列引用、常量、算术、比较、逻辑与条件表达式以及 Filter 与 Aggregate 算子；列批次按固定行数与列式数组组织并携带空值位图；计划非法、列不存在或类型不匹配时返回业务码 E_PLAN_INVALID 且不执行任何批次。
2. 实现向量化执行核心：对算术、比较、逻辑与条件表达式按 NumPy 数组整体求值并传播空值位图，条件表达式在空值分支上的取值规则须显式定义；结果列的 dtype 由输入类型与算子推导得出，整数溢出按声明的回绕或饱和规则处置，不得产生静默的类型提升差异。
3. 实现精确逐行路径与向量化路径，并保证两条路径对同一输入逐元素结果一致：评估器依据行数、列数与计划复杂度选择默认路径，调用方也可显式指定；两条路径在整数算术、比较边界、空值传播与条件表达式上均不得出现结果差异，浮点比较须使用声明的一致比较规则。
4. 实现数据规模自适应的批大小与路径选择：批大小按总行数与列数在给定上下界内自适应，并输出本次选择的路径、批大小与推断依据；当数据规模跨过配置阈值时须切换到大数组向量化并避免中间列峰值内存超出声明预算，超预算时返回 E_MEMORY_BUDGET 而非静默降低正确性。
5. 实现数值精度契约：浮点结果在 JSON 输出中保留固定小数位并附舍入说明，比较两路径结果时使用带相对容差的比较并记录最大绝对与相对偏差；聚合求和须采用补偿求和以降低累计误差，并对空批次、全空列与除零返回确定业务码或确定结果，不得抛出未分类异常。
6. 实现单写者执行与幂等复用：执行会话按提交串行执行，多个只读查询可并发读取已提交结果；同一请求标识重复提交只执行一次，其余等待并复用同一结果；并发提交不同计划时各自的批次统计与意图日志不得互相污染，查询不得看到结果已写入而批统计仍为旧的中间状态。
7. 使用 SQLite 持久化执行会话、计划摘要、批统计与意图日志，写操作先落意图记录再提交事务；进程在批次执行中途被强制终止后重启须扫描未完成意图，把会话标记为已中止或恢复到最后一个完整批次边界，并输出仅基于已持久化事实的恢复报告，不得承诺强制终止后仍生成完整结果。
8. 提供本地 HTTP API 与可重复实验脚本：API 覆盖会话提交、结果查询、批统计查询、恢复报告查询，统一错误响应为含业务码的 JSON（至少覆盖 E_PLAN_INVALID、E_MEMORY_BUDGET、E_SESSION_NOT_FOUND、E_DUPLICATE_REQUEST）；脚本用固定种子生成小、中、大三档本地样本，分别以两条路径执行并输出一致性比对、路径与批大小选择、运行耗时与恢复演练结果。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
