在 Windows 空白工作区中，需要从零构建一个面向本地多进程场景的分布式租约锁中间件，用于协调对共享资源（以本地 SQLite 中的命名资源行表示）的独占访问。锁以租约（lease）形式授予，持有者需在 TTL 内周期性续约，否则租约过期后锁可被其他候选者获取。锁的元数据（锁键、持有者、租约到期时间、版本号、依赖的父租约链）需持久化到 SQLite，并通过带版本号的快照在内存中维护索引以加速判定。中间件需支持对锁依赖关系的增量更新：当某条租约的持有者、TTL 或依赖的父租约链发生变化时，只提交受影响的增量片段，系统据此增量重建依赖索引并级联失效所有下游租约相关缓存，而不是整份重建。难点在于增量更新与依赖失效之间的强耦合：增量的基础版本必须与当前版本严格匹配、失效传播必须原子完成、并发续约与增量更新必须串行化，且进程被强制终止后必须依据持久化状态恢复到一致视图。过期判定以服务端单调时钟为真值来源，租约到期时间由获取时的现在时刻加 TTL 计算得到，脚本只用可控的本地时钟偏移参数注入漂移，不依赖真实等待。所有输入来自本地确定性样本与本地 HTTP 测试端点，不依赖任何外部服务。

任务环境与准备：
Windows 10 或 11 本地工作区，Python 3.11 及以上并确保 python 与 pip 在 PATH 中。
使用 Python 标准库 http.server 或 flask（通过 pip install flask 安装）提供本地 HTTP 服务，无需 Docker 或外部数据库。
准备固定本地确定性样本 JSON 文件，包含若干锁键、持有者、TTL、父子依赖声明与强/弱依赖模式，样本内容在脚本中预置并随仓库分发。
在本地回环地址启动 HTTP 测试端点模拟持有者心跳，端点行为由脚本控制，不依赖真实网络或第三方账号。
确保工作区可写，SQLite 数据库文件与意图日志存放于工作区子目录，演示脚本可重复执行并清理旧状态。

业务要求：
1. 实现租约锁核心模型：锁键、持有者标识、租约版本号、获取时间、TTL 与到期时间以毫秒精度持久化到 SQLite；获取锁时若锁空闲或已过期则授予并返回新版本号，否则返回业务码 E_LOCK_HELD 并附当前持有者与剩余 TTL；续约必须校验持有者与版本号严格匹配，不匹配返回 E_STALE_LEASE 且不改变锁状态。
2. 实现带版本号的租约依赖快照与增量提交：每条租约可声明依赖的父租约键列表，快照带单调递增版本号；增量提交只包含受影响的租约条目并携带基础版本，若基础版本不是当前版本则返回 E_STALE_BASE 且不改变任何状态；整份快照替换时必须识别版本变化并原子切换，不得把新旧快照条目混合使用。
3. 实现依赖失效与级联重建：为每条租约维护父链索引与下游引用索引；当某租约的持有者、TTL 或依赖列表变化时，该租约全部派生索引及其所有下游租约的派生索引必须级联失效并在同一事务边界内原子重建，禁止出现部分索引已更新而另一部分仍为旧版本的中间可见状态；重建结果需可查询受影响租约清单。
4. 实现获取锁与增量更新的并发一致：锁判定读取快照时不得看到半更新状态；获取、续约与增量更新按提交串行化执行，同一基础版本的两个并发增量只允许一个成功，另一个返回 E_STALE_BASE；查询可并发读取某一完整快照版本。
5. 实现依赖链上的租约过期传导：当父租约因未续约而过期时，依赖它的下游租约须按依赖规则在确定时间内级联失效或降级，具体处置由快照中的依赖模式（强依赖/弱依赖）决定；强依赖下游锁须被释放并返回 E_DEPENDENCY_EXPIRED，弱依赖下游保持有效但在查询中标记依赖已过期；过期扫描与增量更新不得相互产生中间可见状态。
6. 实现统一错误码与 JSON 错误体：至少覆盖 E_LOCK_HELD、E_STALE_LEASE、E_STALE_BASE、E_LEASE_NOT_FOUND、E_DEPENDENCY_EXPIRED、E_DEPENDENCY_CYCLE；当增量提交的依赖关系形成环时返回 E_DEPENDENCY_CYCLE 并拒绝整个增量；错误体包含业务码、消息与当前快照版本。
7. 实现强制终止恢复：增量提交与锁授予先写入意图记录再提交事务；进程在重建过程中被强制终止后，重启必须扫描未完成意图，把快照回滚到最后一个完整版本或将对应增量标记为已中止，并基于持久化事实输出恢复报告；恢复报告不得声称强制终止后仍能生成完整退出报告。
8. 提供本地 HTTP 测试端点与可重复演示脚本：端点支持获取、续约、释放、增量提交、整份快照替换、按租约查询依赖链与恢复报告；脚本使用固定本地样本完成一次全量快照加载、一次只改单条租约 TTL 的增量提交并验证级联失效范围、一次形成依赖环的拒绝提交、一次强依赖父租约过期的级联释放，以及一次强制终止后恢复，输出每次的快照版本、失效租约清单与错误码。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
