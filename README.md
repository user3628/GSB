三维内容管线的方案评审已经结束，首个版本要求在本机空白工作目录里把多视角图像到体素化场景表示的增量重建能力落成可运行服务，此前没有任何代码可复用。输入由程序内置固定种子生成器产出：一组低分辨率灰度 PNG 视角分片与一份 JSON 场景清单，清单逐视角声明旋转矩阵、平移向量、内参、图像尺寸与一组真值采样点坐标，作为校验的唯一真值来源。重建按视角投影采样、视角局部体素贡献体构建、全局体素融合稀疏化、重建校验四阶段推进。运维人员通过本地 HTTP 接口导入分片、调整相机或融合参数、触发重建与查询。核心冲突在于：交互查询必须整体遵守可配置延迟预算，而参数变更需让受影响体素区域按依赖失效增量重建，且增量结果必须与从零全量重建逐字节一致，缓存与中间状态在并发与中断下不能被读到半提状态。

任务环境与准备：
准备 Linux（WSL Ubuntu）工作目录，安装 Go 1.21 或以上版本并确认 go 命令可用。
安装 SQLite 开发库与命令行工具（如 libsqlite3-dev、sqlite3），供 Go 通过驱动访问本地数据库文件。
无需 GPU、外部模型或网络素材；视角分片与场景清单均由程序内置固定种子生成器在本地写出，运行前执行一次生成步骤即可。

业务要求：
1. 实现视角投影采样阶段：按清单声明的旋转矩阵、平移向量与内参把每张分片的采样像素映射到世界射线，沿射线以配置步长读取灰度值，输出带分片标识、世界坐标与灰度值的贡献记录；位姿矩阵非正交、内参焦距为零或射线完全落在图像外时返回带分片标识的 E_INVALID_CAMERA 并保留诊断上下文，同一输入与配置必须产生逐字节一致的贡献记录。
2. 实现视角局部体素贡献体构建与全局融合：把采样点按体素分辨率量化到体素坐标，在截断距离内累计灰度与命中计数并生成视角局部体素块，再按分片序与视角内顺序融合为全局体素场，按融合半径加权平均灰度并按稀疏度阈值剪枝；同一体素被同视角多次命中时合并顺序须显式可复算，剪枝前后占用体素数与被跳过数须记录。
3. 实现交互查询的延迟预算与缓存一致性：单次查询（体素摘要、剔除原因、误差统计或贡献明细）须在可配置延迟预算内返回，超出预算时返回带查询标识与已耗时字段的 E_LATENCY_BUDGET 结构化错误而非阻塞等待或静默截断；缓存键须包含分片内容指纹、相机参数指纹与融合参数版本，命中缓存的结果必须与重新计算的结果逐字节一致。
4. 实现重建校验阶段：把全局体素场中与清单真值采样点最近的体素灰度按双线性或最近邻比对，计算逐点偏差、均方根误差与落在可配置容差内的点数比例，超出容差时返回带分片标识、真值点编号与最大偏差的 E_NUMERIC_MISMATCH；误差统计的分母与参与采样点数须显式记录，不得从缺失信息推断。
5. 实现持久化阶段检查点与优雅停止恢复：每个阶段与每个分片完成时以 SQLite 事务写入含阶段名、分片标识、输入内容指纹、配置版本、产物摘要与单调序号的记录，同一分片同一阶段只允许一条有效记录，写入中断不得留下半提记录；收到停止请求时完成当前不可拆分分片后退出，不承诺强制终止后生成退出报告，恢复后的最终体素场与校验报告须与一次连续执行逐字节一致。
6. 实现版本指纹与增量失效传播：当某分片像素、相机内外参、体素分辨率、截断距离、融合半径或稀疏度阈值任一变化时，通过各阶段内容摘要构成的版本指纹识别受影响的最早阶段与体素区域，仅重建该区域并复用其余上游产物；增量重建结果须与从零全量重建的体素场摘要与稀疏度统计做逐字节比对，不一致返回 E_INCREMENTAL_MISMATCH 并附首个差异体素坐标。
7. 实现并发发布保护与快照整体替换识别：多个工作进程对同一 SQLite 库发布阶段产物时使用事务条件更新与真实文件锁并比较分片内序号，仅允许序号连续推进，落后、重复或跨分片错位发布返回 E_STALE_CHECKPOINT；检测到检查点整体被替换（序号回退、指纹变化或摘要不匹配）时须区分正常推进、整体替换与篡改，仅正常推进被接受。
8. 实现峰值内存约束与本地确定性演示：在可配置峰值内存上限内规划各视角贡献体、全局体素场与缓存的工作集占用，超预算时按视角拆分或按体素块分批执行并记录拆分决策与每步内存估算，或返回带预算明细的 E_MEMORY_BUDGET；命令行与本地 HTTP 接口提供分片导入、参数编辑、分阶段重建、状态与版本查询、请求停止与恢复，演示数据至少 3 个视角与两类融合参数。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
