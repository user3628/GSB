项目从零开始，需要在 Windows 本地构建一个面向本地回环环境的网关后端权重调度与并行探测预算裁决工作台，供上层流量网关集成。后端池由若干实例组成，每个实例声明标识、监听端口、千分比权重、所属可用区与探测参数；与单纯维护健康状态不同，本工作台的核心是「按权重把请求轨迹调度到实例」：给定一段确定性的客户端请求轨迹（毫秒时间戳、客户端标识、请求权重、请求字节数），工作台须在全局并发上游上限、每实例并发上限与每轮时间预算的约束下，把请求调度到当前可用实例并真实发起上游请求，同时并行探测实例可用性以驱动调度决策。实例可用性以 UNKNOWN、HEALTHY、SUSPECT、UNHEALTHY、DRAINING 五种阶段演进，并影响权重归一化与可用区亲和分配。难点在于调度决策、探测结论与权重快照必须整体一致：探测结果与权重调整并发发生，进程可能随时被强制终止，重启后须依据持久化事实恢复调度计划与权重视图。

任务环境与准备：
Windows 10 或更高版本，安装 Go 1.22 或更高版本（安装包从官方渠道获取，安装后 go version 可执行）。
使用纯 Go 实现的 SQLite 驱动与标准库 net/http、net 包，不要求 CGO；依赖通过 go mod tidy 拉取，版本在 go.mod 中固定。
准备本地确定性 JSON 样本：后端实例清单、请求轨迹、探测参数与可用区亲和配置，放在项目 samples 目录。
准备本地回环测试端点：至少一个正常返回约定状态码与响应体标记的 HTTP 端点、一个不响应以触发真实超时的端口、一个未监听以触发连接拒绝的端口。
确认工作区可写，SQLite 数据库文件与意图日志放在项目 data 目录，演示脚本可在无网络外部依赖时重复运行。

业务要求：
1. 实现后端实例与请求轨迹模型：实例包含标识、监听端口、千分比权重（1-1000 整数）、可用区与探测参数（路径、期望状态码、响应体标记）；请求记录包含毫秒时间戳、客户端标识、请求权重与请求字节数。解析本地 JSON 样本时校验端口在 1-65535、权重为正整数、可用区非空、客户端标识唯一，解析失败或实例标识重复返回业务码 E_INSTANCE_INVALID 且整份样本不生效。
2. 实现并行探测与真实超时：探测向本地测试端点发起真实 HTTP 或 TCP 连接，以约定状态码与响应体标记共同判定成功，连接被拒绝返回 E_PROBE_REFUSED，每次探测具备独立超时，超时后必须真实关闭底层连接并返回 E_PROBE_TIMEOUT 且释放其占用的并发名额，不得以等待冒充超时。
3. 定义实例可用性阶段机，至少包含 UNKNOWN、HEALTHY、SUSPECT、UNHEALTHY、DRAINING 五种并规定合法迁移路径，连续成功与失败阈值、探测参数由后端池声明，非法迁移返回 E_INVALID_TRANSITION 且不修改已提交状态；DRAINING 为人工摘除入口，处于 DRAINING 或 UNHEALTHY 的实例不得获得新的调度请求但须将其权重从分配中移除并记录摘除原因。
4. 实现基于确定性哈希的权重调度：对每条请求按客户端标识与请求序号计算确定性哈希并映射到当前可用实例的千分比权重区间，同一请求在相同权重快照与相同可用实例集合下必须调度到同一实例；某可用区声明的亲和比例生效时，须优先在该区内按权重选择，区内无可用实例时按声明规则回退到其他区并记录回退原因。
5. 实现并行调度器，以全局并发上游上限、每实例并发上限与每轮时间预算三重约束推进：预算内按时间戳顺序与可用区轮转取请求并向上游真实发起；超出并发上限者进入有界等待队列，队列满返回 E_DISPATCH_QUEUE_FULL；同一请求在同一轮内不得被重复派发，并发触发同一轮次时仅一个实际执行、其余等待复用结果。
6. 实现权重归一化与可用集合的跨模块一致：每次探测结论或人工摘除导致实例阶段变化时，须在同一事务边界内更新实例阶段、可用实例集合与按可用区归一化后的千分比权重分配，禁止出现实例已 UNHEALTHY 而分配仍计入其权重、或分配已更新而可用集合版本未推进的中间可见状态；查询只能看到某一完整提交版本。
7. 使用 SQLite 持久化实例阶段、可用集合版本、调度计划、探测历史与意图日志，所有写操作先落意图记录再提交事务；进程在探测轮次或调度派发中途被强制终止后重启，必须扫描未完成意图把对应轮次标记为已中止、把未提交派发回滚为待调度，并将权重分配回滚到最后一个完整提交边界，恢复报告只基于已落盘事实给出差异明细。
8. 提供本地 HTTP API 与可重复演示脚本：API 覆盖样本加载、触发探测轮次、触发调度轮次、按实例查询阶段与分配权重、按请求查询调度决策依据、查询恢复报告，统一失败响应为含业务码与上下文的 JSON（至少覆盖 E_INSTANCE_INVALID、E_PROBE_REFUSED、E_PROBE_TIMEOUT、E_DISPATCH_QUEUE_FULL、E_INVALID_TRANSITION）；脚本使用固定本地端点完成一次全量探测、一次超时阻塞、一次可用区回退与一次强制终止后恢复。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本与回环端点验证权重调度、并行探测预算、可用集合一致与强杀恢复，附运行结果。
