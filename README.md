为命名实体识别（NER）团队从零构建一个本地可运行的领域服务，核心问题是实体词典与类型规则增量更新后，已缓存的识别结果如何按依赖关系精确失效，并在中断后保持状态一致。输入是本地样本目录：一份待识别文本清单 JSONL，每条含 doc id、原始 UTF-8 文本；一份实体词典 JSON，含若干实体名、实体类型、别名字列表、优先级与是否区分大小写标记，并带词典版本号；一份类型规则文件，声明合法实体类型集合、类型之间的兼容关系与相邻实体类型转移权重。工作区为空，需从零创建项目：一个可交互的 FastAPI 服务，提供工程创建、按文档执行识别、增量更新词典、查询依赖状态、导出快照与诊断报告的接口。识别采用本地确定性管线：先做基于词典的最大匹配并结合优先级解冲突，再按类型转移权重做序列修正，最后输出每个实体的文本区间、类型、来源标记与置信度。

任务环境与准备：
安装 Python 3.11 与 pip，创建虚拟环境并安装 fastapi、uvicorn、numpy、httpx、pytest，版本以本地锁定文件为准。
在空工作区初始化项目目录，准备本地确定性样本：文本清单 JSONL、实体词典 JSON、类型规则文件，样本中需含重叠实体、别名、大小写与未声明类型情形。
准备确认进程退出与强制终止可用的本地运行方式与脚本，确认 SQLite 文件与结果分片目录可写。
启动 FastAPI 服务使用本地回环端口，演示请求用 curl 复现，不依赖任何真实账号或线上站点。

业务要求：
1. 工程创建接口接收文本清单、实体词典、类型规则文件与匹配参数，校验 doc id 唯一、实体名非空、别名不得与实体名相同、类型规则声明合法类型集合、匹配窗口为正整数；任一非法返回 E_PARAM 业务码并定位出错文件与行号，且不得写入任何工程状态或创建临时结果文件。
2. 识别管线须保证输出按起始字符下标升序排列，区间以 Unicode 字符计数而非字节；同一文本区间被多个实体名或别名命中时，先按匹配长度降序、再按词典优先级降序、同分按实体名字典序稳定选择；重叠区间须被消解为互不重叠实体序列，被消解的候选须计入统计并可按 doc id 查询。
3. 类型修正须基于类型转移权重做序列解码，输出每个实体一个类型；实体名命中但类型不在规则文件声明集合中、或相邻两个实体类型的兼容关系被声明为不允许时，须按转移权重选择合规替代类型并记录被修正的实体区间与原因，禁止整篇文本失败。
4. 每个实体须附带置信度，定义为该实体在所有命中的实体名候选与类型候选上的归一化后验，用 log-sum-exp 在 float64 下计算；置信度须在文档范围内构成有效概率分布，归一化误差超过配置容差时返回 E_PRECISION 并指出 doc id 与实测误差，不得静默截断。
5. 词典须支持增量更新：新增实体、修改别名列表、调整优先级与修改是否区分大小写四种操作，每次更新推进词典版本号；服务须按实体类型与实体名到文档的依赖关系计算受影响文档集合，只重算真正引用的实体名或类型发生变化的文档，未受影响文档须复用已持久化识别结果。
6. 失效判定须精确到依赖粒度：若某文档未命中任何被更新实体名，且其已产出实体的类型未被规则文件变更影响，则该文档不得重算；诊断报告须区分“依赖失效被评估但结果未变”与“实际重算”两类文档，给出各自计数与 doc id 范围，并说明判定所依据的实体名与类型集合。
7. 识别进度与结果须在 SQLite 中以文档粒度事务提交，识别结果以原子替换写入不可分割的分片文件并登记内容哈希；进程被强制终止后重启须核对分片哈希与数据库提交标记，重算未提交文档且不重复消费已提交文档，恢复后的逐文档实体集合与快照版本序列须与无中断执行完全一致。
8. 每次词典更新或完整识别须生成整体替换的版本化快照，含词典版本号、各文档实体摘要与分片哈希；查询快照时若检测到数据库记录与磁盘分片哈希不一致、词典版本变化或残留旧分片，须返回 E_STALE 并定位到文档与分片；另须提供确定性演示入口，输出逐文档实体数、被消解候选数、被修正类型数、实际重算文档数与快照版本序列的可重复结果。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
