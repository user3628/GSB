工作目录中尚无任何代码，只有一份待实现的需求说明，需要先落地一个本地可运行的中文客服工单意图分类与优先级判定引擎，交付数据处理管线与结果验证工具。输入为内置固定种子生成器在本地确定性产出的 JSONL 工单分片，每条含 ticket_id、文本、渠道、语言标签、意图标签（多类单标签）、优先级标签（0-3）与标注一致度百分比；覆盖中英混排、同渠道重复文本、空文本、优先级越界与标注一致度缺失等情形。另附一份带单调版本号的策略快照，声明意图词表权重、优先级阈值、分类平滑强度、哈希维度、分片采样比例与异常注入开关。管线按规范化与词项抽取、朴素贝叶斯意图打分、优先级阈值判定、结果验证四阶段推进，需要把每阶段输入输出摘要与统计写入 SQLite，供验证工具按版本回放核对。核心矛盾是：异常注入与增量重训都要求阶段可复现，但采样与归并顺序一旦随并发或版本变化而漂移，历史版本的重放结果就对不上，因此必须在任何执行路径下保持确定性。

任务环境与准备：
安装 Go 1.22 或以上，确认 go version 在 Windows 命令行可用。
安装 SQLite 驱动依赖（如 modernc.org/sqlite），通过 go mod tidy 拉取，执行不依赖 CGO。
在工作区创建 data 与 out 目录；工单样本与策略快照由程序内置固定种子生成器产出，无需下载外部数据。
本地 HTTP 服务绑定 127.0.0.1 的回环端口，仅用于本地演示与验证工具，不访问线上站点。

业务要求：
1. 实现规范化与词项抽取阶段：对工单文本做 Unicode NFKC、空白折叠、全半角统一与小写化，按中文单字与相邻二字组合切分、拉丁字母数字按连续串切分，输出带字符偏移与渠道标记的词项序列；空文本或仅含标点须返回带 ticket_id 的 E_EMPTY_TEXT，同一输入与配置必须产生逐字节一致的词项摘要。
2. 实现意图分类打分解码：从本地已标注工单统计各类别先验与词项条件计数，采用可配置平滑强度并全程在对数域累加后验分数，未见词项回退到显式未知标记；同一输入与配置必须产生逐字节一致的类别分数，出现 NaN 或对数域下溢为零时须返回带 ticket_id 与词项的 E_NUMERIC 并保留诊断上下文。
3. 实现优先级阈值判定与标签越界裁决：依据可配置阈值把意图分数与标注一致度合成为优先级判定，并将判定结果与标注优先级比对输出命中、漏判、误判三类明细；标注优先级越界或标注一致度缺失时须按显式降级规则处理并标注降级依据，不得静默丢弃样本。
4. 实现四阶段检查点与增量重训：每题按规范化、意图打分、优先级判定、验证四阶段完成时以事务写入含阶段名、输入内容指纹、配置版本、产物摘要与单调序号的记录；当词表权重或阈值变化时通过版本指纹识别受影响的最早阶段并仅重建该阶段及其下游，未受影响上游产物继续复用，增量结果须与从零全量运行逐字节一致。
5. 实现异常注入与业务错误码一致性：提供参数注入入口，支持注入空文本、优先级越界、标注一致度缺失、平滑强度为零、哈希维度为零与分片声明行数与实际不符等情况；各异常须在对应阶段返回稳定业务码（E_EMPTY_TEXT、E_LABEL_RANGE、E_CONFIG、E_NUMERIC 等）并附 ticket_id 与阶段名，不得以通用错误替代。
6. 实现 SQLite 事务化状态与强制终止恢复边界：同一阶段同一工单只允许一条有效记录；进程被强制终止后重启仅凭已提交事实重建进度，不承诺生成退出报告；恢复后的意图分数、优先级判定与验证报告须与一次连续执行逐字节一致，且检查点序号连续推进、无跳跃与重复。
7. 实现并发发布互斥与整体替换识别：多工作进程发布阶段产物时使用 SQLite 条件更新与真实文件锁并比较阶段内序号，仅允许序号连续推进，落后、重复或跨阶段错位发布返回 E_STALE_CHECKPOINT；当检测到记录被整体替换（序号回退、指纹变化或摘要不匹配）时须区分正常推进、整体替换与回退，仅正常推进被接受。
8. 提供本地 HTTP 与命令行验证工具及确定性演示：支持导入工单分片与策略快照、触发分阶段执行、查询各阶段状态与版本指纹、执行单分片替换与单配置变更、请求优雅停止与恢复、导出验证报告；演示数据至少 3 个分片，覆盖中英混排、空文本、优先级越界与至少一次强制终止后恢复，一次完整运行产生固定摘要。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证意图分类、优先级判定、增量重训一致性与异常错误码，并演示强制终止后恢复。
