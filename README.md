当前为空白工作区，需要从零实现一个面向本地单机数据库内核场景的「日志结构存储与崩溃恢复引擎」。引擎以仅追加日志（WAL 风格）记录键值写入与索引变更，内存维护有序索引与过期映射，定期把日志内容刷写为不可变段文件并截断旧日志。真实数据库的崩溃恢复不是简单的重放全量日志：重启时必须依据检查点、日志序号与页校验判断哪些操作已落到段文件、哪些尚未持久化，对未完成的多行事务做整体回滚，对部分写入的日志尾部做截断修复，并在日志被截断后基于段文件增量重建内存索引与过期映射，使恢复后的读结果与崩溃前最后一次已提交状态一致。引擎还需提供外部可触发的崩溃模拟（在指定日志位置真实终止当前进程），用于验证恢复路径而不是用延迟替代真实失败。

任务环境与准备：
安装 Python 3.11 及以上版本并在命令行确认 python --version 可用。
使用 pip 安装 pytest 与 NumPy，确认可在离线环境导入。
在工作区创建项目目录与日志、段文件、样本数据目录，全部路径使用本地相对路径。
准备固定随机种子的多事务样本生成脚本与子进程崩溃驱动脚本入口，不依赖网络、账号或外部服务。

业务要求：
1. 实现仅追加日志的二进制格式与追加写入：每条日志记录含严格递增日志序号、事务标识、操作类型（Put、Del、Expire、Commit、Rollback）、键、值与过期逻辑刻度，记录头含长度与 CRC32；追加写入须以一次写系统调用落地并支持 fsync，尾部半条记录的 CRC 或长度不符须能识别，不得把残缺记录当作有效操作。
2. 实现检查点与段文件刷写：在配置阈值或外部触发时，把内存索引中的有效键值按确定次序写成自描述段文件（魔数、格式版本、键区间、条目数、CRC32、最小与最大日志序号），段文件写临时文件校验后原子替换，并在替换完成后写入检查点记录，记录已落盘的最大日志序号与段清单，后续恢复以检查点为起点判断日志余量。
3. 实现崩溃模拟与恢复判定：提供在指定日志位置或指定日志序号后真实终止当前进程的注入方式（通过子进程运行并可观察非零退出），恢复时区分三种情形并各自给出判定依据：最后一条记录完整且已提交、最后一条记录残缺需截断、已提交事务的 Commit 记录存在但段文件刷写未完成，三种情形下的恢复结果必须与持久化状态推导出的预期一致。
4. 实现多行事务的原子恢复与部分回滚：同一事务的 Put、Del、Expire 操作必须整体生效或整体丢弃；恢复时遇到无 Commit 也无 Rollback 的事务须将其全部操作视为未提交并回滚，遇到 Commit 记录后才在内存索引生效；已截断日志中 Commit 落在残缺区域的整个事务不得生效，且回滚不得改变同日志内其他已提交事务的结果。
5. 实现段文件与日志的增量索引重建：恢复时须先载入检查点引用的段文件重建索引基础状态，再只重放检查点之后且校验通过的日志记录，不得重复应用已在段文件中的操作；段文件段头声明的最大日志序号必须参与去重判定，段清单与日志序号区间存在空洞或重叠时须返回业务码 E_SEGMENT_LOG_MISMATCH，不得静默继续。
6. 实现过期映射在恢复后的逻辑刻度一致性：过期映射按过期逻辑刻度排序索引，日志中的过期刻度与内存逻辑时钟必须落在同一刻度体系；恢复后逻辑时钟须取所有已持久化记录与段文件中过期刻度的最大值再前进，使重启前后的过期判定结果一致；已过期但未回收的键在读路径返回 E_KEY_EXPIRED 并从索引中惰性移除。
7. 实现恢复期间的并发读与恢复完成可见性：恢复未完成前对外接口须返回 E_RECOVERING 而非读到半重建索引，恢复完成后才允许读写；恢复过程中到达的写请求须排队等待而不丢失，恢复结束后的服务状态必须与崩溃前最后一次已提交状态一致，并且恢复耗时与重建条数须写入恢复报告，报告含截断日志字节数与回滚事务列表。
8. 提供本地接口、崩溃恢复演示与可重复测试：通过命令行 JSON 请求文件与标准输出提供写、读、触发检查点、触发崩溃注入、查询恢复报告的入口，所有错误以固定业务码在 JSON 中返回；提供固定随机种子生成的多事务样本与演示脚本，展示完整记录崩溃、残缺尾部崩溃、段刷写未完成崩溃三种场景的恢复前后比对，pytest 用例须在 Windows 离线运行且以子进程真实终止驱动崩溃场景。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
在本地以子进程真实终止制造三类崩溃，验证恢复后读结果与已提交状态一致且残缺日志被正确截断。
