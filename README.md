这项需求交由一名开发者在空目录内完成首版，工作区尚无任何代码或样本，需要为本地流式日志分析场景交付一套分区聚合状态搬迁与跨版本格式裁决组件，供上层查询服务集成。程序内置固定种子生成器在本地确定性产出：日志事件分片（毫秒时间戳、分区键、分组键、int64 定点度量值 scale=1e6、空值标记、事件序号）与带单调版本号的聚合规格快照（分区数、分组键、乱序容忍窗口毫秒、每轮时间预算、全局并发上限）。聚合状态既要能与外部工具互换数据，又要在工具链升级后继续读取历史快照，因此必须同时支持紧凑二进制与分片 JSON 行两种持久化格式，两代格式在字段存在性与时间戳精度上存在差异，且状态搬迁需要识别版本变化并整体替换。真实环境中同一分区的日志会乱序到达，进程可能在聚合提交或状态搬迁中途被强制终止，重启后必须依据 SQLite 中已落盘的事实恢复。

任务环境与准备：
在 Linux（WSL Ubuntu）空目录中初始化 Go 模块；安装 Go 1.22 及以上版本与 SQLite 开发头文件（Ubuntu 包 libsqlite3-dev），并使用成熟的 Go SQLite 驱动作为依赖。
确认本地无网络依赖：样本由程序内置固定种子生成器在运行时生成，不依赖外部数据源或在线服务。
准备运行任务所需的基础命令与工具链（go env、go build、sqlite3 客户端可选），任务开始前无需预置任何项目文件。

业务要求：
1. 实现日志事件与聚合规格快照的解析和归一化：事件声明毫秒时间戳、分区键、分组键、int64 定点度量值（scale=1e6）、空值标记与事件序号，规格声明分区数、分组键、乱序容忍窗口毫秒、每轮时间预算与全局并发上限；解析时校验分区键落在分区数范围内、事件序号非负、度量值不越界，非法记录返回业务码 E_EVENT_INVALID 且整批不入库。
2. 实现聚合状态的两种持久化格式编解码：紧凑二进制格式必须含魔数、格式版本字节、大小端标记、每条窗口记录长度前缀、CRC32 校验与可选字段存在位图，纳秒偏移承载时间戳；分片 JSON 行格式每行含分区、分组键、窗口起止毫秒、计数、和、最小值、最大值与毫秒时间戳。两种格式对同一逻辑状态的往返编解码后聚合结论必须逐位一致。
3. 实现格式协商与版本兼容裁决：导入前检测输入格式与格式版本，可从配置文件读取并覆盖兼容矩阵，给出接受、降级接受或拒绝三种结论；旧版本缺空值标记或时间戳精度较低时降级接受，按声明规则补齐并记录降级明细；高版本含未知必填字段或 CRC32 不符时拒绝并返回 E_FORMAT_INCOMPATIBLE 且不改变已提交状态。
4. 实现乱序容忍与窗口聚合核心：按分区维护乱序容忍窗口，窗口内到达的记录按事件序号归位，超出容忍深度仍未到达的序号判定缺口并固定窗口；迟到记录落在已固定窗口内时按声明策略回填该窗口或落入迟到队列。窗口内按分组键计算计数、求和、最小值与最大值，求和使用带显式舍入方式的补偿求和并输出每批可量化误差上界。
5. 实现聚合状态的版本化搬迁与整体替换：搬迁请求携带源格式、目标格式、快照版本号与生成时间，引擎须先校验版本单调与摘要，再在内存状态与 SQLite 表之间原子切换，切换成功后才释放旧状态资源；搬迁失败返回 E_STATE_SWAP_FAILED 并保持旧状态完全可用，禁止新旧状态混合读取。
6. 实现全局并发上限与每轮时间预算下的聚合批次调度：批次受分区并发上限与每轮时间预算共同约束，预算内按分区号与窗口起始毫秒取任务，超并发上限进入有界等待队列，队列满返回 E_BATCH_QUEUE_FULL；预算耗尽时按稳定次序给出确定性降载次序并输出降载依据与剩余预算，被降载批次不得推进窗口状态。
7. 实现单写者提交与多读者查询的并发一致及幂等：批次聚合提交、状态搬迁与降载裁决按规格版本单写者串行执行，多个只读查询可并发读取某一完整提交版本；同一批次标识重复提交只执行一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_BATCH；查询不得看到窗口已标记完成而误差记录尚未落定。
8. 实现基于 SQLite 的意图持久化与强制终止后恢复：批次聚合开始、窗口提交与状态搬迁前先写意图记录再提交事务；进程在聚合或搬迁中途被强制终止后重启须扫描未完成意图，把未提交窗口回滚为待重算、未提交搬迁标记为已中止或按已落盘事实恢复，恢复报告只包含持久化事实，并提供本地 HTTP 接口覆盖快照提交、两种格式导入、批次聚合触发、按版本查询窗口结论与恢复报告查询，失败响应为含业务码的 JSON。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
