计算引擎层需要新增一个执行服务，当前目录尚不具备任何代码基础，首个版本要在本地完成分组聚合在内存受限条件下的分段解码与部分和续算能力。输入由程序内置固定种子生成器确定性产出：若干 JSON 分片，每片描述一个按分区键哈希预分区的逻辑数据块，逐块声明块内行数、列式编码方式、解压后字节大小与内容摘要；同时给出字节预算清单，逐块声明单块内存上限与全局并发解码上限。离线流量样本以毫秒时间戳、分组键与定点度量值组织，查询描述需要同时给出分组键、度量列与结果精度约定。与单纯在内存中整体载入后再聚合的做法不同，这里首先要回答的是在单块上限被突破时如何把一次解码切成可连续推进的段，并在段与段之间只保留必要状态。

任务环境与准备：
安装 Go 1.22 或更高版本，确认 go version 可用
安装 sqlite3 命令行工具用于查看意图记录与部分和
确认可打开本地回环端口用于 HTTP 接口与演示脚本
任务开始前工作区为空，样本由程序内置固定种子生成器在本地确定性产出，无需外部数据集或网络访问

业务要求：
1. 实现分片与数据块的加载与版本识别：每个分片携带单调递增版本号、生成时间、列定义与逐块摘要，加载时校验版本单调与摘要，任一失败返回 E_SHARD_INVALID 且必须保持已提交分片完全可用；提交新分片时整体切换并识别版本变化，切换成功后旧分片资源才可释放，禁止新旧分片的块索引混用。
2. 实现三种编码的确定性解码：定长、游程与字典编码各提供可独立调用的解码实现，解码前校验块头声明的行数、编码类型与摘要，损坏块返回 E_BLOCK_CORRUPT 并指明块号与块内偏移；解码须支持从指定行偏移开始只产出下一段行，且段与段拼接后与一次性解码逐行一致，禁止以先整体解码再切片的方式实现分段。
3. 实现单块内存上限下的分段裁决：依据块声明的解压后字节大小与单块内存上限决定整体解码或分段解码，分段大小须输出计算依据与预计峰值内存；当声明字节数不足以容纳最小行宽时的边界情形返回 E_BLOCK_UNSPLITTABLE 并给出该块不可分段的原因，不得静默放弃该块。
4. 实现跨段部分和与续算状态：每段解码后按分组键累计计数、求和、最小值与最大值，部分和须带可比对的段基版本与已处理行区间；续算时从已提交部分和继续并复用未变化的段结果，禁止从头重扫整块；同一分片同一块在相同分段参数下重复累计必须逐位一致，分位使用确定性最近秩法并注明样本规模。
5. 实现按字节预算的调度与延后裁决：解码与聚合任务在全局并发解码上限、单块内存上限与每轮处理字节预算共同约束下执行，超出并发上限的任务进入有界等待队列，队列满返回 E_DECODE_QUEUE_FULL；预算耗尽时按块号与已消耗字节给出确定性延后次序与剩余预算，延后块须保持可续算且其部分和不得提前出现在查询结果中。
6. 实现基于 SQLite 的意图持久化与强制终止后恢复：段解码开始、部分和提交与分片切换前先写意图记录再提交事务；进程在分段解码或部分和提交中途被强制终止后重启须扫描未完成意图，把未提交块恢复为待解码或标记为已中止，恢复报告只包含已落盘事实，不得把线程中断或超时当作已终止。
7. 实现单写者推进与多读者查询的并发一致及幂等：聚合会话推进、部分和提交与分片切换按会话单写者串行执行，多个只读查询可并发读取某一完整提交版本，不得出现某块已标记完成而部分和未落定、或分片已切换而块索引仍指向旧摘要的中间状态；同一请求标识重复提交只执行一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_REQUEST。
8. 提供本地 HTTP 接口与可重复演示脚本：接口覆盖分片加载、聚合会话提交、触发解码轮次、按会话查询块状态与部分和、查询分段依据与延后明细、恢复报告查询，失败响应统一为含业务码与上下文的 JSON，至少覆盖 E_SHARD_INVALID、E_BLOCK_CORRUPT、E_BLOCK_UNSPLITTABLE、E_DECODE_QUEUE_FULL、E_CONFLICTING_REQUEST；脚本用固定样本完成一次分段解码、一次续算与一次强制终止后恢复。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证分段解码与整体解码逐行一致、续算结果及强制终止后的恢复结论。
