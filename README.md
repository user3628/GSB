某推理平台准备在 Linux 开发机上落地一个单机 GPU 显存配额调度与批推理裁决组件，工作区此刻还是空的，需要交付可集成的 Go 领域数据编辑与操作应用。程序内置固定种子生成器在本地确定性产出逻辑 GPU 节点（显存字节、算力份额千分比整数、配额组、健康状态）、推理请求（模型标识、显存需求、每批样本数、期望批延迟上限毫秒、优先级、配额组）以及带单调版本号的调度策略快照和只含受影响字段的增量片段。运维通过本地 HTTP 接口编辑节点与请求、触发调度轮次、查询配额占用与批组织结论。核心冲突在于交互延迟与计算结果一致性：运维会在预算内反复查询配额与批视图，而调度又必须让节点占用、配额组预留、批组成与请求状态在同一提交边界内共同生效。

任务环境与准备：
安装 Go 1.22 及以上版本并确认 go version 可用；安装 sqlite3 命令行工具用于核对数据。
工作区为空目录，先执行 go mod init 初始化模块，SQLite 驱动与依赖通过本地模块缓存或离线可用的模块代理获取，不依赖任何网络服务。
在项目中实现固定种子样本生成器，生成节点、请求、策略快照与增量片段样本并写入本地文件，供重复运行使用。
准备本地 HTTP 客户端脚本用于调用接口与触发强制终止后再启动的恢复验证，全部操作在 Linux（WSL Ubuntu）本地执行。

业务要求：
1. 实现节点、配额组、推理请求与策略快照的解析与归一化：量纲字符串如 40Gi、512Mi、250m 须解析为显存字节整数与算力千分比整数，并做溢出与负数检查；快照携带单调递增版本号、整体校验摘要与调度参数，重复请求标识、未知配额组或非法量纲返回 E_SPEC_INVALID 并整批不入库。
2. 实现配额组准入判定：组内成员节点已占用显存与算力份额，加上本组已准入请求的预留量，共同计入组占用；准入时须在同一事务内递增组预留，超额返回 E_QUOTA_EXCEEDED 并附当前占用、请求需求与差额，禁止仅改请求状态而组预留未变。
3. 定义请求状态机，至少包含 PENDING、ADMITTED、BATCHED、RUNNING、COMPLETED、REJECTED、PREEMPTED 七种并规定合法迁移路径；非法迁移返回 E_INVALID_TRANSITION 且不修改已持久化状态，同一请求在同一版本下重复迁移只生效一次。
4. 实现推理批组织：把同模型、同节点且按提交顺序相邻的请求装入批，批的合计显存不得超过节点剩余显存与模型单批样本数上限，批估计延迟超过期望上限时拆分重排；批组成须输出每批成员、样本数、合计显存与估计延迟，拒绝混入不同优先级请求并在拆分时保留原提交次序。
5. 实现并行调度器，以全局并发批上限与每轮时间预算双重约束推进：预算内按优先级、配额组轮转与批估计延迟取批，超出并发上限的批进入有界等待队列，队列满返回 E_EXEC_QUEUE_FULL；预算耗尽时按稳定次序给出确定性降级清单，被降级批内请求保持已准入状态而非静默丢弃。
6. 实现抢占与配额回收的真实释放：高优先级请求在组预留不足时可抢占低优先级请求，被抢占请求迁移为 PREEMPTED 且其预留显存与算力份额须在同一事务内真实归还；仅改状态而配额不变返回 E_QUOTA_LEAK 并回滚，回收后的组占用须可被下一次准入立即使用。
7. 实现单写者裁决与多读者查询的并发一致及幂等：准入、批组织、抢占与状态迁移按提交串行执行，多个只读查询可并发读取某一完整提交版本，不得出现请求已 ADMITTED 而组预留未计入、或批已 BATCHED 而节点余量未扣减的中间可见状态；同一请求标识重复裁决只执行一次、其余等待复用结果，内容不一致返回 E_CONFLICTING_REQUEST。
8. 使用 SQLite 持久化节点占用、配额预留、请求状态、批记录与意图日志，所有写操作先写意图记录再提交事务；进程在批调度或抢占中途被强制终止后重启须扫描未完成意图，把批与请求回滚到最后一个完整版本或标记为已中止，恢复报告只包含已落盘事实。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
