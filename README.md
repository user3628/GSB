在 Windows 空白工作区中，需要从零构建一个面向领域数据编辑与操作应用的 MVCC 可见性裁决引擎。应用维护若干业务表，每行保留创建事务号、删除事务号、行版本号与提交序号；用户通过本地 HTTP 接口开启带隔离级别（READ_COMMITTED、REPEATABLE_READ、SNAPSHOT）的事务，事务内可读取、编辑与删除行并设置保存点。并发编辑依赖两类界面操作：点开某行编辑面板时须返回该行的当前可编辑版本与锁状态，保存时须校验编辑面板打开时所见版本仍可见，否则按业务码拒绝。核心问题是交互延迟与计算结果一致性：低延迟的页面读取必须与写事务的可见性快照严格对应，长事务与短事务混跑时，若页面读取直接读当前已提交状态或缓存可见性结果，就可能出现编辑器显示旧值而保存写入新值。

任务环境与准备：
在 Windows 空白工作区创建项目目录与 Python 虚拟环境，使用标准库与 SQLite3，不安装额外数据库服务。
准备固定本地样本：若干业务表行数据、两个并发编辑脚本与一个用于等待超时与死锁场景的参数文件。
确认本地 HTTP 服务可绑定回环端口，SQLite 数据库与意图日志文件放在工作区目录内。
准备强制终止演示脚本，通过外部终止本地服务进程来触发恢复流程，不修改源码制造失败。

业务要求：
1. 实现行版本存储与 MVCC 可见性判定：每行保留行标识、创建事务号、删除事务号、行版本号与提交序号，已提交事务表记录提交序号；READ_COMMITTED 事务每次语句读取最新已提交且未删除版本，REPEATABLE_READ 与 SNAPSHOT 事务在事务内首次读取时固定可见快照，后续读取不得看到更高提交序号的版本；同一行被并发更新产生多版本时按创建与删除事务号正确判定可见版本。
2. 实现编辑会话与版本校验语义：打开编辑会话返回行数据、行版本号与当前可见快照标识；保存请求必须携带打开时取得的行版本号，若该版本已不可见（被其他事务提交覆盖或删除）返回业务码 E_EDIT_STALE 并附最新可编辑版本，不得静默覆盖；由打开到保存之间的间隔计入交互延迟预算，超出预算的保存即使版本未变也须返回 E_EDIT_EXPIRED 并说明判定依据。
3. 实现保存点与语句回滚的跨模块一致：事务内设置保存点后，回滚到保存点须同时撤销该点后的行版本写入与编辑会话状态，且保存点之前已持有的可见性快照与行锁保持不变；禁止出现行版本已回滚而编辑会话仍指向旧版本、或可见性快照已丢弃而事务仍在读取的中间可见状态。
4. 实现行级写冲突判定与真实可中断等待：保存某行前须取得该行排他写权，当另一事务已持有冲突写权时按隔离级别决定立即返回 E_WRITE_CONFLICT 或进入有界等待队列；等待须使用可被真实唤醒的中断等待原语，在写权释放、等待超时或事务取消时被唤醒并释放资源，不得以固定延迟轮询冒充超时；等待超时返回 E_LOCK_TIMEOUT 并记录等待对象与已等时长。
5. 实现资源预算调度：全局并发事务上限、有界等待队列容量与单次等待时限共同约束事务推进，超出并发上限的开启请求返回 E_TXN_LIMIT，队列满返回 E_LOCK_QUEUE_FULL；当等待图出现环时按确定性规则选取牺牲事务返回 E_DEADLOCK_VICTIM 并回滚其未提交版本与编辑会话，其余等待者须被真实唤醒而非继续挂起。
6. 实现意图持久化与强制终止后的恢复：事务开启、行版本写入、编辑会话打开与提交均先写入 SQLite 意图记录再提交数据事务；进程在被强制终止后重启须扫描未完成意图，回滚未提交行版本、释放其全部写权与编辑会话，并仅基于已持久化事实输出恢复报告，恢复报告不得声称强制终止后仍生成完整退出报告；已提交事务的数据与可见性必须完全保留。
7. 实现单写者提交与多读者可见性的并发一致：事务提交、写权授予与保存点回滚按单写者串行执行，多个页面读取与行查询可并发；查询只能看到某一完整提交版本，不得出现行版本已提交而其删除事务号尚未写入的中间状态；同一事务标识重复提交只生效一次，其余请求复用同一结果，内容不一致时返回 E_CONFLICTING_TXN。
8. 提供统一错误码与可重复演示脚本：所有失败响应为含业务码与上下文的 JSON，至少覆盖 E_INVALID_ISOLATION、E_EDIT_STALE、E_EDIT_EXPIRED、E_WRITE_CONFLICT、E_LOCK_TIMEOUT、E_LOCK_QUEUE_FULL、E_TXN_LIMIT、E_DEADLOCK_VICTIM、E_CONFLICTING_TXN；脚本使用固定本地样本完成两事务并发编辑同一行、打开后回滚保存点、等待超时、死锁牺牲与强制终止后恢复，输出各阶段可见版本、错误码与恢复报告摘要。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
