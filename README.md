新业务线的分布式锁服务准备替换旧协调组件，接手人只有一个未初始化的空工作区和一份需求说明，需要先把「带租约的锁授予与策略增量下行」这条链路做成可集成的 Go 组件，而不是重写整个协调系统。组件维护一组锁键与持有者：持有者通过本地 HTTP 端点发起获取、续约与释放，租约以毫秒精度记录锁键、持有者、授予时刻、到期时刻、续约次数与持有者申报的千分比权重；策略以带单调版本号的 JSON 快照整体提交，运维也可提交只含受影响锁键的增量片段，声明 TTL 上限、安全续约点比例、权重容差、每轮时间预算与全局并发续约上限。真实运行中同一锁键的续约请求会错序与重复，策略片段会与续约竞争，进程可能在授予或片段重建中途被强制终止。锁的公平性度量、续约余量比例与集群锁占用率等派生指标会因策略片段而失效，必须在可界定的误差内重建，并与 SQLite 中已提交事实保持一致。

任务环境与准备：
在 Linux（WSL Ubuntu）上准备一个空工作目录并初始化 Go 模块，使用发行版自带或官方安装的 Go 1.21 及以上版本（如 go version 确认），无需容器。
确保可读写本地 SQLite 数据库文件，选用成熟的 Go SQLite 驱动（如 modernc.org/sqlite 或 mattn/go-sqlite3），依赖通过 go mod tidy 拉取，不依赖外部网络服务或真实账号。
在本地起一个回环 HTTP 协同测试端点，可返回成功、连接拒绝与挂起不响应三种行为，用于触发真实超时并验证连接被关闭；端口与地址写入运行配置。
实现内置固定种子生成器，在本地确定性产出锁键、持有者、权重、续约上报序列（含错序与重复）与策略快照、增量片段样本，样本随仓库生成，不提交外部数据。
准备默认运行参数：总锁键数量、全局并发续约上限、每轮时间预算毫秒、若干锁键的 TTL 与安全续约点比例，作为演示与复现实验的显式观测。
提供本地 HTTP 服务与可重复演示脚本的启动说明，确保获取、续约、释放、快照与片段提交、指标查询与恢复报告查询可在同一进程内依次复现。

业务要求：
1. 实现锁键、持有者与租约模型：记录锁键、持有者标识、租约版本号、授予时刻、到期时刻毫秒、续约次数与千分比整数权重；获取时若锁空闲或已过期则授予并返回新版本号，未过期由他人持有时返回 E_LEASE_HELD 并附当前持有者与剩余寿命；同一锁键同一持有者的续约携带当前租约版本号，版本落后返回 E_LEASE_STALE 并附当前版本，续约次数超过策略上限返回 E_RENEW_EXHAUSTED。
2. 实现策略快照整体替换与增量片段提交：快照携带单调递增版本号、生成时间、各锁键 TTL 上限、安全续约点比例、权重容差与整体校验摘要，提交时版本号不大于当前已提交版本返回 E_STALE_SNAPSHOT；增量片段只含受影响锁键的字段并携带基础版本号，基础版本不是当前版本返回 E_STALE_BASE 且不改变任何已提交状态；整份快照与增量片段必须识别版本变化并原子切换，校验失败保持旧策略完全可用。
3. 实现续约时序裁决：依据授予时刻、复用同一租约的历次续约时刻与安全续约点比例，判断每次续约早于还是晚于安全续约点，并输出续约余量比例、已流逝毫秒与判定依据；续约余量比例与权重一律使用整数或显式定点表示，输出每步舍入方式与累计舍入误差；到期时刻须由授予时刻加 TTL 毫秒与续约累加得出，禁止浮点秒与毫秒整数混用导致漂移。
4. 实现派生指标的增量重建与级联失效：为每个锁键维护其续约余量比例、权重占比与集群锁占用率对策略版本与租约记录的引用关系；某锁键的 TTL、安全续约点或权重因增量片段变化时，该锁键全部派生指标及依赖它的跨租约公平度必须级联失效并在同一事务边界内原子重建，禁止出现策略已更新而余量比例仍按旧上限计算；比较占比与权重偏差时使用带相对容差的定点比较，容差内按持有者标识稳定字典序打破平局。
5. 实现全局并发续约上限与每轮时间预算下的续约调度：续约与到期回收任务在全局并发上限与每轮时间预算共同约束下执行，预算内按到期时刻升序与锁键稳定次序取任务，超出并发上限的进入有界等待队列，队列满返回 E_RENEW_QUEUE_FULL；预算耗尽时按到期时刻与锁键给出确定性延后次序，被延后记录迁移为 DEFERRED 并附延后依据，不得静默丢弃仍在有效期内的续约。
6. 实现真实可中断的续约协同与并发一致：向本地回环协同端点下发续约确认时具备独立超时，超时后必须真实关闭底层 HTTP 连接并释放其占用的并发名额，返回 E_COORD_TIMEOUT 并附锁键与持有者；授予、续约、释放与片段重建按锁键单写者串行执行，多个只读查询可并发读取某一完整提交版本，不得看到租约已续期而余量比例仍为旧值，也不得看到片段的增量已生效而公平度仍按旧权重计算；同一请求标识重复提交只执行一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_REQUEST。
7. 实现基于 SQLite 的意图持久化与强制终止后恢复：授予、续约、释放、片段提交与级联重建前先写意图记录再提交事务；进程在授予或片段重建中途被强制终止后重启须扫描未完成意图，把未提交授予回滚为可获取、未提交续约回滚为原到期时刻、未提交片段回滚到最后一个完整策略版本，恢复报告只依据已落盘事实并列出每条差异；恢复完成后才开始接受新的续约与片段提交。
8. 实现统一业务错误码 JSON 错误体并支持本地端到端验证：所有失败响应为含业务码与上下文的 JSON，至少覆盖 E_LEASE_HELD、E_LEASE_STALE、E_RENEW_EXHAUSTED、E_STALE_SNAPSHOT、E_STALE_BASE、E_CONFLICTING_REQUEST、E_RENEW_QUEUE_FULL、E_COORD_TIMEOUT；本地 HTTP 接口覆盖获取、续约、释放、快照与片段提交、按锁键查询租约与派生指标、查询恢复报告，并附可重复脚本完成一次错序续约裁决、一次片段引发的级联重建与一次强制终止后恢复的演示。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地样本验证租约裁决、片段级联重建与强制终止后恢复，比较派生指标与误差上界。
