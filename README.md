当前是空白工作区，需要从零实现一个面向本地 TCP 连接场景的「拥塞窗口演进与 RTT 观测一致性工作台」，用于在离线环境下复现真实 TCP 拥塞控制的核心机制与可观测性问题。系统模拟一条本地 TCP 连接在确定性往返时延与丢包事件下的完整时间轴：每轮包含报文发送、ACK 回执、丢包检测、拥塞窗口调整与状态迁移，连接状态覆盖 slow_start、congestion_avoidance、fast_recovery、loss_recovery 与 closed。ACK 到达时刻与发送时刻构成 RTT 采样，但采样必须区分是否可重传歧义（Karn 规则）；拥塞窗口随 ACK 与丢包演进，而平滑 RTT 与 RTO 由采样序列推导，二者互相影响：RTO 过小会误判重传并污染后续 RTT 样本，RTO 过大又拉长恢复判定。工作台须在交互延迟预算内完成单轮推进，并把每轮窗口、RTT、RTO 与决策事件持久化到 SQLite，支持进程重启后从持久化状态续推。

任务环境与准备：
在 Windows 上准备 Python 3.11 及以上解释器，使用 venv 创建虚拟环境。
在虚拟环境中安装 numpy、pytest、httpx 与 uvicorn，版本自选但需在 requirements.txt 中锁定。
无需外网、容器或真实网络设备；全部事件时间轴与 ACK 由本地确定性生成器产出。
确保工作区可写，SQLite 数据库文件与 pytest 临时目录均位于工作区内部。
首次运行前执行 pytest 收集用例，确认解释器与依赖可用。

业务要求：
1. 实现连接配置与事件时间轴的解析校验：配置声明初始拥塞窗口、慢启动阈值、MSS、基础往返时延、往返时延抖动参数、丢包注入规则与随机种子；事件时间轴由固定种子确定性生成为逐轮事件（ACK 到达、超时、重复 ACK、丢包），校验须拒绝非正窗口、慢启动阈值小于最小窗口、时延参数为负与种子缺失，非法配置返回 E_BAD_CONFIG 且不得进入模拟。
2. 实现拥塞窗口演进状态机：合法状态为 slow_start、congestion_avoidance、fast_recovery、loss_recovery、closed，迁移由 ACK 确认新数据、三次重复 ACK、超时与重传成功驱动；非法迁移须拒绝并返回 E_INVALID_TRANSITION。慢启动按指数增长、拥塞避免按线性增长、快恢复按窗口折半与增量恢复，窗口下界与 MSS 上界须严格约束。
3. 实现 RTT 采样与 Karn 规则：每轮根据 ACK 所确认报文是否经过重传标记采样可用性，重传报文对应的 ACK 不得产生有效 RTT 样本；有效样本按加权移动平均与偏差更新平滑 RTT 与 RTO，RTO 须被钳制在配置上下界内。须区分无有效样本、样本被 Karn 规则拒绝与样本时钟异常三类情况并分别记录。
4. 实现 RTO 回退与重传判定：超时事件须触发指数回退并进入 loss_recovery，同一报文的重传次数超过上限须判定连接失败并以 E_RETRANSMIT_EXHAUSTED 终止；重传成功后的窗口与 RTO 恢复须与从无丢包路径出发的结果在配置容差内一致，容差超出须输出首个越界轮次与偏差来源分类。
5. 实现交互延迟预算与单轮推进语义：每轮推进须按真实单调时钟计时并在声明预算内完成，预算耗尽须中断本轮并以 E_ROUND_BUDGET_EXHAUSTED 返回且本轮对窗口与 RTT 状态不产生任何影响；已完成轮次的窗口、平滑 RTT、RTO 与事件须可重复查询，重复查询同一轮须返回相同内容。
6. 实现 SQLite 持久化与重启续推一致性：每轮完成后须在单个事务中写入轮次序号、状态、窗口、平滑 RTT、RTO、有效与拒绝样本计数与决策事件，事务提交后才对查询可见；进程重启后须从最后已提交轮次继续推进，中断时未提交轮次须丢弃并可从该位置重算，续推结果与不中断运行逐轮一致。
7. 实现并发模拟会话的隔离与资源控制：多个模拟会话可并发推进，每个会话在开始时固定配置版本与事件时间轴版本，中途版本变化须以 E_SNAPSHOT_STALE 终止该会话并保留已提交轮次；同一会话的推进须串行化，跨会话并发写入 SQLite 须以真实锁超时返回 E_CONTENTION_TIMEOUT 而不是无限阻塞，锁超时后会话状态不得被破坏。
8. 提供本地 HTTP 接口与可重复测试：通过本地 HTTP 提供创建会话、推进若干轮、查询轮次快照与决策事件、查询 RTT 样本拒绝统计、终止会话的接口，错误统一以固定业务码在 JSON 中返回；诊断报告须给出窗口演进轨迹、RTO 回退次数与样本拒绝原因分布。pytest 用例须在 Windows 离线使用固定种子覆盖状态迁移、Karn 拒绝、回退与恢复等价、预算中断与重启续推。
