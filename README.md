在 Windows 空白工作区中，需要从零构建一个面向本地回环环境的递归解析器中间件，供上层网络诊断工具集成。中间件以本地 UDP 与 TCP 侦听真实 DNS 查询，向本地测试权威服务器递归取回应答，同时维护带生存期（TTL）的正缓存与负缓存（NXDOMAIN、NODATA）。核心工作不在持久化文件互操作，而在解析协议层：同一域名可能经 CNAME 链收敛到目标记录，应答需携带正确的权威标志、递归可用位、截断标志与 EDNS(0) 扩展；当下游客户端用不同 EDNS 载荷大小或不同协议（UDP、TCP）查询同一域名时，中间件须在报文重编码、分片截断与缓存复用之间保持语义一致。本地样本还包含大小写混写的查询名、带压缩指针的应答、跨 TTL 的链式记录与并发重复查询，考察解析链路在真实报文层面的正确性与并发安全。

任务环境与准备：
安装 Python 3.11 并用内置 venv 创建虚拟环境，pip 安装 dnslib 与 pytest，版本以本地安装结果为准。
确认 Windows 回环 127.0.0.1 可绑定高位空闲 UDP 与 TCP 端口，演示脚本使用固定端口配置。
准备本地权威测试服务器与固定 zone 样本，覆盖 A、AAAA、CNAME 链、MX、TXT、NS、SOA、NXDOMAIN 与 NODATA 应答，并含大小写混写查询名与带压缩指针的应答样本。
准备故意超时的本地上游端点配置与演示脚本所需全部参数，所有数据与端点均在本地回环。

业务要求：
1. 实现 DNS 查询与应答的报文编解码，支持 A、AAAA、CNAME、MX、TXT、NS 与 SOA 记录，正确处理域名压缩指针、标签长度上限与报文截断；畸形报文、非法压缩指针与超长标签必须返回业务码 E_MALFORMED_MESSAGE 并通过本地 UDP 测试客户端验证应答不被错误生成。
2. 实现递归解析链路：从本地权威测试服务器获取应答，沿 CNAME 链最多追踪配置的最大跳数，链中任何一跳失败按确定规则终止并返回带业务码 E_CNAME_LOOP 或 E_CHAIN_TOO_LONG 的应答；解析结果写入正缓存，NXDOMAIN 与 NODATA 写入负缓存并遵循不同的负缓存 TTL 来源。
3. 实现 EDNS(0) 协商与响应策略：解析查询中的 OPT 伪记录读取客户端 UDP 载荷大小，应答须回显 OPT 并按客户端载荷决定是否设置 TC 截断标志；客户端未携带 EDNS 时按传统 512 字节上限处理；TCP 查询不受载荷上限约束但须完整回传全部相关记录，本地测试客户端据此核对截断与重传。
4. 实现正缓存与负缓存的生存期语义：每条缓存条目记录写入时刻、剩余 TTL 与来源记录类型，命中时按已流逝时间递减返回 TTL，过期条目不得命中且须被清理；负缓存命中返回对应对答码与 SOA 中的负缓存 TTL；链式 CNAME 命中的各跳记录需按各自 TTL 分别递减，不得用链首 TTL 覆盖下游记录。
5. 实现缓存键规范化与协议一致性：缓存键由规范化查询名（小写、统一末尾点、保留转义标签）、查询类型与查询类别组成，大小写混写查询不得造成重复缓存项或不同应答；同一域名在 UDP 与 TCP 查询间必须复用同一缓存语义，但各自按协议约束重新编码应答，禁止直接回放旧报文导致 TC 标志或 OPT 内容错误。
6. 实现并发查询抑制与单写者一致性：当多个客户端并发查询同一未缓存域名时，仅首个查询触发上游解析，其余请求挂起等待并复用同一结果，不得各自向权威服务器发起重复解析；缓存写入按单写者串行提交，查询读取只能看到某一完整提交版本的缓存，不得观察到部分 CNAME 链已写入的中间状态。
7. 实现上游超时与资源释放：向本地权威测试服务器的每跳解析具备独立超时，超时后必须真实关闭 UDP 套接字或 TCP 连接并返回带业务码 E_UPSTREAM_TIMEOUT 的 SERVFAIL 应答，不得以延迟等待冒充已终止；上游应答被拒绝或格式错误时区分业务码与 SERVFAIL 应答，且失败不得作为正缓存写入。
8. 实现持久化与强制终止恢复：正负缓存条目与解析会话持久化到 SQLite，缓存写入先落意图记录再提交事务；进程在链式解析中途被强制终止后重启须扫描未完成意图，将对应查询恢复为未完成状态并清理未提交的缓存条目，输出仅基于持久化事实的恢复报告；提供本地 HTTP 管理接口与使用固定样本完成 UDP 截断、TCP 重传、CNAME 链、负缓存与一次强制终止恢复的演示脚本。
