这项需求没有既有代码，需要在 Windows 空白工作区中从零构建一个面向本地多进程编辑场景的行级写权租约与版本化读快照仲裁引擎，供上层协同编辑客户端集成。与常规事务组件不同，这里不提供跨语句的 MVCC 事务，而是把并发控制拆成两件独立但必须协同的机制：写侧以带租约的行级排他写权串行化对同一行的修改，租约到期未续则写权自动失效；读侧以单调递增的已提交版本号作为读快照，读者按提交版本读取，不持有任何锁。每次修改会产出一条新行版本并被分配新的提交版本号，旧行版本按保留策略保留供旧快照读者读取。客户端通过本地 HTTP 接口申请写权、续约、提交修改、按版本读取行；编辑面板打开时须拿到该行在当前可见版本上的内容与写权状态，保存时须校验所基于的行版本仍是该行最新可见版本。核心业务问题是写权租约与读快照的一致性：写权失效、租约被抢占、提交版本推进与旧快照回收之间必须严格收敛，快速预检与完整提交两条路径对同一次编辑须给出可逐项核对的结论，并发与强制终止都不能让行版本、写权租约与读快照出现部分可见。

任务环境与准备：
安装 Go 1.22 或更高版本，并确认 go env 可用；本任务不依赖任何外部网络服务。
通过 go mod init 初始化模块，使用 Go 标准库 net/http 提供本地接口，使用 database/sql 配合 SQLite 驱动（如 modernc.org/sqlite）；版本与安装命令在执行前由 go get 拉取到本地模块缓存。
在本地准备确定性样本：若干业务表行数据、并发编辑与写权续约脚本、读快照版本矩阵，全部放入工作区 sample 目录，不依赖真实账号或线上站点。
所有服务绑定回环地址，测试与演示均通过本地 HTTP 调用与本地 SQLite 文件完成；进程强制终止场景通过终止本地进程复现，不引入容器环境。

业务要求：
1. 实现行版本存储与版本化读快照：每行保留行标识、行版本号、提交版本号、内容摘要与删除标记，全局提交版本号单调递增；读请求携带读快照版本，只能读到提交版本号不大于该快照且未被删除的最新行版本，快照版本高于当前已提交版本时返回 E_SNAPSHOT_AHEAD 且不返回任何行，旧快照读到的行版本被回收后返回 E_VERSION_RETIRED 而不得返回更新的行版本。
2. 实现带租约的行级排他写权：写权记录行标识、持有者、写权版本号、授予时刻与租约到期时刻，申请时若该行无有效写权则授予并返回新写权版本号，已有未过期写权则返回 E_WRITE_LEASE_HELD 并附原持有者与到期时刻；续约须携带当前写权版本号，版本落后返回 E_LEASE_STALE，逾期未续的写权在到期时刻之后不得再被续约或用于提交。
3. 实现提交时的行版本校验与租约有效性校验：提交修改须同时携带所基于的行版本号与写权版本号，行版本号不是该行当前最新可见版本时返回 E_EDIT_STALE 并附当前最新行版本号，写权已失效或已被他人持有时返回 E_LEASE_LOST 并附失效原因；两项校验须在同一事务边界内完成，禁止出现行版本校验通过而写权已失效的提交被接受。
4. 实现租约到期回收与真实可中断等待：申请写权处于冲突时按调用方指定的等待策略立即返回或进入有界等待队列，等待须使用可被真实唤醒的中断等待，等待超时后须从队列移除并返回 E_LEASE_TIMEOUT，不得以空转延时冒充等待，也不得把协程超时描述为已终止失控逻辑；写权到期回收与等待者唤醒须保证同一行同一时刻只有一个持有者。
5. 实现提交版本推进与旧快照回收：每次成功提交分配新的提交版本号并使该行旧版本进入保留集，回收时按声明的最小保留快照与版本数量选择可回收的旧行版本，仍被活跃读快照引用的旧版本不得回收；回收前须写意图记录，回收后对旧快照的读取返回 E_VERSION_RETIRED，同一读快照重复读取在回收前后不得返回不同内容。
6. 实现单写者仲裁与多读者并发查询：写权授予、续约、提交版本推进与回收按行标识单写者串行执行，多个按快照版本的读请求可并发；读请求只能看到某一完整提交版本，不得出现行版本已写入而提交版本号尚未推进、或写权已释放而新行版本尚未可见的中间状态；同一请求标识重复提交只执行一次、其余等待并复用结果，内容不一致时返回 E_CONFLICTING_REQUEST。
7. 实现基于 SQLite 的意图持久化与强制终止后恢复：写权申请、续约、提交与回收前先写入意图记录再提交事务；进程被强制终止后重启须扫描未完成意图，把未提交的写权授予回滚为可申请、未提交的行版本写入丢弃、未提交的回收回滚为保留，并将等待中的请求重新入队或标记为已中止，恢复报告只基于已持久化事实。
8. 实现编辑面板快速预检与完整提交两条路径并保证结论可核对：快速路径依据已缓存的写权状态与最新行版本号在声明时延预算内返回是否可编辑预判并标注模式与依据，完整路径在同一读快照与写权版本上重新校验；预判为可编辑而完整提交失败时必须逐项输出差异（实际行版本号、实际写权持有者、读快照版本），预算内未完成预检须返回未完成标识而不得返回跨快照混合结论。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。
