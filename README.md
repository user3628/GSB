在 Windows 空白工作区中，需要从零构建一个面向本地可观测性数据集的超标告警根因定位管线，供 SRE 团队在离线环境中进行告警降噪与根因分析。系统接收带毫秒时间戳的 SLI 样本（服务名、指标名、是否良好事件、延迟微秒）与带版本号的服务依赖拓扑快照（服务到下游的依赖边、拓扑版本与校验摘要），依据可配置的告警阈值与窗口聚合规则产生告警，并构建三类派生产物：按服务与指标的分位聚合索引、按告警指纹的抑制索引、以及基于依赖拓扑的根因候选关联评分表。随着样本持续摄入，服务以带基础版本的增量批次提交新增数据，拓扑以带基础版本的增量片段提交变化；当某服务的指标分布变化或拓扑依赖变化时，依赖该服务的分位聚合索引、抑制索引与根因评分必须级联失效并原子重建。用户通过本地 HTTP API 提交样本批次、提交拓扑增量、查询告警、查询根因候选与诊断报告，并可通过异常注入接口验证各类失败路径。所有数据来自本地确定性样本，不依赖外部监控系统或真实网络。

任务环境与准备：
安装 Python 3.10 或更高版本，并确保可用的 pip 用于安装 FastAPI、uvicorn 与 pytest。
准备固定本地样本：一份 SLI 样本文件（包含多个服务、指标与时间戳的确定性记录）与一份服务依赖拓扑快照文件（含版本号与校验摘要），均放置在本地工作目录。
在本地运行 SQLite 数据库文件（通过 Python 内置 sqlite3 模块访问），无需启动额外数据库服务。
启动本地 HTTP 服务监听回环地址，确保能够通过 HTTP 客户端访问样本提交、拓扑提交、查询与恢复报告接口。

业务要求：
1. 实现 SLI 样本解析与批次入库：每条样本含毫秒时间戳、服务名、指标名、是否良好事件与延迟微秒；解析失败或服务名未在拓扑中声明时返回业务码 E_SAMPLE_INVALID 且整批不入库；同批次内相同（服务名、指标名、时间戳）的重复记录必须按确定性规则保留首条并去重，重复条数写入批次报告。
2. 实现带基础版本校验的增量提交：样本增量片段只含新增记录并携带基础版本，拓扑增量片段只含受影响的依赖边并携带基础版本；若基础版本不是当前已提交版本则返回 E_STALE_BASE 且不改变任何已提交状态；整份快照替换时必须识别版本变化并整体替换旧快照，禁止新旧快照内容混合使用。
3. 实现按服务与指标的分位聚合索引：对每个（服务名、指标名）按滑动窗口计算良好事件率与延迟分位，分位使用声明的确定性最近秩法并注明样本规模；样本数不足以计算分位时返回 E_INSUFFICIENT_SAMPLES 而非静默返回零值，聚合索引条目须记录其生成所基于的样本版本范围。
4. 实现告警生成与抑制索引：依据可配置阈值（良好事件率下限、延迟上限）产生告警并计算告警指纹，抑制规则按服务与级别在抑制窗口内合并同指纹告警；告警状态至少包含 FIRING、SUPPRESSED、RESOLVED 三种并规定合法迁移路径，非法迁移返回 E_INVALID_TRANSITION 且不修改已持久化状态。
5. 实现依赖失效与级联重建：为每个服务维护其对分位聚合索引、抑制索引与根因评分表的引用关系；当某服务的指标分布变化或拓扑依赖边变化时，该服务全部派生条目及依赖它的下游根因评分必须级联失效并在同一事务边界内原子重建，禁止出现分位索引已更新而根因评分仍为旧值的中间可见状态。
6. 实现根因候选关联评分与数值契约：根因评分由拓扑跳数衰减与告警时间邻近度合成，跳数与时间差使用定点表示并在每步校验不越界，评分比较使用带相对容差的定点比较并按稳定次序打破平局；评分输出须附舍入方式与累计误差说明，同一输入重复计算必须逐位一致。
7. 实现单写者提交与多读者查询的并发一致：样本与拓扑提交、级联重建按提交串行执行，多个只读查询可并发读取某一完整提交版本；同一提交标识重复提交只执行一次、其余等待并复用结果，内容不一致返回 E_CONFLICTING_BATCH；携带基础版本的并发增量仅一个成功、另一个必须收到 E_STALE_BASE。
8. 实现基于 SQLite 的意图持久化及强制终止恢复：样本与拓扑提交、级联重建前先写意图记录再提交事务；进程被强制终止后重启须扫描未完成意图，把派生索引回滚到最后一个完整版本或把对应增量标记为已中止，恢复报告只包含已持久化事实，不得承诺强制终止后仍生成完整退出报告；所有失败响应为含业务码与上下文的 JSON，至少覆盖上述业务码。
