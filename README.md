当前是空白工作区，需要在 Windows 本地从零构建一个面向本地微服务测试环境的灰度路由与流量镜像中间件，交付算法实现与可复现的实验环境。中间件接收带毫秒时间戳、路由键、客户端标识、请求权重与目标版本的请求事件，依据带版本号的灰度策略快照（按版本权重分流、按请求权重再分配、镜像采样率、灰度上限比例、单客户端去重窗口）裁决每条请求应命中的版本以及是否被镜像复制。核心业务问题是数值精度与误差传播：版本分流比例与镜像采样率均为浮点比例，请求权重为大整数并可叠加，实际分流占比需要经过多级乘除、权重归一化与累计求和，浮点运算顺序、舍入方式、分位与比例边界包含关系都会放大误差，导致同一策略版本在不同计算路径下分流结论不一致、灰度上限被越界或镜像样本产生偏差。所有输入来自本地确定性样本，通过本地 HTTP 接口提交策略与事件批次并查询裁决轨迹。

任务环境与准备：
确认 Windows 本地已安装 Python 3.11 或以上，并可用 pip 安装 FastAPI、uvicorn、NumPy 与 pytest；SQLite 使用 Python 标准库 sqlite3，无需额外安装。
在工作区创建项目目录与虚拟环境（如 python -m venv .venv），安装上述依赖后以本地固定随机种子生成确定性样本：策略快照 JSON、请求事件批次与用于误差对比的混合量级样本。
规划启动命令（如 uvicorn 本地服务），监听本地回环固定端口，并准备实验脚本的运行入口；所有数据与端点均在本地，不访问外部网络、真实账号或付费资源。

业务要求：
1. 实现请求事件与灰度策略快照的加载和归一化：事件含毫秒时间戳、路由键、客户端标识、请求权重（正整数）与目标版本，策略快照含单调递增版本号、生成时间、各版本权重比例、镜像采样率、灰度上限比例与单客户端去重窗口，以及整体校验摘要；加载时校验版本单调与摘要，失败返回业务码 E_SNAPSHOT_INVALID 并保持既有已提交状态不变，权重与时间字段解析失败返回 E_EVENT_INVALID 且整批不入库。
2. 实现权重归一化与版本分流计算：各版本权重比例之和须显式归一化为内部定点表示（比例保留固定小数位），请求权重参与累计分流时须使用补偿求和，禁止在未声明的情况下混用浮点与定点；分流结果必须落在合法版本集合内，比例总和为零或负权重的非法输入返回 E_WEIGHT_INVALID，不得静默回落到默认版本。
3. 实现误差可界定的数值契约：对分流占比、灰度使用比例与镜像采样率分别输出每步运算的舍入方式与累计舍入误差，并给出可量化误差上界，与朴素浮点求和在混合大数小数的固定样本上对比；同一策略版本与同一事件批次多次重算须逐位一致，裁决结论不得因运算顺序变化而翻转。
4. 实现灰度上限判定与容差契约：判断当前灰度使用比例是否越过灰度上限比例时使用带相对容差的定点比较而非裸浮点比较，容差内视为未越界并按稳定字典序打破平局；越界时返回 E_GRAY_LIMIT_EXCEEDED 并附当前使用值、上限值与容差取值，使同一输入在容差内外的判定可被逐项核对，并在输出中保留固定小数位。
5. 实现镜像采样与去重裁决：按镜像采样率与策略声明的固定种子及事件序号共同决定是否镜像，同一客户端在单客户端去重窗口内只允许被镜像一次，窗口边界包含关系与时戳精度须显式定义；采样判定必须与灰度裁决读取同一策略版本与同一累计状态，禁止出现按新版本的采样率决定镜像而按旧版本比例分流。
6. 实现定点数值契约下的单写者提交与多读者查询并发一致：策略提交、事件批次裁决与派生统计重建按提交串行执行，多个只读查询可并发读取已提交版本；同一请求标识重复提交只裁决一次、其余等待复用结果，内容不一致返回 E_CONFLICTING_REQUEST；查询只能看到某一完整提交版本，不得出现分流结论已写入而灰度使用比例尚未更新的中间可见状态。
7. 使用 SQLite 持久化策略版本、事件裁决结果、灰度使用累计与意图日志，所有写操作先写意图记录再提交事务；进程在批次裁决或派生统计重建中途被强制终止后重启须扫描未完成意图，把灰度累计与裁决状态回滚到最后一个完整版本或把批次标记为已中止，恢复报告只基于已持久化事实，不得承诺强制终止后仍生成完整退出报告。
8. 提供本地 HTTP API 与可重复实验脚本：API 覆盖策略提交、事件批次提交、按版本查询分流占比与灰度使用、误差说明查询与恢复报告查询，失败响应统一为含业务码与上下文的 JSON，至少覆盖 E_SNAPSHOT_INVALID、E_EVENT_INVALID、E_WEIGHT_INVALID、E_GRAY_LIMIT_EXCEEDED、E_CONFLICTING_REQUEST；脚本使用固定本地样本完成一次全量策略裁决、一次镜像采样、一次越过灰度上限与一次强制终止后恢复，输出各版本分流占比、镜像条数、误差声明与恢复结论。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地样本验证策略版本加载、分流与镜像裁决的定点一致性、灰度上限容差判定及强制终止后恢复结论。
