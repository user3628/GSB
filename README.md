某个本地推理编排项目在新一轮迭代中需要把批处理作业的调度层独立出来，当前工作目录除了一份需求说明之外没有任何实现与样本。平台按「作业→任务→阶段」三层组织推理作业，每个作业声明 CPU 毫核与内存字节预算上限，其下任务各自声明资源需求、依赖任务、优先级与预计推理耗时；依赖关系构成有向无环图，同一波次内任务可并行、跨波次必须等待上游波次全部完成。执行端是本地回环的推理测试服务，任务派发后须真实发起 HTTP 请求并在超时后真实断开连接。难点在于作业预算被波次内所有并发任务共享，高优先级任务到来时须从低优先级已准入任务中抢占资源，同时不得让已派发任务处于预算欠账状态，且进程可能在派发或抢占中途被强制终止。

任务环境与准备：
安装 Go 1.22 或以上版本与 go 命令行工具，确保 GOPATH 与模块代理可用，运行 go version 核对。
安装 SQLite 3.40 或以上版本命令行工具 sqlite3，供核对持久化事实与意图日志。
在空工作目录初始化 Go 模块，仅使用标准库与 SQLite 驱动，确保无需网络即可构建与运行。
准备本地回环 HTTP 测试端点，用于模拟任务派发成功、非成功状态码与真实超时关闭连接。
样本与意图日志均写入工作目录下的本地文件与 SQLite 数据库，不依赖外部账号或线上服务。

业务要求：
1. 实现作业、任务与阶段模型及本地确定性样本加载：作业声明预算上限与波次划分规则，任务声明资源需求、依赖任务列表、优先级与预计推理耗时；解析时校验标识唯一、资源量为非负整数并做溢出检查、依赖引用存在且不得自指，非法样本返回业务码 E_SPEC_INVALID 并指明字段；加载失败必须保持已提交作业完全可用。
2. 实现依赖图的波次划分与合法性校验：依据任务依赖边计算每个任务的波次序号，要求所有上游任务波次严格小于下游任务波次；出现依赖环时返回 E_DEPENDENCY_CYCLE 并附环上任务标识列表，同时仍须输出未被环污染部分的任务波次结果与受阻任务清单，且同一事务边界内查询可见。
3. 实现作业预算账本与三级占用视图：作业已用额度由已准入但未结束的任务需求合计得到，同时按波次与任务两级汇总，三视图必须逐项守恒；准入任务前在同一事务内递增占用，释放时递减，任何视图间差额非零即返回 E_BUDGET_INVARIANT 并拒绝该次状态迁移。
4. 实现带精确对齐的抢占裁决：高优先级任务因作业预算不足无法准入时，可从同波次或更早波次中挑选低优先级已准入任务抢占，挑选须使释放额度不低于待准入需求且超出部分最小，超出相等的按任务标识稳定字典序打破平局；被抢占任务迁移为 PREEMPTED 并在同一事务内释放其占用的并发名额与预算额度。
5. 实现波次推进与并行调度的三重预算约束：调度轮次受全局并发任务上限、作业预算上限与每轮时间预算共同约束，预算内按波次序号、优先级与任务标识稳定次序取任务，超出并发上限的任务进入有界等待队列，队列满返回 E_DISPATCH_QUEUE_FULL；预算耗尽时按波次与优先级给出确定性延后次序并输出延后依据与剩余预算。
6. 实现向本地回环端点的真实派发与资源释放：每次派发具备独立超时，超时后必须真实关闭底层 HTTP 连接并释放其占用的并发名额与作业预算，返回 E_DISPATCH_TIMEOUT 并附任务标识；上游返回非成功状态码返回 E_UPSTREAM_FAILED 并保留响应状态码与摘要；不得以等待冒充超时。
7. 实现单写者调度与多读者查询的并发一致及幂等：准入、抢占、波次推进与预算变更按作业单写者串行执行，多个只读查询（作业账本、波次视图、任务状态、抢占明细）可并发读取某一完整提交版本，不得出现任务已 PREEMPTED 而预算尚未归还的中间可见状态；同一请求标识重复提交只执行一次、其余等待并复用同一结果，内容不一致返回 E_CONFLICTING_REQUEST。
8. 实现基于 SQLite 的意图持久化与强制终止后恢复：准入、抢占、派发与预算变更前先写意图记录再提交事务，进程被强制终止后重启须扫描未完成意图，把未提交准入回滚为待调度、未提交派发回滚为可重派并把预算额度按已落盘事实重算，恢复报告只包含持久化事实且不得承诺生成退出报告；恢复后账本三级视图仍须守恒。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用固定本地样本验证波次划分、预算守恒、抢占对齐与超时释放，并核对强制终止后的账本恢复。
