当前是空白工作区，需要从零构建一个面向本地单机场景的事件总线流式集成中间件，交付数据处理管线与结果验证工具。总线维护若干主题与订阅者，生产者按主题与分区键发布事件，事件在总线内经过接入、投递、确认三段状态演进，订阅者通过本地 HTTP 接口拉取并确认。为支撑流式集成，每个订阅者维护消费位点，总线依据位点推进投递并支持位点回拨重放。订阅者的消费会驱动一条本地确定性聚合管线（按事件键分组累计计数与度量求和），管线的中间状态随事件批次演进。核心业务问题是状态演进与恢复一致性：接入、投递、确认与位点推进之间存在多步中间状态，进程可能在任意时刻被强制终止，重启后必须依据持久化意图与位点恢复，使继续消费后的聚合结果与从未中断时逐项一致；慢消费者与重放的组合还会威胁分区内投递顺序。所有数据来自本地确定性样本，不依赖任何外部消息系统或真实账号。

任务环境与准备：
在 Windows 空白工作区创建工作目录，安装 Python 3.11 及以上版本，并用虚拟环境隔离依赖。
安装 FastAPI、Uvicorn、pytest 与 requests 等本地依赖，全部使用本地回环端口，不访问外部网络。
准备固定随机种子与本地确定性事件样本文件，包含多分区、多键与混合量级度量值，样本与测试服务均由本地脚本生成。
确认 SQLite 可用并指定本地数据库文件路径，准备端到端演示脚本入口与本地 HTTP 服务启动说明。

业务要求：
1. 实现主题、分区与事件模型：主题声明分区数与消费者组，事件含事件标识、分区键、生产序号、事件时刻、体摘要与批次标识；同一分区内生产序号由总线单调分配且无缺口，分区键经确定性哈希路由到分区；重复发布同一事件标识且内容一致时幂等成功，内容不一致返回业务码 E_CONFLICTING_EVENT 且保留首次内容，解析失败返回 E_EVENT_INVALID 且整批不入库。
2. 定义事件与订阅状态机，至少包含 ACCEPTED、DISPATCHED、ACKED、REDELIVERED、DEAD_LETTERED 五种状态并规定合法迁移路径；非法迁移返回 E_INVALID_TRANSITION 且不修改任何已持久化状态；同一事件的重复确认必须幂等，未经投递的事件确认返回 E_NOT_DISPATCHED，并把每次状态迁移写入事件状态轨迹以便核对。
3. 实现基于消费位点的顺序投递：消费者按消费者组与分区拉取，返回该分区位点之后最小未确认事件；同一分区同一时刻只允许一个消费者组内消费者持有投递租约，租约超时后真实释放并按原顺序重投而非跳到后继事件；并发拉取同分区时仅一个成功，其余返回空结果或 E_LEASE_HELD，且慢消费者不得导致后续消费者越过其未确认事件。
4. 实现位点回拨与重放：调用方可将消费位点回拨到指定生产序号并触发重放，重放期间新事件的投递须暂缓，重放完成后按位点继续；回拨目标早于最早保留序号时返回 E_OFFSET_EXPIRED，指向未提交序号时返回 E_OFFSET_NOT_FOUND；位点回拨与位点推进必须在同一事务内生效，禁止出现位点已回拨而投递租约仍指向旧位点的中间状态。
5. 实现消费驱动的确定性聚合管线：按事件键分组累计计数与度量求和，度量求和采用补偿求和以降低混合量级样本的累计误差，空值与缺失字段按声明规则处理；管线的聚合中间状态随已确认事件批次演进并可在位点回拨后回退重算；同一事件集合无论分批确认还是一次确认，分组聚合结果必须逐项一致且分组键输出稳定有序。
6. 使用 SQLite 持久化事件、投递记录、确认记录、位点与聚合状态，接入、投递、确认与位点推进均先写入意图记录再提交事务；进程在确认或位点推进中途被强制终止后重启，必须扫描未完成意图把未提交确认回滚为未确认、位点回滚到最后一个完整提交边界，并输出仅基于已持久化事实的恢复报告，不得承诺强制终止后仍生成完整退出报告。
7. 实现单写者提交与多读者查询的并发一致：拉取租约授予、确认与位点推进按分区单写者串行执行，多个只读查询（事件状态、位点、聚合结果）可并发读取某一完整提交版本；查询不得看到事件已 ACKED 而聚合状态仍为旧值、或位点已推进而确认记录未落库的中间可见状态；并发提交同一确认时仅一个生效，其余按幂等或冲突规则处理。
8. 实现统一业务错误码与结果验证工具：所有失败响应为含业务码与上下文的 JSON，至少覆盖 E_EVENT_INVALID、E_CONFLICTING_EVENT、E_INVALID_TRANSITION、E_LEASE_HELD、E_OFFSET_EXPIRED、E_NOT_DISPATCHED；验证工具读取持久化状态，检查分区内生产序号连续性、确认与聚合的一致性、位点单调性及状态迁移合法性并输出结构化结论；附端到端脚本用固定本地样本完成一次正常消费、一次位点回拨重放、一次租约超时重投与一次强制终止后恢复，并输出恢复前后的聚合差异。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用固定本地样本验证顺序投递、位点回拨重放、聚合一致性与强制终止后恢复，并输出错误码与验证结论。
