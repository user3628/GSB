从无到有搭建时，需要为一家多租户 SaaS 的开放平台实现一套 OAuth 2.0 授权码流程鉴权组件，并叠加基于定点小数的配额计费与误差传播追踪。授权码由授权端点签发，客户端以 PKCE S256 换取访问令牌与刷新令牌，刷新令牌轮换时必须原子地失效旧令牌并保证重放检测。计费侧按“请求次数 × 单位成本”的定点利率对每个租户配额做累计扣减，所有金额以 1e-9 为最小单位的整数定点数表示，禁止浮点；令牌签发、撤销和计费扣减跨多个模块，要求误差可界定、异常可追溯。验收通过本地确定性样本与可重复集成测试观察令牌状态、配额余量与错误码。

任务环境与准备：
安装 Go 1.22 或以上版本（Windows 安装包或压缩包），确保 go 命令可用并设置本地 GOPATH 与模块缓存目录。
创建新工作区目录并执行 go mod init 初始化模块，仅使用标准库与 modernc.org/sqlite 纯 Go 驱动，避免 CGO 依赖。
准备本地确定性样本：在 testdata 下生成固定租户、客户端、PKCE 密钥对与计费脚本 JSON，所有随机源使用固定种子或预置常量。
不依赖任何外部 OAuth 服务、真实账号或网络；授权端点、令牌端点与计费账本均在本地进程内以 SQLite 文件实现。
提供命令行入口与环境变量参数用于切换恢复策略、并发度上限与故障注入类型，全部可在 Windows PowerShell 中运行。

业务要求：
1. 实现授权码签发与兑换端点核心逻辑：授权码须绑定 client_id、redirect_uri、PKCE code_challenge、租户与一次性 nonce，兑换时严格校验 S256 challenge、redirect_uri 全等与授权码未使用，失败返回稳定业务码 E_INVALID_GRANT 或 E_PKCE_MISMATCH，且校验失败不消耗授权码。
2. 实现定点计费账本：所有单位成本与扣减以 int64 定点数（scale=1e9）运算，累计时执行乘法溢出与精度截断检查，截断误差逐次记录到误差账本并可按租户聚合出有界误差上界；金额路径禁止 float32/float64，溢出返回 E_PRECISION_OVERFLOW。
3. 实现刷新令牌轮换与重放检测：每次刷新生成新令牌、标记旧令牌失效并记录族谱（family_id 与序号），已失效令牌再被使用时整族撤销并返回 E_TOKEN_REUSE；轮换与计费扣减须在同一 SQLite 事务提交，任一步失败则两者均不生效。
4. 实现令牌会话状态快照与版本迁移：每个租户会话保存递增版本号快照，令牌撤销、轮换或配额触底均产生新版本；读取时校验版本连续性，发现跳号则拒绝服务并返回 E_SNAPSHOT_VERSION，并能从最近一致版本恢复只读视图。
5. 实现并发配额扣减的资源控制：多个刷新请求并发到达时按租户串行化扣减，以可配置上限的信号量限制在途计费事务，排队超阈值的请求返回 E_QUOTA_CONTENTION 而非阻塞，所有并发冲突须记录租户、请求标识与账本版本。
6. 实现异常链路注入验证：通过参数构造授权码过期、PKCE 不匹配、刷新令牌重放、定点乘法溢出、快照版本跳号与配额耗尽六类故障，分别断言对应业务码、账本未被污染的终态与快照版本变化，注入不得修改源码。
7. 实现幂等重放与强制终止后恢复：请求携带客户端幂等键，重复提交须返回首次结果与相同账本版本；进程被强制终止后重启，依赖 SQLite 已提交事务恢复，已提交不回滚、未提交整体丢弃，不承诺生成退出报告，恢复后版本号可识别。
8. 提供可集成的领域组件与完整示例：导出 Go 包接口供宿主服务接入鉴权中间件，附带本地确定性样本（租户、客户端、密钥对与计费脚本）与可重复集成示例，重复运行得到字节级一致的账本导出与令牌状态，示例须在 Windows 下通过 go test 与命令行入口执行。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地确定性样本验证授权码兑换、定点扣减、令牌轮换重放与快照恢复的终态及业务码，重复运行字节级一致。
