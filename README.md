在 Windows 空白工作区中，需要从零构建一个面向本地微服务测试环境的服务注册与健康探测中间件。注册中心接受服务实例注册（服务名、实例 ID、端点、权重、租约 TTL），维护实例的 UP/DOWN/EXPIRED 状态，并按并行调度器对已注册实例执行健康探测。调度器必须在固定的并发预算与每轮时间预算内完成尽可能多的探测，对不同服务采用不同探测策略（HTTP 探针到本地测试服务、TCP 拨号、租约心跳判定），并在预算耗尽时按确定规则排队而不得无限拖延。健康判定结果需要与注册状态、租约过期时间保持一致，进程被强制终止后重启要依据 SQLite 持久化状态恢复，不能依赖内存残留。用户通过本地 HTTP API 注册、注销、查询实例并触发探测轮次，所有探测目标为本地确定性测试服务与本地端口，不依赖真实线上站点或外部账号。

任务环境与准备：
安装 Python 3.11 并在空白工作区创建虚拟环境，安装 FastAPI、uvicorn、httpx、pytest，仅使用本地包源。
准备固定本地样本：若干可返回 200 带标记、返回 500、故意挂起的测试端点，以及一组确定性实例注册配置，全部绑定 127.0.0.1 本地端口。
初始化 SQLite 数据库文件用于实例、租约、探测轮次与任务记录，执行前清空旧库以保证可重复。
演示脚本以固定参数运行两轮探测并在第二轮中途发送强制终止，重启后再次采集统计，所有步骤在 Windows 命令行可执行。

业务要求：
1. 实现实例注册与租约模型：注册请求包含服务名、实例 ID、端点、权重和租约 TTL，同一服务名与实例 ID 重复注册时按更新处理并返回业务码 E_DUPLICATE_INSTANCE 的明确语义说明；租约过期依据持久化的到期时间判定，查询时不得把已过期实例报告为 UP。
2. 实现三类健康探测：HTTP 探针要求本地测试服务返回约定状态码与响应体标记，TCP 拨号探针以真实连接成功或拒绝为判定，租约心跳探针依据最近心跳时间与 TTL 计算剩余寿命；每类探测返回结构化结果与耗时，探测失败不得吞掉异常原因。
3. 实现并行调度器，以全局并发上限和每轮时间预算两个参数约束执行；在预算内按优先级取任务，超出并发上限的任务进入有界等待队列，队列满时返回业务码 E_QUEUE_FULL；调度器需保证同一实例在同一轮中不被重复探测。
4. 实现探测超时与取消语义：单次探测有独立超时，超时后必须通过真实机制关闭该探测的连接或拨号资源并记录超时，不能用延迟等待冒充已终止；某探测挂起不得阻塞其他探测，也不得使整轮越过时间预算继续执行。
5. 实现健康状态与注册状态的跨模块一致：探测结果、权重调整与租约过期共同决定实例状态，状态变更必须在同一事务边界内更新实例记录与探测历史，禁止出现探测历史已记录失败而实例仍显示 UP 的中间可见状态；查询接口返回的字段集合固定且包含状态与最近探测时间。
6. 实现崩溃恢复：进程在探测轮次中途被强制终止后，重启必须扫描持久化的轮次与任务记录，将未完成轮次标记为已中止并按确定规则重新排队，恢复报告只基于已持久化的事实，不得声称强制终止后仍能生成完整退出报告；恢复后不得把半完成的探测结果计入健康统计。
7. 实现资源预算取舍：当实例数超过并发与时间预算可覆盖范围时，调度器需按权重与最近失败次数给出确定性优先级，并输出本轮被跳过实例清单及跳过原因；在低预算下必须牺牲部分覆盖而非违反并发上限，跳过与超时的区分需在输出中可核验。
8. 提供本地测试服务与端到端演示脚本：使用固定本地样本启动若干可返回成功、返回失败与故意挂起的测试端点，脚本完成注册、探测、注销并模拟一次强制终止与重启恢复，输出每轮探测统计、状态迁移记录、被跳过实例清单与恢复前后差异，便于人工核验。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地测试服务验证注册、并行探测、预算跳过与强制终止后的恢复，输出统计与状态迁移记录。
