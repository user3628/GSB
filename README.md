工作区目前只有一份运动推演设计草案，需要据此独立实现一个多镜头视频预测与运动时序滚动推演引擎，交付可交互的专业应用与可重复演示。输入由程序内置固定种子生成器产出：一组低分辨率帧序列样本（每段含匀速平移方块、缓慢变形色块与一次方向突变），以及一份 JSON 运动清单，逐序列声明初始位移与速度、加速度衰减系数、预测分支数、每步期望状态取值范围与序列总帧数；另有带版本号的分支执行策略快照，声明全局并发上限、每分支步数配额、单轮时间预算与分支剪枝阈值。真值帧与取值范围由同一生成器可复现产出，作为误差评估的唯一真值来源。引擎须在有限并发与步数预算下，同时滚动推演多个预测分支，完成帧渲染、逐步误差汇总与分支裁决，并把推演状态持久化到 SQLite，使中断后能依据已提交事实恢复。核心难点在于并行分支数、步数配额与时间预算相互挤压，而分支间存在共享的初始帧与运动状态，剪枝与恢复必须与从零完整推演逐字节一致。

任务环境与准备：
Windows 本机，安装 Go 1.22 或更高版本，并确保 go 命令可用；SQLite 通过纯 Go 驱动 go-sqlite3 或 modernc.org/sqlite 引入，安装命令为 go get。
创建空白工作区目录并初始化 Go 模块，所有样本、帧序列与运动清单由程序内置的固定种子生成器在首次运行时写出，不依赖外部数据集、下载或 GPU。
本地 HTTP 服务仅监听回环地址，演示与测试均在单机完成；运行前确认工作目录具有读写权限，用于写出 SQLite 数据库与检查点文件。

业务要求：
1. 实现运动状态滚动推演与确定性帧渲染核心：按清单初始状态逐步更新位移、速度与形变参数，速度按衰减系数更新，依据状态对画布执行平移与形变变换并做双线性采样与 8 位量化；同一序列与配置必须产生逐字节一致的状态轨迹与帧摘要。
2. 实现多预测分支的并行滚动推演：以分支为调度单元，在全局并发分支上限、每分支步数配额与单轮时间预算三重约束下决定接纳顺序与并发度，超预算分支记录为未启动或已剪枝并给出原因，不得静默丢弃。
3. 实现分支间共享状态的复用与隔离：多分支共享同一初始帧与初始运动状态，分支内的状态演进与渲染中间量互不可见；共享帧只允许读访问，出现写冲突时须返回带序列标识与分支号的结构化错误。
4. 实现分支剪枝裁决与预算回收：依据剪枝阈值在推演中途终止偏差过大的分支并释放其配额，剪枝后剩余分支的推演结果与配额使用必须与从未派发被剪枝分支时逐字节一致，剪枝依据须可追溯。
5. 实现逐步误差与分支对比汇总：把每步预测帧与清单对应真值帧比对，计算逐像素平均绝对误差与逐步误差曲线，并横向对比各分支的误差轨迹与最终裁决；预测步数超出真值帧数时返回带序列标识与超出帧数的 E_TIMELINE_OVERFLOW。
6. 实现 SQLite 事务化推演状态与强制终止恢复：以事务写入分支、步进度、状态摘要与裁决结论，同一分支同一步只允许一条有效记录；进程被强制终止后仅凭已提交事实重建进度，恢复后结果须与一次连续执行逐字节一致，且不承诺生成退出报告。
7. 实现并发发布保护与整体替换识别：多工作进程发布同一步状态时使用事务条件更新与文件锁，仅允许序号连续推进，落后或重复发布返回 E_STALE_CHECKPOINT；当策略快照被整体替换时须区分正常推进、替换与回退，替换使全部分支状态失效重建，回退拒绝。
8. 提供本地 HTTP 与命令行交互应用及确定性演示：支持导入帧序列与运动清单、设置分支与预算、触发分阶段推演、查询各分支状态与版本指纹、查看剪枝与误差明细、请求优雅停止与恢复；演示数据至少 3 个序列，含方向突变与多分支剪枝情形。

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
使用本地确定性帧序列验证多分支并行推演、剪枝后预算一致性、误差汇总与强制终止后恢复，附运行摘要。
