一个面向本地日志分析的列式聚合执行服务刚完成方案讨论，准备进入实现，工作区将新建 Go 模块，没有任何既有代码。服务以计算引擎身份接收按分区键预分区的逻辑数据块，每块声明行数、列式编码方式、解压后字节大小与内容摘要，并要求在单块内存上限与全局并发解码上限内完成解码与分组聚合。查询需同时给出分组键、度量列与结果精度约定，聚合结果须能跨批次增量追加并支持分段续算。真实运行时热点分区与长尾分区并存，强制终止后只能依据 SQLite 已落盘事实恢复执行会话。

任务环境与准备：
安装 Go 1.21 或以上版本与 SQLite 开发库（如 libsqlite3-dev），并在 Go 模块中引入 SQLite 驱动；具体版本与安装命令由执行者在本机确认
在 Linux（WSL Ubuntu）下创建工作目录并初始化 Go 模块，确认本地 HTTP 回环端口可用
程序内置固定种子生成器负责产出分片清单、列式块样本与离线事件，不依赖外部数据集或网络服务
保留 SQLite 数据文件以便复现强制终止后的恢复行为

业务要求：
1. 实现分片清单与数据块的加载与版本识别：每个分片携带单调递增版本号、生成时间、列定义与逐块内容摘要，加载时校验版本单调与摘要一致性，任一失败返回 E_SHARD_INVALID 且必须保持已提交分片完全可用；提交新分片须整体替换旧分片索引并识别版本变化
2. 实现三种列式编码的确定性解码：定长、游程与字典编码各提供可独立调用的解码实现，解码前校验块头声明的行数、编码类型与摘要，损坏块返回 E_BLOCK_CORRUPT 并指明块号与块内偏移；解码须支持从指定行号开始的分段解码，分段边界不得改变行序与取值
3. 实现单块内存上限下的分段裁决：依据块声明的解压后字节大小与单块内存上限决定整体解码或分段解码，输出分段大小计算依据与预计峰值内存；声明字节数不足以容纳最小行宽时返回 E_BLOCK_UNBOUNDED 并附最小行宽与可用预算
4. 实现跨段部分和与续算状态：每段解码后按分组键累计计数、求和、最小值与最大值，部分和须带段基版本与已处理行区间；续算时从已提交部分和继续并复用未变化的段结果，不得从头重扫整块；同一分片同一块在相同版本下重复续算必须逐位一致
5. 实现按字节预算的调度与延后裁决：解码与聚合任务在全局并发解码上限、单块内存上限与每轮处理字节预算共同约束下执行，超出并发上限的任务进入有界等待队列，队列满返回 E_DECODE_QUEUE_FULL；预算耗尽时按分区号与块号稳定次序给出确定性延后安排与剩余预算，已开始解码的块不得被静默丢弃
6. 实现定点度量值的数值契约与精度声明：分量求和全程使用 int64 定点并在每步校验不越界，越界返回 E_NUMERIC_OVERFLOW 并指明窗口与分组；结果按查询精度约定做显式舍入并输出每步舍入方式与累计舍入误差，与逐行朴素求和在固定样本上比对给出可量化偏差上界
7. 实现单写者推进与多读者查询的并发一致及幂等：聚合会话推进、部分和提交与分片切换按会话单写者串行执行，多个只读查询可并发读取某一完整提交版本，不得出现某块已标记完成而部分和未落盘、或分片已切换而块索引仍指向旧摘要；同一批次标识重复提交只执行一次、其余复用结果，内容不一致返回 E_CONFLICTING_BATCH
8. 实现基于 SQLite 的意图持久化与强制终止后恢复，并提供本地 HTTP 接口：段解码开始、部分和提交与分片切换前先写意图记录再提交事务，进程被强制终止后重启须扫描未完成意图，把未提交块恢复为待解码或复用已提交部分和，恢复报告只陈述已落盘事实并区分已提交、已回滚与需重算三类

执行约束：不使用 Docker 或其他容器环境；使用本地确定性样本验证，不访问未授权目标。按上述任务意图交付相应代码、测试或技术说明，记录实际验证结果。

验收：
用本地确定性样本验证分段解码、部分和续算、字节预算延后、精度契约与强制终止后恢复结果。
